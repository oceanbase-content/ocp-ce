# グラフィカルインターフェースを使用したOCPのアップグレード

このセクションでは、OceanBase Deployer（OBD）を使用してOCP-CEを最新バージョンにアップグレードする方法について説明します。

## 前提条件

* この方法でのアップグレードは、OCP V4.0.3以降のバージョンでのみサポートされています。その他のバージョンのアップグレード方法については、テクニカルサポートまでお問い合わせください。
* Java環境がインストールおよび設定済みであること。現在、JDK17バージョンのみサポートされています。
* [インストールの準備](../../300.deployment-guide/200.deploying-community-ocp/400.installation-preparation.md) を参照して、`ocp-all-in-one-2-YYYYMMDDhhmmss.el7.x86_64.tar.gz`ソフトウェアパッケージを取得し、パッケージをOCPホストの任意のディレクトリにアップロードして、以下のコマンドを実行して解凍します。

   ```bash
   tar zxf ocp-all-in-one-4.4.2-YYYYMMDDhhmmss.el7.x86_64.tar.gz
   ```

## 手順

### ステップ1：obdを起動する

1. obdのコントロールマシンが配置されているノードにログインします。

2. 以下のコマンドを実行して、解凍後のソフトウェアパッケージの`bin`ディレクトリに移動し、デプロイプログラムを起動します。

    ```bash
    cd ocp-all-in-one/bin && bash install.sh
    ```

3. 以下のコマンドを実行して、環境変数を有効にします。

    ```bash
    source ~/.oceanbase-all-in-one/bin/env.sh
    ```

4. `obd web upgrade`を実行し、戻り値からアップグレードウィザードページのIPアドレスを取得します。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/upgrade.png)

### ステップ2：OCPアップグレードウィザードページにアクセスする

ブラウザで**ステップ1**で取得したIPアドレスにアクセスし、アップグレードウィザードページに移動して、**アップグレードを開始**をクリックします。

<!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E5%90%91%E5%AF%BC.png) -->

### ステップ3：デプロイ関連情報を設定する

1. 管理対象のOceanBaseクラスタ名をカスタマイズします。

   システムはOBDが管理しているすべてのクラスタ名を自動的に取得します。**<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.ClusterName">クラスタ名</UI-TERM>**のドロップダウンリストから、アップグレードするクラスタを選択できます。
   アップグレードするクラスタ（例えば、Dockerを使用してデプロイされたクラスタ）がOBDによって管理されていない場合は、手動でクラスタ名を入力できます。クラスタのアップグレードが完了すると、OBDは自動的にそのクラスタを管理します。

2. アップグレードする製品バージョンを選択します。

<!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E9%85%8D%E7%BD%AE.png) -->

### ステップ4：MetaDB接続性の検証

1. MetaDB接続情報に誤りがないことを確認し、**<UI-TERM key="ocp-v2.page.Credential.Host.Verification">検証</UI-TERM>** をクリックします。システムはこのMetaDBが正常に接続されているかどうかを検証します。

   インストーラーは、現在のホストのOCPに基づいてMetaDBの設定情報を自動取得します。フォーム内の情報がアップグレード対象環境の想定と一致しているか確認してください。OCPはこの情報に基づいてアップグレードプログラムを実行します。

2. オペレーティングシステムユーザー関連情報を入力し、入力完了後、**<UI-TERM key="ocp-v2.page.Credential.Cluster.Verification">検証</UI-TERM>** をクリックしてユーザー接続性をテストします。

   |  パラメータ   |   説明   |
   |---------|----------|
   |  ユーザー名   | インストーラーが自動設定を行うために必要なホストオペレーティングシステムのユーザー名です。このユーザーにはsudo権限が付与されている必要があります。    |
   |  <UI-TERM>ユーザーパスワード</UI-TERM>   | **<UI-TERM key="ocp-v2.Channel.FormComponent.EMailForm.Username">ユーザー名</UI-TERM>** に対応するパスワードを入力してください。ホストでパスワードレスログインが設定されている場合は、この構成を無視できます。     |

3. **<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">次のステップ</UI-TERM>** をクリックします。

<!-- ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E8%BF%9E%E6%8E%A5%E4%BF%A1%E6%81%AF.png) -->

### ステップ5：環境事前チェック

環境事前チェックでは、お使いの環境がOCPのアップグレード要件を満たしているかどうかを検証します。

システムはMetaDBの設定情報に基づいてOCP関連の設定情報を取得します。管理機能の一貫性を保証するため、アップグレードプログラムはプラットフォーム管理サービス(COP Server)およびそれが管理するすべてのホストエージェントサービス(OCP Agent)をアップグレードします。

1. **インストール設定** および **アップグレード設定情報** のアップグレード内容が想定要件を満たしていることを確認し、問題がなければ **<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">事前チェック</UI-TERM>** をクリックします。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E9%85%8D%E7%BD%AE%E4%BF%A1%E6%81%AF.png) -->

2. チェック結果を確認します。

   * チェックに合格した場合、**<UI-TERM key="ocp-v2.Detail.TakeOver.Next">次のステップ</UI-TERM>** をクリックします。
   * チェックに失敗した場合、失敗項目を修正または無視することができます。修正を選択した場合、修正完了後に **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">再確認する</UI-TERM>** をクリックすると、システムは環境事前チェックプログラムを再度実行します。無視を選択した場合、**すべての未合格項目を無視** をクリックすると、未合格のチェック項目の状態は **無視済み** に変更され、その後 **<UI-TERM key="ocp-v2.Detail.TakeOver.Next">次のステップ</UI-TERM>** が可能になります。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>すべての未合格項目を無視すると、アップグレードが失敗する可能性があります。チェックに失敗した項目を修正してから次のステップに進むことを推奨します。</p>
   </main>

   <!-- ![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7%E9%A2%84%E6%A3%80%E6%9F%A5.png) -->

### ステップ6：OCPのアップグレード

OCPのアップグレード中、**アップグレードログ** モジュールで詳細なアップグレードログを確認できます。

* OCPのアップグレードが成功した場合、**アップグレードログ** でOCPのログイン情報（URL、ユーザー名、パスワードなど）を確認できます。

* OCPのアップグレードが失敗した場合、ログ情報を確認して失敗原因を特定し、技術サポートに連絡して対処してもらいます。インストール失敗の原因を特定し、問題を修正した後、**再アップグレード** をクリックすると、システムは失敗したアップグレード手順を再度実行します。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OCPのアップグレードには時間がかかる場合があります。しばらくお待ちください。</p>
</main>

### ステップ7（オプション）：OBDを使用して元のmetadbクラスタを引き継ぐ

OBDを使用してOCPをアップグレードした後、元のOCPのmetadbクラスタをOBDで管理したい場合は、元のmetadbクラスタの情報をOBDディレクトリにコピーするだけです。コマンドは以下のとおりです：

```bash
cp -rf ~/.ocp-installer/cluster/<metadb_cluster_name> ~/.obd/cluster/
```

ここで、`metadb_cluster_name` は元のmetadbクラスタの名前を表します。実際の状況に応じて置き換える必要があります。
