# コンテナを使用したOCPのアップグレード

このセクションでは、Dockerコンテナを使用してOCPをアップグレードする方法について説明します。

## 前提条件

OCPをデプロイしたホストにDockerがインストールされており、システムのPATHにdockerコマンドが含まれていること。現在、podman-dockerはサポートされていないため、Dockerのインストールについては [Dockerのインストール](../../300.deployment-guide/200.deploying-community-ocp/700.deploy-appendix/100.deploy-docker.md) を参照してください。

## OCPサービスの停止

OCPをアップグレードする前に、まずOCPサービスを停止する必要があります。デプロイ方法によって、OCPサービスを停止する方法は異なります。

### OCPコンテナの停止

アップグレード対象のOCPがコンテナ方式でデプロイされている場合、以下のコマンドでコンテナを停止できます：

```json
docker kill ${container_name}
```

### OCPプロセスの停止

アップグレード対象のOCPがRPMパッケージ方式でデプロイされている場合、以下のコマンドでプロセスを停止できます：

```json
# find ocp process
ps -ef | grep ocp

# kill ocp process
kill -9 ${pid_of_OCP}
```

## OCPイメージの取得

OCPをアップグレードする前に、まずOCPイメージをローカルに取得する必要があります。

* **オンライン環境**

    デプロイ環境からdockerhubに正常にアクセスできる場合は、以下のコマンドで直接OCPイメージを取得できます。

    ```bash
    docker pull oceanbase/ocp-ce:4.2.1
    ```

* **オフライン環境**

    デプロイ環境からdockerhubにアクセスできない場合は、他のdockerhubに正常にアクセスできるホストで先にイメージを取得し、その後デプロイ環境にインポートする必要があります。

    ```bash
    # execute at a host being able to access dockerhub
    docker pull oceanbase/ocp-ce:4.2.1
    docker save -o ocp-ce.tar oceanbase/ocp-ce:4.2.1
    scp ocp-ce.tar ${user}@${target}:/tmp/
    # execute at target host
    docker load < /tmp/ocp-ce.tar
    ```

OCPイメージを取得した後、以下のコマンドでイメージの取得状況を確認できます。以下の図のような結果が得られれば、イメージの取得またはインポートが成功したことを意味します。

```bash
docker images | grep ocp-ce
```

## OCPコンテナの起動

既存のOCPのmetadbを使用して、新バージョンのOCPコンテナを起動し、アップグレードを完了します。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>OCPのコンテナ名は、アップグレード前のコンテナ名と同じにすることはできません。同じ場合、起動に失敗します。</p>
</main>

以下のコマンドを使用してOCPコンテナを起動します：

```json
## set environment parameters
export OCP_CPU_COUNT=4
export OCP_MEMORY_GB=8
export OCP_METADB_HOST=xxx.xxx.xxx.xxx # do not use 127.0.0.1 or localhsot
export OCP_METADB_PORT=2881
export OCP_METADB_USER=root@ocp_meta
export OCP_METADB_PASSWORD=ocp_meta_password
export OCP_METADB_DBNAME=ocp_meta
export OCP_MONITORDB_USER=root@ocp_monitor
export OCP_MONITORDB_PASSWORD=ocp_monitor_password
export OCP_MONITORDB_DBNAME=ocp_monitor
export OCP_CONFIG_PROPERTIES=`cat << EOF
server.port:8080
ocp.site.url:http://xxx.xxx.xxx.xxx:8080
obsdk.ob.connection.mode:direct
EOF
`

# start ocp container
docker run -d --name ocp-421 \
--network host \ 
--cpu-period 100000 --cpu-quota ${OCP_CPU_COUNT}00000 --memory=${OCP_MEMORY_GB}G \
 -e OCP_METADB_HOST="${OCP_METADB_HOST}" \
 -e OCP_METADB_PORT="${OCP_METADB_PORT}" \
 -e OCP_METADB_DBNAME="${OCP_METADB_DBNAME}" \
 -e OCP_METADB_USER="${OCP_METADB_USER}" \
 -e OCP_METADB_PASSWORD="${OCP_METADB_PASSWORD}" \
 -e OCP_MONITORDB_DBNAME="${OCP_MONITORDB_DBNAME}" \
 -e OCP_MONITORDB_USER="${OCP_MONITORDB_USER}" \
 -e OCP_MONITORDB_PASSWORD="${OCP_MONITORDB_PASSWORD}" \
 -e OCP_CONFIG_PROPERTIES="${OCP_CONFIG_PROPERTIES}" \
oceanbase/ocp-ce:4.2.1
```

**環境変数の説明:**

| 変数名 | 意味 |
| --- | --- |
| OCP_CPU_COUNT | OCPコンテナに割り当てるCPUコア数。[ホスト計画](../../300.deployment-guide/200.deploying-community-ocp/300.installation-planning/200.host-planning.md)を参照してください。 |
| OCP_MEMORY_GB | OCPコンテナに割り当てるメモリ(GiB単位)。[ホスト計画](../../300.deployment-guide/200.deploying-community-ocp/300.installation-planning/200.host-planning.md)を参照してください。 |
| OCP_METADB_HOST | OCP metadbの接続アドレス。 |
| OCP_METADB_PORT | OCP metadbの接続ポート。 |
| OCP_METADB_DBNAME | OCP metadbデータベース名。 |
| OCP_METADB_USER | OCP metadbユーザー。observerに直接接続する場合はuser@tenant形式を使用できます。obproxyを使用する場合はuser@tenant#cluster形式を使用できます。 |
| OCP_METADB_PASSWORD | OCP metadbユーザーパスワード。 |
| OCP_MONITORDB_DBNAME | OCP monitordbデータベース名。 |
| OCP_MONITORDB_USER | OCP monitordbユーザー。observerに直接接続する場合はuser@tenant形式を使用できます。obproxyを使用する場合はuser@tenant#cluster形式を使用できます。 |
| OCP_MONITORDB_PASSWORD | OCP monitordbユーザーパスワード。 |
| OCP_CONFIG_PROPERTIES | OCPシステムパラメータの設定です。複数行を設定でき、各行に1つのシステムパラメータをセミコロン(:)で区切ります。 |

## OCPのアップグレード結果を確認する

1. OCPコンテナが起動した後、metadbの初期化とサービスの起動を待機する必要があります。通常は2分程度かかります。ブラウザにOCPのアクセスアドレスを入力し、ログインページが表示されればサービスの起動に成功しています。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E7%99%BB%E5%BD%95%E9%A1%B5%E9%9D%A2.png)

    OCPサービスが長時間起動しない場合は、ログを確認してOCPの状態を確認できます。

    ```json
    # use the following command to log into ocp container
    docker exec -it ocp-421 bash

    # check ocp bootstrap log
    less /home/admin/logs/ocp/bootstrap.log

    # check ocp runtime log
    less /home/admin/logs/ocp/ocp.log
    ```

2. OCPのバージョン番号を確認し、OCPがターゲットバージョンにアップグレードされたことを確認します。

    ![image.png](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%8D%87%E7%BA%A7ocp.png)
