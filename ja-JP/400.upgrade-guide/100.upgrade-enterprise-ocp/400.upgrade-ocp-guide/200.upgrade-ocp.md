# OCPのアップグレード

OCP V3.2.4以降では、OATのGUI操作により新バージョンへのアップグレードがサポートされています。

## 前提条件

アップグレード対象のOCPがOATに引き継がれていること。

## 手順

1. OATにログインします。

2. 左側のナビゲーションバーで、**製品サービス \> 製品管理** をクリックします。

3. アップグレード対象のOCPサービスを見つけ、対応する **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.Plan.Name">名称</UI-TERM>** 列の製品名をクリックして詳細ページに移動します。
   製品が多すぎる場合は、ページ上部で製品名を使って検索できます。

4. 詳細ページの右上隅にある **<UI-TERM key="ocp-v2.Detail.Component.UpgradeObproxiesModal.Upgrade">アップグレード</UI-TERM>** をクリックします。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E5%8D%87%E7%BA%A7ocp-1.png)

5. 表示された **<UI-TERM key="ocp-v2.Binlog.Component.UpgradeBinlogModal.Upgrade">アップグレード</UI-TERM>** ダイアログで、関連情報を入力します。

   関連フィールドの説明は以下の通りです：

   | **フィールド**  | **<UI-TERM key="ocp-v2.page.Property.Description">説明</UI-TERM>**   |
   |---------|------------|
   | アップグレード方法    | OATは現在、**<UI-TERM key="ocp-v2.Component.UpgradeDrawer.StopServiceUpgrade">サービス停止を伴うアップグレード</UI-TERM>** のみをサポートしています。**<UI-TERM key="ocp-v2.Component.UpgradeDrawer.StopServiceUpgrade">サービス停止を伴うアップグレード</UI-TERM>** は、業務継続性が不要な製品に適用されます。アップグレード中、OATは製品の旧バージョンサービスを停止し、外部へのサービス提供ができなくなります。 |
   | アップグレード用イメージファイル | ターゲットアップグレードイメージファイル。 |
   | ユーザー名     | OCPユーザー名。OCP V4.0.1以降のバージョンをアップグレードする場合は、OCPのユーザー名とパスワードを入力する必要はありません。その際、フォームは自動的に消えます。   |
   | パスワード      | OCPパスワード。OCP V4.0.1以降のバージョンをアップグレードする場合は、OCPのユーザー名とパスワードを入力する必要はありません。その際、フォームは自動的に消えます。 |

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E5%8D%87%E7%BA%A7ocp-2.png)

6. **<UI-TERM key="ocp-v2.Host.Component.ReinstallModal.Determine">確定</UI-TERM>** をクリックします。

7. アップグレードタスクを送信した後、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>** ページに移動し、タスク名をクリックすると詳細なタスク情報を確認できます。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E5%8D%87%E7%BA%A7ocp-3.png)

8. OCPにログインします。OCPの画面が起動できれば、主要なプロセスの初期化アップグレードは完了したことを意味しますが、時間のかかるタスクはバックグラウンドで引き続き実行されます。

   以下の3点に注意する必要があります：

   1. **<UI-TERM key="ocp-v2.page.Task.TaskList">タスクリスト</UI-TERM>** 内のアップグレードエージェントタスクが正常に実行されているかどうか。

   2. OCP-Serverのbootstrap.log（ログパスはデフォルトで `/home/admin/logs/ocp/bootstrap.log`）を確認し、`ALTER_TABLES_DELAYED` や `MIGRATIONS_DELAYED` など DELAYED マークが付いたタスクを調べ、対応するタスクがすべて END マークで終了しているかどうか、BEGINとENDはペアで現れるかどうかを確認します。

   3. アップグレードタスクが失敗した場合、OCP-Serverのocp.log（ログパスはデフォルトで `/home/admin/logs/ocp`）を確認し、「BootstrapRunListener」または「DataSourceInterceptor」というキーワードを含む関連ログに予期しないエラーがないか調べます。このログは、ocp-bootstrapがリスナーを登録した後に生成され、起動時にSpring初期化Beanイベントの処理を遮断するために使用されます。予期しないエラーが存在する場合は、テクニカルサポートにお問い合わせください。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E5%8D%87%E7%BA%A7ocp-4.png)
