# 復元の開始

このページを参照して、バックアップ済みのクラスタの復元を開始できます。

以下の3つの方法で復元を開始できます：

* **方法1**：OCPにログインし、**バックアップ・リストア > 復元**に移動し、**<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.InitiateRecovery">回復を開始する</UI-TERM>**をクリックします。

* **方法2**：OCPにログインし、クラスタの**<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>**ページに移動します。左側のナビゲーションバーで**<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">バックアップと復元</UI-TERM>**を選択し、そのクラスタの**<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">バックアップと復元</UI-TERM>**ページで**<UI-TERM key="ocp-v2.Backup.Restore.RestoreNow.InitiateRecovery">復元を開始する</UI-TERM>**をクリックします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>以下のいずれかの場合は、方法2からそのクラスタの復元を開始できません：<ul><li>そのクラスタの状態が「実行中」ではない場合。</li><li>そのクラスタにバックアップポリシーが設定されていない場合。</li></ul></p>
   </main>

* **方法3**：OCPにログインし、テナントの**<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>**ページに移動します。左側のナビゲーションバーで**<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">バックアップと復元</UI-TERM>**を選択し、そのテナントの**<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.BackupAndRestoration">バックアップと復元</UI-TERM>**ページで**<UI-TERM key="ocp-v2.Backup.Restore.RestoreNow.InitiateRecovery">復元を開始する</UI-TERM>**をクリックします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>以下のいずれかの場合は、方法3からそのテナントの復元を開始できません：<ul><li>そのテナントの状態が「実行中」ではない場合。</li><li>そのテナントにバックアップポリシーが設定されていない場合。</li></ul></p>
   </main>

## 前提条件

* **方法1** から復元を開始する場合は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * バックアップ・リストア **<UI-TERM key="ocp-v2.Restore.SamplingStrategy.New.Recovery">リストア</UI-TERM>** メニュー権限。

* **方法2** から復元を開始する場合は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Detail.Backup.BackupAndRestoration">バックアップと復元</UI-TERM>** メニュー権限。

* **方法3** から復元を開始する場合は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** リソース権限。
  * テナント **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">バックアップと復元</UI-TERM>** メニュー権限。

* 復元対象に対して、[即時バックアップ](400.backup-now/100.back-up-cluster-now.md) を実行済みであること。

* 物理バックアップを行ったOceanBaseクラスタでバックアップ・リストアを開始する場合、高バージョンから低バージョンへの復元はサポートされていません。

## 手順

以下の手順では、**方法1**を例に説明します。

1. OCPにログインします。

2. 左側のナビゲーションバーで、**バックアップ・リストア > リストア**をクリックします。

3. **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.Recovery">回復</UI-TERM>**ページで、右上の**<UI-TERM key="ocp-v2.src.constant.backup.InitiateRecovery">復元を開始する</UI-TERM>**をクリックします。

4. （オプション）グローバルページでリストアを開始する場合は、ストレージ設定を入力する必要があります。カスタム設定または既存のストレージ設定を選択できます。カスタム設定を行う場合は、以下のパラメータ設定を参照してください。既存の設定を選択した場合、**<UI-TERM key="ocp-v2.Backup.Component.StorageConfigDropdown.SelectAnExistingConfiguration">既存の設定を選択してください</UI-TERM>**をクリックすると、パラメータが自動的に入力されます。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>ネイティブのOSSストレージタイプが存在する場合、OSS方式での設定を優先することを推奨します。</p>
   </main>

    * **File**：ローカルファイルストレージ、通常はNFSです。

      | パラメータ  |  説明  |
      |--------|-------|
      | ストレージディレクトリ  | バックアップファイルが現在のメディア上に保存されるディレクトリ。  |
      | 解決ホスト  | このディレクトリにアクセス可能なホストを選択します。論理バックアップを解析する場合は、バックアップ・リストアサービスが配置されているホストを選択してください。物理バックアップを解析する場合は、V2.2.70以降のOceanBaseクラスタが配置されているホストを選択してください。**<UI-TERM key="ocp-v2.Component.StorageConfigCard.Parsing">解析</UI-TERM>**をクリックして、復元可能なクラスタのリストを取得します。  |

    * **OSS**：Alibaba Cloud OSSオブジェクトストレージ。OceanBase V2.2.76以降のバージョンでのみサポートされています。

      | パラメータ  |  説明  |
      |--------|-------|
      | ストレージディレクトリ | バックアップファイルがあるディレクトリを選択します。   |
      | アクセスドメイン名 | Alibaba Cloudストレージへのアクセスドメイン名を入力します。例：`oss-cn-hangzhou.aliyuncs.com`。  |
      | アクセスユーザー | Alibaba CloudストレージへのアクセスAccessKey IDを入力します。  |
      | アクセス秘密鍵 | Alibaba CloudストレージへのアクセスAccessKey Secretを入力します。  |
      | 解決ホスト | このディレクトリにアクセス可能なホストを選択します。論理バックアップを解析する場合は、バックアップ・リストアサービスが配置されているホストを選択してください。物理バックアップを解析する場合は、V2.2.70以降のOceanBaseクラスタが配置されているホストを選択してください。**<UI-TERM key="ocp-v2.Component.StorageConfigCard.Parsing">解析</UI-TERM>**をクリックして、復元可能なクラスタのリストを取得します。  |

    * **OBS**：Huawei Cloud OBSオブジェクトストレージ。OceanBase V3.2.3.2-105000062022090916以上、V4.0.0.0未満のバージョンでのみサポートされています。

      | パラメータ  |  説明  |
      |--------|-------|
      | ストレージディレクトリ | バックアップファイルがあるディレクトリを選択します。  |
      | アクセスドメイン名 | Huawei Cloud OBSオブジェクトへのアクセスドメイン名を入力します。例：`obs.cn-north-4.myhuaweicloud.com`。  |
      | AK | OBSストレージスペースのアクセスキーID。  |
      | SK | OBSストレージスペースのシークレットアクセスキー。  |
      | 解決ホスト | このディレクトリにアクセス可能なホストを選択します。論理バックアップを解析する場合は、バックアップ・リストアサービスが配置されているホストを選択してください。物理バックアップを解析する場合は、V2.2.70以降のOceanBaseクラスタが配置されているホストを選択してください。**<UI-TERM key="ocp-v2.Component.StorageConfigCard.Parsing">解析</UI-TERM>**をクリックして、復元可能なクラスタのリストを取得します。  |

    * **S3**：AWS S3プロトコルに互換性のあるストレージメディアをサポートしており、ネイティブAWS S3、Huawei Cloud OBS、Tianyi Cloud OBS、Google GCSなどが含まれます。OceanBase V4.2.1-BP7および4.2.3-BP1以上のバージョンでのみサポートされています。AWS S3プロトコルのストレージメディアに関する説明については、[S3プロトコルの説明](../2100.appendix/900.s3-overview.md)を参照してください。

      | パラメータ  |  説明  |
      |--------|-------|
      | ストレージディレクトリ | バックアップファイルが現在のメディア上に保存されるディレクトリ。  |
      | アクセスドメイン名 | S3ストレージスペース(Bucket)内のオブジェクトにアクセスするためのドメイン名を入力します。例：`s3.us-west-2.amazonaws.com`。  |
      | AK | S3ストレージのアクセスキーIDを入力します。  |
      | SK | S3ストレージのシークレットアクセスキーを入力します。  |
      | リージョン | S3ストレージのリージョン情報を入力します。  |
      | 解決ホスト | このディレクトリにアクセスできるホストを選択します。論理バックアップを解析する場合は、バックアップ・リストアサービスが配置されているホストを選択してください。物理バックアップを解析する場合は、V2.2.70以降のOceanBaseクラスタが配置されているホストを選択してください。**<UI-TERM key="ocp-v2.Component.StorageConfigCard.Parsing">解析</UI-TERM>** をクリックして、復元可能なクラスタのリストを取得します。  |

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>ストレージメディアがAWS S3の場合、<b>リージョン</b>情報は必須です。その他のストレージメディア（例：Huawei Cloud OBS、Tianyi Cloud OBS、Google GCSなど）は入力不要です。</p>
      </main>

5. （オプション）ログバックアップのパスを指定します。OceanBaseバージョンがV4.0以上の場合、ログバックアップ用に独立したストレージパスを指定し、データバックアップとログバックアップで異なるストレージディレクトリを使用できます。指定しない場合、データバックアップのストレージパスがデフォルトで使用されます。

6. **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.RestoreSourceInformation">ソース情報の復元</UI-TERM>** を入力します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>ストレージタイプとしてオブジェクトストレージを使用しており、復元日付に復元可能な時間がない場合は、以下のコマンドを参照してob_adminに権限を付与する必要があります：<code>setcap cap_sys_admin,cap_dac_override,cap_fowner+ep /home/admin/oceanbase/bin/ob_admin</code>。</p>
   </main>
