# リストアタスクのコピー

このセクションでは、リストアタスク情報をコピーする方法について説明します。

以下の3つの方法でリストアタスクをコピーできます：

* **方法1**：OCPにログインし、**バックアップ・リストア > リストア**に移動します。**<UI-TERM key="ocp-v2.Backup.Overview.Task.RestoreTask">タスクの復元</UI-TERM>**タブで、リストアタスクをコピーします。

* **方法2**：OCPにログインし、クラスタの**<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>**ページに移動します。左側のナビゲーションバーで**バックアップ・リストア > リストア**を選択し、**<UI-TERM key="ocp-v2.Backup.Overview.Task.RestoreTask">タスクの復元</UI-TERM>**タブを見つけて、クラスタのリストアタスクをコピーします。

* **方法3**：OCPにログインし、テナントの**<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>**ページに移動します。左側のナビゲーションバーで**バックアップ・リストア > リストア**を選択し、**<UI-TERM key="ocp-v2.Backup.Overview.Task.RestoreTask">タスクの復元</UI-TERM>**タブを見つけて、テナントのリストアタスクをコピーします。

## 前提条件

* 対象タスクの状態は **<UI-TERM key="ocp-v2.src.constant.backup.Completed">完了済み</UI-TERM>** である必要があります。

* **方法1** から復元タスクをコピーする場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ管理** または **<UI-TERM key="ocp-v2.src.util.menu.TenantManagement">テナント管理</UI-TERM>** のリソース権限。
  * バックアップ・リストア **<UI-TERM key="ocp-v2.src.constant.compute.Recovery">リストア</UI-TERM>** メニュー権限。

* **方法2** から復元タスクをコピーする場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ管理** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">バックアップと復元</UI-TERM>** メニュー権限。

* **方法3** から復元タスクをコピーする場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ管理** または **<UI-TERM key="ocp-v2.Detail.Tenant.TenantManagement">テナント管理</UI-TERM>** リソース権限。
  * テナント **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.BackupAndRestoration">バックアップと復元</UI-TERM>** メニュー権限。

## 手順

以下の手順では、**方法1**を例に説明します。

1. OCPにログインします。

2. 左側のナビゲーションバーで、**バックアップ・リストア > リストア**をクリックします。システムはデフォルトで**<UI-TERM key="ocp-v2.Backup.Overview.Task.RestoreTask">タスクの復元</UI-TERM>**タブに移動します。

3. **<UI-TERM key="ocp-v2.Backup.Overview.Task.RestoreTask">タスクの復元</UI-TERM>**タブで、対象タスクを見つけて、その**<UI-TERM key="ocp-v2.Inspection.Component.TaskTable.Operation">操作</UI-TERM>**列の**<UI-TERM key="ocp-v2.component.TenantList.Copy">コピー</UI-TERM>**ボタンをクリックします。

4. **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.CopyAndRestoreTasks">復元タスクをコピーする</UI-TERM>**ページで、**<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.RestoreSourceInformation">ソース情報の復元</UI-TERM>**を入力します。

   * テナントのリストア

      |  パラメータ   |              説明               |
      |-------|-------------------------------|
      | ソースクラスタ   | デフォルトは現在のテナントが存在するクラスタ。 |
      | ソーステナント   | デフォルトは現在のテナント。                    |
      | リストアオブジェクト   | **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.UpgradeArbitrationGroup.Tenant">テナント</UI-TERM>**を選択してください。                    |
      | リストア日付  | 表示された復元可能時間帯内である必要があります。                 |

   * データベースのリストア

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>データベースのリストアはOceanBase 4.xでのみサポートされています。データベースのリストアはテーブルのリストアに依存し、両者でサポートされるテーブルの種類は同じです。</p>
      </main>

      |  パラメータ   |              説明               |
      |-------|-------------------------------|
      | ソースクラスタ   | デフォルトは現在のテナントが存在するクラスタ。 |
      | ソーステナント   | デフォルトは現在のテナント。                    |
      | リストアオブジェクト   | **<UI-TERM key="ocp-v2.Backup.Component.RestoreTenantCard.Library">データベース</UI-TERM>**を選択してください。                    |
      | リストア日付  | 表示された復元可能時間帯内である必要があります。                 |
      | リストアデータベースオブジェクト | 左側の**<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.RecoverableObject">復元可能なオブジェクト</UI-TERM>**から復元したいデータベースを選択し、**>**をクリックして右側の**<UI-TERM key="ocp-v2.component.TreeTransfer.SelectedObjects">選択済みのオブジェクト</UI-TERM>**に追加します。データベース名は一意である必要があります。OCPではデータベースの名前変更をサポートしています。  |

      <h4>説明</h4>
      <p>最大200個のデータベースオブジェクトを選択できます。</p>
      </main>

   * テーブルのリストア

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><ul><li>ユーザーテーブルのみのリストアをサポートしており、カラムストアテーブル、一時テーブル、ビュー、マテリアライズドビュー、マテリアライズドビューのログ、インデックスなどを個別にリストアすることはサポートされていません。</li><li>テーブルデータのリストアが成功した場合、テーブルのリストアも成功したことを意味します。インデックス、制約、またはその他の関連するスキーマのリストアが失敗してもかまいません。</li></ul></p>
      </main>

      |  パラメータ   |              説明               |
      |-------|-------------------------------|
      | ソースクラスタ   | デフォルトは現在のテナントが存在するクラスタです。 |
      | ソーステナント   | デフォルトは現在のテナントです。                    |
      | 復元オブジェクト   | **<UI-TERM key="ocp-v2.src.constant.tenant.Table">テーブル</UI-TERM>**を選択してください。                    |
      | 復元日付  | 表示された復元可能な期間内である必要があります。                 |
      | 復元テーブルオブジェクト | 左側の**<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.RecoverableObject">復元可能なオブジェクト</UI-TERM>**から復元したいテーブルを選択し、**>**をクリックして右側の**<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.SelectedObjects">選択した対象</UI-TERM>**に追加します。テーブル名は一意である必要があります。OCPではテーブルの名前変更が可能です。  |

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>最大200個のテーブルオブジェクトを選択できます。</p>

6. **<UI-TERM key="ocp-v2.Backup.Component.RestoreTenantCard.RestoreTargetInformation">目標情報の復元</UI-TERM>**を入力します。

   * テナントの復元

      |  パラメータ   |              説明               |
      |-------|-------------------------------|
      | ターゲットクラスタ   | ターゲットクラスタを選択してください。 |
      | ターゲットテナント   | ターゲットテナントを選択してください。                    |
      | 各ZoneのUnit数   | Zone内の最小OBServer数によって、Unitの最大設定数が決定します。                    |

   * データベースの復元

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>データベース・テーブルの復元プロセスでは、ターゲットクラスタ内に補助テナントを作成する必要があります。補助テナントの仕様はソーステナントと同じにすることを推奨します。また、ターゲットクラスタに十分なCPU/Memory/ディスクリソースがあることを確認してください。リソース不足により、復元が遅延または失敗する可能性があります。データベース・テーブルの復元完了後、システムはデフォルトで補助テナントを削除します。</p>
      </main>

      |  パラメータ   |              説明               |
      |-------|-------------------------------|
      | ターゲットクラスタ   | ターゲットクラスタを選択してください。 |
      | ターゲットテナント   | ターゲットテナントを選択してください。                    |
      | 各ZoneのUnit数   | Zone内の最小OBServer数によって、Unitの最大設定数が決定します。                    |

      |  パラメータ   |              説明               |
      |-------|-------------------------------|
      | ターゲットクラスタ   | ターゲットクラスタを選択してください。 |
      | ターゲットテナント   | ターゲットテナントを選択してください。                    |
      | 各ZoneのUnit数   | Zone内の最小OBServer数によって、Unitの最大設定数が決定します。                    |

6. 以下のパラメータを入力してゾーンを設定し、ゾーンの優先順位を付けます。

   |   パラメータ    | 説明   |
   |---------|---|
   | レプリカタイプ    | 値の範囲： <ul><li>フル機能レプリカ：現在サポートされている通常レプリカで、トランザクションログ、MemTable、SSTableなど、すべての完全なデータと機能を備えています。いつでも迅速にリーダーに切り替えて外部へのサービス提供が可能です。</li><li>ログ専用レプリカ：ログのみを含み、MemTableやSSTableはありません。ログの投票に参加し、外部へのログサービスを提供します。他のレプリカの復元にも関与できますが、自らがリーダーとなってデータベースサービスを提供することはできません。   </li><li>読み取り専用レプリカ：完全なログ、MemTable、SSTableなどを含みます。業務上、読み取りデータの一貫性に対する要求が高くない場合に選択することを推奨します。 </li></ul>   |
   | ユニット構成 | このレプリカが使用するリソース構成。<ul><li>既存の構成を選択することもできます。</li><li>実際のニーズに応じて新しい構成を作成してから選択することもできます。 </li></ul>  |
   | ユニット数 | このレプリカが使用するリソース数。<blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">注意</UI-TERM>**</br>復元対象としてV4.0以上のクラスタを選択した場合、単一ゾーンのユニット数の設定はサポートされません。ここで入力するユニット数は、新規作成される復元テナント内のすべてのゾーンに適用されます。</blockquote>|

8. **<UI-TERM key="ocp-v2.Alarm.Template.Copy">コピー</UI-TERM>** をクリックします。
