# クラスタレベルのバックアップポリシーを新規作成する

クラスタレベルのバックアップポリシーは、テナントレベルのバックアップポリシーが設定されていないテナントにのみ適用されます。このようなテナントに対してクラスタレベルのバックアップポリシーを設定することで、統一的な管理を実現できます。

以下の3つの方法からクラスタレベルのバックアップポリシーを新規作成できます：

* **方法1**：OCPにログインし、**バックアップ・リストア > バックアップ**に移動します。ページの右上にある **<UI-TERM key="ocp-v2.Backup.Overview.Welcome.CreateABackupPolicy">新規バックアップポリシー</UI-TERM>** のドロップダウンリストから、**<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateAClusterLevelBackupPolicy">新しいクラスタレベルのバックアップポリシーを作成する</UI-TERM>** を選択します。

* **方法2**：OCPにログインし、クラスタの **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** ページに移動します。左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.constant.package.BackupAndRestoration">バックアップと復元</UI-TERM>** を選択し、**<UI-TERM key="ocp-v2.Detail.Backup.CreateAClusterLevelBackupPolicy">新しいクラスタレベルのバックアップポリシーを作成する</UI-TERM>** をクリックします。

* **方法3**：OCPにログインし、テナントの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動します。左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">バックアップと復元</UI-TERM>** を選択し、**<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateAClusterLevelBackupPolicy">新しいクラスタレベルのバックアップポリシーを作成する</UI-TERM>** をクリックします。

<main id="notice" type='explain'>
<h4>説明</h4>
<p><b>方法3</b> を使用してクラスタレベルのバックアップポリシーを新規作成できるのは、テナントおよび所属クラスタにバックアップポリシーが設定されていない場合のみです。</p>
</main>

## 前提条件

* **エントリ1** からクラスタレベルのバックアップポリシーを新規作成する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * バックアップ・リストア **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.Backup">バックアップ</UI-TERM>** メニュー権限。

* **エントリ2** からクラスタレベルのバックアップポリシーを新規作成する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">バックアップと復元</UI-TERM>** メニュー権限。

* **エントリ3** からクラスタレベルのバックアップポリシーを新規作成する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** リソース権限。
  * テナント **<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">バックアップと復元</UI-TERM>** メニュー権限。

* OceanBaseは、ロックされている状態のテナントのバックアップをサポートしていません。

## 手順

以下の手順では、**エントリー１**を例に説明します。

1. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.Detail.Backup.BackupAndRestoration">バックアップと復元</UI-TERM>** **\>** **<UI-TERM key="ocp-v2.src.constant.backup.Backup">バックアップ</UI-TERM>** をクリックします。

2. **<UI-TERM key="ocp-v2.Component.BackupStrategyCard.Backup">バックアップ</UI-TERM>** ページで、**<UI-TERM key="ocp-v2.src.constant.backup.CreateABackupPolicy">バックアップポリシーを新規作成</UI-TERM>** の上にカーソルを合わせ、**<UI-TERM key="ocp-v2.Backup.AddClusterStrategy.CreateAClusterLevelBackupPolicy">新しいクラスタレベルのバックアップポリシーを作成する</UI-TERM>** をクリックします。

3. ドロップダウンリストからバックアップ対象のクラスタを選択します。

   * バックアップ対象のクラスタがV2.2.60より古い場合、バックアップ方式は **<UI-TERM key="ocp-v2.Backup.Component.BackupNowDrawer.LogicalBackup">論理バックアップ</UI-TERM>** となります。

   * バックアップ対象のクラスタがV2.2.60以上の場合、バックアップ方式は **<UI-TERM key="ocp-v2.src.constant.backup.PhysicalBackup">物理バックアップ</UI-TERM>** となります。

4. 以下のパラメータを入力してストレージ設定を行い、**<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">テスト</UI-TERM>** をクリックします。

   * 論理バックアップの場合、[サービスのインストール](../../1000.manage-backup-and-recovery-service/200.installation-services.md)で設定したストレージを選択します。

     バックアップサービスがインストールされていない場合は、事前にインストールしてください。サービスのインストールについては、[サービスのインストール](../../1000.manage-backup-and-recovery-service/200.installation-services.md)を参照してください。

   * 物理バックアップの場合、既存のストレージ設定を選択するか、カスタマイズできます。カスタマイズする場合は、以下のパラメータを参照してください。既存の設定を選択する場合、**<UI-TERM key="ocp-v2.Backup.Component.StorageConfigDropdown.SelectAnExistingConfiguration">既存の設定を選択してください</UI-TERM>** をクリックすると、以下のパラメータが自動的に入力されます。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>ネイティブのOSSストレージタイプが存在する場合、OSS方式を優先的に使用することを推奨します。</p>
      </main>

      * **File**：ローカルファイルストレージ、通常はNFSです。

         | パラメータ  |  説明  |
         |--------|-------|
         | ストレージディレクトリ  |  バックアップファイルが現在のメディアに保存されるディレクトリ。  |
         | バックアップストレージ容量アラートしきい値  |  バックアップストレージ容量のアラートしきい値を設定します。デフォルト値は80%です。  |

      * **OSS**：Alibaba Cloud OSSオブジェクトストレージ。OceanBase V2.2.76以降のバージョンでのみサポートされます。

         | パラメータ  |  説明  |
         |--------|-------|
         | ストレージディレクトリ  |  バックアップファイルが現在のメディアに保存されるディレクトリ。  |
         | アクセスドメイン名  |  Alibaba Cloudストレージ側へのアクセスドメイン名を入力します。例：`oss-cn-hangzhou.aliyuncs.com`。  |
         | アクセスユーザー  |  Alibaba Cloudストレージ側へのアクセスAccessKey IDを入力します。  |
         | アクセスシークレットキー  |  Alibaba Cloudストレージ側へのアクセスAccessKey Secretを入力します。  |
         | 上級設定  |  OSSプロトコルを使用するオブジェクトストレージにのみ適用されます。<ul><li>checksum_type データチェックサムタイプの設定：md5（デフォルト）/no_checksum。サポートされているOceanBaseのバージョン範囲は[V4.2.1.6, V4.2.2.0)、[V4.2.3.0, +∞)です。</li><li>enable_worm OceanBaseデータベースがBucketの保持ポリシー(WORMポリシー)に従ってそのパスに対する書き込みおよび削除操作を実行するかどうかを指定します：false(デフォルト)/true。サポートされているOceanBaseのバージョン範囲は[V4.2.5.7, V4.3.0.0)、[V4.3.5.2, +∞)です。<main id="notice" type='explain'><h4>説明</h4><p>OSS準拠の保持ポリシーはWORM(Write Once Read Many)特性を備えており、データを削除や改ざんが不可能な方法で保存・利用するユーザーのニーズを満たします。特定の期間内、どのユーザー(リソース所有者を含む)もOSSのあるBucket内のObjectを変更または削除できないようにしたい場合、そのBucketにWORM保持ポリシーを設定できます。保持ポリシーで指定されたObjectの保持期間が満了するまで、Bucket内でのObjectのアップロードと読み取りのみがサポートされます。Objectの保持期間が満了した後に、Objectを変更または削除できます。</p></main></li></ul>  |

      * **OBS**：Huawei Cloud OBSオブジェクトストレージ。OceanBase V3.2.3.2-105000062022090916以上、V4.0.0.0未満のバージョンでのみサポートされます。

         | パラメータ  |  説明  |
         |--------|-------|
         | ストレージディレクトリ  |  バックアップファイルが現在のメディアに保存されるディレクトリ。  |
         | アクセスドメイン名  |  Huawei Cloud OBSオブジェクトへのアクセスドメイン名を入力します。例：`obs.cn-north-4.myhuaweicloud.com`。  |

      * **S3**: AWS S3プロトコルに互換性のあるストレージメディアをサポートしており、ネイティブAWS S3、Huawei Cloud OBS、Tianyi Cloud OBS、Google GCSなどが含まれます。OceanBase V4.2.1-BP7およびV4.2.3-BP1(含)以降のバージョンでのみサポートされています。AWS S3プロトコルのストレージメディアの説明については、[S3プロトコルの説明](../../../2100.appendix/900.s3-overview.md)を参照してください。

         | パラメータ  |  説明  |
         |--------|-------|
         | ストレージディレクトリ  |  バックアップファイルが現在のメディア上に保存されるディレクトリ。  |
         | アクセスドメイン名  |  S3ストレージ容量(Bucket)内のオブジェクトにアクセスするためのドメイン名を入力します。例：`s3.us-west-2.amazonaws.com`。  |
         | AK  |  S3ストレージ容量の秘密キーIDを入力します。  |
         | SK  |  S3ストレージ容量のアクセスキーを入力します。  |
         | リージョン  |  S3ストレージ容量のリージョン情報を入力します。  |
         | 上級設定  |  S3互換プロトコルを使用するオブジェクトストレージにのみ有効です。<ul><li>delete_mode ファイル削除モード：delete（デフォルト）/tagging、サポートされているOceanBaseバージョン範囲は[V4.2.3.0, V4.2.5.0)、[V4.3.0.0, +∞)です。</li><li>checksum_type データチェックサムタイプ：md5（デフォルト）/crc32、サポートされているOceanBaseバージョン範囲は[V4.2.1.6, V4.2.2.0)、[V4.2.3.0, +∞)です。</li><li>addressing_model リソース位置付け方式：virtual_hosted_style（デフォルト）/path_style、サポートされているOceanBaseバージョン範囲は[V4.2.1.9, V4.2.2.0)、[V4.2.5.1, V4.3.0.0)、[V4.3.5.0, +∞)です。</li></ul>  |

         <main id="notice" type='notice'>
         <h4>注意</h4>
         <p>ストレージメディアがAWS S3の場合、<b>リージョン</b>情報は必須設定項目です。その他のストレージメディア、例えばHuawei Cloud OBS、Tianyi Cloud OBS、Google GCSなどは入力不要です。</p>
         </main>

   * **<UI-TERM key="ocp-v2.Component.StorageConfigCard.LogBackupStorage">ログバックアップストレージ</UI-TERM>**: OceanBaseバージョンがV4.0以上の場合、ログアーカイブ用に個別のストレージ設定を指定できます。デフォルトでは**データバックアップと同じ**が選択されており、データバックアップと同じストレージ設定を使用します。異なるストレージパスを使用する必要がある場合は、**個別設定**を選択し、上記のデータバックアップストレージ設定方法を参照して設定してください。

5. スケジュール設定を行います。

   * スケジュール周期：週または月単位です。スケジュール周期が月の場合、最大で10日間を選択できます。

   * 物理バックアップでログバックアップをオフにした後、システムはデータバックアップ開始前にログバックアップを起動し、データバックアップ完了後にログバックアップを停止します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>OceanBaseバージョンがV4.0以上の場合、手順4でログアーカイブ用に個別のストレージ設定を指定することで、ログバックアップとデータバックアップで異なるストレージパスを使用できます。</p>
   </main>

   ![Image 37](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/%E9%9B%86%E7%BE%A4-%E8%B0%83%E5%BA%A6%E9%85%8D%E7%BD%AE.png)

6. 期限切れバックアップクリーンアップのスケジュール設定を行います。

   ![Image 52](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428171.png)

7. アラートしきい値設定を行います。データバックアップタイムアウトアラートしきい値、ログバックアップ遅延アラートしきい値、成功なしデータバックアップアラート日数を設定できます。設定成功後、実際の出力がしきい値を超えた場合、アラート通知を受け取ります。

   ![Image 53](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E6%8A%A5%E8%AD%A6%E9%98%88%E5%80%BC%E9%85%8D%E7%BD%AE.png)

8. （オプション）二次バックアップ設定を行います。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>OceanBase 4.x系では二次バックアップはサポートされていません。
   </p>
   </main>

   バックアップデータファイルとログファイルを別のディレクトリにバックアップすることを選択できます。二次バックアップを行う場合は、**<UI-TERM key="ocp-v2.Component.AddBackupStrategy.SecondaryBackup">二次バックアップ</UI-TERM>**スイッチをオンにしてください。

   1. 二次バックアップのストレージ設定を行います。

      ![Image 54](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428178.png)

   2. 二次バックアップのスケジュール設定を行います。

      ![09221429](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/2859542361/p328243.png)

9. **<UI-TERM key="ocp-v2.src.constant.alarm.Create">新規作成</UI-TERM>** をクリックし、クラスタレベルのバックアップポリシーの作成を完了します。
