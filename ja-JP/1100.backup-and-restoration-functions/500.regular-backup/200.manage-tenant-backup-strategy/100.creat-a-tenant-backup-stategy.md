# テナントレベルのバックアップポリシーを作成する

OCPは、テナント単位で個別のバックアップ・リストアポリシーを設定できます。テナントに対してテナントレベルのバックアップポリシーを作成すると、そのテナントはクラスタレベルのバックアップポリシーの影響を受けなくなります。

以下の2つの方法でテナントレベルのバックアップポリシーを新規作成できます：

* **方法1**：OCPにログインし、左側のナビゲーションバーから**バックアップ・リストア > バックアップ**を選択して、**<UI-TERM key="ocp-v2.Component.AddBackupStrategy.Backup">バックアップ</UI-TERM>**の概要ページに移動します。

* **方法2**：OCPにログインし、テナントの**<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>**ページに移動します。左側のナビゲーションバーから**<UI-TERM key="ocp-v2.Backup.BackupStrategy.Edit.BackupAndRestoration">バックアップと復元</UI-TERM>**を選択し、テナントの**<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">バックアップと復元</UI-TERM>**詳細ページに移動します。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>テナントが属するクラスタに既にクラスタレベルのバックアップポリシーが存在する場合、新規にテナントレベルのバックアップポリシーを作成すると、デフォルトでそのクラスタレベルのバックアップポリシーの内容が入力されます。</p>
</main>

## 前提条件

* **エントリ1** からテナントレベルのバックアップポリシーを作成する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * バックアップ・リストア **<UI-TERM key="ocp-v2.src.constant.compute.Backup">バックアップ</UI-TERM>** メニュー権限。

* **エントリ2** からテナントレベルのバックアップポリシーを作成する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">バックアップと復元</UI-TERM>** メニュー権限。

* テナントレベルのバックアップポリシーの作成は、テナントが属するクラスタがV4.0.0以降である場合にのみサポートされます。

* OceanBaseは、ロック状態のテナントのバックアップをサポートしていません。

* sysテナントでは、テナントレベルのバックアップポリシーを作成できません。

## 手順

以下の手順では、**入口一**を例に説明します。

1. 左側のナビゲーションバーで、**バックアップ・リストア > バックアップ**をクリックします。

2. **<UI-TERM key="ocp-v2.src.constant.compute.Backup">バックアップ</UI-TERM>**ページで、**<UI-TERM key="ocp-v2.Backup.Overview.Statistics.CreateABackupPolicy">バックアップポリシーを新規作成</UI-TERM>**にカーソルを合わせ、**<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateATenantLevelBackupPolicy">新規テナントレベルのバックアップポリシー</UI-TERM>**をクリックします。

3. プルダウンボックスで、バックアップ対象のテナントを選択します。

   * テナントが属するクラスタがV2.2.60以下の場合、バックアップ方式は**<UI-TERM key="ocp-v2.Component.AddBackupStrategy.LogicalBackup">論理バックアップ</UI-TERM>**となります。

   * テナントが属するクラスタがV2.2.60以上の場合、バックアップ方式は**<UI-TERM key="ocp-v2.src.constant.backup.PhysicalBackup">物理バックアップ</UI-TERM>**となります。

4. 以下のパラメータを入力してストレージ設定を行い、**<UI-TERM key="ocp-v2.Component.StorageConfigCard.Test">テスト</UI-TERM>**をクリックします。

   * 論理バックアップの場合、[サービスのインストール](../../1000.manage-backup-and-recovery-service/200.installation-services.md)で設定したストレージを選択します。

     バックアップサービスがインストールされていない場合は、事前にインストールしてください。サービスのインストールについては、[サービスのインストール](../../1000.manage-backup-and-recovery-service/200.installation-services.md)を参照してください。

   * 物理バックアップの場合、カスタムストレージまたは既存のストレージを選択できます。カスタムストレージを選択する場合は、以下のパラメータを参照して設定してください。既存のストレージを選択する場合、**<UI-TERM key="ocp-v2.Backup.Component.StorageConfigDropdown.SelectAnExistingConfiguration">既存の設定を選択してください</UI-TERM>**をクリックすると、以下のパラメータが自動的に入力されます。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p>ネイティブのOSSストレージタイプが存在する場合、優先的にOSS方式での設定を推奨します。</p>
      </main>

      * **File**：ローカルファイルストレージ、通常はNFSです。

         | パラメータ  |  説明  |
         |--------|-------|
         |  ストレージディレクトリ  |  バックアップファイルが現在のメディア上に保存されるディレクトリです。テナントが属するクラスタに既存のバックアップ・リストアポリシーがある場合、このストレージディレクトリはクラスタと一致させることを推奨します。そうでない場合、テナントのバックアップデータ統計に影響します。  |
         |  バックアップストレージ容量アラートしきい値  |  バックアップストレージ容量のアラートしきい値を設定します。デフォルト値は80%です。  |

      * **OSS**：Alibaba Cloud OSSオブジェクトストレージ。OceanBase V2.2.76以降のバージョンでのみサポートされます。

         | パラメータ  |  説明  |
         |--------|-------|
         |  ストレージディレクトリ  |  バックアップファイルが現在のメディア上に保存されるディレクトリです。テナントが属するクラスタに既存のバックアップ・リストアポリシーがある場合、このストレージディレクトリはクラスタと一致させることを推奨します。そうでない場合、テナントのバックアップデータ統計に影響します。  |
         |  アクセスドメイン名  |  Alibaba Cloudストレージ側へのアクセスドメイン名を入力します。例：`oss-cn-hangzhou.aliyuncs.com`。  |
         |  アクセスユーザー  |  Alibaba Cloudストレージ側へのアクセスAccessKey IDを入力します。  |
         |  アクセス秘密鍵  |  Alibaba Cloudストレージ側へのアクセスAccessKey Secretを入力します。  |
         |  詳細設定  |  OSSプロトコルを使用するオブジェクトストレージにのみ適用されます。<ul><li>checksum_type データチェックサムタイプの設定：md5（デフォルト）/no_checksum。サポートされているOceanBaseバージョン範囲は[V4.2.1.6, V4.2.2.0)、[V4.2.3.0, +∞)です。</li><li>enable_worm OceanBaseデータベースがBucketの保持ポリシー(WORMポリシー)に従ってそのパスに対する書き込みおよび削除操作を実行するかどうかを指定します：false（デフォルト）/true。サポートされているOceanBaseバージョン範囲は[V4.2.5.7, V4.3.0.0)、[V4.3.5.2, +∞)です。<main id="notice" type='explain'><h4>説明</h4><p>OSS準拠の保持ポリシーはWORM（Write Once Read Many）特性を備えており、データを削除や改ざんが不可能な方法で保存・利用するユーザーのニーズを満たします。特定の期間内、どのユーザー（リソース所有者を含む）もOSSのあるBucket内のObjectを変更または削除できないようにしたい場合、そのBucketにWORM保持ポリシーを設定できます。保持ポリシーで指定されたObjectの保持期間が満了するまで、Bucket内でのObjectのアップロードと読み取りのみがサポートされます。Objectの保持期間が満了した後に、Objectを変更または削除できます。</p></main></li></ul>  |

      * **S3**：AWS S3プロトコルに互換性のあるストレージメディアをサポートしています。これには、ネイティブAWS S3、Huawei Cloud OBS、Tianyi Cloud OBS、Google GCSなどが含まれます。OceanBase V4.2.1-BP7およびV4.2.3-BP1(含)以降のバージョンでのみサポートされます。AWS S3プロトコルのストレージメディアに関する説明については、[S3プロトコルの説明](../../../2100.appendix/900.s3-overview.md)を参照してください。

         | パラメータ  |  説明  |
         |--------|-------|
         |  ストレージディレクトリ  |  バックアップファイルが現在のメディア上に保存されるディレクトリです。テナントが属するクラスタに既存のバックアップ・リストアポリシーがある場合、このストレージディレクトリはクラスタと一致させることを推奨します。そうでない場合、テナントのバックアップデータ統計に影響します。  |
         |  アクセスドメイン名  |  S3ストレージ領域(Bucket)内のObjectにアクセスするためのドメイン名を入力します。例：`s3.us-west-2.amazonaws.com`。  |
         |  AK  |  S3ストレージのキーIDを入力します。  |
         |  SK  |  S3ストレージのアクセスキーを入力します。  |
         |  リージョン  |  S3ストレージのリージョン情報を入力します。  |
         | 詳細設定  |  S3互換プロトコルを使用するオブジェクトストレージにのみ適用されます。<ul><li>delete_modeファイル削除モード：delete（デフォルト）/tagging、サポートされているOceanBaseバージョン範囲は[V4.2.3.0, V4.2.5.0)、[V4.3.0.0, +∞)です。</li><li>checksum_typeデータチェックサムタイプ：md5（デフォルト）/crc32、サポートされているOceanBaseバージョン範囲は[V4.2.1.6, V4.2.2.0)、[V4.2.3.0, +∞)です。</li><li>addressing_modelリソース位置付け方式：virtual_hosted_style（デフォルト）/path_style、サポートされているOceanBaseバージョン範囲は[V4.2.1.9, V4.2.2.0)、[V4.2.5.1, V4.3.0.0)、[V4.3.5.0, +∞)です。</li></ul>  |

         <main id="notice" type='notice'>
         <h4>注意</h4>
         <p>ストレージメディアがAWS S3の場合、<b>リージョン</b>情報は必須項目です。その他のストレージメディア（Huawei Cloud OBS、Tianyi Cloud OBS、Google GCSなど）では入力不要です。</p>
         </main>

      * **<UI-TERM key="ocp-v2.Component.StorageConfigCard.LogBackupStorage">ログバックアップストレージ</UI-TERM>**：OceanBaseバージョンがV4.0以上の場合、ログアーカイブに対して個別のストレージ設定を指定できます。デフォルトでは**データバックアップと同じ**が選択されており、データバックアップと同じストレージ設定を使用します。異なるストレージパスを使用する必要がある場合は、**個別設定**を選択し、上記のデータバックアップストレージ設定方法を参照して設定してください。

5. （オプション）カスタムバックアップ範囲機能のスイッチをオンにします。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <ul>
    <li>現在、カスタムバックアップ範囲をサポートしているOceanBaseバージョンは：[V4.2.1.11, V4.2.0) および [V4.2.5.2, V4.3.0) です。</li>
    <li>テナントレベルのバックアップポリシーが存在する場合、即時バックアップはカスタムバックアップ範囲をサポートしません。</li>
    <li>データバックアップはデフォルトでフォロワーレプリカからバックアップデータを読み取り、ログバックアップはデフォルトでリーダーレプリカからバックアップデータを読み取ります。</li>
    <li>バックアップ対象のゾーンを選択する際は、優先順位を設定する必要があります。設定しない場合、バックアップ失敗やデータセンター間のトラフィックが発生する可能性があります。</li>
    <li>カスタムバックアップ範囲機能のスイッチをオンにした場合、Primary Zoneをrandomに設定することは推奨されません。</li>
    </ul>
    </main>

   1. データバックアップのタイプを選択します：Zone、リージョン、またはデータセンター。次に、シャトルボックスを使用してZone、リージョン、またはデータセンターの優先順位を設定します。

   2. ログバックアップのタイプを選択します：Zone、リージョン、またはデータセンター。次に、シャトルボックスを使用してZone、リージョン、またはデータセンターの優先順位を設定します。

      ![Image 49](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/%E8%87%AA%E5%AE%9A%E4%B9%89%E5%A4%87%E4%BB%BD%E8%8C%83%E5%9B%B4.jpg)

6. スケジュール設定を行います。

   * スケジュール周期：週または月単位です。スケジュール周期が月の場合、最大で10日間を選択できます。

   * 物理バックアップでログバックアップをオフに選択すると、システムはデータバックアップ開始前にログバックアップを起動し、データバックアップ終了後にログバックアップを停止します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>OceanBaseバージョンがV4.0以上の場合、手順4でログアーカイブに対して個別のストレージ設定を指定できます。これにより、ログバックアップとデータバックアップで異なるストレージパスを使用できます。</p>
   </main>

   ![Image 37](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/%E8%B0%83%E5%BA%A6%E9%85%8D%E7%BD%AE.png)

7. 期限切れバックアップのクリーンアップスケジュール設定を行います。

   ![Image 52](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428171.png)

8. アラートしきい値設定を行います。データバックアップタイムアウトアラートしきい値、ログバックアップ遅延アラートしきい値、成功しないデータバックアップのアラート日数を設定できます。設定成功後、実際の出力がしきい値を超えた場合、アラート通知を受け取ります。

   ![Image 53](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E6%8A%A5%E8%AD%A6%E9%98%88%E5%80%BC%E9%85%8D%E7%BD%AE.png)

9. （オプション）セカンダリバックアップの設定を行います。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>OceanBase 4.x系では、セカンダリバックアップはサポートされていません。
   </p>
   </main>

   バックアップデータファイルとログファイルを別のディレクトリにバックアップすることができます。二次バックアップが必要な場合は、**<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.SecondaryBackup">二次バックアップ</UI-TERM>**スイッチをオンにします。

   1. 二次バックアップのストレージ設定を行います。

      ![Image 54](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/1307669461/p428178.png)

   2. 二次バックアップのスケジュール設定を行います。

      ![09221429](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/2859542361/p328243.png)

10. **<UI-TERM key="ocp-v2.src.constant.alarm.Create">新規作成</UI-TERM>**をクリックして、テナントレベルのバックアップポリシーの作成を完了します。
