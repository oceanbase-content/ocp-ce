# グラフィカルインターフェースを使用したOCPのデプロイ

このセクションでは、OceanBase Deployer（OBD）のグラフィカルインターフェースを使用してOCPをデプロイする方法について説明します。

MetaDBはOCPの重要な構成要素であり、OCPがメタ情報や監視データを管理するための基盤ストレージ機能を提供します。OCP-ServerはMetaDBのデータを呼び出すことで、OceanBaseデータベースのライフサイクル全体を管理するサービスを提供します。OCPのデプロイには、以下のいずれかのMetaDB設定方法を選択できます：

* （推奨）OCPのMetaDBとして、新しいOceanBaseデータベースを作成します。

* 既存のOceanBaseデータベースをOCPのMetaDBとして使用します。

## 前提条件

* OCP-CEのバージョンV4.0.3以降のみがデプロイをサポートしています。

* Java環境がインストールおよび設定済みであること。現在、JDK1.8のみがサポートされており、ビルドバージョン番号は161以上である必要があります。

* OCPホストに既存バージョンのOCPソフトウェアパッケージの解凍ディレクトリが存在する場合、新しいバージョンのソフトウェアパッケージの解凍ディレクトリと混同を避けるため、古い解凍ディレクトリを名前変更または削除する必要があります。

* [インストールの準備](400.installation-preparation.md) を参照して、`ocp-all-in-one-4.4.2-YYYYMMDDhhmmss.el7.x86_64.tar.gz` ソフトウェアパッケージを取得します。このパッケージをOCPホストの任意のディレクトリにアップロードし、以下のコマンドを実行して解凍します。

    ```bash
    tar zxf ocp-all-in-one-4.4.2-YYYYMMDDhhmmss.el7.x86_64.tar.gz
    ```

## （推奨）OCPのMetaDBとして新しいOceanBaseデータベースを作成する

### ステップ１：obdを起動する

1. OCPホストにログインします。

2. 以下のコマンドを実行して、解凍したソフトウェアパッケージの`bin`ディレクトリに移動し、デプロイプログラムをインストールします。

    ```bash
    cd ocp-all-in-one/bin && bash install.sh
    ```

3. 以下のコマンドを実行して、環境変数を有効にします。

    ```bash
    source ~/.oceanbase-all-in-one/bin/env.sh
    ```

4. `obd web install` を実行し、戻りメッセージからデプロイウィザードページのIPアドレスを取得します。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/install.png)

### ステップ2：OCPデプロイウィザードページにアクセスする

1. ブラウザで**ステップ１**で取得したIPアドレスにアクセスし、デプロイウィザードページに移動して、**体験を開始**をクリックします。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%83%A8%E7%BD%B2%E5%90%91%E5%AF%BC%E9%A1%B5%E9%9D%A2.png)

2. **OCP**製品を選択し、**<UI-TERM key="ocp-v2.Detail.Monitor.Determine">確定</UI-TERM>**をクリックします。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%80%89%E6%8B%A9%E5%AE%89%E8%A3%85%E4%BA%A7%E5%93%81.png)

3. **新しいOceanBaseデータベースを作成**を選択し、これをOCPのMetaDBとして使用します。そして、**<UI-TERM key="ocp-v2.page.Information.Ok">確定</UI-TERM>**をクリックします。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%88%9B%E5%BB%BA%E6%96%B0%E7%9A%84metadb.png)

### ステップ3：デプロイ関連情報を設定する

1. 管理対象のOceanBaseクラスタ名をカスタマイズします。

    この名前は一意でなければならず、クラスタ名は英字で始まり、英字または数字で終わる2～32文字の長さである必要があります。

2. デプロイする製品バージョンを選択します。

    OceanBaseとOBProxyのバージョンは関連付けられています。例えば、V4.1.0以降のOceanBaseデータベースをデプロイする場合、V4.1.0以降のOBProxyのみをデプロイできます。

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/440/%E9%83%A8%E7%BD%B2%E9%85%8D%E7%BD%AE.png)

### ステップ4：MetaDBを設定する

新しいMetaDBを作成します。OCP-ServerはローカルのMetaDBにアクセスすることで、サービスの信頼性を向上させます。

1. デプロイユーザーを設定します。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>オペレーティングシステムのユーザー権限が競合するのを避けるため、MetaDBとOCPには独立したオペレーティングシステムユーザーを設定することを推奨します。</p>
    </main>

    |  パラメータ   |   説明   |
    |---------|----------|
    |  ユーザー名   | インストーラーが自動設定を行うために、ホストOSのユーザー名を入力してください。このユーザー名にはsudo権限が付与されていなければなりません。    |
    |  ユーザーID   | **<UI-TERM key="ocp-v2.Auth.User.NewUserName">ユーザー名</UI-TERM>** のパスワードを入力してください。ホストでパスワードレスログインが設定されている場合は、この設定を無視できます。     |
    |  SSHポート   | ホストのSSHポート番号です。デフォルト値は `22` です。カスタムポートもサポートしています。     |
    |  実行ユーザー   | （オプション）OCPサービスを実行するための独立したOSユーザーを設定します。 |

2. OCPノードの設定

    OCPをデプロイするホストを選択します。複数のホストを設定することも可能です。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>ホストアドレスは127.0.0.1にすることはできません。</p>
    </main>

3. データベースノードの設定

    |  パラメータ   |   説明   |
    |---------|----------|
    | Zone名   | デフォルトのままでもかまいませんし、カスタマイズも可能です。Zone名は英字で始まり、英字または数字で終わる2～32文字の長さである必要があります。複数ZoneをデプロイするOceanBaseクラスタでは、少なくとも1つのZoneのRegionがプライマリZoneと同じである必要があります。  |
    |  OBServerノード   | MetaDBをデプロイするホストを選択します。複数のホストを設定することも可能です。  |
    |  RootServerノード   | RootServiceが配置されるマシンとして、IPアドレスを1つ選択してください。マルチレプリカのOceanBaseクラスタでは、各ZoneにRootServerを指定する必要があります。   |

    デフォルトでは1つのZone情報が追加されます。デプロイするクラスタのZone数が1つより多い場合は、下部の **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Add">新規追加</UI-TERM>** ボタンをクリックしてZone情報を追加できます。デプロイするクラスタのZone数が1つ未満の場合は、Zoneの後ろにある削除アイコンをクリックできます。

4. クラスタ関連情報の設定

    |  パラメータ   |   説明   |
    |---------|----------|
    |  root@sysパスワード   | カスタマイズまたはランダム生成が可能です。パスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8～32文字</li><li>数字(0～9)、大文字(A～Z)、小文字(a～z)、特殊文字の4種類のうち、少なくとも3種類を含む。<code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>がサポートされています。</li></ul>  |
    |  ソフトウェアパス   | MetaDBのインストールパスです。デフォルト値は `/デプロイユーザー/oceanbase` です。カスタムディレクトリもサポートしていますが、対応するディレクトリの読み書き権限が必要です。    |
    |  データパス   | MetaDBのデータ保存パスです。デフォルト値は `/data/1` です。カスタムディレクトリもサポートしています。対応するディレクトリの読み書き権限が必要であり、設定するディレクトリが空であることを確認してください。     |
    |  ログパス   | MetaDBのログ保存パスです。デフォルト値は `/data/log1` です。カスタムディレクトリもサポートしています。対応するディレクトリの読み書き権限が必要であり、設定するディレクトリが空であることを確認してください。   |
    |  SQLポート   | MetaDBのSQLポートです。デフォルト値は `2881` です。カスタムポートもサポートしています(1024～65535の範囲のみ)。設定するポートが使用されていないことを確認してください。    |
    |  RPCポート   | MetaDBのRPCポートです。デフォルト値は `2882` です。カスタムポートもサポートしています(1024～65535の範囲のみ)。設定するポートが使用されていないことを確認してください。    |
    |  詳細設定   | （オプション）クリックするとOceanBaseクラスタのパラメータを表示および設定できます。自動割り当てられた値を使用して設定することも、各パラメータをカスタマイズすることもできます。OceanBaseクラスタ関連パラメータの説明については、[パラメータ一覧を見る](../../600.cluster-functions/1300.manage-cluster-parameters/200.view-the-parameters-list.md)を参照してください。  |

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><b>ソフトウェアパス</b>、<b>データパス</b>、<b>ログパス</b>が配置されるディレクトリのディスク容量が十分であることを確認してください。不足している場合は、設定に失敗します。</p>
    </main>

5. OBProxy関連情報の設定

    |  パラメータ   |   説明   |
    |---------|----------|
    |  OBProxyノード   |  OBProxyをデプロイするホストを選択します。IPアドレスは1つのみ指定可能で、単一ノードのOBProxyインストールのみサポートされます。   |
    |  SQLポート   | OBProxyのSQLポートです。デフォルト値は`2883`で、カスタムポート（1024～65535の範囲のみ）をサポートします。設定したポートが使用されていないことを確認してください。    |
    |  Exporterポート   | OBProxyのPrometheusリスニングポートです。デフォルト値は`2884`で、カスタムポート（1024～65535の範囲のみ）をサポートします。設定したポートが使用されていないことを確認してください。    |
    |  ソフトウェアパス   | OBProxyのインストールパスです。デフォルト値は`/デプロイユーザー/obproxy`で、カスタムディレクトリをサポートします。対応するディレクトリに対する読み書き権限が必要です。    |
    |  設定を追加   | （オプション）OBProxyクラスタパラメータを設定します。関連パラメータの説明については、[OBProxyパラメータの説明](../../800.obproxy-functions/900.obproxy-parameters-description.md)を参照してください。  |

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/metadb%E9%85%8D%E7%BD%AE.png)

### ステップ5：OCPの設定

このステップでは、OCPサービスおよびテナント情報を設定します。

1. OCPサービスの設定。

    |  パラメータ   |   説明   |
    |---------|----------|
    |  Adminパスワード   | OCP管理者のアカウントパスワード。パスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8〜32文字</li><li>少なくとも数字(0〜9)、大文字(A〜Z)、小文字(a〜z)、特殊文字の4種類のうち3種類を含む。<code>~^*{}[]_-+</code>がサポートされています。</li></ul>  |
    |  ソフトウェアパス   | OCPのインストールパス。デフォルト値は `/デプロイユーザー/ocp` です。ソフトウェアパスはカスタマイズ可能です。対応するディレクトリに対する読み書き権限が必要であり、このパスのディスク容量が十分であることを確認してください。  |
    |  ログパス   | OCPのログ保存パス。デフォルト値は `/home/デプロイユーザー/logs` です。ログパスはカスタマイズ可能です。対応するディレクトリに対する読み書き権限が必要であり、このパスのディスク容量が十分であることを確認してください。  |
    |  ソフトウェアパッケージパス   | OCP Agentのインストールパス。デフォルト値は `/home/デプロイユーザー/software` です。ソフトウェアパッケージパスはカスタマイズ可能です。対応するディレクトリに対する読み書き権限が必要であり、このパスのディスク容量が十分であることを確認してください。  |
    |  ocp.site.url   | OCP Webサイトへの外部アクセスアドレス。`http/https` で始まり、VIPアドレス/ドメイン名/ポート番号を含むURLである必要があり、末尾にスラッシュ (/) を含めないでください。例えば、`http://localhost:8080`。<br>` とします。設定後、**検証** をクリックしてアドレスの接続性をテストできます。検証に失敗した場合は、表示されたメッセージに従って修正してください。  |
    |  サービスポート   | OCPのサービスリスニングポート。デフォルト値は `8080` です。ポートはカスタマイズ可能です(1024〜65535の範囲のみ)。設定したポートが使用されていないことを確認してください。  |

2. リソース割り当ての計画。

    OCPサービスの実行中には大量の計算およびストレージ負荷が発生するため、管理対象の規模に応じたリソース計画が必要です。同時に、OCPはMetaDBに必要なテナントを設定し、OceanBaseデータベースのライフサイクル全体を管理する必要があります。設定完了後、システムは自動的に **メタ情報テナント** と **監視データテナント** を作成します。

    1. 管理するホストのサイズを入力します。

        システムはデフォルトで10台以下のホストを管理します。実際の状況に応じて変更できます。

    2. メモリリソースの設定。

        デフォルトで16GiBのメモリが割り当てられます。メモリリソースの設定は管理するホスト数に関連しています。OCPホストリソース計画の詳細については、[ホスト計画](300.installation-planning/200.host-planning.md)を参照してください。

    3. メタ情報テナント情報の設定。

        |  パラメータ   |   説明   |
        |---------|----------|
        | テナント名 | メタ情報テナント名。デフォルトは `ocp_meta` です。カスタマイズ可能です。  |
        | パスワード   |  メタ情報テナントのアカウントパスワード。パスワードはランダム生成またはカスタム設定が可能です。カスタムパスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8〜32文字</li><li>少なくとも数字(0〜9)、大文字(A〜Z)、小文字(a〜z)、特殊文字の4種類のうち3種類を含む。<code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>がサポートされています。</li></ul> |
        | CPU | メタ情報テナントに割り当てるCPUリソース。デフォルトは1VCPUSです。調整可能です。|
        | メモリ | メタ情報テナントに割り当てるメモリリソース。デフォルトは2GiBです。調整可能です。|

    4. 監視データテナント情報の設定。

        |  パラメータ   |   説明   |
        |---------|----------|
        | テナント名 | 監視データテナント名。デフォルトは `ocp_monitor` です。カスタマイズ可能です。 |
        | パスワード   |  監視データテナントのアカウントパスワード。パスワードはランダム生成またはカスタム設定が可能です。カスタムパスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8〜32文字</li><li>少なくとも数字(0〜9)、大文字(A〜Z)、小文字(a〜z)、特殊文字の4種類のうち3種類を含む。<code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>がサポートされています。 </li></ul> |
        | CPU | 監視データテナントに割り当てるCPUリソース。デフォルトは2VCPUSです。調整可能です。|
        | メモリ | 監視データテナントに割り当てるメモリリソース。デフォルトは4GiBです。調整可能です。|

### ステップ6：環境事前チェック

OCPのインストール情報設定完了後、まず設定情報を確認し、確定した上で事前チェックを開始します。

* 設定に誤りがある場合は、**<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.PreviousStep">前の手順</UI-TERM>** をクリックして設定ページに戻り、修正してください。

    ![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%A2%84%E6%A3%80%E6%9F%A5.png)

* 設定に誤りがない場合は、**<UI-TERM key="ocp-v2.Detail.TakeOver.Precheck">事前チェック</UI-TERM>** をクリックします。システムは、MetaDBとOCPのインストール・設定に必要なすべての最低要件を満たしているかどうかを検証します。

    * チェックで失敗した項目がある場合、OCPは修復方法の説明を提供します。説明を参考に問題を調査し、修正してください。自動修復可能なチェック項目については、**<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">自動修復</UI-TERM>** をクリックすることで修復できます。

        修復完了後、**<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">再確認する</UI-TERM>** をクリックして環境の事前チェックプログラムを再度実行できます。

   * チェックに合格した場合は、**<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">次のステップ</UI-TERM>** をクリックします。

    ![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%A2%84%E6%A3%80%E6%9F%A5-%E6%96%B0%E5%BB%BAmetadb.png)

### ステップ7：OCPのデプロイ

OCPのデプロイ中、**デプロイログ**モジュールで詳細なインストールログを確認できます。

* デプロイに失敗した場合は、ログ情報を確認して失敗原因を把握し、技術サポートにお問い合わせください。インストール失敗の原因を特定し、問題を解決したら、**再デプロイ**をクリックします。システムは現在の失敗したOCPインストール環境をクリーンアップし、インストールプログラムを再度実行します。

* デプロイに成功した場合は、**<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** をクリックしてデプロイプログラムを終了します。プログラムを終了する前に、アクセスアドレスとアカウント情報をコピーし、デプロイされたOCPプラットフォームにログインするために使用できます。

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%AE%89%E8%A3%85%E6%88%90%E5%8A%9F.png)

## 既存のOceanBaseデータベースをOCPのMetaDBとして使用する

この方法は、既存のOceanBaseデータベースをOCPのMetaDBとして使用する場合に適用されます。

### ステップ１：obdを起動する

1. OCPホストにログインします。

2. 以下のコマンドを実行して、解凍したソフトウェアパッケージの`bin`ディレクトリに移動し、デプロイプログラムをインストールします。

    ```bash
    cd ocp-all-in-one/bin && sh install.sh
    ```

3. 以下のコマンドを実行して、環境変数を有効にします。

    ```bash
    source ~/.oceanbase-all-in-one/bin/env.sh
    ```

4. `obd web install` を実行し、戻りメッセージからデプロイウィザードページのIPアドレスを取得します。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/install.png)

### ステップ2：OCPデプロイウィザードページにアクセスする

1. ブラウザで**ステップ１**で取得したIPアドレスにアクセスし、デプロイウィザードページに移動して、**体験を開始**をクリックします。

### ステップ3：デプロイ関連情報を設定する

1. 管理対象のOceanBaseクラスタ名をカスタマイズします。

    この名前は一意でなければならず、英字で始まり、大文字・小文字、数字、アンダースコアをサポートし、長さは2～32文字です。

2. デプロイするOCPバージョンを選択します。

### ステップ4：OceanBaseクラスタに接続する

OCPは入力されたMetaDB情報に基づいてデプロイプログラムを実行します。

1. OceanBaseデータベースの接続情報を入力します。

    OCPはこの接続情報で指定されたデータベースをMetaDBとして使用し、メタ情報や監視データを格納します。

    |  パラメータ   |   説明   |
    |---------|----------|
    |  ホストIP   | データベースアクセス用IPアドレス。OCPがMetaDBに接続するために使用され、1つのみ入力可能です。    |
    |  アクセスポート | データベース接続用アクセスポート。     |
    |  アクセスアカウント | データベースのアクセスアカウント。`sys`テナントのみ使用可能で、デフォルトは`root@sys`、カスタマイズ可能です。     |
    |  アクセスパスワード | データベースの**アクセスアカウント**のパスワード。 |

2. 情報に誤りがないことを確認したら、**<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">次のステップ</UI-TERM>**をクリックします。システムはこのMetaDBが正常に接続されているか検証します。

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/ob%E9%9B%86%E7%BE%A4%E8%BF%9E%E6%8E%A5%E9%85%8D%E7%BD%AE.png)

### ステップ5：OCPの設定

1. デプロイユーザーの設定。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>オペレーティングシステムのユーザーとの競合を避けるため、MetaDBとOCPには独立したオペレーティングシステムユーザーを設定することを推奨します。</p>
    </main>

    |  パラメータ   |   説明   |
    |---------|----------|
    |  ユーザー名   | プログラムが自動設定を行うために必要なホストOSのユーザー名。このユーザー名にはsudo権限が付与されていなければなりません。    |
    |  ユーザーパスワード | **<UI-TERM key="ocp-v2.Auth.User.Detail.UserName">ユーザー名</UI-TERM>**に対応するパスワード。ホストで秘密鍵なしログインが設定されている場合は、この設定を無視できます。     |
    |  SSHポート | ホストのSQLポート。デフォルト値は`22`です。     |
    |  実行ユーザーの使用 | （オプション）OCPの独立したサービス実行ユーザーを設定します。 |

2. OCPノードの設定。

    OCPをデプロイするホストを選択します。複数のホストを設定することも可能です。

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>ホストのアドレスは127.0.0.1にすることはできません。</p>
    </main>

3. OCPサービスの設定。

    |  パラメータ   |   説明   |
    |---------|----------|
    |  Adminパスワード   | OCP管理者のアカウントパスワード。パスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8〜32文字</li><li>少なくとも数字（0〜9）、大文字（A〜Z）、小文字（a〜z）、特殊文字の4種類のうち3種類を含む。<code>~!@#%^&*_-+=\|(){}[]:;,.?/$`'"<>\\</code>がサポートされています。 </li></ul>  |
    |  ソフトウェアパス   | OCPのインストールパス。デフォルト値は`/home/デプロイユーザー/ocp`です。ソフトウェアパスはカスタマイズ可能です。対応するディレクトリの読み書き権限が必要であり、このパスのディスク容量が十分であることを確保してください。  |
    |  ログパス   | OCPのログ保存パス。デフォルト値は`/home/デプロイユーザー/logs`です。ログパスはカスタマイズ可能です。対応するディレクトリの読み書き権限が必要であり、このパスのディスク容量が十分であることを確保してください。  |
    |  ソフトウェアパッケージパス   | OCP Agentのインストールパス。デフォルト値は`/home/デプロイユーザー/software`です。ソフトウェアパッケージパスはカスタマイズ可能です。対応するディレクトリの読み書き権限が必要であり、このパスのディスク容量が十分であることを確保してください。  |
    |  ocp.site.url   | OCP Webサイトへの外部アクセスアドレス。`http/https`で始まり、VIPアドレス/ドメイン名/ポートを含むURLで、末尾にスラッシュ（/）が含まれていないことが求められます。例：`http://localhost:8080`。<br>設定後、**検証**をクリックしてアドレスの接続性をテストできます。検証に失敗した場合は、表示されたメッセージに従って修正してください。  |
    |  サービスポート   | OCPのサービスポート。デフォルト値は`8080`です。カスタムポート（1024〜65535の範囲のみサポート）をサポートしており、設定したポートが使用されていないことを確認する必要があります。  |

4. リソース割り当ての計画。

    OCPサービスの実行中には大量の計算およびストレージ負荷が発生するため、管理対象の規模に応じてリソースを計画する必要があります。同時に、OCPはMetaDB内に必要なテナントを設定し、OceanBaseデータベースのライフサイクル全体を管理する必要があります。設定完了後、システムは自動的に**メタ情報テナント**と**監視データテナント**を作成します。

    1. 管理するホストの数を入力します。

        システムはデフォルトで10台以下のホストを管理します。実際の状況に応じて変更できます。

    2. メモリリソースを設定します。

        デフォルトで16GiBのメモリが割り当てられます。メモリリソースの設定は管理するホストの台数に関連しています。OCPホストリソース計画の詳細については、[ホスト計画](300.installation-planning/200.host-planning.md)を参照してください。

    3. メタ情報テナント情報を設定します。

        |  パラメータ   |   説明   |
        |---------|----------|
        | テナント名 | メタ情報テナント名。デフォルトは`ocp_meta`で、カスタマイズ可能です。  |
        | パスワード   |  メタ情報テナントのアカウントパスワードを設定します。パスワードはランダム生成またはカスタム設定が可能です。カスタムパスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8〜32文字</li><li>少なくとも数字（0〜9）、大文字（A〜Z）、小文字（a〜z）、特殊文字の4種類のうち3種類を含む。<code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>がサポートされる特殊文字です。</li></ul> |
        | CPU | メタ情報テナントに割り当てるCPUリソース。デフォルトは1VCPUSで、調整可能です。|
        | メモリ | メタ情報テナントに割り当てるメモリリソース。デフォルトは2GiBで、調整可能です。|

    4. モニタリングデータテナント情報を設定します。

        |  パラメータ   |   説明   |
        |---------|----------|
        | テナント名 | モニタリングデータテナント名。デフォルトは`ocp_monitor`で、カスタマイズ可能です。 |
        | パスワード   |  モニタリングデータテナントのアカウントパスワードを設定します。パスワードはランダム生成またはカスタム設定が可能です。カスタムパスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8〜32文字</li><li>少なくとも数字（0〜9）、大文字（A〜Z）、小文字（a〜z）、特殊文字の4種類のうち3種類を含む。<code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>がサポートされる特殊文字です。</li></ul> |
        | CPU | モニタリングデータテナントに割り当てるCPUリソース。デフォルトは2VCPUSで、調整可能です。|
        | メモリ | モニタリングデータテナントに割り当てるメモリリソース。デフォルトは4GiBで、調整可能です。|

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/ocp%E9%85%8D%E7%BD%AE-%E5%B7%B2%E6%9C%89metadb.png)

### ステップ6：環境事前チェック

OCPのインストール情報設定が完了したら、まず設定情報を確認し、問題がなければ事前チェックを開始します。

* 設定に誤りがある場合、**<UI-TERM key="ocp-v2.Credential.Component.ImportModal.PreviousStep">前の手順</UI-TERM>** をクリックして設定ページに戻り、修正してください。

    ![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%A2%84%E6%A3%80%E6%9F%A5-%E5%B7%B2%E6%9C%89metadb.png)

* 設定に誤りがない場合、**<UI-TERM key="ocp-v2.Cluster.Import.Precheck">事前チェック</UI-TERM>** をクリックすると、システムはMetaDBとOCPのインストール・設定に必要な最低要件を満たしているかどうか検証します。

    * チェックで失敗した項目がある場合、OCPは修正方法を説明します。その手順を参考に問題を調査・修正してください。自動修復可能なチェック項目については、**<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">自動修復</UI-TERM>** をクリックして修復できます。

      修復完了後、**<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">再確認する</UI-TERM>** をクリックして環境事前チェックプログラムを再度実行できます。

   * チェックに合格した場合、**<UI-TERM key="ocp-v2.Cluster.Import.Next">次のステップ</UI-TERM>** をクリックします。

     ![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E9%A2%84%E6%A3%80%E6%9F%A5%E6%88%90%E5%8A%9F.png)

### ステップ7：OCPのデプロイ

OCPのデプロイプロセス中、**デプロイログ**モジュールで詳細なログを確認できます。

* デプロイに失敗した場合は、ログ情報を確認して失敗の原因を特定し、技術サポートチームに連絡して対応してもらいます。インストール失敗の原因を特定し、問題が修正されたら、**再デプロイ**をクリックします。システムは現在の失敗したOCPインストール環境をクリーンアップし、インストーラを再度実行します。

* デプロイに成功した場合は、**<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>**をクリックしてデプロイプログラムを終了します。プログラムを終了する前に、アクセスアドレスとアカウント情報をコピーしておくと、デプロイ済みのOCPプラットフォームにログインする際に使用できます。

![Alt text](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E5%AE%89%E8%A3%85%E6%88%90%E5%8A%9F.png)
