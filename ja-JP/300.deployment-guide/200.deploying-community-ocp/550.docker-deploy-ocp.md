# コンテナを使用したOCPのデプロイ

このセクションでは、Dockerコンテナを使用してOCPをデプロイする方法について説明します。

## 前提条件

* 事前に利用可能なOceanBaseデータベースのMySQLモードへの接続を2つ作成しておいてください。メタデータとモニターデータを格納するために、それぞれ独立したテナントを使用することを推奨します。

    データベースの作成に関する詳細は、[クラスタのデプロイ](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000218235)を参照してください。テナントの作成に関する詳細は、[テナントの作成](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000218355)を参照してください。

* OCPをデプロイするホストにはDockerがインストールされており、dockerコマンドがシステムのPATHパスで見つかることを確認してください。現在、podman-dockerとの互換性はありません。Dockerのインストールについては、[Dockerのインストール](700.deploy-appendix/100.deploy-docker.md)を参照してください。

* デプロイするユーザーには、dockerコマンドの実行権限のみが必要です。

## OCPイメージの取得

OCPをデプロイする前に、まずローカルにOCPイメージを取得しておく必要があります。

OCPイメージのアドレス：https://hub.docker.com/r/oceanbase/ocp-ce/tags

* **オンライン環境**

    デプロイ環境からdockerhubに正常にアクセスできる場合は、以下のコマンドで直接OCPイメージを取得できます。

    ```bash
    docker pull oceanbase/ocp-ce:4.2.1
    ```

* **オフライン環境**

    デプロイ環境からdockerhubにアクセスできない場合は、他のアクセス可能なホストでまずイメージを取得し、その後デプロイ環境にインポートする必要があります。

    ```bash
    # execute at a host being able to access dockerhub
    docker pull oceanbase/ocp-ce:4.2.1
    docker save -o ocp-ce.tar oceanbase/ocp-ce:4.2.1
    scp ocp-ce.tar ${user}@${target}:/tmp/
    # execute at target host
    docker load < /tmp/ocp-ce.tar
    ```

OCPイメージを取得した後、以下のコマンドでイメージの取得状況を確認できます。以下の図に示す結果が得られれば、イメージの取得またはインポートが成功したことを意味します。

```bash
docker images | grep ocp-ce
```

## OCPコンテナの起動

以下のコマンドを使用してOCPコンテナを起動します。

```SQL
## set environment parameters
export OCP_CPU_COUNT=4
export OCP_MEMORY_GB=8
export OCP_METADB_HOST=xxx.xxx.xxx.xxx # do not use 127.0.0.1 or localhsot
export OCP_METADB_PORT=2881
export OCP_METADB_USER=root@ocp_meta
export OCP_METADB_PASSWORD=ocp_meta_password
export OCP_METADB_DBNAME=ocp_meta
export OCP_MONITORDB_USER=root@ocp_monitor
export OCP_MONITORDB_PASSWORD=ocp_monitor_password
export OCP_MONITORDB_DBNAME=ocp_monitor
export OCP_INITIAL_ADMIN_PASSWORD=****** #should match ocp's password validation
export OCP_CONFIG_PROPERTIES=`cat << EOF
server.port:8080
ocp.site.url:http://xxx.xxx.xxx.xxx:8080
obsdk.ob.connection.mode:direct
EOF
`

# start ocp container
docker run -d --name ocp-421 \
--network host \ 
--cpu-period 100000 --cpu-quota ${OCP_CPU_COUNT}00000 --memory=${OCP_MEMORY_GB}G \
 -e OCP_METADB_HOST="${OCP_METADB_HOST}" \
 -e OCP_METADB_PORT="${OCP_METADB_PORT}" \
 -e OCP_METADB_DBNAME="${OCP_METADB_DBNAME}" \
 -e OCP_METADB_USER="${OCP_METADB_USER}" \
 -e OCP_METADB_PASSWORD="${OCP_METADB_PASSWORD}" \
 -e OCP_MONITORDB_DBNAME="${OCP_MONITORDB_DBNAME}" \
 -e OCP_MONITORDB_USER="${OCP_MONITORDB_USER}" \
 -e OCP_MONITORDB_PASSWORD="${OCP_MONITORDB_PASSWORD}" \
 -e OCP_INITIAL_ADMIN_PASSWORD="${OCP_INITIAL_ADMIN_PASSWORD}" \
 -e OCP_CONFIG_PROPERTIES="${OCP_CONFIG_PROPERTIES}" \
oceanbase/ocp-ce:4.2.1
```

環境変数の説明:

| 変数名 | 意味 |
|--------|------|
| OCP_CPU_COUNT | OCPコンテナに割り当てるCPUコア数。[ホスト計画](300.installation-planning/200.host-planning.md)を参照してください。|
| OCP_MEMORY_GB | OCPコンテナに割り当てるメモリ（単位はGiB）。[ホスト計画](300.installation-planning/200.host-planning.md)を参照してください。 |
| OCP_METADB_HOST | OCP metadbの接続アドレス。 |
| OCP_METADB_PORT | OCP metadbの接続ポート。 |
| OCP_METADB_DBNAME | OCP metadbデータベース名。 |
| OCP_METADB_USER | OCP metadbユーザー。OBServerに直接接続する場合はuser@tenant形式を使用し、OBProxyを使用する場合はuser@tenant#cluster形式を使用します。|
| OCP_METADB_PASSWORD | OCP metadbユーザーパスワード。 |
| OCP_MONITORDB_DBNAME | OCP monitordbデータベース名。 |
| OCP_MONITORDB_USER | OCP monitordbユーザー。OBServerに直接接続する場合はuser@tenant形式を使用し、OBProxyを使用する場合はuser@tenant#cluster形式を使用します。|
| OCP_MONITORDB_PASSWORD | OCP monitordbユーザーパスワード。 |
| OCP_INITIAL_ADMIN_PASSWORD | OCP adminユーザーのログインパスワード。パスワードは以下の要件を満たす必要があります：<li>長さが8～32文字</li><li>英字、数字、特殊文字をサポートし、大文字、小文字、数字、特殊文字をそれぞれ2つ以上含む</li><li>サポートされている特殊文字は \~!@#%\^\&\*_-+=\`\|(){}\[\]:;',.?/</li> |
| OCP_CONFIG_PROPERTIES | OCPシステムパラメータの設定です。複数行を設定でき、各行に1つのシステムパラメータを『:』で区切ります。|

## OCPのデプロイが成功したかどうかの確認

OCPコンテナが起動した後、metadbの初期化とサービスの起動を待機する必要があります。通常は約2分かかります。ブラウザにOCPのアクセスアドレスを入力し、ログインページが表示されればサービスの起動に成功しています。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421-ce/%E7%99%BB%E5%BD%95%E9%A1%B5%E9%9D%A2.png)

OCPサービスが長時間起動しない場合は、ログを確認してOCPの状態を確認できます。

```SQL
# use the following command to log into ocp container
docker exec -it ocp-421 bash

# check ocp bootstrap log
less /home/admin/logs/ocp/bootstrap.log

# check ocp runtime log
less /home/admin/logs/ocp/ocp.log
```
