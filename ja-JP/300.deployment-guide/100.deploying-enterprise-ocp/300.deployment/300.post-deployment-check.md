# デプロイ後の確認

デプロイが完了したら、OCPの機能、ログファイル、OCPバージョン、時刻、およびDockerを確認することで、インストールが正常に完了したかどうかを検証できます。

## OCP機能の確認

OCPのデプロイが完了したら、『ユーザーガイド』を参照して、以下の機能が正常に使用できるかどうか確認してください：

* アラートチャネルを設定し、アラートチャネルが利用可能であることを確認します。

* ホストのインポート、クラスタの作成、テナントの作成、モニタリングの表示など、基本的な機能を確認します。

* アラートのプッシュ通知を設定し、プッシュ機能が利用可能であることを確認します。

## ログファイルの確認

* `/home/admin/logs/ocp` ディレクトリにocp.logログファイルが存在するかどうか確認します。

* `/home/admin/logs/ocp/ocp.log` ログファイルの出力情報が正常であるかどうか確認します。

## OCPバージョンの確認

以下のコマンドを実行してOCP-Serverのバージョン情報を確認します。戻り値のbuildVersionが対応するバージョンと一致していれば、OCP-Serverのバージョンは正しいことを意味します。

```shell
curl --user <username>:<password> 'http://<OCP_HOST>:<OCP_PORT>/api/v2/info'
```

## 時刻の確認

以下のコマンドを実行してOCP-Serverの時刻を取得します。返された時刻が期待通りであれば、OCP-Serverの現在時刻が正常であることを示します。

```java
curl 'http://xxx.xxx.xxx.xxx:8080/api/v2/time'
```

## Dockerの確認

Dockerを使用してOCPをデプロイした場合、Dockerが正常に動作しているかどうかを確認する必要があります。

* `docker stats ocp` コマンドを使用して現在のDocker状態を確認し、CPUやMemoryなどの情報が正しいかどうか確認します。

* `docker exec -it ocp bash` コマンドを実行してDockerイメージのコンソールにアクセスし、`pgrep -a java` コマンドを使用してjavaプロセスが正常に動作しているか、JVMの起動パラメータが期待通りであるかを確認します。

## ファイルとソフトウェアパッケージの確認

OCPが正常に起動すると、一部のソフトウェアパッケージが自動的にOCP Serverにアップロードされます。OCPの左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.src.constant.information.SoftwarePackage">ソフトウェアパッケージ</UI-TERM>** をクリックし、パッケージリストで `ocp-agent-<version>-<buildNumber>.<operatingSystem>.<architecture>.rpm` パッケージが存在するかどうか確認します。また、パッケージのバージョン、OS、アーキテクチャが期待通りであることを確認します。
