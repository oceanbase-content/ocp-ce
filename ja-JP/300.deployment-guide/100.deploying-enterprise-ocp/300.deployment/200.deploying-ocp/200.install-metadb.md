# MetaDBの作成

OCPをデプロイする前に、まずOAT内でOCP用のメタデータベースMetaDBコンポーネントを作成する必要があります。既にデプロイ済みのMetaDBを直接利用したい場合は、[MetaDBの引き継ぎ](https://www.oceanbase.com/docs/enterprise-oat-doc-cn-10000000001092554)を参照してMetaDBをOATに引き継いでください。

このセクションでは、OAT内でMetaDBを作成する方法について説明します。

## 前提条件

MetaDBを作成する前に、以下の情報を確認してください：

* スーパーユーザーまたは運用保守担当者のアカウントを使用してOATにログインしていること。詳細については、[OATのインストール](../../200.prepare-the-deployment-environment/100.install-oat.md)を参照してください。
* MetaDBをインストールするサーバーを追加済みであること。詳細については、[サーバーの追加](../../200.prepare-the-deployment-environment/200.standardized-host.md)を参照してください。
* サーバーがMetaDBのインストールに必要なリソース要件を満たしていること。

## 手順

### ステップ1：MetaDB作成ページにアクセスする

1. OATにログインします。

2. 左側のナビゲーションバーで、**プロダクトサービス > コンポーネント**をクリックします。

3. **コンポーネント管理**ページで、右上の**コンポーネントの作成**をクリックし、**MetaDBの作成**を選択します。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%88%9B%E5%BB%BAmetadb1.png)

### ステップ2：基本情報を設定する

入力が必要なMetaDBの基本情報は以下の通りです：

|   パラメータ   |   説明   |
|--------|---------|
|   MetaDBイメージ   |   MetaDBのDockerイメージファイルです。ドロップダウンリストの**イメージファイルの管理**ボタンをクリックすると、表示されるパネルで**ローカルスキャン**または**リモート接続**の方法でイメージファイルを追加できます。<ul><li>**ローカルスキャン**を推奨します。イメージファイルをOATコンテナ内の`/data/images`ディレクトリにアップロードする必要があります。OAT起動時にホスト機のディレクトリがマウントされている場合は、MetaDBイメージをホスト機のマッピングディレクトリに直接コピーできます。</li><li>**リモート接続**は、イメージレジストリにアクセスできる場合に適用されます。ここで、**<UI-TERM key="ocp-v2.pages.Kubernetes.MirrorWarehouse">イメージリポジトリ</UI-TERM>**にはdockerレジストリのアドレスを入力します。例：`reg.docker.alibaba-inc.com/xxx/xxx`。**イメージタグ**にはイメージのバージョン番号を入力します。例：`3.3.9-x64`。**<UI-TERM key="ocp-v2.Sop.components.ClusterInfoTable.Architecture">アーキテクチャ</UI-TERM>**は実際の状況に応じて選択します。</li></ul>   |
|   コンポーネント名   |   コンポーネントの名前です。他のコンポーネントと重複してはならず、デフォルト名はmetadbです。   |
|   カスタムZone |   カスタムZoneを有効にするには、Zone名、データセンター（IDC）、サーバー、Root Serverの場所を入力する必要があります。 <main id="notice" type='explain'><h4>説明</h4>このパラメータと<b>サーバー</b>パラメータのどちらか一方を選択してください。カスタムZoneを有効にすると、サーバーパラメータは自動的に非表示になります。</main>    |
|   アービトレーションサービスの設定  | 自由に有効または無効にできます。有効にする場合は、インストール済みのアービトレーションサービスを選択できます。事前にアービトレーションサービスを作成していない場合や、インストール済みのアービトレーションサービスを選択しない場合でも、新規アービトレーションサービスボタンをクリックして関連情報を入力し、新規アービトレーションサービスを作成できます。<main id="notice" type='explain'><h4>説明</h4><ul><li><b>MetaDBイメージ</b>でV4.xバージョンのMetaDBを選択した場合にのみ、アービトレーションサービスを設定できます。</li><li>作成済みのアービトレーションサービスを選択する場合は、MetaDBイメージと同一アーキテクチャのアービトレーションサービスのみを選択できます。</li><li>新規アービトレーションサービスを作成する場合、アービトレーションサービスのイメージはMetaDBイメージと同一アーキテクチャで、サーバー用途はアービトレーションサービスまたはOceanBaseプロダクトサービスである必要があります。</li></ul></main>    |
|   サーバー   |   MetaDBをインストールするサーバーのIPアドレスです。複数ノードのMetaDBをデプロイする必要がある場合は、複数のMetaDBをインストールするサーバーのIPアドレスを選択できます。複数選択した場合、各サーバーに1つのMetaDBがインストールされます。   |
|   CPU   |   サーバー上でMetaDBが使用可能なCPUです。デフォルトは32Cです。  |
|   メモリ   |   サーバー上でMetaDBが使用可能なメモリです。デフォルトは90GiBです。   |
|   MetaDBクラスタ名   |   MetaDBのクラスタ名です。   |
|   root@sysパスワード   |   sysテナントのrootユーザーパスワードです。  |

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/02271047.png)

### ステップ3（オプション）：インストールパスを設定する

設定が必要なディレクトリ情報は以下の通りです：

|   パラメータ   |   説明   |
|--------|---------|
|   インストールディレクトリ   |   MetaDBのインストールパス。デフォルト値は `/home/admin/oceanbase` で、カスタムディレクトリをサポートします。 |
|   データディレクトリ   |   MetaDBのデータ保存パス。デフォルト値は `/data/1` で、カスタムディレクトリをサポートします。   |
|   ログディレクトリ   |   MetaDBのログ保存パス。デフォルト値は `/log/1` で、カスタムディレクトリをサポートします。   |
|   バックアップディレクトリ  |   オプション。MetaDBのバックアップパス。デフォルト値は空です。カスタムディレクトリをサポートします。   |

![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/metadb%E5%AE%89%E8%A3%85%E8%B7%AF%E5%BE%841.png)

### ステップ4（オプション）：起動パラメータの設定

設定が必要な起動パラメータは以下のとおりです：

|   パラメータ   |   説明   |
|--------|---------|
|   MySQLポート   |   MetaDBのMySQLポート。デフォルト値は2881です。  |
|   RPCポート   |   MetaDBのRPCポート。デフォルト値は2882です。  |
|   OBProxyサービスポート   |   OBProxyのサービスポート。デフォルト値は2883です。  |
|   SSHDポート  |   MetaDBコンテナ内のSSHDポート。デフォルト値は2022です。OCPはSSHDポートに接続してOCP Agentをデプロイします。  |
|   rootパスワード  |   MetaDBコンテナ内のrootユーザーパスワード。  |

![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/02271116.png)

<main id="notice" type='explain'>
<h4>説明</h4>
<ul>
<li>MetaDBに必要なCPUおよびメモリリソースは、<a href="../100.planning-resources/200.metadb-resources.md">MetaDBリソース</a>、<a href="../100.planning-resources/300.monitordb-resources.md">MonitorDBリソース</a>、sysテナント、system_memory、OBProxyなどのリソースの合計値です。MetaDBに関連リソースを割り当てる際は、必要なリソースに加えて一定の余裕を確保することを推奨します（システムテナント自体も一定のリソースを消費します）。</li>
<li>MetaDBのインストールパスを設定する際は、データディレクトリ、インストールディレクトリ、ログディレクトリが空であること、およびディレクトリの所有者がadminであることを確認する必要があります。</li>
<li>同一のMetaDBクラスタ内では、イメージのハードウェアアーキテクチャを統一する必要があります（現在、OATは異種構成をサポートしていません）。</li>
</ul>
</main>

### ステップ5：作成タスクを送信する

1. MetaDBの設定が完了したら、**<UI-TERM key="ocp-v2.Settings.Component.ModifyUserInfoDrawer.Submit">送信</UI-TERM>** をクリックします。設定に誤りがある場合は、**<UI-TERM key="ocp-v2.Alarm.Subscriptions.Reset">リセット</UI-TERM>** をクリックすると、デフォルト設定にワンクリックで戻ります。

2. MetaDBの作成が送信された後、**システムとセキュリティ** > **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>** に移動し、タスク名をクリックすると詳細なタスク情報を確認できます。
