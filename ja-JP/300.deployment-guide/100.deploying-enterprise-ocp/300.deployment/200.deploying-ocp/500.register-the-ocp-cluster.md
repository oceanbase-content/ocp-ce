# OCPクラスタの登録

このセクションでは、OCPのマルチクラスタモードで、スタンバイOCPクラスタに初めてログインする際に、そのスタンバイOCPクラスタをプライマリOCPクラスタにバインドする方法について説明します。OCPのマルチクラスタモード以外の場合は、このセクションをスキップしてください。

## 前提条件

* マルチクラスタモードのプライマリおよびスタンバイOCPクラスタが作成済みであること。

  * [OCPのインストール](300.install-ocp.md)の手順を参照して、プライマリおよびスタンバイOCPクラスタをデプロイ済みであること。

  * 複数の通常モードの単一ノードOCPをマルチクラスタOCPに変換する必要がある場合は、[マルチクラスタモードスイッチ](../../../../1200.manage-disaster-recovery/300.ocp-multi-cluster-mode/900.multi-cluster-mode-switch.md)を参照して、そのうちの1つのクラスタをプライマリクラスタに、残りの通常モードの単一ノードOCPをスタンバイクラスタに変換できます。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>このシナリオでは、プライマリおよびスタンバイOCPクラスタに同名のOceanBaseプライマリクラスタは存在できません。</p>
  </main>

* プライマリクラスタMetaDBのJDBCアクセス情報を取得済みであること。

## 手順

1. スタンバイOCPのログイン画面で、**<UI-TERM key="ocp-v2.page.Settings.Profile.Username">ユーザー名</UI-TERM>**と**<UI-TERM key="ocp-v2.Auth.User.New.Password">パスワード</UI-TERM>**を入力し、**<UI-TERM key="ocp-v2.page.Login.Login">ログイン</UI-TERM>**をクリックします。

   システムは**<UI-TERM key="ocp-v2.MultiCluster.RegisterOcp.WelcomeToMultiClusterMode">マルチクラスタモードへようこそ</UI-TERM>**画面に入ります。

   <!-- ![07271009](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/8712537261/p298450.png) -->

2. **プライマリOCP metaDBの接続情報**のパラメータを入力します。

   |  パラメータ  |                     説明                     |
   |------|--------------------------------------------|
   | ホストアドレス | プライマリOCP MetaDBが配置されているノードのIPアドレス。例：xxx.xxx.xxx.xxx。       |
   | ポート   | プライマリOCP MetaDBのアクセスポート。例：2881。                 |
   | ユーザー名  | プライマリOCP MetaDBのアクセスユーザー。例：ocp@ocp_meta#ocp321。  |
   | パスワード   | プライマリOCP MetaDBのアクセスユーザーのパスワード。例：aA\*\*\*\*\*\*1j 。 |
   | データベース  | プライマリOCP MetaDBのデータベース名。例：meta_01。              |

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>表内の情報がMetaDBのJDBCアクセス情報であり、バックグラウンドでこのMetaDBにアクセスするためにも使用できます。プライマリOCPへのバインドに失敗した場合、以下のコマンドを使用してこのMetaDBにバックグラウンドでアクセスし、基本的なトラブルシューティングを実行できます。</p>
   </main>

   ```sql
   ###クライアントがobclientコマンドを実行してデータベースサーバーに接続する
   obclient -hxxx.xxx.xxx.xxx -P2881 -u<ユーザー名>@<テナント名#クラスタ名> -paA******1j -Dmeta_01
   ```

3. **<UI-TERM key="ocp-v2.MultiCluster.RegisterOcp.BindToPrimaryOcp">メイン OCP にバインド</UI-TERM>** をクリックします。

   システムが業務モードに切り替わると、このスタンバイOCPクラスタはプライマリOCPクラスタにバインドされます。

   このプライマリOCPクラスタが他のスタンバイOCPにもバインドされている場合、`ocp.multi-cluster.replication.interval.seconds` パラメータで設定されたプライマリ/スタンバイデータ同期間隔の影響を受け、スタンバイOCPの **<UI-TERM key="ocp-v2.MultiCluster.Detail.ActiveStandbyList">プライマリ/スタンバイリスト</UI-TERM>** に他のスタンバイOCPが一時的に表示されないことがあります。詳細については、[プライマリ/スタンバイ詳細ページの説明](../../../../1200.manage-disaster-recovery/300.ocp-multi-cluster-mode/100.overview-of-multi-cluster-mode.md) の **<UI-TERM key="ocp-v2.MultiCluster.Detail.ActiveStandbyList">プライマリ/スタンバイリスト</UI-TERM>** の説明を参照してください。
