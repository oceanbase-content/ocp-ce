# OCPのインストール

このセクションでは、OATにOCPをインストールする方法について説明します。

## 前提条件

OCPをインストールする前に、以下の事項を確認してください：

* スーパーユーザーまたは運用スタッフアカウントを使用してOATにログインし、インストール済みであること。詳細については、[OATのインストール](../../200.prepare-the-deployment-environment/100.install-oat.md)を参照してください。
* OCPをインストールするサーバーが追加済みであること。詳細については、[サーバーの追加](../../200.prepare-the-deployment-environment/200.standardized-host.md)を参照してください。
* サーバーがOCPのインストール要件を満たしていること。詳細については、[OCPサービス構成要件](../100.planning-resources/100.ocp-server-specifications.md)を参照してください。
* OCP用のメタデータベースMetaDBコンポーネントを作成済みであること。詳細については、[MetaDBの作成](200.install-metadb.md)を参照してください。

## 注意事項

単一ノードのOCPは異なるタイムゾーン環境へのデプロイをサポートしますが、同一のOCP内のすべてのノードのタイムゾーンは統一されている必要があります。高可用性モードのプライマリ/スタンバイOCPクラスタも異なるタイムゾーン環境へのデプロイをサポートしますが、各OCPクラスタにおいて、すべてのOCPノードのタイムゾーンは統一されている必要があります。OCPの実行中は、MetaDBのタイムゾーンを変更することは禁止されています。管理面では、OCPは異なるタイムゾーンのOceanBaseクラスタやOceanBaseテナント、およびタイムゾーンを跨ぐプライマリ/スタンバイクラスタやプライマリ/スタンバイテナントなどを管理することをサポートします。ただし、OceanBaseの内部テーブルとビューのタイムゾーン変換ロジックの制限により、テナントの`system_time_zone`と`time_zone`パラメータの値が一致している必要がある点には特に注意してください。そうでない場合、OCPの機能に問題が発生する可能性があります。

## 手順

### ステップ１：OCPのインストールページにアクセスする

1. OATにログインします。

2. 左側のナビゲーションバーで、**プロダクトサービス > プロダクト管理**をクリックします。

3. **プロダクト管理**ページで、右上の**プロダクトのインストール**をクリックし、**OCPのインストール**を選択します。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%AE%89%E8%A3%85ocp1.png)

### ステップ2：OCPの基本情報を設定する

単一ノードOCPと高可用性OCPのデプロイでは、設定が異なります。実際の状況に応じて入力してください。

* **単一ノードOCP**：

  |   パラメータ   |   説明   |
  |--------|---------|
  |   OCPイメージ   |   OCPのDockerイメージ。   |
  |   プロダクト名   |   プロダクト名は他のプロダクトと重複してはなりません。   |
  |   管理者パスワード  |    OCP adminアカウントのパスワードをリセットします。パスワードはカスタマイズまたはランダム生成が可能です。OCPのデプロイが完了したら、このパスワードで直接OCPにログインできます。**パスワード設定によるアカウントの有効化**操作は不要です。<main id="notice" type='explain'><h4>説明</h4>OAT V4.1.1バージョンのみ、OCPのインストール時に管理者パスワードの設定をサポートします。</main>      |
  |   マルチゾーンモード |   シングルノードOCPモードでは、このモードを有効にする必要はありません。     |
  |   CPU   |   各サーバー上でOCPが利用可能なCPUコア数。デフォルトは8Cです。  |
  |   メモリ   |   各サーバー上でOCPが利用可能なメモリ。デフォルトは20GiBです。   |
  |   HTTPポート   |   OCPのHTTPポート。デフォルト値は8080です。   |
  |   マルチクラスタモード   |   シングルノードOCPモードでは、このモードを有効にする必要はありません。  |
  |   ログディレクトリ  |   OCPのログ保存パス。   |

* **高可用性OCP**：

  |   パラメータ   |   説明   |
  |--------|---------|
  |   OCPイメージ   |   OCPのDockerイメージ。   |
  |   プロダクト名   |   プロダクト名は他のプロダクトと重複してはなりません。   |
  |   管理者パスワード  |    OCP adminアカウントのパスワードをリセットします。パスワードはカスタマイズまたはランダム生成が可能です。OCPのデプロイが完了したら、このパスワードで直接OCPにログインできます。**パスワード設定によるアカウントの有効化**操作は不要です。<main id="notice" type='explain'><h4>説明</h4>OAT V4.1.1バージョンのみ、OCPのインストール時に管理者パスワードの設定をサポートします。</main>     |
  |   マルチゾーンモード |   マルチゾーンモードでのインストールを有効にするかどうかを選択します。<main id="notice" type='notice'><h4>注意</h4>OCPがV4.3.0以降のバージョンの場合、マルチゾーンモードでのデプロイはサポートされなくなりました。この設定は有効にしないでください。</main>    |
  |   サーバー   |   OCPノードを指定するサーバーのIPアドレスを入力します。   |
  |   CPU   |   各サーバー上でOCPが利用可能なCPUコア数。デフォルトは8Cです。  |
  |   メモリ   |   各サーバー上でOCPが利用可能なメモリ。デフォルトは20GiBです。   |
  |   HTTPポート   |   OCPのHTTPポート。デフォルト値は8080です。   |
  |   マルチクラスタモード   |   マルチクラスタインストールモードを有効にします。  |
  |   クラスタタイプ     |   OCPノードのクラスタタイプを選択します。**プライマリクラスタ**または**スタンバイクラスタ**を選択できます。<main id="notice" type='notice'><h4>注意</h4>OCPのマルチクラスタモードでは、プライマリクラスタは1つだけ存在し、それ以外はすべてスタンバイクラスタである必要があります。</main>   |
  |   OCPクラスタ名     |   OCPノードのクラスタ名を入力します。  |
  |   ログディレクトリ  |   OCPのログ保存パス。   |

  <main id="notice" type='explain'>
  <h4>説明</h4>
  CPUとメモリのサイズ設定については、<a href="../100.planning-resources/100.ocp-server-specifications.md">OCP管理サービスおよび設定</a>の<strong>CPUとメモリ</strong>の章を参照してください。
  </main>

### ステップ3：MetaDB関連情報の設定

OCPは、metaDBのOCP metaテナントとOCP monitorテナントの情報を設定するための2つの方法を提供しています。

* テナントが作成されていない場合、**既存のMetaDB**タブをクリックし、MetaDB用に新しいOCP metaテナントとOCP monitorテナントを作成します。テナントのCPUとメモリサイズの設定については、[MetaDBリソース](../100.planning-resources/200.metadb-resources.md)の**CPUとメモリ**セクションを参照してリソースを計画してください。

  |   パラメータ   |   説明   |
  |--------|---------|
  |   既存のMetaDBの選択   |   OCPで既存のMetaDBを選択します。  |
  |   MetaDBクラスタの引き継ぎ   |   MetaDBクラスタを引き継ぐかどうかを選択します。引き継いだ後は、このMetaDBクラスタがOCPで表示されます。各OceanBaseクラスタは、OCPによって1回のみ引き継がれることができます。  |
  |   OCP Metaテナント   |   OCP MetaDB専用のテナントです。   |
  |   テナント名   |   Metaテナント名。  |
  |   テナントパスワード  |   Metaテナントのパスワード。  |
  |   テナントCPU  |   MetaDBがサーバー上で使用可能なCPU。デフォルトは2Cです。  |
  |   テナントメモリ  |   MetaDBがサーバー上で使用可能なメモリ。デフォルトは5GiBです。  |
  |   OCP Monitorテナント  |   OCP MonitorDB専用のテナントです。  |
  |   テナント名  |   Monitorテナント名。  |
  |   テナントパスワード  |   Monitorテナントのパスワード。  |
  |   テナントCPU  |   MonitorDBがサーバー上で使用可能なCPU。デフォルトは4Cです。  |
  |   テナントメモリ  |   MonitorDBがサーバー上で使用可能なメモリ。デフォルトは16GiBです。  |

* テナントが既に存在する場合、**その他のOB_MySQL**タブをクリックし、OCP metaテナントとOCP monitorテナントの接続情報を入力します。入力するユーザー名がrootでない場合、該当するユーザーにはデータベーステーブルを作成する権限が付与されていなければなりません。

![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%AE%89%E8%A3%85ocp-metadb%E9%85%8D%E7%BD%AE1.png)

### ステップ4（オプション）：ロードバランシング情報の設定

MetaDBとOCPの複数ノードでロードバランシングが必要な場合、対応するプロキシIPを設定できます。

|   パラメータ   |   説明   |
|----------|---------|
|   ロードバランシングモード   |   ロードバランシングモードを選択します。**既存のOBDNS**、**その他のロードバランシング**、**既存のNLB**、**使用しない**が含まれます。  |
|   MetaDB TCPプロキシIP   |  **その他のロードバランシング**モードを選択した場合に表示されます。MetaDBに接続するためのTCPプロトコルアドレスを入力します。  |
|   MetaDB TCPプロキシポート   |  **その他のロードバランシング**モードを選択した場合に表示されます。TCPプロトコルのポート番号を入力します。   |
|   HTTPプロキシドメイン名  |   **既存のOBDNS**モードを選択した場合に表示されます。OCPのコンソールにアクセスするためのHTTPプロトコルアドレスを入力します。   |
|   HTTPプロキシポート  |   **既存のOBDNS**モードを選択した場合に表示されます。HTTPプロトコルのポート番号を入力します。  |

![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%AE%89%E8%A3%85ocp-%E8%B4%9F%E8%BD%BD%E5%9D%87%E8%A1%A1%E9%85%8D%E7%BD%AE1.png)

### ステップ5：OpenSearch情報の設定

OpenSearchの設定モードは以下の3種類に分かれています：

|   パラメータ   |   説明   |
|----------|---------|
|   既存のOpenSearch   |  ドロップダウンボックスから、OATによって作成されたOpenSearchを選択します。OpenSearchの作成については、[OpenSearchの作成とアンインストール](https://www.oceanbase.com/docs/enterprise-oat-doc-cn-1000000005282177)を参照してください。  |
|   外部のOpenSearch     |  外部にデプロイされたOpenSearchのURL、ユーザー名、パスワードを入力する必要があります。  |
|   使用しない。              |  何も設定する必要はありません。   |

![4](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/02251505.png)

### ステップ6：インストールタスクを送信する

1. OCPの設定が完了したら、**<UI-TERM key="ocp-v2.component.OperationConfig.ModifyParameterDrawer.Submit">送信</UI-TERM>** をクリックします。設定に誤りがある場合は、**<UI-TERM key="ocp-v2.page.QueryLog.Reset">リセット</UI-TERM>** をクリックして、デフォルト設定にワンクリックで戻すことができます。

2. OCPのインストール送信が成功すると、**<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">タスクセンター</UI-TERM>** ページに移動し、タスク名をクリックすると詳細なタスク情報を確認できます。

  ![4](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%AE%89%E8%A3%85ocp%E4%BB%BB%E5%8A%A11.png)
