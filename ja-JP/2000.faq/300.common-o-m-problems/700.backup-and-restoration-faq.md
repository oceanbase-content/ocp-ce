# バックアップ・リストアに関するよくある質問
このセクションでは、OCPシステムのバックアップ・リストア機能に関するよくある質問を紹介します。

## 機能サポート

**Q1: OCPはOSSのバックアップ・リストアに対応していますか？**
A: OCPはV2.2.xバージョンからOSSベースの論理バックアップ・リストアをサポートし、V2.5.1バージョンからはOSSベースの物理バックアップ・リストアをサポートしています。

## ストレージ設定

**Q1: バックアップ・リストアでストレージアドレスのテストに失敗したと表示されますが、原因は何ですか？**

A: adminユーザーにNFSディレクトリへの書き込み権限がありません。
**Q2: OCPと3台のOceanBaseサーバーすべてにNFSファイルシステムがマウントされているにもかかわらず、3台のOceanBaseサーバーのストレージ設定検出に失敗します。原因は何でしょうか？**

A: 3台のOceanBaseサーバー上の`/obbackup`ディレクトリに書き込み権限がない可能性があります。

**Q3: グローバルビューでリストアを開始したところ、システムがストレージアドレスのテストに失敗したと表示されます。どう解決すればよいですか？**

A: OCP V2.5.3以降のバージョンでは、グローバルビューでリストアを開始する際、選択したホスト上でストレージアドレスの読み書き権限があるかどうかテストされます。選択したホスト上で`ls -l`コマンドを使用して、ストレージディレクトリの読み書き権限に問題がないか確認することをお勧めします。その内容は以下の通りです：

* rwx は、ファイル所有者が読み取り、書き込み、実行できることを表します。

* r-x は、ファイル所有者グループが読み取り可能、書き込み不可、実行可能であることを表します。

* r-x は、他のユーザーが読み取り可能、書き込み不可、実行可能であることを表します。

## バックアップ

**Q1: OCPを使用してフルバックアップを実行する際、`pre-check`ステップで`Cluster compaction needed before full data backup`というエラーが発生しました。原因は何ですか？**

A: フルバックアップを実行する前に、クラスタのメジャーコンパクションを実行する必要があります。詳細については、[メジャーコンパクションの実行](../../600.cluster-functions/1100.manage-cluster-merge/200.cluster-perform-merge.md)を参照してください。

**Q2: バックアップタスクが`Pre-check before data backup`で失敗し、`data backup pre-check failed, full data backup needed before incremental data backup`というエラーが発生しました。どう解決すればよいですか？**
A: 増分バックアップを行う前に、一度のフルバックアップが必要です。

**Q3: OCPを使用して一度のフルデータバックアップを開始した後、終了時間列に終了時間が表示された場合、バックアップは終了したことを意味しますか？**

A: 実際の状況は、該当タスクの**<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.State">ステータス</UI-TERM>**列の結果をご確認ください。

## リストア

**Q1: フルバックアップから特定のテナントデータを同一クラスタ内の既存テナントに復元できますか？**

A: 同一クラスタには復元できますが、既存のテナントには復元できません。復元処理中に自動的に新しいテナントが作成されます。

**Q2: 復元タスクの開始に成功し、バックエンドリソースプールが作成されたことを確認できましたが、テナントが作成されていません。なぜですか？**

A: 対象クラスタにNFSがマウントされていないためです。
**Q3: 物理復元時に `restore_concurrency 未設定` というエラーが表示されます。何が原因ですか？**

A: 想定される動作です。OceanBaseのパラメータ restore_concurrency の反映には遅延が生じる可能性があるため、OCPはエラーを報告します。**<UI-TERM key="ocp-v2.Backup.Restore.InitiateRecovery">復元を開始する</UI-TERM>** が正常に送信されれば、このエラーは無視してください。

**Q4: OCPとOceanBaseのクラスタをクリーンアップした後に復元を行う場合、事前にMetaDBをバックアップする必要はありますか？**

A: 不要です。新しくインストールしたOCPでバックアップファイルを選択して復元するだけで済みます。NFSシナリオでは、復元対象のクラスタにバックアップディレクトリを先にマウントする必要があります。

**Q5: OceanBaseの復元時にログエラー `error code [9023]; cannot start log archive backup;` が発生します。何が原因ですか？**

A: 9023エラーについては、ログバックアップを有効にするコマンドを繰り返しスケジュールすることを避ける必要があります。

## インスペクション

**Q1: V2.2.7x バージョンのOceanBaseクラスタでCLIを使用してバックアップ・復元を行った際、バックアップ・復元のインスペクションでエラーが発生しました。なぜですか？**

A: バックアップ・復元の異常状態が処理されていません。ocp_inspect_task テーブル内のバックアップ・復元関連インスペクションの `valid` フィールドを `0` に設定することで、インスペクションを無効にできます。
