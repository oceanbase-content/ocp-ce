# モニタリング指標に関するよくある質問
このセクションでは、**クラスタ概要**、**テナント概要**、および **OBProxy** 画面における一般的なモニタリング指標の問題について説明します。

## 表示

**Q1: 他のPCのChromeブラウザではリアルタイムモニタリング情報が表示されますが、ローカルのChromeでは表示されません。何が原因ですか？**
A: ブラウザで `/api/v2/time` を呼び出してOCPの時刻を確認し、ローカルの時刻と比較して、大きくずれていないかご確認ください。

**Q2: OCPのリアルタイムモニタリングが表示されません。OceanBaseの3台のマシンのエクスポーターをすべてチェックしたところ正常で、OCPホストから `curl` を使用したOceanBaseマシンへのアクセスも正常です。どうすればいいですか？**

A: ブラウザがあるマシンの時刻とOCPマシンの時刻の差が大きすぎる可能性があります。30秒以内に保つことを推奨します。

**Q3: 拡大したトレンドグラフと元のトレンドグラフにデータの誤差があります。どう解決すればいいですか？**

A: 拡大したトレンドグラフでは、モニタリングデータが多すぎる場合、キャッシュの影響でグラフのデータに誤差が生じることがあります。しばらく待ってから再度確認することを推奨します。

## クラスタ

**Q1: OCPクラスタ画面で、パフォーマンスモニタリングのトップ5が表示されません。その他のモニタリングページではほとんどが504エラーです。なぜですか？**

A: ネットワークが正常であるかご確認ください。ネットワークが正常な場合は、OCPイメージを最新バージョンに更新することを推奨します。
**Q2: OCPクラスタ画面で、パフォーマンスモニタリングのトップ5のソート基準は何ですか？**

A: 選択した期間内の指標値の合計です。

**Q3: クラスタ概要画面のディスク使用量は、マルチレプリカの合計ですか、それとも単一レプリカのサイズですか？**

A: マルチレプリカの合計です。

**Q4: クラスタ概要画面のリソース使用状況における割り当て済みメモリはどのように計算されますか？**

A: テナントがすべてのマシンに割り当てたUnitメモリ仕様の合計とマシンの総メモリの比率です。

**Q5: システムメモリがなぜ900GBも占めているのですか？**

A: OBServerノード上のテナントが共有するリソースまたは機能は、システム内部メモリと呼ばれ、システム内部メモリもシステムメモリの一部です。システムパラメータ **system_memory_percentage** を使用して、システム内部メモリが使用できるシステムメモリの上限割合を調整できます。

**Q6: V4.x系のクラスタでCPUリソースがマイナス数値で表示されます。なぜですか？**

A: V4.x系のクラスタでCPUオーバーコミットとCgroupを有効にした後、新規作成されたテナントが残りのリソースを使い切った状態で、さらにCPUオーバーコミット率を下げると、クラスタのCPUリソースデータがマイナス数値で表示されることがあります。この現象は製品の想定通りです。

## API

**Q1: OCP上のモニタリングデータを取得するためのAPIはありますか？**

A: OCP V2.5.0から取得できます。詳細については、[APIリファレンス](../../1900.reference-guide/200.api-reference/100.api-overview.md)を参照してください。

**Q2: [モニタリングデータのクエリ](../../1900.reference-guide/200.api-reference/900.monitoring/200.query-monitoring-data.md)に記載されているように、`interval`に60を指定した場合、戻り値のサンプリングポイントは1分ごとに集計されたものですか、それともその1秒間だけのものですか？**
A: 1分ごとに集計されたものです。
