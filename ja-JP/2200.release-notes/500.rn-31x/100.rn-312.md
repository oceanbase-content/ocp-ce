# OCP V3.1.2

<!--#RNDate#2021-07-13-->

OceanBaseクラウドプラットフォーム（OceanBase Cloud Platform、OCP）V3.1.2では、アクティブセッション履歴レポートが新たに追加されました。この機能はパフォーマンス診断モジュールの新機能であり、データベースの過去のアクティブセッション情報を提供し、ユーザーのテナントパフォーマンス診断を支援します。このバージョンでは、バックアップ・リストアがセカンダリバックアップをサポートしています。また、OCPの異なる権限を持つユーザー向けの可視化コンテンツも最適化され、ユーザーが見るままの表示が実現されています。OBProxyの引き継ぎ機能が新たに追加され、引き継ぎリンクの整合性が確保されています。その他の機能についても最適化と強化が行われており、SQL診断部分にはエクスポート機能が追加され、問題の分析を容易にしました。

## バージョン情報

* **バージョン番号：** V3.1.2

* **前回のバージョン：** V3.1.1

* **リリース日：** 2021年9月29日

* **サポートされるアップグレードパス：** OCP V2.3.x以降のバージョンからは直接このバージョンにアップグレードできます。OCP V2.3.0以前のバージョンからは、まずV2.3.xバージョンにアップグレードし、その後このバージョンにアップグレードする必要があります。

OceanBaseクラウドプラットフォームV3.1.2は、以下の表に記載されているバージョンのOceanBaseデータベースをサポートしています。

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.2.x

## 新機能

* アクティブセッション履歴レポートの生成とダウンロードをサポートします。

  アクティブセッション履歴レポートは、テナントのパフォーマンス診断機能の一部として、SQL、セッション、待機イベント、システム統計などの関連ビューからサンプルを取得し、ユーザーがデータベースの過去のアクティブセッション情報を確認できるようにします。詳細については、[アクティブセッション履歴レポートの管理](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380271)を参照してください。

* バックアップ・リストア機能がセカンダリバックアップをサポートします。

  セカンダリバックアップは、ベースラインデータとアーカイブログを含むバックアップファイルを他の場所にアーカイブする機能を提供します。セカンダリバックアップをサポートすることで、バックアップファイルのストレージ負荷を軽減できます。必要に応じて、
  * セカンダリバックアップについては、[バックアップ・リストアの概要](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380164)の**<UI-TERM key="ocp-v2.Component.AddBackupStrategy.SecondaryBackup">二次バックアップ</UI-TERM>**を参照してください。

  * セカンダリバックアップの使用については、[新規バックアップポリシーの作成](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380317)を参照してください。

* OCP内の異なる権限を持つユーザーの表示内容を最適化しました。

  この機能に対する権限がないユーザーにはエントリを非表示にし、ユーザーが見ることができる製品のパスを簡略化することで、ユーザーによる無効なクリックを削減します。

* OBProxyのタッチオーバーをサポートします。

  この機能により、タッチオーバープロセスが一段と整備されました。OceanBaseクラスタをタッチオーバーした後、そのOceanBaseクラスタに対応するOBProxyクラスタもOCPでタッチオーバーできるようになりました。OBProxyのタッチオーバーについては、[OBProxyのタッチオーバー](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380261)を参照してください。

* マルチゾーンモードにおいて、OCPはGUI管理をサポートします。

  マルチゾーンモードは、OceanBase、OCP、またはOBProxyがデータセンターや都市をまたいで展開される場合に、優先的に同一ゾーン内のターゲットにアクセスすることを制御します。マルチゾーンモードは、リンクの遅延を効果的に低減すると同時に、データセンターや都市をまたぐ帯域幅コストも削減します。マルチゾーンの詳細については、[マルチゾーンの概要](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380186)を参照してください。

  OCPによるマルチゾーン管理は以下をサポートします：
  * 各ゾーンの詳細情報を表示します。各ゾーンに含まれるデータセンター、対応するOCPなどの情報が含まれます。詳細については、[マルチゾーンの表示](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380368)を参照してください。

  * マルチゾーンパラメータの表示または変更を行います。詳細については、[マルチゾーンパラメータの管理](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380369)を参照してください。

## 機能強化

* SQL診断機能を最適化し、TopSQL、疑わしいSQL、SlowSQLのエクスポート機能を追加しました。

* クラスタおよびテナントのパフォーマンス監視機能を最適化し、クラスタおよびテナントのパフォーマンス指標収集機能を無効にした場合のヒントを追加しました。

* 監視収集のメモリ使用量を最適化し、OCPが管理するホスト数が増えてもパフォーマンスを保証します。

## 修正された問題

OceanBaseクラウドプラットフォームV3.1.2では、以下の問題が修正されました：

* SQL診断機能において、リモート計画と分散計画の統計情報が不正確であった。

* ob_host_log_disk_percent_over_thresholdアラートが一定期間報告された後、問題が解決されない状態で自動的に回復し、継続的なアラートが発報されなかった。

* OCPからOBProxyタイプのログをダウンロードする際、ダウンロードしたログを解凍できなかった。

* OCPのアップグレード後、テナントの作成日時がOCPのアップグレード日時にリセットされた。

* **TopSQL**にSQLテキストがないデータが存在した。

* OCPを通じてOBProxyパラメータを変更する際、一部のパラメータが変更できない、または特定の範囲内の値に変更できない場合があった。

* OCPを通じてテナントパラメータのrecyclebinの値をONに変更しても、反映されなかった。

* データ型フィールドが2つあるパーティションテーブルについて、このテーブルが1つのフィールドにのみパーティションを作成している場合、**<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">システム管理</UI-TERM>**の**<UI-TERM key="ocp-v2.Inspection.Item.ConfigRule.Inspection">巡回点検</UI-TERM>**でこのテーブルを巡検できなかった。

* OceanBaseクラスタのプライマリ/スタンバイ災害復旧切り替え後、プライマリ/スタンバイ関係は存在しないにもかかわらず、クラスタリストには引き続きプライマリ/スタンバイ関係として表示された。

## バージョンの使用制限

### ハードウェア要件

OCP-Serverは物理マシンにインストールできるほか、Dockerコンテナ内での実行もサポートしています。OCP-Serverは、複数ノードによる高可用性デプロイメントモードをサポートしています。

OCP-Serverノードの最低ハードウェア要件は以下の表のとおりです。

| ハードウェア  |                 要求                 |
|-----|------------------------------------|
| CPU | <li>x86_64、8コア</li><li>ARM AArch64アーキテクチャ、8コア</li> |
| メモリ  | 利用可能メモリ16GB                         |
| NIC  | 10ギガビットNIC                               |

OCP-Agent自体が消費するリソースは非常に少なく、インストールノードのハードウェアリソースに特別な要件はありません。

### オペレーティングシステム要件

OCPサーバー側（OCP-Agentを含む）のインストールに適したオペレーティングシステム要件は以下の表のとおりです。

|    サーバータイプ    |    オペレーティングシステム    |   対応バージョン    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2以降のバージョン |
| x86_64      | CentOS     | 7.2以降のバージョン |
| x86_64      | AliOS      | 7.2以降のバージョン |
| x86_64      | openSUSE   | 12 SP3以降 |
| ARM AArch64 | AliOS      | 7.2以降のバージョン |
| ARM AArch64 | NeoKylin    | 7.6       |
| ARM AArch64 | Huawei EulerOS | 2.0 SP8   |
