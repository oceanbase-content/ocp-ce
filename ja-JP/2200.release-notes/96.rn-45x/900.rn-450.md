# OCP V4.5.0

OCP V4.5.0が正式リリースされました！今回のアップグレードは、**OceanBase AIバージョン**の機能構築を中心に展開されています。OceanBase AIクラスタ（共有ストレージアーキテクチャ）への対応と互換性を新たに追加し、それに依存する基盤機能である**オブジェクトストレージ外部連携**と**LogService（ログサービス）コンポーネントのライフサイクル全体管理**を整備しました。これにより、ユーザーはOCP上でAIシナリオ下のデータベースおよび関連コンポーネントを統一的に管理・運用できるようになります。

**主な特徴**：

* **OceanBase AIバージョン対応と互換性**：OceanBase AIクラスタ（共有ストレージアーキテクチャ、カーネル最小バージョン4.6.2.0）の作成、運用、監視など、ライフサイクル全体のサポートを新たに追加。

* **オブジェクトストレージ外部連携**：「外部連携 - オブジェクトストレージ」管理機能を新たに追加。AIクラスタ、LogServiceクラスタが依存するオブジェクトストレージ（S3など）の接続情報と認証情報を一元的に管理し、接続性検証、AK/SKのローテーションをサポートします。

* **LogServiceコンポーネント管理**：LogService（ログサービス）クラスタの作成、起動・停止・再起動、スケーリング（Zone/Server）、AKローテーションなど、ライフサイクル全体の管理機能を新たに追加。

## 主な機能の解説

### OceanBase AIバージョンの適応と互換性

ユーザーがOCP上でOceanBaseの従来クラスタとAIバージョン（共有ストレージアーキテクチャ）クラスタを統一的に管理できるようにするため、今回のリリースではAIクラスタ関連の適応が追加されました：

* **バージョン要件**：AIクラスタが現在サポートする最低OceanBaseカーネルバージョンは **4.6.2.0** です。このバージョン未満の場合、作成時や検証時に処理が中断され、メッセージが表示されます。

* **運用保守機能**：AIクラスタの作成、Zoneのスケーリング時のオブジェクトストレージへの自動バインディング指示の配布、Unit仕様の運用保守、AI専用ソフトウェアパッケージのインストールとアンインストールをサポートします。

* **監視の適応**：共有ストレージ（SS）モードの収集項目とグラフ単位を区別し、データなしシナリオでの監視グラフの表示問題を修正しました。

* **機能制限**（AIクラスタは現在以下の機能をサポートしていません。操作時には明確なテキストプロンプトが表示されます）：

  * Oracleテナントの作成はサポートされていません。

  * プライマリ/スタンバイ（Standby）テナントの作成はサポートされておらず、ディザスタリカバリも現在サポートされていません。

  * クラスタの引き継ぎ（Takeover）はサポートされていません。

  * 単一Zoneの停止はサポートされていません。

### オブジェクトストレージの外部連携（新規、AIクラスタ/LogService依存サービス）

OceanBase AIクラスタとLogServiceクラスタはどちらもオブジェクトストレージ（例：S3）にデータを保存します。今回、「外部連携」に統一されたオブジェクトストレージ管理機能が新規追加されました：

* オブジェクトストレージ連携設定の新規作成/編集/削除をサポートし、Endpoint、Bucket、AK/SKなどの接続情報を一元的に管理します。

* オブジェクトストレージの接続性検証（Endpoint形式の検証を含む）をサポートし、事前に設定問題を発見できます。

* 利用元別（AIクラスタ / LogServiceクラスタ）でオブジェクトストレージの参照関係を確認できます。

* オブジェクトストレージのAK/SKを交換でき、カーネルのキーローテーション用SQLの仕様に対応し、ローテーション中にクラスタ側の同期を自動的に完了します。

### LogService（ログサービス）コンポーネントのライフサイクル管理（新規）

LogServiceクラスタの包括的な管理機能が新規追加され、メインメニューではOBProxy、Binlog、LogServiceの3種類のコンポーネントが統一された「コンポーネント」メニューに統合されました：

* **クラスタ管理**：作成、削除、起動、停止、再起動、状態同期

* **弾性スケーリング**：Zoneの一括新規作成/削除/起動/停止/再起動、Serverの一括新規作成/削除/起動/停止/再起動

* **パラメータ管理**：パラメータメタ情報、パラメータテンプレートの作成/編集/削除、クラスタパラメータのオンライン変更

* **セキュリティ**：オブジェクトストレージAK/SKのローテーションにおける事前検証とローテーション、組織権限（階層的組織可視性）管理

* **観測可能性**：ログサービス専用のモニタリング指標収集、アラートルール、ログクエリ

## 製品の最適化

### クラスタ管理

* AIクラスタでサポートされていない操作（Oracle/プライマリ/スタンバイテナントの作成、クラスタの引き継ぎ、単一ゾーンの停止など）を明確なエラーメッセージに統一し、誤操作のリスクを低減

* モニタリング指標の収集とグラフ表示を共有ストレージモードに合わせて最適化し、グラフの空データ表示異常を回避

* LogServiceクラスタは組織権限管理をサポートしており、多層組織構造下で権限に応じて表示範囲を制御可能

## 製品動作の変更

* メインメニュー構造の調整：OBProxy、Binlog、LogServiceが独立したメニューから「コンポーネント」メニューに統合

* 元の「ログサービス」機能は、Logserviceコンポーネント名との競合を避けるため、「ログ検索」と改称

* ランタイムPythonが2.7から3.8にアップグレードされました。Python 2.7の構文や依存関係に基づくカスタムアラートチャネルスクリプトを使用している場合、アップグレード後に実行失敗や動作変化が発生する可能性があります。

## 主な修正事項

OCP V4.5.0では、以下の問題が主に修正されました：

* OCPがソフトウェアパッケージのアップロードに成功した後、リストが表示されない問題を修正しました。

* OCPタスクのob_agentプロセス異常によりモニタリングデータ収集が失敗する問題を修正しました。

* OCPがOBソフトウェアパッケージを認識できない問題を修正しました。

## バージョンの使用制限

### ハードウェア要件

OCP-Serverは物理マシンにインストールできるほか、Dockerコンテナ内での稼働もサポートしています。OCP-Serverは複数ノードの高可用性デプロイメントモードをサポートしています。

OCP-Serverノードの最低ハードウェア要件は以下の表のとおりです。

| ハードウェア | 要件 |
|------|------|
| CPU | <li>X86_64、8コア</li><li>ARM AArch64アーキテクチャ、8コア</li> |
| メモリ | 利用可能メモリ 16 GiB |
| NIC | 10ギガビットNIC |

OCP-Agent自体が消費するリソースは非常に少なく、インストールノードのハードウェアリソースに特別な要件はありません。
