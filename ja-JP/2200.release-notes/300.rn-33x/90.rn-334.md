# OCP V3.3.4

<!--#RNDate#2022-10-21-->

OceanBase Cloud Platform（OCP）の新バージョンでは、一部の監査イベントが追加されたほか、その他の機能も向上・最適化されています。

## バージョン情報

* **バージョン番号：** V3.3.4

* **前回バージョン：** V3.3.3

* **リリース日：** 2022年10月21日

* **サポートされるアップグレードパス：** OCP V2.3.x以降のバージョンからは直接本バージョンにアップグレードできます。OCP V2.3.0より前のバージョンからは、まずV2.3.xバージョンにアップグレードし、その後本バージョンにアップグレードする必要があります。

## サポートされるOceanBaseデータベースのバージョン

OCP V3.3.4バージョンは、以下の表に記載されているバージョンのOceanBaseデータベースをサポートしています。

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## 機能の最適化

* 操作監査：Zoneの停止、Zoneの起動、Zoneの再起動、デッドロック検出スイッチの変更、ソフトウェアパッケージの削除、OceanBaseクラスタTopSQLスイッチの変更、OceanBaseクラスタのメジャーコンパクションのトリガー、OceanBaseクラスタのメジャーコンパクション失敗状態のクリア、テナントUnitの運用（スケールアウト・スケールイン）など、新しい監査イベントが追加されました。

* 診断中の **<UI-TERM key="ocp-v2.page.Overview.SuspiciousSql">不審なSQL</UI-TERM>** に新しい判断モードが追加され、PARTITION_CNTがAffectRowsを上回る場合、該当するSQLは **<UI-TERM key="ocp-v2.page.Diagnosis.SuspiciousSql">不審なSQL</UI-TERM>** として扱われます。

* スタンバイクラスタの作成プロセスが最適化され、プライマリ/スタンバイクラスタの作成完了の判定基準が、従来の **add standy コマンド成功** から **スナップショット接続完了** に調整されました。

* テストアラート機能が最適化され、環境変数のデフォルト値が追加され、テストアラートの成功率が向上しました。

* 二次バックアップパスの事前チェックロジックが最適化され、バックアップパス内に同一クラスタ名のディレクトリが存在することが禁止されました。

## 修正された問題

OCP V3.3.4バージョンでは、以下の問題が修正されました：

1. システム変数 `connect_timeout` の単位 **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.Seconds">秒</UI-TERM>** が誤って **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.Microseconds">マイクロ秒</UI-TERM>** と記述されていた問題を修正しました。

2. スロットリングを無効にした際、OCPが起動しない問題を修正しました。

3. 特定のアラートメッセージにおけるホストIPアドレスの記述ミスとテナントリストの記述ミスを修正しました。

4. 変更できないパラメータがフロントエンドで変更可能と表示される問題を修正しました。

5. AWRレポートの生成パフォーマンスを最適化し、テナント数が多い場合（100個以上）のレポート生成タイムアウト頻度を低減しました。

6. 内部テーブルのクエリステートメントを最適化し、業務負荷によるクラスタ状態表示異常を回避しました。

7. ホストの運用保守操作のフォールトトレランスを最適化しました。

8. Grafanaの監視データプッシュロジックを最適化し、データ欠落を防ぎました。

9. ホストのNTP遅延収集方式を最適化し、ホストに負荷がかかっている状態での精度を向上させました。

## バージョンの使用制限

### ハードウェア要件

OCP-Serverは物理マシンにインストールできるほか、Dockerコンテナ内での実行もサポートしています。OCP-Serverは複数ノードの高可用性デプロイメントモードをサポートしています。

OCP-Serverノードの最低ハードウェア要件は以下の表のとおりです。

| ハードウェア | 要件 |
|-----|------------------------------------|
| CPU | <li>x86_64、8コア</li><li>ARM aarch 64アーキテクチャ、8コア</li> |
| メモリ | 利用可能メモリ16GB |
| NIC | 10ギガビットNIC |

OCP-Agent自体が消費するリソースは非常に少なく、インストールノードのハードウェアリソースに特別な要件はありません。

### オペレーティングシステム要件

OCPサーバー側（OCP-Agentを含む）のインストールに必要なオペレーティングシステム要件は以下の表のとおりです。

|    サーバータイプ    |    オペレーティングシステム    |   サポートバージョン    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2以降のバージョン |
| x86_64      | CentOS     | 7.2以降のバージョン |
| x86_64      | AliOS      | 7.2以降のバージョン |
| x86_64      | openSUSE   | 12 SP3以降 |
| ARM aarch64 | AliOS      | 7.2以降のバージョン |
| ARM aarch64 | NeoKylin     | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |

### クライアント要件

一般的にユーザーはWebブラウザを通じてOCPサービスにアクセスします。そのため、クライアントに関する要件は以下のとおりです。

| ブラウザ     | 最小バージョン |
|---------|------|
| Chrome  | 81   |
| Firefox | 64   |
| Safari  | 10   |
| Edge    | 13   |

iOSオペレーティングシステムを搭載したデバイスからOCPにアクセスする場合、バージョン要件は以下の表のとおりです。

| OS         | 最小バージョン |
|------|------|
| iOS  | 10   |

最適な使用体験を得るために、解像度が1440 × 810を超えるディスプレイの使用を推奨します。
