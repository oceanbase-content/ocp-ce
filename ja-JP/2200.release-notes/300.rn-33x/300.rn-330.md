# OCP V3.3.0

<!--#RNDate#2022-04-27-->

OceanBase Cloud Platform（OCP）の新バージョンでは、主にSQL診断機能がアップグレードされ、プライマリ/スタンバイデータベースの分離など豊富な機能が追加されています。同時に、その他の機能についても詳細な最適化が施されています。

## バージョン情報

* **バージョン番号：** V3.3.0

* **前回のバージョン：** V3.2.3

* **リリース日：** 2022年4月27日

* **サポートされているアップグレードパス：** OCP V2.3.x以降のバージョンからは、このバージョンへ直接アップグレードできます。OCP V2.3.0より前のバージョンからは、まずV2.3.xにアップグレードし、その後このバージョンにアップグレードする必要があります。

## サポートされているOceanBaseデータベースのバージョン

OCP V3.3.0は、以下の表に記載されているバージョンのOceanBaseデータベースをサポートしています。

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## 新機能

### 診断関連

* トランザクション診断

  コールチェーン上に長時間トランザクションやハングしたトランザクションが存在すると、特定のリソースを長時間占有し続け、システムを不安定な状態に陥れ、効率的なサービス提供に影響を与えます。トランザクション診断は、トランザクションの監視と分析を提供し、トランザクションの **詳細情報**、**<UI-TERM key="ocp-v2.Transaction.Detail.ExecutionInformation">実行情報</UI-TERM>**、および **<UI-TERM key="ocp-v2.Transaction.Detail.SqlExecutionDetails">実行された SQL の詳細</UI-TERM>** を提供します。これにより、トランザクションのモデルを把握し、時間やリソースを消費する具体的な原因を判断できます。

  同時に、OCPは異常なトランザクションに対処するための緊急手段を提供しており、ワンクリックで異常なトランザクションを停止し、システムを迅速に安定した状態に戻すことができます。

  <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/1.png) -->

* 関連分析

  トランザクション診断、AP SQL診断、SQLリクエスト分析といった新しい診断次元を追加したほか、アラート、監視、トランザクション、SQL、トレース間の関連分析もサポートしています。

  <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/2.png) -->

  <!-- ![5](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/6.png) -->

* SQLリクエスト分析

  既存のSQL診断機能に加え、SQLリクエスト分析が追加されました。これにより、**データベース/SQL**タイプの観点から、すべてのデータベースリクエストの実行状況を分析できます。実行時間の分布、各種類のSQLの割合、実行傾向などを確認できます。これにより、SQLの実行状況をより包括的に理解できるだけでなく、SQL実行プロセスで異常が発生していないかをより簡単かつ迅速に把握できます。

  <!-- ![6](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/7.png) -->
  <!-- ![7](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/8.png) -->

* パラレルSQL実行の概要

  SQL診断はOLAP型SQLの分析・診断機能を強化し、分散クエリ、パラレルクエリ、複数テーブルのJOIN、APなどの複雑なSQLシナリオにおいて、SQL実行プロセス内で具体的に遅延している演算子や手順を特定し、SQLチューニングの進行を加速します。

* カスタム列

  SQL診断機能では、カスタム列と高度な条件フィルタリングをサポートしています。

  <!-- ![11](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/12.png) -->
* SQL最適化の推奨事項

  現在、SQL診断は優れた異常検知能力を備えており、SlowSQLの存在を検知するだけでなく、専門家の経験に基づいて疑わしいSQLの存在も検知できます。同時に、SQL診断はSQLの同時実行数制限、プラン/インデックスのバインドなど、非常に実用的な緊急対応策を提供しています。しかし、システムが検出した異常なSQLについては、どのように緊急対応を行うかをご自身で判断する必要があります。SQL最適化の推奨事項は、SQLチューニングの方法をガイド（推奨）するために役立ちます。

  現在、OCPは最適なインデックス作成の推奨、履歴実行計画の推奨、テナントCPU拡張の推奨などの機能をサポートしており、SQL問題の解決をより迅速に進めるための指導と支援を提供します。

  <!-- ![12](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/13.png) -->

* デッドロック検出

  デッドロック検出は、デッドロックに関与する各ノードのロール、デッドロックが発生した実行順序、デッドロックノードに対応する実行SQLなど、デッドロックの詳細情報を表示します。これにより、デッドロックの根本原因を分析し、循環依存関係をリアルタイムで解析して解消することができます。

  <!-- ![13](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/14.png) -->

* 緊急対応

  以前からの実行計画のバインディング機能に加え、単一のSQLまたは複数のSQLに対する同時実行数制限機能を提供し、緊急時に対応できます。

### プライマリ/スタンバイデータベース

* プライマリ/スタンバイデータベースの分離

  プライマリデータベースとスタンバイデータベースを物理的に分割し、スタンバイデータベースを独立したプライマリデータベースとして設定できます。これにより、本番環境での業務演習や負荷テストが容易になります。

  <!-- ![14](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/15.png) -->

* Failover後の元プライマリデータベースは読み取り専用モードで起動

  新しいプライマリデータベースのデータ検証と移行を容易にするため、OCPは災害復旧後に使用されなくなった元プライマリデータベースを読み取り専用モードで起動することをサポートしています。Failover後の元プライマリクラスタを読み取り専用クラスタとして起動すると、新しいプライマリクラスタと元のプライマリクラスタのデータを比較・修正できます。

### アラート

カスタムアラートをサポートしており、監視指標を簡単にアラート情報に変換できます。

## 機能強化

* アラート機能が強化され、カスタムアラート指標をサポートし、監視指標を簡単にアラート情報に変換できるようになりました。また、スロークエリに対するアラート設定も可能になりました。

* 組織権限管理機能が強化されました。必要に応じてすべてのリソースを一つの組織にまとめることができ、リソースの管理と識別が容易になりました。

* クラスタの**<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**機能が改善されました。パフォーマンス監視に**ブロックキャッシュサイズ**、**<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.CacheHitRate">キャッシュヒット率</UI-TERM>**、**キャッシュリクエスト数**、**オープンカーソル数**の統計情報表示が追加されました。

* データ基盤機能が強化されました。ocp-agentが収集したOBServerノードやOBProxyなどのログをES/SLSなどのストレージプラットフォームに書き込む機能が強化され、完全なログクエリ機能を備え、より多くのログ分析などの機能のためのデータ基盤が整備されました。

## 修正された問題

OCP V3.3.0では、以下の問題が修正されました：

* 特定のシナリオで、agentの再インストールが失敗する問題。

* OceanBaseのアップグレードプロセスにおいて、ロールバックや再試行によりテナントデータが削除される可能性がある問題。

* 特定のシナリオで、OBProxyの設定ページに「OBProxyのパラメータバージョンとクラスタのパラメータバージョンが一致しません。設定を更新してください」というエラーが表示される問題。

* 特定のシナリオで、OBProxyプロセスが繰り返し起動される問題。

* 特定のシナリオで、ホストの状態表示が異常になる問題。

* ソフトウェアパッケージのソートでエラーが発生する問題。

* クラスタのパフォーマンスレポートにおいて、特定のシナリオでテナント名が異常に表示される問題。

* logbackコンポーネントのバグにより、多数のtmpログファイルが残存する問題。

* 特定のシナリオでSQL診断がデータをクエリできない問題。

* OCPのフロントエンド応答が極めて遅く、ocp-serverコンテナのCPU使用率が常に高い状態が続く問題。

## バージョンの使用制限

### ハードウェア要件

OCP-Serverは物理マシンにインストールできるほか、Dockerコンテナ内での稼働もサポートしています。OCP-Serverは、マルチノードの高可用性デプロイメントモードをサポートしています。

OCP-Serverノードの最低ハードウェア要件は以下の表のとおりです。

| ハードウェア  |                 要件                 |
|-----|------------------------------------|
| CPU | <li>x86_64、8コア</li><li>ARM AArch64アーキテクチャ、8コア</li> |
| メモリ  | 利用可能メモリ16GB                         |
| NIC  | 10ギガビットNIC                               |

OCP-Agent自体が消費するリソースは非常に少なく、インストールノードのハードウェアリソースに特別な要件はありません。
