# 標準運用保守プロセスの実行詳細を表示する

この記事では、標準運用保守プロセス(SOP)タスクの実行詳細を表示し、実行中のタスクに対して運用保守操作を実行する方法について説明します。

## 前提条件

* 現在OCPにログインしているユーザーが、**クラスタ管理**、**テナント管理**、または**ホスト管理**のいずれかのリソース権限(対象リソースを操作するために使用されます)を持っていること。
* クラスタ/テナント/ホストの**更新**権限(起動、次の手順の実行、手順の再試行などの操作に使用されます)。
* SOP権限は、システムがログインユーザーの種別に基づいて自動的に判断します。詳細については、[標準運用保守プロセスの概要](100.sop-overview.md#権限の説明)を参照してください。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能を提供していません。</p>
</main>

## 実行詳細の表示

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.src.hook.useMenu.OMManagement">運用および保守管理</UI-TERM>** > **<UI-TERM key="ocp-v2.src.hook.useMenu.StandardProcess">標準プロセス</UI-TERM>** をクリックします。

3. **<UI-TERM key="ocp-v2.pages.Sop.StandardProcess">標準プロセス</UI-TERM>** ページで対象タスクを見つけ、タスク名または **<UI-TERM key="ocp-v2.Main.ExecutionDetail.ExecutionDetails">実行の詳細</UI-TERM>** をクリックして、実行詳細ページに移動します。

実行詳細ページには以下の情報が表示されます：

### 基本情報

タスクの基本情報を表示します。タスク名、タスクタイプ、実行対象、作成時間、作成者、開始時間、終了時間、現在の状態が含まれます。

### 実行進捗

タスクの全体的な実行進捗を表示します。完了したステップ数と有効なステップの総数(例：7/7)および各ステップの実行状態が含まれます。

### ステップリスト

すべてのステップの詳細な実行情報を表示します：

| 項目 | 説明 |
|------|------|
| ステップ番号 | ステップの実行番号。 |
| ステップ名 | ステップの表示名。 |
| ステップ状態 | ステップの現在の状態：<ul><li>**PENDING**：実行待ち。</li><li>**RUNNING**：実行中。</li><li>**SUCCESSFUL**：正常に完了。</li><li>**FAILED**：実行失敗。</li></ul> |
| 自動実行 | このステップが自動実行モードかどうか。 |
| 関連タスク | ステップの実行中に作成されたOCPタスクインスタンスID。 |
| 再試行回数 | このステップの再試行回数。 |
| エラーメッセージ | ステップの直近の失敗エラーメッセージ。 |
| 開始時間 | ステップの実行開始時間。 |
| 終了時間 | ステップの実行終了時間。 |

## メンテナンス操作

タスクの状態に応じて、以下の操作を実行できます。

### タスクの開始

**<UI-TERM key="ocp-v2.src.constant.schedule.ToBeImplemented">実行待ち</UI-TERM>** 状態のタスクについて、**<UI-TERM key="ocp-v2.src.constant.logservice.Start">起動</UI-TERM>** をクリックすると、実行インスタンスを作成し、最初のステップを開始します。

* 最初のステップが自動実行の場合、返されるステータスはその場での処理結果によって決まります。
* 最初のステップを手動で実行する必要がある場合、返されるステータスは **<UI-TERM key="ocp-v2.src.constant.alarm.WaitingForConfirmation">確認待ち</UI-TERM>** となります。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>各タスクは1回しか開始できません。開始後は再開始できません。</p>
</main>

### 次のステップの実行

タスクの状態が **<UI-TERM key="ocp-v2.src.constant.alarm.WaitingForConfirmation">確認待ち</UI-TERM>** または **<UI-TERM key="ocp-v2.src.constant.schedule.InExecution">実行中</UI-TERM>** であり、かつ `autoRun=false` の準備完了ステップが存在する場合、**次のステップの実行** をクリックすると、手動ステップを進めることができます。

* 複数のステップを進めることができる場合は、進めるステップの番号を選択する必要があります。
* 次のステップを実行する際には、明示的な確認が必要です。確認しない限り、進めることはできません。

### 失敗したステップの再試行

ステップの実行に失敗した場合、以下の再試行操作をサポートしています：

* **すべての失敗したステップの再試行**：実行インスタンス全体の状態が **FAILED** の場合、すべての失敗したステップを一度に再試行できます。

* **指定された失敗したステップの再試行**：状態が **FAILED** の個々のステップを再試行します。実行インスタンス全体が **FAILED** 状態である必要はありませんが、指定したステップは **FAILED** でなければなりません。

### ステップ設定の更新

開始済みタスク内で **PENDING** 状態のステップについて、その設定を更新できます：

* **自動実行スイッチの変更**：テンプレートで編集可能（editable=true）とマークされているステップのみ変更が許可されます。
* **ステップパラメータの設定**：ステップの実行前にステップレベルのパラメータを保存できます。異なるSOPタイプ/ステップで設定可能なパラメータは異なります：
  * **OBServer異常後のデータ再構築** の **OBServerの追加** ステップ：代替ホストID（`replacementHostId`）と代替ホストIP（`replacementHostIp`）を設定できます。
  * **スタンバイテナントの再構築** の **スタンバイテナントの新規作成** ステップ：テナント名、互換モード、プライマリテナントID、スタンバイクラスタID、プライマリ/スタンバイ同期方式、Zoneレプリカ設定、テナントパラメータなど、新しいスタンバイテナントを作成するための完全なパラメータ（`createStandbyTenantParamJson`）を設定できます。

### タスクの編集

**実行待ち** 状態のタスクについて、**編集** をクリックすると、タスクの名前、ターゲットパラメータ、ステップ設定、備考を変更できます。タスクの種類は変更できず、サーバー側は常にタスクの元の種類を維持します。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>開始済みのタスクは編集できません。タスクに実行インスタンスが存在する場合、エラーが返されます。</p>
</main>

### タスクの削除

* **実行待ち** 状態のタスクは直接削除できます。
* **終了** および **失敗** 状態のタスクは削除できます。
* **確認待ち** および **実行中** 状態のタスクは削除できません。

タスクを削除すると、実行インスタンス、ステップの実行履歴、およびステップ関連タスクの記録が連鎖的にクリーンアップされます。

## ステップ識別子の説明

異なるSOPタイプのステップ識別子は以下のとおりです。タスクの作成時および編集時には、ステップ配列に対応するタイプの識別子のみを使用できます。

| SOPタイプ | ステップ識別子（デフォルトのステップ順序） |
|----------|------------------------|
| スタンバイテナントの再構築 | 操作対象の確認（CONFIRM_STANDBY_TENANT_INFO）、プライマリ/スタンバイの分離（DISCONNECT_STANDBY_TENANT）、元のスタンバイテナントのロック（LOCK_STANDBY_TENANT）、プライマリテナントのバックアップ（BACKUP_PRIMARY_TENANT）、元のスタンバイテナントの削除（DELETE_STANDBY_TENANT）、スタンバイテナントの新規作成（CREATE_STANDBY_TENANT）、プライマリ/スタンバイ同期の検証（VERIFY_PRIMARY_STANDBY_SYNC） |
| レプリカ異常時のアービトレーションサービスの開始 | 操作対象の確認（CONFIRM_ARBITRATION_TARGET）、アービトレーションサービスの追加（ADD_ARBITRATION_SERVICE）、テナントレプリカの削除（DELETE_TENANT_REPLICA）、OBServerの削除（DELETE_OBSERVER）、テナントアービトレーションサービスの有効化（ENABLE_TENANT_ARBITRATION）、テナントアービトレーションサービスの可用性検証（VERIFY_TENANT_ARBITRATION） |
| OBServer異常後のデータ再構築 | 操作対象の確認（CONFIRM_OBSERVER_TARGET）、テナントレプリカの削除（DELETE_TENANT_REPLICA）、OBServerの削除（DELETE_OBSERVER）、ホストの強制削除（FORCE_DELETE_HOST）、OBServerの追加（ADD_OBSERVER）、テナントレプリカの追加（ADD_TENANT_REPLICA）、テナントレプリカ再構築の成功検証（VERIFY_REPLICA_REBUILD） |
