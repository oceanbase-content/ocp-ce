# 標準運用保守プロセスの作成

この記事では、OCPで標準運用保守プロセス(SOP)タスクを新規作成する方法について説明します。

## 前提条件

* 現在OCPにログインしているユーザーが、**クラスタ管理**、**テナント管理**、または**ホスト管理**のいずれかのリソース権限(対象リソースを操作するために使用されます)を持っていること。
* クラスタ/テナント/ホストの**更新**権限(作成、起動、または実行の手順に使用されます)。
* SOP権限は、システムがログインユーザーの種別に基づいて自動的に判断します。詳細については、[標準運用保守プロセスの概要](100.sop-overview.md#権限の説明)を参照してください。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能を提供していません。</p>
</main>

## 背景

OceanBaseクラスタ、テナント、またはホストに対して標準化された障害回復操作を実行する必要がある場合、SOPタスクを新規作成して実行できます。OCPは事前設定されたプロセステンプレートを提供しており、タスクタイプを選択し、対象パラメータと手順を設定するだけで、標準運用保守プロセスタスクを作成できます。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.src.hook.useMenu.OMManagement">運用および保守管理</UI-TERM>** > **<UI-TERM key="ocp-v2.src.hook.useMenu.StandardProcess">標準プロセス</UI-TERM>** をクリックします。

3. **<UI-TERM key="ocp-v2.pages.Sop.StandardProcess">標準プロセス</UI-TERM>** ページで、**<UI-TERM key="ocp-v2.Content.BasicInformation.ModifyDataStorageModal.NewCreation">新設</UI-TERM>** をクリックすると、システムは **<UI-TERM key="ocp-v2.Sop.CreateTaskDrawer.NewStandardOperationAndMaintenance">標準運用プロセスの新規作成</UI-TERM>** ダイアログボックスをポップアップ表示します。

4. **<UI-TERM key="ocp-v2.Sop.CreateTaskDrawer.NewStandardOperationAndMaintenance">標準運用プロセスの新規作成</UI-TERM>** ダイアログボックスで、以下の情報を設定します。

   1. 基礎情報を設定します。

      | パラメータ | 説明 |
      |------|------|
      | **<UI-TERM key="ocp-v2.pages.Schedule.CreateTaskDrawer.TaskName">タスク名</UI-TERM>** | タスクの名前を入力します。以下のルールに従う必要があります：<ul><li>2～32文字をサポートします。</li><li>中国語、日本語の文字、または英字で始まる必要があります。</li><li>中国語、日本語の文字、英字、または数字で終わる必要があります。</li><li>特殊文字はアンダースコアのみサポートします。</li></ul>タスク名はグローバルに一意である必要があります。 |
      | **<UI-TERM key="ocp-v2.pages.Schedule.TaskDetailDrawer.TaskType">タスクの種類</UI-TERM>** | SOPタスクタイプを選択します。**<UI-TERM key="ocp-v2.Sop.core.constants.RebuildStandbyTenant">スタンバイテナントの再構築</UI-TERM>**、**<UI-TERM key="ocp-v2.Sop.core.constants.QuorumServiceEnabledWithCopy">レプリカ異常時のアービトレーションサービスの有効化</UI-TERM>**、または **OBServer異常後のデータ再構築** を選択できます。各タイプの詳細については、[標準運用保守プロセスの概要](100.sop-overview.md#sopタイプの説明)を参照してください。 |
      | **<UI-TERM key="ocp-v2.External.Component.CreateEsDataSource.Remarks">備考</UI-TERM>** (オプション) | タスクの用途や説明を記録するための備考情報を入力します。 |
      | **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ExecuteNow">今すぐ実行</UI-TERM>** | このチェックボックスを選択すると、タスクの作成が成功した後、直ちに実行が開始されます。選択しない場合、タスクの作成後の状態は **<UI-TERM key="ocp-v2.src.constant.task.ToBeExecuted">実行待ち</UI-TERM>** となり、後から手動で開始できます。 |

   2. 選択したタスクタイプに応じて、対象パラメータを設定します。

      * **<UI-TERM key="ocp-v2.Sop.core.constants.RebuildStandbyTenant">スタンバイテナントの再構築</UI-TERM>**：再構築するスタンバイテナントが属するクラスタとスタンバイテナントを選択し、プライマリ/スタンバイ同期方式(ネットワークベースまたはアーカイブベース)を選択します。

      * **<UI-TERM key="ocp-v2.Sop.core.constants.QuorumServiceEnabledWithCopy">レプリカ異常時のアービトレーションサービスの有効化</UI-TERM>**：対象クラスタを選択し、アービトレーションサービスまたはアービトレーションサービスグループ(いずれか一方)を選択します。

      * **OBServer異常後のデータ再構築**：対象クラスタを選択し、代替ホストを事前に選択できます。代替ホストを選択しない場合は、**<UI-TERM key="ocp-v2.src.constant.oceanbase.AddObserver">OBServerを追加する</UI-TERM>** の手順を実行する前に設定できます。

   3. 手順を設定します。

      システムは選択したタスクタイプに応じてデフォルトの手順テンプレートを自動的に読み込みます。各手順の設定を確認および調整できます：

      | パラメータ | 説明 |
      |------|------|
      | 手順番号 | 手順の実行順序。1から始まります。移動可能な手順は、テンプレート内で位置を調整できます。 |
      | 手順名 | 現在の手順の表示名。 |
      | 手順タイプ | **EXECUTABLE**：実行系手順。OCPタスクインスタンスを作成する可能性があります。**CONFIRMATION**：確認系手順。タスクインスタンスは作成しません。 |
      | **<UI-TERM key="ocp-v2.Component.ArbitrationServerList.AutomaticExecution">自動実行</UI-TERM>** | 有効にすると、前の手順の完了後にこの手順が自動的にトリガーされます。無効にすると、この手順は人の確認後に進行します。一部の手順では、自動実行のスイッチを変更できません。 |
      | **<UI-TERM key="ocp-v2.component.CPUBindCoreConfigDrawer.Enable">有効にする</UI-TERM>** | この手順を有効にするかどうか。一部の手順は固定で有効であり、無効にすることはできません。|

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><ul><li>手順の <b>stepKey</b> はテンプレートに属している必要があり、重複してはなりません。</li><li>固定で有効な手順は維持され、無効にすることはできません。</li><li>手順の自動実行スイッチが変更可能かどうかは、テンプレート内のその手順の <b>editable</b> 属性によって決まります。</li></ul></p>
      </main>

5. **<UI-TERM key="ocp-v2.page.External.CreateDrawer.Create">新規作成</UI-TERM>** をクリックします。

   * **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ExecuteNow">今すぐ実行</UI-TERM>** が選択されている場合、タスク作成後に自動的に実行が開始され、ページは実行詳細ページに切り替わります。
   * **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ExecuteNow">今すぐ実行</UI-TERM>** が選択されていない場合、タスク作成後の状態は **<UI-TERM key="ocp-v2.src.constant.plan_PENDINGExecution">実行待ち</UI-TERM>** となります。タスクリストで確認し、いつでも実行を開始できます。

## 次のステップ

* **実行待ち** 状態のタスクについては、実行の開始、タスク設定の編集、またはタスクの削除ができます。
* 実行中のタスクについては、実行詳細の確認、次の手順の実行、失敗した手順の再試行、または手順設定の更新ができます。詳細については、[標準運用プロセスの実行詳細を見る](300.view-sop-execution-details.md)を参照してください。
