# 標準運用保守プロセスの概要

標準運用保守プロセス（Standard Operating Procedure、SOP）は、OCPが提供する標準化された障害回復およびデータ再構築機能です。OceanBaseデータベースの運用保守において一般的な複雑な操作シナリオに対して、SOPは複数の手順からなる運用保守プロセスを標準化されたタスクテンプレートに編成し、自動実行と手動トリガーを組み合わせたハイブリッドモードをサポートします。これにより、安全かつ効率的に障害回復操作を完了できます。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能を提供しません。</p>
</main>

## 権限の説明

SOP権限はロール設定の権限項目をチェックする方式ではなく、システムがログインユーザーの身元を自動的に判断します。異なる身元のユーザーが実行できる操作は以下のとおりです：

| 身元 | 実行可能な操作 |
|------|-----------|
| システム管理者（ADMIN） | すべてのSOPタスクの表示と操作。 |
| 組織管理者（ORG_ADMIN） | 自身の組織内のすべてのSOPタスクの表示と操作。 |
| 読み取り専用管理者（ADMIN_VIEWER） | 表示のみ可能で、作成、編集、起動、実行はできません。default組織の読み取り専用管理者はすべてのタスクを表示できますが、他の組織の読み取り専用管理者は自身の組織のタスクのみを表示できます。 |
| その他のログインユーザー | 自身が作成したSOPタスクの表示と操作のみ可能です。ロールにSOPが設定されているかどうかは関係ありません。 |

未ログインユーザーはSOPにアクセスできません。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>SOPは独立した権限項目としてロール設定には現れません。</p>
</main>

### クラスタ/テナント権限との関係

SOPインターフェースが許可された後でも、作成、起動、実行時には操作対象のリソース権限が検証されます。例えば、クラスタに**更新**権限がない場合、SOPページは開けても、そのクラスタに対して実際にSOPタスクを作成または実行することはできません。

## 前提条件

* 現在OCPにログインしているユーザーが、**クラスタ管理**、**テナント管理**、または**ホスト管理**のいずれかのリソース権限を持っていること。（対象リソースを操作するために使用）
* クラスタ/テナント/ホストの**更新**権限。（作成、起動、または実行のステップに使用）

## 機能の概要

SOPは、事前に設定された複数の標準運用保守プロセステンプレートを提供しています。各テンプレートには、順序良く実行される標準的なステップのセットが含まれています。ビジネスシナリオに応じて適切なプロセスタイプを選択し、ステップの自動実行属性を設定し、必要に応じて人の確認を経てプロセスを進めることができます。

SOPの主な特徴は以下のとおりです：

* **プロセスのテンプレート化**：各SOPタイプには、事前に設定された標準ステップテンプレートが提供されます。ステップの実行順序、タイプ、識別子はすべて固定されており、操作の規範性を確保します。
* **自動と手動の組み合わせ**：各ステップで自動実行の有無を設定できます。自動実行ステップは前のステップが完了すると自動的にトリガーされます。非自動実行ステップは自動的にはトリガーされず、次のステップへの進行は手動で行う必要があります。
* **プロセスの追跡可能性**：各ステップの実行状態、開始/終了時間、関連タスク、リトライ回数、エラーメッセージが完全に記録されており、問題の特定や監査に役立ちます。
* **柔軟な障害処理**：ステップの実行に失敗した場合、単一の失敗ステップまたはすべての失敗ステップをリトライできます。非自動実行ステップは、実行前に自動実行スイッチやステップパラメータを変更できます。

## タスクリスト

**標準プロセス**ページでは、タスク名、タスクタイプ、実行対象、実行進捗状況、作成日時、作成者、開始時刻、終了時刻、ステータスなどの情報を含むすべてのSOPタスクを確認できます。

* 検索ボックスにタスク名を入力すると、タスクをあいまい検索できます。
* タスク名または**実行詳細**をクリックすると、そのタスクの実行詳細を確認できます。これには、手順設定、実行ステータス、手順の実行情報が含まれます。詳細については、[標準運用保守プロセスの実行詳細を表示する](300.view-sop-execution-details.md)を参照してください。
* 標準運用保守プロセスタスクの新規作成をサポートします。詳細については、[標準運用保守プロセスの新規作成](200.create-a-sop-task.md)を参照してください。

### タスクステータスの説明

| ステータス | 説明 |
|------|------|
| 待実行（NOT_STARTED） | タスクは作成されましたが、まだ実行を開始していません。 |
| 確認待ち（WAITING_CONFIRM） | タスクが実行中です。現在の手順では、次の手順への進行を手動で行う必要があります。 |
| 実行中（RUNNING） | タスクが実行中です。現在の手順は自動的に実行されています。 |
| 失敗（FAILED） | タスクの実行中に失敗した手順が発生しました。 |
| 完了（COMPLETED） | タスクのすべての有効な手順が正常に完了しました。 |

## SOPタイプの説明

OCPは現在、以下の3種類の標準運用保守プロセスタイプをサポートしています：

### レプリカ異常時のアービトレーションサービスの開始

クラスタ内のレプリカに異常が発生した場合、アービトレーションサービスを開始することでテナントの可用性を保証するために使用されます。このプロセスには、操作対象の確認、アービトレーションサービスの追加、テナントレプリカの削除、OBSERVERの削除、テナントアービトレーションサービスの開始、テナントアービトレーションサービスの可用性の検証などの手順が含まれます。対象クラスタおよびアービトレーションサービスまたはアービトレーションサービスグループを指定する必要があります。

### OBSERVER異常後のデータ再構築

OBSERVERノードに障害が発生した後、障害ノードを削除し、新しいノードを追加することでデータの再構築を完了するために使用されます。このプロセスには、操作対象の確認、テナントレプリカの削除、OBSERVERの削除、ホストの強制削除（オプション）、OBSERVERの追加、テナントレプリカの追加、テナントレプリカの再構築成功の検証などの手順が含まれます。代替ホストの事前選択をサポートしています。

### スタンバイテナントの再構築

スタンバイテナントのデータに異常や損傷が発生した場合、プライマリテナントのデータをバックアップし、スタンバイテナントを再作成することで復元を完了するために使用されます。このプロセスには、操作対象の確認、プライマリテナントのバックアップ、プライマリ/スタンバイの分離、元のスタンバイテナントのロック、元のスタンバイテナントの削除、スタンバイテナントの新規作成、プライマリ/スタンバイ同期の検証などの手順が含まれます。プライマリ/スタンバイ同期方式は、ネットワーク（NETWORK）ベースとアーカイブ（LOG_BACKUP）ベースの2つのモードをサポートしています。
