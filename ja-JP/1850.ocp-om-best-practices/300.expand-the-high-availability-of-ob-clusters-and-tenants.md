# OceanBaseクラスタおよびテナントの高可用性の拡張

このセクションでは、OCPを使用してOceanBaseクラスタおよびテナントの高可用性機能を拡張する方法について説明します。

## 適用シナリオ

* データセンターの数を増やし、より信頼性の高い高可用性機能を提供する。例えば、**2リージョン3データセンター**構成から**3リージョン5データセンター**構成への拡張。
* ビジネス移行に伴うデータセンターの移転。ビジネスアクセスにほとんど影響を与えることなく、OceanBaseクラスタのすべてのサーバーを別のデータセンターに移行する。

## 前提条件

* ゾーンを追加する際は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス**リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** メニュー権限。

* レプリカを追加する際は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス**または**テナントメンテナンス**リソース権限。
  * テナント **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* ゾーンを追加する前に、OceanBaseクラスタは **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Running">実行中</UI-TERM>** 状態である必要があります。
* OCP内にOBServerをデプロイ可能なホストが存在すること。
* テナントレプリカを追加する前に、テナントは **<UI-TERM key="ocp-v2.page.Information.Running">実行中</UI-TERM>** 状態である必要があります。

## 注意事項

1. OceanBase V4.0以降では、テナント内の各レプリカのUnit数を一致させる必要があります。テナントレプリカを追加する前に、ゾーン内に十分なホストリソースがあることを確認してください。

2. ゾーンを追加する前に、拡張対象のすべてのホストがOceanBaseクラスタの時刻ソースと同期されており、時刻のずれが10msを超えないことを確認してください。

    チェック方法：OceanBaseクラスタのRSリーダーホストで、拡張するホストのIPアドレスを指定してclockdiffを実行し、時刻のずれを確認します。

3. アービトレーションサービスを有効にするには、テナントが2F/4Fモードである必要があります。テナントでアービトレーションサービスが有効になっている場合、2Fから4Fへの拡張のみが可能です。

## 手順

操作の詳細については、[ゾーンの追加](../600.cluster-functions/500.manage-a-zone/100.create-a-zone.md)および[レプリカの追加](../700.tenant-functions/1000.manage-tenant-replica/200.create-a-replica.md)を参照してください。

**<UI-TERM key="ocp-v2.Tenant.Detail.NewCopy">レプリカを追加</UI-TERM>**は非同期タスクであり、タスクがトリガーされるとRSバックグラウンドスケジューラーによって段階的に完了します。データ量が多い場合、データコピーには時間がかかる可能性があります。以下のコマンドを参考に、定期的にデータコピーの状態を確認することを推奨します：

```SQL
# OceanBaseクラスタのsysテナントのoceanbaseデータベースに接続
mysql -hxxx.xxx.xxx.xxx -P2881 -uroot@sys -Doceanbase

# RSの履歴タスクレコードを確認し、tenant_balance_finishedが表示されればデータコピーが完了したことを示します
select * from __all_rootservice_event_history order by gmt_create desc limit 10;

# サーバーの状態を確認します。startはoffline時間より遅く、statusはactiveである必要があります。
select svr_ip, gmt_modified, zone, usec_to_time(start_service_time), usec_to_time(last_offline_time), status from __all_server;

# データレプリカが補完されているかどうかを確認します。<レプリカ数> を期待されるレプリカ数に置き換えてください。空を返す場合は補完済みです。
select /*+read_consistency(weak)*/ count(*)c from gv$partition group by table_id, partition_id having c != <レプリカ数>;

# ログが同期されているかどうかを確認します。空を返す場合は同期済みです。
select svr_ip, svr_port, table_id, partition_idx from __all_virtual_clog_stat where is_in_sync= 0 and is_offline = 0 and replica_type != 16;
```

## よくある質問

Q1：テナントのレプリカを追加する際、記事で示されている方法でデータコピーを確認すると、非常に遅いです。
A：以下のコマンドを参考に、データコピーの並列パラメータを適切に引き上げることで、移行を加速できます。

```SQL
# クラスタのデータコピー並列パラメータを確認し、設定を元に戻せるよう、現在のパラメータ値を記録します。
show parameters like "%data_copy_concurrency%";
show parameters like "%server_data_copy_out_concurrency%";
show parameters like "%server_data_copy_in_concurrency%";

# 並列パラメータを引き上げます。
alter system set data_copy_concurrency=100;
alter system set server_data_copy_out_concurrency=40;
alter system set server_data_copy_in_concurrency=40;
```

OCPのリソース管理インターフェースでテナントのレプリカ分布を確認できます。詳細については、[Unit分布の確認](../600.cluster-functions/1000.manage-cluster-resource/100.view-the-unit-distribution.md)を参照してください。
