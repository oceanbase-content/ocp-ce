# Clog同期チェック

このセクションでは、クラスタ内のClog同期をチェックする方法について説明します。

## 適用シナリオ

この点検項目は、OceanBaseクラスタ内にClogが同期されていないパーティションが存在するかどうかをチェックするために使用されます。

## 前提条件

OceanBaseのバージョンはV4.0未満である必要があります。

## 技術原理

OceanBase Clogの正式名称はOceanBase Commit Logであり、OceanBaseログサービスの核心です。ログサービスはOceanBaseの基盤コンポーネントであり、トランザクションの原子性、永続性、隔離性、およびデータベースの高可用性などのコア機能を支える役割を担っています。データベースのコミットプロセスでは、Paxosプロトコルにより過半数のClogがディスクに書き込まれることが保証され、少数派のClogログ内容も最終的にはハードディスクに永続化されます。OceanBaseには、ログディスクの継続的な書き込み可能性を保証するための自動ログ回収メカニズムも備えられています。OceanBase Clogは、OceanBaseにおける最も重要な基盤モジュールの一つとして、システムアーキテクチャ全体において主に以下の重要な役割を果たしています：

* トランザクションコミット時にMemStoreのコミットレコード内容およびトランザクション状態情報を永続化することで、トランザクションの原子性(Atomic)と永続性(Durability)を保証します。
* トランザクションバージョン(trans_version)を生成し、メッセージを通じてすべてのフォロワーレプリカに同期することで、トランザクションの隔離性(Isolation)を保証します。
* Paxosプロトコルを実装することで、ログを過半数のレプリカ上で同期レプリケーションし、分散データベースのデータ災害復旧および高可用性を支援し、さらに各種レプリカタイプ(読み取り専用レプリカ、ログレプリカなど)をサポートします。
* OceanBase内の各モジュールが使用する、正規のレプリカメンバーグループとリーダー情報を維持します。RootServiceのロードバランシングやローテーションマージなどの複雑な戦略に基盤メカニズムを提供します。
* 外部データサービスを提供し、DRCや増分バックアップなどの外部ツールに増分データを供給します。

OceanBaseのトランザクションコミットにおいて、パーティションのリーダーレプリカとフォロワーレプリカはPaxosグループを形成し、Clogログをリーダーレプリカからフォロワーノードへ同期します。フォロワーレプリカは定期的にチェックを行い、一定期間、確認済みの最新ログが更新されない場合、フォロワー側からClog Fetchアクションを発信し、能動的にClogをバッチ単位でフォロワーレプリカに同期します。ノードがClog同期にかなりの遅延を検出した場合、フォロワーレプリカはリーダーレプリカからベースラインデータを再構築します。これは、Clog自体が循環再利用構造であるため、Clogの遅延が大きい場合、リーダーレプリカのSSTableからデータを取得する必要があるためです。

## 手順

クラスタオブジェクトに対して基本点検を開始した後、Clogが同期されていない場合、点検レポートには対応するテナント、テーブル名、OBServerのIP、パーティションindexなどの情報が詳細に記載されます。Clogの同期不具合は、以下の原因によって引き起こされる可能性があります：

* ノード間のネットワーク遅延。`ping`コマンドでネットワークの遅延を確認できます。

* フォロワーパーティションのClogスライディングウィンドウがいっぱいになる。フォロワーパーティションは、リーダーから送信されるClogの受信を一時停止し、observer.logに`"check_can_receive_log, now can not recieve log"`メッセージを出力します。これは、Clogがウィンドウの範囲外に出るまで続きます。長時間にわたりフォロワーノードのスライディングウィンドウがいっぱいになり、自動的に解消されない場合、過半数のClogコミットに影響を与えた場合はトランザクションコミットに影響を及ぼし、少数派のClogコミットに影響を与えた場合はフォロワーノードのClogが常に遅れる原因となります。
