# アラートをWeChatワークグループに接続する

WeChatワークグループを使用してアラートメッセージを受信し、ロボットを通じてメッセージを送信することで、グループの全メンバーがアラートメッセージを確認できます。

## 適用シナリオ

OCPのアラートメッセージは、WeChatワークグループ内のロボットにプッシュされ、ロボットがそれをグループ内に送信します。WeChatロボットとの連携には、ロボットのWebhookアドレスを提供するだけで済みます。

一部の拡張機能は以下のとおりです：

* @特定のグループメンバー：@される人の携帯電話番号を設定する必要があります。
* メッセージのMarkdown形式を定義し、アラート名を太字に表示したり、アラート情報をリスト形式で表示したりできます。
* プロキシの設定：社内ネットワークとパブリックネットワークが接続されていない場合は、ネットワークプロキシを設定する必要があります。アラートメッセージはまずプロキシに送信され、プロキシからWeChatワークグループに転送されます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス**、**テナントメンテナンス**、**OBProxyメンテナンス**、**アービトレーションサービスメンテナンス**、**Binlogサービスメンテナンス**、または**ホストメンテナンス**のいずれかのリソース権限。
  * アラートセンターの**<UI-TERM key="ocp-v2.component.alarm.AlarmTargetLabel.All">すべて</UI-TERM>**メニュー権限。

* WeChatワークグループのロボットの作成と設定が完了していること。各ロボットが送信できるメッセージ数は1分あたり20件を超えてはなりません。

  WeChatロボットの接続については、[WeChatロボット公式ドキュメント](https://developer.work.weixin.qq.com/document/path/91770)を参照してください。

  1. グループ設定でグループロボットを管理します。

     WeChatワークグループで、**<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLLimit.Set">設定</UI-TERM>** > **ロボットの管理** > **ロボットの追加**を選択します。

     ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E9%85%8D%E7%BD%AE%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E5%91%8A%E8%AD%A6-1.png)

  2. 追加が成功すると、Webhookアドレスを確認できます。

     ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E9%85%8D%E7%BD%AE%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E5%91%8A%E8%AD%A6-2.png)

* WeChatロボットのWebhookを取得していること。WeChatロボットの設定後、ロボットのWebhookが提供されます。これはOCPのWeChatアラートチャネルを設定するための必須項目です。アラートメッセージのセキュリティを確保するため、このWebhookが漏洩しないようにしてください。

  WeChatロボットのWebhookを取得したら、ネットワークが正常に接続されていることを確認してください。以下のコマンドを使用してテストメッセージを送信できます：

    ```shell
    curl -XPOST 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=补充完整您的Webhook地址' \
    -H 'Content-Type:application/json; charset=utf-8' \
    --data '{"msgtype":"text","text":{"content":"WeChatアラートテストメッセージ"}}' \
    --compressed \
    --insecure
    ```

## 手順

1. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.page.Alarm.Alarm">アラートセンター</UI-TERM>** をクリックします。

2. アラートセンターページで、**<UI-TERM key="ocp-v2.page.Alarm.AlarmChannel">アラートチャネル</UI-TERM>** をクリックします。

3. アラートチャネルタブで、**<UI-TERM key="ocp-v2.Alarm.Channel.New.CreateAChannel">新規チャネル</UI-TERM>** をクリックします。

4. 企業微信アラートチャネルを設定します。

    1. 基本設定。

        ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E9%85%8D%E7%BD%AE%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E5%91%8A%E8%AD%A6-3.png)

        | 選択項目 | 必須 | 説明 |
        |-------|----------|------|
        | チャネルタイプ | はい | 企業微信からドロップダウンで選択します。 |
        | チャネル名 | はい | 後の識別を容易にするため、チャネル名をカスタマイズします。 |
        | Webhookアドレス | はい | 企業微信ボットのアクセスアドレスです。取得方法については、[企業微信ボット公式ドキュメント](https://developer.work.weixin.qq.com/document/path/91770)を参照してください。 |
        | 署名秘密鍵 | いいえ | 企業微信ボットは3種類のセキュリティ設定を提供しています。署名設定を選択すると署名秘密鍵を取得できます。 |
        | @指定ユーザー | いいえ | 入力する携帯電話番号は、ユーザーの企業微信ログイン番号である必要があります。アラート発生時にボットがそのメンバーを@します。複数のメンバー番号を入力する場合は、半角カンマで区切ります。 |

    2. メッセージ設定。

        ![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E9%85%8D%E7%BD%AE%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%E5%91%8A%E8%AD%A6-4.png)

        メッセージ構造は変更可能です。**メッセージ形式** を `markdown` に設定すると、`${}` を入力して変数を挿入できます。

       　```shell
       　### OCP アラート通知 ${alarm_name}
       　- レベル：${alarm_level}
       　- アラート対象：${alarm_target}
       　- 概要：${alarm_summary}
       　- 生成時間：${alarm_active_at}
       　- 詳細：${alarm_description}

5. その他の機能。

   アラートメッセージの集約：チャネル集約機能を有効にすると、一定期間に同一のアラートが複数回送信されるのを防ぐことができます。OCP アラートはデフォルトで3分ごと（4.1.0バージョン以降）に1回生成されます。アラートチャネルの集約を有効にすると、同一のアラートはデフォルトで600秒間に1回のみ送信されます。

## よくある質問

### メッセージのレート制限

Q：レート制限の問題をどう処理しますか？

A：WeComボットのレート制限ポリシーは「各ボットが1分間に送信できるメッセージ数は20件を超えてはならない」というものです。アラートポリシーが多数ある場合は、複数のボットを作成し、アラートポリシーを分散してバインドすることを推奨します。これにより、複数のアラートポリシーが同時にアラートをトリガーした際に、一部のアラート通知を受信できない状況を回避できます。レート制限された後は、送信失敗の原因を確認できます。レート制限後は、WeComグループ宛てのすべてのメッセージが失敗するため、一定のリスクが伴います。解決策は以下の通りです：

* アラートチャネルで集約機能を有効にします。同種のアラートや同一のアラートは、集約期間内に1回だけアラートを送信します。
* プッシュレート制限：OCPプッシュ設定ではレート制限ポリシーが提供されており、日単位・時間単位でのレート制限をサポートしています（レート制限の次元はプッシュ設定 + アラートチャネル）。
* コマンドラインで `ocp.alarm.event.resend-interval-seconds` システム設定を調整します。デフォルトでは3分ごとに1回のアラートイベントが生成されます。

上記の手順により、アラートメッセージの数を効果的に削減し、アラートがレート制限される可能性を低減できます。ただし、瞬時に大量の異なるアラートが発生した場合は、レート制限される可能性があります（1分間に20件を超えるメッセージを送信した場合）。

### ネットワークが接続できない

Q：ユーザー環境からWeCom APIに直接アクセスできない場合、どう対処しますか？

A：まず、curlを使用してテストメッセージを送信できるかテストします。ネットワークが接続できない場合は、**<UI-TERM key="ocp-v2.Alarm.Channel.NewChannel">新規チャネル作成</UI-TERM>** > **<UI-TERM key="ocp-v2.Alarm.Rule.New.BasicConfiguration">基本設定</UI-TERM>** > **<UI-TERM key="ocp-v2.Channel.FormComponent.HTTPForm.Proxy">代理人</UI-TERM>** でネットワークプロキシを設定する必要があります。

### アップグレードと移行

Q：アップグレードまたは移行後、アラートプッシュを更新するにはどうすればよいですか？

A：OCP 4.0.1以前のバージョンでは、HTTPチャネルまたはスクリプトチャネルを介してWeComアラートメッセージを送信していました。4.0.1以降のバージョンでは、組み込みのWeComチャネルの追加を推奨します。送信結果の検証に失敗する事態を避けるため、以下の説明を参照してください：

* 使用しているチャネルタイプがHTTPまたはスクリプトチャネルで、かつアラートがWeComグループ宛ての場合、組み込みのWeComチャネルの使用を推奨します。この記事の設定を参照してください。

* 顧客のアラートプラットフォーム宛てのアラートで、その後顧客のアラートプラットフォームからWeComグループに送信される場合は、組み込みのWeComチャネルに変更する必要はありません。元のアラートチャネルタイプを引き続き使用してください。

### Response検証情報失敗

Q：Response検証情報失敗を解決するにはどうすればよいですか？

A：Response検証情報失敗の設定は、スクリプトの記述が不適切でユーザーがアラートを受信できない、アラートが漏れるといった問題を防ぐために行われます。スクリプトには、有効な情報を1回だけ出力することが求められます（API応答コードまたはAPI応答ボディのいずれか）。OCPが情報が一致するかどうかを検証します。正規表現マッチングとJSONキー値ペアマッチングをサポートしており、WeComボットAPIが返すのはJSONコンテンツであるため、JSONキー値ペアマッチングを使用する必要があります。WeComグループメッセージチャネルのResponse検証情報は `{"errcode":0,"errmsg":"ok"}` に設定する必要があります。スクリプトチャネルでは、Response以外の内容を出力しないでください（例えば、curlコマンドには進捗情報の出力を防ぐために -s パラメータを追加する必要があります）。
