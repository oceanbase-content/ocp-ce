# アービトレーションサービスグループによる高可用性の実現

## 適用シナリオ

OceanBase V4.1からアービトレーションサービス機能が提供され、低コストでの2レプリカ・デュアルデータセンター構成による高可用性（2F1A）を実現できます。しかし、このデプロイメントモードでは、Aレプリカ自体の高可用性は保証されません。もしAレプリカがプロセス異常やマシンダウンにより利用不能になると、OceanBaseは高可用性の運用状態を維持できません。この問題に対処するため、OCP V4.3.5からアービトレーションサービスグループによる高可用性機能が導入されました。

**アービトレーションサービスグループとは？**

アービトレーションサービスグループには複数のアービトレーションサービスが含まれており、特定のアービトレーションサービスが利用不能になったことが検出されると、OCPは自動的に関連するクラスタをグループ内の他のアービトレーションサービスに切り替えます。

<!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01232128.png) -->

アービトレーションサービスグループは、**アービトレーションサービスリスト**と**切り替えポリシー**の2つの部分で構成されています。

* アービトレーションサービスグループ内のアービトレーションサービスには優先順位属性があり、関連するOceanBaseクラスタが切り替えポリシーをトリガーすると、優先順位の高いアービトレーションサービスに優先的に切り替えられます。第一優先順位のリソースが不足している場合は、一部のOceanBaseクラスタを次の優先順位のアービトレーションサービスに移行します。

* 切り替えポリシーは**Unit切断ポリシー**と**継続時間**の2つの部分で構成されています。

  * Unit切断ポリシーには以下の3種類が含まれます：

    1. デフォルトポリシー：OceanBaseクラスタ内のテナントの半数のレプリカがアービトレーションサービスとの接続を失った場合。
    2. Unit数：OceanBaseクラスタ内の指定された数のUnit Serverがアービトレーションサービスとの接続を失った場合。
    3. Unit割合：OceanBaseクラスタ内の指定された割合のUnit Serverがアービトレーションサービスとの接続を失った場合。

  * 継続時間：OceanBaseクラスタがUnit切断ポリシーをトリガーしてから、どのくらいの時間経過後に切り替えを実施するかを設定します。

## 前提条件

1. OCPに少なくとも1つのアービトレーションサービスが存在すること。
2. アービトレーションサービスグループを作成する際、指定されたアービトレーションサービスが**正常稼働**状態であること。
3. アービトレーションサービスグループ内のアービトレーションサービスのバージョンが一致していること。

## 技術原理

<!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1144.png) -->

**OCP Agentのレポートルール**：クラスタのRSノード上のmonagentプロセスが、クラスタとアービトレーションサービスの接続状態をMonitorDBに5秒ごとにレポートします。

**OCP Serverのチェックルール**：

   1. アービトレーションサービスグループごとにシャーディングされ、各OCP-Serverは自身のシャード内のアービトレーションサービスグループをチェックします。
   2. 10秒ごとにMonitorDBをクエリし、アービトレーションサービスとの接続を失ったすべてのServerのリストを取得します。そして、ユーザー定義の切り替えポリシーに基づいて、クラスタのUnit切断数が切り替え条件を満たしているかどうかを判断します。

## 注意事項

* クラスタが異常状態またはメンテナンス状態にある場合、OCPは自動切り替えを実行しません。

* アービトレーションサービスグループ内に、正常に稼働し、十分なリソースがあり、OceanBaseクラスタと通信できる別のアービトレーションサービスが、少なくとも1台必要です。そうでない場合、OCPは自動切り替えを実行しません。リソースが十分であるかどうかの定量的な判断基準は以下の通りです：

    1. 対象となるアービトレーションサービスマシンのメモリ使用率は90%以下である必要があります。
    2. 対象となるアービトレーションサービスマシンのディスクは2F/4F要件を満たしている必要があります：2Fテナントが12 MiB、4Fテナントが24 MiBを占有します。このアービトレーションマシンへ移行した場合にリソースが十分であるかどうかを確認します。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.component.ParameterTemplate.DetailDrawer.Cluster">クラスタ</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.Auth.Org.SharedResourceDrawer.ArbitrationService">アービトレーションサービス</UI-TERM>** ページに移動します。

3. **<UI-TERM key="ocp-v2.Component.ArbitrationServerList.ServiceGroup">サービスグループ</UI-TERM>** タブをクリックし、**<UI-TERM key="ocp-v2.Detail.Component.ReplaceArbitrationServerDrawer.ServiceGroup">サービスグループ</UI-TERM>** リストページに移動します。

4. 右上の **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.CreateArbitrationGroup.CreateAServiceGroup">サービスグループを新規作成</UI-TERM>** をクリックします。

5. **<UI-TERM key="ocp-v2.Cluster.Arbitration.CreateAServiceGroup">サービスグループを新規作成</UI-TERM>** パネルで、アービトレーションサービスグループの基本情報を設定します。
