# OCPの監視をPrometheusに統合する

このセクションでは、Prometheusを使用してOceanBaseの業務監視を統合する方法について説明します。

## 適用シナリオ

ユーザーは独自のPrometheusシステムを使用してビジネス監視を統合する必要があります。

## 前提条件

* 現在OCPにログインしているユーザーが **ADMIN** ロールを持つことを確認してください。
* V2.28以降のPrometheusサービスがデプロイ済みであること。
* V4.4.2以降のOCPバージョンがデプロイ済みであること。

## 手順

### ステップ１：Prometheusデータソースを新規作成

1. OCPプラットフォームにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">システム管理</UI-TERM>** > **<UI-TERM key="ocp-v2.page.External.ExternalIntegration">外部統合</UI-TERM>** をクリックします。

3. **Prometheus** タブをクリックします。

4. **Prometheusデータソース** ページで、**Prometheusデータソースの新規作成** をクリックします。

5. ポップアップダイアログで、**Prometheusデータソース** の関連情報を入力します。

   | 構成パラメータ | 説明 |
   | ---------- | ------------- |
   | データソース名 | Prometheusデータソースの名前。2～32文字で、英字、数字、アンダースコア（_）を含むことができ、一意である必要があります。 |
   | アクセスアドレス | PrometheusサービスのアクセスIPアドレス。`http/https` で始まり、1つのIPアドレスのみを入力できます。 |
   | ポート | Prometheusサービスのアクセスポート。デフォルトは9090で、カスタマイズ可能です。 |
   | ユーザー名 | Prometheusサービスの認証アカウントのユーザー名。なければ入力不要です。 |
   | パスワード | Prometheusサービスの認証アカウントのパスワード。なければ入力不要です。 |
   | 備考 | Prometheusデータソースに関する特別な説明を追加します。 |

6. **<UI-TERM key="ocp-v2.page.Credential.OBProxy.Verification">検証</UI-TERM>** をクリックし、データソースの接続性を検証します。

7. 検証に成功したら、**<UI-TERM key="ocp-v2.External.Component.CreateSlsDataSource.New">新規作成</UI-TERM>** をクリックします。

8. ポップアップに表示されたPrometheusの設定情報をコピーします。

### ステップ2：`prometheus.yaml` 設定ファイルを修正する

Prometheusの設定ファイル `prometheus.yaml` に、前のステップでコピーした設定情報を追加します：

```yaml
scrape_configs:
  - job_name: 'ocp_sd'
    scheme: 'http'
    fallback_scrape_protocol: "PrometheusText1.0.0"  # このパラメータはPrometheus 3.x系でのみ設定が必要です。2.x系では不要です
    http_sd_configs:
      - url: 'http://xx.xx.xx.xx:8080/api/v2/monitor/prometheus_sd'
        basic_auth:   # OCPにアクセスしてprometheus_sd内のすべてのTargetを取得する
            username: "******"
            password: "******"
    basic_auth:   # すべてのTargetへのアクセスを制御する
        username: "******"
        password: "******"
```

### ステップ3：Prometheusサービスを再起動する

1. Prometheusサービスを再起動し、設定を有効にします。

2. Prometheusサービスのコンソールにログインします。

3. **Status** > **Target health** を選択し、接続されたジョブが正常に動作しているか確認します。すべてのTargetの状態が **UP** であることを確認する必要があります。

4. **Query** に `executor_active_threads`、`ob_sysstat` を入力し、OCPとAgentの監視データが正常に取得されているか確認します。

### ステップ4：Prometheusデータソースを有効にする

1. OCPプラットフォームにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">システム管理</UI-TERM>** > **<UI-TERM key="ocp-v2.page.External.ExternalIntegration">外部統合</UI-TERM>** をクリックします。

3. **Prometheus** タブをクリックします。

4. **Prometheusデータソース** ページで、操作列の **<UI-TERM key="ocp-v2.Backup.Component.RestoreTenantCard.Enable">有効にする</UI-TERM>** をクリックします。

   Prometheusデータソースを有効にすると、OCPとPrometheusは双方向で監視データを同期できるようになります。つまり、PrometheusがOCPのデータを収集することも、OCPがPrometheusから監視データを読み取ることもサポートされます。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>PrometheusがOCPのデータを収集するだけで、OCPの監視機能からPrometheusデータソースにクエリする必要がない場合は、OCPプラットフォームでPrometheusデータソースを有効にする必要はありません。</p>
</main>

## 補足説明

### Prometheusの基本認証について

具体的な認証方法については、Prometheus公式サイトを参照してください：[Basic Authentication](https://prometheus.ac.cn/docs/guides/basic-auth/)。

ここで、作成した`web.yml`ファイルは`prometheus.yaml`ファイルと同じディレクトリに配置することができます。これにより、Dockerまたはコンテナを起動する際に`--web.config.file=/etc/prometheus/web.yml`フィールドを追加できます。

以下の例では、`/home/admin`はコンテナ外のディレクトリであり、`prometheus.yaml`と`web.yml`ファイルを一元的に格納します。

```yaml
docker run  -d --name prometheus -p 9090:9090 -v /home/admin/docker/prometheus/prometheus.yml:/etc/prometheus/prometheus.yml -v /home/admin/docker/prometheus/web.yml:/etc/prometheus/web.yml prom/prometheus:v3.3.0    --config.file=/etc/prometheus/prometheus.yml --storage.tsdb.path=/prometheus --web.config.file=/etc/prometheus/web.yml
```

### OCPがPrometheusへの接続を検証する仕組み

OCPは、Prometheusの`/api/v1/status/buildinfo`インターフェースにアクセスするためのHTTPリクエストを送信します。

**リクエスト例**：

```yml
# アカウントとパスワード方式：
curl -H "Authorization: Basic $(echo -n 'Prometheus アカウント:Prometheus パスワード' | base64)" \
http://{PrometheusIP}:{Port}/api/v1/status/buildinfo

# アカウントとパスワードなし方式：
curl -L http://{PrometheusIP}:{Port}/api/v1/status/buildinfo
```

**応答例**：

```json
{
  "status": "success",  // リクエストが成功したかどうか
  "data": {
    "version": "3.3.0",  // Prometheusのバージョン番号
    "revision": "3c49e69330ceee9c587a1d994c78535695edff16",
    "branch": "HEAD",
    "buildUser": "root@b362765c931d",
    "buildDate": "20250415-13:32:00",
    "goVersion": "go1.24.1"
  }
}
```

### OCPバージョンのアップグレードについて

デフォルトでは、OCP V4.4.2は過去のバージョンのPrometheus設定と互換性があります。ただし、今後のメンテナンスを容易にするため、本記事の内容を参考にPrometheusデータソースを再作成し、設定し直すことを強く推奨します。

### Prometheusの設定ファイルについて

`http_sd_configs`には2つの`basic_auth`フィールドが存在します。その役割は、OCPがPrometheus用のアクセスキーの生成を支援し、Prometheusが限られた権限でOCPおよびAgent関連のExporterにアクセスできるようにすることです。

**注意**：この設定情報は自ら変更しないでください。変更が必要な場合は、**Agent認証キーの変更について**を参照し、OCP上で変更してください。

```yaml
global:
  scrape_interval:  10s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'ocp_sd'
    scheme: 'http'
    fallback_scrape_protocol: "PrometheusText1.0.0"  # このパラメータはPrometheus 3.x系でのみ設定が必要です。2.x系では不要です。
    http_sd_configs:
      - url: 'http://xx.xx.xx.xx:8080/api/v2/monitor/prometheus_sd'
        basic_auth:   # OCPにアクセスし、prometheus_sd内のすべてのTargetを取得するための認証情報
            username: "******"
            password: "******"
    basic_auth:   # すべてのTargetへのアクセスを制御するための認証情報
        username: "******"
        password: "******"
```

### Agent認証キーの変更について

OCPはAgent認証キーを変更するためのインターフェースを提供しています。以下の手順を参考に操作してください：

1. metaDBに接続し、以下のSQLステートメントを実行してキーIDを照会します：

   ```sql
   select id from profile_credential where access_target = 'PROMETHEUS'
   ```

2. OCPコンテナ上で以下のコマンドを実行してキーを変更します：

   ```bash
   curl --location --request PUT 'http://OCP-IP:OCP-port/api/v2/integration/prometheus/changeAuthPd/{id}?id={id}' \
   --header 'Content-Type: application/json' \
   -u 'admin:OCP パスワード'  \
   --data '{
       "newAuthPd": "******"
   }'
   ```

   ここで、`{id}` は前のステップで照会したID、`{OCP-IP}` はOCPのIPアドレス、`{OCP-port}` はOCPのポート、`{admin:OCP パスワード}` はOCPのアカウントとパスワード、`{******}` は変更後の新しいパスワードです（OCPのパスワード形式に可能な限り合わせることを推奨します）。

3. 実行結果が成功であるか確認します。

4. `prometheus.yaml` ファイルを修正し、`basic_auth` 内の2つの `password` を手順2で変更した新しいパスワードに更新します。

5. Prometheusコンテナを再起動し、Prometheusコンソールにアクセスして、**Status** > **Target health** を選択し、接続されたjobが正常に動作しているか確認します。すべてのTargetの状態が **UP** であれば、変更は成功です。

### HTTPS認証に関する説明

HTTPSを使用してOCPとPrometheusにアクセスする場合は、[HTTPS認証の説明](../2100.appendix/1300.https-authentication-instructions.md)を参照し、OCPとPrometheusにTLSおよび関連する証明書を追加してください。
