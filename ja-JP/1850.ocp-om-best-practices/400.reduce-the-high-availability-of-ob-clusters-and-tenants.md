# OceanBaseクラスタおよびテナントの高可用性の削減

このセクションでは、OCPを使用してOceanBaseクラスタおよびテナントの高可用性機能を削減する方法について説明します。

## 適用シナリオ

* テナントのレプリカを削減し、クラスタの規模を縮小する場合。例えば、**3リージョン5データセンター** のデプロイメントモードから **2リージョン3データセンター** のデプロイメントモードへのスケールインです。

* ビジネスのためデータセンターを移転する際に、まず新しいZoneを追加し、その後古いZoneを削除する必要がある場合。

## 前提条件

* Zoneを削除する際は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** メニュー権限。

* Zone内のテナントレプリカを削除する際は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** リソース権限。
  * テナント **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** メニュー権限。

* テナントレプリカを削除する前に、OceanBaseクラスタおよびテナントは **<UI-TERM key="ocp-v2.Detail.Statistics.utils.Running">実行中</UI-TERM>** 状態でなければなりません。
* テナントレプリカを削除する前に、テナントの残りレプリカが過半数を維持していることを保証する必要があります。つまり、F/Lレプリカの数が削除前のF/Lレプリカ総数の半分を超えている必要があります。
* OceanBaseクラスタのZoneを削除する前に、クラスタは **<UI-TERM key="ocp-v2.src.constant.tenant.Running">実行中</UI-TERM>** 状態でなければなりません。
* Zoneを削除する前に、そのZone上にテナントレプリカが存在しないことを確認する必要があります。

## 注意事項

* アービトレーションサービスを有効にするには、テナントが2F/4Fモードである必要があります。テナントでアービトレーションサービスが有効になっている場合、レプリカ数は4Fから2Fへのみ削減できます。
* レプリカを削除する前に、プライマリレプリカを事前に切り替えることを推奨します（つまり、テナントのプライマリZoneを変更する）。これにより、レプリカ削除時にビジネスに影響が出ないようにします。

## 手順

操作の詳細については、[Zoneの削除](../600.cluster-functions/500.manage-a-zone/400.delete-a-zone.md)および[Zone内のテナントレプリカの削除](../700.tenant-functions/1000.manage-tenant-replica/400.delete-a-replica-of-a-tenant-in-a-private-zone.md)を参照してください。

テナントレプリカの削除は非同期タスクであり、タスクがトリガーされるとRSバックグラウンドがスケジューリングして段階的に完了します。データ量が多い場合、データ削除には時間がかかる可能性があります。以下のコマンドを参考に定期的にデータ削除状況を確認することを推奨します：

```SQL
# RSの履歴タスクレコードを確認し、tenant_balance_finishedが表示されればデータ削除が完了したことを示します
# OceanBase V3.x系
select * from __all_rootservice_event_history order by gmt_create desc limit 10;
# OceanBase V4.x系
select * from DBA_OB_ROOTSERVICE_EVENT_HISTORY order by timestamp desc limit 10;

# サーバーの状態を確認します。startはoffline時間より遅く、状態はactiveである必要があります。
# OceanBase V3.x系
select svr_ip, gmt_modified, zone, usec_to_time(start_service_time), usec_to_time(last_offline_time), status from __all_server;
# OceanBase V4.x系
SELECT svr_ip, zone, UNIX_TIMESTAMP(NVL(`start_service_time`, 0))*1000000 as start_service_time, status from DBA_OB_SERVERS;

# データレプリカが補完されているかどうかを確認します。<レプリカ数>は期待されるレプリカ数に置き換えてください。空を返す場合は補完済みを意味します。
# OceanBase V3.x系
select /*+read_consistency(weak)*/ count(*)c from gv$partition group by table_id, partition_id having c != <レプリカ数>;
# OceanBase V4.x系ではパーティションレプリカの概念がないため、以下のSQLはログストリームにプライマリが存在するかどうかをチェックします。すべてにプライマリが存在する場合は0を返し、正常を示します。
SELECT COUNT(1) FROM CDB_OB_LS A LEFT JOIN GV$OB_LOG_STAT B ON A.LS_ID = B.LS_ID AND A.TENANT_ID = B.TENANT_ID AND B.ROLE='LEADER' WHERE B.LS_ID IS NULL AND A.STATUS NOT IN ('CREATING', 'CREATED', 'TENANT_DROPPING', 'CREATE_ABORT', 'PRE_TENANT_DROPPING');

# ログが同期されているかどうかを確認します。空を返す場合は同期済みを意味します。
# OceanBase V3.x系
select svr_ip, svr_port, table_id, partition_idx from __all_virtual_clog_stat where is_in_sync= 0 and is_offline = 0 and replica_type != 16;
# OceanBase V4.x系ではログが同期されているかどうかを確認します。空を返す場合は同期済みを意味します。
select count(1) as unsync_cnt from GV$OB_LOG_STAT where in_sync = 'NO';
```

OCPのリソース管理画面でテナントのレプリカ分布を確認できます。詳細については、[Unit分布の確認](../600.cluster-functions/1000.manage-cluster-resource/100.view-the-unit-distribution.md)を参照してください。

## よくある質問

**Q1: Zoneを削除する際に「指定されたZone=xにUnitが存在し、削除できません」というエラーが発生しました。**

A: OCPでは、Zoneを削除する前に、そのZone上のすべてのテナントレプリカを削除する必要があります。リソース管理画面でZone上のレプリカ分布を確認し、すべてのレプリカを削除してからZoneを削除してください。

**Q2: テナントレプリカを削除する際に「violate locality principal not allowed」というエラーが発生しました。**

A: このエラーは、レプリカを削除した後、テナントの(F/L)レプリカ数が過半数を満たさないため、削除を禁止するものです。リソース管理画面でテナントのレプリカ分布を確認し、テナントのレプリカが過半数を満たすようにしてください。
