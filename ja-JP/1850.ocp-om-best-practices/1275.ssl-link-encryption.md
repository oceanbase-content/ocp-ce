# SSLリンク層暗号化

## 適用シナリオ

1. **エンドツーエンドSSL認証**：業務アプリケーション > OBProxy > OceanBase の全リンクでSSL認証方式を使用し、接続およびデータの暗号化伝送を確立します。
2. **OBProxy SSL認証**：OBProxyクラスタにSSL認証を個別に有効にし、業務アプリケーション => OBProxy間でSSL認証方式を使用して接続およびデータの暗号化伝送を確立します。
3. **OceanBase SSL認証**：OceanBaseクラスタにSSL認証を個別に有効にし、OBProxyが存在しないシナリオにおいて、業務アプリケーション > OceanBaseクラスタ間でSSL認証方式を使用して接続およびデータの暗号化伝送を確立します。

OceanBase/OBProxy エンドツーエンド SSL認証の概要図は以下のとおりです：

## 前提条件

**証書の申請と発行**

1. 事前に権威あるCA証書機関にCAルート証書を申請し、CAルート証書が期限切れでないことを確認してください。
2. 事前にCAルート証書を使用してサーバー証書を発行し、サーバー証書が期限切れでないことを確認し、証書と秘密鍵を保管してください。
3. 上記の操作後、3つのpem形式ファイルが生成されます（ファイルタイプは必ずPEM、ファイル名は自由）。CAルート証書（ca.pem）、サーバー証書（server.pem）、サーバー秘密鍵（server-key.pem）です。

CAルート証書を使用してサーバー証書を発行する際は、関連する**注意事項**を必ずご確認ください。

**SSLリンク層暗号化の有効化**

1. OceanBaseおよびOBProxyクラスタは**正常稼働**状態でなければなりません。
2. OceanBaseクラスタはV4.0.0.0以降のバージョンである必要があります。

## 技術原理

### OceanBase SSL認証の有効化

**ステップ1：証書ファイルのアップロード**

OceanBase SSL認証を有効にする前に、CAルート証書、サーバー証書、サーバー秘密鍵を各OBServerの`${run_path}/wallet`ディレクトリに配置する必要があります。OceanBaseでSSL認証が有効になると、OBServerの追加、再インストール、置き換え、ゾーンの追加などのシナリオで、OCPは新しいOBServerに証書ファイルを自動的に配置します。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>OCPがSSL認証を有効にしたクラスタを引き継いだ後、新しいOCP内にそのクラスタの証書ファイルがない場合、上記のシナリオでOCPは新しいOBServerに証書ファイルをアップロードできません。この問題は、OCPに証書ファイルを再アップロードし、SSL証書を更新することで解決できます。</p>
</main>

**ステップ2：SSLスイッチの有効化**

OceanBaseのSSL認証は、RPC SSL認証とSQL SSL認証に分かれており、それぞれOceanBaseとOBServerがRPC接続やSQL接続を確立する際にSSL認証を通過するかどうかを制限します。両プロトコルは同じ証書セットを共有します。

RPC SSL認証を有効にするSQLは以下のとおりです:

```sql
# SSL証書の取得方法を指定します。fileのみサポートしており、ローカルファイルから取得します。無効な場合は空文字列です。
ALTER SYSTEM SET ssl_external_kms_info = '{"ssl_mode":"file"}';

# OceanBaseがサーバー側およびクライアント側のRPC認証方式を設定します：
# RPCサーバー側としてSSL接続と非SSL接続の両方を確立できます。無効な場合はALLを取得します。
ALTER SYSTEM SET rpc_server_authentication_method = 'ALL';

# RPCクライアント側としてSSL接続のみを確立します。無効な場合はNONEを取得します。
ALTER SYSTEM SET rpc_client_authentication_method = 'SSL_NO_ENCRYPT';

# SQL RPC認証スイッチを有効にします。
ALTER SYSTEM SET ssl_client_authentication = True;

# TLSプロトコルバージョンを設定します。
ALTER SYSTEM SET sql_protocol_min_tls_version = "TLSv1.1";
```

### OBProxyでSSL認証を有効にする

**ステップ1：証書ファイルをアップロードする**

OceanBaseと同様に、3つのファイルをすべてのOBProxy Serverの`${run_path}/wallet`ディレクトリにアップロードする必要があります。OBProxy Serverを追加するシナリオでは、OCPも新しいOBProxy Server上に証書ファイルを配置します。

**ステップ2：SSL認証を有効にする**

1. OBProxy管理者ユーザーroot@proxysysを使用してOBProxyに接続し、以下のSQLを実行して証書の絶対パスを設定します。

    ```sql
    update proxyconfig.security_config set CONFIG_VAL= '{"sourceType" : "FILE", "CA" : "/xxx/wallet/ca.pem", "publicKey": "/xxx/wallet/proxy-cert.pem", "privateKey" : "/xxx/wallet/proxy-key.pem"}' where APP_NAME = 'obprox
    ' and VERSION = '1';
    ```

2. SSL認証スイッチを有効にします。

    ```sql
    # クライアント側のSSL認証を有効にします。有効にすると、業務アプリケーションはSSL認証を通じてOBProxyに接続できます。
    alter proxyconfig set enable_client_ssl=true;

    # サーバー側のSSL認証を有効にします。有効にすると、OBProxyはSSL認証を通じてOceanBaseに接続できます。
    alter proxyconfig set enable_server_ssl=true;
    ```

クライアントとOBProxy間のSSL認証は必須ではなく、SSLおよび非SSL認証方式の両方をサポートして接続を確立できます。OBProxyでSSL認証が有効になっている場合、SSL認証を有効にしたOceanBaseクラスタと無効にしたOceanBaseクラスタの両方をサポートします。OBProxyが接続を確立する際、まずOceanBaseと協議してどちらの方式で接続を確立するかを決定します。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>通常、OBProxyと関連付けられたすべてのOceanBaseクラスタは、同一の証書セットを使用する必要があります。企業のCA証書は一般的に1つしかないことを考慮し、OBProxyとOceanBaseクラスタを関連付ける際、OCPは追加の検証を行いません。このシナリオはユーザーが自ら保証するものとします。</p>
</main>

## 注意事項

### サーバー証書の発行

CAルート証書を使用してサーバー証書を発行する場合、OceanBaseとOBProxyはサーバー証書の発行方法について以下の特別な要件を持っています。

1. サーバー証書を発行して秘密鍵を生成する際、鍵長を2048に指定する必要があります。例：

    ```shell
    openssl genkey -algorithm RSA -out server-key.pem -pkeyopt rsa_keygen_bits:2048
    ```

2. OBProxyとOceanBaseの両方でSSL認証を有効にした場合、OceanBaseとOBProxyが同じサーバー証書セットを使用すると、その証書はクライアント証書とサーバー証書の両方として機能します。証書の**Extended Key Usage**には`Client Authentication`と`Server Authentication`の両方を含める必要があります。以下のコマンドで正しく設定されているか確認できます。

    ```sql
    openssl x509 -in サーバー証書ファイルパス -text -noout
    ```

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1617.png)

3. セカンダリ証書が必要な場合、CAルート証書を使用してセカンダリ証書を発行する際、その証書がCA証書であることを指定する必要があります。発行済みのセカンダリ証書に対して以下のコマンドを実行して確認できます。

    ```shell
    openssl x509 -in セカンダリ証書ファイルパス -text -noout
    ```

    `CA:TRUE`はセカンダリ証書がCA証書であり、他の証書を発行するために使用できることを示します。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1618.png)

### フルリンクSSL認証

OceanBaseとOBProxyの両方でSSL認証を有効にした場合、OBProxyとOceanBaseは双方向SSL認証を使用します。OceanBase側では、ユーザーがテナントパラメータ`ob_ssl_invited_common_names`を手動で設定し、OBProxy証書のsubject内の`cn`フィールドをこのパラメータに追加する必要があります。そうでない場合、OBProxyはテナントにアクセスできません。

詳細については、[ob_ssl_invited_common_names](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015566)を参照してください。
