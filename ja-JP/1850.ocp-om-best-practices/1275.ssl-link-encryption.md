# SSL暗号化

## 適用シナリオ

1. **エンドツーエンドSSL認証**：業務アプリケーション > OBProxy > OceanBase の全経路でSSL認証方式を使用し、接続を確立し、データを暗号化して転送します。
2. **OBProxy SSL認証**：OBProxyクラスタにSSL認証を個別に有効にし、業務アプリケーション => OBProxy間でSSL認証方式を使用して接続を確立し、データを暗号化して転送します。
3. **OceanBase SSL認証**：OceanBaseクラスタにSSL認証を個別に有効にし、OBProxyが存在しないシナリオにおいて、業務アプリケーション > OceanBaseクラスタ間でSSL認証方式を使用して接続を確立し、データを暗号化して転送します。

## 前提条件

**証明書の申請と発行**

1. 事前に信頼できる認証局（CA）にCAルート証明書を申請し、CAルート証明書が期限切れでないことを確認してください。
2. 事前にCAルート証明書を使用してサーバー証明書を発行し、サーバー証明書が期限切れでないことを確認し、証明書と秘密鍵を保管してください。
3. 上記の操作後、3つのpem形式ファイルが生成されます（ファイルタイプは必ずPEM、ファイル名は自由）。CAルート証明書（ca.pem）、サーバー証明書（server.pem）、サーバー秘密鍵（server-key.pem）です。

CAルート証明書を使用してサーバー証明書を発行する際は、関連する**注意事項**を必ずご確認ください。

**SSL暗号化の有効化**

1. OceanBaseおよびOBProxyクラスタは**正常稼働**状態でなければなりません。
2. OceanBaseクラスタはV4.0.0.0以降のバージョンである必要があります。

## 技術原理

### OceanBase SSL認証の有効化

**ステップ1：証明書ファイルのアップロード**

OceanBase SSL認証を有効にする前に、CAルート証明書、サーバー証明書、サーバー秘密鍵を各OBServerの`${run_path}/wallet`ディレクトリに配置する必要があります。OceanBaseでSSL認証が有効になると、OBServerの追加、再インストール、置き換え、ゾーンの追加などのシナリオで、OCPは新しいOBServerに証明書ファイルを自動的に配置します。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>OCPがSSL認証を有効にしたクラスタを引き継いだ後、新しいOCP内にそのクラスタの証明書ファイルがない場合、上記のシナリオでOCPは新しいOBServerに証明書ファイルをアップロードできません。この問題は、OCPに証明書ファイルを再アップロードし、SSL証明書を更新することで解決できます。</p>
</main>

**ステップ2：SSLスイッチの有効化**

OceanBaseのSSL認証は、RPC SSL認証とSQL SSL認証に分かれており、それぞれOceanBaseとOBServerがRPC接続やSQL接続を確立する際にSSL認証を通過するかどうかを制限します。両プロトコルは同じ証明書セットを共有します。

RPC SSL認証を有効にするSQLは以下のとおりです:

```sql
# SSL証明書の取得方法を指定します。fileのみサポートしており、ローカルファイルから取得します。無効にする場合は空文字列を指定します。
ALTER SYSTEM SET ssl_external_kms_info = '{"ssl_mode":"file"}';

# OceanBaseがサーバーおよびクライアントとして使用するRPC認証方式を設定します：
# RPCサーバー側としてSSL接続と非SSL接続の両方を確立できます。無効にする場合はALLを指定します。
ALTER SYSTEM SET rpc_server_authentication_method = 'ALL';

# RPCクライアント側としてSSL接続のみを確立します。無効にする場合はNONEを指定します。
ALTER SYSTEM SET rpc_client_authentication_method = 'SSL_NO_ENCRYPT';

# SQL RPC認証スイッチを有効にします。
ALTER SYSTEM SET ssl_client_authentication = True;

# TLSプロトコルバージョンを設定します。
ALTER SYSTEM SET sql_protocol_min_tls_version = "TLSv1.1";
```

### OBProxyでSSL認証を有効にする

**ステップ1：証明書ファイルをアップロードする**

OceanBaseと同様に、3つのファイルをすべてのOBProxy Serverの`${run_path}/wallet`ディレクトリにアップロードする必要があります。OBProxy Serverを追加するシナリオでは、OCPも新しいOBProxy Server上に証明書ファイルを配置します。

**ステップ2：SSL認証を有効にする**

1. OBProxy管理者ユーザーroot@proxysysを使用してOBProxyに接続し、以下のSQLを実行して証明書の絶対パスを設定します。

    ```sql
    update proxyconfig.security_config set CONFIG_VAL= '{"sourceType" : "FILE", "CA" : "/xxx/wallet/ca.pem", "publicKey": "/xxx/wallet/proxy-cert.pem", "privateKey" : "/xxx/wallet/proxy-key.pem"}' where APP_NAME = 'obprox
    ' and VERSION = '1';
    ```

2. SSL認証スイッチを有効にします。

    ```sql
    # クライアント側のSSL認証を有効にします。有効にすると、業務アプリケーションはSSL認証を通じてOBProxyに接続できます。
    alter proxyconfig set enable_client_ssl=true;

    # サーバー側のSSL認証を有効にします。有効にすると、OBProxyはSSL認証を通じてOceanBaseに接続できます。
    alter proxyconfig set enable_server_ssl=true;
    ```

クライアントとOBProxy間のSSL認証は必須ではなく、SSLおよび非SSL認証方式の両方をサポートして接続を確立できます。OBProxyでSSL認証が有効になっている場合、SSL認証を有効にしたOceanBaseクラスタと無効にしたOceanBaseクラスタの両方をサポートします。OBProxyが接続を確立する際、まずOceanBaseと協議してどちらの方式で接続を確立するかを決定します。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>通常、OBProxyと関連付けられたすべてのOceanBaseクラスタは、同一の証明書セットを使用する必要があります。企業のCA証明書は一般的に1つしかないことを考慮し、OBProxyとOceanBaseクラスタを関連付ける際、OCPは追加の検証を行いません。このシナリオはユーザーが自ら保証するものとします。</p>
</main>

## 注意事項

### サーバー証明書の発行

CAルート証明書を使用してサーバー証明書を発行する場合、OceanBaseとOBProxyはサーバー証明書の発行方法について以下の特別な要件を持っています。

1. サーバー証明書を発行して秘密鍵を生成する際、鍵長を2048に指定する必要があります。例：

    ```shell
    openssl genkey -algorithm RSA -out server-key.pem -pkeyopt rsa_keygen_bits:2048
    ```

2. OBProxyとOceanBaseの両方でSSL認証を有効にした場合、OceanBaseとOBProxyが同じサーバー証明書セットを使用すると、その証明書はクライアント証明書とサーバー証明書の両方として機能します。証明書の**Extended Key Usage**には`Client Authentication`と`Server Authentication`の両方を含める必要があります。以下のコマンドで正しく設定されているか確認できます。

    ```sql
    openssl x509 -in サーバー証明書ファイルパス -text -noout
    ```

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1617.png)

3. 中間証明書が必要な場合、CAルート証明書を使用して中間証明書を発行する際、その証明書がCA証明書であることを指定する必要があります。発行済みの中間証明書に対して以下のコマンドを実行して確認できます。

    ```shell
    openssl x509 -in 中間証明書ファイルパス -text -noout
    ```

    `CA:TRUE`は中間証明書がCA証明書であり、他の証明書を発行するために使用できることを示します。

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1618.png)

### エンドツーエンドSSL認証

OceanBaseとOBProxyの両方でSSL認証を有効にした場合、OBProxyとOceanBaseは双方向SSL認証を使用します。OceanBase側では、ユーザーがテナントパラメータ`ob_ssl_invited_common_names`を手動で設定し、OBProxy証明書のsubject内の`cn`フィールドをこのパラメータに追加する必要があります。そうでない場合、OBProxyはテナントにアクセスできません。

詳細については、[ob_ssl_invited_common_names](https://docs.oceanbase.com/oceanbase-database/V4.3.5-ob_ssl_invited_common_names)を参照してください。
