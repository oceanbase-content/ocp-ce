# アラートをSlackグループチャットに連携する

Slackグループチャットを使用してアラートメッセージを受信できます。ボットがSlackグループにメッセージを送信し、グループの全メンバーがアラートメッセージを確認できます。

## 適用シナリオ

OCPのアラートメッセージはSlackグループ内のボットにプッシュされ、ボットがそのメッセージをグループに送信します。Slackボットと連携するには、SlackボットのWebhook URLを提供するだけで済みます。また、メッセージのMarkdown形式の定義や、アラート名の太字表示、アラート情報のリスト表示など、一部の拡張機能も利用できます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ管理**、**テナント管理**、**OBProxy管理**、**アービトレーションサービス管理**、**Binlogサービス管理**、または**ホスト管理**のいずれかのリソース権限。
  * アラートセンターの**すべて**メニュー権限。

* Slackグループチャットを作成し、Webhookを追加して、対応するSlackグループに追加していること。

* Webhookを取得した後は、ネットワークが正常に接続されていることを確認してください。以下のコマンドを参考に、テストメッセージを送信してみてください：

  ```bash
  # YOU_WEBHOOK_URL_HERE：Webhookが生成したURLです。例：https://hooks.slack.com/services/XXX/XXX/XXX
  curl -X POST -H 'Content-type: application/json' --data '{"text":"Hello, World!"}' YOU_WEBHOOK_URL_HERE
  ```

  受信したメッセージの結果は次のとおりです：

  ![テストメッセージの効果](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/01261415.png)

## 注意事項

Slackメッセージの長さ制限は通常約3000文字です。公式の頻度制限は明確ではありませんが、プラットフォームレベルでのレート制限が存在します。OCPのアラートチャネルで集約設定を有効にし、複数のメッセージを1つのメッセージに集約して送信することを推奨します。

## 手順

1. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.page.Alarm.Alarm">アラートセンター</UI-TERM>**をクリックします。

2. アラートセンターページで、**<UI-TERM key="ocp-v2.Alarm.Channel.Detail.AlarmChannel">アラートチャネル</UI-TERM>**をクリックします。

3. アラートチャネルタブで、**<UI-TERM key="ocp-v2.Alarm.Channel.NewChannel">新規チャネル作成</UI-TERM>**をクリックします。

4. Slackアラートチャネルを設定します。

   1. 基本設定。

      | 選択肢 | 必須 | 説明 |
      |--------|----------|------|
      | チャネルタイプ     | はい | ドロップダウンで**Slack**を選択します。 |
      | チャネル名       | はい | 後の識別を容易にするためのカスタムチャネル名。 |
      | Webhookアドレス | はい | Slackボットへのアクセスアドレスです。取得方法については、[Slackグループチャットの作成とWebhookアドレスの取得](../2100.appendix/1100.create-a-slack-group-chat.md)を参照してください。 |

   2. メッセージ設定。

      1. アラートメッセージ形式を選択します。**<UI-TERM key="ocp-v2.Alarm.Channel.New.AlertMessageText">テキスト</UI-TERM>** と **Json** の2種類の形式がサポートされています。

      2. 実際のニーズに応じて、アラートメッセージをカスタマイズ設定します。

         1. アラートの **<UI-TERM key="ocp-v2.Alarm.Channel.New.MessageTemplates">メッセージテンプレート</UI-TERM>** を設定します。システムからプッシュされるメッセージは、設定したテンプレートのスタイルで表示されます。
         2. **<UI-TERM key="ocp-v2.Alarm.Channel.Detail.RepeatAlarmConfiguration">重複アラート設定</UI-TERM>** では、同じアラートに対して送信回数と時間間隔を設定し、同一アラートのメッセージが繰り返し送信されるかどうかおよび送信頻度を制御します。アラートの時間間隔はデフォルトで600秒、最小値は300秒で、設定値はアラートルールの検出周期以上である必要があります。
         3. **<UI-TERM key="ocp-v2.Alarm.Channel.New.AlertMessageAggregation">アラートメッセージの集約</UI-TERM>** 機能を有効にするかどうかを選択します。メッセージ集約を有効にすると、一定期間にアラートが過剰に送信されることを防ぎ、重要なメッセージが埋もれるのを防ぐことができます。アラートメッセージ集約を有効にした後、システムは設定したテンプレートのスタイルと間隔でアラートメッセージを送信します。

      3. 実際のニーズに応じて、復旧メッセージをカスタマイズ設定します。
         1. アラートの **<UI-TERM key="ocp-v2.Alarm.Channel.New.MessageTemplates">メッセージテンプレート</UI-TERM>** を設定します。システムからプッシュされるメッセージは、設定したテンプレートのスタイルで表示されます。
         2. **<UI-TERM key="ocp-v2.Alarm.Channel.Detail.RecoveryMessageAggregation">メッセージ集約の復元</UI-TERM>** 機能を有効にするかどうかを選択します。メッセージ集約を有効にすると、一定期間に復旧メッセージが過剰に送信されることを防ぎ、重要なメッセージが埋もれるのを防ぐことができます。復旧メッセージ集約を有効にした後、システムは設定したテンプレートのスタイルと間隔で復旧メッセージを送信します。

5. **<UI-TERM key="ocp-v2.Alarm.Channel.New.SendTestMessages">テストメッセージを送信</UI-TERM>** をクリックし、現在設定されているアラートチャネルがアラートメッセージを正常に送信できるかどうかをテストします。
6. テストメッセージの送信に成功した場合、**<UI-TERM key="ocp-v2.component.OperationConfig.ModifyParameterDrawer.Submit">送信</UI-TERM>** をクリックして設定を完了します。

## よくある質問

### メッセージのレート制限

**レート制限によりメッセージの送信が失敗した場合、どう対処しますか？**（例：「アクティビティ数が多すぎるため、このインバウンドWebhook統合からの一部のメッセージは表示されません。」）

Slackのメッセージ長は通常約3000文字で、公式に明確な送信頻度の制限はありませんが、プラットフォームレベルでのレート制限が存在します。レート制限がかかると、Slackに送信されるすべてのメッセージが失敗し、一定のリスクが伴います。解決策は以下の通りです：

* **アラートチャネルで集約機能を有効にする**：同種のアラートや同一のアラートは、集約期間内に1回だけ送信されます。
* **プッシュレート制限**：OCPのプッシュ設定ではレート制限戦略を提供しており、日単位や時間単位でのレート制限をサポートしています（レート制限の次元はプッシュ設定+アラートチャネル）。
* **コマンドラインでの調整**：システム構成パラメータ `ocp.alarm.event.resend-interval-seconds` を変更します。デフォルトでは3分ごとにアラートイベントが生成されます。

上記の手順により、アラートメッセージの数を効果的に削減し、アラートがレート制限される可能性を低減できます。ただし、瞬時に大量の異なるアラートが発生した場合は、レート制限される可能性があります。

### ネットワークが接続されない

**ユーザー環境でSlack APIに直接アクセスできない場合、どう対処しますか？**

まず、curlを使用してテストメッセージを送信できるかどうかをテストします。ネットワークが接続されていない場合は、OCPとWebhookの接続性を調整する必要があります。

### アップグレード移行

**アップグレードまたは移行後、アラートのプッシュを更新するにはどうすればよいですか？**

Slack Webhookは新規のアラートプッシュ方法であり、理論上はHTTP、スクリプト、DingTalkなどのチャネルに対して特別な操作を行う必要はありません。Slackチャネルに切り替える必要がある場合は、直接新規に追加するだけです。

### Response検証情報失敗

**Response検証情報失敗を解決するにはどうすればよいですか？**

Response検証情報の設定に失敗した場合、スクリプトの記述が不適切でユーザーがアラートを受信できない、またはアラートが漏れるなどの問題を防ぐためです。アラートスクリプトには、有効な情報を1回だけ出力する必要があります（API応答コードまたはAPI応答ボディのいずれか）。OCPはこの情報が一致するかどうかを検証し、正規表現マッチングおよびJSONキー値ペアマッチングをサポートしています。

SlackボットのAPIはJSON形式の内容を返すため、JSONキー値ペアマッチングを使用する必要があります。SlackグループのメッセージチャネルにおけるResponse検証情報は`ok`に設定する必要があります。スクリプトチャネルでは、Response以外の内容を出力しないでください（例えば、curlコマンドでは進捗情報の出力を防ぐために`-s`パラメータを追加する必要があります）。
