# 2つのデータセンターを使用する構成におけるOceanBaseプライマリ/スタンバイクラスタの災害復旧フェイルオーバー

この記事では、2つのデータセンターを使用する構成において、OceanBaseプライマリ/スタンバイクラスタの災害復旧フェイルオーバーを実行する方法について説明します。

## 適用シナリオ

本番データセンターに障害が発生した場合（例：データセンター全体の停電など）、スタンバイデータセンター内のOceanBaseスタンバイクラスタをプライマリクラスタとして切り替え、外部へのサービス提供を開始し、短期間で業務を復旧します。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス**リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* 現在のクラスタがスタンバイクラスタであり、**<UI-TERM key="ocp-v2.src.constant.compute.Running">実行中</UI-TERM>** 状態にあること。
* 現在のクラスタのプライマリクラスタが停止または利用不能であり、すべてのOBServerがダウン状態であること。
* 現在のクラスタが最大パフォーマンスモードにあること。
* 現在のクラスタのOceanBaseバージョンがV2.2.76以上、V4.0未満であること。

## 手順

1. スタンバイOCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.component.ParameterTemplate.Cluster">クラスタ</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** からスタンバイクラスタに移動します。
2. 右上のメニューボタンをクリックし、**プライマリクラスタへの切り替え：災害復旧フェイルオーバー**を選択します。

    <!-- ![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/5946790261/p273267.png) -->

3. ポップアップウィンドウで **<UI-TERM key="ocp-v2.MultiCluster.Detail.DisasterRecoverySwitch">フェイルオーバー</UI-TERM>** をクリックします。

    <!-- ![image.png](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/5685987361/p355763.png) -->

4. `Failover ob cluster` タスクが完了するのを待ちます。この時点で、元のスタンバイクラスタが新しいプライマリクラスタとして外部へのサービス提供を開始します。

<main id="notice" type='explain'>
<h4>説明</h4>
<p><li>スタンバイクラスタはプライマリクラスタと完全に同期されていないため、災害復旧フェイルオーバーでは一部のデータが失われます。クラスタの <b>概要</b> > <b>基本情報</b> の <b>同期状態</b> で、<b>未同期時間</b> が最も短いスタンバイクラスタを選択して災害復旧フェイルオーバーを実行することを推奨します。</li><li>災害復旧フェイルオーバーが成功すると、元のプライマリクラスタはスタンバイクラスタに変更されず、独立した廃棄クラスタとなります。OCPからそのクラスタを削除することを推奨します。</li><li>災害復旧フェイルオーバーが成功すると、元のプライマリクラスタの他のスタンバイクラスタは新しいプライマリクラスタとデータを同期できません。そのため、そのスタンバイクラスタもOCPから削除することを推奨します。</li></p>
</main>

## よくある質問

1. Q：災害復旧フェイルオーバーのチェックに失敗し、生存しているOBServerが存在するというエラーが表示されました。
A：災害復旧フェイルオーバーが必要であることを確認した後、まずプライマリクラスタのすべてのOBServerが使用不能であるか確認することを推奨します。そうでない場合は、プライマリクラスタの稼働中のOBServerプロセスを停止してから、災害復旧フェイルオーバーを実行してください。

2. Q：OCP V3.3.0より前のバージョンでは、スタンバイクラスタのfailover速度を向上させるにはどうすればよいですか？
A：以下の2つの隠れたパラメータを手動で変更し、failover終了後に元の値に戻すことができます：

   * `_mini_merge_concurrency`：ダンプの並列度を制御します。デフォルト値は `3` ですが、`16` に変更することを推奨します。
   * `_ob_minor_merge_schedule_interval`：ダンプのスケジューリング間隔時間を設定します。デフォルトは `20s` ですが、`3s` に変更することを推奨します。

    ```sql
    # パラメータ値の確認
    SQL> SELECT NAME, VALUE FROM __ALL_VIRTUAL_SYS_PARAMETER_STAT WHERE NAME = '_mini_merge_concurrency';
    +-------------------------+-------+
    | NAME                    | VALUE |
    +-------------------------+-------+
    | _mini_merge_concurrency | 3     |
    +-------------------------+-------+
    1 row in set

    SQL> SELECT NAME, VALUE FROM __ALL_VIRTUAL_SYS_PARAMETER_STAT WHERE NAME = '_ob_minor_merge_schedule_interval';
    +-----------------------------------+-------+
    | NAME                              | VALUE |
    +-----------------------------------+-------+
    | _ob_minor_merge_schedule_interval | 20s   |
    +-----------------------------------+-------+
    1 row in set
    ```

    ```sql
    # パラメータの変更
    SQL> ALTER SYSTEM SET _mini_merge_concurrency = 16;
    Query OK, 0 rows affected

    SQL> ALTER SYSTEM SET _ob_minor_merge_schedule_interval = '3s';
    Query OK, 0 rows affected
    ```

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OCP V3.3.0以降では、クラスタのフェイルオーバー時にこのパラメータが自動的に変更され、スタンバイクラスタのフェイルオーバー速度が向上します。ユーザーが手動でこの構成パラメータを変更する必要はありません。</p>
    </main>

3. Q：フェイルオーバー処理は通常どのくらい続きますか？
A：フェイルオーバーの完了速度はゾーン数、ゾーン内のOBServer数、パーティション数に関連しており、通常は30秒から25分の範囲です。

4. Q：フェイルオーバー後、どのくらいでOBProxyを介して新しいプライマリクラスタに接続できますか？
A：OCPのフェイルオーバータスクが完了した後、業務でOBProxyを使用して新しいプライマリクラスタに接続する場合、約20秒から1分ほど接続失敗が発生する可能性があります。
