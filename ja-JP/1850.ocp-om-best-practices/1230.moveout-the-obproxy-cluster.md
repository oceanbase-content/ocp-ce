# OBProxyクラスタの移出

この記事では、OBProxyクラスタを移出する方法について説明します。

## 適用シナリオ

OBProxyクラスタを移出すると、現在のOBProxyクラスタは現在のOCPの管理から外れますが、OBProxyプロセスの実際の実行は停止せず、OBProxyソフトウェアも削除されません。[OBProxyの引き継ぎ](1260.takeover-the-obproxy.md)と組み合わせて使用し、OBProxyクラスタをあるOCPから別のOCPに移動することができます。

## 前提条件

* 現在ログインしているOCPユーザーが以下の権限を持っていることを確認してください：

  * **OBProxy管理** リソース権限。
  * OBProxy **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** メニュー権限。

* 将来的に移出後のOBProxyおよびそのOBProxyから接続可能なOceanBaseクラスタを別のOCPに引き継ぐ予定がある場合は、移出前に各OBProxy ServerでOceanBaseクラスタに一度接続することを推奨します。これにより、各OBProxy ServerがOceanBaseクラスタにアクセスしたことがあることを保証できます。

## 手順

1. OCPにログインし、OBProxyクラスタ一覧ページに移動します。

2. クラスタ一覧で移出するOBProxyクラスタを選択し、**その他 > クラスタの移出** をクリックします。または、OBProxyクラスタの概要ページに移動し、右上の **...** ボタンをクリックして、**<UI-TERM key="ocp-v2.Detail.Overview.MoveOutOfTheCluster.1">クラスタの移行</UI-TERM>** を選択します。

3. **<UI-TERM key="ocp-v2.Detail.Overview.MoveOutOfTheCluster.1">クラスタの移行</UI-TERM>** をクリックすると、確認ダイアログが表示されます。確認ダイアログ内の情報に基づいて、さらなる操作と確認を行う必要があります：

    * 移出対象のOBProxyクラスタがOBLBまたはSLBインスタンスに関連付けられている場合、確認ダイアログの上半分に関連付けられたロードバランサーのインスタンス情報が表示されます。引き継ぎ時にこれらのロードバランサーインスタンスを引き続き使用したい場合は、この情報をエクスポートすることができます。その場合、OCPはローカルにファイルとして保存し、引き継ぎ時にこのファイルをインポートできます。また、OCPは移出をクリックすると自動的にこの情報をローカルにエクスポートして保存します。OBProxyの引き継ぎについては、[OBProxyの引き継ぎ](../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md)を参照してください。

    * OCPはポップアップダイアログ内に、この移出操作に関連するすべてのホストのリストも表示します。ホストに他のサービスがデプロイされていない場合は、それを選択することで、OBProxyの移出後にホストも一緒に削除されます。削除したいホストがオフライン状態の場合は、OCPが移出タスクを完了した後、該当ホストに手動でログインしてOCP Agentをアンインストールする必要があります。

4. 上記のすべての情報を確認した後、下部の入力ボックスに `move out` と入力し、**<UI-TERM key="ocp-v2.Cluster.Arbitration.MoveOut">転出</UI-TERM>** ボタンをクリックします。これにより、OBproxyクラスタの移出に関する運用保守タスクが送信されます。運用保守タスクの実行が完了すると、OBProxyはこのOCPから正常に移出されたことを意味します。

## よくある質問

**Q：OBProxyを移出した後、上位の業務は切断されますか？**

A：通常、業務は切断されません。OBProxyの移出操作は、ロードバランサーとOBProxy、OBProxyとOBServer間の関連関係を変更しないため、上位の業務が切断されることはありません。ただし、例外として切断されるケースがあります：config urlモードのOBProxyをOCPから移出すると、元のconfig urlから最新のOBServer RS情報を取得できなくなります。その際、OBServerのRS情報に変更があった場合、OBProxyのルーティングエラーが発生する可能性があります。この場合、OBProxyを移出した後、速やかに新しいOCPに引き継ぐことを推奨します。OCPへの引き継ぎ計画がない場合は、OBProxyのconfig server urlを適切に変更することを推奨します。

**Q：OBServerの移出、OBProxyの移出、ホストの削除の3つの操作の順序はどのように処理すべきですか？**

以下の順序で操作することを推奨します：まずOBProxyを移出し、次にOBServerを移出し、最後に対応するホストを削除します。
