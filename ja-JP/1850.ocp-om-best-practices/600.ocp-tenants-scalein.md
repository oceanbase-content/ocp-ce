# OceanBaseクラスタおよびテナントのスケールイン

このセクションでは、OceanBaseクラスタおよびテナントのスケールイン方法について説明します。

## 適用シナリオ

縮小は拡張の逆操作です。クラスタ内のリソースに余裕がある場合、または業務トラフィックが減少した場合、テナントのUnit構成を縮小するかUnit数を削減することでOBServerのリソース使用量を抑え、OBServerノードを削除することでクラスタの柔軟なスケールインを実現します。

## 前提条件

* テナントのスケールダウンを行う際は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* クラスタのスケールインを行う際は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** のリソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** メニュー権限。

* OBServerノード数を減らす際は、クラスタが **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Running">実行中</UI-TERM>** 状態である必要があります。テナントのスケールダウンを行う際は、クラスタとテナントが **<UI-TERM key="ocp-v2.src.constant.compute.Running">実行中</UI-TERM>** 状態である必要があります。
* テナントのスケールダウンを行う前に、テナントが使用しているメモリを解放するため、メジャーコンパクションを1回実行することを推奨します。操作の詳細については、[メジャーコンパクションの実行](../700.tenant-functions/1400.manage-tenant-merge/300.perform-a-major-compaction.md)を参照してください。

## 注意事項

* OBServerノードの削除操作はロードバランシングに関わり、削除されるOBServerノード上のテナントUnitは同一ゾーン内で移行されます。Unit移行のターゲットマシンを選択したい場合は、OBServerノードを削除する前に手動でUnit移行を実行できます。詳細は [Unit分布の確認](../600.cluster-functions/1000.manage-cluster-resource/100.view-the-unit-distribution.md)を参照してください。

* OBServerノードの削除によりシステム利用可能リソースが減少します。同一ゾーン内の他のOBServerノードの残存リソースが削除対象ノード上のUnitを収容するには不十分な場合、Unit移行が失敗します。ノードを削除する前に、まずクラスタリソース管理ページで残存リソースが十分であるか判断することを推奨します。

* 残存するOBServerノードがすべてのテナントのデータレプリカまたはUnitを収容できない場合、OBServerノードの削除操作は失敗します。テナントのUnit構成を縮小するかUnit数を削減してから、OBServerノードを削除することを推奨します。

## 手順

### テナントのスケールダウン

* テナントUnit構成を小さくします。

    1. スケールダウン対象テナントの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動します。

    2. **<UI-TERM key="ocp-v2.Tenant.Detail.CopyDetails">レプリカの詳細</UI-TERM>** 領域で、操作列の **<UI-TERM key="ocp-v2.Alarm.Subscriptions.Edit">編集</UI-TERM>** をクリックし、Unit構成を小さくします。

        **Unit** ドロップダウンリストに必要なUnit構成がない場合は、**構成の追加** をクリックして新しい構成を追加して使用できます。

        <main id="notice" type='explain'>
        <h4>説明</h4>
        <p>テナント内の各Unitの構成は統一されている方が望ましいため、Unit構成を同じサイズに小さくすることを推奨します。</p>

* テナントUnit数を削減します。

    1. スケールダウン対象テナントの **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページに移動します。

    2. **<UI-TERM key="ocp-v2.Tenant.Detail.CopyDetails">レプリカの詳細</UI-TERM>** 領域で、**<UI-TERM key="ocp-v2.Detail.Overview.ModifyUnit">ユニットの変更</UI-TERM>** をクリックし、Unit数を減らします。

        <main id="notice" type='explain'>

        <li>テナントが属するクラスタがV4.0またはV4.1バージョンの場合、Unit数を減らす必要がある場合は、まずクラスタをV4.2以降のバージョンにアップグレードする必要があります。</li></p>
        </main>

### クラスタのスケールイン

テナントをスケールインした後、クラスタ内のOBServerノードのリソースに余裕が生じた場合、OBServerノードを削除する操作を実行して、クラスタをスケールインすることができます。

1. スケールイン対象のクラスタの **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページに移動します。

2. 削除するOBServerノードを選択し、**<UI-TERM key="ocp-v2.Tenant.Detail.BatchDelete">一括削除</UI-TERM>** をクリックして、タスクを生成します。

    一般的に、OBServerノードをスケールインする際は、各ゾーンで同数のOBServerノードを削除し、ゾーン間のリソース均等性を保証する必要があります。例えば、2-2-2構成のクラスタでは、各ゾーンから1台のOBServerノードを削除し、スケールイン後は1-1-1構成になります。

    <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E6%9C%80%E4%BD%B3%E5%AE%9E%E8%B7%B5/%E5%88%A0%E9%99%A4observer.png) -->

3. OBServerノードの削除タスクが完了するのを待ちます。

    タスク完了後、クラスタの **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページでデプロイメントモードを確認し、クラスタ内のOBServerノード数が減少しているかどうかを確認します。

    OBServerノード数が減少すると、テナントのリソースとデータはOBServerノード間で自動的にバランス調整されます。クラスタの **<UI-TERM key="ocp-v2.src.util.menu.ResourceManagement">リソース管理</UI-TERM>** ページで [Unit分布を確認する](../600.cluster-functions/1000.manage-cluster-resource/100.view-the-unit-distribution.md)ことができます。

## よくある質問

Q：テナントのスケールインタスクがずっと進行中のままです。
A：テナントのスケールインにはレプリカの移行が伴う場合があり、時間がかかることがあります。しばらくお待ちください。また、以下のコマンドを参照して、OceanBaseの関連ビューからタスクの状態を手動で確認することもできます。

```SQL
-- OceanBase V4.0より前のバージョンでテナントのスケールインタスクを照会する場合、JOB_STATUSがINPROGRESSの場合はタスクが進行中を意味します。
SELECT tenant_id, job_id, job_type, job_status, progress
FROM oceanbase.__all_rootservice_job
WHERE job_type = 'SHRINK_RESOURCE_POOL_UNIT_NUM'
ORDER BY job_id DESC LIMIT 1;

-- OceanBase V4.0以降のバージョンでテナントのスケールインタスクを照会する場合、JOB_STATUSがINPROGRESSの場合はタスクが進行中を意味します。
SELECT TENANT_ID, JOB_ID, JOB_TYPE, JOB_STATUS, PROGRESS
FROM oceanbase.DBA_OB_TENANT_JOBS
WHERE JOB_TYPE = 'SHRINK_RESOURCE_POOL_UNIT_NUM'
ORDER BY JOB_ID DESC;
```

Q：Delete observerタスクが失敗しました。
A：通常は残りのOBServerノードが過半数要件を満たせないためです。テナントのレプリカを確認してください。

Q：Delete observerの処理が遅いです。
A：Delete server時にUnitの移行が必要で、移行レプリケーションが遅いため長時間完了しない可能性があります。移行レプリケーションに関連する並列パラメータを適切に変更できます。

```SQL
-- OceanBase V4.0より前のバージョンでは、以下のパラメータでレプリカ移行速度を設定できます。
alter system set data_copy_concurrency = 100;
alter system set server_data_copy_out_concurrency = 40;
alter system set server_data_copy_in_concurrency = 40;

-- OceanBase V4.0以降のバージョンでは、以下のパラメータでレプリカ移行速度を設定できます。
alter system set ha_high_thread_score = 80;
alter system set ha_mid_thread_score = 80;
```

パラメータの説明については以下を参照してください：

* OceanBase V4.0より前のバージョン：[data_copy_concurrency](https://docs.oceanbase.com/oceanbase-database/V4.2.1-data_copy_concurrency)、[server_data_copy_out_concurrency](https://docs.oceanbase.com/oceanbase-database/V4.2.1-server_data_copy_out_concurrency)、[server_data_copy_in_concurrency](https://docs.oceanbase.com/oceanbase-database/V4.2.1-server_data_copy_in_concurrency)。
* OceanBase V4.0以降のバージョン：[ha_high_thread_score](https://docs.oceanbase.com/oceanbase-database/V4.2.1-ha_high_thread_score)、[ha_mid_thread_score](https://docs.oceanbase.com/oceanbase-database/V4.2.1-ha_mid_thread_score)。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>タスクが成功した後は、直ちにパラメータ値を元の設定に戻してください。クラスタ機能への影響を防ぐためです。</p>
</main>

Q：Wait observer deleteタスクがずっと実行中のままです。
A：OBServerノードが異常でダウンしたことがある場合、delete server後、OBServerが完全に削除されるまでの永続的なオフライン時間（デフォルトで1時間）を待たなければなりません。Wait observer deleteタスクはタイムアウトにより失敗します。解決策は、クラスタの永続的なオフライン時間を手動で短縮することです。

```SQL
alter system set server_permanent_offline_time = '120s';
```

パラメータの説明については、[server_permanent_offline_time](https://docs.oceanbase.com/oceanbase-database/V4.2.1-server_permanent_offline_time)を参照してください。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>タスクが成功した後は、直ちに永続的オフライン時間のパラメータ値を元の設定に戻してください。これにより、クラスタ機能への影響を防ぐことができます。</p>
</main>
