# OBProxyクラスタのスケールアウト

このセクションでは、OBProxyクラスタをスケールアウトする方法について説明します。

## 適用シナリオ

既存のOBProxyクラスタにOBProxy Serverを追加し、OBProxyクラスタの信頼性を向上させ、クラスタ内の各OBProxy Serverの負荷を分散します。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **OBProxyメンテナンス** リソース権限。
  * OBProxy **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** メニュー権限。

* OBProxy Serverをデプロイするためのホストを [ホストの追加](../850.host-features/100.manage-a-host/200.add-a-host.md) によりOCP管理下に追加します。
* 新しいホストに `nc` コマンドが存在し、OBProxyプロセスが実行されていないことを確認します。

## 手順

**ステップ1：OBProxyクラスタにOBProxy Serverを追加する**

1. OCPにログインします。
2. 左側のナビゲーションバーで **OBProxy** をクリックし、操作対象のOBProxyクラスタをクラスタリストから選択して、OBProxyクラスタの **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページに移動します。
3. **<UI-TERM key="ocp-v2.LoadBalance.ObproxyCondition.AddObproxy">OBProxyを追加する</UI-TERM>** をクリックし、ポップアップダイアログに情報を入力します。
4. **<UI-TERM key="ocp-v2.MultiCluster.Detail.FailoverModal.Determine">確定</UI-TERM>** をクリックして運用保守タスクを送信し、タスクの実行完了を待ちます。

**（オプション）ステップ2：ネットワークの切り替え**

* 業務アプリケーションが **<UI-TERM key="ocp-v2.component.MoveOutClusterDrawer.LoadBalancer.AlibabaCloudSlb">Alibaba Cloud SLB</UI-TERM>** または **OBLB** を使用してOBProxyにアクセスしている場合、新しいOBProxyが利用可能になると業務トラフィックは新しいOBProxyにも自動的に分散されるため、ネットワークの切り替えは不要です。
* 業務アプリケーションが手動で作成した **SLB/F5** インスタンスなど、他のロードバランシングインスタンスを使用している場合は、これらのネットワークリソースを追加で変更し、新しいOBProxyノードをロードバランシングインスタンスのバックエンドに追加する必要があります。変更が有効になると業務トラフィックが新しいOBProxyにも分散されます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p><li>OBProxyクラスタがV4.0以降のバージョンの場合、V4.0.0以降のバージョンのソフトウェアパッケージのみを選択できます。</li><li>OBProxyクラスタがV3.x以下のバージョンの場合、V1.8.0以上、V4.0.0未満のバージョンのソフトウェアパッケージのみを選択できます。</li><li>新しく追加するOBProxyのバージョンは、既に稼働中のOBProxyのバージョンやアーキテクチャと一致させることを推奨します。これにより、予期しない問題を回避できます。</li></p>
</main>
