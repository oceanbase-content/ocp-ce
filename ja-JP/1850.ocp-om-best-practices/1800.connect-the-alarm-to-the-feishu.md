# アラートをFeishuグループに連携する

Feishuグループを使用してアラートメッセージを受信し、ボットを通じてFeishuにメッセージを送信することができます。グループの全メンバーがアラートメッセージを確認できます。

## 適用シナリオ

OCPのアラートメッセージは、Feishuグループ内のボットにプッシュされ、ボットがグループ内にアラートメッセージを送信します。Feishuボットと連携するには、FeishuボットのWebhookアドレスを提供するだけで済みます。

一部の拡張機能は以下のとおりです：

* ボットのセキュリティ設定で署名追加をサポート：より安全な通知方法です。OCPは提供された秘密鍵を使用して送信メッセージに署名を追加し、悪意のあるメッセージ送信を防ぎます。
* メッセージのMarkdown形式を定義し、アラート名を太字に表示したり、アラート情報をリスト形式で表示したりできます。
* プロキシの設定：社内ネットワークとパブリックネットワークが接続されていない場合は、ネットワークプロキシを設定する必要があります。アラートメッセージはまずプロキシに送信され、プロキシからFeishuに転送されます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス**、**テナントメンテナンス**、**OBProxyメンテナンス**、**アービトレーションサービスメンテナンス**、**Binlogサービスメンテナンス**、または**ホストメンテナンス**のいずれかのリソース権限。
  * アラートセンターの**<UI-TERM key="ocp-v2.Auth.Role.Detail.All">すべて</UI-TERM>**メニュー権限。

* Feishuボットの作成と設定が完了していること。カスタムボットのメッセージ受信頻度は、1分あたり最大100回、1秒あたり最大5回に制限されています。この制限を超えると、メッセージはスロットリングされます。

  Feishuボットへの接続については、[Feishuボット公式ドキュメント](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot#399d949c)を参照してください。

* ボットのWebhookを取得していること。Feishuボットの設定後、ボットのWebhookを取得します。これはOCPのFeishuアラートチャネルを構成するために必須の項目です。アラートメッセージのセキュリティを確保するため、このWebhookが漏洩しないようにしてください。Webhookを取得した後、以下のコマンドを実行して、メッセージがFeishuグループに正しく送信されるかどうかをテストします：

    ```shell
    curl 'https://open.feishu.cn/open-apis/bot/v2/hook/请补充完整您的webhook地址' \
    -H 'Content-Type: application/json' \
    -d '{"msg_type": "text","content": {"text":"Feishuボットテストメッセージ"}}'
    ```

## 注意事項

上記のテスト例からわかるように、アラートメッセージはFeishu APIにリクエストすることでFeishuに配信されます。API内のtokenはFeishuボットの一意の識別子であり、適切に保管する必要があります。tokenが漏洩すると、攻撃者はそのAPIにリクエストすることで、広告や違反コンテンツなどの悪意のあるメッセージを送信する可能性があります。アラートメッセージのセキュリティと信頼性を確保するため、Feishuは3種類のセキュリティ設定を提供しています：

* カスタムキーワード：アラートメッセージにはキーワードが含まれている必要があります。
* IPアローリスト：アローリスト内のIPアドレス(OCPアドレス)のみが、Webhookを介してアラートメッセージを送信できます。
* 署名検証：送信メッセージは秘密鍵を使用して署名され、Feishuは署名が正しいかどうか検証します。これにより、メッセージの改ざんや悪意のあるアラート送信などのリスクを防ぎます。このセキュリティ設定の使用を推奨します。

## 手順

1. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.page.Alarm.Alarm">アラートセンター</UI-TERM>**をクリックします。

2. アラートセンターページで、**<UI-TERM key="ocp-v2.Alarm.Subscriptions.New.AlarmChannel">アラートチャネル</UI-TERM>**をクリックします。

3. アラートチャネルタブで、**<UI-TERM key="ocp-v2.Alarm.Channel.NewChannel">新規チャネル作成</UI-TERM>**をクリックします。

4. Larkアラートチャネルを設定します。

        | 選択項目 | 必須 | 説明 |
        |-------|----------|------|
        | チャネルタイプ | はい | Larkをドロップダウンで選択します。 |
        | チャネル名 | はい | 後の識別を容易にするため、チャネル名をカスタマイズします。 |
        | Webhookアドレス | はい | Larkボットのアクセスアドレスです。取得方法については、[Larkボット公式ドキュメント](https://open.dingtalk.com/document/orgapp/custom-robot-access)を参照してください。 |
        | 署名秘密鍵 | いいえ | 署名秘密鍵：Larkボットは3種類のセキュリティ設定を提供しています。署名設定を選択すると署名秘密鍵を取得できます。 |
        | @指定ユーザー | いいえ | 入力する携帯電話番号は、ユーザーのLarkログイン番号である必要があります。アラート発生時、ボットはそのメンバーを@します。複数のメンバー番号を入力する場合は、半角カンマで区切ります。 |

## よくある質問

### メッセージのレート制限

Q：レート制限によりメッセージ送信が失敗しました。キーワード例：`{"code":9499,"msg":"too many request","data":{}}`。

A：Larkのカスタムボットがメッセージを受信できる頻度は、1分あたり最大100件、1秒あたり最大5件です。この制限を超えると、メッセージはレート制限されます。レート制限後、Larkに送信されるすべてのメッセージは失敗し、一定のリスクが伴います。解決策：

* アラートチャネルで集約機能を有効にすると、同種のアラートや同一のアラートが集約期間内に1回のみ送信されます。
* プッシュのレート制限：OCPのプッシュ設定ではレート制限戦略が提供されており、日単位や時間単位でのレート制限をサポートしています（レート制限の次元はプッシュ設定 + アラートチャネル）。
* コマンドラインで `ocp.alarm.event.resend-interval-seconds` システム設定を調整します。デフォルトでは3分ごとにアラートイベントが発生します。

上記の手順により、アラートメッセージの数を効果的に削減し、アラートがスロットリングされる可能性を低減できます。ただし、瞬間的に大量の異なるアラートが発生した場合は、スロットリングされる可能性があります。

### ネットワーク不通

Q：ユーザー環境からLark APIに直接アクセスできない場合はどう対処しますか？

A：まず、curlを使用してテストメッセージを送信できるかどうかをテストします。ネットワークが不通の場合は、**<UI-TERM key="ocp-v2.Alarm.Channel.NewChannel">新規チャネル作成</UI-TERM>** > **<UI-TERM key="ocp-v2.Alarm.Rule.New.BasicConfiguration">基本設定</UI-TERM>** > **<UI-TERM key="ocp-v2.Channel.FormComponent.WeComForm.Proxy">代理人</UI-TERM>** でネットワークプロキシを設定する必要があります。

### アップグレードと移行

Q：アップグレードまたは移行後、アラートのプッシュ通知を更新する方法は何ですか？

A：OCP 4.0.1以前のバージョンでは、HTTPチャネルまたはスクリプトチャネルを介してLarkへのアラートメッセージを送信していました。4.0.1以降のバージョンでは、組み込みのLarkチャネルを追加することを推奨します。送信結果の検証に失敗することを避けるため、以下の説明を参照してください：

* 加署機能の使用：OCP 4.0.1以前では、Larkボットへのメッセージ送信はスクリプトまたはHTTPチャネルで設定されており、加署設定はサポートされていません。OCP 4.0.1以降にアップグレードした後、この方法に切り替えることができます：Webhookをコピーし、新規作成の手順は本記事を参照してください。

* チャネルタイプがHTTPまたはスクリプトチャネルを使用しており、アラートがLarkグループ宛ての場合は、組み込みのLarkチャネルの使用を推奨します。本記事を参照して設定してください。

### Response検証情報失敗

Q：Response検証情報失敗を解決する方法は何ですか？

A：Response検証情報失敗の設定は、スクリプトの記述が不適切でユーザーがアラートを受信できない、アラートが漏れるなどの問題を防ぐために行われます。スクリプト内には、有効な情報を1回だけ出力する必要があります（API応答コードまたはAPI応答ボディのいずれか）。OCPが情報が一致するかどうかを検証します。正規表現マッチングとJSONキー値ペアマッチングをサポートしています。LarkボットAPIが返すのはJSON内容であるため、JSONキー値ペアマッチングを使用する必要があります。LarkアラートチャネルのResponse検証情報は次のように設定する必要があります：`{"StatusCode":0,"StatusMessage":"success"}`。スクリプトチャネルでは、Response以外の内容を出力しないでください（例えば、curlコマンドには進捗情報の出力を防ぐために-sパラメータを追加する必要があります）。
