# プライマリ/スタンバイテナントのディザスタリカバリ切り替え

このセクションでは、プライマリテナントとスタンバイテナントのディザスタリカバリ切り替え方法について説明します。

## 適用シナリオ

プライマリテナントが利用不能な場合、ディザスタリカバリ切り替えを実行してスタンバイテナントをプライマリテナントに切り替え、外部へのサービス提供を継続します。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス**または**テナントメンテナンス**のリソース権限。
  * テナントの**<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>**メニュー権限。

* 以下で言及するスタンバイテナントとは、ディザスタリカバリ切り替えを実行するスタンバイテナントを指し、プライマリテナントとはそのスタンバイテナントのプライマリテナントを指します。階層型のプライマリ/スタンバイテナント関係では、例えば `テナントA` > `テナントB` > `テナントC` のように、`テナントB` と `テナントC` の役割はどちらも standbyです。しかし、`テナントC` でディザスタリカバリ切り替えを実行する場合、本文では `テナントC` をスタンバイテナント、`テナントB` をプライマリテナントと呼びます。これは記事の記述を明確にするためだけです。

  * プライマリテナントが既に利用不能であること。（プライマリテナントが利用可能な場合は、プライマリ/スタンバイテナント分離機能を直接使用してプライマリ切り替えを実行できます。）
  * プライマリテナントとスタンバイテナントがどちらもOCPによって管理されていること。（OCPのマルチクラスタモードでは、プライマリテナントとスタンバイテナントは異なるOCPクラスタに存在できます。）
  * スタンバイテナントが利用可能であり、かつスタンバイテナントが配置されているクラスタの状態が正常であること。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーの **<UI-TERM key="ocp-v2.Alarm.Event.Tenant">テナント</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.page.Tenant.TenantList">テナント一覧</UI-TERM>** からスタンバイテナントに移動します。

3. 右上のメニューアイコンをクリックし、**<UI-TERM key="ocp-v2.Detail.Component.FailoverStandbyTenantModal.DisasterRecoverySwitchover">フェイルオーバー</UI-TERM>** を選択します。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E5%AE%B9%E7%81%BE%E5%88%87%E6%8D%A2.png)

4. OCPはプライマリテナントのすべてのスタンバイテナントの一貫性ポイント状況を一覧表示します。時間的に最新の一貫性ポイントを持つスタンバイテナントを使用してディザスタリカバリ切り替えを実行することを推奨します。これは、最新の時点を持つスタンバイテナントが最新のデータを保持しているためです。

   **<UI-TERM key="ocp-v2.MultiCluster.Detail.FailoverModal.DisasterRecoverySwitch">フェイルオーバー</UI-TERM>** をクリックして運用保守タスクを送信します。タスクの実行が成功すると、プライマリ/スタンバイテナントのディザスタリカバリ切り替えが完了したことを意味します。

   ![11221346](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E5%AE%B9%E7%81%BE%E5%88%87%E6%8D%A2.png)

## よくある質問

**OCPにおけるプライマリ/スタンバイテナントのディザスタリカバリ切り替えとプライマリ/スタンバイテナント分離の違いは何ですか？**

* プライマリ/スタンバイテナントのディザスタリカバリ切り替えを実行する際、OCPは以下の追加検査を行います：

  1. プライマリテナントとスタンバイテナントがOCPによって管理されているかどうか。
  2. プライマリテナントが既に利用不能であるかどうか。この検査は、ディザスタリカバリ切り替え後にデュアルプライマリ状態が発生し、上位の業務にエラーが生じるのを防ぐために行われます。

* [プライマリ/スタンバイテナント分離](1290.primary-or-standby-tenant-decouple.md)を実行する場合、プライマリテナントが利用不能になることは想定されていないため、OCPは追加の検査を行いません。
