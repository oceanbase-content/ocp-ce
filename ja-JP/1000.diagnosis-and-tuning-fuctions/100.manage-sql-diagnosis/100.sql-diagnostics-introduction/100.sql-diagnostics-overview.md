# SQL診断の概要

SQL問題はパフォーマンス問題の中で最も一般的なものです。OCPはさまざまな観点からSQLを診断する機能を提供し、SQLの実行特性に基づいて、疑わしいSQL、TopSQL、SlowSQL、ParallelSQLに分類します。SQLの実行過程で異常が発生した場合、異なるアプリケーションシナリオに応じて異なる診断タイプを選択し、SQLの異常箇所を特定することができます。また、SQLプランとアウトラインを通じて実行計画の確認と変更をサポートしています。

## TopSQL診断

TopSQLは、SQLリクエストのSQL IDを集約軸として、さまざまな形態のSQLの実行統計情報を集計し、異なるリソース消費量に基づいてSQLをソートし、SQL実行の履歴傾向を表示します。TopSQL機能を利用して、このようなSQLのリクエスト動作を分析し、潜在的な異常リクエストを発見したり、特定の目的に沿ってSQLのパフォーマンスチューニング分析を行ったりできます。

## 疑わしいSQL診断

SQL診断は、OCPの既存のTopSQL収集データに基づき、専門家の経験を組み込んでSQLを診断し、潜在的なリスクを持つSQL、すなわち疑わしいSQLを特定します。SQL診断のデータソースはTopSQLと同じであり、各診断項目はOCPのMonitorDBのメタデータから、一定のルール（CPU時間、実行頻度など）にマッチする対象を取得して診断します。
疑わしいSQLの診断では、パフォーマンスの低下や実行計画の変化が見られるSQLが表示されます。これらのSQLを重点的に確認してください。同時に、疑わしいSQLの診断結果には、パフォーマンス低下の原因分析などの情報が含まれており、SQLチューニングに向けたより具体的な指針を提供します。

## SlowSQL

OCPでは、実行時間が一定時間（設定可能、デフォルト100ms）を超えるSQLをSlowSQLと呼びます。ビジネスシナリオに応じてSlowSQLのしきい値を設定できます。SlowSQLの影響は以下のとおりです：

* SQLの応答が遅く、応答時間が長い。
* システムリソースの消費が大きく、極端な場合はシステムが利用不能になる可能性がある。

そのため、システムの安定性に影響を与える可能性のあるこれらのSlowSQLを収集・分析し、問題の早期特定とリスク回避を支援する必要があります。OCPのSlowSQLは、単一のSQL実行情報に注目し、`oceanabse v$sql_audit`のデータをサンプリングして保存します。これにより、さまざまな観点からSlowSQLのリソース消費と実行詳細を分析できます。

## ParallelSQL

ParallelSQLとは、パラレルスケジューリングメカニズムを使用して実行されるSQLを指します。ParallelSQL診断を通じて、APクエリのパフォーマンスが期待に達していないSQLを確認し、SQL実行プロファイルを通じて、収集時間範囲内の演算子レベルのSQL実行詳細を確認できます。

## アウトラインのバインド

上記のSQL診断機能で異常なSQLを特定した後、それがSQL実行計画の誤りによるパフォーマンス問題であると判断された場合、OCPはインデックスベースのアウトラインバインディング機能を提供し、SQLの実行計画を直接変更することをサポートします。これにより、データベースが期待通りに適切な実行計画を使用するようにします。
アウトラインバインディング機能は主に、特定のシナリオで発生する問題を解決するために使用されます：

* データベースオプティマイザーに欠陥があり、特定のシナリオで誤った実行計画を使用する場合。例えば、オプティマイザーが統計情報に基づくコスト計算で、大量の増分データがある状況下で誤った実行計画を生成する可能性があります。
* SQLリクエストがデータベースに過度の負荷をかける場合、データベース側でユーザーのリクエスト速度を低下させる必要がある場合。

## SQLプラン

SQL診断ページのSQLリストで任意のSQLをクリックすると、SQL詳細ページに移動します。このページでは、SQLの詳細な実行文を確認できるほか、OCPはSQL実行計画の履歴表示もサポートしています。これには以下が含まれます：

* 実行計画の履歴傾向。
* 実行計画のリストと詳細。
