# 高リスクSQLの診断

OCPは、ルールに基づいて特定された、システムのパフォーマンス、セキュリティ、データに危害を及ぼす可能性のあるSQLを識別できます。

<main id="notice" type='notice'>
    <h4>機能の適用範囲</h4>
    <p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能を提供していません。</p>
</main>

OCPが識別できる高リスクSQLのタイプは以下のとおりです：

| 操作の説明 | 例  |  高リスクタイプ  |  説明  |
|------  |    -----      |   ----     |    ----     |
|列の追加または削除  |    <ul><li> `alter table test drop column id` </li><li>`alter table test add new_id int not null comment '新id'` </li> </ul>  |    テーブル構造変更-列の追加/削除    |    -     |
|    テーブルまたはデータベースの削除      |  <ul><li>`drop table test`  </li><li>`drop database test` </li> </ul>   |    テーブル/データベースの削除    |  - |
|テーブルのクリア  |     `truncate table test`     |  データテーブルのクリア      |      -   |
|条件なしでの更新  |   `update test set new_id =1`       |   条件なしでの更新     |    -     |
|条件が常に真の更新  |     `update  test set new_id =1 where 1 = 1`     |   条件が常に真の更新     |     -    |
| 条件なしでの削除  |   `delete from test`       |    条件なしでの削除    |   -      |
|条件が常に真の削除  |    `delete  from test where 1=1`      |    条件が常に真の削除    |     -    |
|返される行数が多すぎる  |   `max_return_rows > 50000`       |    返される行数が多すぎる    |    `max_return_rows`は最大返却行数を設定するために使用されます。設定値を超える場合、高リスクSQLと見なされます。[システムパラメータ管理](../../1600.system-management-features/500.manage-system-parameter/100.view-system-parameters.md)でこのしきい値を調整できます。     |
|影響を受ける行数が多すぎる  |    `max_affected_rows  > 50000`      |     影響を受ける行数が多すぎる   |   `max_affected_rows`は最大影響行数を設定するために使用されます。設定値を超える場合、高リスクSQLと見なされます。[システムパラメータ管理](../../1600.system-management-features/500.manage-system-parameter/100.view-system-parameters.md)でこのしきい値を調整できます。      |
|参加パーティション数が多すぎる  |   `max_partition_cnt >2000`       |   参加パーティション数が多すぎる     |   `max_partition_cnt`は最大参加パーティション数を設定するために使用されます。設定値を超える場合、高リスクSQLと見なされます。[システムパラメータ管理](../../1600.system-management-features/500.manage-system-parameter/100.view-system-parameters.md)でこのしきい値を調整できます。      |

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用** または **テナント読み取り専用** のリソース権限。
  * 診断サービス **<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">リアルタイム診断</UI-TERM>** メニュー権限。

* [パラメータの管理](../../600.cluster-functions/300.manage-a-cluster/1200.manage-om-configuration/200.manage-om-configuration-parameters.md)で **<UI-TERM key="ocp-v2.component.OperationConfig.List.SqlDiagnosticCollection">SQL 診断収集</UI-TERM>** モジュールのパラメータが有効になっていること。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.page.Diagnosis.AutonomousService">診断サービス</UI-TERM>** をクリックします。

3. **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">クラスタの詳細</UI-TERM>** セクションで、表示するクラスタ名をクリックします。

4. デフォルトで、**<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">リアルタイム診断</UI-TERM>** の **<UI-TERM key="ocp-v2.Detail.Monitor.SqlDiagnosis">SQL 診断</UI-TERM>** ページに入ります。

5. **<UI-TERM key="ocp-v2.page.Overview.HighRiskSql">高リスクSQL</UI-TERM>** タブをクリックします。

6. 絞り込み条件を設定し、高リスクSQLをフィルタリングします。

     * 時間範囲：**<UI-TERM key="ocp-v2.Detail.Analyze.TimesChart.TimeRange">時間範囲</UI-TERM>** のドロップダウンリストから、過去5分、過去10分、過去20分、過去30分、過去1時間、過去3時間、過去6時間を選択して、時間範囲を簡単に指定できます。また、ドロップダウンリストからカスタム時間を選択し、開始時刻と終了時刻を設定することもできます。デフォルトでは、過去6時間以内の情報が表示されます。

     * OBServer：OBServerノードを選択すると、そのOBServerノード上で実行されたSQLのみがクエリ対象となります。

     * 内部SQL：このオプションを選択すると、クエリ結果にOceanBase内部で発行されたSQLが含まれます。

     * キーワード：クエリ結果には、SQLテキストに該当するキーワードが含まれるSQLが表示されます。マッチング方法はSQLのLIKEと同じで、入力した文字列の前後にはデフォルトで自動的に%記号が追加されます。

     * 上級条件：**<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.AdvancedConditions">高度な条件</UI-TERM>** では、複数のフィルタ条件を同時に追加できます。**<UI-TERM key="ocp-v2.alarm.ExpressionFormList.SingleExpressionFormList.Add">追加</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.Component.SQLCondition.AddAdvancedConditions">高度な条件を追加する</UI-TERM>** パネルで指標、演算子、値を設定します。クエリ時には、条件を満たすSQLが結果リストに表示されます。

     ![Image 9](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/432/%E9%AB%98%E5%8D%B1sql.png)

7. **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Query">クエリ</UI-TERM>** をクリックすると、下部のリストにクエリ条件に合致するすべてのSQLが表示されます。クエリされた高リスクSQLに対して、以下の操作を実行できます：

   * **高リスクSQLのエクスポート** ボタンをクリックすると、リストに表示されているすべてのSQLがエクスポートされます。

   * 高リスクSQLの情報を確認します。

     1. **<UI-TERM key="ocp-v2.page.Overview.HighRiskSql">高リスクSQL</UI-TERM>** タブでは、前の手順で選択した列情報を確認できます。SQLテキストのコピーと、データベースに基づくSQLテキストのフィルタリングがサポートされています。

     2. SQLテキストをクリックすると、**<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.SqlDetails">SQLの詳細</UI-TERM>** ページに移動し、そのSQLの詳細情報を確認できます。詳細については以下のとおりです：

        * **<UI-TERM key="ocp-performance-report.ReportTable.SQL.SordByWaitEventTable.SqlText">SQLテキスト</UI-TERM>** で、SQLの完全な文を確認できます。

        * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.Plan.HistoricalTrends">歴史的傾向</UI-TERM>** タブでは、そのSQLの実行履歴傾向と計画生成時刻を確認できます。詳細については、[SQL実行の履歴傾向の確認](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

        * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">実行計画</UI-TERM>** タブでは、そのSQLの実行計画を確認したり、実行計画をバインドしたりできます。詳細については、[SQLの実行計画の確認](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

        * **<UI-TERM key="ocp-v2.Capacity.Resource.Top.Index">インデックス</UI-TERM>** タブでは、そのSQLがバインドされているインデックスを確認できます。詳細については、[インデックスの確認とバインド](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

        * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.SqlThrottling">SQL スロットリング</UI-TERM>** タブでは、そのSQLのスロットリング状況を確認したり、スロットリングを設定したりできます。詳細については、[SQLスロットリングの設定](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。
