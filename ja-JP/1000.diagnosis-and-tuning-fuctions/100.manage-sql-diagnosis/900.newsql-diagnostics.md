# 新規SQLの診断

新規SQLとは、クエリ期間の直前の一定期間（デフォルトで7日間）に実行された記録がなく、かつクエリ期間内に実行記録があるSQLを指します。このセクションでは、新規SQLの診断方法について説明します。

<main id="notice" type='notice'>
    <h4>機能の適用範囲</h4>
    <p>この内容はOCP Enterprise版にのみ適用されます。OCP Community版はこの機能を提供していません。</p>
</main>

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**または**テナント読み取り専用**のリソース権限。
  * 診断サービスの**<UI-TERM key="ocp-v2.Detail.Realtime.RealTimeDiagnosis">リアルタイム診断</UI-TERM>**メニュー権限。

* [パラメータの管理](../../600.cluster-functions/300.manage-a-cluster/1200.manage-om-configuration/200.manage-om-configuration-parameters.md)で、**<UI-TERM key="ocp-v2.component.OperationConfig.List.SqlDiagnosticCollection">SQL 診断収集</UI-TERM>**モジュールパラメータが有効になっていること。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.pages.Diagnosis.DiagnosticServices">診断サービス</UI-TERM>**をクリックします。

3. **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">クラスタの詳細</UI-TERM>**エリアで、表示したいクラスタ名をクリックします。

4. デフォルトで、**<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">リアルタイム診断</UI-TERM>**の**<UI-TERM key="ocp-v2.Detail.Realtime.SqlDiagnosis">SQL 診断</UI-TERM>**ページに入ります。

5. **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.AddSql">新規SQL</UI-TERM>**タブをクリックします。

6. 絞り込み条件を設定し、新規SQLをフィルタリングします。

     * 時間範囲：**<UI-TERM key="ocp-v2.Detail.Analyze.TimesChart.TimeRange">時間範囲</UI-TERM>**ドロップダウンリストから、直近5分、直近10分、直近20分、直近30分、直近1時間、直近3時間、直近6時間を選択すると、時間範囲を簡単に指定できます。また、ドロップダウンリストからカスタム時間を選択し、開始時刻と終了時刻を設定することもできます。デフォルトでは直近6時間以内の情報が表示されます。

     * OBServer：OBServerノードを選択すると、そのOBServerノード上で実行されたSQLのみがクエリ対象となります。

     * 内部SQL：このオプションを選択すると、クエリ結果にOceanBase内部から発信されたSQLが含まれます。

     * キーワード：クエリ結果には、SQLテキストに該当するキーワードが含まれるSQLが表示されます。マッチング方式はSQLのLIKEと同じで、入力した文字列の前後にはデフォルトで自動的に%記号が付加されます。

     * 高度な条件：**<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.AdvancedConditions">高度な条件</UI-TERM>**では、複数のフィルタ条件を同時に追加できます。**<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterAndHostWithExclude.Add">追加</UI-TERM>**をクリックし、**<UI-TERM key="ocp-v2.Component.SQLCondition.AddAdvancedConditions">高度な条件を追加する</UI-TERM>**パネルで指標、演算子、値を設定します。クエリ時には、指定した条件を満たすSQLが結果リストに表示されます。

7. **<UI-TERM key="ocp-v2.Auth.User.loginHistory.Query">クエリ</UI-TERM>**をクリックすると、下部のリストにクエリ条件に合致するすべてのSQLが表示されます。クエリされた新規SQLに対して、以下の操作を実行できます：

      1. **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.ColumnManager.ColumnManagement">カラム管理</UI-TERM>**をクリックし、パネルで表示したい情報を選択します。選択後、新規SQLリストで関連する結果を確認できます。

      2. **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.AddSql">新規SQL</UI-TERM>**タブで、前の手順で選択した列情報を確認できます。SQLテキストのコピーと、データベースに基づくSQLテキストのフィルタリングがサポートされています。

      3. SQLテキストをクリックすると、**<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.SqlDetails">SQLの詳細</UI-TERM>** ページに移動し、以下の詳細情報を確認できます。

        * **<UI-TERM key="ocp-performance-report.ReportTables.SqlInfo.SQLInfoTable.SqlText">SQLテキスト</UI-TERM>** でSQLの完全なステートメントを確認します。

        * **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.OptimizationSuggestions">最適化の提案</UI-TERM>** で、そのSQLに対する最適化提案を確認します。詳細については、[最適化提案の表示](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

        * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.Plan.HistoricalTrends">歴史的傾向</UI-TERM>** タブで、そのSQLのSQL実行傾向図とSQL計画生成傾向図を確認します。詳細については、[SQL実行の履歴傾向の表示](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

        * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">実行計画</UI-TERM>** タブで、そのSQLの実行計画を確認するか、実行計画をバインドします。詳細については、[SQLの実行計画の表示](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

        * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.Index">インデックス</UI-TERM>** タブで、そのSQLがバインドされているインデックスを確認します。詳細については、[インデックスの表示とバインド](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

        * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.SqlThrottling">SQL スロットリング</UI-TERM>** タブで、そのSQLのスロットリング状況を確認するか、スロットリングを設定します。詳細については、[SQLスロットリングの設定](../100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。
