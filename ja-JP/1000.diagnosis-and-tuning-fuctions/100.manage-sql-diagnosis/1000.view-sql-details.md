# SQLの詳細を表示する

このセクションでは、OCPを使用してSQLの詳細を表示する方法について説明します。これには、SQLの実行状況、実行計画、バインドされたインデックス、およびレート制限の有無が含まれます。

SQL診断の詳細は、以下の2つのエントリから確認できます：

* **エントリ1**：OCPにログインし、左側のナビゲーションバーで**<UI-TERM key="ocp-v2.page.Diagnosis.DiagnosticCenter">診断サービス</UI-TERM>**をクリックし、確認したいクラスタを選択して、クラスタの**<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">リアルタイム診断</UI-TERM>**ページに移動します。

* **エントリ2**：OCPにログインし、テナントの**<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>**ページに移動し、左側のナビゲーションバーで**<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDiagnosis">SQL 診断</UI-TERM>**をクリックします。

<main id="notice" type='notice'>
   <h4>機能の適用範囲</h4>
   <p>コミュニティ版は現在診断サービスをサポートしていません。この機能は<b>エントリ2</b>からアクセスしてご利用ください。</p>
</main>

## 前提条件

* **エントリー1** からSQL詳細を表示する場合は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用** または **テナント読み取り専用** のリソース権限。
  * 診断サービス **<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">リアルタイム診断</UI-TERM>** メニュー権限。

* **エントリー2** からSQL詳細を表示する場合は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用** または **テナント読み取り専用** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SqlDiagnosis">SQL 診断</UI-TERM>** メニュー権限。

* SQL実行プロファイルの表示は、OceanBase V3.0以降のバージョンでのみサポートされています。

* MySQLモードのテナントの場合、OCPユーザーのパスワードボックスにそのテナントのパスワードが含まれている必要があります。

* Oracleモードのテナントの場合、OCPユーザーのパスワードボックスにそのクラスタのSYSテナントのパスワードが含まれている必要があります。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>OCPに現在ログインしているテナントが、テナントの <strong>更新</strong> 権限を持っている場合にのみ、インデックスのバインド、実行計画のバインド、およびレート制限の設定が可能です。</p>
  </main>

## SQL詳細ページへのアクセス

以下の操作手順は、**エントリー1** を例に説明します。

1. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.page.Diagnosis.DiagnosticCenter">診断サービス</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">クラスタの詳細</UI-TERM>** でクラスタ名をクリックして、クラスタ **<UI-TERM key="ocp-v2.Detail.Realtime.RealTimeDiagnosis">リアルタイム診断</UI-TERM>** ページに移動します。

2. システムはデフォルトで **<UI-TERM key="ocp-v2.SQLDiagnosis.Digest.SqlDiagnosis">SQL 診断</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.Overview.SuspiciousSql">不審なSQL</UI-TERM>**、**TopSQL**、**SlowSQL**、**ParallelSQL**、**<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.HighRiskSql">高リスクSQL</UI-TERM>**、および **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.AddSql">SQLを追加</UI-TERM>** タブで対象のSQLを見つけます。

   クエリ条件を設定することで、対象SQLの特定を支援できます。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-1.png)

4. 対象SQLのテキストをクリックして、対象SQLの詳細ページに移動します。

   ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/OAS/%E6%9F%A5%E7%9C%8BSQL%E8%AF%A6%E6%83%85-2.png)

   **<UI-TERM key="ocp-v2.ParallelSQL.TraceDetail.SqlDetails">SQLの詳細</UI-TERM>** ページでは、以下の情報を含むSQLの詳細を確認できます：

   * **<UI-TERM key="ocp-v2.Trace.TraceDetailDrawer.SqlText">SQLテキスト</UI-TERM>** で、SQLの完全なステートメントを確認できます。OCPはSQLテキストを可能な限り匿名化して表示しますが、解析失敗の場合は元のSQLを返します。テーブル構造の表示を選択すると、そのテーブルの作成ステートメントが表示されます。

   * **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTunning.OptimizationSuggestions">最適化の提案</UI-TERM>** で、そのSQLに対する最適化提案を確認できます。詳細については、**最適化提案の表示** を参照してください。

   * **<UI-TERM key="ocp-v2.Component.SQLDetail.ParallelSQLTraceTable.SqlExecutionProfiling">SQL実行イメージ</UI-TERM>** で、SQL実行の詳細を確認できます。詳細については、**SQL実行プロファイルの表示** を参照してください。

   * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.HistoricalTrends">歴史的傾向</UI-TERM>** タブで、そのSQLの実行履歴の傾向を確認できます。詳細については、**SQL実行の履歴傾向の表示** を参照してください。

   * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">実行計画</UI-TERM>**タブで、そのSQLの実行計画を確認するか、実行計画を紐づけます。詳細については、**SQLの実行計画の表示**を参照してください。

   * **<UI-TERM key="ocp-v2.Capacity.Resource.Top.Index">インデックス</UI-TERM>**タブで、そのSQLが紐づけられているインデックスを確認します。詳細については、**インデックスの表示と紐づけ**を参照してください。

   * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.SqlThrottling">SQL スロットリング</UI-TERM>**タブで、そのSQLのスロットリング状況を確認するか、スロットリングを設定します。詳細については、**SQLスロットリングの設定**を参照してください。

   * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ExecutionPlan">実行計画</UI-TERM>**、**<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.Index">インデックス</UI-TERM>**、**<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.SqlThrottling">SQL スロットリング</UI-TERM>**の各タブで、**<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.ViewBindingRecordsInThe">過去30日間のバインド記録を確認</UI-TERM>**から、そのSQLの紐づけ記録を確認できます。

     紐づけ記録では、既に紐づけられた計画の状態を確認できます。**<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.Unbind">バインドを解除する</UI-TERM>**ボタンをクリックすると、SQLとその計画の紐づけを解除できます。また、**<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetailTabs.BindPlan">バインディング計画</UI-TERM>**ボタンをクリックすると、再度紐づけできます。

## 最適化提案の表示

SQLの実行計画に変更があり、パフォーマンスが低下した場合、システムは計画の紐づけに関する提案を提供します。SQLのインデックスが最適でなく、かつ以下の条件を満たす場合、システムはインデックスの最適化に関する提案を提供します：

* SQLの平均応答時間が20msを超えるか、平均CPU時間が10msを超える場合。
* SQLのタイプがSELECT、SELECT_FOR_UPDATE、UPDATE、DELETEのいずれかである場合。
* SQLに複雑な述語「OR」が含まれない場合。
* SQLにJOINが含まれない場合。

**<UI-TERM key="ocp-v2.Detail.Optimize.OptimizationSuggestions">最適化の提案</UI-TERM>**で、そのSQLの診断された問題と推奨される解決策（インデックスの推奨、履歴計画の推奨など）を確認できます。また、Plan Hashの表示、実行計画の紐づけ、診断の詳細を表示する操作も行えます。

* インデックスの推奨は、以下のアルゴリズムに基づいて行われます：

  * 等値検索の列を先頭に配置し、任意の順序で組み合わせます。

  * 範囲検索がある場合、選択性が最も高い範囲検索の列を等値検索の列の後に配置します。

  * 範囲検索がない場合、ソート条件の除去が可能な場合は、ソート列を等値検索の後に配置します。

  * 述語内の他の列をインデックスの後ろに配置すると、半幅インデックスとなります。

  * Select内の他の列をインデックスの後ろに配置すると、カバーインデックスが構築されます。

  * カバーインデックスが8列を超えない場合は、カバーインデックスを推奨します。超える場合は、半幅インデックスを推奨します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>テーブル結合のシナリオは現在サポートされていません。</p>
  </main>

  設定パラメータは以下のとおりです：

  * `ocp.perf.sql.index-advisor-cpu-time-threshold`：インデックスを推奨する際のSQLの平均CPU時間のしきい値です。SQLの平均CPU時間がこの値を超える場合、インデックスを推奨します。

  * `ocp.perf.sql.index-advisor-elapsed-time-threshold`：インデックスを推奨する際のSQLの平均応答時間のしきい値です。SQLの平均応答時間がこの値を超える場合、インデックスを推奨します。

* 履歴計画の推奨は、SQLの直近1週間の実行計画を分析し、特定の計画の平均CPU時間が同種類の最新計画の平均CPU時間の80%を下回った場合に行われます。ローカル計画を優先的に推奨し、ローカル計画が存在しない場合は分散計画を推奨します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>診断の詳細は、疑わしいSQLのみ表示できます。</p>
  </main>
