# プライマリ/スタンバイテナントのディザスタリカバリ切り替え

プライマリテナントが利用不能になった場合、OCPはディザスタリカバリ切り替えを通じてスタンバイテナントをプライマリテナントに切り替えることをサポートします。ディザスタリカバリ切り替え完了後、元のスタンバイテナントは読み書き可能な独立したプライマリテナントとなり、元のプライマリテナントとの関連性はなくなります。

このページでは、プライマリ/スタンバイテナントのディザスタリカバリ切り替えの詳細な操作手順について説明します。異なるビジネスニーズに応じて、以下の方法でプライマリ/スタンバイテナントのディザスタリカバリ切り替えを実行できます。

* 方法1：指定されたプライマリ/スタンバイテナントのディザスタリカバリ切り替えを行います。
* 方法2：クラスタ内のすべてのプライマリ/スタンバイテナントのディザスタリカバリ切り替えを行います。

## 方法1：指定されたプライマリ/スタンバイテナントのディザスタリカバリ切り替え

この方法は、指定されたスタンバイテナントをプライマリテナントに切り替えるシナリオに適用されます。

### 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* 現在のテナントがスタンバイテナントであり、かつそのスタンバイテナントが **<UI-TERM key="ocp-v2.src.constant.compute.NormalOperation">正常に稼働</UI-TERM>** 状態にあること。

* 現在のテナントが属するプライマリテナントが利用不能であること。

### 注意事項

* ディザスタリカバリ切り替え時、元のプライマリテナントに複数のスタンバイテナントが存在する場合：

  * 新しいプライマリテナントとして、整合性ポイントが最も新しいスタンバイテナントを選択することを推奨します。切り替えが成功すると、元のプライマリテナントは自動的にスタンバイテナントに変更されます。
  * ビジネスの接続性と分離性を保証するため、新しいプライマリテナントのサービス名を変更することを推奨します。

* 切り替え後、新しいプライマリテナントとスタンバイテナント間の保護モードはデフォルトで最大パフォーマンスモードに変更されます。

### 手順

1. OceanBaseクラウドプラットフォームにログインし、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.component.MonitorSearch.Tenant">テナント</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.page.Tenant.TenantList">テナント一覧</UI-TERM>** からスタンバイテナントに移動します。

2. 右上のメニューバーの「その他」アイコンをクリックし、**<UI-TERM key="ocp-v2.Detail.Component.FailoverStandbyTenantModal.DisasterRecoverySwitchover">フェイルオーバー</UI-TERM>** を選択します。

3. ダイアログボックスでテナント切り替えの情報を確認し、右下の **<UI-TERM key="ocp-v2.MultiCluster.Detail.FailoverModal.DisasterRecoverySwitch">フェイルオーバー</UI-TERM>** をクリックします。

   * プライマリテナントに複数のスタンバイテナントが存在する場合、新しいプライマリテナントのドロップダウンリストから切り替えるスタンバイテナントを指定する必要があります。OCPのマルチクラスタモードが有効な場合、ドロップダウンリストにはリモートOCPクラスタが管理するスタンバイテナントも含まれます。新しいプライマリテナントのサービス名の後ろにある編集アイコンをクリックすると、新しいプライマリテナントに新しいサービス名を設定できます。
   * システムはテナントの事前チェックを行い、タスクを送信します。事前チェックに失敗した場合やタスク送信に失敗した場合は、ダイアログボックス内の失敗原因を確認して調査してください。

4. タスク送信が成功した後、ダイアログボックス内のタスクIDをクリックしてタスクの進捗状況を確認します。

## 方法2：クラスタ内のすべてのプライマリ/スタンバイテナントのディザスタリカバリ切り替え

この方法は、クラスタ内のすべてのスタンバイテナントをプライマリテナントに切り替えるシナリオに適用されます。

### 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* 現在のクラスタで既に[スタンバイテナントの作成](../../700.tenant-functions/600.manage-a-tenant/150.create-a-standby-tenant.md)が完了していること。

### 注意事項

ディザスタリカバリ切り替えは、テナントのプライマリ/スタンバイ関係を切断し、指定したテナントを強制的に読み書き可能なテナントに変換します。この状態は元に戻せませんので、慎重に操作してください。

### 手順

1. OceanBaseクラウドプラットフォームにログインし、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.component.ParameterTemplate.Cluster">クラスタ</UI-TERM>** をクリックします。**<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** から、スタンバイテナントが存在するクラスタの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動します。

2. 右上のメニューアイコンをクリックし、**<UI-TERM key="ocp-v2.Detail.Overview.TenantDisasterRecoverySwitchover">テナントのフェイルオーバー</UI-TERM>** を選択します。

3. ダイアログボックスで切り替えるテナントを選択し、**<UI-TERM key="ocp-v2.MultiCluster.Detail.DisasterRecoverySwitch">フェイルオーバー</UI-TERM>** をクリックします。

   * ディザスタリカバリ切り替えを実行する前に、システムはプライマリ/スタンバイテナントが以下の条件を満たしているかどうかをチェックします。チェックに失敗した場合、テナントを選択してディザスタリカバリ切り替えを実行することはできません：

      * プライマリ/スタンバイテナントが異なるクラスタに存在すること。
      * スタンバイテナントが正常に稼働しており、所属するプライマリテナントが利用不能であること。
      * スタンバイテナントが属するクラスタが **Running** 状態であること。

   * ディザスタリカバリ切り替え後、新しいプライマリテナントのサービス名はデフォルトで削除されます。**<UI-TERM key="ocp-v2.Detail.Overview.NewServiceName">新しいサービス名</UI-TERM>** 列の編集アイコンをクリックして、新しいプライマリテナントに新しいサービス名を設定することができます。

4. ダイアログボックスのタスクIDをクリックして、タスクの進捗状況を確認します。
