# OCPクラスタ間でのプライマリ/スタンバイテナントの作成

OCPでは、異なるクラスタ間で関連付けられたプライマリ・スタンバイテナントを作成できます。データセンターに障害が発生し、OCPクラスタのフェイルオーバーが必要な場合、スタンバイテナントをプライマリテナントへと切り替えることで、テナントレベルの物理スタンバイデータベースによる高可用性ソリューションを構築し、外部へのデータベースサービス提供を継続できます。

OCPにおいて、他のOCPクラスタによって管理されているテナントは **リモートテナント** と呼ばれます。リモートテナントが現在のOCPクラスタのページ上に表示される際には、**<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.Remote">リモート</UI-TERM>** ラベルが付加されます。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能を提供していません。</p>
</main>

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* テナントレベルのプライマリ/スタンバイデータベースの構成は、OceanBase V4.2以降のバージョンでのみサポートされます。

* プライマリテナントを作成するクラスタの状態が「実行中」であること。

* マルチクラスタモードのプライマリ・スタンバイOCPクラスタが作成済みであること。

* 現在ログインしているユーザーがシステム管理者ロール、OCPテナント管理者ロール、またはそのクラスタを管理する権限を持つ他のロールを持っていること。

* OceanBase V4.2.1.8よりも古いバージョンのスタンバイテナントを作成する場合、30日前のベースラインバックアップデータを使用して物理スタンバイデータベースを復元しないでください。これにより、物理スタンバイデータベースの機能異常が発生し、テナントのメジャーコンパクションに影響を与える可能性があります。

* プライマリテナントが存在するクラスタでSSLリンク暗号化が有効になっており、プライマリ/スタンバイ同期方式が **ネットワークベース** の場合、スタンバイテナントが存在するクラスタでもSSLリンク暗号化を有効にする必要があります。また、ルート証書はプライマリテナントが存在するクラスタと一致している必要があります。

* テナントのためにアービトレーションサービスを有効にする前に、以下の情報を確認する必要があります：

  * テナントが属するクラスタにアービトレーションサービスが追加されており、アービトレーションサービスが **RUNNING** 状態にあること。

  * アービトレーションサービスを有効にするテナントのLocalityが2F（F：フル機能レプリカ）または4Fであること。

  * アービトレーションサービスが存在するホストの残りリソースがリソース要件を満たしていること。

    このリソース要件はシステムパラメータで実際の状況に応じて変更できます。変更が必要なパラメータは以下の通りです。操作の詳細については、[システムパラメータの変更](../../700.tenant-functions/1600.manage-tenant-parameters/200.modify-a-tenant-parameter.md)を参照してください。

    * `ocp.arbitration.min.remain.disk.size`：テナントアービトレーションを有効にした場合のアービトレーションサービスホストのCLOGディスクの残り最小値。単位はMBです。データ形式 (a,b) は、テナントレプリカがそれぞれ2F、4Fの場合の値を表します。デフォルトは [12,24] です。
    * `ocp.arbitration.max.cpu.used.percentage`：テナントアービトレーションを有効にした場合のアービトレーションサービスホストの最大CPU利用率。単位は % です。デフォルト値は 90 です。
    * `ocp.arbitration.max.memory.used.percentage`：テナントアービトレーションを有効にした場合のアービトレーションサービスホストの最大メモリ利用率。単位は % です。デフォルト値は 90 です。

## 手順

以下の手順を参考に、現在のOCP内で他のOCPが管理するテナントのためのスタンバイテナントを作成します。

1. OCPにログインします。

2. 左側のナビゲーションバーの **<UI-TERM key="ocp-v2.component.MonitorSearch.Tenant">テナント</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.Backup.Overview.Statistics.Tenant">テナント</UI-TERM>** ページに移動します。

3. ページの右上隅にある **<UI-TERM key="ocp-v2.page.Tenant.NewTenant">新しいテナントを作成</UI-TERM>** をクリックします。

4. **<UI-TERM key="ocp-v2.Backup.Component.BackupNowTenantDrawer.BasicInformation">基本情報</UI-TERM>** を入力します。

7. **<UI-TERM key="ocp-v2.Cluster.New.ParameterConfiguration">パラメータ設定</UI-TERM>**モジュールを開き、テナントパラメータを設定します。

   * **<UI-TERM key="ocp-v2.Tenant.New.BasicSettings">基本設定</UI-TERM>**で負荷タイプを設定した場合、システムはその負荷タイプに対応するパラメータテンプレートをデフォルトで選択します。

   * 図①のように、起動パラメータ項目を1つずつ追加し、値を設定することができます。

   * また、図②のように、**<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">パラメータテンプレートを選択</UI-TERM>**をクリックしてパラメータテンプレートを選択することもできます。システムは、テンプレート内のパラメータと設定を自動的にここに入力します。テナントパラメータテンプレートが作成されていない場合、**新規テナントテンプレート**をクリックしてテナント用にパラメータテンプレートを作成できます。詳細については[テナントパラメータテンプレート管理](../../700.tenant-functions/1700.manage-tenant-parameter-templates.md)を参照してください。

      システムは以下の4種類の組み込みテンプレートを提供しており、テンプレートには一般的なパラメータ設定が含まれています。これらのテンプレートを直接適用してクラスタの初期設定を行うことができます。システムの組み込みテンプレートについての具体的な説明は以下の通りです。

      | テンプレート | 説明 |
      |------|-------|
      | COMPLEX_OLTP デフォルトパラメータテンプレート   |  **Complex OLTP** ロードタイプに対応します。このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。   |
      | HTAP デフォルトパラメータテンプレート   |   **HTAP** ロードタイプに対応します。このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。 |
      | OLAP デフォルトパラメータテンプレート   |   **OLAP** ロードタイプに対応します。このテンプレートはOceanBase V4.3.0以降のバージョンでのみ適用されます。   |
      | EXPRESS_OLTP デフォルトパラメータテンプレート   |  **Express OLTP** ロードタイプに対応します。このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。   |
