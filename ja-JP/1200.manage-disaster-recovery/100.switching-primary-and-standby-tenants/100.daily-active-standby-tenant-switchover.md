# プライマリ/スタンバイテナントの日常的な切り替え

このページでは、プライマリ/スタンバイテナントの日常的な切り替えの操作手順について説明します。業務ニーズに応じて、以下の方法でプライマリ/スタンバイテナントを日常的に切り替えることができます。

* 方法1：指定したプライマリ/スタンバイテナントを日常的に切り替えます。
* 方法2：クラスタ内のすべてのプライマリ/スタンバイテナントを日常的に切り替えます。

## 方法1：指定したプライマリ/スタンバイテナントを日常的に切り替える

この方法は、指定したプライマリテナントをスタンバイテナントに切り替えるシナリオに適用されます。

### 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* 現在のプライマリテナントに利用可能なスタンバイテナントが存在し、かつそのスタンバイテナントが **<UI-TERM key="ocp-v2.src.constant.tenant.NormalOperation">正常に稼働</UI-TERM>** 状態にあること。

### 注意事項

* プライマリ/スタンバイテナントには同じサービス名を設定し、両テナントが属するOceanBaseクラスタが同じOBProxyクラスタに関連付けられていることを推奨します。そうでない場合、プライマリ切り替え後に自動ルーティングが実現できません。
* 元のプライマリテナントがBinlog ServiceのMetaDB情報を保持している場合、プライマリ/スタンバイテナントの切り替えによりBinlogサービスが利用不可になるため、慎重に操作してください。
* プライマリ/スタンバイテナントの日常的な切り替えを実行すると、プライマリ/スタンバイ保護モードが変更される可能性があります：
  * 一主一備モードでは、切り替え後のプライマリ/スタンバイ保護モードは影響を受けません。
  * 一主多備モードでは、新しいプライマリテナントの元のプライマリ/スタンバイ保護モードが最大保護の場合、プライマリ/スタンバイテナント切り替え後、システムはその保護モードを自動的に継続します。元が他のモードの場合、すべてのプライマリ/スタンバイテナントの保護モードを最大パフォーマンスに統一して切り替えます。

### 手順

1. OceanBaseクラウドプラットフォームにログインし、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.src.constant.alarm.Tenant">テナント</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.component.TenantList.TenantList">テナント一覧</UI-TERM>** からプライマリテナントに移動します。

2. 右上のメニューバーのアイコンをクリックし、**<UI-TERM key="ocp-v2.Detail.Component.SwitchoverModal.DailySwitchover">日常の切り替え</UI-TERM>** を選択します。

3. ダイアログボックスでテナント切り替えの情報を確認し、**<UI-TERM key="ocp-v2.Instance.Overview.Switch">切り替え</UI-TERM>** をクリックします。

    * プライマリテナントに複数のスタンバイテナントが存在する場合、**<UI-TERM key="ocp-v2.Component.ChangeTenantView.NewMasterTenant">新しいプライマリテナント</UI-TERM>** のドロップダウンリストから切り替えるスタンバイテナントを指定する必要があります。OCPのマルチクラスタモードが有効な場合、ドロップダウンリストにはリモートOCPクラスタで管理されているスタンバイテナントも含まれます。
    * 選択したスタンバイテナントの同期方式が **<UI-TERM key="ocp-v2.src.constant.tenant.ArchiveBased">アーカイブに基づく</UI-TERM>** であり、かつそのスタンバイテナントでアーカイブが有効になっていない場合、まずアーカイブアドレスを設定する必要があります。具体的なパラメータの説明は以下のとおりです：

      |  パラメータ  |  説明   |
      |--------|---------|
      | ストレージタイプ  | バックアップファイルの保存媒体。値の範囲：<ul><li>File：ローカルファイルストレージ、通常はNFS。</li><li>OSS：Alibaba Cloud OSSオブジェクトストレージ、OceanBase V2.2.76以降のバージョンでのみサポート。</li></ul>|
      | ストレージディレクトリ        | バックアップファイルが現在の媒体に保存されるディレクトリ。<main id="notice" type='explain'><h4>説明</h4><p>プライマリテナントとスタンバイテナントは、このディレクトリに対する読み書き権限が必要です。</p></main>  |
      | アクセスドメイン名        | **<UI-TERM key="ocp-v2.Backup.Service.Detail.StorageType">ストレージタイプ</UI-TERM>** でOSSを選択した場合に表示されます。バックアップファイルのクラウドストレージ側のドメイン名を入力してください。ドメイン名の後にポート番号を追加することもできます。例：`oss.ap-shanghai.myqcloud.com:8080`。 |
      | アクセスユーザー        | **<UI-TERM key="ocp-v2.src.component.ArchiveForm.StorageType">ストレージタイプ</UI-TERM>** でOSSを選択した場合に表示されます。Alibaba Cloudストレージ側のAccessKey IDを入力してください。 |
      | アクセスシークレットキー        | **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.StorageType">ストレージタイプ</UI-TERM>** でOSSを選択した場合に表示されます。Alibaba Cloudストレージ側のAccessKey Secretを入力してください。    |

4. ダイアログボックス内のタスクIDをクリックして、タスクの進捗状況を確認します。

## 方法2：クラスタ内のすべてのプライマリ/スタンバイテナントを日常的に切り替える

この方法は、クラスタの運用保守操作を実施する前に、事業継続性を保証するためにスタンバイテナントでビジネスをサポートする必要があるシナリオに適用されます。この方法を参考に、クラスタ内のすべてのプライマリテナントをスタンバイテナントに切り替えることができます。

### 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナント **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* 現在のクラスタ内にプライマリテナントが作成されており、そのプライマリテナントに利用可能なスタンバイテナントが存在すること。

* プライマリ/スタンバイテナントが属するOceanBaseクラスタが同じOBProxyクラスタに関連付けられていること。関連付けられていない場合、プライマリ切り替え後に自動ルーティングが実現できません。

### 注意事項

* プライマリ/スタンバイテナントに同じサービス名を設定することを推奨します。設定しない場合、プライマリ切り替え後に自動ルーティングが実現できません。
* プライマリ/スタンバイテナントの日常的な切り替えは、以下の影響が生じる可能性があります。事業継続性を保証するため、慎重に操作してください：
  * もともとのプライマリテナントがBinlog ServiceのMetaDB情報を格納していた場合、プライマリ/スタンバイテナントの切り替えによりBinlogサービスが利用不可になります。
  * 新しいプライマリテナントが属するクラスタのビジネス負荷が過大になる可能性があります。新しいプライマリクラスタのリソース消費状況を適切に評価し、クラスタの運用保守操作を実施する前に実行することを推奨します。
* テナントの日常的な切り替えは通常、クラスタの運用保守操作を実施する前に実行されます。新しいプライマリクラスタのリソース消費状況を適切に評価し、新しいプライマリテナントが属するクラスタのビジネスピーク時の負荷が過大になるのを避けてください。事業継続性を保証するため、慎重に操作してください。

### 手順

1. OceanBaseクラウドプラットフォームにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.page.Cluster.Cluster">クラスタ</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** からクラスタ **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページに移動します。

2. 右上のメニューアイコンをクリックし、**<UI-TERM key="ocp-v2.Detail.Overview.TenantDailySwitching">テナントの日常切り替え</UI-TERM>** を選択します。

3. ダイアログボックスで切り替えるテナントを選択し、**<UI-TERM key="ocp-v2.Detail.Component.SwitchoverModal.DailySwitchover">日常の切り替え</UI-TERM>** をクリックします。

    * プライマリテナントに複数のスタンバイテナントが存在する場合、**<UI-TERM key="ocp-v2.Component.ChangeTenantView.NewMasterTenant">新しいプライマリテナント</UI-TERM>** のドロップダウンリストから、プライマリテナントに切り替えるスタンバイテナントを選択する必要があります。OCPのマルチクラスタモードが有効な場合、ドロップダウンリストにはリモートOCPクラスタで管理されているスタンバイテナントも含まれます。

      日常切り替えを実行する前に、システムはプライマリ/スタンバイテナントが以下の条件を満たしているかどうかをチェックします。チェックに失敗した場合、テナントを選択して日常切り替えを行うことはできません：

      * プライマリ/スタンバイテナントはどちらも **<UI-TERM key="ocp-v2.src.constant.tenant.NormalOperation">正常に稼働</UI-TERM>** 状態にあること。
      * プライマリ/スタンバイテナントが属するクラスタが **Running** 状態であり、かつクラスタのバージョンが一致していること。
      * スタンバイテナントの同期遅延がしきい値を超えていないこと。しきい値はデフォルトで5000msです。**<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">システム管理</UI-TERM>** > **<UI-TERM key="ocp-v2.src.util.menu.SystemParameters">システムパラメータ</UI-TERM>** で `ocp.standby.tenant.delay_threshold` パラメータの値を変更することで、しきい値の大きさを調整できます。

    * 選択したスタンバイテナントの同期方式が **<UI-TERM key="ocp-v2.src.constant.tenant.ArchiveBased">アーカイブに基づく</UI-TERM>** であり、かつそのテナントでアーカイブが有効になっていない場合、まずアーカイブアドレスを設定する必要があります。具体的なパラメータの説明は以下のとおりです：

      |  パラメータ  |  説明   |
      |--------|---------|
      | ストレージタイプ  | バックアップファイルのストレージメディア。値の範囲：<ul><li>File：ローカルファイルストレージ、通常はNFS。</li><li>OSS：Alibaba Cloud OSSオブジェクトストレージ、OceanBase V2.2.76以降のバージョンでのみサポートされます。</li></ul>|
      | ストレージディレクトリ        | バックアップファイルが現在のメディアに保存されるディレクトリ。  <main id="notice" type='explain'><h4>説明</h4><p>プライマリテナントとスタンバイテナントは、このディレクトリに対する読み書き権限が必要です。</p></main>  |
      | アクセスドメイン名        | **<UI-TERM key="ocp-v2.src.component.ArchiveForm.StorageType">ストレージタイプ</UI-TERM>** で OSS を選択した場合に表示されます。バックアップファイルのクラウドストレージ側のドメイン名を入力してください。ドメイン名の後にポート番号を追加することもできます。例：`oss.ap-shanghai.myqcloud.com:8080`。 |
      | アクセスユーザー        | **<UI-TERM key="ocp-v2.Backup.Service.Detail.StorageType">ストレージタイプ</UI-TERM>** で OSS を選択した場合に表示されます。Alibaba Cloudストレージ側のAccessKey IDを入力してください。 |
      | アクセス秘密鍵        | **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.StorageType">ストレージタイプ</UI-TERM>** で OSS を選択した場合に表示されます。Alibaba Cloudストレージ側のAccessKey Secretを入力してください。    |

4.  ダイアログボックス内のタスクIDをクリックして、タスクの進捗状況を確認します。
