# マルチクラスタモードの概要

OCPはマルチクラスタモードをサポートしており、デュアルデータセンターによる高可用性の災害復旧アーキテクチャを実現し、より信頼性の高いクラスタ管理と監視サービスを提供します。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionではこの機能は提供されません。</p>
</main>

## 機能紹介

OCPのマルチクラスタモードは、OceanBaseの地理的冗長化ディザスタリカバリシナリオ向けに設計されており、リージョンをまたがるプライマリ/スタンバイデータベースの一元管理機能を提供します。このモードは、プライマリ/スタンバイデータベースの作成、分離、アップグレード、日常的な切り替え、ディザスタリカバリ演習などの重要な操作を含む完全な運用ライフサイクル管理をサポートし、事業継続性とデータの安全性を確保します。

OCPのマルチクラスタ管理機能は、主にOCPクラスタをまたがるプライマリ/スタンバイデータベースの統一的なディザスタリカバリ管理を対象としています。その中核的な役割は、プライマリ/スタンバイデータベース間のトポロジー情報のデータ同期を実現し、データセンターレベルで障害が発生した場合に迅速にディザスタリカバリ切り替えと事業復旧を行うことを保証することです。明確にすべき点は、この機能が自動的な障害引き継ぎメカニズムではないということです。プライマリOCPクラスタがダウンした場合、スタンバイOCPクラスタはプライマリOCPが管理するOceanBaseクラスタのリソースを自動的に引き継ぎません。プライマリ/スタンバイOCPアーキテクチャでは、MetaDB（メタ情報データベース）間にデータ同期のためのパイプラインが設定されておらず、両者はデータ面で独立したストレージを維持します。それらの関係は主にアプリケーション層のデータ伝送と業務ロジックによって協調されます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OceanBaseデータベースはV4.1.0以前では、プライマリ/スタンバイデータベースの形態はクラスタレベルのプライマリ/スタンバイでした。V4.1.0から、プライマリ/スタンバイデータベースの形態はテナントレベルのプライマリ/スタンバイに変更されました。つまり、プライマリまたはスタンバイの役割情報はテナントに属し、プライマリテナントとスタンバイテナントに分かれます。クラスタにはもはやプライマリ/スタンバイの概念はなく、単にテナントを格納するコンテナとなります。</p>
</main>

## マルチクラスタモードのアーキテクチャ

OCPのマルチクラスタディザスタリカバリ切り替えは、主に都市をまたがるデュアルデータセンターやトリプルデータセンターなどのシナリオで適用されます。原理は以下の通りです：

### 都市をまたがるデュアルデータセンター

都市をまたがるプライマリ/スタンバイデータベースのデプロイメントシナリオでは、OCPクラスタの都市をまたがるデュアルデータセンターデプロイメントプランを採用できます。ある都市のOCPクラスタ及びそれが管理するOceanBaseクラスタに障害が発生した場合、予備都市のOCPクラスタをプライマリクラスタに切り替え、プライマリ/スタンバイデータベースのディザスタリカバリ切り替えメカニズムを通じて、OceanBaseデータベースの運用、監視、アラート機能を引き継ぎ、データベースサービスを最短時間で可用状態に復旧します。

OCPのプライマリ/スタンバイクラスタは、それぞれ都市1と都市2にデプロイされます。都市1のOCPクラスタがプライマリクラスタ、都市2のOCPクラスタがスタンバイクラスタとなります。OCPのプライマリ/スタンバイクラスタは、それぞれ複数のOceanBaseクラスタを管理します。

ネットワーク障害により両地域間のネットワーク接続が切断された場合、ディザスタリカバリ切り替えにより、都市2のスタンバイOCPクラスタをプライマリクラスタに切り替えることができます。この時、都市1の元プライマリOCPクラスタは独立した廃棄クラスタとなります。この廃棄クラスタの削除と都市1の新しいプライマリクラスタの再構築を推奨します。都市2のプライマリOCPクラスタはOceanBaseデータベースの運用と監視を正常に行い、自身が管理しないプライマリデータベースのスタンバイデータベースについては、ディザスタリカバリ切り替えまたは移出を行います。詳細については [ディザスタリカバリ切り替え OCPクラスタ](600.switch-an-ocp-cluster-in-a-failover.md) を参照してください。

V4.1.0以前のバージョンのOceanBaseクラスタについては、業務は関連付けられたOBProxyを介してOceanBaseクラスタにアクセスします。OCPクラスタをまたがるOceanBaseのプライマリ/スタンバイクラスタでは、各OceanBaseクラスタに1つのOBProxyが紐づけられます。OBProxyが業務クラスタのスタンバイデータベースに紐づけられている場合、その業務クラスタのスタンバイデータベースにアクセスできます。OCPのプライマリ/スタンバイクラスタでネットワーク障害が発生した場合、業務はOceanBaseのスタンバイクラスタに紐づけられたOBProxyを介して、引き続きOceanBaseクラスタにアクセスできます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OBProxyがOceanBaseのスタンバイクラスタにのみ紐づけられている場合、proxy経由でアクセスする際には、ユーザー名にスタンバイクラスタIDを追加する必要があります。例：<code>mysql -h xxx.xxx.xxx.xxx -P 2881 -u&lt;ユーザー名&gt;@&lt;テナント名#クラスタ名&gt;:1000 -p ****</code>。OCP上のクラスタ接続文字列にもクラスタIDが表示されます。IDを除去すると、その業務クラスタのスタンバイデータベースに接続できません。</p>
</main>

ネットワークが回復した後、2つのプライマリクラスタは依然として独立したOCPクラスタとして稼働します。そのうちの1つのプライマリクラスタをスタンバイクラスタに設定し、OCPクラスタの登録によって2つのクラスタを紐づけることができます。詳細については [OCPクラスタの登録](200.register-an-ocp-cluster.md) を参照してください。

![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/4137375261/p292705.png)

### 都市をまたがるトリプルデータセンター

都市をまたがるトリプルデータセンターを例にすると、都市1と都市2にそれぞれOCPクラスタをデプロイします。都市1に1つのOCPクラスタをプライマリクラスタとして、都市2に2つのOCPクラスタをスタンバイクラスタとしてデプロイします。OCPのプライマリ/スタンバイクラスタは、それぞれ複数のOceanBaseクラスタを管理します。

ネットワーク障害により二つの地域間の接続が切断された場合、災害復旧切り替えを通じて、いずれかのスタンバイOCPクラスタをプライマリクラスタに切り替えることができます。この時点で、都市1には1つのOCPプライマリクラスタが、都市2には1つのOCPプライマリクラスタと1つのOCPスタンバイクラスタが存在します。

各OCPプライマリクラスタは、引き続き自身が管理するOceanBaseデータベースの運用監視を行います。もしスタンバイデータベースに対応するプライマリデータベースが現在のOCPプライマリクラスタにない場合、そのスタンバイデータベースのデータをクリーンアップする必要があります。詳細については、[災害復旧切り替えOCPクラスタ](600.switch-an-ocp-cluster-in-a-failover.md)を参照してください。

V4.1.0以前のバージョンのOceanBaseクラスタでは、業務はOBProxyの関連付けを通じてOceanBaseクラスタにアクセスします。OCPクラスタを跨ぐOceanBaseのプライマリ/スタンバイクラスタでは、各OceanBaseクラスタに1つのOBProxyが紐づけられます。OBProxyが業務クラスタのスタンバイデータベースに紐づけられている場合、その業務クラスタのスタンバイデータベースにアクセスできます。OCPのプライマリ/スタンバイクラスタでネットワーク障害が発生した場合、業務はOceanBaseスタンバイクラスタに紐づけられたOBProxyを通じて、引き続きOceanBaseクラスタにアクセスできます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OBProxyがOceanBaseスタンバイクラスタにのみ紐づけられている場合、proxy経由でアクセスする際には、ユーザー名にスタンバイクラスタIDを追加する必要があります。例：<code>mysql -h xxx.xxx.xxx.xxx -P 2881 -u<ユーザー名>@<テナント名#クラスタ名>:1000 -p ****</code>。OCP上のクラスタ接続文字列にもクラスタIDが表示されます。IDを削除すると、その業務クラスタのスタンバイデータベースに接続できません。</p>
</main>

ネットワークが回復すると、都市1のOCPクラスタリストに都市2のスタンバイデータベースが表示されますが、この時点でそのスタンバイデータベースのプライマリデータベースは都市2のプライマリデータベースです。紐づけを解除することでスタンバイデータベースを削除できます。詳細については、[OCPクラスタの削除](700.delete-an-ocp-cluster.md)を参照してください。

元のプライマリデータベースを再びOCPクラスタに接続する必要がある場合、元のプライマリデータベース内のデータを削除する必要があります。
