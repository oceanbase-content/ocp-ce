# OCPマルチクラスタモードの切り替え

このセクションでは、標準モードのOCPをマルチクラスタモードのプライマリ/スタンバイクラスタに変換する方法について説明します。

<main id="notice" type='notice'>
<h4>適用対象</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能を提供していません。</p>
</main>

## 前提条件

* 現在OCPにログインしているユーザーが **ADMIN** ロールであることを確認してください。
* V3.1.1以降のバージョンのOCPクラスタがインストール済みであること。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OCPが管理するOceanBaseクラスタには、同名のOceanBaseクラスタが存在してはなりません。存在する場合、スタンバイOCPクラスタはプライマリOCPクラスタに正常に登録できません。</p>
  </main>

## 手順

1. `docker exec -it ocp bash` コマンドを実行して、OCPコンテナに入ります。

2. `env | grep -i metadb` コマンドを実行して、以下の環境変数が設定されているか確認します。

   ```SQL
   OCP_METADB_HOST
   OCP_METADB_PORT
   OCP_METADB_USER
   OCP_METADB_PASSWORD
   OCP_METADB_DBNAME
   ```

   設定されていない場合は、以下のコマンドを実行してMetaDBの環境変数を設定してください。

   ```SQL
   #以下の変数値はすべて例です。実際の状況に応じて設定してください。
   export OCP_METADB_HOST="xxx.xxx.xxx.xxx"
   export OCP_METADB_PORT="2881"
   export OCP_METADB_USER="ocp@ocp_meta"
   export OCP_METADB_PASSWORD="******"
   export OCP_METADB_DBNAME="meta_01"
   ```

3. `cd /home/admin/ocp-server/bin` コマンドを実行して、`ocp-bootstrap` スクリプトがあるディレクトリに移動します。

4. `./ocp-bootstrap -i` を実行して、対話モードに入ります。

5. 実際のシナリオに応じて、以下のコマンドのいずれかを選択して実行し、OCPを変換します。

   * 対象OCPで `enableMc <OCP_CLUSTER_ID> <OCP_CLUSTER_NAME> <OCP_CLUSTER_ROLE>` を実行し、対象OCPをプライマリOCPクラスタに変換します。

     ```shell
     ocp-bootstrap> enableMc 1 ocp1 LEADER
     ```

   * ターゲットOCPで実行し、ターゲットOCPをスタンバイOCPクラスタに変換します。

     ```shell
     ocp-bootstrap> enableMc 2 ocp2 FOLLOWER
     ```

   * フェイルオーバー後、元のプライマリOCPで以下のコマンドを実行し、新しいプライマリOCPに登録できる状態に戻します。

     ```shell
     ocp-bootstrap> unregisterMc
     ```

6. OCPホスト上で `docker restart ocp` コマンドを実行してOCPを再起動します。

   このOCPクラスタに複数のOCPインスタンスがデプロイされている場合は、すべて再起動する必要があります。
