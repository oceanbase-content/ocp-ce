# パーティションガードタスクが管理するテーブル

パーティションガードは、OCPがocp_monitorテナントのパーティションテーブルに対して事前にパーティションを作成するタスクです。パーティションの作成に失敗すると、監視データの書き込みに影響を及ぼす可能性があるため、潜在的な問題をユーザーに警告するアラートが発生します。
このセクションでは、MonitorDB内でパーティションガードタスクによって管理されるテーブルや、タスクがこれらのテーブルに対してパーティションを作成するルールなどの情報を紹介します。

## 使用例

以下では、metric_daily_dataパーティションを例に説明します。

```sql
> show create table metric_daily_data\G
*************************** 1. row ***************************
       Table: metric_daily_data
Create Table: CREATE TABLE `metric_daily_data` (
  `series_id` bigint(20) NOT NULL COMMENT '指標系列ID',
  `timestamp` bigint(20) NOT NULL COMMENT 'タイムスタンプ、単位(秒)',
  `value` double NOT NULL COMMENT '値',
  PRIMARY KEY (`series_id`, `timestamp`)
) DEFAULT CHARSET = utf8mb4 COMMENT = '監視daily指標データ'
 partition by range columns(`timestamp`)
(partition DUMMY values less than (0),
partition p2019 values less than (1577836800),
partition p2020 values less than (1609459200),
partition p2021 values less than (1640995200),
partition p2022 values less than (1672531200),
partition p2023 values less than (1704067200));
```

metric_daily_dataパーティションの命名規則はp+年です。パーティションの保持期間は3年、事前作成期間は1年で、パーティションのタイムスタンプはUTC時刻です。上記の例では：

* p2019は、`timestamp`が1577836800未満のデータを1つのパーティションとして設定し、p2019と命名します。

* p2019、p2020、p2021は履歴データを保持するパーティションです。

* p2022は現在時刻のパーティションです。

* p2023は事前作成されたパーティションです。
