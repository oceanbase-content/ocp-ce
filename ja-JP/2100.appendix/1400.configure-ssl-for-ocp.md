# OCPのSSL設定

HTTPSを使用してOCPにアクセスする必要がある場合は、このセクションを参照してOCPにSSL証明書を設定してください。

## 前提条件

OCPのSSLを設定する前に、以下の証明書ファイルを準備し、PKCS12形式のkeystoreファイルにインポートする必要があります。

| ファイル | 説明 | 拡張子の例 |
|------|------|---------|
| サーバー証明書 | CA機関が発行したSSL証明書。ドメイン名またはIPアドレスはSANに含まれている必要があります | `.cer`、`.crt`、`.pem` |
| サーバー秘密鍵 | サーバー証明書に対応する秘密鍵 | `.key`、`.pem` |
| CAルート証明書 | CA機関のルート証明書または中間証明書。証明書チェーンを補完するために使用されます | `.cer`、`.crt`、`.pem` |

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OCPはPKCS12形式のkeystoreからSSL証明書を読み込みます。keystoreにはサーバー秘密鍵、サーバー証明書、CAルート証明書のすべてが含まれていなければなりません。いずれか一つでも欠けてはなりません。証明書ファイルのみで秘密鍵がない場合、SSL通信には使用できません。</p>
</main>

### 公開CA証明書を保有している場合

権威あるCA機関から証明書を取得済みの場合は、サーバー証明書が完全で有効期限が切れていないことを確認してください：

```bash
# 証明書の詳細を確認する（例：ocp.cer）
openssl x509 -in ocp.cer -text -noout

# 以下のフィールドを重点的に確認します：
# - Not After: 証明書の有効期限
# - Subject Alternative Name (SAN): OCPのアクセスドメイン名またはIPアドレスが含まれているかどうか
```

証明書に誤りがないことを確認したら、`openssl` を使用して秘密鍵、サーバー証明書、CAルート証明書をPKCS12形式のkeystoreにパッケージ化します：

```bash
openssl pkcs12 -export \
    -in ocp.cer \
    -inkey ocp.key \
    -certfile ca.cer \
    -name ocp \
    -out ocp.keystore \
    -passout pass:<your_keystore_password>
```

| 項目 | 説明 |
|------|------|
| `ocp.cer` | サーバー証明書ファイル。 |
| `ocp.key` | サーバー秘密鍵ファイル。 |
| `ca.cer` | CAルート証明書ファイル。複数の中間証明書がある場合、`-certfile` を使用して完全な証明書チェーンを含むファイルを指定できます。 |
| `ocp` | keystore内のキー項目のaliasで、後続のOCP設定における `server.ssl.key-alias` と一致させる必要があります。 |
| `<your_keystore_password>` | keystoreのパスワードです。カスタムパスワードに置き換えてください。 |

<main id="notice" type='explain'>
<h4>説明</h4>
<p><code>keytool -import</code> コマンドは証明書を信頼済み項目としてのみインポートし、秘密鍵はインポートしません。そのため、SSLに必要なkeystoreを作成するためには <b>使用できません</b>。秘密鍵と証明書を一緒にインポートするには、<code>openssl pkcs12 -export</code> または <code>keytool -importkeystore</code> などの方法を使用する必要があります。</p>
</main>

### 公開CA証明書がない場合

公開CA証明書がない場合（例：社内ネットワーク環境）、自己署名証明書を生成できます。詳細については、[付録：自己署名証明書の生成](#付録：自己署名証明書の生成)を参照してください。

## OCPへのSSL設定の読み込み

証明書を含むkeystoreを用意した後、OCPにロードする必要があります。前提条件は以下のとおりです：

* keystoreファイル名は`ocp.keystore`です。
* keystoreはOCPコンテナ内の`/home/admin/data/keystore`ディレクトリにマウントされています。
* keystoreのタイプはPKCS12です。
* keyのaliasは`ocp`です。
* keystoreのパスワードは`store_pswd`です。
* keyのパスワードは`key_pswd`です（個別に設定がない場合は空で、<code>openssl pkcs12 -export</code>で作成されたkeystoreのデフォルトkeyパスワードはkeystoreのパスワードと同じです）。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>コンテナでデプロイされたOCPが再起動すると、コンテナ内部のファイルはイメージの初期状態に戻ります。keystoreファイルを直接コンテナ内部にコピーしないでください。そうしないと、OCPが再起動すると証明書ファイルが失われます。ホスト上のkeystoreディレクトリをDockerボリュームマウントによってコンテナ内にマッピングし、証明書ファイルがコンテナ再起動後も存在することを確保する必要があります。</p>
</main>

OCPが使用するMetaDBで以下のSQLを実行し、SSL関連の設定を行います：

```sql
UPDATE `config_properties` SET `value`='8443' WHERE `key`='server.port';
UPDATE `config_properties` SET `value`='true' WHERE `key`='server.ssl.enabled';
UPDATE `config_properties` SET `value`='ocp' WHERE `key`='server.ssl.key-alias';
UPDATE `config_properties` SET `value`='key_pswd' WHERE `key`='server.ssl.key-password';
UPDATE `config_properties` SET `value`='/home/admin/data/keystore/ocp.keystore' WHERE `key`='server.ssl.key-store';
UPDATE `config_properties` SET `value`='store_pswd' WHERE `key`='server.ssl.key-store-password';
UPDATE `config_properties` SET `value`='PKCS12' WHERE `key`='server.ssl.key-store-type';

UPDATE `config_properties` SET `value`='https://<OCPアクセスアドレス>:8443' WHERE `key`='ocp.site.url';
```

DockerでOCPを実行する際には、コンテナ起動パラメータにkeystoreをマウントするパラメータを追加する必要があります。例えば、keystoreがあるホストディレクトリが`/data/ocp/keystore`の場合、OCPコンテナを起動する際に以下のパラメータを追加します：

```bash
-v /data/ocp/keystore:/home/admin/data/keystore
```

OCPを再起動すると、OCPはHTTPSプロトコルを使用して8443ポートでリスニングを開始します。

## 付録：自己署名証明書の生成

パブリックCA証明書がない場合は、`keytool`を使用して自己署名証明書を生成できます。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>自己署名証明書には、すべてのOCPインスタンスのIPアドレスとドメイン名をSAN拡張に含める必要があります。そうでない場合、複数ノード間の相互アクセスは失敗します。クライアントはルート証明書を信頼リストに追加してからサービスにアクセスできます。</p>
</main>

### 自己署名証明書の生成

以下のスクリプトを使用して、自己署名証明書とルート証明書を生成できます。実行前に、ドメイン名やIPアドレスなどの設定情報を実際の状況に応じて修正してください。

```bash
#!/bin/bash
set -euo pipefail

# ===================== 設定エリア =====================
domain="ocp.oceanbase.com"
ips="30.142.17.125"
root_password='root4321'
ocp_password="Oceanbase4321"
validity_days=3650
# ==================================================

# keytoolが利用可能か確認する
if ! command -v keytool &> /dev/null; then
    echo "keytoolが見つかりません。JDKをインストールし、JAVA_HOMEが正しく設定されていることを確認してください。"
    exit 1
fi

echo "keytoolのバージョン: $(which keytool)"
echo "Domain: ${domain}"
echo "IPs:    ${ips}"

# DNとSANの構築
dname="CN=${domain}"
san="SAN=DNS:${domain}"
for ip in ${ips}; do
    san="${san},IP:${ip}"
done

# ---------- 1. ルートCA証明書の生成 ----------
echo ">>> [1/8] ルートCA証明書の生成..."
keytool -genkeypair \
    -keyalg RSA -keysize 4096 \
    -dname "CN=OCP Root CA" \
    -alias root \
    -keystore root.keystore \
    -storetype PKCS12 \
    -storepass "${root_password}" \
    -ext BasicConstraints=CA:TRUE \
    -ext KeyUsage=keyCertSign,cRLSign

# ---------- 2. OCP Serverのキーペアを生成します ----------
echo ">>> [2/8] OCP TLSキーペアを生成します..."
keytool -genkeypair \
    -keyalg RSA -keysize 4096 \
    -validity ${validity_days} \
    -dname "${dname}" \
    -alias ocp \
    -keystore ocp.keystore \
    -storetype PKCS12 \
    -storepass "${ocp_password}" \
    -ext "${san}"

# ---------- 3. 証明書署名要求(CSR)を作成します ----------
echo ">>> [3/8] CSRを作成します..."
keytool -certreq \
    -file server.csr \
    -alias ocp \
    -keystore ocp.keystore \
    -storepass "${ocp_password}" \
    -ext "${san}"

# ---------- 4. ルートCAでサーバー証明書を発行します ----------
echo ">>> [4/8] ルートCAがサーバー証明書を発行します..."
keytool -gencert \
    -infile server.csr \
    -outfile server.cer \
    -alias root \
    -keystore root.keystore \
    -storepass "${root_password}" \
    -ext "${san}" \
    -rfc

# ---------- 5. ルート証明書(DER)をエクスポートします ----------
echo ">>> [5/8] ルート証明書をエクスポートします..."
keytool -exportcert \
    -file root.cer \
    -alias root \
    -keystore root.keystore \
    -storepass "${root_password}"

# ---------- 6. ルート証明書をOCP keystoreにインポートします ----------
# まずルート証明書をインポートする必要があります。その後、サーバー証明書をインポートする際に証明書チェーンを検証できるようになります。
echo ">>> [6/8] ルート証明書をOCP keystoreにインポートします..."
keytool -importcert \
    -file root.cer \
    -alias root \
    -keystore ocp.keystore \
    -storepass "${ocp_password}" \
    -noprompt

# ---------- 7. 発行されたサーバー証明書をOCP keystoreにインポートします ----------
echo ">>> [7/8] 発行されたサーバー証明書のインポート..."
keytool -importcert \
    -file server.cer \
    -alias ocp \
    -keystore ocp.keystore \
    -storepass "${ocp_password}"

# ---------- 8. PEM形式のルート証明書（クライアントの信頼用）をエクスポートします----------
echo ">>> [8/8] PEM形式のルート証明書のエクスポート..."
keytool -exportcert \
    -file root.pem \
    -alias root \
    -keystore root.keystore \
    -storepass "${root_password}" \
    -rfc

# ---------- 一時ファイルのクリーンアップ ----------
rm -f server.csr server.cer root.cer

echo "証明書の生成が完了しました！生成ファイル："
echo "  ocp.keystore  - OCP Server用（完全な証明書チェーンを含む）"
echo "  root.pem      - クライアントの信頼追加用"
```

使い方：

```bash
chmod +x gen_ocp_tls.sh
./gen_ocp_tls.sh
```

より多くのIPを追加する必要がある場合は、スクリプトの先頭にある`ips`変数を変更して、空白で区切ってください：

```bash
ips="30.142.17.125 10.0.0.1 192.168.1.100"
```

<main id="notice" type='notice'>
<h4>注意</h4>
<p>本番環境では、root.keystore（CA秘密鍵を含む）を適切に保管してください。証明書配布が完了した後、証明書を生成したホストからroot.keystoreおよび中間ファイル（server.csrやserver.cerなど）を削除することを推奨しますが、<b>OCPコンテナにマウント済みのocp.keystoreは削除しないでください</b>。削除するとOCPのSSL設定が無効になります。</p>
</main>

### ルート証明書の信頼

自己署名証明書を使用する場合、OBServerやOBProxyが配置されているマシンの信頼証明書リストにルート証明書を追加する必要があります。これにより、OB、Proxy、AgentなどのコンポーネントがOCPに正常にアクセスできるようになります。

ここで、`root.pem`はルート証明書ファイルです。

```bash
# RHEL系
sudo cp root.pem /etc/pki/ca-trust/source/anchors/
sudo update-ca-trust

# Debian系
sudo cp root.pem /usr/local/share/ca-certificates/root.crt
sudo update-ca-certificates

# SUSE系
sudo cp root.pem /usr/share/pki/trust/anchors
sudo update-ca-certificates
```

<main id="notice" type='notice'>
<h4>注意</h4>
<p>OceanBaseクラスタの拡張時に新しいOBServerノードを追加する場合、またはOBProxyクラスタに新しいOBProxyノードを追加する場合、新しいノードのマシンでは自己署名のルート証明書がまだ信頼されていないため、そのノードからOCPに正常にアクセスできません。拡張が完了したら、速やかに新しいノードが配置されているマシンで上記のルート証明書を信頼する操作を実行してください。</p>
</main>
