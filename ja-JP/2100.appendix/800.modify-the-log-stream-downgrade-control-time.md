# ログストリームのダウングレード制御時間の変更

<main id="notice" type='notice'>
<h4>適用対象</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能をサポートしていません。</p>
</main>

テナントレベルのアービトレーションサービスを使用する場合、ログストリームのダウングレード制御時間を設定する必要があります。半数のFレプリカに障害が発生し、ログ同期が失敗した状態でログストリームのダウングレード制御時間に達すると、アービトレーションサービスは自動的にログストリームのダウングレードプロセスを実行してサービスを復旧します。ログストリームの自動ダウングレードの制御時間はデフォルトで5秒です。この値は、データセンターに障害が発生した際のサービス中断時間も表します。

## 手順

1. `sys`テナントまたはユーザーテナントのテナント管理者としてデータベースにログインします。

   接続例は以下のとおりです。データベースへの接続時は、実際の環境に準じてください。

   ```sql
   obclient -h10.xx.xx.xx -P2883 -uroot@sys#obdemo -p***** -A
   ```

   データベースへの接続操作の詳細については、[データベース接続の概要（MySQLモード）](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013253)および[データベース接続の概要（Oracleモード）](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013209)を参照してください。

2. テナントのアービトレーションサービスのログストリームのダウングレード制御時間を確認します。

    * システムテナントから指定テナントの確認：

        ```sql
        SHOW PARAMETERS LIKE 'arbitration_timeout' TENANT = 'tenant_name';
        ```

      テナント`mysql`のアービトレーションサービスのログストリームのダウングレード制御時間を確認する例：

        ```sql
        SHOW PARAMETERS LIKE 'arbitration_timeout' TENANT = 'mysql';
        ```

    * ユーザーテナントから自身のテナントの確認：

      ```sql
      SHOW PARAMETERS LIKE 'arbitration_timeout';
      ```

    結果は次のとおりです：

    ```sql
    +-------+----------+----------------+----------+---------------------+-----------+-------+---------------------------------------------------------------------------------------------+---------+--------+---------+-------------------+---------------+-----------+
    | zone  | svr_type | svr_ip         | svr_port | name                | data_type | value | info                                                                                        | section | scope  | source  | edit_level        | default_value | isdefault |
    +-------+----------+----------------+----------+---------------------+-----------+-------+---------------------------------------------------------------------------------------------+---------+--------+---------+-------------------+---------------+-----------+
    | zone1 | observer | 172.xx.xxx.xxx |     2882 | arbitration_timeout | TIME      | 5s    | The timeout before automatically degrading when arbitration member exists. Range: [3s,+∞]   | TRANS   | TENANT | DEFAULT | DYNAMIC_EFFECTIVE | 5s            |         1 |
    +-------+----------+----------------+----------+---------------------+-----------+-------+---------------------------------------------------------------------------------------------+---------+--------+---------+-------------------+---------------+-----------+
    1 row in set
    ```

3. 使用シナリオに応じて、適切なステートメントを選択してログストリームのダウングレード制御時間を変更します。

   テナントレベルの構成パラメータ`arbitration_timeout`は、ログストリームの自動ダウングレードをトリガーする制御時間を設定するために使用されます。デフォルト値は5秒で、値の範囲は[3s, +∞)です。ダウングレードを防ぐには、十分に大きい値を設定できます。例えば、30d（30日）などです。この構成パラメータは設定後すぐに反映され、OBServerノードの再起動は不要です。

   * ユーザーテナントから自身のテナントのログストリームのダウングレード制御時間の変更：

     ```sql
     ALTER SYSTEM SET arbitration_timeout = '10s';
     ```

   * `sys`テナントから指定テナントのログストリームのダウングレード制御時間の変更：

     ```sql
     ALTER SYSTEM SET arbitration_timeout = '10s' TENANT = 'tenant_name';
     ```

   * `sys`テナントがすべてのユーザーテナント（`sys`テナントおよび`Meta`テナントを除く）のログストリームの降格制御時間を変更します。

     ```sql
     ALTER SYSTEM SET arbitration_timeout = '10s' TENANT = all_user;
     ```

     または：

     ```sql
     ALTER SYSTEM SET arbitration_timeout = '10s' TENANT = all;
     ```

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>OceanBaseデータベースでは、バージョンV4.2.1以降、<code>TENANT = all_user</code>と<code>TENANT = all</code>は同じ意味を持ちます。有効範囲をすべてのユーザーテナントに設定する場合は、<code>TENANT = all_user</code>の使用を推奨します。<code>TENANT = all</code>は今後廃止される予定です。</p>
     </main>
