# ホスト操作リストの管理

システム管理者、ホスト管理者（HOST_MANAGER）ロール、およびホスト読み取り専用ロール（HOST_VIEWER）を持つユーザーは、ページ左側のナビゲーションで **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.Host">ホスト</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.alarm.FormListWithExclude.HostWithExclude.Host">ホスト</UI-TERM>** ページに移動できます。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **クラスタ読み取り専用**、**テナント読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
* ホスト **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterAndHostWithExclude.All">すべて</UI-TERM>** メニュー権限。

## ホストリストの表示

**<UI-TERM key="ocp-v2.page.Host.HostList">ホスト一覧</UI-TERM>** には、現在のすべてのホスト情報が表示されます。これには、**<UI-TERM key="ocp-v2.Cluster.New.IpAddress">IPアドレス</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Host.Hostname">ホスト名</UI-TERM>**、**<UI-TERM key="ocp-v2.Host.Detail.Basic.Label">タグ</UI-TERM>**、**<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.HostType">ホストタイプ</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.Resource.Unit.Models">機種</UI-TERM>**、**<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">データセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.Region">リージョン</UI-TERM>**、**<UI-TERM key="ocp-v2.Tenant.Detail.BelongsCluster">所属クラスタ</UI-TERM>**、**<UI-TERM key="ocp-v2.Host.Detail.Basic.Service">所属サービス</UI-TERM>**、および **<UI-TERM key="ocp-v2.Host.Detail.Basic.State">ステータス</UI-TERM>** が含まれます。

* ページネーション検索がサポートされており、IPアドレス、ホスト名、および所属クラスタでの検索も可能です。ホストのIPアドレスについては、複数のアドレスをスペース区切りで指定して一括検索することもできます。
* ホストのラベルにカーソルを合わせると、そのホストのすべてのラベル情報を確認できます。編集アイコンをクリックしてラベルを管理することもできます。操作の詳細については、[ラベルの管理](../../1600.system-management-features/300.manage-tags/100.tags-overview.md)を参照してください。
* **<UI-TERM key="ocp-v2.component.TagLabel.Label">タグ</UI-TERM>**、**<UI-TERM key="ocp-v2.src.component.AddHostDrawer.HostType">ホストタイプ</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.New.Models">機種</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Host.DataCenter">データセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.Region">リージョン</UI-TERM>**、**<UI-TERM key="ocp-v2.Backup.Backup.Log.Cluster">所属クラスタ</UI-TERM>**、**<UI-TERM key="ocp-v2.Host.Detail.Basic.Service">所属サービス</UI-TERM>**、および **<UI-TERM key="ocp-v2.Statistics.components.StatTable.Status">ステータス</UI-TERM>** でのフィルタリングがサポートされています。
* ホストが **<UI-TERM key="ocp-v2.src.constant.binlog.OM">運用中</UI-TERM>** 状態の場合、**操作列** の **<UI-TERM key="ocp-v2.page.Welcome.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、クラスタ運用のタスク詳細ページに移動します。タスク詳細ページでは、ログの表示、ロールバック、再試行などの操作を実行できます。詳細については、[タスクの管理](../../1600.system-management-features/600.manage-tasks.md)を参照してください。
* ホストのIPアドレスをクリックすると、ホストの基本情報、OCP Agent情報、およびホスト監視データを確認できます。詳細については、[ホストの詳細を表示する](150.view-a-host-overview.md)を参照してください。
* クラスタ名をクリックすると、クラスタの **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** ページに移動し、クラスタの詳細を確認できます。

ページを展開すると、**<UI-TERM key="ocp-v2.page.Host.HostId">ホストID</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Host.MappingPort">マッピングポート</UI-TERM>**、**<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SshPort">SSH ポート</UI-TERM>**、**<UI-TERM key="ocp-v2.Host.Component.ReinstallModal.OcpAgentVersion">OCP Agent バージョン</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Host.OperatingSystem">オペレーティングシステム</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.Component.UpgradeObproxiesModal.CpuArchitecture">CPUアーキテクチャ</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Host.CpuModel">CPUモデル</UI-TERM>**、**<UI-TERM key="ocp-v2.Host.Detail.Basic.CpuCores">CPU コア数</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Host.TotalMemory">総メモリ</UI-TERM>**、および **<UI-TERM key="ocp-v2.Detail.Component.ModifyParameterDrawer.Description">説明</UI-TERM>** も確認できます。

|   パラメータ   |     説明        |
|--------|-----------|
| 所属クラスタ   | ホストが配置されているクラスタを表示します。OceanBaseクラスタとOBProxyクラスタが含まれます。クラスタ名をクリックすると、対応するクラスタの概要ページに移動します。      |
| ホストタイプ   | 現在のバージョンでは、物理ホスト、コンテナ、ECSの3種類のホストをサポートしています：<li>単一の物理ホストに複数のサービスを混合してデプロイできますが、同一タイプのサービスは1つだけデプロイできます。これにより、同種のサービス間の競合を回避できます。</li><li> 単一のコンテナホストは、1種類のサービスのみのデプロイをサポートします。OceanBaseクラスタのデプロイ要件に基づき、コンテナタイプのホストへのOceanBaseクラスタのデプロイは推奨されません。 </li>  |
| 状態     | 新規提出、アイドル、オンライン、オフライン、削除中、Agent再インストール中、Agent再起動中が含まれます。    |
| マッピングポート | ocp-agentとホスト、ocp exportとホストの計2組のマッピング関係で、対応する形式は次のとおりです：`<ホストポート>:<Docker内のocp-agentポート>, <ホストポート>:<Docker内のocp-exporterポート 1>`。       |
