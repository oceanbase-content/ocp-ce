# ホスト標準化チェック項目

ホストの標準化プロセスにおいて、システムはホストをチェックします。本記事では、標準化プロセス中にホストがチェックされる項目について説明します。

<main id="notice" type='explain'>
<h4>説明</h4>
<p><li><b>ホスト標準化チェック</b> は現在、OBServerをデプロイするマシンにのみ適用されます。その他のマシンでは、状況に応じてご利用ください。</li><li>コンテナ環境では、cgroupやnamespaceなどの制限により、チェックや自動修復ができない場合があります。ドキュメントの内容を参照し、必要に応じて手動で適切に操作することを推奨します。</li></p>
</main>

## ファイルシステムタイプの確認

ファイルシステムタイプは EXT4 と XFS の 2 種類をサポートしています。ディスク容量が 16 TB を超える場合、ファイルシステムタイプが XFS であるか確認し、タイプが一致しない場合は、ディスクの再設定を推奨します。

## サービスの確認

`crond`、`sshd`、および `firewalld` サービスを確認します。その中で、`crond` と `sshd` が有効状態になっているか、`firewalld` が無効状態になっているかを確認します。

| サービス | 説明 |
| --- | --- |
| crond | 有効にすることを推奨します。主にスケジュールタスクの設定と関連する運用保守機能の提供に使用されます。 |
| sshd | 有効にすることを推奨します。主に暗号化ログインまたはデータ転送に使用され、基本的な運用保守機能を提供します。 |
| firewalld | `firewalld` を無効にするか、OceanBase クラスタの各サービスに許可ルールを追加して、ファイアウォールによる遮断を回避することを推奨します。 |

**手動での変更方法：**

* サービスを開始する：systemctl enable {serviceName} && systemctl start {serviceName}
* サービスを停止する：systemctl stop {serviceName} && systemctl disable {serviceName}

## Transparent Huge Pagesのチェック

Transparent Huge Pagesが無効になっているか確認し、システムのパフォーマンスを安定させます。

**手動での変更方法：** `echo never > /sys/kernel/mm/transparent_hugepage/enabled` コマンドを実行して、Transparent Huge Pagesの設定を never に設定します。また、マシンが再起動した場合でも設定が持続するように、`rc.local` または `systemd` の設定にこのコマンドを追加することを推奨します。

## Pythonバージョンの確認

OceanBase関連のスクリプトはPython 2.7.xに依存しています。関連スクリプトが正常に動作するように、Pythonバージョンを確認する必要があります。

**手動での変更方法：** パッケージ管理からPython 2.7をインストールし、`python -V` コマンドを実行したときのバージョンが2.7であることを確認します。

## Swapが有効になっていないかの確認

デプロイマシンでSwapパーティションが有効になっていないか確認します。パフォーマンスのジッターを避けるため、Swapパーティションを無効にすることを推奨します。

**手動での変更方法：** `swapoff/swapon -a` を実行し、`/etc/fstab` （永続化のため）からSwap関連のエントリを削除します。

## SELinuxが有効か確認する

システムでSELinuxが有効になっているか確認します。SELinuxは強制アクセス制御（Mandatory Access Control, MAC）を使用し、特定のプログラムと特定のファイルリソースに対して権限を管理します。SELinuxは無効にすることを推奨します。

**手動で修正する方法：** `/usr/sbin/setenforce` コマンドを使用してselinuxを無効にし（値を0に設定）、`/etc/selinux/config` の設定をdisabledに変更します。

## ulimit情報の確認

主にシェルから起動したプロセスが使用するリソースを制限するために使用されます。OBServerプロセスに関連する制限事項には、スレッドの最大スタックサイズ（stack）、最大ファイルハンドル数（open files）、コアファイルサイズ（core file size）が含まれます。システムの制限がサービスに影響を与えるのを避けるため、ulimit関連項目を以下の値に設定することを推奨します：

```Json
root soft nofile 655350
root hard nofile 655350
admin soft nofile 655350
admin hard nofile 655350
admin soft stack 10240
admin hard stack 10240
admin soft nproc 655360
admin hard nproc 655360
admin soft core unlimited
admin hard core unlimited
```

**手動で修正する方法：** `/etc/security/limits.d/99-oceanbase_limits.conf` ファイルを作成し、上記の設定内容をファイルに書き込みます。同時に、このファイルが最も高い優先順位を持つようにします。

## clocksource情報の確認

システムパラメータclocksourceが要件を満たしているかどうかを確認します。推奨値は`tsc`です。他の値はパフォーマンス問題を引き起こす可能性があります。

**手動で修正する方法：** `echo tsc > /sys/devices/system/clocksource/clocksource0/current_clocksource` コマンドを実行して、clocksourceの値を`tsc`に変更します。

## デフォルトのNIC MTU値の確認

デフォルトのNIC MTU値を確認します。推奨値は1500です。大きすぎたり小さすぎたりするとシステムの動作には影響しませんが、ネットワーク転送効率やパフォーマンスに影響します。

**手動で修正する方法：**

* **一時的に有効にする方法**

  * IPコマンド：`sudo ip link set dev eth0 mtu 1500` 。
  * ifconfigコマンド：`sudo ifconfig eth0 mtu 1500` 。

* **永続的に有効にする方法**

  * Debian/Ubuntu: `/etc/network/interfaces` ファイルを編集し、以下の内容を追加します。

    ```bash
    auto eth0
    iface eth0 inet dhcp
    mtu 1500
    ```

  * CentOS/RHEL: `/etc/sysconfig/network-scripts/ifcfg-eth0` ファイルを編集し、以下の内容を追加または変更します。

    ```bash
    MTU=1500
    ```

## クロック同期サービスNTP/Chronyの確認

ホストが時刻源と同期しているかどうかを確認します。NTPまたはChronyサービスを有効にすることを推奨します。

**手動で修正する方法：**

1. NTPソフトウェアパッケージをインストールします。既にインストール済みの場合は、この手順をスキップできます。

    ```bash
    sudo apt update
    sudo apt install ntp    # Debian/Ubuntuの場合
    # または
    sudo yum install ntp    # CentOS/RHELの場合
    ```

2. NTPサービスを起動します。

    ```bash
    sudo systemctl start ntp
    ```

3. NTPサービスの起動時自動起動を設定します。

    ```bash
    sudo systemctl enable ntp
    ```

4. NTPサービスの状態を確認します。

    ```bash
    sudo systemctl status ntp
    ```
