# ホストの標準化チェック

データベースクラスタはデータの基盤であり、パフォーマンスと安定性は本番環境において極めて重要です。データベースクラスタが最大限の価値を発揮できるようにするため、本番環境への導入前にホスト環境の標準化チェックを実施し、潜在的なリスクを修正することを推奨します。

このセクションでは、OCPにホストを追加した後、ホストの標準化チェックを実行する手順について説明します。

## 前提条件

* 現在OCPにログインしているユーザーが少なくとも以下の権限を持っていることを確認してください：

  * **ホストメンテナンス** リソース権限。
  * ホスト **<UI-TERM key="ocp-v2.component.HostSelect.All">すべて</UI-TERM>** メニュー権限。

* ホストが [追加済み](200.add-a-host.md) であること。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Service.Component.ServiceModal.Host">ホスト</UI-TERM>** をクリックします。

3. ホスト一覧ページで、実際の業務シナリオに応じて、ホスト標準化の操作を選択します。

   * 新規ホストが **<UI-TERM key="ocp-v2.src.constant.compute.Idle">空き</UI-TERM>** 状態にあり、かつホストの標準化について把握しているか、既に完了している場合は、操作列の **...** をクリックし、**<UI-TERM key="ocp-v2.page.Host.HostStandardization">ホスト標準化</UI-TERM>** を選択します。

   * 新規ホストが **<UI-TERM key="ocp-v2.src.constant.oceanbase.Idle">空き</UI-TERM>** 状態で標準化操作が行われていない場合、ホストの ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E7%A9%BA%E9%97%B2%E5%9B%BE%E6%A0%87.png) アイコンにカーソルを合わせ、ポップアップ表示されたメッセージで **<UI-TERM key="ocp-v2.page.Host.HostStandardization">ホスト標準化</UI-TERM>** をクリックします。

4. ダイアログボックスで、ホスト標準化の実行操作タイプと製品タイプを選択し、**<UI-TERM key="ocp-v2.component.TagFilterDropDown.Ok">確定</UI-TERM>** をクリックします。

   |  パラメータ  |  説明 |
   |--------|-------|
   | 実行操作  | **<UI-TERM key="ocp-v2.page.Host.CheckAndRepairAutomatically">検査と自動修復</UI-TERM>** と **<UI-TERM key="ocp-v2.page.Host.CheckOnly">チェックのみ</UI-TERM>** の 2種類があります。<ul><li>チェックして自動修復：システムがホストをチェックし、チェック中に検出されたリスクを自動的に修復します。</li><li>チェックのみ：システムはホストをチェックするだけで、チェック中に検出されたリスクを自動的に修復しません。</li></ul>   |
   | 製品タイプ  | **OceanBase** と **OBProxy** の 2種類があり、複数選択が可能です。システムは製品タイプごとに必要なホスト標準化チェック項目を実行します。  |

5. チェックタスク終了後、ホストにリスクが存在する場合は、以下の手順を参照して修正してください：

   * ホスト標準化の実行操作が **<UI-TERM key="ocp-v2.page.Host.CheckAndRepairAutomatically">検査と自動修復</UI-TERM>** の場合：

     1. **<UI-TERM key="ocp-v2.page.Host.ViewTheFixReport">修正レポートを確認する</UI-TERM>** をクリックして詳細なリスク明細を確認し、レポートの情報に基づいて手動でリスクを修正します。
     2. リスクの修正後、**<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">再確認する</UI-TERM>** をクリックして、ホストに対して新たなチェックタスクを開始します。

   * ホスト標準化の実行操作が **<UI-TERM key="ocp-v2.page.Host.CheckOnly">チェックのみ</UI-TERM>** の場合：

     1. **<UI-TERM key="ocp-v2.page.Host.ViewInspectionReports">検査報告を確認する</UI-TERM>** をクリックして詳細なリスク明細を確認します。
     2. チェックレポートに自動修復可能なリスクがある場合、**<UI-TERM key="ocp-v2.page.Host.AutomaticRepair.1">自動修復</UI-TERM>** ボタンをクリックすると、システムがリスク項目を自動的に修復します。チェックレポートで自動修復できないリスクについては、レポートの情報に基づいて手動で修正する必要があります。
     3. リスクの修正後、**<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">再確認する</UI-TERM>** をクリックして、ホストに対して新たなチェックタスクを開始します。
