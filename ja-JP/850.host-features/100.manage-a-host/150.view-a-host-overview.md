# ホストの詳細を表示する

ホストの詳細ページでは、ホストの基本情報、OCP Agent情報、およびホストの監視データを確認できます。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **クラスタ読み取り専用**、**テナント読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
* ホストの **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterAndHostWithExclude.All">すべて</UI-TERM>** メニュー権限。

## ホスト基本情報の表示

**<UI-TERM key="ocp-v2.TraceDetail.TraceContent.BasicInformation">基本情報</UI-TERM>** タブでは、ホストの詳細とディスク使用状況を確認でき、タグ管理操作もサポートされています。

* **<UI-TERM key="ocp-v2.Alarm.Event.Detail.Details">詳細</UI-TERM>** では、ホストの状態、ホスト名、ホストエイリアス、SSHポート、データセンター、マシンタイプ、ホストタイプ、リージョン、ディスク使用量、所属サービス、時刻のずれ、現在時刻、タイムゾーン、OS、CPUアーキテクチャ、CPU型番、CPUコア数、タグ、総メモリ、説明などの情報を確認できます。

    ホストのタグにカーソルを合わせると、そのホストのすべてのタグ情報を確認できます。タグの編集アイコンをクリックすると、タグを管理できます。操作の詳細については、[タグの管理](../../1600.system-management-features/300.manage-tags/100.tags-overview.md)を参照してください。

* **<UI-TERM key="ocp-v2.Host.Detail.Basic.DiskUsage">ディスク使用状況</UI-TERM>** では、各パスが使用するパーティションのディスク使用量、ディスク使用済み量、利用可能なディスクサイズ、使用率、マウントディレクトリなどの情報を確認できます。

## OCP Agent情報の表示

**OCP Agent** タブでは、OCP Agentの詳細とプロセスリストを確認できます。

* **<UI-TERM key="ocp-v2.Alarm.Event.Detail.Details">詳細</UI-TERM>** では、OCP Agentの状態、インストールディレクトリ、インストール時間、バージョン、ログディレクトリ、最終利用可能時間を確認できます。

* **<UI-TERM key="ocp-v2.Host.Detail.OCPAgent.Processes">プロセス一覧</UI-TERM>** では、プロセスID、名前、起動コマンド、OSユーザー、ポート番号、仕様、実行時間、最終利用可能時間、状態などの詳細なプロセス情報を確認できます。

  * 操作列の **<UI-TERM key="ocp-v2.Host.Detail.OCPAgent.DownloadLogs">ログをダウンロードする</UI-TERM>** をクリックすると、現在のプロセスのログ情報をダウンロードできます。

  * `ocp_monagent` プロセスの操作列の **<UI-TERM key="ocp-v2.Host.Detail.OCPAgent.ChangeSpecifications">仕様変更</UI-TERM>** をクリックすると、現在のホストのOCP Agent仕様を変更できます。

     <main id="notice" type='notice'>
     <h4>注意</h4>
     <p><ul><li>推奨される最大仕様は6C/12GiBです。</li><li>ocp_monagentのメモリ設定は、クラスタ内の各ホストの利用可能な物理メモリサイズより低く設定することを推奨します。そうでない場合、リソース設定に失敗する可能性があります。ホストの利用可能な物理メモリサイズは、<b>パフォーマンス監視</b> > <b>ホストパフォーマンス</b> > <b>ホスト次元</b> > <b>メモリ</b> から確認できます。</li><li>高い業務負荷やストレステストのシナリオでは、リソース不足によるOOM（Out Of Memory、メモリ不足）や監視データの損失を防ぐため、OCP Agentのリソース仕様を引き上げることを推奨します。</li><li>OCP Agentの仕様を変更するには、<a href="400.restart-the-ocp-agent.md">OCP Agentを再起動</a>する必要があります。再起動中はOCPが運用操作を実行できず、一部の監視データが失われるため、慎重に操作してください。</li><li>クラスタ内のすべてのOCP Agentのリソース仕様を変更する必要がある場合は、<a href="../../600.cluster-functions/300.manage-a-cluster/1200.manage-om-configuration/400.configuring-ocp-agent-resources.md">OCP Agentリソースの設定</a>を参照して操作してください。</li></ul></p>
     </main>

### パイプライン監視情報の表示

**OCP Agent** タブでは、パイプラインの監視データを確認できます。これには、収集パイプラインと監視パイプラインの実行状態、スループット、所要時間などの情報が含まれます。

### 収集パイプライン

| 監視指標 | 説明 |
|----------|------|
| パイプラインTableInputプラグイン収集時間 | TableInputプラグインがデータ収集を完了するまでにかかった時間。 |
| パイプラインTableInputプラグイン収集タイムアウト回数 | TableInputプラグインの収集タイムアウト回数。 |
| パイプライン入力プラグインスループット | パイプライン入力プラグインのデータ収集スループット。 |
| パイプライン処理プラグインスループット | パイプライン処理プラグインのデータ収集スループット。 |
| パイプライン出力プラグインスループット | パイプライン出力プラグインのデータ収集スループット。 |
| パイプラインエクスポートプラグインスループット | パイプラインエクスポートプラグインのデータ収集スループット。 |
| パイプライントリガー型エクスポートプラグインスループット変化 | トリガー型エクスポートプラグインのスループット変化状況。 |
| パイプラインエクスポートHTTPリクエスト失敗回数 | エクスポートプラグインがHTTPリクエストを送信した際の失敗回数。 |

### 監視パイプライン

| 監視メトリクス | 説明 |
|----------|------|
| パイプライン実行回数 | 監視パイプラインの実行総回数。 |
| パイプライン実行時間 | 監視パイプラインの1回の実行にかかる時間。 |
| パイプラインプラグイン実行回数 | 監視パイプライン内の各プラグインの実行回数。 |
| パイプラインプラグイン実行時間 | 監視パイプライン内の各プラグインの実行時間。 |

## 監視情報の表示

**<UI-TERM key="ocp-v2.src.hook.useMenu.Monitoring">監視</UI-TERM>**タブで、**<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.HostPerformance">ホストパフォーマンス</UI-TERM>**、**<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.HostResources">ホストリソース</UI-TERM>**、および**<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.HostProcess">ホストプロセス</UI-TERM>**の監視データを確認できます。詳細については、[ホストパフォーマンスの表示](../../880.manage-performance-monitoring/100.performance-monitoring-overview/300.view-host-performance.md)、[ホストリソースの表示](../../880.manage-performance-monitoring/100.performance-monitoring-overview/700.view-host-resources.md)、[ホストプロセスの表示](../../880.manage-performance-monitoring/100.performance-monitoring-overview/750.view-host-process.md)を参照してください。
