# clog同期遅延

このセクションでは、OceanBaseテナントのモニタリング指標である**clog同期遅延**について説明します。この指標は、full_clog_sync_delay（フル機能レプリカのclog同期遅延）、readonly_clog_sync_delay（読み取り専用レプリカのclog同期遅延）、logonly_clog_sync_delay（ログ専用レプリカのclog同期遅延）の3つの指標に細分化されています。統計範囲を指定することで、単一ゾーンまたはOBServerノード内のテナントの**clog同期遅延**データを照会できます。

OceanBaseデータベースにおけるレプリカタイプは以下の通りです：

* フル機能レプリカ：現在サポートされている一般的なレプリカで、トランザクションログ、MemTable、SSTableなど、すべての完全なデータと機能を備えています。いつでも迅速にリーダーに切り替えて外部へのサービス提供が可能です。

* ログ専用レプリカ：ログのみを含むレプリカで、MemTableやSSTableはありません。ログ投票に参加し、外部へのログサービスを提供します。他のレプリカの復元にも関与できますが、自身がリーダーになってデータベースサービスを提供することはできません。

* 読み取り専用レプリカ：完全なログ、MemTable、SSTableなどを含みます。ただし、そのログは特殊で、Paxosメンバーとしてログ投票には参加せず、観察者としてリアルタイムでPaxosメンバーのログを追従し、ローカルで再生します。このようなレプリカは、業務上データ読み取りの一貫性に対する要求が高くない場合に読み取り専用サービスを提供できます。Paxosメンバーグループに加わらないため、投票メンバーの増加によるトランザクションコミット遅延も発生しません。

clog同期遅延とは、これらのレプリカのclog同期遅延を指します。

## full_clog_sync_delay

### 指標紹介

統計範囲内の、フル機能レプリカのclog同期最大遅延。

### 指標パラメータ説明

|  **<UI-TERM key="ocp-v2.Monitor.AddMonitor.IndicatorItem">メトリクス項目</UI-TERM>**   |  **指標名**  | **<UI-TERM key="ocp-v2.Monitor.AddMonitor.VisualizationsTable.Unit">単位</UI-TERM>** |
|-------|--------|--------|
| full_clog_sync_delay | max_full_clog_sync_delay_seconds | s     |

### 計算式

max(ob_clog_max_sync_delay_seconds{replica_type="0",@LABELS}) by (@GBLABELS)

### 取得SQL

OceanBase V4.0未満のバージョン：

```sql
select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ stat.table_id >> 40 tenant_id, stat.replica_type, max(stat.next_replay_ts_delta) / 1000000 as max_clog_sync_delay_seconds from __all_virtual_clog_stat stat left join (select meta.table_id, meta.partition_id from __all_virtual_meta_table meta where meta.status = 'REPLICA_STATUS_NORMAL'and meta.svr_ip = ? and meta.svr_port = ? and meta.table_id not in (select table_id from __all_virtual_partition_migration_status mig where mig.action <> 'END') ) meta on stat.table_id = meta.table_id and stat.partition_idx = meta.partition_id where stat.svr_ip = ? and stat.svr_port = ? group by tenant_id, replica_type having max_clog_sync_delay_seconds < 3153600000
```
