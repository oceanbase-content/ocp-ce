# アラートAPI呼び出し例

このセクションでは、アラートAPIとの連携方法およびテスト方法を理解するためのスクリプト例を提供します。

## OCPインターフェース呼び出し例

以下のスクリプトは、「アラートイベントプッシュインターフェース」を例に、そのインターフェースの呼び出し方法を説明します。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>アラートイベントのプッシュとは、アラートをOCPにプッシュし、OCPがアラートメッセージを処理することを指します。</p>
  </main>

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-

import base64
import requests
import json

data = {
    "alarmType": "your_alarm_type",
    "labels": {"key":"value"},
    "target":"alarm_target",
}

base64userpass = base64.b64encode('{0}:{1}'.format('username', 'password'))
headers = {
    'Content-Type': 'application/json',
    'Accept': 'application/json',
    "Authorization": "Basic %s" % base64userpass,
}

resp = requests.post(url='http://xxx.xxx.xxx.xxx:8080/api/v2/alarm/alarms', headers=headers, data=json.dumps(data))
jresp = json.loads(resp.text)
print(jresp)
```

## OCPアラート連携例

OCPがアラートを生成すると、アラートメッセージはアラートチャネルを通じて送信されます。チャネルではShellスクリプトやPythonスクリプトを設定できます。この例では、アラートをチャネルを通じて送信する方法を説明します。`send_alarm` 関数は、os.environを使用して環境変数からアラート関連の変数値を取得します。

以下はPythonスクリプトの例です。その他の例については、[アラートチャネル設定例](../../../860.alert-management/500.manage-alert-channels/600.examples-of-alert-channel-configuration.md)を参照してください。

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-

# 注意：スクリプトの最初の行は必ずshebangであり、実行プログラムを指定する必要があります。サポートされているのはpythonとbashのみです。

import json
import requests
import os
import sys

ACCESS_TOKEN = "Ding Talk Token"

def send_alarm():
    """
    os.environを使用して環境変数からアラート関連の変数値を取得できます。
    サポートされている変数の一覧については、『ユーザーガイド/付録4 OCPアラートテンプレート変数』を参照してください。
    """
    message = os.environ['message']
    data = {
        "msgtype": "markdown",
        "markdown": {
            "text": message
        }
    }
    resp = requests.post("https://oapi.dingtalk.com/robot/send?access_token=" + ACCESS_TOKEN, json=data)
    resp.close()
    response = json.loads(resp.text)

    # 実行結果を標準エラー出力（stderr）または標準出力（stdout）に書き込みます。これはアラート送信の成功を検証するために使用され、優先的にstderrが検証されます。
    if not response['errcode'] == 0:
        sys.stderr.write(resp.text)
    else:
        print(resp.text)

def main():
    """
    送信成功時、戻り値は0です。
    送信失敗時、エラーはstderrに出力され、戻り値は0ではありません。
    """
    try:
        send_alarm()
        return 0
    except Exception as e:
        sys.stderr.write(str(e))
        return 1

if __name__ == "__main__":
    sys.exit(main())
```

## 適用例

アラートパイプラインが正常に機能しているか、つまりアラートがサードパーティのアラートプラットフォームにプッシュできるかどうかをテストする場合、以下の方法があります：

* OCPでアラートをトリガーする：

  1. OCP-Agentを一時停止し、Agentが利用不可であることに関連するアラート（例：`exporter数量不足` アラート）をトリガーします。

  2. サードパーティプラットフォームがこのアラートを受信したかどうかを確認します。

* OCPチャネル設定にはテスト機能があり、**<UI-TERM key="ocp-v2.Alarm.Channel.New.SendTestMessages">テストメッセージを送信</UI-TERM>** ボタンをクリックするだけで直接テストできます。[新しいアラートチャネルの作成](../../../860.alert-management/500.manage-alert-channels/100.create-an-alert-channel.md)を参照してください。

上記の「OCPアラートイベントプッシュインターフェース」を使用してアラートを構築し、アラートチャネルスクリプトを通じてサードパーティプラットフォームにアラートを送信することもできます。

## アラートAPI接続例

以下では、OCPのアラートをユーザーのアラートプラットフォームに接続する手順をご紹介します。

### 背景

OCPのアラートをユーザーのアラートプラットフォームに接続する際には、アラートイベントを照会するAPIを使用する必要があります。詳細については、[現在のアラートの取得](200.fetch-actived-alarms.md)または[履歴アラートの取得](300.fetch-history-alarms.md)を参照してください。

### シナリオ1：リアルタイムアラートの確認

システム内のリアルタイムアラートを確認する必要がある場合、コード例を参考に操作を行い、定期的にアラートイベントリストを照会するAPIをリクエストすることで、現在アラートが発生している対象を取得できます。

#### コード例

```javascript
curl 'http://OCP-IP:8080/api/v2/alarm/alarms?isSubscribedByMe=false&status=Active&page=1&size=10' \
--user username:password \
--compressed \
--insecure
```

ここで`data.page.totalPages`はリアルタイムアラートの総ページ数であり、特定のページのアラートを表示することができます。例えば、2ページ目のデータを表示するには、page数を2に設定します：

```javascript
curl 'http://OCP-IP:8080/api/v2/alarm/alarms?isSubscribedByMe=false&status=Active&page=2&size=10' \
--user username:password \
--compressed \
--insecure
```

重要な情報の説明：

|     パラメータ      |                                                                                                      説明                                                                                                      |
|-------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| alarmType   | アラートルール名。                                                                                                                                                                                                       |
| activeAt    | アラートのトリガー時間、グリニッジ標準時です。使用する際は現地時間に変換する必要があります。                                                                                                                                                                                 |
| updatedAt   | アラートの更新時間、グリニッジ標準時です。使用する際は現地時間に変換する必要があります。                                                                                                                                                                                 |
| target      | アラート対象、例えば特定のクラスタの特定のテナントなどです。                                                                                                                                                                                             |
| description | アラートの説明情報。                                                                                                                                                                                                      |
| summary     | アラートの概要情報。                                                                                                                                                                                                      |
| level       | アラートレベル。                                                                                                                                                                                                        |
| labels      | その他の情報、例えば：クラスタ（旧バージョンではobregionまたはob_cluster）、テナント（tenant_name）、ホストIP（svr_ip）などです。_1、_2、_3をサフィックスとするものは非標準の国際化内容であり、必要でない限り使用しないでください。新しいバージョンでは、このフィールドとの互換性がありません。現在使用可能な一部のlabelの説明は[アラートチャネル設定例](../../../860.alert-management/500.manage-alert-channels/600.examples-of-alert-channel-configuration.md)を参照してください。 |

### シナリオ2 顧客アラートプラットフォームとの連携

シナリオ1のコード例を参考に、定期的にアラートイベント一覧を取得するAPIを呼び出し、受信したアラートオブジェクト(target)の状態を更新する必要があります。

更新される情報は以下の通りです：

* 最終アラート時間：アラートのトリガー時間からアラートの継続時間を計算できます。

* アラート状態：各バッチ（複数のページネーションリクエストで全アラートを取得する場合を1バッチとする）でAPIを呼び出した際に、特定のtargetのアラートが返されなかった場合、そのアラートは復旧済み状態に設定されます。

* アラートレベル別に、「アラート発生中」のアラート数をリアルタイムで集計できます。
