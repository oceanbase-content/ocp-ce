# SOPタスクの編集

## 機能の概要

開始前のSOPタスクの名前、ターゲットパラメータ、手順設定、備考を完全に更新します。リクエスト内の`sopType`はタスクタイプを切り替えるものではなく、サーバー側は常にタスクの元のタイプを維持します。

## 呼び出しの説明

### インターフェース制約

タスクに対する`SOP_TASK:UPDATE`権限とターゲットリソースに対する`UPDATE`権限が必要です。タスクはまだ開始されていない必要があります。

### リクエストパス

`PUT /api/v2/sop/tasks/{id}`

### リクエストパラメータ

| パラメータ | 位置 | 型 | 必須 | 説明 |
| --- | --- | --- | --- | --- |
| id | Path | Long | はい | 編集対象のタスクID。 |
| name | Body | String | はい | 作成インターフェースと同じ：グローバル一意、2～32文字、文字規則は同じです。 |
| sopType | Body | String | いいえ | リクエストの可読性を保つために元のタスクタイプを指定できます。有効な値は`REBUILD_STANDBY_TENANT`、`ARBITRATION_FOR_FAULTY_REPLICA`、`OBSERVER_DATA_REBUILD`ですが、タスクタイプの変更には使用されません。 |
| targetParam | Body | Object | はい | 作成インターフェースと同じで、元のタスクのSOPタイプに応じたフィールドと制約が提供されます。 |
| steps | Body | Array | はい | 作成インターフェースと同じです。手順は空にできません。テンプレートの手順は重複できません。固定で有効な手順は必ず指定する必要があります。 |
| steps[].stepIndex | Body | Integer | いいえ | ターゲット手順の番号です。指定しない場合はテンプレートのデフォルト値が使用され、最終的には連続しており重複していない必要があります。移動可能な手順のみ位置を調整できます。 |
| steps[].stepKey | Body | String | はい | 元のタスクタイプのテンプレートにおける手順識別子で、重複してはなりません。 |
| steps[].autoRun | Body | Boolean | いいえ | 自動実行スイッチです。指定しない場合はテンプレートのデフォルト値が保持されます。手順を編集できない場合はデフォルト値を変更できません。 |
| steps[].enabled | Body | Boolean | いいえ | 手順を有効にするかどうかです。テンプレートで無効化が許可されている手順のみ`false`に設定できます。 |
| comments | Body | String | いいえ | 更新後の備考です。 |
| startNow | Body | Boolean | いいえ | `true`の場合、更新後すぐに開始します。指定なしまたは`false`の場合は開始しません。 |

編集時の`steps[].stepKey`の許容値も元のタスクタイプによって決まります：

| `sopType` | `steps[].stepKey` の有効な値 |
| --- | --- |
| `REBUILD_STANDBY_TENANT` | `CONFIRM_STANDBY_TENANT_INFO`、`BACKUP_PRIMARY_TENANT`、`DISCONNECT_STANDBY_TENANT`、`LOCK_STANDBY_TENANT`、`DELETE_STANDBY_TENANT`、`CREATE_STANDBY_TENANT`、`VERIFY_PRIMARY_STANDBY_SYNC` |
| `ARBITRATION_FOR_FAULTY_REPLICA` | `CONFIRM_ARBITRATION_TARGET`、`ADD_ARBITRATION_SERVICE`、`DELETE_TENANT_REPLICA`、`DELETE_OBSERVER`、`ENABLE_TENANT_ARBITRATION`、`VERIFY_TENANT_ARBITRATION` |
| `OBSERVER_DATA_REBUILD` | `CONFIRM_OBSERVER_TARGET`、`DELETE_TENANT_REPLICA`、`DELETE_OBSERVER`、`FORCE_DELETE_HOST`、`ADD_OBSERVER`、`ADD_TENANT_REPLICA`、`VERIFY_REPLICA_REBUILD` |

### 戻り値

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| successful | Boolean | 成功した場合は`true`。 |
| data.id | Long | タスクID。 |
| data.name | String | 更新後のタスク名。 |
| data.sopType | String | 元のタスクのSOPタイプコード。 |
| data.sopTypeDisplayName | String | 現在のlocaleにおけるSOPタイプの表示名。 |
| data.targetParam | Object | 保存後のタスクレベル目標パラメータおよびサーバー側で解析/補完されたフィールド。スタンバイテナントの再構築には `standbyClusterId`、`standbyTenantId`、`logTransportMode` などが含まれます。アービトレーションタイプには `clusterId` とアービトレーションサービス/サービスグループのいずれか一方が含まれます。OBServerの再構築には `clusterId` とオプションの `replacementHostId` が含まれます。 |
| data.operationObjects | Object | 解析済みオブジェクト（表示用）。スタンバイテナントの再構築には、元の/新しいスタンバイテナント、元の/新しいスタンバイクラスタ、プライマリテナント、プライマリクラスタ、各種ID、ログ転送方式、バックアップ設定が含まれる場合があります。アービトレーションタイプには、影響を受けるテナント、障害IP、アービトレーションサービス/サービスグループ、サービス接続情報が含まれる場合があります。OBServerの再構築には、影響を受けるテナント、障害IP、ゾーン、代替ホストID/IPが含まれる場合があります。該当するフィールドが存在しない場合は返しません。 |
| data.targetSummary.displayText | String | ターゲットの概要テキスト。 |
| data.targetSummary.kind | String | ターゲットのカテゴリ。 |
| data.targetSummary.details[] | Array | 概要の詳細。各項目には `label`（名前）と `value`（値）が含まれます。 |
| data.steps[] | Array | 保存後の手順。各項目には `stepIndex`、`stepKey`、`stepName`、`stepKind`、`stepDescription`、`autoRun`、`enabled`、`blockNext`、`editable`、`userMovable`、`minStepIndex`、`maxStepIndex` が含まれます。 |
| data.comments | String \| null | 更新後の備考。 |
| data.creator | String | 作成者のユーザー名。 |
| data.createTime | Datetime | タスクの作成時間。 |
| data.updateTime | Datetime | タスクの最終更新時間。 |
| data.displayStatus | String | 更新後のステータス。未開始の場合は `NOT_STARTED`、即時開始の場合は実際の実行状態です。 |
| data.currentExecutionId | Long \| null | 実行インスタンスID。未開始の場合は `null`。 |
| timestamp | Datetime | サーバー側が応答を作成した時間。 |
| duration | Long | サーバー側の処理時間。単位はミリ秒。 |
| status | Integer | HTTPステータスコード。成功時は `200`。 |
| traceId | String | ログ調査に使用されるリクエストのトレースID。 |

### エラーコード

作成インターフェースの `SOP10001`–`SOP10007` 以外に、以下のエラーコードも返される場合があります。

| HTTP | エラーコード | 説明 |
| --- | --- | --- |
| 404 | `SOP10008` | タスクが存在しません。 |
| 400 | `SOP10009` (`SOP_TASK_ALREADY_STARTED`) | タスクに実行インスタンスが存在するため、編集できません。 |
