# グローバルバックアップ情報の解析

## 機能の概要

このインターフェースは、現在OCPが管理するホストを使用して指定されたバックアップストレージにアクセスし、その中からソースクラスタ、ソーステナント、データバックアップポイント、ログバックアップ区間、復元可能時間区間を解析します。

典型的なシナリオとしては、本番環境でテナントのバックアップをOSSに保存し、テスト環境のOCPおよびOceanBaseクラスタは本番環境と関連付けられていないものの、テスト環境からそのOSSにアクセスできる場合が挙げられます。呼び出し側はこのインターフェースを通じてバックアップ情報を解析し、復元可能な時刻を選択してオフラインテナントの復元タスクを送信できます。

## 呼び出しの説明

### インターフェース制約

* ユーザーはOCPアプリケーションサービスの認証を通過し、バックアップ読み取り権限を持っている必要があります。
* ユーザーは選択した解析ホストに対する読み取り権限を持っており、かつ解析ホストが指定されたバックアップストレージにアクセスできる必要があります。

### リクエストパス

`POST /api/v2/backup/info`

### リクエストパラメータ

**Queryパラメータ**

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
| --- | --- | --- | --- | --- |
| startTime | DateTime | いいえ | 2026-09-02T10:00:00+08:00 | クエリ時間範囲の開始時刻。ISO 8601形式を使用します。 |
| endTime | DateTime | いいえ | 2026-09-09T10:00:00+08:00 | クエリ時間範囲の終了時刻。ISO 8601形式を使用します。 |
| timeScopeType | String | いいえ | LATEST_SEVEN_DAYS | クエリ時間範囲のタイプ。`LATEST_SEVEN_DAYS`、`LATEST_SIX_MONTHS`、`MONTHS`、`YEARS`、`USER_DEFINED`が指定可能です。デフォルト値は`LATEST_SEVEN_DAYS`です。 |

**Bodyパラメータ**

**ParseObBackupInfoParamのデータ構造**

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
| --- | --- | --- | --- | --- |
| obBackupStorageBaseInfo | Object | はい | - | データバックアップストレージ情報。データ構造については、**ObBackupStorageBaseInfoのデータ構造**を参照してください。 |
| hostIdList | LongArray | はい | [3001] | データバックアップ解析ホストIDのリスト。現在OCPが管理するホストIDを少なくとも1つ指定してください。 |
| logStorageMode | String | いいえ | SAME_AS_DATA | ログバックアップストレージモード。`SAME_AS_DATA`はログとデータが同一ストレージを使用することを示します。`INDEPENDENT`はログが独立したストレージを使用することを示します。明示的に指定することを推奨します。 |
| logBackupStorageBaseInfo | Object | 条件付き必須 | - | `logStorageMode`が`INDEPENDENT`の場合は必須です。`SAME_AS_DATA`の場合は省略してください。データ構造は`obBackupStorageBaseInfo`と同じです。 |
| logHostIdList | LongArray | いいえ | [3002] | 独立ログバックアップの解析ホストIDリスト。省略または空配列を指定した場合は`hostIdList`を再利用します。 |
| storageId | Long | いいえ | 10 | 現在のOCP内で既に設定されているバックアップストレージのID。アプリケーションサービスの呼び出し時には、完全なストレージパラメータとオブジェクトストレージアクセス資格情報を指定する必要があります。このフィールドにのみ依存することはできません。 |

**ObBackupStorageBaseInfoのデータ構造**

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
| --- | --- | --- | --- | --- |
| backupStorageType | String | はい | BACKUP_STORAGE_OSS | ストレージタイプ。現在のインターフェースで使用されているタイプは`BACKUP_STORAGE_FILE`、`BACKUP_STORAGE_OSS`、`BACKUP_STORAGE_COS`、`BACKUP_STORAGE_OBS`、`BACKUP_STORAGE_S3`です。 |
| storageUrl | String | はい | example-bucket/obbackup | ストレージディレクトリ。最大1024文字です。`file://`、`oss://`、`cos://`、`obs://`、`s3://`のいずれのプレフィックスも含める必要はありません。 |
| ossAccessKey | Object | 条件付き必須 | - | OSSアクセス情報。`backupStorageType`が`BACKUP_STORAGE_OSS`の場合にのみ指定してください。 |
| cosAccessKey | Object | 条件付き必須 | - | COSアクセス情報。`backupStorageType`が`BACKUP_STORAGE_COS`の場合にのみ指定してください。 |
| obsAccessKey | Object | 条件付き必須 | - | OBSアクセス情報。`backupStorageType`が`BACKUP_STORAGE_OBS`の場合にのみ指定してください。 |
| s3AccessKey | Object | 条件付き必須 | - | S3アクセス情報。`backupStorageType`が`BACKUP_STORAGE_S3`の場合にのみ指定してください。 |
| customBackupRangeList | Array | いいえ | [] | カスタムバックアップ範囲。カスタム範囲がない場合は省略または空配列を指定してください。 |
| advancedConfigList | Array | いいえ | [] | バックアップストレージの詳細設定。詳細設定がない場合は省略または空配列を指定してください。 |

<p>オブジェクトストレージの資格情報は機密情報に該当します。実際の資格情報をドキュメント、コードリポジトリ、または通常のログに記録しないでください。</p>

`logStorageMode`が`INDEPENDENT`の場合、以下の制約も満たす必要があります。

* 独立ログストレージは`BACKUP_STORAGE_FILE`または`BACKUP_STORAGE_S3`のみをサポートします。
* データバックアップとログバックアップのストレージルートディレクトリは同じであってはならず、互いに含み合うこともできません。
* `logBackupStorageBaseInfo`は必ず完全に記入してください。`logHostIdList`を個別に指定しない場合、OCPは`hostIdList`を再利用します。

| パラメータ | 型 | 説明 |
| --- | --- | --- |

**ObRecoverableInfoAggregationのデータ構造**

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| obQueryTimeScopeType | String | この応答で使用された時間範囲のタイプ。 |
| latestSevenDaysAggregation | Object | 詳細リスト。`LATEST_SEVEN_DAYS`、`LATEST_SIX_MONTHS`、`USER_DEFINED`がこのフィールドを使用します。 |
| ├─ obRecoverableSectionItems | Array | データバックアップポイント、ログバックアップ区間、実際の復元可能区間のリスト。 |
| latestMonthsAggregation | Object | 日単位で集計されたバックアップ情報。`MONTHS`がこのフィールドを使用します。 |
| ├─ dayFormatAndRecoverableItems | Object | Keyは`yyyy-MM-dd`、Valueはその日のバックアップ情報リストです。 |
| latestYearsAggregation | Object | 月単位で集計されたバックアップ統計。`YEARS`がこのフィールドを使用します。 |
| ├─ monthFormatAndRecoverableStatics | Object | キーは `yyyy-MM` で、値にはデータバックアップ数とログバックアップの累積時間が含まれます。 |

**ObRecoverableSectionItemのデータ構造**

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| obRecoverableSectionItemType | String | ノードタイプ。値は `FULL_DATA_BACKUP`、`INCREMENTAL_DATA_BACKUP`、`LOG_BACKUP`、および `RECOVERABLE` です。 |
| backupMode | String | バックアップモード。値は `PHYSICAL_BACKUP` または `LOGICAL_BACKUP` です。 |
| backupDimension | String | バックアップ次元。値は `CLUSTER` または `TENANT` です。 |
| dataBackupRecoverableInfo | Object | データバックアップ情報。ノードタイプがデータバックアップの場合にのみ有効です。`freezeTime`、`recoverableTime`、`dataVersion`、および `fullBackupSetId` を含みます。 |
| logRecoverableTimeInterval | Object | ログバックアップ区間。ノードタイプが `LOG_BACKUP` の場合にのみ有効です。`startTime` と `endTime` を含みます。 |
| realRecoverableTimeInterval | Object | 実際に復元可能な区間。ノードタイプが `RECOVERABLE` の場合にのみ有効です。`startTime` と `endTime` を含みます。 |

## 例

### リクエスト例

OSS内の過去7日間のバックアップ情報を解析する：

`POST /api/v2/backup/info?timeScopeType=LATEST_SEVEN_DAYS`

```json
{
  "obBackupStorageBaseInfo": {
    "backupStorageType": "BACKUP_STORAGE_OSS",
    "storageUrl": "example-bucket/obbackup",
    "ossAccessKey": {
      "endpoint": "oss-cn-hangzhou.aliyuncs.com",
      "accessKeyId": "${ACCESS_KEY_ID}",
      "accessKeySecret": "${ACCESS_KEY_SECRET}"
    }
  },
  "hostIdList": [3001],
  "logStorageMode": "SAME_AS_DATA"
}
```

ファイルシステムまたはNFSを使用する場合、ストレージ部分を次のように置き換えます：

```json
{
  "backupStorageType": "BACKUP_STORAGE_FILE",
  "storageUrl": "/data/obbackup"
}
```
