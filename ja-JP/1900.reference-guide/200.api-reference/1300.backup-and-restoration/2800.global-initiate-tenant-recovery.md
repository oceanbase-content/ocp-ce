# グローバルでテナントの復元を開始する

## 機能の概要

このAPIは、グローバルビューからテナントの復元を開始するために使用されます。[グローバルバックアップ情報の解析](2700.parse-global-backup-info.md) APIで解析されたオフラインテナントを、現在のOCPが管理するターゲットクラスタに復元します。ソースクラスタは現在のOCPが管理している必要はありません。

既存の「テナント/データベース/テーブルの復元を開始する」API(`POST /api/v2/ob/clusters/{id}/backup/restore`)と比較して、このAPIのリクエストパスではソースクラスタIDを指定する必要がなく、OCP間などのグローバルなオフライン復元シナリオに適しています。

インターフェースモデルには `ONLINE` と `OFFLINE` の2つの分岐が含まれています。グローバルオフライン復元シナリオでは、`backupTenantStatus`は固定で `OFFLINE` を使用し、`restoreOfflineTenantRequiredParam`を記入します。

## 呼び出しの説明

### インターフェース制約

* 呼び出し元はOCPアプリケーションサービスの認証を通過している必要があります。
* 呼び出し元は対象クラスタに対する更新権限を持ち、選択した解析ホストに対する読み取り権限を持っている必要があります。

### リクエストパス

`POST /api/v2/backup/restore`

### リクエストパラメータ

**RestoreTenantParamのデータ構造**

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
| --- | --- | --- | --- | --- |
| backupTenantStatus | String | はい | OFFLINE | バックアップテナントの状態。値は`ONLINE`または`OFFLINE`です。グローバルオフライン復元では常に`OFFLINE`を指定します。 |
| restoreOnlineTenantRequiredParam | Object | いいえ | - | オンラインテナント復元パラメータ。グローバルオフライン復元時は省略します。 |
| restoreOfflineTenantRequiredParam | Object | 条件付き必須 | - | `backupTenantStatus`が`OFFLINE`の場合は必須です。 |

**RestoreOfflineTenantRequiredParamのデータ構造**

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
| --- | --- | --- | --- | --- |
| backupMode | String | はい | PHYSICAL_BACKUP | バックアップモード。値は`PHYSICAL_BACKUP`または`LOGICAL_BACKUP`です。解析結果の値を使用してください。 |
| backupClusterName | String | はい | prod_cluster | バックアップソースクラスタ名。解析結果の`clusterName`から取得します。 |
| backupObClusterId | Long | 物理バックアップ必須 | 1001 | バックアップソースクラスタのOceanBaseクラスタID。解析結果の`obClusterId`から取得します。 |
| backupTenantName | String | はい | tenant_a | バックアップソーステナント名。解析結果の`tenantName`から取得します。 |
| backupObTenantId | Long | いいえ | 1002 | バックアップソーステナントのOceanBaseテナントID。解析結果の`obTenantId`から取得します。指定することを推奨します。 |
| restoreClusterId | Long | はい | 2001 | 対象クラスタの現在のOCPにおけるクラスタID。このフィールドはソースクラスタの`obClusterId`ではない点に注意してください。 |
| obBackupStorageBaseInfo | Object | はい | - | データバックアップストレージ情報。解析インターフェースで使用されたストレージ情報と一致している必要があります。データ構造については、[グローバルバックアップ情報の解析](2700.parse-global-backup-info.md) の **ObBackupStorageBaseInfoのデータ構造** を参照してください。 |
| hostIdList | LongArray | グローバル復元必須 | [3001] | データバックアップ解析ホストIDリスト。解析インターフェースで使用されたホストと一致している必要があります。 |
| logStorageMode | String | いいえ | SAME_AS_DATA | ログバックアップストレージモード。解析インターフェースと同じ意味です。`INDEPENDENT`は`PHYSICAL_BACKUP`にのみ適用されます。明示的に指定することを推奨します。 |
| logBackupStorageBaseInfo | Object | 条件付き必須 | - | `logStorageMode`が`INDEPENDENT`の場合は必須です。 |
| logHostIdList | LongArray | いいえ | [3002] | 独立ログバックアップ解析ホストIDリスト。省略または空配列を指定した場合は`hostIdList`を再利用します。 |
| restoreEndTime | DateTime | はい | 2026-09-09T09:30:00+08:00 | 復元時間。解析結果の実際の復元可能時間帯内にある必要があります。 |
| restoreTenantInfoParam | Object | はい | - | 対象テナントの定義。詳細については、**RestoreTenantInfoParamのデータ構造**を参照してください。 |
| storageId | Long | いいえ | 10 | 現在のOCPに既に設定されているバックアップストレージのID。アプリケーションサービスの呼び出し時も完全なストレージ情報を指定する必要があります。 |
| addSource | Boolean | いいえ | false | 読み込まれた指定の復元ソースを使用するかどうか。グローバルオフライン復元のデフォルト値は`false`です。 |

**RestoreTenantInfoParamのデータ構造**

| パラメータ | 型 | 必須 | サンプル値 | 説明 |
| --- | --- | --- | --- | --- |
| id | Long | いいえ | - | 対象テナントID。テナント全体のオフライン復元時は省略します。 |
| name | String | はい | tenant_a_restore | 対象テナント名。対象クラスタ内の既存テナント名と重複してはなりません。英字で始まり、英字、数字、アンダースコアのみを含み、長さは2～64文字である必要があります。 |
| primaryZone | String | いいえ | zone1 | 対象テナントのプライマリゾーン。 |
| zones | Array | はい | - | 対象テナントのゾーンとリソースプールの設定。少なくとも1つを指定してください。 |
| ├─ name | String | はい | zone1 | ゾーン名。 |
| ├─ replicaType | String | はい | FULL | レプリカタイプ。値は `FULL`、`LOGONLY`、`READONLY`、`COLUMNSTORE` です。 |
| ├─ resourcePool | Object | はい | - | リソースプールの設定。 |
| ├─ resourcePool.unitSpecName | String | はい | S1 | 現在のターゲットクラスタに既に存在するユニット仕様名。 |
| ├─ resourcePool.unitCount | Long | はい | 1 | ユニット数。 |
| restoreMethod | String | いいえ | full | 復元方法。値は `full` または `quick` で、デフォルト値は `full` です。`quick` を使用する場合は、OceanBase のバージョンが V4.3.3 以上である必要があります。 |
| enableDynamicPartition | Boolean | いいえ | true | 動的パーティションを有効にするかどうか。デフォルト値は `true` です。この機能を使用するには、OceanBase のバージョンが V4.3.5.2 以上である必要があります。 |

### 解析結果と復元パラメータのマッピング

| `/backup/info` の戻り値フィールド | `/backup/restore` のリクエストフィールド | 説明 |
| --- | --- | --- |
| `contents[].clusterName` | `backupClusterName` | ソースクラスタ名。 |
| `contents[].obClusterId` | `backupObClusterId` | ソースクラスタの OceanBase クラスタ ID。物理バックアップ・リストアでは必須です。 |
| `contents[].tenantBackupInfos[].tenantName` | `backupTenantName` | ソーステナント名。 |
| `contents[].tenantBackupInfos[].obTenantId` | `backupObTenantId` | ソーステナントの OceanBase テナント ID。 |
| `...obRecoverableSectionItems[].backupMode` | `backupMode` | `RECOVERABLE` ノードに対応するバックアップモードを選択します。 |
| `...realRecoverableTimeInterval` | `restoreEndTime` | `startTime` と `endTime` の間から復元時間を選択します。 |
| 解析リクエスト内の `obBackupStorageBaseInfo` | 同名フィールド | 2回の呼び出しで同じデータバックアップ保存情報を使用します。 |
| 解析リクエスト内の `hostIdList` | 同名フィールド | 2回の呼び出しでバックアップ保存にアクセスできる現在の OCP ホストを使用します。 |
| 解析リクエスト内のログストレージフィールド | 同名フィールド | 独立したログ保存を使用する場合は、設定を一致させてください。 |

<main id="notice" type='notice'>
<h4>注意</h4>
<p>解析結果の <code>clusterId</code> を <code>restoreClusterId</code> と混同しないでください。OCP を跨ぐオフラインバックアップの <code>clusterId</code> は通常空です。<code>restoreClusterId</code> には、現在の OCP 内のターゲットクラスタの ID を入力してください。</p>
</main>

### 戻り値

**基本データ構造**

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| data | Object | 復元タスクの送信結果。詳細は **BackupCommonResponseのデータ構造** を参照してください。 |
| successful | Boolean | リクエストが成功したかどうか。 |
| timestamp | DateTime | サーバーがリクエストを完了したタイムスタンプ。 |
| duration | Long | サーバーがリクエストを処理した時間。単位はミリ秒。 |
| status | Integer | HTTP ステータス規格に準拠するステータスコード。 |
| traceId | String | リクエストの Trace ID。問題の調査に使用されます。 |
| server | String | リクエストに応答した OCP ノードのアドレス。 |

**BackupCommonResponseのデータ構造**

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| obBackupTaskType | String | タスクタイプ。このインターフェースが成功した場合は `RESTORE` です。 |
| backupObjectOpsResultList | Array | 操作結果リスト。 |
| ├─ obBackupObjectList | Array | 操作対象リスト。空の場合があります。 |
| ├─ beSuccessful | Boolean | この操作が正常に送信されたかどうか。 |
| ├─ taskIdList | LongArray | 復元タスク ID リスト。 |
| ├─ errorCode | Object | バックアップ・リストアのエラーコード。成功した場合は空の場合があります。 |
| ├─ hint | String | ヒント情報。成功した場合は空の可能性があります。 |

## 例

### リクエスト例

以下の例では、[グローバルバックアップ情報を解析する](2700.parse-global-backup-info.md) インターフェースで解析されたOSS物理バックアップを使用して、`tenant_a` を現在のOCPのターゲットクラスタに復元します。

`POST /api/v2/backup/restore`

```json
{
  "backupTenantStatus": "OFFLINE",
  "restoreOfflineTenantRequiredParam": {
    "backupMode": "PHYSICAL_BACKUP",
    "backupClusterName": "prod_cluster",
    "backupObClusterId": 1001,
    "backupTenantName": "tenant_a",
    "backupObTenantId": 1002,
    "restoreClusterId": 2001,
    "obBackupStorageBaseInfo": {
      "backupStorageType": "BACKUP_STORAGE_OSS",
      "storageUrl": "example-bucket/obbackup",
      "ossAccessKey": {
        "endpoint": "oss-cn-hangzhou.aliyuncs.com",
        "accessKeyId": "${ACCESS_KEY_ID}",
        "accessKeySecret": "${ACCESS_KEY_SECRET}"
      }
    },
    "hostIdList": [3001],
    "logStorageMode": "SAME_AS_DATA",
    "restoreEndTime": "2026-09-09T09:30:00+08:00",
    "restoreTenantInfoParam": {
      "name": "tenant_a_restore",
      "primaryZone": "zone1",
      "zones": [
        {
          "name": "zone1",
          "replicaType": "FULL",
          "resourcePool": {
            "unitSpecName": "S1",
            "unitCount": 1
          }
        }
      ],
      "restoreMethod": "full",
      "enableDynamicPartition": true
    },
    "addSource": false
  }
}
```

### レスポンス例

```json
{
  "data": {
    "obBackupTaskType": "RESTORE",
    "backupObjectOpsResultList": [
      {
        "beSuccessful": true,
        "taskIdList": [4001]
      }
    ]
  },
  "duration": 51,
  "server": "10.0.0.10",
  "status": 200,
  "successful": true,
  "timestamp": "2026-09-09T10:05:00.051+08:00",
  "traceId": "5962f337662d4043"
}
```

## 注意事項

* 両インターフェースのストレージ情報と解析ホストは一致している必要があります。そうでない場合、復元前の検証では解析結果を再現できない可能性があります。
* `successful=true` および HTTP 200 は、インターフェース処理が成功したことを示すだけです。復元の最終結果は、`taskIdList` に対応するタスクの状態に基づいて判断する必要があります。
* 解析インターフェースが返すデータのバックアップポイント、ログバックアップ区間、および `RECOVERABLE` 区間の意味は異なります。復元を実行する際には `RECOVERABLE.realRecoverableTimeInterval` を使用し、単一のデータバックアップポイントのみに基づいて時間を選択しないでください。
* オブジェクトストレージのネットワーク接続性、権限、およびリージョン設定は呼び出し側の環境によって決定されます。インターフェース自体は、呼び出し側に代わってクロス環境のネットワークや認可を確立するものではありません。
