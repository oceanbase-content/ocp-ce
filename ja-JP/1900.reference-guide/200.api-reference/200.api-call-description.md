# API呼び出しの説明

本記事では、HTTPを使用してOCPのオープンAPIを呼び出す方法について説明します。"クラスタリストの取得"インターフェースの呼び出しを例とします。

## リクエスト構造

完全なHTTPリクエストには、**リクエストURI**、**<UI-TERM key="ocp-v2.Alarm.Channel.Detail.RequestMethod">リクエストメソッド</UI-TERM>**、**リクエストヘッダー**、**リクエストボディ**が含まれます。

## リクエストURI

リクエストURIは以下の部分で構成されます：

```code
{scheme}://{endpoint}/{resource-path}?{query-string}
```

|      フィールド       |                                       説明                                        |
|---------------|---------------------------------------------------------------------------------|
| scheme        | 伝送プロトコルを指定します。通常は `http` または `https` です。                                                   |
| endpoint      | OCPのサービスアドレスです。例えば `xxx.xxx.xxx.xxx:8080` のように、具体的なデプロイメントによって決定されます。                                   |
| resource-path | インターフェースのリソースパスです。各インターフェースのリソースパスについては、対応するインターフェースドキュメントの"リクエストパス"セクションを参照してください。"クラスタリストの取得"のリソースパスは `/api/v2/ob/clusters` です。 |
| query-string  | クエリパラメータです。オプションで、`a=10&b=hello` のような形式で、複数のキーと値のペアで構成されます。query-string は resource-path と `?` で区切られます。    |

完全な" **クラスタリストの取得** "のURI例は以下のとおりです：

```java
http://xxx.xxx.xxx.xxx:8080/api/v2/ob/clusters
```

## リクエストメソッド

HTTPプロトコルのメソッドです。GET、PUT、POST、DELETEが含まれます。各インターフェースドキュメントでは、インターフェースのリクエストメソッドについて詳しく説明されています。

例えば："クラスタリストの取得"のリクエストパスは `GET /api/v2/ob/clusters` です。つまり、このインターフェースのリクエストメソッドは"GET"です。

## リクエストヘッダー

言語や認証情報など、リクエストに関する追加情報を含みます。

|       名前        | 必須 |                              説明                               |                   例                   |
|-----------------|----|---------------------------------------------------------------|----------------------------------------|
| Content-Type    | はい  | メッセージボディのタイプです。OCPは統一的にapplication/jsonタイプのメッセージボディを使用します。                      | application/json                       |
| Accept-Language | いいえ  | クライアントがサポートする言語です。OCPのオープンAPIは国際化をサポートしており、クライアントの言語設定に基づいて、指定された言語オプションの内容を返します。       | en-US, en, q=0.9 zh-CN |
| Authorization   | はい  | 認証情報です。OCPのオープンAPIは、HTTP規格のBasic認証を使用して認証します。ユーザー名とパスワードはBase64規格でエンコードされます。 | Basic Zm9vOmJhcg==                     |

## リクエストボディ

リクエストボディはオプションです。サーバーに送信する業務データを含みます。OCPのオープンAPIは、統一的にJSON形式のリクエストボディを使用します。

## 認証の説明

OCPが公開するAPIのクライアント認証では、AK/SKとHTTP Basicの2種類の認証モードをサポートしています。

* HTTP Basic認証モード

  呼び出し時には、「リクエストヘッダー」の`Authorization`プロパティを使用して、ユーザー名/パスワードのBase64エンコードを渡す必要があります。

  例えば、ユーザーfooのパスワードがbarだとします。ユーザーfooを使用してOCPの公開APIを呼び出す場合、次のようなリクエストヘッダーを渡す必要があります：

  ```java
  Authorization: Basic Zm9vOmJhcg==
  ```

  ここで、`Zm9vOmJhcg==`は`foo:bar`のBase64エンコードです。

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>HTTP Basic認証モードではパスワードが平文で送信されるリスクがあるため、AK/SK認証モードの使用を推奨します。</p>
  </main>

* AK/SK認証モード

  AK/SK認証モードは、HTTPでのパスワードの平文伝送を回避し、パスワードを共有することなく他者にログイン権限を付与することも可能にします。

  詳細については[AK/SK署名の生成ルール](../200.api-reference/300.ak-sk-sign-roles.md)を参照してください。

## 戻り値構造

公開APIが返すデータは、統一されたデータ構造を採用しています（一部の特殊なAPIを除く）。基本的な戻り値のデータ構造は以下の通りです：

|     パラメータ      |    型    |           説明            |
|-------------|----------|-------------------------|
| data        | Object   | "単一値データ"または"リストデータ"または"ページネーションデータ" |
| ├─ contents | Array    | ├─  前の行のパラメータに対する従属関係を表す       |
| successful  | Boolean  | リクエストが成功したかどうか                  |
| timestamp   | Datetime | サーバーがリクエストを完了したタイムスタンプ             |
| duration    | Integer  | サーバーがリクエストを処理した時間（ミリ秒）          |
| status      | Integer  | HTTPステータスコード    |
| traceId     | String   | リクエストのTrace Id。問題の調査に使用されます。    |
| server      | String   | リクエストに応答したサーバーの識別子             |

## 呼び出し例

**curl**

curlツールを使用して公開APIのインターフェースを呼び出すことができます。以下の例では、ユーザーadmin:helloを使用し、OCPアプリケーションのアドレスを`xxx.xxx.xxx.xxx`、ポート情報を`8080`として、テナントリストを照会するインターフェースにアクセスします。ここで、`YWRtaW46aGVsbG8=`は`admin:hello`のBase64エンコードです。

```java
curl "http://xxx.xxx.xxx.xxx:8080/api/v2/ob/clusters/1/tenants"  \
  -H "Authorization: Basic YWRtaW46aGVsbG8="
```

curlは平文のパスワードを使用した呼び出し方法も提供しています。

```java
curl "http://xxx.xxx.xxx.xxx:8080/api/v2/ob/clusters/1/tenants"  \
  --user admin:hello
```

  <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>平文パスワードの使用はセキュリティを低下させるおそれがあります。慎重にご利用ください。</p>
  </main>

## 国際化に関する説明

OCPのオープンAPIは国際化をサポートしています。クライアントの言語設定に応じて、対応する言語のコンテンツを返します。詳細については、各APIドキュメントを参照してください。そこでは、各プロパティが国際化をサポートしているかどうかが説明されています。

OCPのオープンAPIは、「リクエストヘッダー」の`Accept-Language`プロパティを使用して、クライアントの言語オプションを指定します。

## レート制御に関する説明

OCPはレート制御機能を提供し、ユーザーがOCPに過度に頻繁にアクセスするのを防ぎます。ユーザー作成時に、システム管理者はOCPユーザーにレート制御ポリシーを設定できます。レート制御の対象となるリソースには、静的リソースを除くHTTPリクエストを含むグローバルなパスが含まれます。細かい粒度のアクセス制御では、OCP内の異なるリソースタイプに対してアクセス回数の制限を設定できます。レート制御の時間枠は、10秒、1分、1時間、1日をサポートしています。

<!-- ![1](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/9246790261/p273248.png) -->

システムパラメータ`ocp.iam.rate-limit.enabled`を使用して、レート制御機能を有効または無効にします。デフォルトは`true`、つまりレート制御機能は有効です。

レート制御で許可された場合、返されるヘッダーには以下が含まれます：

1. `RateLimit-Limit`：現在の時間枠内のアクセス回数の上限。例："10"。

2. `RateLimit-Remaining`：現在の時間枠内の残りアクセス回数。例："7"。

3. `RateLimit-Reset`：現在の時間枠がリセットされるまでの残り時間。例："53"。

特定の時間枠内において、ユーザーによる対応するリソースインターフェースへのアクセス頻度が設定値を超え、レート制御によりリクエストが拒否された場合、HTTPリターンコードは`429`となります。この場合の戻り値は次のとおりです：

```sql
{
    "duration":0,
    "error":{
        "code":0,
        "message":"リクエスト回数が多すぎます。現在のレート制御時間窓内のリクエスト上限を超えています"
    },
    "server": "a83ad33525",
    "status":429,
    "successful":false,
    "timestamp":"2020-12-03T09:38:24.194+08:00",
    "traceId":""
}
```
