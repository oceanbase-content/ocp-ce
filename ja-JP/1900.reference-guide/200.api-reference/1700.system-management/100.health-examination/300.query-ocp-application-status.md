# OCPアプリケーションのステータスを照会する

## **<UI-TERM key="ocp-v2.Tenant.New.ServiceName.Description">製品説明</UI-TERM>**

OCPアプリケーションのステータスを照会します。このインターフェースは、OCPアプリケーションの各モジュールのステータスをチェックし、すべてのステータスが正常であるかどうかを返します。

## **呼び出し説明**

**インターフェース制約**

呼び出し元はOCPアプリケーションサービスの認証を通過している必要があります。

**リクエストパス**

`GET /api/status`

**リクエストパラメータ**

|             パラメータ              |   型    | 必須 | サンプル値  |                                                                                        説明                                                                                         |
|-----------------------------|---------|----|------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| includeUnavailableComponent | Boolean | いいえ  | true | 利用不可なモジュール名を照会するかどうかを指定します。 * デフォルトはfalseで、この場合はアプリケーションの健全状態のみを返します。   * trueに設定した場合、不健全なモジュールが存在すると、そのモジュール名も同時に返されます。    |

**戻り値**

戻り値はシンプルテキストです。

API利用可能状態のキーワード、デフォルトはokay

API利用不可状態のキーワード、デフォルトはbad
**<UI-TERM key="ocp-v2.Alarm.Template.Detail.Description">説明</UI-TERM>**

返されるテキストは、OCPシステムパラメータで設定できます。ocp.health-check.status.available-keywordでAPI利用可能状態のキーワードを設定し、ocp.health-check.status.unavailable-keywordでAPI利用不可状態のキーワードを設定します。

## **例**

**リクエスト例**

* アプリケーションの健全状態を照会します。利用不可なモジュールが存在する場合は、そのモジュール名も照会できます。

```code
GET /api/status?includeUnavailableComponent=true
```

**返却例**

* アプリケーションが健全な場合：

```code
okay
```

* アプリケーションが不健全な場合：

```code
bad
```

* アプリケーションが不健全で、かつモジュール名をクエリするリクエストがある場合：

```code
bad monitordb
```
