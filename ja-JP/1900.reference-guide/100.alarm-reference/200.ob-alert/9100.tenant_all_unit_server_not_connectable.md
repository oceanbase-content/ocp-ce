# tenant_all_unit_server_not_connectable OceanBaseテナントが接続できない

## アラートの概要

OBProxy V4.3.3.0から、テナントサービス名に基づく読み書き分離がサポートされています。OBProxyはOCP Serverにリクエストしてすべてのテナントのサービス名情報を取得し、同一サービス名下のプライマリ・スタンバイテナント間で読み書き分離を実現します。スタンバイテナントが利用不能な場合でも、OCPはそれを検知できず、引き続きそのスタンバイテナントのサービス名をOBProxyに返します。その結果、OBProxyはSQL読み取りリクエストを継続的にスタンバイテナントにルーティングし、業務上の読み取り処理でリクエスト失敗が繰り返し発生します。

上記のシナリオに対処するため、OCPは以下の機能を備えた対策を立案・実装する必要があります。

1. スタンバイテナントの利用不能を検出できること。
2. スタンバイテナントが利用不能な場合、そのテナントをOBProxyに返すサービス名情報から除外し、OBProxyが再度そのテナントにルーティングしないようにすること。

この対策はアラートによってトリガーされます。このアラートは上記のシナリオに特化しており、対策を設定したスタンバイテナントの接続性をチェックし、テナントが接続できないと判断された場合にアラートを発報します。

## アラートの仕組み

このアラートの前提条件は以下の通りです。

1. テナントがスタンバイテナントであること。
2. テナントに`サービス名情報から生存確認失敗テナントを削除`対策が設定されていること。
3. テナントのサービス名がVALID状態であること。

次の表は、このアラートのモニタリングロジックに関連する主要パラメータを示しています。

| パラメータ | 値  |
|------|------|
| モニタリング指標 | ob_tenant_any_unit_connectable。この指標はOceanBaseテナントが接続可能かどうかを示します。パラメータ値が`1`の場合はテナントが接続可能、`0`の場合はテナントが接続不可でアラートがトリガーされます。  |
| モニタリング式 | ```max(ob_tenant_any_unit_connectable{@LABELS}) by (@GBLABELS)```  |
| 取得指標  | ob_tenant_any_unit_connectable  |
| データソース | OCPの定期タスクがテナントのUnit Server状態をチェックし、すべてのUnit Serverポートへの接続に失敗した場合、テナントが接続不可と判断し、`ob_tenant_any_unit_connectable = 0`を記録します。成功した場合は`ob_tenant_any_unit_connectable = 1`を記録します。 |
| 取得周期 | 5秒  |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：larm_template_id=0:ob_cluster=ob4353-22:tenant_name=standby_tenant OceanBaseテナントに接続できません。

* **アラート詳細**

  * テンプレート：クラスタ：${ob_cluster_name}、テナント：${tenant_name}、アラート：${alarm_name}。テナントのすべてのUNITノードのSQLポートへの接続に失敗しました。
  * サンプル：クラスタ：ob4353、テナント：standby_tenant、アラート：OceanBaseテナントに接続できません。テナントのすべてのUNITノードのSQLポートへの接続に失敗しました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OceanBaseテナントUNITへの接続は可能か：\${recover_value}
  * サンプル：アラート：OceanBaseテナントに接続できません、OceanBaseテナントUNITへの接続は可能か：1

## システムへの影響

* OCPへの影響：OCPがプランを開始し、当該テナントをサービス名の情報から削除し、OBProxyに対して非表示にします。
* OBProxyへの影響：OBProxyは当該テナントを非表示とし、そのテナントからの読み取りトラフィックを同じサービス名の他のテナントに切り替えます。
* アプリケーションへの影響：テナントに接続できないため、アプリケーションが当該テナントに接続できなくなる可能性があります。OBProxyによるトラフィックの切り替えにより、アプリケーションの読み取りトラフィックは自動的に別のテナントに転送されます。

## 考えられる原因

データセンターの障害により、テナントのすべてのホストがダウンした場合。

## 解決策

1. ユーザーはテナントの異常原因を自己調査し、テナントを復旧する必要があります。
2. テナントを復旧した後、OCP内でテナントのサービス名を変更し、再びVALID状態に戻してOBProxyに表示されるようにします。
