# arbitration_service_unavailable アービトレーションサービスが利用できません

## アラートの概要

アービトレーションサービスのプロセスが利用可能かどうかを監視します。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| 監視指標 | arbitration_service_available。この指標はアービトレーションサービスのプロセスが利用可能かどうかを示します。指標値が `0` の場合、プロセスは利用可能です。指標値が `1` の場合、プロセスは利用できず、アラートがトリガーされます。 |
| 監視式 | ```sum(arbitration_service_available{@LABELS}) by (@GBLABELS)```   |
| 取得指標 | arbitration_service_available |
| 指標の出典 | OCP-Agentは、ローカルのobserverプロセスが起動しているかどうか、およびアービトレーションサービスのポートが占有されていないかどうかをチェックします。 |
| 取得間隔 | 5秒 |

## ルール情報

| 監視式 | デフォルトしきい値 | 継続時間 | 検出サイクル | 解消サイクル |
| --------- | -------- | -------- | -------- | -------- |
| arbitration_service_available | 0 | 120秒 | 60秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| ------------ | -------- | ------ |
| 監視指標の式に基づく | 重大 | アービトレーションサービス |

## アラートテンプレート

* **アラートの概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:host=xxx.xxx.xxx.xxx:svr_port=2882 アービトレーションサービスが利用できません

* **アラートの詳細**

  * テンプレート：クラスタ：アービトレーションサービス \${svr_ip}:${svr_port} は利用できません。
  * サンプル：クラスタ：アービトレーションサービス xxx.xxx.xxx.xxx:2882 は利用できません。

* **アラートの回復**

  * テンプレート：アラート：${alarm_name}、アービトレーションサービスの利用可能性：\${recover_value}
  * サンプル：アラート：アービトレーションサービスが利用できません、アービトレーションサービスの利用可能性：0

## システムへの影響

アービトレーションサービスが利用できない場合、アービトレーションを有効にしているテナントは信頼性の高い高可用性保証を受けられません。テナントのレプリカに障害が発生した場合、テナントは正常にアービトレーションサービスを提供することが保証されません。

## 考えられる原因

* アービトレーションサービスが稼働しているホストがダウンした。
* ファイアウォールが有効なため、外部からアービトレーションサービスポートにアクセスできない。

## 解決策

1. アービトレーションサービスのobserverプロセスが異常終了した場合、再起動を試みます。プランを実行することで迅速に対処できます。詳細な操作については、[アラート対応プラン](../500.appendix/400.execute-the-plan.md)を参照してください。

   <main id="notice" type='explain'>
     <h4>イベント発生後30分以内に1回のみ再起動します。</h4>
     <p></p>
   </main>

2. アービトレーションサービスが稼働しているホストが正常に動作しているか確認します。ダウンしている場合は、ホストを再起動し、OCPの管理画面からアービトレーションサービスを再起動します。

3. ホストが正常に動作している場合、アービトレーションサービスプロセスが存在するか、アービトレーションサービスポートが正常にリッスンしているか、ファイアウォールが他のIPアドレスからのアクセスを遮断していないかなどを調査する必要があります。
