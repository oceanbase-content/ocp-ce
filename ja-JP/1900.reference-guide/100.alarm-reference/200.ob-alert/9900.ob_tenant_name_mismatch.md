# ob_tenant_name_mismatch OceanBaseテナントのテナント名が変更された

## アラートの概要

このアラートは、OceanBaseテナントのクラスタ内での実際の名前と、OCPメタデータベースに記録されているテナント名が一致しない場合に検出するために使用されます。OCPがテナント情報を同期する際に、特定のテナントがOceanBase側で名前が変更されているにもかかわらず、OCP側では古い名前のままであることが検出された場合、このアラートがトリガーされ、管理者に注意を促し、テナント名の同期を行うよう促します。

## アラートテンプレート

* **アラート概要**
  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：ob_cluster=obcluster1:tenant_name=old_tenant:ob_tenant_id=1001 OceanBaseテナントのテナント名が変更された

* **アラート詳細**
  * テンプレート：クラスタ：${ob_cluster_name}、テナント：${tenant_name}:${ob_tenant_id}、アラート：${alarm_name}。テナント${tenant_name}:${ob_tenant_id}のテナント名が${actual_tenant_name}に変更されました。
  * サンプル：クラスタ：obcluster1、テナント：old_tenant:1001、アラート：OceanBaseテナントのテナント名が変更された。テナントold_tenant:1001のテナント名がnew_tenantに変更されました。

## システムへの影響

テナント名の不整合は、以下の問題を引き起こす可能性があります：

* OCPに表示されるテナント名が誤っている：コンソールや監視などには古いテナント名が表示され、OceanBaseの実際のテナント名と一致しないため、誤操作や誤判断を招く可能性があります。

* 同期と運用が制限される：テナント名が一致しない場合、OCPはテナント情報の同期をスキップする可能性があり、メタ情報が古くなる可能性があります。テナント名に依存する一部の運用や更新が失敗する可能性があります。

## 考えられる原因

* OceanBase側で `ALTER TENANT ... RENAME GLOBAL_NAME TO ...` などのリネーム操作を実行し、OCPがそれに応じて更新していない場合。

* 複数の環境や複数のOCPが同一クラスタを管理する場合、一方でテナント名を単独で変更したことにより、OCPのメタデータとクラスタの実際の状態が一致しなくなった場合。

## 解決策

1. アラート情報の確認：アラートに記載されているクラスタ名（ob_cluster_name）、OCP側のテナント名（tenant_name）、テナントID（ob_tenant_id）、および実際の名前（actual_tenant_name）を確認し、どのテナントがリネームされたかを特定します。

2. 予期された変更かどうかの確認：OceanBaseでそのテナントの現在の名前を確認します：

   ```sql
   SELECT tenant_id, tenant_name FROM oceanbase.DBA_OB_TENANTS WHERE tenant_id = <ob_tenant_id>;
   ```

   もし tenant_name が既に actual_tenant_name であれば、OceanBase側で名前が変更されたものの、OCPが同期していないことを意味します。

3. OCPコンソールの該当テナントの詳細/編集ページで、テナント名を actual_tenant_name（OceanBaseと一致させる）に変更し、保存後、次回の同期を待ちます。これにより、アラートは解消されるはずです。

4. OCP側の名前を保持したい場合：OceanBase側でそのテナント名を、OCPに記録されている名前に戻す必要があります（ビジネス接続文字列やアプリケーション設定への影響を評価する必要があります）。戻した後、再度同期を行うと、アラートは解消されます。

5. 検証：OCP上のそのテナント名がOceanBaseと一致していることを確認すると、アラートは自動的に解消されます（解消までの時間は約300秒です）。それでもアラートが残っている場合は、過去のアラートが複数存在するか、他のテナントでも名前が一致しない場合がないか確認してください。
