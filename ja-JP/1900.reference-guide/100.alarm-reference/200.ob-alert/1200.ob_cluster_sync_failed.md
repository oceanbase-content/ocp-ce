# ob_cluster_sync_failed OceanBaseクラスタ情報の取得に失敗しました

## アラートの概要

OCPは30秒ごとにOceanBaseクラスタへの接続を試み、クラスタのメタデータをOCPに同期します。同期に失敗した場合、このアラートがトリガーされます。

## アラートの仕組み

このアラートの報告は、5秒間隔の定期タスクによって実現されます。その動作原理は以下の通りです：

1. OCP-Serverは、OceanBaseクラスタへの接続可能性をチェックします。

   * 接続可能な場合、ステップ2に進みます。

   * 接続不可な場合、チェックプロセスを終了し、アラートをトリガーしません。

2. OCPが記録しているOceanBaseクラスタの状態がUnavailableの場合、OCP-Serverはその状態をRunningに更新しようと試みます。

   * 更新に失敗した場合、アラートをトリガーします。

   * 更新に成功した場合、ステップ3に進みます。

3. ゾーン、クラスタ、ホストなど、クラスタのその他の情報を同期します。同期に失敗した場合、アラートをトリガーします。

| パラメータ | 値 |
|-------|---------------|
| モニタリング指標 | ob_cluster_sync。この指標はOceanBaseクラスタ情報の取得に失敗したかどうかを示します。指標値が`1`の場合は取得成功、指標値が`0`の場合は取得失敗であり、アラートがトリガーされます。 |
| モニタリング式 | ```max(ob_cluster_sync{ob_cluster_status=~"RUNNING\|UNAVAILABLE\|OPERATING",@LABELS}) by (@GBLABELS)```  |
| 取得指標 | ob_cluster_sync |
| 指標ソース | OCP-ServerはすべてのOceanBaseクラスタの接続状態をチェックします。接続がタイムアウトまたは異常な場合、検出に失敗します。 |
| 取得サイクル | 5秒 |

| モニタリング指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| -------- | -------- | -------- | -------- | -------- |
| ob_cluster_sync | 0 | 60秒 | 15秒 | 5分 |

## システムへの影響

原因によって異なります。

* OCPメタデータとOceanBaseクラスタ情報が一致しない場合、その後のOCP運用操作に影響を与える可能性があります。

* OceanBaseクラスタの障害により同期できない場合、ユーザーサービスに影響を与える可能性があります。

## 考えられる原因

* OceanBaseクラスタで管理されているIDC/リージョン情報とOCPホストで管理されているIDC/リージョン情報が一致していません。

* OceanBaseクラスタの障害により同期できません。この場合、ob_cluster_status_check_failedアラートも発生します。

## 解決策

アラートに記載されている失敗原因に基づいて障害を排除し、障害が解消されればOCPはクラスタ同期を回復するはずです。

1. OceanBaseクラスタの障害が同期不能の原因であるか確認します。

   その原因である場合は、ob_cluster_status_check_failedアラートも同時に報告されます。

   この場合、まず[ob_cluster_status_check_failed OBクラスタ状態検出失敗](../200.ob-alert/300.ob_cluster_status_check_failed.md) アラートの対処方法を参照して障害を排除し、5分待ってアラートが引き続き報告されるか観察します。

   * はいの場合、他の問題があるため、次の手順に進みます。

   * いいえの場合、問題は解決されています。

2. OceanBaseクラスタ内のゾーンのIDC/リージョン情報がOCPメタデータに存在するか、およびIDC/リージョンの関連性とOCPメタデータが一致しているかを確認します。以下の情報を参照して確認できます。

   * OCPが管理するホスト/リージョン/IDCのデータテーブルは以下のとおりです：

     * compute_host ホスト

     * compute_idc データセンター

     * compute_region 地域

   * OCP MetaDBで全リージョン/IDC情報を照会するSQLコマンドは以下のとおりです：

     ```sql
     -- OCP MetaDBが管理するIDCとリージョン情報を照会する
     SELECT r.`name` AS region, i.`name` AS idc
      FROM compute_region r JOIN compute_idc i
      ON r.id=i.region_id;
     ```

   * OceanBaseクラスタでゾーンのIDC/リージョン情報を照会するSQLコマンドは以下のとおりです：

     ```sql
     -- OceanBaseクラスタ内のゾーンのIDCとリージョン情報を照会する
     SELECT `zone`,
       MAX(CASE `name` WHEN 'region' THEN `info` ELSE '' END ) `region`,
       MAX(CASE `name` WHEN 'idc' THEN `info` ELSE '' END ) `idc`
      FROM oceanbase.__all_zone WHERE `zone` <> '' GROUP BY `zone` ;
     ```

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>OCP MetaDBが管理するリージョン/IDCの関連付けとOceanBaseクラスタ内のゾーンのリージョン/IDCが競合する場合、クラスタの同期は失敗します。その場合は次の手順を実行してください。ただし、OceanBaseクラスタ内のゾーンのIDC設定が空の場合は、クラスタ同期に影響しません。</p>
      </main>

3. OceanBaseクラスタのゾーンのIDC/リージョンなどは論理的な区分であり、OceanBaseクラスタ内のIDC/リージョン情報に変更が生じた場合、OCP MetaDBで手動で同期する必要があります。

   以下の情報を例にします：

   * IDCの旧名は'old idc'、変更後の名前は'zue'です。
   * Regionの旧名は'old region'、変更後の名前は'SHANGHAI'です。

   1. OCP MetaDBクラスタ（デフォルトのクラスタ名はobcluster）のocp_metaテナントのrootユーザーでocp_metaデータベースにログインし、変更履歴が存在するかどうか確認します。

      * 名前がSHANGHAIのRegionが存在するかどうかを照会します：

        ```sql
        select * from compute_region where name='SHANGHAI';
        ```

      * 名前がzueのIDCが存在するかどうかを照会します：

        ```sql
        select * from compute_idc where name='zue';
        ```

      存在しない場合は、以下のコマンドを実行して新しいRegionとIDCを追加します。存在する場合は、次の手順に進みます。

      ```sql
      # 新しいRegionを追加する
      insert into compute_region (`name`, `description`) values ('SHANGHAI', 'SHANGHAI region');
      # 新規IDCの追加
      insert into compute_idc (`name`, `description`, `region_id`) select 'zue', 'zue idc', id from compute_region where name='SHANGHAI';
      ```

   2. OCPゾーンのリージョンとIDC情報を修正します。

      ```sql
      update ob_zone set idc_id = (select id from compute_idc where name='zue') where name='your zone name' and cluster_id= your cluster id in ocp;
      ```

   3. OCP compute_hostのリージョンとIDC情報を修正します：

      ```sql
      update compute_host set idc_id = (select id from compute_idc where name='zue') where inner_ip_address in (ips of the hosts);
      ```

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OCPメタデータに既存のリージョンやIDCデータは、他のOceanBaseクラスタで参照されている可能性があります。コマンドラインでOceanBaseクラスタのリージョンやIDC情報を変更した場合は、まずOCPメタデータにそのリージョンとIDC情報を新規追加し、その後クラスタのゾーンおよびホストデータに関連付けてください。OCPメタデータ内の既存のリージョンやIDCレコードを変更しないでください。これにより、他のクラスタが誤ったリージョンやIDCに関連付けられ、障害が発生するのを防ぐことができます。</p>
    </main>
