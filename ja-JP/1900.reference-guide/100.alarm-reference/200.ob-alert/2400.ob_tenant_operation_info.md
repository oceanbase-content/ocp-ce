# ob_tenant_operation_info OceanBaseテナント運用保守操作リマインダー

## アラートの概要

ユーザーがOCPを通じて実行するすべてのテナントレベルの運用保守操作により、このイベントがトリガーされます。

運用保守タスクリスト：

* テナントの作成
* テナントのロック/アンロック
* テナントの削除
* レプリカの追加
* レプリカの変更（ユニット構成/数）
* レプリカの削除
* アクティブセッション履歴レポート
* 即時バックアップ

## アラートの仕組み

なし。

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${operation_result}
  * サンプル：alarm_template_id=0:ob_cluster=obcluster-1:tenant_name=tenant-1:operation_name=Create network standby tenant SUCCESS

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、アラート：\${operation_name} \${operation_result}、操作者 ${operator}、実行結果：\${operation_result}。
  * サンプル：クラスタ：obcluster-1、アラート：Create network standby tenant SUCCESS、操作者 admin、実行結果：success。

ここで：

*   ${alarm_target}：アラートが発生したオブジェクトを表します。形式は ob_cluster=xxxxxxx です。ob_cluster はアラートが発生したクラスタの名前です。

*   ${operation_name}：実行された操作を表します。

*   ${operation_result}：操作の結果を表します。値は SUCCESS（操作が成功したことを示す）と FAILED（操作が失敗したことを示す）です。

*   操作者 ${operator}：この操作を実行したユーザー名を表します。

## システムへの影響

影響ありません。

## 考えられる原因

一般的に、OCP を使用してテナントレベルの運用保守を行う際に発生します。例えば、レプリカの追加や削除などのシナリオです。

## 対処方法

操作結果が SUCCESS の場合は特に処理は不要です。操作結果が FAILED の場合は、失敗の原因に応じて後続の操作を実行してください。
