# agent_process_count_abnormal ocp-agent プロセス数異常

## アラートの概要

ocp-agentは、ocp_agentd、ocp_mgragent、ocp_monagentの3つのプロセスで構成されています。いずれかの種類のプロセス数が1を超えた状態が60秒間継続した場合、ocp-agent プロセス数異常アラートが発報されます。アラートの詳細には、具体的な異常なプロセス名が表示されます。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | agent_process_count。この指標は、ocp_agentd/ocp_mgragent/ocp_monagent 各プロセスの数を表します。プロセス数が `1` 以外の場合、アラートがトリガーされます。 |
| モニタリング式 | ```max(process_count{name=~"ocp_mgragent\|ocp_monagent\|ocp_agentd",@LABELS}) by (@GBLABELS)``` |
| 取得指標 | process_count |
| 指標ソース | ocp-agent自身が収集します。 |
| 取得サイクル | 5秒 |

## ルール情報

| モニタリング式 | デフォルトしきい値 | 継続時間 | 検出サイクル | 解消サイクル |
| ---------- | ------- | -------- | --------- | --------- |
| agent_process_count | != 1 | 60秒 | 20秒 | 5分 |

## アラート情報

| アラートトリガー方法 | アラートレベル | 対象範囲 |
| ------------ | ------- | ------ |
| モニタリング指標の式に基づく | 警告 | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:host=xxx.xxx.xxx.xxx:name=ocp_mgragent ocp-agent プロセス数異常。

* **アラート詳細**

  * テンプレート：クラスタ：${ob_cluster_name}、ホスト：${host}、プロセス名：${name}、プロセス数：${value}。
  * サンプル：クラスタ：TEST、ホスト：xxx.xxx.xxx.xxx、プロセス名：ocp_mgragent、プロセス数：2。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、プロセス数：\${value}
  * サンプル：アラート：ocp-agent プロセス数異常、プロセス数：1

## システムへの影響

アラートが発生した場合、残留しているocp-agentプロセスがあることを意味します。ocp-agentプロセスはSO_REUSEADDRを設定しており、ポートの再利用を許可しています。
複数のocp-agentプロセスが存在し、同じインターフェースを提供する場合、バージョンが一致しないとAPIの動作も一致せず、予期しない状況が発生する可能性があります。

## 考えられる原因

1. ocp-agentのアンインストール処理で残留プロセスが完全にクリーンアップされなかった。
2. ocp-agentの再インストール処理で残留プロセスが完全にクリーンアップされなかった。
3. ocp-agentをCLIで操作したことがある。

## 解決策

OCPのGUIでocp-agentの具体的なプロセス番号を確認し、使用されていないocp-agentプロセスをCLIでクリーンアップします。コマンド例：`kill {pid}`。
