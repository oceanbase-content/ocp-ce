# ob_tenant_log_stream_replica_absent OceanBaseテナントのログストリームがレプリカ不足

## アラートの概要

<main id="notice" type='explain'>
<h4>説明</h4>
このアラートは、V4.0.0.0以降のOceanBaseクラスタでのみ有効です。
</main>

このアラートは、テナント内のログストリーム（LS）のレプリカ数が不足しているリスクシナリオを特定するために使用されます。特定のログストリームの実際のレプリカ数が、テナントのローカリティから導出された期待レプリカ数より少ない場合、そのログストリームはレプリカ不足状態と判断されます。テナント内にレプリカ不足のログストリームが存在する場合、このアラートがトリガーされます。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
| --------- | -------- |
| 監視指標 | tenant_log_stream_replica_absent_count。この指標はテナント内のレプリカ不足ログストリームの数を示し、その数がしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | `max(log_stream_replica_absent_count{@LABELS}) by (@GBLABELS)` |
| 取得指標 | log_stream_replica_absent_count |
| 指標ソース | OCP AgentがRootServiceノードでSQLを実行し、各テナントのレプリカ不足ログストリームの数(log_stream_replica_absent_count)を集計します。<br>取得SQL：```sql
SELECT /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(5000000) */ t.tenant_id, t.tenant_name, COUNT(DISTINCT CASE WHEN (r.replica_count IS NULL OR r.replica_count < t.expected_replica_count) THEN ls.ls_id ELSE NULL END) as cnt FROM (SELECT tenant_id, tenant_name, LENGTH(locality) - LENGTH(REPLACE(locality, '@', '')) as expected_replica_count FROM DBA_OB_TENANTS WHERE tenant_type IN ('SYS', 'USER') AND locality IS NOT NULL) t INNER JOIN CDB_OB_LS ls ON t.tenant_id = ls.tenant_id AND ls.status NOT IN ('creating', 'create_abort') LEFT JOIN (SELECT tenant_id, ls_id, COUNT(DISTINCT CONCAT(zone, ':', replica_type)) as replica_count FROM CDB_OB_LS_LOCATIONS WHERE zone IS NOT NULL AND replica_type IS NOT NULL GROUP BY tenant_id, ls_id) r ON ls.tenant_id = r.tenant_id AND ls.ls_id = r.ls_id GROUP BY t.tenant_id, t.tenant_name``` |
| 取得サイクル | 60秒 |

## システムへの影響

* OceanBase テナントへの影響：ログストリームのレプリカが不足すると、データの高可用性冗長化能力が低下し、障害発生時にサービスリスクが増大する可能性があります。

* OCPへの影響：OCPは当該テナントのリスクアラートを継続的に生成し、運用保守側に対して速やかなレプリカ復旧を促します。

* 業務への影響：短期的には業務は利用可能な場合がありますが、ノードやデータセンターの異常などの状況では災害復旧能力が低下し、さらなる可用性リスクが存在します。

## 考えられる原因

* 特定のレプリカノードが異常によりオフラインまたはアクセス不能になった場合。

* レプリカの補完/移行タスクが完了していない場合。

* テナントのローカリティ設定が現在のレプリカ分布と一致しない場合。

* Zoneレベルのリソース不足により、レプリカが予期通り作成できない場合。

## 解決策

1. テナントのローカリティと目標レプリカポリシーが正しいか確認します。

2. `CDB_OB_LS_LOCATIONS` の異常なログストリームのレプリカ分布を確認し、欠落したレプリカが存在するZone/ノードを特定します。

3. 異常なノードを復旧するかリソースを補完した後、レプリカの補完/均等化（例：rebalance）を実行し、ログストリームのレプリカ数を期待値に戻します。

4. 指標 tenant_log_stream_replica_absent_count を継続的に監視し、値が0に戻ったことを確認すると、アラートは自動的に解消されます。
