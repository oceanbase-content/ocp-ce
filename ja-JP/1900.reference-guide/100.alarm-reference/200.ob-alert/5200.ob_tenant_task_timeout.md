# ob_tenant_task_timeout OceanBaseテナントタスクのタイムアウト

## アラートの概要

OceanBaseテナントで実行されるタスクの処理時間が3時間を超えた場合に、このアラートがトリガーされます。対象となるタスクは以下のとおりです：

* MIGRATE_UNIT：Unit移行タスク
* ALTER_TENANT_LOCALITY：テナントのローカリティ変更タスク
* ROLLBACK_ALTER_TENANT_LOCALITY：テナントのローカリティロールバックタスク
* SHRINK_RESOURCE_TENANT_UNIT_NUM：テナントUnit数のスケールインタスク

### アラートの仕組み

| パラメータ | 値 |
| -------- | -------- |
| モニタリング指標 | ob_tenant_task_max_duration_seconds。この指標はOceanBaseテナントで実行されるタスクの処理時間を示し、時間がしきい値を超えた場合にアラートがトリガーされます。  |
| モニタリング式 | ```max(ob_tenant_task_max_duration_seconds{@LABELS}) by (@GBLABELS)``` |
| 取得指標 | ob_tenant_task_max_duration_seconds |
| 指標の出典 | 内部ビューから取得します。取得SQL：<li>OceanBase V4.0以前のバージョン：```SELECT /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ tenant_id, task_type, max(TIMESTAMPDIFF(SECOND, sys_task_status.start_time, CURRENT_TIMESTAMP ) ) max_sys_task_duration_seconds FROM __all_virtual_sys_task_status sys_task_status WHERE svr_ip = ? AND svr_port = ? GROUP BY tenant_id,task_type```</li><li>OceanBase V4.0以降のバージョン：```SELECT /* MONITOR_AGENT */ tenant_id, job_type as task_type, TIMESTAMPDIFF(SECOND, START_TIME, CURRENT_TIMESTAMP) as max_sys_task_duration_seconds, rs_svr_ip as svr_ip FROM DBA_OB_TENANT_JOBS WHERE job_status='INPROGRESS' AND rs_svr_ip=? and rs_svr_port=? UNION SELECT tenant_id, job_type as task_type, TIMESTAMPDIFF(SECOND, START_TIME, CURRENT_TIMESTAMP) as max_sys_task_duration_seconds, rs_svr_ip as svr_ip FROM DBA_OB_UNIT_JOBS WHERE tenant_id IS NOT NULL AND job_status='INPROGRESS' AND rs_svr_ip=? and rs_svr_port=?```</li>|
| 取得サイクル | 5秒 |

## ルール情報

| モニタリング式 | デフォルトしきい値（秒） | 持続時間 | 検出サイクル | 解消サイクル |
| ---------- | ------------- | -------- | -------- | -------- |
| ob_tenant_task_max_duration_seconds | 10800 | 0秒 | 20秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| ----------- | -------- | ------ |
| モニタリング指標の式に基づく | 重大 | テナント |

## アラートテンプレート

* **アラートの概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=C1-1000:tenant_name=T1:host=xxx.xxx.xxx.xxx:task_type=ALTER_RESOURCE_TENANT_UNIT_NUM OceanBaseテナントタスクのタイムアウト

* **アラートの詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、テナント：\${tenant_name}、ホスト：\${host}（zone：\${obzone}）、アラート：OceanBaseテナントシステムタスクのタイムアウト。タスクタイプ：\${task_type}、実行時間 \${value_shown}、しきい値 \${alarm_threshold} 秒を超えました。
  * サンプル：クラスタ：C1、テナント：T1、ホスト：xxx.xxx.xxx.xxx（zone：Z1）、アラート：OceanBaseテナントシステムタスクのタイムアウト。タスクタイプ：ALTER_RESOURCE_TENANT_UNIT_NUM、実行時間 4時間、しきい値 10800 秒を超えました。

* **アラートの復元**

  * テンプレート：アラート：${alarm_name}、OceanBaseテナントシステムタスク実行時間：\${value_shown}
  * サンプル：アラート：OceanBaseテナントシステムタスクタイムアウト、OceanBaseテナントシステムタスク実行時間：2時間

## システムへの影響

* タスクの実行時間が長すぎると、OceanBaseのタスク処理スケジューリングに影響を及ぼし、タスク処理スループットが低下します。
* リソースを長時間占有したまま解放しないと、システムの安定性に影響します。
* タスクが正常に実行できない場合、例えばUnitの移行が長時間成功しない場合、Unitの配信が不均一になり、断片化されたリソースを再利用できなくなります。

## 考えられる原因

一般的な原因はありません。

## 解決策

1. Unitの移行や変更を行う際は、対象マシンのUnitリソースが要件を満たしていることを確認する必要があります。そうでない場合、操作が失敗する可能性があります。
2. `observer.log.wf` のERRORエラーに注意し、関連情報を収集した後、技術サポート担当者に連絡して調査を依頼してください。
