# ob_tenant_service_name_is_invalid テナントサービス名が無効です

## アラートの概要

このアラートは、OceanBaseクラスタ内の各テナントのサービス名（Service Name）の状態が有効かどうかを監視します。OCPが特定のテナントのサービス名の状態をINVALIDと検出し、その状態が一定時間継続すると、このアラートが発報されます。

テナントサービス名は、OceanBase V4.2.4.0バージョンから導入された機能で、テナントのデータベースサービスを識別するために使用されます。サービス名はグローバルに一意である必要があります。複数のテナント（同一のプライマリ/スタンバイ関係内のテナントを除く）が同じサービス名を使用すると、競合が発生し、サービス名の状態がINVALIDに変わります。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
| -------- | --------- |
| 監視指標 | ob_tenant_service_name_status |
| 監視式 | `max(ob_tenant_service_name_status{@LABELS}) by (@GBLABELS)` |
| 取得指標 | ob_tenant_service_name_status |
| 指標ソース | OCPの定期タスクCheckAllTenantServiceNameConflictTaskがすべてのテナントを走査し、MetaDBの`ob_tenant`テーブルの`service_name`および`service_name_status`フィールドをチェックします。テナントデータは、最初にOceanBaseシステムビュー`CDB_OB_SERVICES`から同期されます。 |
| 取得サイクル | 60秒 |

OCPは、定期タスク`TenantSchedules.syncAllTenantInfo()`を通じて、60秒ごとにOceanBaseクラスタの`CDB_OB_SERVICES`ビューからテナントサービス名情報をMetaDBに同期し、`analyzeTenantServiceNameStatus()`メソッドを用いてサービス名に競合がないか分析し、状態をVALID、INVALID、またはDISABLEDにマークします。

もう一つの定期タスク`TenantSchedules.checkAllTenantServiceNameConflict()`は、60秒ごとにすべてのテナントを走査し、サービス名が設定されているテナントごとにその状態を判断します：

* サービス名がNULLではなく、かつ状態がINVALIDの場合、指標値1を発信します。

* それ以外の場合、指標値0を発信します。

監視指標ob_tenant_service_name_statusの値が1の場合、そのテナントのサービス名が無効であることを意味し、120秒間継続するとアラートがトリガーされます。

## ルール情報

| 監視指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| -------- | --------- | --------- | --------- | --------- |
| ob_tenant_service_name_status | 1 | 120秒 | 60秒 | 5分 |

## アラート情報

| アラートトリガー方式 | アラートレベル | 対象範囲 |
| ------------ | ------- | -------- |
| 監視指標の式に基づく | 重大 | テナント |

## アラートテンプレート

* **アラート概要**
  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：ob_cluster=obcluster-1:tenant_name=mytenant テナントのサービス名が無効です

* **アラートの詳細**
  * テンプレート：OceanBaseクラスタ${ob_cluster_name}のテナント${tenant_name}のサービス名が無効です。現在のサービス名の状態はINVALIDです。サービス名に競合がないか確認し、速やかにテナントのサービス名を変更してください。
  * サンプル：OceanBaseクラスタobcluster-1のテナントmytenantのサービス名が無効です。現在のサービス名の状態はINVALIDです。サービス名に競合がないか確認し、速やかにテナントのサービス名を変更してください。

ここで、${alarm_target}はアラートが発生した対象を表し、形式はob_cluster=xxxxxxx:tenant_name=xxxxxxxです。

## システムへの影響

テナントのサービス名がINVALID状態にあるということは、サービス名の競合が存在することを意味し、以下の影響が発生する可能性があります：

* アプリケーションがサービス名を使用してデータベースに接続する際、誤ったテナントにルーティングされ、データアクセス異常が発生する可能性があります。

* プライマリ/スタンバイ切り替え（Failover/Switchover）シナリオでは、サービス名の競合により、ビジネストラフィックが新しいプライマリテナントに正しく切り替えられない可能性があります。

* OBProxyまたは接続管理コンポーネントがサービス名に依存してルーティングを行う際、接続失敗や誤ったインスタンスへの接続といった問題が発生する可能性があります。

## 考えられる原因

一般的なケースは以下のとおりです：

* プライマリ/スタンバイ切り替え後のサービス名競合：Failover実行後、元のプライマリテナントのサービス名がタイムリーにINVALIDに設定されず、新しいプライマリテナントと元のプライマリテナントが同じサービス名を使用してしまう場合。OCPはFailoverプロセス中にInvalidTenantServiceNameTaskを通じて、元のプライマリテナントのサービス名を自動的にINVALIDに設定し、アラートをトリガーします。

* 重複するサービス名の手動設定：管理者が異なるクラスタやテナント間で同じService Nameを手動で設定した場合。ただし、これらのテナントが同一のプライマリ/スタンバイ関係内にない場合。

* マルチクラスタ管理下でのクロスクラスタ競合：OCPが管理する複数のクラスタ間で、異なるクラスタのテナントが同じサービス名を使用した場合。OCPのグローバル競合検出によりINVALIDとマークされます。

* テナント同期異常：OCPとOceanBaseクラスタ間のテナント情報同期に遅延や異常が発生し、サービス名の状態判断が不正確になる場合。

## 解決方法

1. アラートに関連するテナント情報を確認します。OCPのアラート詳細からクラスタ名（ob_cluster_name）とテナント名（tenant_name）を取得し、具体的なテナントを特定します。

2. サービス名競合の詳細を確認します。OCPにログインし、対応するテナントの詳細ページに移動して、現在のテナントのService Nameとその状態を確認します。同時に、他のテナントが同じService Nameを使用していないかも確認します。OceanBaseクラスタのsysテナントで以下のSQLを実行してサービス名情報を確認することもできます：

   ```sql
   SELECT TENANT_ID, SERVICE_NAME, SERVICE_STATUS FROM CDB_OB_SERVICES;
   ```

3. プライマリ/スタンバイ切り替えが原因かどうかを確認します。

   * Failover/Switchover後にアラートがトリガーされた場合、元のプライマリテナントのサービス名を変更する必要があるかどうかを確認します。通常、元のプライマリテナント（スタンバイテナントに降格）のサービス名を新しい一意の名前に変更するか、サービス名を空にする必要があります。

   * 以下のSQLを使用してテナントのサービス名を変更できます：

     ```sql
     -- sysテナントで実行
     ALTER SYSTEM MODIFY SERVICE '<old_service_name>' TO '<new_service_name>' TENANT = '<tenant_name>';
     ```

4. 手動設定による競合がないか確認します。

   * プライマリ/スタンバイ切り替えシナリオでない場合、管理者が異なるテナントで同じサービス名を手動で設定していないか調査します。

   * テナントのうち1つのテナントのサービス名を変更し、すべてのテナントのサービス名がOCP管理範囲内でグローバルに一意であることを確認します（同一のプライマリ/スタンバイ関係内のテナントは除く）。

5. アラートが自動的に解消されるのを待ちます。サービス名を変更すると、OCPは次の同期サイクル（60秒後）にサービス名の状態を再分析します。競合が解消されれば、service_name_statusはVALIDに更新され、指標値は0に戻ります。アラートは指標が正常に戻った後、最大5分以内（resolve_timeout_seconds: 300）に自動的に解消されます。

6. 上記の方法でも問題が解決しない場合は、OCP技術サポートチームにお問い合わせください。
