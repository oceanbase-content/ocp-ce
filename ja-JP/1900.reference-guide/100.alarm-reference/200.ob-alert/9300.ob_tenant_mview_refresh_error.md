# ob_tenant_mview_refresh_error テナントマテリアライズドビュー自動リフレッシュエラー

## アラートの説明

<main id="notice" type='explain'>
<h4>説明</h4>
<li>このアラートは、V4.3.5.0以降のOceanBaseクラスタでのみ有効です。</li>
<li>テナントにプライマリ/スタンバイ関係が存在する場合、アラートを報告できるのはプライマリテナントのみです。</li>
</main>

このアラートは、テナント内のデータベースにおけるマテリアライズドビューのリフレッシュに異常がないか監視します。異常が検出された場合、アラートを報告します。

## アラートの仕組み

1. OCPの定期タスクは、すべてのクラスタのsysテナントで以下のSQLを実行し、マテリアライズドビューの自動リフレッシュ異常データを収集し、データをOCP MonitorDBの`sql_aggregate_data`テーブルに格納します。定期タスクは60秒ごとに実行されます。

    ```sql
    SELECT 
          D.tenant_id,
          D.tenant_name,
          A.database_name,
          B.table_name AS mview_name,
          E.start_time,
          E.result
    FROM  oceanbase.__all_virtual_database A,
          oceanbase.__all_virtual_table B,
          oceanbase.__all_virtual_mview C,
          oceanbase.DBA_OB_TENANTS D,
          (SELECT tenant_id,
                  result,
                  start_time,
                  mview_id
            FROM   (SELECT tenant_id,
                          result,
                          start_time,
                          mview_id,
                          Row_number()
                            over(
                              PARTITION BY tenant_id, mview_id
                              ORDER BY start_time DESC) rn
                    FROM   oceanbase.__all_virtual_mview_refresh_stats A)
            WHERE  rn = 1)E
    WHERE  A.tenant_id = B.tenant_id
          AND B.tenant_id = C.tenant_id
          AND C.tenant_id = D.tenant_id
          AND D.tenant_id = E.tenant_id
          AND C.mview_id = E.mview_id
          AND A.database_id = B.database_id
          AND B.table_id = C.mview_id
          AND B.table_type = 7
          AND E.result != 0
          AND D.tenant_type<>'META' AND D.tenant_name IS NOT NULL
          AND D.tenant_role = 'PRIMARY';
    ```

2. OCPアラート検出タスクを通じて、アラート項目がSQL_AUDITタイプかどうかを識別します。該当する場合、以下のコマンドを実行して`sql_aggregate_data`内の異常データをスキャンし、アラート検出のルール設定に基づいて対応するアラートを生成します。

   ```sql
   select * from sql_aggregate_data where tags like '%mview_stat%' order by timestamp desc
   ```

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=test471-11:tenant_name=mysqlTes:database=test:mview_name=test_mv_refresh_retry_mv2 マテリアライズドビュー自動リフレッシュ異常

* **アラート詳細**

  * テンプレート：OceanBaseクラスタ${ob_cluster_name}のテナント${tenant_name}のデータベース${database}のマテリアライズドビュー${mview_name}に異常が発生しました。結果は${result}、リフレッシュ時間は${start_time}です。
  * サンプル：OceanBaseクラスタtest471のテナントmysqlTesのデータベースtestのマテリアライズドビューtest_mv_refresh_retry_mv2に異常が発生しました。結果は-5024、リフレッシュ時間は2025-11-14T16:13:55.026383+08:00です。

## システムへの影響

マテリアライズドビューのデータ更新が停止する可能性があります。

## 考えられる原因

システム内部の異常。

## 解決策

1. デフォルト設定では、マテリアライズドビューの更新エラー発生時にはTrace IDとエラーコードのみ取得できます。sysテナントで以下のコマンドを実行して取得します：

    ```sql
    SELECT A.database_name, B.table_name AS mview_name, C.last_refresh_trace_id, C.last_refresh_time
    FROM oceanbase.__all_virtual_database A, oceanbase.__all_virtual_table B, oceanbase.__all_virtual_mview C
    WHERE A.tenant_id = B.tenant_id
      AND B.tenant_id = C.tenant_id
      AND A.database_id = B.database_id
      AND B.table_id = C.mview_id
      AND B.table_name = 'mview_name';
    ```

    ここで、`mview_name` は実際に異常が発生したマテリアライズドビューの名前を記入します。

2. Trace IDや更新時間などの情報を用いて、クラスタのobserverログディレクトリから関連するエラーログを収集し、OCPサポートチームに連絡して調査を依頼します。
