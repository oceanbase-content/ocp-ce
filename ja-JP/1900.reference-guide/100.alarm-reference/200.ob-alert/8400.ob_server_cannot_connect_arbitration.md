# ob_server_cannot_connect_arbitration OceanBaseクラスタには、アービトレーションサービスと通信できないノードが存在します

## 警報の概要

OceanBaseクラスタには、アービトレーションサービスと通信できないノードが存在します。この警報はOceanBase V4.2.0以降のクラスタでのみ有効であり、かつそのクラスタがアービトレーションサービスに関連付けられている場合にのみ発生する可能性があります。

## 警報の仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | arbitration_status_inactive_server_count。この指標は、アービトレーションサービスとの通信に失敗したOBServerノードの数を示します。その値がしきい値を超えた場合に警報が発生します。 |
| モニタリング式 | ```max(arbitration_status_inactive_server_count{@LABELS}) by (@GBLABELS)``` |
| 取得指標 | arbitration_status_inactive_server_count |
| 指標の出典 | 内部ビューから取得。取得SQL：```select /*+ MONITOR_AGENT */ count(1) as inactive_server_count from GV$OB_ARBITRATION_SERVICE_STATUS where status = 'INACTIVE'```   |
| 取得間隔 | 5秒 |

## ルール情報

| モニタリング式 | デフォルトのしきい値 | 継続時間 | 検出間隔 | 解消間隔 |
| ---------- | ------- | ---------- | -------- | ---------- |
| arbitration_status_inactive_server_count | 0 | 0秒 | 60秒 | 5分 |

## 警報情報

| 警報のトリガー方法 | 警報レベル | 対象範囲 |
| ------------ | ------- | -------- |
| モニタリング指標の式に基づく | 重大 | クラスタ |

## システムへの影響

OBServerとアービトレーションサービスが通信できないため、アービトレーション機能に異常が発生し、2F/4Fテナントに高可用性を提供できなくなる可能性があります。アービトレーションサービスを有効にしているテナントで半数のレプリカが利用不能になると、テナントサービスに異常が発生します。

## 考えられる原因

1. observerとアービトレーションサービス間のネットワークに障害が発生しています。
2. アービトレーションサービスのプロセスに異常が発生しています。

## 解決策

1. root@sysでクラスタに接続します。以下のSQLを実行して、どのServerの状態がINACTIVEか確認します。

   ```sql
   SELECT svr_ip, svr_port, arbitration_service_address, status FROM GV$OB_ARBITRATION_SERVICE_STATUS;
   ```

2. これらのServerとアービトレーションサービス間のネットワークが正常に接続されているか確認します。

3. アービトレーションサービスのプロセス自体が正常に動作しているか確認します。
