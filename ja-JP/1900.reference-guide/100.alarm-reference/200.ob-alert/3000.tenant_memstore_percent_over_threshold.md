# tenant_memstore_percent_over_threshold OceanBaseテナントのMemStore使用率がしきい値を超えた場合

## 警報の概要

この警報は、テナントのMemStore使用率が制限値を超えているかどうかを監視し、超えた場合にアラートを発報します。

## 警報の仕組み

次の表は、この警報の監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|-------|--------|
| 監視指標 | memstore_percent。この指標は、OceanBaseクラスタ内のテナントのメモリ使用率を示し、使用率がしきい値を超えた場合にアラートがトリガーされます。    |
| 監視式 | ```100 * sum(ob_sysstat{stat_id="130001",@LABELS}) by (@GBLABELS) / sum(ob_sysstat{stat_id="130004",@LABELS}) by (@GBLABELS)```<ul><li>統計イベントID 130001：テナントで使用済みのメモリの合計量を集計します。</li><li>統計イベントID 130004：テナントで使用可能な最大メモリの合計量を集計します。</li></ul>監視式は、「stat_id=130001 の時の value の合計」と「stat_id=130004 の時の value の合計」の比率をテナントのメモリ使用率の監視指標値として表します。   |
| 収集指標 | ob_sysstat |
| 指標ソース | 内部ビューから収集。収集SQL：<li>OceanBase V4.0未満のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN (130001, 130004) and (con_id > 1000 or con_id = 1)```</li><li>OceanBase V4.0以降のバージョン：```select /* MONITOR_AGENT */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN (130001, 130004) and (con_id > 1000 or con_id = 1) and con_id in (select tenant_id from DBA_OB_TENANTS WHERE tenant_type<>'META')```</li> |
| 収集サイクル | 5秒 |

## ルール情報

|         監視指標        | デフォルトしきい値（単位：%） | 持続時間 | 検出サイクル | 解消サイクル |
|-------------------------|------------|------|------|------|
| memstore_percent        | <li>memstore_percent > 85</li><li>memstore_percent > 95</li>    | 120秒  | 10秒 | 5分 |

## 警報情報

|   アラートのトリガー方法   | アラートレベル | 対象範囲 |
|------------------|---------|-------|
| 監視指標の式に基づく | <li>memstore_percent > 85：警告</li><li>memstore_percent > 95：重大</li>   | テナント |

## アラートテンプレート

* **アラートの概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:obcluster-1:tenant_name=tenant-1:host=xxx.xxx.xxx.xxx OceanBaseテナントのMemStore使用率がしきい値を超えた場合

* **アラートの詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、アラート：\${alarm_name}。MemStore使用率 \${value_shown} が \${alarm_threshold} % を超えました。
  * サンプル：クラスタ：obcluster-1、アラート：OceanBaseテナントのMemStore使用率がしきい値を超えた場合。MemStore使用率 86.0 % が 85.0 % を超えました。

* **アラートの回復**

  * テンプレート：アラート：${alarm_name}、OceanBaseテナントのMemStore使用率：\${value_shown}
  * サンプル：アラート：OceanBaseテナントのMemStore使用率が上限を超えました、OceanBaseテナントMemStore使用率：83%

## システムへの影響

テナントのメモリが不足していると、SQLの実行が遅くなったり、書き込みに失敗したりする可能性があります。

## 考えられる原因

特定の時間帯に書き込みが集中し、テナントのリソース設定が小さい場合によく見られます。

## 解決策

1. テナントのメモリが上限を超えた後、テナントメモリの拡張を試みます。プランを実行して迅速に対処できます。詳細な操作については、[アラートプラン](../500.appendix/400.execute-the-plan.md)を参照してください。

2. 調査結果に基づいて、トラフィック制限または拡張を行います。

   1. OCP上で該当テナントの**<UI-TERM key="ocp-v2.Detail.Realtime.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**に移動し、**パフォーマンスとSQL**タブを選択します。

   2. 時間を「1週間」に設定します。

   3. **MEMStore使用率**の折れ線グラフを確認します。

      アラートが発生した時刻のメモリ使用量が異常に上昇していないか観察します。

      ![08091500](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/p302467.png)

      * 異常に上昇している場合、または規則的に上昇し、毎回上昇するたびにアラートが発生し、かつリソースが不足している場合。

        [OceanBaseクラスタのトラフィックを制限する](../500.appendix/200.limit-the-inbound-traffic-of-the-oceanbase-cluster.md)を参考に、このテナントのタイプのSQLに並列数を制限するHintをバインドできます。

      * 常に変動しているか、規則的に上昇しているが、リソースに余裕がある場合。

        [Unit仕様の管理](../../../700.tenant-functions/1630.manage-unit-specification.md)を参考に、このテナントのUnit仕様におけるメモリを増やすことができます。
