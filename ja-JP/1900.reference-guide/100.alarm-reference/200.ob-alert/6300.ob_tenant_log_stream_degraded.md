# ob_tenant_log_stream_degraded OceanBaseテナントにデグレードされたログストリームが存在する

## 警報の概要

この警報は、テナントのログストリームがデグレードされたことを示します。アービトレーションサービスを有効にしたテナントは、必ず2Fまたは4F構成である必要があります。2F構成のテナントで単一レプリカ障害が発生した場合、または4F構成で2つのレプリカに障害が発生した場合、テナントのログストリームがデグレードされ、テナントのレプリカ数が過半数を満たさなくてもサービスを提供できるようになります。この時、OCPは警報を発し、具体的にどのテナントでログストリームのデグレードが発生したかを示します。

## 警報の仕組み

| パラメータ | 値 |
| ------- | ---------- |
| モニタリング指標 | ob_tenant_log_stream_degraded_count。この指標は、テナントでデグレードされたログストリームの数を示します。デグレードされたログストリームの数がしきい値を超えた場合に警報がトリガーされます。 |
| モニタリング式 | ```sum(log_stream_degraded_count{@LABELS}) by (@GBLABELS)```     |
| 取得指標 | log_stream_degraded_count      |
| 指標ソース | 内部ビューから取得。取得SQL：```select /*+ MONITOR_AGENT */ t2.tenant_id, t2.tenant_name, sum(t1.degraded_list <> '') as degraded_count from V$OB_LOG_STAT t1 inner join DBA_OB_TENANTS t2 on t1.tenant_id = t2.tenant_id and t2.tenant_type != 'META' where svr_ip= ? and svr_port= ? group by t1.tenant_id``` |
| 取得周期 | 5秒 |

## システムへの影響

ログストリームがデグレードすると、テナントは数秒間利用できなくなり、業務システムにわずかな影響を与える可能性があります。

## 考えられる原因

* テナントのあるFレプリカが配置されているデータセンターで障害が発生した場合。
* テナントのあるFレプリカのログストリームが配置されているOBServerでダウンなどの障害が発生した場合。

## 解決策

1. root@sysでOceanBaseクラスタに接続し、以下のコマンドを実行して、デグレードしたログストリームとそのOBServerを確認します。

   ```SQL
   select t2.tenant_id, t2.tenant_name, t1.degraded_list from V$OB_LOG_STAT t1 inner join DBA_OB_TENANTS t2 on t1.tenant_id = t2.tenant_id and t2.tenant_type != 'META';
   ```

2. **手順1**で取得したOBServer情報に基づき、これらのOBServerの稼働状態を確認します。

3. OBServerがダウンしている場合は、OBServerを再起動することを推奨します。起動後、アラートが解消されれば正常に戻ります。
