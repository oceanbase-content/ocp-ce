# ob_host_data_disk_percent_over_threshold OceanBaseサーバーのデータディレクトリのディスク使用率がしきい値を超えた場合

## 警報の概要

OBServerノードのデータディレクトリのマウントポイントのディスク容量使用率がしきい値を超えると、この警報がトリガーされます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OBServerノードのデータディレクトリは、デフォルトで <code>/data/1</code> です。</p>
</main>

## 警報の仕組み

次の表は、この警報の監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|---------|-----------|
| 監視指標 | ob_data_disk_usage_percent。この指標はOBServerノードのデータディスクの使用率を示し、使用率がしきい値を超えると警報がトリガーされます。 |
| 監視式 | ```100 * (1 - avg(node_filesystem_avail_bytes{is_ob_disk="1",mount_label="data_disk_path",@LABELS}) by (@GBLABELS) / avg(node_filesystem_size_bytes{is_ob_disk="1",mount_label="data_disk_path",@LABELS}) by (@GBLABELS))```      |
| 取得指標 | node_filesystem_avail_bytes、node_filesystem_size_bytes     |
| データソース | この警報の指標ソースはやや特殊です。OCP-Agentは `df -B1` コマンドを実行してOBServerノードのディスク使用量をチェックし、ディスクに関連するラベルを追加します。ラベルは以下のとおりです：<ul><li> インストールディレクトリのディスク：`mount_lable="install_path"`</li><li>データディレクトリのディスク：`mount_lable="data_path"`</li><li>ログディレクトリのディスク：`mount_lable="log_path"`</li></ul>  |
| 取得サイクル | 5秒     |

## ルール情報

|           監視指標              | デフォルトしきい値（単位：%） | 持続時間 | 検出サイクル | 解消サイクル |
|--------------------------------|------------|------|------|------|
| ob_data_disk_usage_percent     | 97         | 0秒  | 10秒 | 5分 |

## 警報情報

|   警報トリガー方法   | 警報レベル | 対象範囲  |
|------------|------|-----|
| 監視指標の式に基づく | 重大   | ホスト |

## 警報テンプレート

* **警報の概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=obcluster-1:host=xxx.xxx.xxx.xxx OceanBaseサーバーのデータディレクトリのディスク使用率がしきい値を超えた場合

* **警報の詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、警報：\${alarm_name}。データディレクトリ \${data_disk_path} のマウントポイント \${mount_point} のディスク使用率 \${value_shown} が ${alarm_threshold} % を超えました。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：OceanBaseサーバーのデータディレクトリのディスク使用率が限度を超えています。データディレクトリ /data/1 のマウントポイント /data/1 のディスク使用率が98.0%で、97.0%を超えています。

* **アラートの回復**

  * テンプレート：アラート：${alarm_name}、OBServerデータディレクトリのディスク使用率：\${value_shown}
  * サンプル：アラート：OceanBaseサーバーのデータディレクトリのディスク使用率が限度を超えています、OBServerデータディレクトリのディスク使用率：95.0%

## システムへの影響

OBServerノードのデータディスクには、core dump用の領域が設定されています。OSの観点から見ると、残りの空き容量が不足している場合、OBServerノードのcore dumpに影響を及ぼす可能性があります。

## 考えられる原因

他のプログラムによって生成されたファイルが多すぎる。

## 解決策

1. `df` コマンドを実行し、`/data/1` のディスク使用率が実際に限度を超えているか確認します。

2. OCPのアラート画面に以下のアラートやその他のデータディスク関連のアラートが報告されていないか確認します。

   [ob_server_sstable_percent_over_threshold OBサーバーのデータディスク使用率が限度を超えています](../200.ob-alert/2200.ob_server_sstable_percent_over_threshold.md)

   * ある場合は、他のアラートの処理を優先的に参照し、アラートが自動的にクリアされるかどうか観察します。

   * ない場合は、次の手順に進みます。

3. 以下のコマンドを実行し、最も多くの容量を占有するディレクトリとファイルを特定します。

   ```shell
   # 容量が最も大きい上位5つのディレクトリを見つける
   du -a /data/1 | sort -n -r | head -n 5

   # サイズが最も大きい上位5つのファイルを見つける
   cd /data/1 && find -type f -exec du -Sh {} + | sort -rh | head -n 5
   ```

4. 不要なファイルを削除します。
