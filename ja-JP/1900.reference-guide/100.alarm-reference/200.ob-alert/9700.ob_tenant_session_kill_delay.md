# ob_tenant_session_kill_delay テナントのSession Killed遅延

## アラートの説明

<main id="notice" type='explain'>
<h4>説明</h4>
このアラートは、V4.2.1.0以降のOceanBaseクラスタでのみ有効です。
</main>

このアラートは、OceanBaseテナントのセッションが長時間Kill状態にあることを監視します。

## アラートの仕組み

以下の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

|  パラメータ    |  値      |
|--------------|----------|
|  監視指標    |  ob_tenant_session_kill_delay。この指標はテナントのSession Killed遅延時間を表し、時間がしきい値を超えた場合にアラートがトリガーされます。   |
|  監視式  |  `max(session_kill_delay_second)`   |
|  取得指標    |  session_kill_delay_second   |
|  データソース    |  SQL取得：<ul><li>OceanBase V4.2.1.0以降、V4.2.5.7未満のバージョン：```select svr_ip, svr_port, tenant_id, tenant, id as session_id, time from oceanbase.__all_virtual_processlist where state='SESSION_KILLED';```</li><li>OceanBase V4.2.5.7以降、V4.3.0.0未満のバージョン：```select svr_ip, svr_port, tenant_id, tenant, id as session_id, time from oceanbase.__all_virtual_processlist where state='SESSION_KILLED'and top_info is null;```</li><li>OceanBase V4.3.0.0以降、V4.4.1.0未満のバージョン：```select svr_ip, svr_port, tenant_id, tenant, id as session_id, time from oceanbase.__all_virtual_processlist where state='SESSION_KILLED';```</li><li>OceanBase V4.4.1.0以降のバージョン：```select svr_ip, svr_port, tenant_id, tenant, id as session_id, time from oceanbase.__all_virtual_processlist where state='SESSION_KILLED'and top_info is null;```</li></ul>   |
|  取得サイクル    |  10分   |

## ルール情報

|  監視指標  |  デフォルトしきい値（単位：秒）  |  持続時間  |  検出サイクル  |  解消サイクル   |
|------------|-----------------------|------------|-----------|--------------|
|  session_kill_delay_second  |  600  |  0秒  |  60秒  |  6分   |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster_name=obcluster:ob_cluster_id=4:tenant_name=mysql:svr_ip=xx.xx.xx.xx:svr_port=10106:session_id=2147483648 OceanBaseテナントのSession Killed遅延

* **アラート詳細**

  * テンプレート：OceanBaseクラスタ${ob_cluster_name}のテナント${tenant_name}内のホスト${svr_ip}ポート${svr_port}のSessionId ${session_id}が正常に終了せず、${value_shown}秒を超えており、しきい値の${alarm_threshold}秒を超えました。
  * サンプル：OceanBaseクラスタobclusterのテナントmysql内のホストxx.xx.xx.xxのポート10106のセッションId 2147483648が正常に終了せず、867秒を超え、しきい値の600秒を上回りました。

* **アラートの復旧**

  * テンプレート：アラート：${alarm_name}、テナントSession Killed遅延：${value_shown}
  * サンプル：アラート：テナントSession Killed遅延、テナントSession Killed遅延：10

## システムへの影響

セッションが長時間終了できない場合、そのセッションはスレッドリソースを継続的に占有します。複数のセッションが終了できない場合、通常のリクエスト処理に影響を与える可能性があります。

## 考えられる原因

* 対応するセッションが中断できないデータベースタスクを実行中であり、タスクがセッション状態チェックポイントに達するまで終了できません。
* データベースセッションの実行に異常が発生し、セッションが終了できません。

## 解決策

* タイムアウト時間の関係を確認します。セッションがKillできない期間が対応するテナントのSQLステートメントのタイムアウト時間(ob_query_timeout)を超えていないか確認します。タイムアウトしていない場合は、一時的に介入せず、ステートメントが自然にタイムアウトするのを待ち、アラートが自動的に復旧するか観察します。

* リソースへの影響を評価し、対応を決定します。セッションのブロック時間がSQLタイムアウトのしきい値を超えてもアラートが解消されず、多くのKillできないセッションが存在する場合、これらのセッションがスレッドリソースを継続的に占有し、通常のリクエスト処理に影響を与える可能性があります。この場合、業務への影響を評価した上で、対応するOBServerノードを再起動して異常なセッションと関連リソースを解放し、アラートに対応する情報収集情報を収集して、技術サポートに連絡し、解決を依頼することを推奨します。
