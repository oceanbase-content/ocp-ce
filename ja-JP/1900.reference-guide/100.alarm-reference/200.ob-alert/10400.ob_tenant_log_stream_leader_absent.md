# ob_tenant_log_stream_leader_absent OceanBaseテナントのログストリームのリーダーが不在

## アラートの説明

<main id="notice" type='explain'>
<h4>説明</h4>
このアラートは、V4.0.0.0以降のOceanBaseクラスタでのみ有効です。
</main>

このアラートは、テナント内のログストリーム（LS）リーダーの異常な状況を特定するために使用されます。特定のログストリームのリーダー数が1ではない場合（リーダーなしまたは複数リーダー）、そのログストリームが異常と判断され、アラートがトリガーされます。

## アラートの仕組み

以下の表は、このアラートの監視ロジックに関連する主要パラメータを示しています。

| パラメータ    | 値      |
| ------- | ------- |
| 監視指標 | ob_tenant_log_stream_no_leader、この指標はテナントのログストリームのリーダーが不在かどうかを示します。値が1の場合、アラートがトリガーされます。 |
| 監視式 | ob_tenant_log_stream_no_leader{@LABELS} |
| 取得指標 | ob_tenant_log_stream_no_leader |
| 指標ソース | OCPの定期タスクによる検査（Agentによる収集ではありません）、取得SQL：<li>LS1リーダー検査：`SELECT tenant_id FROM __all_virtual_log_stat WHERE ls_id = 1 AND role = 'LEADER'`</li><li>その他のLSリーダー統計：`SELECT a.tenant_id, a.ls_id, COUNT(*) as leader_count FROM CDB_OB_LS a INNER JOIN CDB_OB_LS_LOCATIONS b ON a.tenant_id = b.tenant_id AND a.ls_id = b.ls_id AND b.role = 'LEADER' WHERE a.status NOT IN ('creating', 'create_abort') GROUP BY a.tenant_id, a.ls_id`</li> |
| 検出サイクル  | 60秒 |

## ルール情報

| 監視指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| -------- | -------- | -------- | ------- | ---------- |
| ob_tenant_log_stream_no_leader |  1 | 180秒 | 60秒 | 5分 |

| アラートトリガー方式 | アラートレベル | 対象範囲    |
| ------------ | -------- | --------- |
| 監視指標式に基づく | 極度 | テナント    |

## システムへの影響

* OceanBase テナントへの影響：ログストリームのリーダーが不在の場合、そのログストリームの読み書き可用性と障害回復能力に影響します。

* OCPへの影響：OCPは継続的にログストリーム単位のアラートを生成し、運用保守担当者に対して速やかにリーダー選出状態を回復するよう促します。

* 業務への影響：リクエストの失敗、遅延の増加、または一部の業務が利用できなくなる可能性があります。

## 考えられる原因

* 過半数のレプリカが利用不能となり、リーダー選出が完了できない。

* ノードのダウン、ネットワーク分断、またはデータセンター障害によりレプリカが切断される。

* レプリカロール異常またはログストリームメタ情報の不整合により、リーダー選出に失敗する。

## 対処方法

1. まず、異常なログストリームが存在するテナントおよびノードの状態を確認し、障害ノードやネットワーク接続を回復します。

2. レプリカの分布と過半数が満たされているか確認し、ログストリームがリーダー選出の条件を備えていることを確認します。

3. ob_tenant_log_stream_no_leader指標が0（同じラベルの組み合わせ）に戻ったことを確認し、アラートが自動的に復旧したことを確認します。

4. 引き続き異常が続く場合、ログストリームとレプリカの診断結果を踏まえ、さらなる修復を行います（レプリカの再構築、移行、障害ノードの置換など）。
