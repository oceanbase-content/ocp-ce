# same_alarm_rule_detect_too_many_targets 複数のインスタンスが同一のアラートルールをトリガーする場合

## アラートの概要

SQL系のアラート（例：スローSQLアラート）では、過剰な数のアラートが発生する可能性があります。このような場合、過剰なアラートを同一のアラートに統合する必要があります。つまり、同じアラートタイプで異なるアラートインスタンスがトリガーするアラート数がしきい値を超えた場合、それらを1つのアラートに統合します。

システムパラメータ `ocp.alarm.detect.too-many-targets-alarm-threshold` を使用して、アラート数がいくつを超えた場合に同一のアラートに統合するかを設定できます。

## ルール情報

|----------|----------|----------|----------|---------|

## システムへの影響

SQLアラートが過剰になると、アラート受信者がアラート情報を確認することが困難になり、多すぎるアラートはその意義を失います。アラートが過剰な場合、アラートを統合し、関連する責任者に速やかに通知する必要があります。システムへの影響は、具体的なアラート情報に基づいて個別に分析する必要があります。

## 考えられる原因

* ob_tenant_slow_sql_exists スローSQLアラート
* ob_tenant_large_trans_exist テナントに大規模トランザクションが存在する
* ob_tenant_long_trans_exist テナントに長時間トランザクションが存在する
* ob_tenant_expired_trans_exist テナントにハングトランザクションが存在するなど、アラートが過剰な場合にこのアラートが生成されます。
