# ob_tenant_tde_kms_cmk_info_not_exist テナントのTDEキー情報が現在のOCPに存在しません。テナントのTDEキーを速やかに更新してください。

## アラートの概要

このアラートは、テナントのTDEキー情報が現在のOCPに存在するかどうかを検出します。つまり、`GV$OB_PARAMETERS`ビューの対応するテナントの`external_kms_info`パラメータが、現在のOCP MetaDBの`kms_cmk_info`テーブルで対応するKMS TDEキー情報レコードと一致するかどうかを確認します。

## アラートの仕組み

| パラメータ       | 値       |
| ---------- | ------------ |
| モニタリング指標   | ob_tenant_kms_cmk_info_exist_status。この指標は、テナントのTDEキー情報が現在のOCPに存在するかどうかを示します。パラメータ値が`0`の場合は存在し、`1`の場合は存在せず、アラートがトリガーされます。 |
| モニタリング式 | ```max(ob_tenant_kms_cmk_info_exist_status{@LABELS}) by (@GBLABELS)``` |
| 収集指標   | ob_tenant_kms_cmk_info_exist_status |
| データソース   | OCP-Serverが定期的に`GV$OB_PARAMETERS`ビューの対応するテナントの`external_kms_info`パラメータを照会し、そのパラメータに基づいて`kms_cmk_info`テーブルに対応するキー情報レコードが存在するかどうかを検索します。存在しない場合、アラートを発報します。 |
| 収集サイクル   | 5秒 |

* **アラート詳細**

  * テンプレート：OceanBaseクラスタ${ob_cluster_name}のテナント${tenant_name}のTDEキー情報が現在のOCPに存在しません。テナントのTDEキーを速やかに更新してください。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、テナントTDE KMS情報が現在のOCPに存在するかどうか：\${value}
  * サンプル：アラート：テナントTDEキー情報が現在のOCPに存在しません。テナントのTDEキーを速やかに更新してください、テナントTDE KMS情報が現在のOCPに存在するかどうか：0

## システムへの影響

OBServerの追加、新規スタンバイテナントの作成、新規暗号化テーブル領域の作成などの機能は利用できなくなります。

## 考えられる原因

* コマンドラインを使用して、現在のOCP MetaDBの`profile_credential`テーブル内のsecretの`cmkId`または`kmsEndpoint`データを変更した場合。
* コマンドラインを使用して、`GV$OB_PARAMETERS`ビュー内の該当テナントの`external_kms_info`パラメータの`access_key_id`値を変更した場合。
* クラスタの移出および引き継ぎ後、関連するテナントのTDE暗号化設定を適時に完了しなかった場合。

## 解決策

* 方法1：アラート対象のクラスタの概要モジュールに移動し、ページの指示に従って**<UI-TERM key="ocp-v2.Detail.Overview.ModifyEncryption">暗号化を変更する</UI-TERM>**をクリックし、**<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">セキュリティ設定</UI-TERM>** > **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">TDE 透過的データ暗号化</UI-TERM>**で対応するテナントのTDE暗号化情報を変更します。
* 方法2：テナントが属するクラスタで、**<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">セキュリティ設定</UI-TERM>** > **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">TDE 透過的データ暗号化</UI-TERM>**に移動し、対応するテナントのTDE暗号化情報を変更します。
