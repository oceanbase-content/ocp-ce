# ob_cluster_rs_not_same Config serverのrootserver情報が正しくない

## アラートの概要

このアラートは、OceanBaseクラスタに設定されたconfig server内のrootserver情報が、クラスタ自体のrootserver情報と一致しているかどうかを監視します。一致しない場合にアラートがトリガーされます。

## アラートの仕組み

OceanBaseデータベースは、obconfig_urlが指すリソースに自身のrootserver情報を更新します。OCPは、そのリソース識別子で指定されたリソースにアクセスし、取得したrootserver情報とクラスタ自体のrootserver情報を比較します。リソース識別子で指定されたリソースにアクセスできない場合、または取得したrootserver情報とクラスタ自体のrootserver情報が一致しない場合、アラートがトリガーされます。

## アラートテンプレート

* **アラート概要**

  * テンプレート: \${alarm_target} ${alarm_name}
  * 例: alarm_template_id=0:ob_cluster=obcluster-1 Config serverのrootserver情報が正しくない

* **アラート詳細**

  * テンプレート: OceanBaseクラスタ\${ob_cluster_name}:${ob_cluster_id}のrootserver情報がconfig server内のrootserver情報と一致しません。OceanBaseクラスタのconfigUrl設定を確認してください。
  * 例: OceanBaseクラスタobcluster-1:10000のrootserver情報がconfig server内のrootserver情報と一致しません。OceanBaseクラスタのconfigUrl設定を確認してください。

## システムへの影響

config server内のrootserver情報が正しくない場合、obproxyがそのクラスタを正常にプロキシできなくなる可能性があります。

## 考えられる原因

* OceanBaseクラスタのobconfig_url設定URLにアクセスできません。

* OceanBaseクラスタで誤ったobconfig_urlが設定されています。

## 対処方法

* クラスタのobconfig_urlが現在のOCPのconfig urlであるかどうかを判断します。

  ```sql
  SHOW PARAMETERS LIKE 'obconfig_url'
  ```

  * そうである場合、そのurlが正常にサービスを提供できるかどうかを判断します。

  * そうでない場合、OceanBaseのobconfig_urlを現在のOCPのconfig urlに変更し、そのconfig serverサービスが利用可能であることを確認します。

    ```sql
    ALTER SYSTEM SET `obconfig_url`='...'
    ```
