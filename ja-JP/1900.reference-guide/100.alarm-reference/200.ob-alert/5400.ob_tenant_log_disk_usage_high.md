# ob_tenant_log_disk_usage_high OceanBaseテナントのログディスク使用率がしきい値を超えた

## アラートの概要

OceanBase V4.0以降、ログディスク容量はテナントごとに完全に分離されています。各サーバーは各テナントに十分なログディスク容量を予約し、テナント間での相互干渉を防ぎます。Unit Configに`LOG_DISK_SIZE`パラメータが追加され、Unitのログディスク容量を表します。ユーザーが`LOG_DISK_SIZE`を指定しない場合、Shared-Nothing (SN)モードではデフォルトでテナントメモリサイズの3倍、最小2GiBとなります。Shared-Storage (SS)モードではデフォルトでテナントメモリサイズの1倍、最小3GiBとなります。

テナントUnitの作成時および移行時には、RSがログディスク容量を考慮し、ログディスクの残存空き容量がUnitの`LOG_DISK_SIZE`設定より大きいサーバーをターゲットサーバーとして選択します。テナントのログ容量使用率がしきい値を超えるとこのアラートがトリガーされます。

## アラートの仕組み

| パラメータ | 値 |
| -------- | ------- |
| モニタリング指標 | ob_tenant_log_disk_usage。この指標はOceanBaseテナントのログディスク使用率を示し、使用率がしきい値を超えるとアラートがトリガーされます。  |
| モニタリング式 | ```100 * avg(ob_tenant_log_disk_used_bytes{@LABELS}) by (@GBLABELS) / avg(ob_tenant_log_disk_total_bytes{@LABELS}) by (@GBLABELS)```  |
| 取得指標 | ob_tenant_log_disk_used_bytes、ob_tenant_log_disk_total_bytes |
| 指標ソース | 内部ビューから取得。取得SQL：```SELECT T1.UNIT_ID, T1.SVR_IP, T1.SVR_PORT, T3.TENANT_ID, T3.TENANT_NAME, T1.LOG_DISK_SIZE, T1.LOG_DISK_IN_USE FROM (SELECT UNIT_ID, SVR_IP, SVR_PORT, SUM(LOG_DISK_SIZE) AS LOG_DISK_SIZE, SUM(LOG_DISK_IN_USE) AS LOG_DISK_IN_USE FROM V$OB_UNITS GROUP BY UNIT_ID) T1 JOIN DBA_OB_UNITS T2 JOIN (SELECT TENANT_ID, TENANT_NAME FROM DBA_OB_TENANTS WHERE TENANT_TYPE IN ('SYS', 'USER')) T3 ON T1.UNIT_ID = T2.UNIT_ID AND T2.TENANT_ID = T3.TENANT_ID```   |
| 取得周期 |  5秒 |

## システムへの影響

OBServerノードのログディスクの残り容量が不足している場合、OBServerノードが正常に動作しなくなる可能性があります。

## 考えられる原因

ログ容量の設定が不適切です。

## 解決策

OceanBase V4.0では、ログディスクのパラメータは以下のように導入されました：

* `log_disk_size` ：ログディスクのサイズを表します。つまり、このサーバーが使用できるログディスクの総容量です。デフォルト値は0で、ローカルのログディスクの実際の容量に基づいて計算する必要があることを意味します。

* `log_disk_percentage` ：ログディスクの使用割合を表します。ユーザーが `log_disk_size` を0に設定した場合、ログディスク容量は `log_disk_percentage` に基づいて割り当てられます。デフォルト値は0で、データと同じディスクを共有するかどうかに基づいて自動的に計算されることを意味します。

`log_disk_size` と `datafile_size` が0に設定されている場合、ログディスクとデータディスクのサイズを自動的に計算する必要があることを意味します。以下が計算方法です。

1. `log_disk_percentage` または `datafile_disk_percentage` の設定が0以外の場合、percentageに基づいてsizeを計算します：

   1. `log_disk_size = ログが存在する物理ディスクのサイズ * log_disk_percentage`

   2. `datafile_size = データが存在する物理ディスクのサイズ * datafile_disk_percentage`

2. `log_disk_percentage` または `datafile_disk_percentage` の設定が0の場合、データとログが同じディスクを共有するかどうかに基づいてpercentageを計算し、その後percentageに基づいてsizeを計算します：

   1. データとログが同じディスクを共有する場合：

      1. `log_disk_percentage = 30%`

      2. `datafile_disk_percentage = 60%`

   2. データとログが別々のディスクを専有する場合：

      1. `log_disk_percentage = 90%`

      2. `datafile_disk_percentage = 90%`

3. ログディスクとデータディスクが同じディスクを共有する場合、使用可能なログディスクの割合である `log_disk_percentage` を調整し、デフォルト値が小さすぎてログディスク容量が不足するのを防ぎます。

4. ログディスクとデータディスクが同じディスクを共有せず、ログディスクに空き容量がある場合、`log_disk_percentage` を適切に大きく設定できます。
