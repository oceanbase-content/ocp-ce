# obproxy_client_connections_usage_over_threshold OBProxyクライアント接続利用率がしきい値を超えた

## アラートの概要

OBProxyクライアントの接続数利用率がしきい値を超えた場合にアラートが発生します。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | client_connection_used_percent。この指標はOBProxyクライアントの接続利用率、すなわちOBProxyクライアント接続数 / 接続総数を表します。接続利用率がしきい値を超えるとアラートがトリガーされます。 |
| モニタリング式 | ```100 * sum(odp_current_session{sessionType="client",@LABELS}) by (@GBLABELS) / sum(obproxy_client_max_connections{@LABELS}) by (@GBLABELS)```   |
| 取得指標 | odp_current_session、obproxy_client_max_connections |
| 指標の出典 | <li>クライアント接続数はOBProxyのモニタリングから取得します：`http://ip:2884/metrics` の `odp_current_session` データ（カウント）。</li><li>クライアント接続数の上限はOBProxyのシステムパラメータから取得します：`SHOW proxyconfig LIKE`。</li> |
| 取得サイクル | 5秒 |

## ルール情報

|        モニタリング指標         | デフォルトしきい値（単位：%） | 持続時間 | 検出サイクル | 解消サイクル |
|-------------------------|--------------------|----------|----------|---------|
| client_connection_used_percent | 85    | 0秒      | 15秒     | 5分       |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| ------------ | ------- | ------ |
| モニタリング指標の式に基づく | 重大 | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:obproxy_cluster=TEST-1:host=xxx.xxx.xxx.xxx OBProxyクライアント接続利用率がしきい値を超えた

* **アラート詳細**

  * テンプレート：OBProxyクラスタ：${obproxy_cluster}、ホスト：${host}、アラート：${alarm_name}。クライアント接続利用率 ${value_shown} がしきい値 ${alarm_threshold} % を超えました。
  * サンプル：OBProxyクラスタ：TEST、ホスト：xxx.xxx.xxx.xxx、アラート：OBProxyクライアント接続利用率がしきい値を超えた。クライアント接続利用率 90 % がしきい値 85 % を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OBProxyクライアント接続数利用率：\${value_shown}
  * サンプル：アラート：OBProxyクライアント接続利用率がしきい値を超えた、OBProxyクライアント接続数利用率：80 %

## システムへの影響

* 業務リクエストの応答時間が長くなります。
* 業務リクエストがバックログとして蓄積された後に影響が発生します。例えば、SQLリクエストが長時間応答しない、接続タイムアウトなどが発生します。

## 考えられる原因

* 業務リクエスト量が多すぎる。
* OBServerの応答が遅く、接続数がバックログとして蓄積されています。

## 解決策

1. アラート対応プランによる処理

   1. プランを実行し、アラート問題を迅速に解決します。詳細な操作については、[アラート対応プラン](../500.appendix/400.execute-the-plan.md)を参照してください。
   2. プランの再試行。プランが継続して実行され、元の問題が解決されることを確保する必要があります。
   3. プランのロールバック。OceanBaseサポートチームに連絡し、プランのロールバックを支援してもらうことができます。

2. OBProxyの接続数の上限を設定し、OBProxyのメモリを拡張することを試みることができます。メモリは20%程度拡張し、パラメータ`client_max_connections, proxy_mem_limited`を変更します。具体的なコマンド：

   ```sql
   ALTER proxyconfig SET client_max_connections = xxx;
   ALTER proxyconfig SET proxy_mem_limited = xxx;
   ```
