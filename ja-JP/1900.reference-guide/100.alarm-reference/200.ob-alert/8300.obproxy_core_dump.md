# obproxy_core_dump OBProxy server Core Dump

## アラートの説明

OBProxyでコアダンプが発生した場合にこのアラートが生成されます。20分後にはアラートが表示されなくなります。

## アラートの仕組み

| パラメータ | 値 |
| -------- | -------- |
| モニタリング指標 | obproxy_core_dump_seconds。この指標は、OBProxyの直近のコアダンプ時間を示します。その値がしきい値を超えた場合にアラートがトリガーされます。  |
| モニタリング式 | ```max(obproxy_coredump_time_seconds{@LABELS}) by (@GBLABELS)``` |
| 取得指標 | obproxy_coredump_time_seconds  |
| 指標の出典 | OBProxyモニタリング。OBProxyの直近のコアダンプ時間を秒単位で確認します。 |
| 取得サイクル | 5秒 |

## ルール情報

| モニタリング式 | デフォルトしきい値(単位：秒) | 検出サイクル | 解消サイクル |
| --------- | --------- | -------- | -------- | -------- |
| obproxy_core_dump_seconds | obproxy_core_dump_seconds < 1200 and obproxy_core_dump_seconds > 0 | 0 | 10秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| -------- | -------- | -------- |
| モニタリング指標の式に基づく | 悪質 | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=2:obproxy_cluster=TEST-2000005:host=xxx.xxx.xxx.xxx OBProxy server Core Dump

* **アラート詳細**

  * テンプレート：クラスタ：\${obproxy_cluster}、ホスト：${host}、アラート：\${value_shown}前にOBProxy server Core Dump。
  * サンプル：クラスタ：TEST、ホスト：xxx.xxx.xxx.xxx、アラート：19分50.54秒前にOBProxy server Core Dump。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OBProxyの直近のコアダンプまでの時間：\${value_shown}
  * サンプル：アラート：OBProxy server Core Dump、OBProxyの直近のCore Dumpまでの時間：0秒

## システムへの影響

プロセスのコアダンプは、予期しないエラーによって発生し、異常が発生した際の環境を保存して後の分析に利用するためのものです。コアダンプ後、プロセスは再起動します。これはシステムにとって保護策であり、予期しない状況がシステムに与える影響は、ケースバイケースで分析する必要があります。

## 考えられる原因

* プログラムに予期しないエラーが存在します。
* OBProxyのバージョンが古すぎる場合、設計上の制限が存在する可能性があります。例えば、低バージョンのMySQLパケットが16MBを超えるとコアダンプがトリガーされることがあります。

## 解決策

1. コアダンプファイルを取得し、OBProxyの技術サポートに連絡して分析を依頼します。コアダンプファイルのディレクトリはOBProxyの実行ディレクトリ内にあり、デフォルトのパスは`/home/admin/logs/obproxy/minidump`です。ファイルの拡張子は`.dmp`です。
2. 設定されたOBProxyのメモリが大きすぎると、コアダンプ処理が長引く可能性があります。例えば、デフォルトのメモリが2GBで、設定されたメモリがデフォルト値を大幅に上回る場合です。緊急時の対応として、OBProxyプロセスを再起動せず（コアを無視して）、問題の拡大を防ぎます。また、OBProxyのバージョンアップグレードを試みてください。新バージョンではメモリ管理が最適化されています。
