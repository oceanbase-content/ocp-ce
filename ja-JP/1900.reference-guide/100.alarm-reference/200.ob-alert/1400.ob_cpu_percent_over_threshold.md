# ob_cpu_percent_over_threshold OceanBaseサーバー上のテナントスレッド平均使用率がしきい値を超える

## アラートの概要

OceanBaseサーバー上のテナントスレッド平均使用率がしきい値を超えたことを示します。

## アラートの仕組み

以下の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|---------|-------------|
| 監視指標 | ob_tenant_thread_percent。この指標はOceanBaseサーバー上のテナントスレッド平均使用率を表し、平均使用率がしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | ```100 * sum(ob_sysstat{stat_id="140006",@LABELS}) by (@GBLABELS) / sum(ob_sysstat{stat_id="140005",@LABELS}) by (@GBLABELS)```</br><ul><li>統計イベントID 140005：OceanBaseサーバー上のテナントが使用できる最大スレッド数を集計します。</li><li>統計イベントID 140006：OceanBaseサーバー上のテナントが使用しているスレッド数を集計します。</li></ul>監視式は、「stat_id=140006 の value の合計」と「stat_id=140005 の value の合計」の比率を監視指標値として表し、OceanBaseサーバー上のテナントスレッド平均使用率を示します。 |
| 収集指標 | ob_sysstat |
| 指標ソース | 内部ビューから収集。収集SQL：<li>OceanBase V4.0.0.0 より前のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN (140005, 140006) and (con_id > 1000 or con_id = 1)```</li><li>OceanBase V4.0.0.0 以降のバージョン：```select /* MONITOR_AGENT */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN (140005, 140006) and (con_id > 1000 or con_id = 1) and con_id in (select tenant_id from DBA_OB_TENANTS WHERE tenant_type<>'META')```</li> |
| 収集サイクル | 5秒 |

## ルール情報

|   監視指標     | デフォルトしきい値（単位：%） | 持続時間 | 検出サイクル | 解消サイクル |
|----------------|------------|------|------|------|
| ob_tenant_thread_percent | 80         | 60秒 | 10秒 | 5分 |

## アラート情報

|   アラートトリガー方式   | アラートレベル | 対象  |
|------------|------|-----|
| 監視指標の式に基づく | 悪質   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：alarm_template_id=0:ob_cluster=obcluster-1:host=xxx.xxx.xxx.xxx OceanBaseサーバー上のテナントスレッド平均使用率がしきい値を超える

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：OceanBaseテナントスレッド平均使用率 ${value_shown} が ${alarm_threshold} % を超えました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：OceanBaseテナントスレッド平均使用率 91.0 % が 80.0 % を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OceanBaseサーバー上のテナントスレッド平均使用率：\${value_shown}
  * 例：アラート：OceanBaseサーバーのテナントスレッド平均使用率が上限を超えました、OceanBaseサーバーのテナントスレッド平均使用率：79 %

## システムへの影響

テナントスレッドの平均使用率が高すぎると、システムのスループットが低下し、リクエストの遅延が高くなります。

一般的に、一時的なスレッド平均使用率の上昇は大きな影響はありませんが、継続的に高い場合は対処が必要です。

## 考えられる原因

複雑なSQLの実行などでよく見られます。

## 解決策

1. まず、[tenant_cpu_percent_over_threshold OceanBaseテナントスレッド使用率が上限を超えた](../200.ob-alert/2900.tenant_cpu_percent_over_threshold.md)が発生していないか確認します。

   * 発生している場合は、[tenant_cpu_percent_over_threshold OceanBaseテナントスレッド使用率が上限を超えた](../200.ob-alert/2900.tenant_cpu_percent_over_threshold.md)の解決策を参照してください。

   * 発生していない場合は、次の手順を実行します。

2. 複数のテナントで同時に負荷が高まり、OBServerノード内で負荷が重なり合ってアラートがトリガーされている可能性があります。

   複数のテナントで同時にトラフィックが増加し、スレッド使用率が高くなった場合は、以下の方法で低減できます：

   * クラスタの緊急拡張を行います。

     そのOceanBaseクラスタにOBServerノードを追加します。方法については、[OBServerノードの追加](../../../600.cluster-functions/600.manage-an-observer/100.add-an-observer.md)を参照してください。

   * [OceanBaseクラスタのトラフィック制限](../500.appendix/200.limit-the-inbound-traffic-of-the-oceanbase-cluster.md)を参照して、OceanBaseクラスタのトラフィックを制限します。
