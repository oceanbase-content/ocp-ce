# OBログアラート

## アラートの概要

OCP-Agent（ocp_monagent）は、OBServerノードおよびOBProxyの実行ログを監視し、ログにアラート設定と一致するパターンが検出されるとアラートをトリガーします。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>V4.0.2以降のOCPでは、画面上で直接ログアラートを設定できます。V4.0.2より前のバージョンでは、ログアラートのキーワードはシステムパラメータ<code>ob.logtailer.keyword.alarm.rules</code>で設定できます。設定例は以下のとおりです。</p>
   </main>

```shell
[{"keyword":"error occurs on data disk or slog disk", "logLevel":"warn", "svrType":"observer", "errorCode":100003, "alarmLevel":2}]</br>
## OBServerノードのログに「error occurs on data disk or slog disk」というキーワードが含まれ、かつログレベルがwarnの場合、errorCode 100003の重大なアラートがトリガーされます。logLevelはerror、warnを設定できます。
```

## アラートの仕組み

OCP-Agentは、OBServerノードの以下のログを監視し、これらのログにERRORレベルのログが含まれるとログアラートをトリガーします。

* election.log

* observer.log

* rootservice.log

* /home/admin/oceanbase/logs/obproxy/log/obproxy_error.log

アラートの詳細には、エラーコード、ログの詳細、ログのTraceIdなど、ERRORログに関連するコンテキスト情報が表示されます。

## アラート情報

| アラートのトリガー方法     | アラートレベル | 対象範囲   |
| ---------------- | -------- | ------ |
| OceanBaseログ解析に基づく | 重大     | サーバー |

## ルール情報

| 監視指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| -------- | -------- | -------- | -------- | -------- |
| NA       | NA       | 0秒     | 3分   | 5分   |

## アラートテンプレート

* アラート概要テンプレート：[\${alarm_name}] ${alarm_target}

* アラート詳細テンプレート：[${alarm_name}] クラスタ：${ob_cluster_name}、ホスト：${host}、ログタイプ：${server_type}、ログファイル：${filename}、ログレベル：${log_level}、キーワード=${keyword}、エラーコード=${error_code}、TraceId=${trace_id}、ログ詳細=${error_message}

* アラート詳細例：[OBServer プログラムログ] クラスタ：obtest、ホスト：xxx.xxx.xxx.xxx、ログタイプ：observer_log、ログファイル：/home/admin/oceanbase/log/observer.log.wf、ログレベル：ERROR、キーワード=、エラーコード=-1、ログ詳細=2020-09-12 01:00:05.839998 ERROR SHARE fetch_rs_list_from_url (ob_web_service_root_addr.cpp:176) 71411Y0-0005ABFA67B71CA5lt=3 call web service failed(ret=-4216, url="http://www.domain.com:80/services?Action=ObRootServiceInfo\&User_ID=alibaba\&UID=ocp_master\&ObRegion=test-ob-cluster", timeout_ms=2000) BACKTRACE:0x31f2fb9 0x3183c77 0x197e50d 0x197e624 0x193b389 0x846de0 0x847742 0x3475fe2 0x323bd7d 0x3239b1e 0x7f5290057e25 0x7f528e912bad

ログ名は OB_CURL_ERROR で、ログ詳細の説明は web service の呼び出し失敗であり、これは OBServer ノードが配置されているマシンが対応する URL アドレスにアクセスできないために発生した可能性があります。

ここで：

* ${alarm_name}：アラート名を表します。例：OBServerノードプログラムログ。

* ${ob_cluster_name}：アラートが発生したクラスタ名を表します。

* ${host}：アラートが発生したサーバーの IP またはホスト名を表します。

* ${filename}：ログファイル。

* ${log_level}：ログレベル。

* ${keyword}：キーワード。

* ${error_code}：エラーコード。

* ${error_message}：ログ詳細。

## システムへの影響

具体的な問題によっては、一部の ERROR 問題がビジネスに影響を与える可能性があります。特に以下のキーワードに注意してください。これらはサービス停止を引き起こす可能性があります：

1. is_out_of_memstore_mem=true ERROR ログ、memstore 不足。
2. right_to_die_or_duty_to_live ERROR ログ、プロセスは終了する可能性があります。
3. on_fatal_error ERRORログ、システムの致命的なエラー、プロセスは終了する可能性があります。

## 考えられる原因

OBServerノードが重大な回復不能なエラーに遭遇し、OceanBaseログに ERROR レベルのログが存在する原因となりました。

## 対処方法

1. ログ内のエラーが無視できるか確認します。

   アラートのヒントに従ってログ詳細を確認し、該当するログエラーが無視できるものであることを確認します。

   * 無視できる場合は、OCP **アラート \> OceanBaseログフィルタリング** でフィルタールールを設定し、今後同じログが再びアラートをトリガーするのを防ぎます。

   * 無視できない場合は、次の手順を実行します。

2. ログ詳細に基づいて具体的な問題を特定し、解決します。

   * 他のアラートが発生している場合は、まずドキュメントを参照して他のアラートを解決します。

   * 他のアラートが発生していない場合、詳細を確認し、エラーコードが提供されているかどうかを確認します。

     * エラーコードが提供されている場合、それは既知のエラーです。[OCPエラーメッセージ表](../../500.error-code-reference/100.ocp-error-table.md) を参照して解決してください。

     * エラーコードが提供されていない場合、それは未知のエラーです。そのTraceIDに関連するログを収集し、OceanBaseテクニカルサポートチームに提供して調査してもらいます。
