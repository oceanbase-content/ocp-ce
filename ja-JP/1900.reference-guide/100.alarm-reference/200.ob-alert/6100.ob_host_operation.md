# ob_host_operation OceanBaseサーバー運用保守操作リマインダー

## アラートの説明

OBServerに対して運用保守タスクを実行すると、**<UI-TERM key="ocp-v2.src.constant.alarm.Reminder">注意</UI-TERM>** レベルのアラートが発報されます。アラートレベルは他のレベルに変更できます。

運用保守タスクのリスト：

* サービス/プロセスの停止
* observerの起動
* observerの再起動
* observerの置換
* observerの追加
* observerの再インストール
* observerの削除

## アラートの仕組み

なし。

## ルール情報

| モニタリング式 | モニタリング指標の意味 | デフォルトしきい値 | 検出周期 | 解消周期 |
| ---------- | ------------ | -------- | -------- | -------- |
| NA         | NA           | 0秒     | NA       | 5分   |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 適用範囲      |
| ------------ | -------- | --------- |
| 運用保守イベントのトリガー | リマインダー     | ホスト |

## アラートテンプレート

* アラート概要

  * テンプレート：\${alarm_target} \${alarm_name}
  * 例：alarm_template_id=0:ob_cluster=ob1-1:host=xxx.xxx.xxx.xxx:operation_name=Restart observer SUCCESS

* アラート詳細

  * テンプレート：クラスタ：\${ob_cluster_name}、サーバー：\${host}、アラート：\${operation_name} \${operation_result}、操作者 \${operator}、実行結果：\${task_result}。
  * 例：クラスタ：ob1、サーバー：xxx.xxx.xxx.xxx、アラート：Restart observer SUCCESS、操作者 admin、実行結果：success。

## システムへの影響

システム障害は日常の運用保守でよく発生します。運用保守後にシステムに異常が発生していないか注意深く観察し、具体的な状況に応じて詳細に分析する必要があります。

## 考えられる原因

一般的な原因はありません。

## 対処方法

1. 運用保守後に異常が発生した場合は、テクニカルサポートにお問い合わせいただき、解決をお手伝いします。
2. 業務に重大な影響が生じた場合は、速やかに運用保守操作をロールバックしてください。
