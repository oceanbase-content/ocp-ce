# ob_tenant_large_trans_exist OceanBaseテナントに大規模トランザクションが存在する

## アラートの説明

OCPでは、大規模トランザクションは以下の2つの条件のいずれかを満たすものと定義されています。いずれか一つの条件を満たせば大規模トランザクションとなります。

1. 単一参加者のログサイズが0.5MiBを超える場合（OceanBase V3.2以降でサポートされています）。

2. トランザクション実行時間が500msを超える場合。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>このアラートは、ログサイズが0.5MiBを超える場合にのみ発報されます。トランザクション実行時間はスローSQLのアラート基準に従います。</p>
</main>

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要パラメータを示しています。

| パラメータ | 値 |
|-------|----------|
| 監視指標 | trans_max_log_size_mb。この指標は、OceanBaseテナントの単一参加者のログサイズを示し、その値がしきい値を超えた場合にアラートがトリガーされます。   |
| 監視式 | ```max(log_size_byte)/1024/1024```  |
| 収集指標 | log_size_byte   |
| データソース | 内部ビューから収集。<li>収集SQL：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(%d)*/ a.tenant_id, b.tenant_id as tenant_id_xa, a.trans_id, `partition`, floor(ctx_create_time) as ctx_create_time, session_id, participants, trans_type, part_trans_action, sql_no, log_size_byte from (select tenant_id, svr_ip, trans_id, `partition`, unix_timestamp(ctx_create_time) *1000000 as ctx_create_time, session_id, participants, (pending_log_size + flushed_log_size) as log_size_byte, trans_type, part_trans_action, sql_no from __all_virtual_trans_stat where svr_ip = ? and svr_port = ? and is_exiting != 1) a left join __all_virtual_global_transaction b on a.tenant_id = b.tenant_id and a.trans_id = b.trans_id```</li><li>トランザクションログサイズ：```select max(log_size_byte)/1024/1024 as trans_max_log_size_mb from ob_hist_trans_stat```</li>   |
| 収集間隔 | 5秒 |

<main id="notice" type='explain'>
<h4>説明</h4>
<p>システムパラメータ <code>ocp.alarm.datasource.trans-min-log-size-mb</code> が、トランザクションログサイズが何MiBを超えるとアラートを発報するかを決定します。したがって、アラートのしきい値はこのシステムパラメータの設定値以上である必要があり、デフォルトは0.5MiBです。</p>
</main>

## システムへの影響

大規模トランザクションはシステムメモリに影響を及ぼす可能性があります。例えば、スタンバイマシンでは順不同で再生が行われるため、メモリ不足によりダンプが必要になった場合、後にコミットされたが先に再生されたトランザクションを移動させる必要があります。移動にはメモリが必要であり、トランザクションをダンプポイントまで再生するのにもメモリが必要です。この時、両方とも完了できず、結果としてメモリが枯渇することがあります。同様に、リーダー上でトランザクションを実行する際にも同様の問題が発生する可能性があります。

## 考えられる原因

単一のトランザクション内で過剰なデータがコミットされた。

## 対処方法

1. OCPテナント管理のトランザクション診断機能を使用して、大規模トランザクションが発生した原因を特定し、適切に対処します。

2. 業務上予想される大規模トランザクションの場合、業務を分割できないか確認し、大規模トランザクションを回避するか、アラートのしきい値を引き上げることを検討します。
