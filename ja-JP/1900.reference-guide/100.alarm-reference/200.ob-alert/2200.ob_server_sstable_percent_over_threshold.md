# ob_server_sstable_percent_over_threshold OceanBaseサーバーのデータディスク使用率が上限を超えた場合

## 警報の概要

この警報は、OBServerノードのデータディスクにおいて、データファイルの保存に利用可能な空き容量の使用率が上限を超えているかどうかを監視し、超えた場合にアラートを発報します。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>データディスクは、デフォルトで <code>/data/1</code> ディレクトリのマウントディスクです。</p>
</main>

OceanBaseクラスタ作成時に、システムがこのディスクを初期化し、データファイルの保存に利用可能な空き容量のサイズを指定します。

## 警報の仕組み

以下の表は、この警報の監視ロジックに関連する主要パラメータを示しています。

| パラメータ | 値 |
|-------|----------------|
| 監視指標 | ob_disk_percent。この指標はOBServerノードのデータディスク使用率を示し、使用率がしきい値を超えた場合に警報がトリガーされます。      |
| 監視式 | ```100 * (sum(ob_disk_total_bytes{@LABELS}) by (@GBLABELS) - sum(ob_disk_free_bytes{@LABELS}) by (@GBLABELS)) / sum(ob_disk_total_bytes{@LABELS}) by (@GBLABELS)``` |
| 取得指標 | ob_disk_total_bytes、ob_disk_free_bytes       |
| データソース | 内部ビューから取得。取得SQL：<li>OceanBase V4.0.0.0未満のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ total_size, free_size from __all_virtual_disk_stat where svr_ip = ? and svr_port = ?```</li><li>OceanBase V4.0.0.0以上、V4.2.0.0未満のバージョン：```select /* MONITOR_AGENT */ data_disk_capacity, (data_disk_capacity - data_disk_in_use) as data_disk_in_free, log_disk_capacity, log_disk_assigned, log_disk_in_use from V$OB_SERVERS where svr_ip = ? and svr_port = ?```</li><li>OceanBase V4.2.0.0以上のバージョン：```select /* MONITOR_AGENT */ data_disk_capacity, data_disk_allocated, (data_disk_capacity - data_disk_in_use) as data_disk_in_free, (data_disk_allocated - data_disk_in_use) as data_disk_allocated_in_free,log_disk_capacity, log_disk_assigned, log_disk_in_use from V$OB_SERVERS where svr_ip = ? and svr_port = ?```</li>    |
| 取得間隔 | 5秒 |

## ルール情報

|       監視指標            | デフォルトしきい値（単位：%） | 持続時間 | 検出周期 | 解消周期 |
|---------------------------|------------|------|------|------|
| ob_disk_percent | この指標には以下の2つのデフォルトしきい値があります：<li>ob_disk_percent > 85</li><li>ob_disk_percent > 97</li>       | 0秒  | 20秒 | 5分 |

## 警報情報

|   アラートのトリガー方法   | アラートレベル | 対象  |
|------------|------|--------|
| 監視指標の式に基づく | <li>ob_disk_percent > 85：警告</li><li>ob_disk_percent > 97：重大</li>   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：ob_cluster=obcluster-1:svr_ip=xxx.xxx.xxx.xxx OceanBaseサーバーのデータディスク使用率が上限を超えた場合

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。データディスク使用率 \${value_shown} が ${alarm_threshold} % を超えました。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：OceanBaseサーバーのデータディスク使用率が限度を超えています。データディスク使用率 86.0 % が 85.0 % を超えました。

* **アラートの復旧**

  * テンプレート：アラート：${alarm_name}、OBServerデータディスク使用率：\${value_shown}
  * サンプル：アラート：OceanBaseサーバーのデータディスク使用率が限度を超えています、OBServerデータディスク使用率：80 %

## **システムへの影響**

データディスクの空き容量が不足しているため、今後新しいデータの書き込みがデータディスクに保存できない可能性があります。

## **考えられる原因**

アプリケーションデータの規模が継続的に増加したことが原因です。

## **対処方法**

以下の方法を試して解決できます：

1. 不要なテナント、データベース、テーブルを削除します。

2. ごみ箱を空にすると、2回のメジャーコンパクション後にリソースが解放されます。

3. ユニットを他のOBServerノードに移行します。利用可能なターゲットOBServerノードがない場合は、まずクラスタの拡張（OBServerノードの追加）を行う必要があります。

以下のSQLコマンドを参照して、特定のテナントのすべてのテーブルのストレージ容量を確認できます：

```sql
-- テナントIDの設定
set @tenant_id=1001

-- 適用シナリオ：1.x のすべてのバージョン
select  b.table_name,sum(a.required_size)/1024/1024/1024 required_GB,sum(row_count) as rows from __all_meta_table a, __all_table b where a.table_id = b.table_id and a.zone = 'zone_name' and a.tenant_id = @tenant_id group by a.table_id order by required_GB desc;

-- 適用シナリオ：2.x および 3.x のすべてのバージョン
select c.database_name, b.table_name,sum(a.required_size)/1024/1024/1024  required_GB,sum(row_count)  as  rows  from  __all_virtual_meta_table  a inner join  __all_virtual_table  b on a.table_id=b.table_id inner join __all_virtual_database c on b.database_id=c.database_id where b.table_type<>5 and a.zone  =  'zone_name'  and  a.tenant_id  = @tenant_id group  by  a.table_id  order  by required_GB  desc;
```
