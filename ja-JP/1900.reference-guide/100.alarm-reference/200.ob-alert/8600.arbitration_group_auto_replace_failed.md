# arbitration_group_auto_replace_failed アービトレーショングループの自動アービトレーションサービス切り替え失敗

## アラートの概要

<main id="notice" type='explain'>
<h4>説明</h4>
このアラートは、V4.2.0.0以降のOceanBaseクラスタでのみ有効です。
</main>

アービトレーションサービスに関連付けられたOceanBaseクラスタがアービトレーションサービスとの接続を失い、かつアービトレーショングループの自動切り替えポリシーがトリガーされた場合、OceanBaseクラスタはグループ内の他のアービトレーションサービスへ自動的に切り替えます。OceanBaseクラスタのアービトレーションサービス自動切り替えタスクが失敗した場合、このアラートがトリガーされ、ユーザーに切り替え失敗を通知し、関連するタスクIDを提供します。

## アラートの仕組み

| パラメータ | 値 |
| ---------- | ------------ |
| モニタリング指標   | arbitration_group_auto_replace_task_status。この指標はアービトレーショングループの自動切り替え状態を示し、値が`1`の場合はそのアービトレーショングループに切り替え失敗のタスクが存在しないことを意味します。値が`0`の場合はアービトレーショングループに切り替え失敗のタスクが存在し、アラートがトリガーされることを意味します。 |
| モニタリング式 | ```sum(arbitration_group_auto_replace_task_status{@LABELS}) by (@GBLABELS)``` |
| 取得指標   | arbitration_group_auto_replace_task_status |
| データソース   | OCP-Serverが定期的にアービトレーションサービスの自動切り替え失敗タスクの有無を照会し、存在する場合はタスクからアービトレーショングループ情報を解析してアラートを発します。 |
| 取得サイクル   | 5秒 |

| アラートトリガー方法 | アラートレベル | 対象範囲   |
| ----------- | -------- | ------ |
| モニタリング指標の式に基づく | 重大     | アービトレーションサービス |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${group_name} \${alarm_name}
  * サンプル：alarm_template_id=0:arbitration_group_A アービトレーショングループの自動アービトレーションサービス切り替え失敗

* **アラート詳細**

  * テンプレート：アービトレーショングループ \${group_name} の自動アービトレーションサービス切り替えに失敗しました。
  * サンプル：アービトレーショングループ arbitration_group_A の自動アービトレーションサービス切り替えに失敗しました。

* **アラートの復元**
  * テンプレート：アラート：${alarm_name}、アービトレーショングループの自動アービトレーションサービス切り替えタスク状態：\${recover_value}
  * サンプル：アラート：アービトレーショングループの自動アービトレーションサービス切り替え失敗、アービトレーショングループの自動アービトレーションサービス切り替えタスク状態：1

## システムへの影響

OceanBaseクラスタのアービトレーションサービスの自動切り替えタスクが失敗すると、クラスタが長時間アービトレーションサービスを持たない可能性があり、2F/4Fテナントの高可用性機能に影響を与えます。テナントのレプリカ障害が発生した場合、システムサービスに直接影響します。

## 考えられる原因

1. 切り替えタスクの実行中に、ターゲットのアービトレーションサービスサーバーがダウンしました。
2. 切り替えタスクの実行中に、ターゲットのアービトレーションサービスプロセスが停止しました。
3. OCPとOceanBaseクラスタが接続できません。

## 解決策

1. ターゲットのアービトレーションサービスサーバーが稼働状態にあるか確認します。
2. ターゲットサーバープロセスが存在し、外部にサービスを提供しているか確認します。
3. OCPがOceanBaseクラスタに接続でき、OceanBaseクラスタが生存しているか確認します。
