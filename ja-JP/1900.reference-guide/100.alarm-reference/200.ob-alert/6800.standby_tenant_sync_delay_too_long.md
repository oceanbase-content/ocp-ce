# standby_tenant_sync_delay_too_long スタンバイテナントの同期遅延が大きすぎる

## アラートの概要

OCP Serverは、スタンバイテナントとプライマリテナント間の同期遅延時間を監視します。スタンバイテナントの同期遅延が600秒以上になると、このアラートが発生します。

## アラートの仕組み

| パラメータ | 値 |
| -------- | --------- |
| 監視指標 | standby_tenant_delay_seconds。この指標はスタンバイテナントとプライマリテナントの同期遅延時間を示し、遅延時間がしきい値以上になるとアラートがトリガーされます。 |
| 監視式 | ```sum(standby_tenant_delay_seconds{@LABELS}) by (@GBLABELS)``` |
| 取得指標 | standby_tenant_delay_seconds |
| 指標ソース | Oceanbase内部テーブル`GV$OB_LOG_STAT`、`DBA_OB_TENANTS`からプライマリ・スタンバイテナントの現在のデータ位置を取得し、両者の差を計算してスタンバイテナントの同期遅延時間を求めます。 |
| 取得サイクル | 5秒 |

## ルール情報

| 監視式 | デフォルトしきい値（単位：秒） | 持続時間 | 検出サイクル | 解消サイクル |
| ---------- | ------------------- | -------- | -------- | -------- |
| standby_tenant_delay_seconds | 600 | 0秒 | 60秒 | 5分 |

## アラート情報

| アラートトリガー方式 | アラートレベル | 対象範囲 |
| ----------- | -------- | ----- |
| 監視指標の式に基づく | 警告 | テナント |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=clusterB-1:tenant_name=tenant_standby スタンバイテナントの同期遅延が大きすぎる

* **アラート詳細**

  * テンプレート：OceanBaseクラスタ${ob_cluster_name}のスタンバイテナント${tenant_name}の同期遅延が大きすぎます。現在の同期遅延は${value}秒です。
  * サンプル：OceanBaseクラスタclusterBのスタンバイテナントtenant_standbyの同期遅延が大きすぎます。現在の同期遅延は2854.016秒です。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、スタンバイテナント同期遅延時間：\${value}秒
  * サンプル：アラート：スタンバイテナントの同期遅延が大きすぎる、スタンバイテナント同期遅延時間：68秒

## システムへの影響

スタンバイテナントで同期されるデータはプライマリテナントより遅延します。

## 考えられる原因

* スタンバイテナントのリソース構成が低すぎる。
* スタンバイテナントの同期状態が異常です。
* プライマリテナントで過大な `archive_lag_target` パラメータが設定されています。

## 解決策

1. テナントのプライマリ/スタンバイ関係トポロジーダイアグラムを確認し、スタンバイテナントの同期状態に異常がないか確認します。異常がある場合は、まずその問題を解決します。
2. プライマリ・スタンバイテナントのUnit仕様を確認すると同時に、スタンバイテナントの同期遅延を継続的に観察します。スタンバイテナントの同期遅延が継続的に大きく、かつUnit仕様がプライマリテナントより小さい場合は、スタンバイテナントの仕様を適切に引き上げるか、プライマリテナントと同一にすることを推奨します。
3. アーカイブを基盤とするプライマリ/スタンバイテナントの場合、プライマリテナントの `archive_lag_target` パラメータの設定値を確認します。このパラメータはテナントのアーカイブ遅延に影響し、それによってスタンバイテナントの同期遅延時間にも影響します。状況に応じて適切な `archive_lag_target` パラメータ値を設定することを推奨します。
