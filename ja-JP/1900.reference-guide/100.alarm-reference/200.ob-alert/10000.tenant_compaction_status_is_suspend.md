# tenant_compaction_status_is_suspend テナントのメジャーコンパクション一時停止

## アラートの概要

このアラートは、OceanBaseクラスタ内の各テナントのメジャーコンパクションが一時停止状態にあるかどうかを監視します。OCPが特定のテナントのメジャーコンパクションが一時停止されたことを検出すると、即座にアラートを発報します。

メジャーコンパクションは、OceanBaseデータベースのコアバックグラウンド操作であり、増分データとベースラインデータを統合してストレージ容量を解放し、クエリパフォーマンスを最適化します。この機能は、OceanBase V4.0バージョンからテナントレベルでのメジャーコンパクション管理をサポートしています。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
| -------- | --------- |
| 監視指標 | tenant_compaction_status |
| 監視式 | `max(tenant_compaction_status{@LABELS}) by (@GBLABELS)` |
| 取得指標 | tenant_compaction_status |
| 指標ソース | OCPの定期タスクCheckSuspendTenantCompactionTaskが、OceanBaseクラスタのシステムビュー`CDB_OB_MAJOR_COMPACTION`をリアルタイムでクエリし、`is_suspended`フィールドを取得してテナントのメジャーコンパクションが一時停止されているかどうかを判断します。 |
| 取得サイクル | 60秒 |

OCPは、定期タスク`TenantSchedules.checkSuspendTenantCompactionStatus()`を実行し、60秒ごとにデータを取得します。具体的なプロセスは以下のとおりです：

1. OceanBase V4.0以降のバージョンで、実行状態にあり、CLI以外の方法で登録されたクラスタをフィルタリングします。

2. 各クラスタについて、`CompactionOperator.listObTenantCompaction()`を使用して、以下のSQLを実行し、OceanBaseクラスタをリアルタイムでクエリします：

   ```sql
   SELECT tenant_id, global_broadcast_scn AS broadcast_scn, is_error AS error, status,
          frozen_scn, last_scn, is_suspended AS suspend, info, start_time, last_finish_time
   FROM CDB_OB_MAJOR_COMPACTION
   ```

3. 各テナントについて、クエリ結果の`is_suspended`フィールドに基づいてメジャーコンパクションの状態を判断します：

   * `is_suspended`が`YES`(suspend = true)の場合、出力する指標値は1となります。

   * `is_suspended`が`NO`(suspend = false)の場合、出力する指標値は0となります。

監視指標tenant_compaction_statusの値が1の場合、そのテナントのメジャーコンパクションが一時停止状態にあることを意味し、アラートがトリガーされます。

## ルール情報

| 監視指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| -------- | -------- | ------- | -------- | -------- |
| tenant_compaction_status | 1 | N/A | 60秒 | 5分 |

持続時間がN/Aの場合、指標値が1に等しいことが検出されたら、待機することなく即座にアラートがトリガーされます。

|  アラートのトリガー方式  |  アラートレベル  |  対象範囲   |
|---------------|-----------|-----------|
|  モニタリング指標の式    |  重大     |  テナント   |

## アラートテンプレート

* **アラート概要**
  * テンプレート：${alarm_target} ${alarm_name}
  * 例：ob_cluster=obcluster-1:tenant_name=mytenant テナントメジャーコンパクション一時停止

* **アラート詳細**
  * テンプレート：OceanBaseクラスタ${ob_cluster_name}のテナント${tenant_name}のメジャーコンパクション状態が一時停止です。メジャーコンパクションを続行することを推奨します。
  * 例：OceanBaseクラスタobcluster-1のテナントmytenantのメジャーコンパクション状態が一時停止です。メジャーコンパクションを続行することを推奨します。

* **アラート回復**
  * テンプレート：アラート：${alarm_name}、テナントメジャーコンパクション状態は一時停止ですか：${value_shown}
  * 例：アラート：テナントメジャーコンパクション一時停止、テナントメジャーコンパクション状態は一時停止ですか：0

ここで、${alarm_target}はアラートが発生した対象を表し、形式は`ob_cluster=xxxxxxx:tenant_name=xxxxxxx`です。

## システムへの影響

テナントメジャーコンパクションが長時間一時停止すると、以下の問題が発生する可能性があります：

* ストレージ使用量の継続的な増加：増分データがベースラインデータと統合されず、MemTableとSSTableの冗長データが蓄積され続けるため、ディスク使用量が継続的に上昇し、深刻な場合はディスク容量不足のアラートがトリガーされる可能性があります。

* クエリパフォーマンスの低下：未統合の増分データの階層が増えると、読み取り操作でより多くのデータ階層をスキャンする必要があり、クエリの遅延が増大します。

* ダンプの負荷の増大：メジャーコンパクションが一時停止すると、フリーズされたMemTableの数が継続的に増加し、tenant_active_memstore_percent_over_threshold（MemTableメモリ使用率が高すぎるアラート）がトリガーされる可能性があります。深刻な場合は書き込みが制限される可能性があります。

* 以降のメジャーコンパクションへの影響：長時間メジャーコンパクションを行わないと、以降のメジャーコンパクションにかかる時間が長くなり、メジャーコンパクション中のシステムパフォーマンスへの影響がさらに大きくなります。

## 考えられる原因

一般的には、以下のような状況が考えられます：

* 人為的な一時停止：管理者がOCPインターフェースまたはSQLコマンド(`ALTER SYSTEM SUSPEND MERGE`)を使用して、特定の期間(例：セールイベントやデータ移行時)において業務パフォーマンスへの影響を避けるために、手動でテナントのメジャーコンパクションを一時停止した場合。

* メジャーコンパクションエラー後の一時停止：テナントのメジャーコンパクション処理中にエラーが発生し、システムまたは管理者がエラーの拡大を防ぐためにメジャーコンパクションを一時停止した場合。このシナリオでは、通常ob_tenant_compaction_error(テナントメジャーコンパクションエラー)アラートも同時にトリガーされます。

* メンテナンス操作後の未回復：クラスタのアップグレード、ノードの交換、データ移行などのメンテナンス操作中にメジャーコンパクションを一時停止し、操作完了後にそのままにしている場合。

* サードパーティツールまたはスクリプトによる操作：自動化されたメンテナンススクリプトやサードパーティ管理ツールが特定の操作を実行する際にメジャーコンパクションを一時停止し、操作完了後に自動で回復しなかった場合。

## 解決策

1. アラートに関連するテナント情報を確認します。OCPのアラート詳細からクラスタ名(ob_cluster_name)とテナント名(tenant_name)を取得し、該当するテナントを特定します。

2. メジャーコンパクションの一時停止が予定された操作であるか確認します。クラスタ管理者に連絡し、人為的にメジャーコンパクションを一時停止したかどうかを確認します。計画的な操作(例：セールイベント中の手動一時停止)の場合は、一時的にアラートを無視しても構いませんが、操作終了後には速やかにメジャーコンパクションを再開する必要があります。

3. メジャーコンパクションエラーが発生していないか確認します。ob_tenant_compaction_error (テナントのメジャーコンパクションエラー) アラートが同時に発生していないか確認します。メジャーコンパクションエラーにより一時停止した場合は、まずメジャーコンパクションエラーを調査し、解決する必要があります。OceanBaseクラスタのsysテナントで以下のSQLを実行して、メジャーコンパクションの詳細を確認できます：

   ```sql
   SELECT tenant_id, status, is_error, is_suspended, info
   FROM CDB_OB_MAJOR_COMPACTION;
   ```

   `is_error`がYESの場合、infoフィールドに具体的なエラー情報が含まれます。以下のSQLを実行して、エラーステータスをクリアできます：

   ```sql
   ALTER SYSTEM CLEAR MERGE ERROR TENANT = '<tenant_name>';
   ```

4. テナントのメジャーコンパクションを再開します。安全に再開できることを確認したら、OCPインターフェースで操作するか、以下のSQLを実行してメジャーコンパクションを再開します：

   ```sql
   ALTER SYSTEM RESUME MERGE TENANT = '<tenant_name>';
   ```

   OCPのテナントマージ管理ページで**マージの再開**ボタンをクリックすることもできます。

5. メジャーコンパクションが正常に再開されたか確認します。再開後、再度クエリを実行してメジャーコンパクションの状態を確認します：

   ```sql
   SELECT tenant_id, status, is_suspended FROM CDB_OB_MAJOR_COMPACTION
   WHERE tenant_id = <tenant_id>;
   ```

   `is_suspended`がNOであることを確認したら、OCPは次の収集サイクル(60秒)にメトリクス値を0に更新し、アラートは最大5分(resolve_timeout_seconds: 300)以内に自動的に解消されます。

6. 上記の方法でも問題が解決しない場合は、OCPテクニカルサポートにお問い合わせください。
