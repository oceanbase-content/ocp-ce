# ob_cluster_operation_info OceanBaseクラスタ運用保守操作リマインダー

## アラートの概要

ユーザーがOCPを通じて実行するすべてのクラスタレベルの運用保守操作は、このアラートをトリガーします。

運用保守タスクリスト：

* クラスタの作成
* SQL収集の開始/停止
* クラスタの停止/起動
* クラスタの再起動
* クラスタの移出/引き継ぎ
* クラスタの削除
* バージョンのアップグレード
* スタンバイクラスタの新規作成
* 日常/災害復旧切り替え
* 主クラスタへの切り離し
* 読み取り専用クラスタへの切り替え
* パフォーマンスレポートの生成
* クラスタ-バックアップ・リカバリ
  * 即時バックアップ
  * 自動スケジュールバックアップ
  * リカバリの開始
  * 2次バックアップのスケジュール
* Zoneの運用保守
  * Zoneの追加
  * Zoneの停止
  * Zoneの起動
  * Zoneの再起動
  * Zoneの削除

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${operation_name} \${operation_result}
  * サンプル：alarm_template_id=0:ob_cluster=obcluster-1 Create cluster SUCCESS

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、アラート：\${operation_name} \${operation_result}、操作者 \${operator}、実行結果：\${operation_result}。
  * サンプル：クラスタ：obcluster-1、アラート：Create cluster SUCCESS、操作者 admin、実行結果：success。

ここで：

* ${alarm_target}：アラートが発生したオブジェクトを示します。形式は ob_cluster=xxxxxxx です。ob_cluster はアラートが発生したクラスタ名です。

* ${operation_name}：実行された操作を示します。

* ${operation_result}：操作の結果を示します。値は SUCCESS（操作成功）と FAILED（操作失敗）です。

* 操作者 ${operator}：この操作を実行したユーザー名を示します。

## システムへの影響

結果が SUCCESS の場合は影響ありません。結果が FAILED の場合、対応する操作が失敗したことを意味します。

## 考えられる原因

OCP を使用したクラスタレベルのメンテナンス作業（例：OBServerノードの追加・削除など）で一般的です。

## 対処方法

リマインダー情報ですので、必ずしも対処する必要はありません。

リマインダーの結果が FAILED の場合、OCP の **<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">タスクセンター</UI-TERM>** ページでタスクログを確認し、失敗原因を分析できます。
