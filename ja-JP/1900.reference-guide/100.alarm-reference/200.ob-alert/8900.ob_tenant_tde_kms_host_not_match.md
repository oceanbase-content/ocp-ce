# ob_tenant_tde_kms_host_not_match テナントTDE KMSサービスのアドレスと現在のOCPサービスのアドレスが一致しません

## アラートの概要

このアラートは、テナントのTDE KMSサービスのアドレスと現在のOCPサービスのアドレスが一致しているかどうかを検出します。ここで：

* テナントTDE KMSサービスのアドレス：`GV$OB_PARAMETERS`ビューの対応するテナントの`external_kms_info`パラメータの`kms_host`フィールド値から取得します。
* 現在のOCPサービスのアドレス：システムパラメータの`ocp.site.url`値。

## アラートの仕組み

| パラメータ       | 値     |
| ---------- | ------------ |
| モニタリング指標   | ob_tenant_tde_kms_host_match_status、この指標はOceanBaseテナントKMSアドレスと現在のOCPアドレスの一致状態を示します。パラメータ値が`0`の場合はサービスアドレスが一致していることを示し、パラメータ値が`1`の場合はサービスアドレスが一致しないことを示し、アラートがトリガーされます。 |
| モニタリング式 | ```max(ob_tenant_tde_kms_host_match_status{@LABELS}) by (@GBLABELS)``` |
| 取得指標   | ob_tenant_tde_kms_host_match_status |
| データソース   | OCP-Serverが定期的に`kms_host`と`ocp.site.url`が一致するかどうかを照会し、一致しない場合はアラートを発報します。 |
| 取得周期   | 5秒 |

## システムへの影響

OBServerの追加、新規スタンバイテナントの作成、暗号化テーブル領域の作成などの機能は利用できなくなります。

## 考えられる原因

* OCPの現在のサービスアドレスが変更され、システムパラメータ`ocp.site.url`の値が、テナントのTDE暗号化前の`GV$OB_PARAMETERS`ビューの`external_kms_info`パラメータ内の`kms_host`値と一致しない場合。
* テナントの`external_kms_info`情報をCLIで直接変更したことにより、`ocp.site.url`の値と`kms_host`値が一致しなくなった場合。
* クラスタの移出および引き継ぎ後、関連するテナントのTDE暗号化設定を適時に完了していない場合。
* OCPのマルチクラスタモードで、プライマリ/スタンバイテナントが分離された後、新しいプライマリテナントのTDE暗号化設定を適時に更新していない場合。

## 解決策

* 方法1：アラート対象のクラスタ概要モジュールに移動し、ページの指示に従って**<UI-TERM key="ocp-v2.src.constant.security.ModifyEncryption">暗号化を変更する</UI-TERM>**をクリックし、**<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">セキュリティ設定</UI-TERM>** > **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">TDE 透過的データ暗号化</UI-TERM>**で該当テナントのTDE暗号化情報を変更します。
* 方法2：テナントが属するクラスタで、**<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">セキュリティ設定</UI-TERM>** > **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">TDE 透過的データ暗号化</UI-TERM>**に移動し、該当テナントのTDE暗号化情報を変更します。
