# oas_anomaly_sql_from_anomaly_event_analysis_perf_degradation ホストCPU超過の根本原因分析、SQLパフォーマンス低下

## 警報の概要

OBServerのCPU使用率が継続的に高い場合（デフォルトで90%を5分以上超える場合）、そのOBServer上のSQLのCPU占有率がしきい値（デフォルトで15%）を超えると、システムはそのSQLがOBServerのCPU利用率に影響を与えていると判断し、警報をトリガーします。さらに、OCPはそのSQLの直近1日間の実行パフォーマンスの傾向（CPU時間）を分析し、SQLのCPU時間が1日の最低点よりも上昇している場合、パフォーマンスが低下していると判断します。

## ルール情報

## システムへの影響

OBServerのCPU使用率に影響します。

## 考えられる原因

* SQLの実行パフォーマンスが悪い、または実行頻度が高すぎる。
* 業務データ量の増加やリーダー切り替えなどによりSQLパフォーマンスが低下した。
* SQL計画の変更によりSQLパフォーマンスが低下した。

## 対処方法

1. PlanCacheをリフレッシュして、SQLパフォーマンスが回復するかどうか確認します。プランを実行することで迅速にリフレッシュできます。詳細な操作については、[アラート対応プラン](../500.appendix/400.execute-the-plan.md)を参照してください。
2. そのSQLを最適化してみます。
3. 業務側の評価を経て、トラフィック制限を行います。
