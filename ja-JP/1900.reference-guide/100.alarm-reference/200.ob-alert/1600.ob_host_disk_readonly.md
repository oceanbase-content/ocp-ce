# ob_host_disk_readonly サーバーディスクは読み取り専用

## アラートの概要

OceanBaseサーバーのディスクが読み取り専用になると、このアラートがトリガーされます。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要パラメータを示しています。

| パラメータ |                           値                           |
|-------|-------------------------------------------------------|
| 監視指標  | disk_readonly_flag。この指標は、OBServerのインストールディレクトリ、データディレクトリ、ログディレクトリが配置されているディスクに読み取り専用属性が存在するかどうかを示します。指標値が `0` の場合は書き込み可能を意味し、`1` の場合はOBServerのインストールディレクトリ、データディレクトリ、ログディレクトリが配置されているディスクに読み取り専用属性が存在し、アラートがトリガーされます。       |
| 監視式 | ```max(node_filesystem_readonly{@LABELS}) by (@GBLABELS)``` |
| 取得指標  | node_filesystem_readonly    |
| 指標ソース  | node_exporterから取得します。  |
| 取得周期  | 5秒   |

OCP-Agentは、各 **取得周期** において定時タスクを通じてディスクの読み取り可能性を監視し、その結果を **取得指標** node_filesystem_readonly が返します。ディスクが読み取り専用の場合は1を、そうでない場合は0を渡します。また、OceanBaseのインストールディレクトリ、OceanBaseのデータディレクトリ、OceanBaseのログディレクトリが配置されているディスクに対して `is_ob_disk="1"` を設定します。

## ルール情報

|      監視指標            | デフォルトしきい値 | 持続時間 | 検出周期 | 解消周期 |
|----------------------------|------|------|------|------|
| disk_readonly_flag | 1    | 0秒  | 10秒 | 5分 |

## アラート情報

|   アラートトリガー方法   | アラートレベル | 対象  |
|------------|------|-----|
| 監視指標の式に基づく | 重大   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=obcluster-1:host=xxx.xxx.xxx.xxx:mount_point=/home/admin サーバーディスクは読み取り専用です

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。ディスクマウントポイント \${mount_point} は読み取り専用です。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：サーバーディスクは読み取り専用です。ディスクマウントポイント /dev/loop0 は読み取り専用です。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OBServerディスクは読み取り専用かどうか：\${recover_value}
  * サンプル：アラート：サーバーディスクは読み取り専用です、OBServerディスクは読み取り専用かどうか：0

ここで、${alarm_target} の形式は ob_cluster=xxxxxxx:svr_ip=xxxxxx です。

* ob_cluster はアラートが発生したクラスタ名です。

* svr_ip はアラートが発生したクラスタ内の対応するOBServerのIPです。

## システムへの影響

* OceanBaseのログディスクとデータディスクが読み取り専用になると、OBServerは正常に動作できません。

* ログファイルディスクが読み取り専用になると、プログラムは正常にログを出力できません。

## 考えられる原因

* ディスクが満杯です。

* オペレーティングシステムによる権限異常。

* 物理メディアの異常、例えばディスク障害。

## 解決策

* ディスクが満杯または空き容量不足でないか確認します。

  対応するディスクの空き容量が不足している場合、以下のアラートも報告されます。まずドキュメントを参照して処理し、その後このセクションで説明しているアラートも解消されているか観察します。

  * [ob_host_data_disk_percent_over_threshold OBホストデータディレクトリのディスク使用率が限度を超えています](../200.ob-alert/3500.ob_host_data_disk_percent_over_threshold.md)

  * [ob_host_log_disk_percent_over_threshold OBホストログディレクトリのディスク使用率が限度を超えています](../200.ob-alert/3600.ob_host_log_disk_percent_over_threshold.md)

  * [ob_host_install_disk_percent_over_threshold OBホストインストールディレクトリのディスク使用率が限度を超えています](../200.ob-alert/3700.ob_host_install_disk_percent_over_threshold.md)

* その他の原因。

  オペレーティングシステムのディスクが読み取り専用になる原因は複雑で、Linux運用の範疇に属します。Linux運用エンジニアに直接連絡し、解決することを推奨します。

  Linux運用エンジニアがいない場合、`/var/log/messages` 内のディスクが読み取り専用になったことに関するログを確認し、エラーメッセージを [www.baidu.com](https://www.baidu.com/) に持って行って解決策を検索します。

  ```sql
  #すべての読み取り専用ディスクを一覧表示
  grep "[[:space:]]ro[[:space:],]" /proc/mounts

  #戻り値は次のとおりです。ここで/dev/loop0は読み取り専用です。
  tmpfs /sys/fs/cgroup tmpfs ro,nosuid,nodev,noexec,mode=755 0 0
  /dev/loop0 /home/admin iso9660 ro,relatime,nojoliet,check=s,map=n,blocksize=2048 0 0

  #読み取り専用の理由を確認する場合、'/dev/loop0' を 'readonly' に置き換えても構いません。
  grep '/dev/loop0' /var/log/messages -Rn
  ```
