# ob_cpu_assigned_percent_over_threshold OceanBaseがテナントに割り当てたCPUの割合がしきい値を超えた

## アラートの説明

OceanBaseクラスタ全体でテナントに割り当てられたCPUコアの合計数と、同クラスタ内のすべてのホストのCPUコア総数との比率が、設定されたしきい値を超えた場合にこのアラートがトリガーされます。

各テナントは1つのゾーン内で複数のリソースユニットを割り当てられ、各ユニットでは利用可能なCPUコア数の上限と下限を指定できます。このアラートイベントは割り当て状況の飽和度にのみ注目し、実際の使用率ではありません。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要パラメータを示しています。

| パラメータ | 値 |
|-------|-------------|
| 監視指標 | cpu_assigned_percent。この指標は、テナントに割り当てられたすべてのCPUの合計が、そのOceanBaseクラスタ内のすべてのOBServerノードの総CPUに占める割合を示します。比率がしきい値を超えた場合にアラートがトリガーされます。   |
| 監視式 | ```100 * avg(ob_server_resource_cpu_assigned{@LABELS}) by (@GBLABELS) / avg(ob_server_resource_cpu{@LABELS}) by (@GBLABELS)```   |
| 取得指標 | ob_server_resource_cpu_assigned   |
| 指標出典 | 内部ビューから取得。取得SQL：<li>OceanBase V2.0.0未満のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ cpu_total, cpu_assigned, mem_total, mem_assigned,disk_total, cpu_assigned_percent, mem_assigned_percent from __all_virtual_server_stat where svr_ip = ? and svr_port = ?```</li><li>OceanBase V2.0.0以上、V4.0.0.0未満のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ cpu_total,cpu_max_assigned as cpu_assigned,mem_total,mem_max_assigned as mem_assigned,disk_total, cpu_assigned_percent, mem_assigned_percent from __all_virtual_server_stat where svr_ip = ? and svr_port = ?```</li><li>OceanBase V4.0.0.0以上のバージョン：```select /* MONITOR_AGENT */ cpu_capacity_max as cpu_total,cpu_assigned_max as cpu_assigned,mem_capacity as mem_total,mem_assigned as mem_assigned,data_disk_capacity as disk_total, (cpu_assigned_max / cpu_capacity_max) as cpu_assigned_percent, (mem_assigned / mem_capacity) as mem_assigned_percent from V$OB_SERVERS where svr_ip = ? and svr_port = ?```</li>  |
| 取得間隔 | 5秒    |

<main id="notice" type='explain'>
<h4>説明</h4>
<ul><li>cpu_assignedは、テナントに割り当てられたすべてのCPUの合計を表します。</li>
<li>cpu_totalは、クラスタ内のすべてのOBServerノードのCPUの合計を表します。</li>
<li>表の監視式は、上記2つの値の比率を監視値として表しています。</li></ul>
</main>

## システムへの影響

業務でより多くのリソースが必要になったり、新しい業務で新しいテナントを作成する必要がある場合、リソース不足のため作成に失敗する可能性があります。

## 考えられる原因

OceanBaseクラスタのCPUコアがほぼすべて割り当てられている場合によく見られます（さらに割り当てるとCPUの過剰割り当てやオーバーコミットの可能性があります）。

## 解決策

以下の方法で利用可能なリソースを増やすことができます：

* 不要なテナントを削除します。

  削除方法については、[テナントの削除](../../../700.tenant-functions/600.manage-a-tenant/400.delete-a-tenant.md)を参照してください。

* 実際のリソース使用量が割り当てサイズを下回るテナントのスケールイン（Unit仕様の調整）を行います。

  調整方法については、[Unit仕様の管理](../../../700.tenant-functions/1630.manage-unit-specification.md)を参照してください。

* クラスタの拡張。

  そのOceanBaseクラスタにOBServerノードを追加します。方法については、[OBServerノードの追加](../../../600.cluster-functions/600.manage-an-observer/100.add-an-observer.md)を参照してください。
