# tenant_mini_merge_tablet_count_error OceanBaseテナントのダンプされたsstable数が上限を超えるtablet数

## アラートの概要

<main id="notice" type='explain'>
<h4>説明</h4>
このアラートは、V4.2.0.0以降のOceanBaseクラスタでのみ有効です。
</main>

このアラートは、OceanBaseテナントのダンプされたsstable数が上限を超えるtablet数を検出します。

## アラートの仕組み

OceanBaseストレージでは、各パーティションのsstable数に上限が設定されています。sstable数が高水位（デフォルトで56個）を超えると、新しいsstableを追加できなくなり、これによりMini Compactionが実行できなくなる可能性があります。
Minor Compactionは、条件を満たすダンプされたsstableをCompactionし、複数のsstableを1つに統合してsstable数を削減します。そのため、ダンプされたsstable数がアラートのしきい値を超えた場合は、Minor Compactionの実行状況に注意する必要があります。

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|--------|-------|
| 監視指標 | ob_tenant_mini_merge_tablet_count。この指標は、テナントのダンプされたsstable数が上限を超えるtablet数を表し、数値がしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | `sum(ob_tenant_mini_merge_tablet_count{@LABELS}) by (@GBLABELS)` |
| 収集指標 | ob_tenant_mini_merge_tablet_count |
| データソース | SQL収集：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(20000000) */x.tenant_id,x.svr_ip,x.svr_port,count(*) as cnt from (select tenant_id,svr_ip,svr_port,tablet_id,count(*) as cnt from GV$OB_SSTABLES where table_type = 'MINOR' or table_type = 'MINI' group by tenant_id,svr_ip,svr_port,tablet_id having cnt >=30) as x where x.cnt >0 group by x.tenant_id,x.svr_ip,x.svr_port```<br>このSQLは各クラスタのsysテナントで実行され、テナント内の各tabletのダンプされたsstable数が30以上の場合に集計されます。 |
| 収集サイクル | 5秒 |

## システムへの影響

ダンプされた SSTable の数が高水位（デフォルトで 56 個）を超えると、新しい SSTable を追加できなくなり、Mini Compaction も実行できなくなります。その後、Memtable のダンプやメモリの解放に影響を及ぼす可能性があり、メモリ使用量が上限を超えると書き込みが制限されたり、書き込みが停止したりすることがあります。

## 考えられる原因

* Minor Compactionタスクキューが滞留し、タスクの処理速度が追加速度に追いつかない。
* 内部の制限により、Minor Compaction がスケジュールできない場合がある。

## 解決策

* 原因が Minor Compaction タスクキューの積み上がりである場合、以下のコマンドを参考にして、テナントの Minor Compaction キュースレッド数を増やすことができます：

    ```sql
    alter system set compaction_mid_thread_score = xxx tenant xxx;
    ```

* その他の原因の場合、[SSTable数が多すぎる場合のトラブルシューティング](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000994204?back=kb) ドキュメントを参照して調査および対処してください。
