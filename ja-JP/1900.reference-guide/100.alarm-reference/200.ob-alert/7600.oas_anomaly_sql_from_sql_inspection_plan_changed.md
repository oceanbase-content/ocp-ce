# oas_anomaly_sql_from_sql_inspection_plan_changed SQL巡回検査：SQL実行計画の悪化

## アラートの概要

過去のSQL実行計画の中に、現在の実行計画よりもCPU時間が短いものがあります。SQLの現在のCPU時間が過去よりも長くなっています。具体的なルールは、次の診断項目と同じです： **Suspicious SQL - Execution Plan Change with Performance Degradation**。

## システムへの影響

該当するSQLの応答時間と、CPUなどのシステムリソースの消費に影響します。

## 考えられる原因

実行計画の生成時に代表的でないパラメータに遭遇し、SQL計画が変更されたことでSQL全体のパフォーマンスが低下し、CPU使用率に影響を与えた。

## 解決策

1. そのSQLのPlanCacheをリフレッシュして、SQLが新しい実行計画を再生成するよう試みます。プランを実行することで迅速にリフレッシュできます。詳細な操作については、[アラートプラン](../500.appendix/400.execute-the-plan.md)を参照してください。

2. **手順1**が効果がない場合は、そのSQLの実行計画を分析し、過去の実行計画をバインドするか、インデックスをバインドすることを試みます。

3. このアラート情報に注意する必要がない場合は、該当するアラートのプッシュ通知を無効にするか、アラートのプッシュ頻度を下げることができます。

   * アラートプッシュの無効化：OCPシステムパラメータ`ocp.perf.sql-diag.performance-degradation-after-plan-changed-config`で、`"alarm":false`を設定します。このパラメータに`alarm`属性がない場合は、手動で追加できます。変更後のパラメータが有効なJSON形式であることを確認してください。

   * アラートプッシュ頻度の低下：OCPシステムパラメータ`ocp.perf.sql-diag.performance-degradation-after-plan-changed-config`で、`"cpuTimeLimitMs":1.0`を設定します。このパラメータに`cpuTimeLimitMs`属性がない場合は、手動で追加し、実際のニーズに応じて`cpuTimeLimitMs`の属性値を調整します。変更後のパラメータが有効なJSON形式であることを確認してください。

   `ocp.perf.sql-diag.performance-degradation-after-plan-changed-config`パラメータの説明については、[SQLパフォーマンス診断関連パラメータ設定](../../../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/1400.sql-performance-diagnosis-related-parameter-configuration.md)を参照してください。
