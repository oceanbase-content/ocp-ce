# oas_anomaly_sql_from_anomaly_event_analysis_plan_changed ホストCPU上限超過の根本原因分析、SQL計画の悪化

## 警報の概要

OBServerのCPU利用率が継続的に高すぎる場合（デフォルトで90%を5分以上超える場合）、そのOBServer上のSQLのCPU占有率がしきい値（デフォルトで15%）を超えると、システムはそのSQLがOBServerのCPU使用率に影響を与えていると判断し、警報をトリガーします。さらに、そのSQLの直近1日間において、ある実行計画のCPU時間が現在の実行計画よりも低いことが判明した場合（具体的な比較ルールは「最適化推奨-計画推奨」と同じです）、そのSQLの計画が悪化していると判断されます。

## システムへの影響

OBServerのCPU利用率に影響します。

## 考えられる原因

実行計画の生成時に代表的でないパラメータに遭遇し、SQL計画が変更されたことでSQL全体のパフォーマンスが低下し、CPU利用率に影響を与えた。

## 解決策

1. そのSQLのPlanCacheをリフレッシュして、SQLが新しい実行計画を再生成するように試みます。プランを実行することで迅速にリフレッシュできます。詳細な操作については、[アラート対応プラン](../500.appendix/400.execute-the-plan.md)を参照してください。
2. **手順1**が効果がない場合は、そのSQLの実行計画を分析し、過去の実行計画をバインドするか、インデックスをバインドすることを試みます。
3. 上記の操作がすべて効果がない場合は、そのSQLを最適化するか、業務側の評価を経て、トラフィック制限を行います。
