# ob_mem_assigned_percent_over_threshold OceanBaseがテナントに割り当てたメモリの割合が上限を超えた

## アラートの概要

このアラートは、OceanBaseクラスタ全体でテナントに割り当てられたメモリ容量の合計が上限を超えているかどうかを監視し、超えた場合に報告します。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|---------|-------|
| 監視指標 | mem_assigned_percent。この指標はOBServerノードがテナントに割り当てたメモリの割合を示し、メモリ割合がしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | ```100 * avg(ob_server_resource_memory_assigned_bytes{@LABELS}) by (@GBLABELS) / avg(ob_server_resource_memory_bytes{@LABELS}) by (@GBLABELS)``` |
| 収集指標 | ob_server_resource_memory_assigned_bytes |
| データソース | 内部ビューから収集。収集SQL：<li>OceanBase V2.0.0未満のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ cpu_total, cpu_assigned, mem_total, mem_assigned,disk_total, cpu_assigned_percent, mem_assigned_percent from __all_virtual_server_stat where svr_ip = ? and svr_port = ?```</li><li>OceanBase V2.0.0以上、V4.0.0.0未満のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ cpu_total,cpu_max_assigned as cpu_assigned,mem_total,mem_max_assigned as mem_assigned,disk_total, cpu_assigned_percent, mem_assigned_percent from __all_virtual_server_stat where svr_ip = ? and svr_port = ?```</li><li>OceanBase V4.0.0.0以上のバージョン：```select /* MONITOR_AGENT */ cpu_capacity_max as cpu_total,cpu_assigned_max as cpu_assigned,mem_capacity as mem_total,mem_assigned as mem_assigned,data_disk_capacity as disk_total, (cpu_assigned_max / cpu_capacity_max) as cpu_assigned_percent, (mem_assigned / mem_capacity) as mem_assigned_percent from V$OB_SERVERS where svr_ip = ? and svr_port = ?```</li> |
| 収集サイクル | 5秒 |

## ルール情報

|      監視指標           | デフォルトしきい値（単位：%） | 持続時間 | 検出サイクル | 解消サイクル |
|-------------------------|------------|-------|-------|------|
| mem_assigned_percent    | 98         | 0秒  | 20秒 | 5分 |

## アラート情報

|   アラートトリガー方法   | アラートレベル | 対象範囲  |
|------------|------|-----|
| 監視指標の式に基づく | 注意   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=obcluster-1:host=xxx.xxx.xxx.xxx OceanBaseがテナントに割り当てたメモリの割合が上限を超えた

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。割り当て済みメモリの割合 \${value_shown} が ${alarm_threshold} % を超えました。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：OceanBaseがテナントに割り当てたメモリの割合が上限を超えた。割り当て済みメモリの割合 99.0 % が 98.0 % を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OceanBaseがテナントに割り当てたメモリの割合：\${value_shown}
  * サンプル：アラート：OceanBaseがテナントに割り当てたメモリの割合が上限を超えました。OceanBaseがテナントに割り当てたメモリの割合：92%

## **システムへの影響**

業務でより多くのリソースを申請する必要がある場合、または新しい業務で新しいテナントを作成する必要がある場合、リソース不足により作成に失敗する可能性があります。

## **考えられる原因**

* OceanBaseクラスタのメモリリソースの残量が不足しており、さらに割り当てるとメモリのオーバーコミットまたはオーバーコミットの可能性があります。

* クラスタ内にOBServerノードのダウンなどの状況が存在します。

## 解決策

1. OceanBaseクラスタ内にダウンしたOBServerノードが存在するか確認します。

   そのクラスタの**<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">総覧</UI-TERM>**ページの**<UI-TERM key="ocp-v2.Component.OBServerList.ObserverList">OBServerリスト</UI-TERM>**に、状態異常なOBServerノードが存在するか確認します。

   * 存在する場合、[ob_cluster_exists_inactive_server OBクラスタに非稼働OBServerノードが存在します](../200.ob-alert/400.ob_cluster_exists_inactive_server.md)と同時に報告されます。ドキュメントを参照してこのアラートを先に処理し、その後本節で説明するアラートがまだ報告されるか観察してください。

   * 不存在する場合、単にOceanBaseクラスタの残存メモリが不足している可能性があります。次の手順を実行してください。

2. OceanBaseクラスタの残存メモリが不足している可能性があります。

   実際の状況に応じて、以下の方法から解決策を選択できます。

   1. [テナントの削除](../../../700.tenant-functions/600.manage-a-tenant/400.delete-a-tenant.md)を参照して、使用されていないテナントを削除します。

   2. 実際のメモリ使用量が割り当てられたメモリより少ないテナントをスケールインすることで、テナントのUnit仕様を調整します。[Unit仕様の管理](../../../700.tenant-functions/1630.manage-unit-specification.md)を参照してください。

   3. [OBServerノードの追加](../../../600.cluster-functions/600.manage-an-observer/100.add-an-observer.md)を参照して、そのクラスタにOBServerノードを追加し、クラスタの拡張を実現します。
