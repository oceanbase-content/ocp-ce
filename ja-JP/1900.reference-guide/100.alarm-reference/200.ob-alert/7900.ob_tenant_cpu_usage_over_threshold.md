# ob_tenant_cpu_usage_over_threshold OceanBaseテナントCPU使用率がしきい値を超えた場合

## アラートの概要

このメトリクスは、テナントの実際のCPU使用率（テナントCPU使用量 × 100 / テナントCPU割り当て量）に最も近い値です。アラート「tenant_cpu_percent_over_threshold」と「ob_cpu_percent_over_threshold」は、実際にはテナントスレッドの使用率を示します。

このアラートを有効にするには、OceanBaseとOCPのバージョン要件を満たす必要があります。

1. OceanBaseバージョン：V3.2.3 BP10、V3.2.4 BP5、V4.1 BP3、V4.2.0以降のバージョン。
2. OCPバージョン：V4.2.2以降のバージョン。

## アラートの仕組み

| パラメータ      | 値      |
| --------- | ---------- |
| モニタリング指標 | ob_tenant_cpu_percent。この指標はOceanBaseテナントのCPU使用率を表し、使用率がしきい値を超えるとアラートがトリガーされます。 |
| モニタリング式 | ```sum(rate(ob_sysstat{stat_id="140013",@LABELS}[@INTERVAL])) by (@GBLABELS) / sum(ob_sysstat{stat_id="140005",@LABELS}) by (@GBLABELS) / 100``` |
| 取得指標 | ob_sysstat：<ul><li>140005：max cpus。各テナントのCPU割り当て量。</li><li>140013：cpu time。各テナントの全スレッドの累積CPU時間（マイクロ秒単位）。</li></ul> |
| 指標ソース | 内部ビューから取得。取得SQL：<ul><li>OceanBase V4.0より前のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN (140005, 140013) and (con_id > 1000 or con_id = 1)```</li><li>OceanBase V4.0以降のバージョン：```select /* MONITOR_AGENT */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN (140005, 140013) and (con_id > 1000 or con_id = 1) and con_id in (select tenant_id from DBA_OB_TENANTS WHERE tenant_type<>'META')```</li></ul>OceanBase V4.xでcgroupが有効になっている場合にのみ（OceanBase V4.xでは、V4.1 BP3より前のバージョンでは、`cpu time`値を取得するにはcgroupを有効にする必要があります）、cgroup機能を通じて`cpuacct.usage`からCPU時間を取得します。それ以外の場合、cgroupが無効な場合やOceanBase V3.xバージョンの場合は、`/proc/<pid>/task/<tid>/stat`ディレクトリからのみCPU時間を読み取ります。 |
| 取得間隔 | 5秒 |

## ルール情報

|          モニタリング指標        | デフォルトしきい値（単位：%） | 持続時間 | 検出周期 | 解消周期 |
|--------------------------|------------|------|------|------|
| ob_tenant_cpu_percent    | 95         | 60秒  | 10秒 | 5分 |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=TEST-1:tenant_name=t1:host=xxx.xxx.xxx.xxx OceanBaseテナントCPU使用率がしきい値を超えた場合

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、テナント：\${tenant_name}、アラート：\${alarm_name}。テナントCPU使用率 \${value_shown} が \${alarm_threshold} % を超えました。
  * サンプル：クラスタ：TEST、テナント：t1、アラート：OceanBaseテナントCPU使用率がしきい値を超えた場合。テナントCPU使用率 96 % が 95 % を超えました。

* **アラートの復元**

  * テンプレート：アラート：${alarm_name}、OceanBaseテナントCPU使用率：\${value_shown}
  * サンプル：アラート：OceanBaseテナントCPU使用率が上限を超えました、OceanBaseテナントCPU使用率：90 %

## システムへの影響

テナントのCPU使用率が高い場合は、具体的なビジネスシナリオを踏まえて分析する必要があります。CPU使用率が制限値を超えると、考えられる影響は以下の通りです：

1. 業務SQLのRTが増加し、業務応答時間に影響します。
2. テナントの負荷が高くなり、SQL処理がタイムアウトする可能性があり、業務に影響します。

## 考えられる原因

* スローSQLが存在する可能性があります。SQL診断でTopSqlを確認し、CPU占有率分析からCPU使用率が高くなる具体的なSQLを特定できます。

* SQLのパフォーマンスが低下したり、実行計画が悪化したりした場合、OCPはこのようなSQLに対するアラートを発報します：

  * oas_anomaly_sql_from_sql_inspection_plan_changed
  * oas_anomaly_sql_from_sql_inspection_perf_degradation
  * oas_anomaly_sql_from_anomaly_event_analysis_plan_changed
  * oas_anomaly_sql_from_anomaly_event_analysis_perf_degradation
  * oas_anomaly_sql_from_anomaly_event_analysis_cpu_percent_high

* 大規模トランザクションや大規模クエリなどが存在する場合、テナントのパフォーマンス監視を確認することで特定できます。

* 業務の同時実行が多すぎてCPU使用率が高くなっています。

## 対処方法

1. SQLに問題がある場合は、SQL診断の推奨に基づいてSQLを最適化します。
2. 業務においてCPUを消費するクエリ（大規模クエリや大規模トランザクションなど）が存在する場合は、業務と照らし合わせて分析する必要があります。
3. 業務の同時実行が多く、普段からテナントのCPU使用率が高い場合は、テナントのスケールアウトを試みることができます。
