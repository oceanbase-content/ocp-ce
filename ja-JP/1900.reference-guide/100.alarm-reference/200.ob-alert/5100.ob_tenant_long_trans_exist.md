# ob_tenant_long_trans_exist OceanBaseテナントに長トランザクションが存在する

## アラートの説明

このアラートは、テナント内において、持続時間がしきい値（デフォルトで1200秒）を超えるトランザクションが存在するかどうかを監視し、存在する場合にアラートを報告します。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

## システムへの影響

長時間トランザクションは、大量のブロッキングやロックのタイムアウトを引き起こしやすく、他のトランザクションの実行に影響を与えます。

## 考えられる原因

マイノリティ、ディスク満杯、メモリ不足、または業務上の大規模トランザクションなどが長時間トランザクションを引き起こす可能性があります。

## 解決策

1. マイノリティが発生していないか確認します。

   マイノリティが発生する一般的な原因は、OBServerノードの異常やネットワーク障害です。これにより、[ob_cannot_connected OceanBaseサーバーへの接続ができません](../200.ob-alert/100.ob_cannot_connected.md) アラートが同時に報告されます。

   このアラートが報告されている場合は、まずそのアラートのドキュメントに従って処理してください。その後、5分間様子を見て、このセクションで説明しているアラートが解消されたかどうか確認します。

2. ディスク容量が不足していないか確認します。

   ディスク容量が不足している場合、以下のアラートが同時に報告されます。まず、以下のアラート対応ドキュメントに従って問題を解決した後、5分間様子を見て、このセクションで説明しているアラートが解消されたかどうか確認します。

   * [ob_host_data_disk_percent_over_threshold OceanBaseホストのデータディレクトリのディスク使用率が限度を超えています](../200.ob-alert/3500.ob_host_data_disk_percent_over_threshold.md)

   * [ob_host_log_disk_percent_over_threshold OceanBaseホストのログディレクトリのディスク使用率が限度を超えています](../200.ob-alert/3600.ob_host_log_disk_percent_over_threshold.md)

   * [ob_host_install_disk_percent_over_threshold OceanBaseホストのインストールディレクトリのディスク使用率が限度を超えています](../200.ob-alert/3700.ob_host_install_disk_percent_over_threshold.md)

3. メモリが不足していないか確認します。

   メモリが不足している場合、[ob_host_mem_percent_over_threshold OceanBaseサーバーのメモリ使用率が限度を超えています](../300.application-alert/300.ob_host_mem_percent_over_threshold.md) アラートが報告される可能性があります。処理方法については、そのアラートの解決方法を参照してください。

4. 大規模トランザクションが存在するか確認します。

   OCPの **パフォーマンス診断** インターフェースで、**TopSQL** および **SlowSQL** タブの内容を確認し、実行時間が長すぎるSQLなど、疑わしいSQLがないか確認します。

   存在する場合、**<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.DiagnosticResults">診断結果</UI-TERM>** を分析してSQLを最適化し、業務の状況を踏まえて大規模トランザクションを小規模トランザクションに分割できるかどうか判断します。

5. 上記の方法で問題が解決しない場合は、以下の手順を参考に技術サポートにお問い合わせください。

   ```sql
   -- すべてのサーバー情報を確認し、異常なOBServerノードが存在するかどうかを特定するために使用します。
   select * from __all_server;

   -- 現在の長時間トランザクションを確認します。
   SELECT *
   FROM __all_virtual_trans_stat
   WHERE is_exiting !=1 AND part_trans_action <= 2 AND ctx_create_time < DATE_SUB(NOW(), INTERVAL 1200 SECOND)
   LIMIT 100;
   ```
