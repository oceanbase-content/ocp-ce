# os_observer_not_exist OceanBase server プロセスが存在しない

## アラートの概要

このアラートは、OBServerノードのホスト上にobserverプロセスが存在するかどうかを監視し、存在しない場合にアラートを報告します。

## アラートの仕組み

| パラメータ | 値 |
| ------- | --------- |
| 監視指標 | observer_process_exists。この指標はOceanBase serverプロセスが存在するかどうかを示します。指標値が`1`の場合はプロセスが存在し、指標値が`0`の場合はプロセスが存在せず、アラートがトリガーされます。 |
| 監視式 | ```min(process_exists{name="observer",@LABELS}) by (@GBLABELS)``` |
| 取得指標 | process_exists |
| 指標ソース | ホスト基本監視。システムにobserverプロセスがあるかどうかを確認します。`ps -ef\|grep -w observer\|grep -v grep\|wc -l` を実行してobserverプロセスの数を返します。 |
| 取得サイクル | 5秒 |

## ルール情報

| 監視式 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| ---------- | ------- | -------- | -------- | -------- |
| observer_process_exists | 0 | 30秒 | 10秒 | 5分 |

## アラート情報

| アラートトリガー方法 | アラートレベル | 対象範囲 |
| ------------ | -------- | ------ |
| 監視指標の式に基づく | 重大 | ホスト |

## アラートテンプレート

* アラート概要

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=obcluster-1:host=xxx.xxx.xxx.xxx OceanBase server プロセスが存在しない

* アラート詳細

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：${host}、アラート：OceanBase server プロセスが存在しない。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：OceanBase server プロセスが存在しない。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OceanBase server プロセスの生存状態：\${recover_value}
  * サンプル：アラート：OceanBase server プロセスが存在しない、OceanBase server プロセスの生存状態：1

## システムへの影響

* シングルレプリカシステムでは、observerプロセスが存在しない場合、サービスが停止します。
* マルチレプリカのOceanBaseクラスタでは、observerプロセスが存在しないことで可用性が低下する可能性があります。例：3ゾーンが2ゾーンに変更されたり、同一リージョンの3データセンターが2データセンターに変更されたりします。

## 考えられる原因

OBServerノードが予期せず再起動した場合。例：システムリソース不足時にkillされた場合。

## 解決策

1. observerプロセスが異常終了した場合、再起動を試みます。プランを実行して迅速に対処できます。詳細な操作については、[アラート対応プラン](../500.appendix/400.execute-the-plan.md)を参照してください。

   <main id="notice" type='explain'>
     <h4>イベント発生後30分以内に1回のみ再起動します。</h4>
     <p></p>
   </main>

2. ホストの基本モニタリング（メモリ、CPU使用率、負荷、ディスク使用率など）が想定通りであるか確認します。

3. OBServerノードの実行ログを確認し、大量のERRORログが存在しないか確認します：

   ```yaml
   tail -10000 /home/admin/oceanbase/log/observer.log.wf | grep ERROR | wc -l
   ```

   大量のERRORログが存在する場合は、テクニカルサポートにお問い合わせください。

4. OSログを確認し、`/var/log/messages` ログファイルでerrorキーワードを検索し、システムが返す情報を確認します。
