# standby_tenant_sync_status_error スタンバイテナント同期状態異常

## アラートの概要

OCP Serverは、スタンバイテナントとプライマリテナントの同期状態を監視します。スタンバイテナントの同期状態が異常な場合、このアラートが生成されます。異常状態の深刻さに応じて、異なるレベルのアラートが発生します。

* standby_tenant_restore_status_code == 1：テナントの同期状態が同期異常であり、警告レベルのアラートがトリガーされます。
* standby_tenant_restore_status_code == 2：テナントの同期状態がログ欠落またはログ競合であり、重大レベルのアラートがトリガーされます。

## アラートの仕組み

| パラメータ | 値 |
| ------ | ------ |
| 監視指標 | standby_tenant_restore_status_code。この指標はスタンバイテナントの同期状態が異常かどうかを示し、同期状態が異常な場合に対応するレベルのアラートをトリガーします。 |
| 監視式 | ```sum(standby_tenant_restore_status_code{@LABELS}) by (@GBLABELS)``` |
| 取得指標 | standby_tenant_restore_status_code |
| 指標ソース | OceanBase内部テーブル `V$OB_LS_LOG_RESTORE_STATUS` からクエリしてテナントの各ログストリームの同期状態を取得し、すべてのログストリームの同期状態から現在のテナントの同期状態をまとめます。 |
| 取得サイクル | 5秒 |

## ルール情報

| 監視式 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| ---------- | ------- | -------- | -------- | -------- |
| standby_tenant_restore_status_code  | <li>standby_tenant_restore_status_code == 1</li><li>standby_tenant_restore_status_code == 2</li> | 0秒  | 60秒 | 5分 |

## アラート情報

| アラートトリガー方法 | アラートレベル | 対象範囲 |
| ----------- | -------- | ------ |
| 監視指標の式に基づく | <li>standby_tenant_restore_status_code == 1：警告</li><li>standby_tenant_restore_status_code == 2：重大</li> | テナント |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=clusterA-1:tenant_name=tenant_standby スタンバイテナント同期状態異常

* **アラート詳細**

  * テンプレート：OceanBaseクラスタ ${ob_cluster_name} のスタンバイテナント ${tenant_name} の同期状態が異常です。現在の同期状態は ${tenant_restore_status} です。
  * サンプル：OceanBaseクラスタ clusterA のスタンバイテナント tenant_standby の同期状態が異常です。現在の同期状態は ABNORMAL です。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、スタンバイテナントの同期状態は正常ですか：\${recover_value}
  * サンプル：アラート：スタンバイテナントの同期状態が異常です、スタンバイテナントの同期状態は正常ですか：はい

## システムへの影響

スタンバイテナントの同期状態が異常であることは、スタンバイテナントがプライマリテナントと正常にデータを同期できないことを意味し、スタンバイテナントのデータがプライマリテナントより遅延する原因となります。

## 考えられる原因

* プライマリテナントのアーカイブが停止しています。
* プライマリテナントのOceanBaseバージョンがスタンバイテナントより高いです。
* プライマリテナントが削除されました。
* プライマリ/スタンバイテナント間、またはスタンバイテナントとアーカイブアドレス間のネットワークに問題があります。

## 解決策

1. スタンバイテナントの同期状態がログ欠落またはログ競合の場合、そのスタンバイテナントは同期を続行できません。現在のスタンバイテナントを削除して再作成する必要があります。
2. スタンバイテナントの同期状態が同期異常の場合、テナントのプライマリ/スタンバイ関係トポロジーダイアグラムに移動し、そのテナントの各ログストリームの同期状態を確認します。ログストリームの異常状態と説明に基づいて、適切な修正を行います。
