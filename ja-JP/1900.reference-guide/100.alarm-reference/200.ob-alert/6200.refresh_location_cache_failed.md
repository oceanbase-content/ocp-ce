# refresh_location_cache_failed OBServerのlocation cacheのリフレッシュ失敗

## アラートの概要

OBServerのlocation cacheのリフレッシュが失敗し、テナントSQLがタイムアウトする可能性があり、業務に影響を与える可能性があります。

## アラートの仕組み

OCP-Agent（ocp_monagent）はOBServerの実行ログを監視し、以下の2つのシナリオでこのアラートが発生します。

1. ログに以下のキーワードが1分間連続して現れた場合にアラートが発生します：

   ```SQL
   LOCATION_STATISTIC
   SYS_CORE
   suc_cnt=0
   sql_suc_cnt=0
   ```

   上記は正規表現で表すことができます：`.\*LOCATION_STATISTIC.\*SYS_CORE.\*suc_cnt=0.\*sql_suc_cnt=0.\*` 。

2. 以下のキーワードが現れた場合：

   ```SQL
   init_batch_rpc_renew_struct.*fail to check is local server.*ret=-4018
   ```

## システムへの影響

location情報が正しくない場合、システムに以下の影響を及ぼす可能性があります：

1. 業務SQLがタイムアウトする。
2. sysテナントのキューが滞留する場合があります。`dump tenant info` キーワードで `req_queue:total_size` を確認し、滞留がないかご確認ください。

## 考えられる原因

既知のシステム障害。

## 解決策

1. システムテナントからOBServerノードに直接接続します。

2. OBServerノードに障害が発生した場合は、location cacheをリフレッシュするために以下のステートメントを実行することを推奨します：

   ```SQL
   select count(*) from oceanbase.__all_virtual_proxy_schema where tenant_name = "sys" and database_name = "oceanbase" and table_name = "all_core_table" and partition_id = 0;
   ```

3. **手順2** の実行が効果がない場合は、マシンの再起動を推奨します。

4. あまり一般的ではありませんが、この問題が発生する可能性のあるシナリオもあります。クラスタ内のテナントがローカリティ変更によりRをドロップし、その後Rレプリカが配置されていたobserver/zoneを削除した場合、プライマリ切り替え（運用によってトリガーされる場合や障害によってトリガーされる場合など）の際に、「init_batch_rpc_renew_struct.*fail to check is local server.*ret=-4018」というエラーが継続的にログに表示されることがあります。この場合、クラスタ内のすべてのOBServerノードに直接接続し、`alter system flush location cache` を実行してlocation cacheをリフレッシュできます。
