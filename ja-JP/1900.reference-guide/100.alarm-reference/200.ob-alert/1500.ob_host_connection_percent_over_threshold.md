# ob_host_connection_percent_over_threshold OceanBaseサーバー接続数の割合がしきい値を超えた場合

## アラートの概要

このアラートは、OBServerノードの接続数が上限を超えていないかどうかを監視します。単一のOBServerノードの現在の接続数と定数値256Kの比率がしきい値を超えた場合に、このアラートイベントがトリガーされます。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|---------|-------|
| 監視指標 | ob_connection_percent。この指標はOceanBaseサーバーの接続数の割合を表し、接続数の割合がしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | ```100 * max(ob_session_active_num{@LABELS} / 262144) by (@GBLABELS)``` |
| 取得指標 | ob_session_active_num |
| 指標の出典 | 内部ビューから取得。取得SQL：<li>OceanBase V4.0.0.0未満のバージョン：```select t1.tenant_name, coalesce(t2.active_cnt, 0) as active_cnt, coalesce(t2.all_cnt, 0) as all_cnt from (select tenant_name from v$unit) t1 left join (select count(`state`='ACTIVE' OR NULL) as active_cnt, count(1) as all_cnt, tenant as tenant_name from __all_virtual_processlist where svr_ip = ? and svr_port = ? group by tenant) t2 on t1.tenant_name = t2.tenant_name)```</li><li>OceanBase V4.0.0.0以上のバージョン：```select t1.tenant_name, coalesce(t2.active_cnt, 0) as active_cnt, coalesce(t2.all_cnt, 0) as all_cnt from (select tenant_name from dba_ob_tenants where tenant_type <> 'META') t1 left join (select count(`state`='ACTIVE' OR NULL) as active_cnt, count(1) as all_cnt, tenant as tenant_name from V$OB_PROCESSLIST where svr_ip = ? and svr_port = ? group by tenant) t2 on t1.tenant_name = t2.tenant_name```</li> |
| 取得間隔 | 5秒 |

## ルール情報

|         監視指標            | デフォルトしきい値（単位：%） | 持続時間  | 検出周期 | 解消周期 |
|-----------------------------|-------|--------|------|------|
| ob_connection_percent       | 80    |  0 秒  | 10 秒 | 5 分钟 |

## アラート情報

|   アラートのトリガー方法   | アラートレベル | 対象範囲  |
|------------|------|-----|
| 監視指標の式に基づく | 極めて重大   | ホスト |

## アラートテンプレート

* **アラートの概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=obcluster-1:host=xxx.xxx.xxx.1 OceanBaseサーバー接続数の割合がしきい値を超えた場合

* **アラートの詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：接続数の割合 \${value_shown} が ${alarm_threshold} % を超えました。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.1、アラート：接続数の割合 81.0 % が 80.0 % を超えました。

* **アラートの回復**

  * テンプレート：アラート：${alarm_name}、OBServer接続数の割合：\${value_shown}
  * サンプル：アラート：OceanBaseサーバー接続数の割合が上限を超えました、OBServer接続数の割合：79%

## システムへの影響

接続数が上限に達すると、新しい接続は確立できません。

## 考えられる原因

単一のOBServerノードに対するクライアント接続数が多いシナリオで一般的です。

## 解決策

以下のSQLを参照して、接続数が異常なテナントを特定します。

```sql
-- sysテナントに接続して確認する

-- テナントのOBServerノードの接続数、上位5件を確認する
SELECT tenant, svr_ip, COUNT(*) AS session_num FROM __all_virtual_processlist GROUP BY tenant, svr_ip ORDER BY session_num DESC limit 5;

-- 実行結果の例
-- ここで、sysテナントはOceanBaseクラスタのシステムテナントであり、業務テナントではありません
+------------+----------------+-------------+
| tenant     | svr_ip         | session_num |
+------------+----------------+-------------+
| test1      | xxx.xxx.xxx.1    |       66664 |
| test1      | xxx.xxx.xxx.2    |       66560 |
| test1      | xxx.xxx.xxx.3    |         559 |
| test2      | xxx.xxx.xxx.4    |          78 |
| test2      | xxx.xxx.xxx.5    |          57 |
+------------+----------------+-------------+
5 rows in set (0.02 sec)
```

該当する業務部門に連絡し、不要な接続が存在しないか確認します。

* 必要な接続であり、接続数が間もなく不足する場合は、クラスタの拡張を検討する必要があります。

  拡張とは、このOceanBaseクラスタにOBServerノードを追加することです。方法については、[OBServerノードの追加](../../../600.cluster-functions/600.manage-an-observer/100.add-an-observer.md)を参照してください。

* 不要な接続の場合は、`all_virtual_processlist` テーブルを照会して不要な接続のソースを特定する必要があります。
