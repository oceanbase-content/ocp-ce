# standby_cluster_sync_status_error スタンバイクラスタの同期状態異常

## アラートの概要

スタンバイクラスタの同期状態に異常が検出された場合、このアラートがトリガーされます。

## アラートの仕組み

| パラメータ      | 値        |
|-----------|-------------|
| モニタリング指標  | standby_cluster_restore_status_code。この指標はスタンバイクラスタの同期状態を示します。パラメータ値が `0` の場合、スタンバイクラスタの同期状態は正常です。パラメータ値が `1` の場合、スタンバイクラスタの同期状態に異常があり、アラートがトリガーされます。  |
| モニタリング式  | ```sum(standby_cluster_restore_status_code{@LABELS}) by (@GBLABELS)```  |
| 取得指標  | standby_cluster_restore_status_code  |
| 指標ソース  | `V$OB_STANDBY_STATUS` のスタンバイクラスタの synchronization_status フィールドを確認します。  |
| 取得サイクル  | 5秒  |

## ルール情報

| モニタリング式  | デフォルトしきい値  | 継続時間  | 検出サイクル  | 解消サイクル  |
|-------------|-------------|-----------|-------------|-------------|
| standby_cluster_restore_status_code  | 1  | 0秒  | 60秒  | 5分  |

## アラート情報

| アラートトリガー方式  | アラートレベル  | 対象範囲  |
|-----------|-------------|----------|
| モニタリング指標の式に基づく  | 警告  | クラスタ  |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=cluster01-5 スタンバイクラスタの同期状態異常

* **アラート詳細**

  * テンプレート：OceanBaseクラスタ ${ob_cluster_name}:${ob_cluster_id} の同期状態が異常です。現在の同期状態は ${cluster_synchronization_status} です。
  * サンプル：OceanBaseクラスタ cluster01:5 の同期状態が異常です。現在の同期状態は NOT AVAILABLE です。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、スタンバイクラスタの同期状態は正常ですか：${value_down}
  * サンプル：アラート：スタンバイクラスタの同期状態異常、スタンバイクラスタの同期状態は正常ですか: 0

## システムへの影響

原因によって影響は異なります：

* OCP MetaDBとOceanBaseクラスタ情報が一致しない場合、その後のOCP運用操作に影響を与える可能性があります。
* OceanBaseクラスタの障害により同期できない場合、ユーザーサービスに影響を与える可能性があります。

## 考えられる原因

* OceanBaseクラスタで管理されているIDC/リージョン情報とOCP MetaDBで管理されているIDC/リージョン情報が一致していません。
* OceanBaseクラスタの障害により同期できない場合、ob_cluster_status_check_failedアラートも同時に発生します。

## 解決策

アラートに記載されている失敗原因に基づいて障害を排除し、障害が解消されればOCPはクラスタ同期を回復するはずです。

1. 以下のコマンドを実行して、スタンバイクラスタの同期状態を確認します。synchronization_statusの戻り値がOKの場合は同期成功、そうでない場合は同期失敗であり、このときアラートが発生します。

   ```sql
   select cluster_id, cluster_name, cluster_role, cluster_status, current_scn, rootservice_list, synchronization_status from FROM V$OB_STANDBY_STATUS
   ```

   <main id="notice" type='explain'>
   <h4>説明</h4>
   synchronization_statusフィールドはOceanBase V2.2.77以降のバージョンでのみサポートされています。
   </main>

2. 同期できない原因がOceanBaseクラスタの障害によるものかどうかを確認します。

   この場合、OCPはob_cluster_status_check_failedアラートも同時に報告します。[ob_cluster_status_check_failed OceanBaseクラスタ状態検出失敗](300.ob_cluster_status_check_failed.md) のアラート処理方法を参照してトラブルシューティングを行い、5分待ってからアラートが継続して報告されるかどうか観察します。

    * アラートが継続して報告される場合は、次の手順を実行します。
    * アラートが解消された場合は、問題は解決されています。

3. OceanBaseクラスタ内のZoneのIDC/リージョン情報がOCP MetaDBに存在するかどうか、およびクラスタ内のIDC/リージョンの関連性がOCP MetaDBと一致しているかどうかを確認します。以下の情報を参照して確認できます。

   * OCPが管理するホスト/リージョン/IDCのデータテーブルは以下のとおりです：

     * compute_host：ホスト
     * compute_idc：データセンター
     * compute_region：リージョン

   * 以下のコマンドを実行して、OCP MetaDB内のすべてのリージョン/IDC情報を照会します：

      ```sql
      -- OCP metadbが管理するIDCとリージョン情報を照会する
      SELECT r.`name` AS region, i.`name` AS idc
      FROM compute_region r JOIN compute_idc i
      ON r.id=i.region_id;
      ```

   * 以下のコマンドを実行して、OceanBaseクラスタ内のZoneのIDC/リージョン情報を照会します：

      ```sql
      -- OceanBaseクラスタ内のZoneのIDCとRegion情報を照会する
      SELECT `zone`,
      MAX(CASE `name` WHEN 'region' THEN `info` ELSE '' END ) `region`,
      MAX(CASE `name` WHEN 'idc' THEN `info` ELSE '' END ) `idc`
      FROM oceanbase.__all_zone WHERE `zone` <> '' GROUP BY `zone` ;
      ```

    OCP MetaDBで管理されているRegion/IDCの関連性と、OceanBaseクラスタ内のZoneのRegion/IDCの関連性に不整合がある場合は、次の手順を実行してください。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    OceanBaseクラスタ内のZoneのIDC設定が空の場合、クラスタの同期には影響しません。
    </main>

4. OceanBaseクラスタ内のZoneのIDC/Regionなどは論理的な区分です。OceanBaseクラスタ内のIDC/Region情報に変更が生じた場合、OCP MetaDBで手動で同期する必要があります。以下の情報を例にします：

   * IDCの変更前の名前は`old idc`、変更後の名前は`zue`です。
   * Regionの変更前の名前は`old region`、変更後の名前は`SHANGHAI`です。

   手順は以下の通りです：

   1. OCP MetaDB（クラスタ名はデフォルトでobcluster）のocp_metaテナントのrootユーザーでocp_metaデータベースにログインし、変更履歴が存在するかどうかを照会します。

      1. `SHANGHAI`という名前のRegionが存在するかどうかを照会します：

         ```sql
         select * from compute_region where name='SHANGHAI';
         ```

      2. `zue`という名前のIDCが存在するかどうかを照会します：

        ```sql
        select * from compute_idc where name='zue';
        ```

      存在しない場合は、以下のコマンドを実行してRegionとIDCを新規作成します。存在する場合は、次の手順に進みます。

      ```sql
      -- Regionの新規作成
      insert into compute_region (`name`, `description`) values ('SHANGHAI', 'SHANGHAI region');
      -- IDCの新規作成
      insert into compute_idc (`name`, `description`, `region_id`) select 'zue', 'zue idc', id from compute_region where name='SHANGHAI';
      ```

   2. OCP ZoneのRegionとIDC情報を修正します。

      ```sql
      update ob_zone set idc_id = (select id from compute_idc where name='zue') where name='your zone name' and cluster_id= your cluster id in ocp;
      ```

   3. OCP compute_hostのRegionとIDC情報を修正します。

      ```sql
      update compute_host set idc_id = (select id from compute_idc where name='zue') where inner_ip_address in (ips of the hosts);
      ```

<main id="notice" type='notice'>
<h4>注意</h4>
OCP MetaDBに既存のリージョンやIDCデータが、対応するOceanBaseクラスタで参照されている可能性があります。OceanBaseクラスタのRegionおよびIDC情報をCLIで変更した場合は、まずOCP MetaDBにそのRegionとIDC情報を追加し、クラスタのZoneおよびホストデータに関連付けてください。OCP MetaDB内の既存のRegionおよびIDCレコードを変更しないでください。これにより、他のクラスタが誤ったRegionやIDCに関連付けられ、障害が発生するのを防ぐことができます。
</main>
