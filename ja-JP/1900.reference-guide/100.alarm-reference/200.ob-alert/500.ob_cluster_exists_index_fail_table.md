# ob_cluster_exists_index_fail_table OceanBaseクラスタにインデックス作成に失敗したテーブルが存在する場合

## アラートの概要

このアラートは、OceanBaseクラスタ内にインデックス作成に失敗したテーブルが存在するかどうかを監視し、存在する場合にアラートを報告します。

## アラートの仕組み

以下の表は、このアラートの監視ロジックに関連する主要パラメータを示しています。

| パラメータ | 値 |
|-------|---------|
| 監視指標 | index_fail_count。この指標はOceanBaseクラスタ内のインデックス作成に失敗したテーブルの数を示し、指標値がしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | ```sum(ob_index_error_num{@LABELS}) by (@GBLABELS)```     |
| 収集指標 | ob_index_error_num |
| 指標ソース | 内部ビューから収集。収集SQL：<ul><li>OceanBase V4.0未満のバージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(100000000) */ count(*) as cnt from gv$table where table_type in (5) and index_status in (5, 6, 7)```</li><li>OceanBase V4.0以降のバージョン：```select /*+ MONITOR_AGENT QUERY_TIMEOUT(100000000) */ count(*) as cnt from CDB_INDEXES where status in ('ERROR','UNUSABLE')```</li></ul>  |
| 収集サイクル | 5秒 |

## ルール情報

| 監視指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
|-----------------------------|------|------|------|------|
| index_fail_count | 0 | 0秒 | 20秒 | 5分 |

## アラート情報

| アラートトリガー方式 | アラートレベル | 対象範囲 |
|---------------------|--------|---------|
| 監視指標の式に基づく | 重大 | クラスタ |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：alarm_template_id=0:ob_cluster=obcluster-1 OceanBaseクラスタにインデックス作成に失敗したテーブルが存在する場合

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、アラート：\${alarm_name}。インデックス作成に失敗したテーブルの数は \${value} です。
  * 例：クラスタ：obcluster-1、アラート：OceanBaseクラスタにインデックス作成に失敗したテーブルが存在する場合。インデックス作成に失敗したテーブルの数は 1.0 です。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OceanBaseクラスタのインデックス異常テーブル数：\${value}
  * サンプル：アラート：OceanBaseクラスタにインデックス作成失敗のテーブルが存在します、OceanBaseクラスタのインデックスに異常があるテーブル数：0

## システムへの影響

インデックス作成失敗により、SQL実行がインデックスによって最適化されず、実行効率が発揮されません。

## 考えられる原因

インデックス作成タスクの実行中にエラーが発生し、インデックスを作成できない場合によく発生します。一般的なシナリオは以下のとおりです：

* 通常インデックス作成失敗：クラスタ状態に起因する問題。

* 一意性インデックス作成失敗：OceanBaseにおけるインデックス作成は非同期で行われます。データが一意性制約に合致しない場合、エラーは遅延して報告されます。この場合、DBAと業務部門が連携して対処し、データの一意性とインデックス要件が一致していることを確認する必要があります。

## 解決策

1. 以下の方法に従って、失敗したインデックスの内容を特定します。

   1. 以下のコマンドラインを実行して、問題のあるインデックスを検索します。

      ```sql
      -- OceanBase V4.0未満のバージョンに適用：
      select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(100000000) */ count(*) as cnt from gv$table where table_type in (5) and index_status in (5, 6)

      -- OceanBase V4.0以降のバージョンに適用：
      select /*+ MONITOR_AGENT QUERY_TIMEOUT(100000000) */ count(*) as cnt from CDB_INDEXES where status in ('ERROR','UNUSABLE')
      ```

      index_name（インデックス名）とdata_table_id（インデックスが属するテーブルのID）の値を取得します。

   2. data_table_id（インデックスが属するテーブルのID）から、インデックス作成失敗が発生したテーブル名を特定します。

      ```sql
      -- OceanBase V2.xでは__all_virtual_databaseを使用する点に注意してください。

      > SELECT t2.database_name, t1.table_name  from __all_table t1 join __all_database t2 on t1.database_id=t2.database_id where t2.tenant_id=1014 and t1.table_id=1114904790614901;
      +---------------+---------------+
      | database_name | table_name    |
      +---------------+---------------+
      | obsink        | question_dest |
      +---------------+---------------+
      1 row in set (0.05 sec)
      ```

   3. 以下のコマンドを実行して、失敗したインデックスを特定します。

      ```sql
      # MySQLモード #
      obclient> SHOW INDEX FROM table_name;

      # Oracleモード
      obclient> SELECT * FROM USER_IND_COLUMNS WHERE table_name='table_name';
      ```

2. クラスタの状態が正常であることを確認します。

3. インデックスを削除してから再作成します。

   * インデックスの削除については、OceanBaseの対応するバージョンの製品ドキュメントの[インデックスの削除](https://docs.oceanbase.com/oceanbase-database/V4.3.5-delete-indexes-mysql-compatible-mode)を参照してください。

   * インデックスの再作成については、OceanBaseの対応するバージョンの製品ドキュメントの[インデックスの作成](https://docs.oceanbase.com/oceanbase-database/V4.3.5-create-indexes-mysql-compatible-mode)を参照してください。
