# ob_cluster_status_check_failed OceanBaseクラスタ状態チェック失敗

## アラートの概要

このアラートは、OCPが管理するOceanBaseクラスタの状態チェックが成功したかどうかを監視します。失敗した場合にアラートを報告します。

## アラートの仕組み

OCPサーバーは、定期的なタスクを通じてOceanBaseクラスタの状態をチェックします。このタスクは15秒ごとに実行され、毎回OceanBase SDKを使用してOceanBaseクラスタに接続します。接続に失敗した場合、アラートがトリガーされます。

| パラメータ | 値 |
|---------|---------------|
| 監視指標 | ob_cluster_status_check。この指標はOceanBaseクラスタの状態チェックが失敗したかどうかを示します。指標値が`1`の場合はチェック成功、指標値が`0`の場合はチェック失敗でアラートがトリガーされます。       |
| 監視式 | ```max(ob_cluster_status_check{@LABELS}) by (@GBLABELS)```    |
| 取得指標 | ob_cluster_status_check      |
| 指標ソース | 定期タスクがすべてのOceanBaseクラスタの接続状態をチェックし、OceanBaseバージョンの取得を試みることで接続性を判断します。接続がタイムアウトまたは異常な場合、チェックは失敗します。  |
| 取得周期 | 5秒      |

## ルール情報

| 監視指標 | デフォルトしきい値 | 持続時間 | チェック周期 | 解消周期 |
| -------- | -------- | -------- | -------- | -------- |
| ob_cluster_status_check     | 0      | 60秒     | 15秒    | 5分   |

## アラート情報

| アラートトリガー方法 | アラートレベル | 対象範囲 |
| ------------ | -------- | ---- |
| 監視指標の式に基づく | サービス停止     | クラスタ |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：alarm_template_id=0:ob_cluster=obcluster-1 OceanBaseクラスタ状態チェック失敗

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、アラート：\${alarm_name}、クラスタ状態：\${ob_cluster_status}、チェック項目：\${check_item}、失敗理由：${failed_reason}
  * 例：クラスタ：obcluster-1、アラート：OceanBaseクラスタ状態チェック失敗、クラスタ状態：Unavailable、チェック項目：cluster connect check、失敗理由：some reason

* **アラート復旧**

  * テンプレート：アラート：\${alarm_name}、OceanBaseクラスタ状態チェック失敗：\${value}
  * 例：アラート：OceanBaseクラスタの状態検出に失敗しました、OceanBaseクラスタの状態検出に失敗しました：1

## システムへの影響

以下の影響が生じる可能性があります：

* OCPはOBProxyに接続できません。

* OceanBaseクラスタの状態が異常です。

## 考えられる原因

このアラートが報告される一般的な原因は以下のとおりです：

* OCPとOceanBaseクラスタの接続に失敗しました。

  * OCPとOBServer間のネットワーク障害が発生しています。

  * OceanBaseクラスタが利用不可であり、Root Serviceのリーダー不在、またはsysテナント内にリーダーのないテーブルが存在するためです。

* OceanBaseデータベースのsysテナントに異常が発生し、ログインできません。その原因は以下の可能性があります：

  * sysテナントに異常が発生しています。例えば、ocp_monitor@sysアカウントが存在しない場合です。

  * sysテナントのパスワードが間違っています。

## 解決策

* **<UI-TERM key="ocp-v2.Alarm.Event.Detail.AlarmDetails">アラートの詳細</UI-TERM>** の失敗原因にAccess Deniedと表示されている場合、ocp_monitor@sysアカウントが削除されたか、そのアカウントのパスワードが変更された可能性があります。

  1. root@sysアカウントを使用してOceanBaseクラスタにコマンドラインからログインし、以下のステートメントを実行して新しいocp_monitor@sysアカウントを作成します。

  2. 以下のステートメントを実行して、ocp_monitorアカウントと権限を確認します。

     ```sql
     select user_name,priv_select from __all_user;
     ```

     実行結果のuser_nameフィールドの値にocp_monitorが含まれているかどうか、および対応するpriv_selectの値が1であるかどうかを確認します。

     * ocp_monitorが存在しない場合、以下のステートメントを実行してocp_monitorアカウントを作成します。

       `CREATE USER IF NOT EXISTS ocp_monitor IDENTIFIED BY 'your password';`

     * ocp_monitorが存在するものの、対応するpriv_selectの値が0の場合、以下のステートメントを実行してocp_monitorアカウントにSELECTグローバル権限を付与します。

       `GRANT SELECT ON *.* TO ocp_monitor;`

     * ocp_monitorが存在し、対応するpriv_selectの値が1の場合、ocp_monitorのパスワードが間違っている可能性があります。以下のステートメントを実行してパスワードを変更します。

       `ALTER USER ocp_monitor IDENTIFIED BY 'your password';`

  3. [クレデンシャルの管理](../../../1600.system-management-features/100.manage-password-box/100.create-a-credential.md)を参照して、ocp_monitor@sysアカウントをパスワードボックスに保存します。

     パスワードボックスにそのクラスタのocp_monitor@sysアカウントが既に保存されている場合は、削除してください。

* **<UI-TERM key="ocp-v2.Alarm.Event.Detail.AlarmDetails">アラートの詳細</UI-TERM>** の失敗原因が接続失敗を示している場合。

  1. この時点でOCPにそのOceanBaseクラスタに関する他のアラートがないか確認します。

     * もしある場合は、関連ドキュメントを参照し、他のアラートを優先的に処理した後、そのアラートが解消されたかどうかを観察します。

     * なければ、手順2を実行します。

  2. OCPとOBServerノード間のネットワーク障害がないか確認します。

     OCPサーバーで `obclient -hxxx.xxx.xxx.xxx -P2888 -u<ユーザー名>@<テナント名#クラスタ名> -p -Doceanbase` コマンドを実行し、そのOceanBaseに接続できるか確認します。

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>OCPがOBProxy経由でそのOceanBaseクラスタに接続および管理している場合は、IPアドレスとポートをOBProxyプロキシ使用時のものに変更してください。</p>
     </main>

     * 接続できない場合は、接続失敗で返された情報に基づいてトラブルシューティングを行います。

       ネットワーク障害に関連するメッセージが表示された場合は、ネットワーク管理者に連絡し、解決を依頼してください。

       OBProxyまたはOBServerノードのプログラム障害の場合は、プロセスを再起動することで復旧できます。

       <main id="notice" type='explain'>
       <h4>説明</h4>
       <p>OBProxyまたはOBServerノードに関連する障害の確認には、以下のログを確認できます：</p>
       </main>

       * OCPがデプロイしたOBProxyのログファイルは `/home/admin/logs/obproxy/log` にあります。

       * 手動でデプロイしたOBProxyのログファイルは `/opt/taobao/install/obproxy-?/log` にあります（`?` の値はインストールしたOBProxyのバージョンによって異なります）。

       * OBServerノードのログファイルは `/home/admin/oceanbase/log` にあります。

     * 接続できた場合は、次の手順を実行します。

  3. 上記のログを収集し、OCPテクニカルサポートに連絡します。
