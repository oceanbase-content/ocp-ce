# ob_tenant_mview_refresh_delay マテリアライズドビューの自動更新が遅延している

## アラートの概要

<main id="notice" type='explain'>
<h4>説明</h4>
<li>このアラートは、V4.3.5.0以降のOceanBaseクラスタでのみ有効です。</li>
<li>テナントにプライマリ/スタンバイ関係が存在する場合、アラートを報告できるのはプライマリテナントのみです。</li>
</main>

このアラートは、テナント内のデータベースにおけるマテリアライズドビューの更新遅延を監視します。遅延が検出された場合、アラートを報告します。

## アラートの仕組み

1. OCPの定期タスクは、すべてのクラスタのsysテナントで定期的に以下のSQLを実行し、マテリアライズドビューの自動更新が遅延しているデータを収集し、OCP MonitorDBの`sql_aggregate_data`テーブルに格納します。定期タスクは60秒ごとに1回実行されます。

   ```sql
    SELECT E.tenant_id, E.tenant_name, A.database_name, B.table_name AS mview_name, C.last_refresh_date, D.next_date
    FROM oceanbase.__all_virtual_database A, oceanbase.__all_virtual_table B, oceanbase.__all_virtual_mview C, oceanbase.__all_virtual_tenant_scheduler_job D, oceanbase.DBA_OB_TENANTS E
    WHERE A.tenant_id = B.tenant_id
      AND B.tenant_id = C.tenant_id
      AND C.tenant_id = D.tenant_id
      AND D.tenant_id = E.tenant_id
      AND A.database_id = B.database_id
      AND B.table_id = C.mview_id
      AND C.refresh_job = D.job_name
      AND C.refresh_job IS NOT NULL
      AND D.job != 0
      AND D.next_date < Now()
      AND E.tenant_type <> 'META'
      AND E.tenant_name IS NOT NULL
      AND E.tenant_role = 'PRIMARY';
   ```

2. OCPのアラート検出タスクは、アラート項目がSQL_AUDITタイプかどうかを識別します。該当する場合、以下のコマンドを実行して`sql_aggregate_data`内の異常データをスキャンし、アラート検出のルール設定に基づいて対応するアラートを生成します。

   ```sql
   select * from sql_aggregate_data where tags like '%mview_stat%' order by timestamp desc
   ```

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=test471-11:tenant_name=mysqlTes:database=test:mview_name=test_mv_refresh_retry_mv2 マテリアライズドビューの自動更新が遅延しています

* **アラート詳細**

  * テンプレート：OceanBaseクラスタ${ob_cluster_name}のテナント${tenant_name}のデータベース${database}内のマテリアライズドビュー${mview_name}の自動更新が遅延しています。予想される更新日時は${next_date}です。
  * サンプル：OceanBaseクラスタtest471のテナントmysqlTesのデータベースtest内のマテリアライズドビューtest_mv_refresh_retry_mv2の自動更新が遅延しています。予想される更新日時は2025-11-14T16:13:55.026383+08:00です。

## システムへの影響

マテリアライズドビューの時系列性が保証されなくなります。

## 考えられる原因

増分データが多すぎるか、リフレッシュ計画が最適でないためです。

## 解決策

1. sysテナントで以下のコマンドを実行し、マテリアライズドビュー関連のセッションを照会します：

    ```sql
    select id, svr_ip, svr_port,tenant_id, time, info
    from oceanbase.__all_virtual_processlist
    where info like '%mview_name%'\G
    ```

    ここで、`mview_name` は実際に異常が発生したマテリアライズドビューの名前を記入する必要があります。

2. 実行時間が長すぎるセッションが存在する場合、現在実行中の計画をさらに確認できます：

    ```sql
    select dbms_xplan.display_active_session_plan(id, 'all', svr_ip, svr_port)\G
    ```

    ここで、`id`、`svr_ip`、`svr_port` は前の手順で照会した結果を記入する必要があります。

3. 計画情報を分析し、リフレッシュに時間がかかりすぎる問題を調査します。必要に応じて、OCPテクニカルサポートに連絡し、調査を支援してもらうことができます。
