# ob_tenant_request_queue_over_threshold OceanBase テナントリクエストキューオーバーサンプル

## アラートの概要

テナントの通常リクエストキューがスタックアップし、しきい値を超えると、リクエスト処理時間が増加したことを示すアラートが発生します。

テナントのリクエスト優先順位キューは以下のとおりです：

1. queue0: `high prio rpc`、トランザクション関連 RPC。
2. queue1: `lock retry`、ロック競合のリトライ。
3. queue2: `normal prio rpc`、通常 RPC、`inner sql`、SQL トリガー RPC。
4. queue3: `lock retry SQL req`;`OB_TASK`;`OB_GTS_TASK`。
5. queue4: `normal SQL req`;`OB_SQL_TASK`。
6. queue5: `warmup req`。

番号が小さいほど優先順位が高くなります。`dump tenant info` キーワードで検索するか、`__all_virtual_dump_tenant_info` をクエリしてテナントキューの状況を確認できます。

## アラートの仕組み

| パラメータ | 値 |
| -------- | ---------- |
| モニタリング指標 | ob_tenant_request_queue_size、request_queue_time、ここで：<li>ob_tenant_request_queue_size はテナントリクエストキューの長さを表します。</li><li>request_queue_time はテナントキューリクエスト処理時間（マイクロ秒単位）を表します。</li>指標値がしきい値を超えると、対応するレベルのアラートがトリガーされます。 |
| モニタリング式 | <li>ob_tenant_request_queue_total_size：```sum(ob_tenant_request_queue_total_size{@LABELS}) by (@GBLABELS)```</li><li>request_queue_time：```sum(rate(ob_sysstat{stat_id="20002",@LABELS}[@INTERVAL])) by (@GBLABELS) / sum(rate(ob_sysstat{stat_id="20001",@LABELS}[@INTERVAL])) by (@GBLABELS)```</li> |
| 取得指標 | ob_tenant_request_queue_total_size、ob_sysstat |
| 指標ソース | 内部ビューから取得、取得SQL：<li>ob_tenant_request_queue_size：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ tenant_id, req_queue_total_size as total_size, large_queued as large_size from __all_virtual_dump_tenant_info where (tenant_id > 1000 or tenant_id = 1) and svr_ip = ? and svr_port = ?```</li><li>equest_queue_time：<ul><li>OceanBase V4.0 以下バージョン：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN (20001, 20002) and (con_id > 1000 or con_id = 1)```</li><li>OceanBase V4.0 以上バージョン：```select /* MONITOR_AGENT */ con_id tenant_id, stat_id, value from v$sysstat where stat_id IN 20001, 20002) and (con_id > 1000 or con_id = 1) and con_id in (select tenant_id from DBA_OB_TENANTS WHERE tenant_type<>'META')```</li></ul></li>  |
| 取得サイクル | 5秒 |

## システムへの影響

テナントリクエストキューのバックログはシステムに大きな影響を与えます：

1. メモリ使用量が制限を超えます。
2. 業務応答が遅くなります。

## 考えられる原因

* トランザクション処理に時間がかかりすぎ、リクエストの処理が滞っています。
* OBServerのリソース不足により、過剰なリクエストを処理できません。

## 解決策

1. アラート問題を迅速に解消するために、対応計画を実行します。詳細な操作については、[アラート対応計画](../500.appendix/400.execute-the-plan.md)を参照してください。
2. 対応計画を再試行します。対応計画が継続して実行され、元の問題が解決されるようにする必要があります。
3. 対応計画をロールバックする場合は、OceanBaseのサポートチームに連絡し、協力を依頼することができます。
