# ネットワーク障害のトラブルシューティング

このセクションでは、ネットワーク障害のトラブルシューティング手順について説明します。ネットワークケーブル、NIC、物理NIC、NIC設定、ルーティングテーブルなどを確認することで、現在発生しているネットワーク障害を調査できます。

## 手順

1. ネットワークケーブルとNICを確認します。

   * データセンター内で、ネットワークケーブルの両端のLEDインジケーターが点灯しているか確認します。一般的なサーバーでは、緑色のLEDが常に点灯している状態が正常です。スイッチでは、緑色のLEDが点滅している場合はデータ転送中を示します。

     この手順は通常、管理者が実行します。

   * コマンド `ethtool ethX` を使用して、特定のNICのリンクが物理的に接続されているかどうかを確認することもできます。

     ```sql
     $ethtool eth2
     Settings for eth2:
             Supported ports: [ FIBRE ]
             Supported link modes:   10000baseT/Full
             Supported pause frame use: No
             Supports auto-negotiation: No
             Advertised link modes:  10000baseT/Full
             Advertised pause frame use: No
             Advertised auto-negotiation: No
             Speed: 10000Mb/s
             Duplex: Full
             Port: Other
             PHYAD: 0
             Transceiver: external
             Auto-negotiation: off
     Cannot get wake-on-lan settings: Operation not permitted
             Current message level: 0x00000007 (7)
                                    drv probe link
             Link detected: yes
     ```

     ここで、

     * `speed` は現在のNICの速度です。これはギガビットNICです。

     * `Duplex` は、現在のネットワークが全二重をサポートしているかどうかを示します。

     * `link detected` は、現在のNICとネットワークの物理接続状態を示します。

     * `yes` が正常です。

     通常、ネットワーク速度と全/ハーフデュプレックスの状態は、ホストとネットワークプロトコルが自動的に協議して決定します。例えば、上記の8行目の `auto-negotiation` がそれに該当します。

2. 物理NICを確認します。

   * `ifconfig` を使用すると、正常にロードされたNICが表示されます。

   * `ethtool -i ethX` を使用すると、NICドライバーが表示されます。

   * `lspci` を使用すると、PCIバスに接続されているすべてのデバイスが表示されます。

   * `lsmod` は、ロードされたすべてのモジュールを表示します。正常にロードされたモジュールは、/proc/modules にも表示されます。

   通常、NICが正常にロードされると、`ifconfig` で確認できます。その時点でNICが見つからない場合：

   * 物理NICがPCIバスに接続されていない可能性があります。lspci で検出できない場合、NICが故障している可能性が高いです。

   * NICモジュールがロードされていない可能性もあります。

     まず、lspci で対応するメーカーと型番「Ethernet Controller」を見つけ、次に `modprobe` を使用して正しいモジュールをロードしてみます。例：`modprobe 3c509`。エラーが発生した場合、そのモジュールは存在しないことを意味します。正しいモジュールを見つけて再コンパイルする必要があります。

3. NICの設定を確認します。

   1. ifconfigコマンドを使用すると、IPアドレスやマスクなどのNIC設定情報を確認できます。

   2. 設定情報に誤りがある場合は、/etc/sysconfig/network-scripts/ifcfg-ethXファイルを変更することでNICの設定を永続的に修正できます。

   3. service network restartコマンドを実行してネットワークサービスを再起動します。

4. ルーティングテーブルを確認します。

   1. `route -n` コマンドを使用して、特定のNICがターゲットネットワークに接続されているルートを確認します。

   2. `ping ゲートウェイIP` コマンドを使用して、ゲートウェイとの接続を確認できます。

      ゲートウェイにpingが通らない場合は、ゲートウェイがICMPパケットを制限しているか、スイッチの設定に問題がある可能性があります。

      例えば、2枚のNICがそれぞれインターネットと社内ネットワークのサービスを提供している場合、デフォルトゲートウェイが社内ネットワークのNICであると、外部からインターネットサービスにアクセスできません。この場合は、`route delete default gw` コマンドでデフォルトゲートウェイを削除し、その後 `route add default gw` コマンドでデフォルトゲートウェイを追加する必要があります。
