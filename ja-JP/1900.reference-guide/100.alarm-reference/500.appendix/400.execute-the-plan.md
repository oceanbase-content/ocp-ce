# アラート対応プランの処理

このセクションでは、OCPアラートの対応プラン処理機能について説明します。一部のアラート詳細で対応プランを実行し、アラートを迅速に解消できるようになっています。

## 対応プラン処理をサポートするアラート一覧

| アラート名 | アラートの説明 | プランの説明 |
| -------- | -------- | -------- |
| os_observer_not_exist | observerプロセスが存在しない | observerプロセスが異常終了した場合、再起動します。イベント発生後30分間は1回のみ再起動します。 |
| arbitration_service_unavailable | アービトレーションサービスが利用できない | アービトレーションサービスのobserverプロセスが異常終了した場合、再起動します。イベント発生後30分間は1回のみ再起動します。 |
| tenant_memstore_percent_over_threshold | OBテナントメモリ使用率が上限を超えた場合 | テナントメモリが上限を超えた後、テナントメモリを拡張します。 |
| ob_tenant_request_queue_over_threshold | OceanBaseテナントリクエストキューが上限を超えた場合 | テナントCPUが上限を超えた後、テナントCPUを拡張します。 |
| obproxy_client_connections_usage_over_threshold | OBProxyクライアント接続利用率が上限を超えた場合 | OBProxy接続数が不足している場合、クラスタレベルの対応するパラメータ設定を自動的に拡張します。 |
| oas_anomaly_sql_from_anomaly_event_analysis_perf_degradation | ホストCPU上限超過根本原因分析、SQL性能低下 | そのSQLのPlanCacheをリフレッシュします。 |
| oas_anomaly_sql_from_anomaly_event_analysis_plan_changed | ホストCPU上限超過根本原因分析、SQL計画悪化 | そのSQLのPlanCacheをリフレッシュします。 |
| oas_anomaly_sql_from_sql_inspection_perf_degradation | SQL巡回検査、SQL性能低下 | そのSQLのPlanCacheをリフレッシュします。 |
| oas_anomaly_sql_from_sql_inspection_plan_changed | SQL巡回検査、SQL実行計画悪化 | そのSQLのPlanCacheをリフレッシュします。 |

## 手順

以下の手順は、ob_tenant_request_queue_over_threshold（OceanBaseテナントリクエストキューが上限を超えた場合）のアラートを例に説明します。

1. アラートイベントリストで、対象のアラートをクリックして詳細を開きます。

2. アラート詳細ページで、アラートの基本情報を確認した後、対応プランの **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ExecuteNow">今すぐ実行</UI-TERM>** をクリックします。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>一部のアラートでは、対応プランの自動実行が実装されています。アラート詳細を確認する際、実行結果を直接確認できます。**手順6**を参照してください。例えば、<code>os_observer_not_exist</code>、<code>arbitration_service_unavailable</code> などのアラートです。</p>
    </main>

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/ob_tenant_request_queue_over_threshold-1.png) -->

3. ポップアップウィンドウで、**<UI-TERM key="ocp-v2.Plan.Component.CreateDrawer.Confirm">OK</UI-TERM>** をクリックし、対応プランを実行します。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/ob_tenant_request_queue_over_threshold-2.png) -->l

4. 実行結果を確認します。

   1. 対応プランが正常に実行されました。

      <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/ob_tenant_request_queue_over_threshold-5.png) -->

   2. 対応プランの実行に失敗し、対応プランの再試行または対応プランのロールバックを行います。

      * プランの再試行

        実行結果を確認する画面で、**<UI-TERM key="ocp-v2.Alarm.Event.Detail.Retry">再試行</UI-TERM>** をクリックします。

        <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/ob_tenant_request_queue_over_threshold-6.png) -->

      * プランのロールバックについては、OceanBaseのテクニカルサポートにお問い合わせください。

5. 確認が完了したら、**<UI-TERM key="ocp-v2.Backup.Backup.Log.Closed">閉じる</UI-TERM>** をクリックして、アラート詳細ページに戻ります。

6. プランが実行されたアラートでは、**正常に実行された場合を見る** または **失敗した場合を見る** ボタンをクリックして、プランの実行結果を確認できます。プラン結果の詳細については、**ステップ4** を参照してください。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/ob_tenant_request_queue_over_threshold-4.png) -->
