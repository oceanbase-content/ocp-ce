# os_observer_fd_usage OceanBase serverが開いているハンドルが多すぎます

## アラートの概要

OBServerノードのファイルハンドル数がシステムの最大容量の65％を超えた場合にこのアラートが生成されます。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | observer_fd_usage, observer_fd_count |
| 指標の出典 | observer_fd_count: `ls /proc/<observer pid>/fd &#124; wc -l`</br>`ulimit -n` を実行してシステムのFD最大容量を確認できます|
| 収集指標 | observer_fd_count, observer_ulimit_max_fd_count |
| モニタリング式 | <li>observer_fd_count: avg(observer_fd_count{@LABELS}) by (@GBLABELS)</li><li>observer_fd_usage: round(100 * avg(observer_fd_count{@LABELS}) by (@GBLABELS) / avg(observer_ulimit_max_fd_count{@LABELS}) by (@GBLABELS))</li> |
| 収集サイクル | 5秒 |

## システムへの影響

オペレーティングシステムにはファイルハンドル数の上限があり、この上限を超えると「too many open files」というエラーが発生し、システムの正常な動作に影響します。

## 考えられる原因

プロセスのリソースが適時に解放されていないことが原因である可能性があります。例：

* ソケット通信で接続が正しく閉じられていない。
* 大量のデータベース接続リクエストが存在する。
* データベースで大量のI/Oリクエストが発生し、過剰なFDファイルが作成されている。

## 解決策

考えられる原因を順に調査します：

1.  以下のコマンドを実行して、FD数を確認します：

   * OBServerノードのFD数を確認する：`lsof -p <observer pid> | wc -l`
   * システムのFD上限を確認する：`ulimit -n`

2.  FD数がシステムのFD上限の65％を超える場合は、運用保守担当者に連絡し、調査を依頼してください。
