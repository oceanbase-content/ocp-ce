# node_file_inode_usage サーバーのinode使用率が高すぎる

## アラートの概要

Linuxシステムでは、inodeはファイルのメタ情報を格納します。これには、ファイルサイズ、ファイル所有者ID、読み書き権限、変更日時、ブロックの位置などが含まれます。

inodeはファイルのインデックスであり、その格納もディスク容量を消費します。多数の小さなファイルを作成しすぎると、過剰なinodeを消費する可能性があります。inode使用率が80%を超えた場合、このアラートがトリガーされます。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | file_inode_usage |
| 指標の出典 | ホスト基本モニタリング、node_exporterから収集</br>inode使用率、`df -i` のIUsed / Inodesに相当 |
| 収集指標 | node_filesystem_files_free, node_filesystem_files |
| モニタリング式 | round(100 - 100 * sum(node_filesystem_files_free{@LABELS}) by (@GBLABELS) / sum(node_filesystem_files{@LABELS}) by (@GBLABELS)) |
| 収集周期 | 1秒 |

## ルール情報

| モニタリング式 | モニタリング指標の意味 | デフォルトしきい値（パーセンテージ） | 検出周期 | 解消周期 |
| --- | --- | --- | --- | --- |
| file_inode_usage > 80 | inode使用率 | 80% | 10秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| --- | --- | --- |
| モニタリング指標の式に基づく | 重大 | サーバー |

## アラートテンプレート

* **アラートの概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：svr_ip=xxx.xxx.xxx.xxx サーバーのinode使用率が高すぎる

* **アラートの詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。inode使用率 \${value_shown} が ${alarm_threshold} % を超えました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：サーバーのinode使用率が高すぎる。inode使用率 95 % が 80 % を超えました。

* **アラートの回復**

  * テンプレート：アラート：${alarm_name}、サーバーのinode使用率：\${value_shown}
  * 例：アラート：サーバーのinode使用率が高すぎます。サーバーのinode使用率：60 %

## システムへの影響

inodeが使い果たされると、システムはファイルを作成できなくなります。これはデータベースの書き込み操作にとって致命的であり、トランザクションのコミット失敗、ログの同期不能、OBServerの利用不能などを引き起こす可能性があります。

## 考えられる原因

システム内に小さなファイルが多すぎて、大量のinodeを消費しています。

## 解決策

1. inode使用量が最も多いディレクトリを確認します。

   ```yaml
   df -i
   ```

2. ファイル数が最も多いディレクトリを特定します。

   ```yaml
   for i in /target-path/* ; do echo $i; find $i | wc -l | sort -nr; done
   ```

3. 不要なファイルを削除します。
