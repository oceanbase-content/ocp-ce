# os_tsar_nvme_ioawait OceanBase server ディスクIOawaitが高い

## アラートの概要

ディスクI/Oの重要な指標には以下のものがあります。

* svctmはディスクの性能を反映し、通常は20ミリ秒未満です。
* ioawaitはI/O処理効率を反映します。ioawaitが低いほどI/Oキューの輻輳がないことを示します。ioawaitがsvctmに近い場合、I/Oの待機がほとんどないことを意味します（ioawaitがsvctmよりわずかに大きい場合は許容範囲内です）。
* io_utilは単位時間あたりのデバイスI/O占有率で、I/Oの混雑度を示します。
* io_qusizeはI/Oキューの長さです。キューの長さが長いほど、ioawaitは高くなる可能性があります。

連続する30秒間にio_awaitが20ミリ秒以上、io_utilが98％以上、io_qusizeが20以上の場合、このアラートがトリガーされます。

## システムへの影響

IO utilが98%を超えると、IOデバイスがフル負荷で動作していることを意味します。ioawaitが20 msを超えると、ディスクデバイスの処理効率が低いか、大量のIOリクエストがある可能性があります。この場合、ダンプやメジャーコンパクション操作の進捗に影響します。

OBディスクはデータディスク(/data/1)、ログディスク(/data/log1)、インストールディスク(/home)に分かれており、このアラートはデータディスクとログディスクに対して有効です。データディスクとログディスクでIO異常が発生すると、OBServerノードのサービスに影響します。

## 考えられる原因

1. ディスクの性能が低い。
2. CPUの性能が低く、大量のIOリクエストを処理できない。
3. 多数のIOリクエストが同時に発生している。

## 解決策

1. ディスクやCPUの性能低下が原因でないか調査します。この問題はハードウェアリソースのアップグレードにより回避できます。

2. リクエストトラフィックが想定通りであるか確認し、IO異常の原因を調査します：

   ```yaml
   # IO統計情報を確認する
   iostat -dx

   # IOが高いプロセスを確認する
   iotop

   # プロセスがどのファイルに書き込んでいるか、書き込み量が想定通りかなどを確認する
   lsof -p <pid>
   ```
