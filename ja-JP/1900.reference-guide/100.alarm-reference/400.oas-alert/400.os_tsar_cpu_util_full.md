# os_tsar_cpu_util_full サーバーのCPU使用率が100%に達した

## アラートの説明

CPU使用率（util+steal）が98%を超えた場合にこのアラートが発生します。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | cpu_used_percent |
| 指標の出典 | ホストの基本モニタリング、node_exporterから収集</br>topコマンドのCPU指標と同様に、util = user + system + nice + irq + softirq |
| 収集指標 | node_cpu_seconds_total |
| モニタリング式 | 100 * (1 - sum(rate(node_cpu_seconds_total{mode=~"idle&#124;iowait",@LABELS}[@INTERVAL])) by (@GBLABELS)) |
| 収集周期 | 1秒 |

## ルール情報

| モニタリング式 | モニタリング指標の意味 | デフォルトのしきい値（単位：パーセンテージ） | 検出周期 | 解消周期 |
| --- | --- | --- | --- | --- |
| cpu_used_percent >= 98 | CPU利用率。以下を含む：<li>user：ユーザースペースコードの実行時間の割合</li><li>system：カーネルスペースコードの実行時間の割合</li><li>nice：プロセス優先度の変更によって占有されるCPUの割合。デフォルトは0</li><li>irq：ハードウェア割り込みのCPU占有率</li><li>softIRQ：ソフトウェア割り込みのCPU占有率</li> | 98% | 10秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| --- | --- | --- |
| モニタリング指標の式に基づく | 重大 | サーバー |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：svr_ip=xxx.xxx.xxx.xxx サーバーのCPU使用率が100%に達した

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。CPU使用率 \${value_shown} が ${alarm_threshold} % を超えました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：サーバーのCPU使用率が100%に達しました。CPU使用率 99.178 % が 98 % を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、サーバーCPU使用率：user、system、nice、irq、softirq、steal の合計：\${value_shown}
  * 例：アラート：サーバーのCPU使用率が100%に達しました、サーバーCPU使用率：user、system、nice、irq、softirq、steal の合計：90 %

## システムへの影響

CPU利用率が長時間100%を維持すると、システムの安定性とパフォーマンスに深刻な影響を及ぼし、サービス停止を引き起こす可能性があります。

## 考えられる原因

* ユーザー空間コードの実行によるCPU占有率が高すぎる。一般的にはアプリケーションプロセスの負荷が高いためであり、例えば、高並行性のリクエスト処理や大量データの処理などが挙げられます。
* カーネル空間のCPU利用率が高すぎる。例えば、頻繁なシステムコールの発生などが挙げられます。
* ソフトインタラプトによるCPU占有率が高すぎる。例えば、ネットワーク攻撃などが挙げられます。

## 対処方法

1. `top` コマンドを実行して、どのメトリクスのCPU利用率が高いか調査します。
2. OBServerノードのCPU利用率が高い場合、マージやダンプなどCPUを消費する操作が発生していないか確認します。CPU利用率が想定通りでない場合は、管理者に連絡して確認してもらいます。
