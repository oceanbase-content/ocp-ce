# os_tsar_sda_ioawait OceanBase ServerのディスクI/O待ち時間が高すぎる

## アラートの概要

ディスクI/Oの主要な指標には以下のものがあります：

* svctmはディスクの性能を示し、通常は20ms未満です。
* ioawaitはI/O処理効率を示します。ioawaitが低いほどI/Oキューの輻輳がないことを意味します。ioawaitがsvctmに近い場合、I/O待ち時間がほとんどないことを示します（ioawaitがsvctmよりわずかに大きい場合は許容範囲内です）。
* io_utilは単位時間あたりのデバイスI/O割合で、I/Oの混雑度を示します。

連続30秒間にわたりio_awaitが200ms以上、かつio_utilが99%以上の場合、このアラートがトリガーされます。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | io_util, io_qusize, io_read_write_time |
| 指標の出典 | ホスト基本モニタリング、node_exporterから収集</br>`iostat -dx`コマンドの結果に含まれる指標に対応：util（io_util）、avgqu-sz（io_qusize）、rkB/sおよびwkB/s（io_read_write_time） |

| モニタリング式 | <li>io_util: avg(io_util{@LABELS}) by (@GBLABELS)</li><li>io_qusize: sum(delta(node_disk_io_time_weighted_seconds_total{@LABELS}[@INTERVAL])) by (@GBLABELS)</li><li>io_read_write_time: avg(rate(node_disk_read_time_seconds_total{@LABELS}[@INTERVAL])) by (@GBLABELS) + avg(rate(node_disk_write_time_seconds_total{@LABELS}[@INTERVAL])) by (@GBLABELS)</li> |
| 収集サイクル | 1秒 |

## アラートテンプレート

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：ob_cluster=obcluster-1631964370:svr_ip=xxx.xxx.xxx.xxx:device=dm-0 OceanBase ServerのディスクI/O待ち時間が高すぎる

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。OceanBaseディスク：\${ob_device}、デバイス \${device}、io await \${io_await_value_zh_cn} が \${io_await_alarm_threshold} ms を超え、io util \${io_util_value_zh_cn} が ${io_util_alarm_threshold} % を超えました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：OceanBase ServerのディスクI/O待ち時間が高すぎる。OceanBaseディスク：ob_log、デバイス dm-0、io await 300ミリ秒が200ミリ秒を超え、io util 99.1 % が99 % を超えました。

* **アラートの回復**

  * テンプレート：アラート：${alarm_name}、OBServerディスクio_await：\${io_await_value_zh_cn}、OBServerディスクio_util：\${io_util_value_zh_cn}
  * サンプル：アラート：OceanBaseサーバーのディスクioawaitが高すぎます、OBServerディスクio_await：120ミリ秒、OBServerディスクio_util：85%

## システムへの影響

IO utilが99%を超えると、IOデバイスがフル負荷で動作していることを意味します。ioawaitが200ミリ秒を超える場合、ディスクデバイスの処理効率が低いか、大量のIOリクエストがある可能性があり、ダンプやメジャーコンパクション操作の進捗に影響を与える可能性があります。

OBディスクは、データディスク(/data/1)、ログディスク(/data/log1)、インストールディスク(/home)に分かれており、このアラートはデータディスクとログディスクに対して有効です。データディスクとログディスクでIO異常が発生すると、OBServerノードがサービスを提供することに影響します。

## 考えられる原因

* ディスクの性能が低い。
* CPUの性能が低く、大量のIOリクエストを処理できない。
* 多数のIOリクエストが同時に発生している。

## 解決策

1. ディスクやCPUの性能低下が原因であるかどうかを調査します。この問題は、ハードウェアリソースをアップグレードすることで回避できます。

2. リクエストトラフィックが想定通りであるか確認し、IO異常の原因を調査します：

   ```yaml
   # IO統計情報を確認する
   iostat -dx

   # IOが高いプロセスを確認する
   iotop

   # プロセスがどのファイルに書き込んでいるか、書き込み量が想定通りかどうかなどを確認する
   lsof -p <pid>
   ```
