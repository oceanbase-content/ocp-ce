# os_observer_core_dump OceanBase server Core Dump

## アラートの概要

OBServerノードが異常終了すると、コアダンプファイルが生成されます。コアダンプファイルは非常に大きく、数十GBから数百GBに達することがあるため、緊急対応およびOBServerノードの異常終了に対する根本原因分析が必要です。OBServerノードがコアダンプを行うと、その後20分間、このアラートが連続して送信されます。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | observer_core_dump_seconds |
| 指標の出典 | OBServerノードのモニタリング。最新のobserverコアダンプファイルから現在時刻までの時間を秒単位で確認します |
| 取得指標 | observer_coredump_time_seconds |
| モニタリング式 | max(observer_coredump_time_seconds{@LABELS}) by (@GBLABELS) |
| 取得サイクル | 5秒 |

## ルール情報

| モニタリング式 | デフォルトしきい値(秒) | 持続時間 | 検出サイクル | 解消サイクル |
| --- | --- | --- | --- | --- |
| observer_core_dump_seconds  | observer_core_dump_seconds < 1200 and observer_core_dump_seconds > 0 | 0秒 | 10秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| --- | --- | --- |
| モニタリング指標の式に基づく | 重大 | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：ob_cluster=obcluster-1631964370:svr_ip=xxx.xxx.xxx.xxx OceanBase server Core Dump

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${value_shown} 前 OceanBase server Core Dump。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：10 分钟前 OceanBase server Core Dump。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OBServer の最新コアダンプまでの時間：\${value_shown}
  * 例：アラート：OceanBase server Core Dump、OBServer の最新コアダンプまでの時間：0 秒

## システムへの影響

OBServerノードがcore dumpした場合、そのOBServerノードは異常終了します。

* レプリカが1つのシステムでは、observerプロセスが存在しないことでサービスが停止します。
* レプリカが複数あるOceanBaseクラスタでは、observerプロセスが存在しないことで可用性が低下する可能性があります。例えば、3ゾーンが2ゾーンに変わったり、同一リージョンの3データセンターが2データセンターになったりします。

## 考えられる原因

通常、OBServerノードはsignal 11（無効なメモリアクセス）、signal 6（プロセス放棄）などの異常な理由で終了する可能性があります。一般的には、OBServerノード自体の問題、またはオペレーティングシステムや基盤レベルの原因によるものであり、この場合は具体的な問題に応じた分析が必要です。

通常、ハードウェアの損傷やオペレーティングシステムの問題でない限り、緊急対応としてOBServerノードを再起動する必要があります。

## 対処方法

1. 緊急対応：障害が発生したOBServerノードをオフラインにします。
2. 技術サポートに連絡し、根本原因を分析します。
