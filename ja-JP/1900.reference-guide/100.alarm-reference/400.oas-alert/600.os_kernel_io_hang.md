# os_kernel_io_hang OceanBase server サーバー IO Hang

## アラートの説明

OCPはIO Hangのメトリクスを定義しており、このメトリクスが異常値の状態が30秒間続いた場合にこのアラートが発生します。IO Hangのメトリクスの説明は以下の通りです：

* io_util >= 99は、IOがフル負荷で動作していることを示します。
* io_qusize >= 20は、処理待ちの読み取りまたは書き込みデータがIOキューにあることを示します。
* io_read_write_time == 0は、IOの書き込みと読み取りが停止し（応答を停止）、ハング状態になっていることを示します。

## アラートの原理

| パラメータ | 値 |
| --- | --- |
| モニタリングメトリクス | io_util, io_qusize, io_read_write_time |
| メトリクスソース | ホスト基本モニタリング、node_exporterから収集</br>`iostat -dx` コマンドの結果に含まれる指標に類似：util（io_util）、avgqu-sz（io_qusize）、rkB/s および wkB/s（io_read_write_time） |
| メトリクス収集 | io_util, node_disk_io_time_weighted_seconds_total, node_disk_read_time_seconds_total, node_disk_write_time_seconds_total |
| モニタリング式 | <li>io_util: avg(io_util{@LABELS}) by (@GBLABELS)</li><li>io_qusize: sum(delta(node_disk_io_time_weighted_seconds_total{@LABELS}[@INTERVAL])) by (@GBLABELS)</li><li>io_read_write_time: avg(rate(node_disk_read_time_seconds_total{@LABELS}[@INTERVAL])) by (@GBLABELS) + avg(rate(node_disk_write_time_seconds_total{@LABELS}[@INTERVAL])) by (@GBLABELS)</li> |
| 収集サイクル | 1秒 |

## ルール情報

| モニタリング式 | モニタリングメトリクスの意味 | デフォルトしきい値 | 検出サイクル | 解消サイクル |
| --- | --- | --- | --- | --- |
| io_util >= 99 and io_qusize >= 20 and io_read_write_time == 0 | <li>io_util: 単位時間内にディスクが処理するIOの時間割合。計算式：（r/s + w/s) * svctm/1000、すなわち1秒あたりの読み書き回数に処理時間の割合を掛けたもの。svctmはIO応答時間です。</li><li>io_qusize: IOキューの長さ。</li><li>io_read_write_time: IOの読み書きにかかる時間の合計。</li> | <li>io_util: 99%</li><li>io_qusize: 20</li><li>io_read_write_time: 0 </li>| 10秒 | 5分 |

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：ob_cluster=obcluster-1631964370:svr_ip=xxx.xxx.xxx.xxx:device=dm-1 OceanBase server サーバー IO Hang

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。OceanBaseディスク：\${ob_device}、デバイス ${device}、io util \${io_util_value_zh_cn} が \${io_util_alarm_threshold} % を超え、io qusize \${io_qusize_value} が \${io_qusize_alarm_threshold} を超えました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：OceanBase server サーバー IO Hang。OceanBaseディスク：ob_data、デバイス dm-1、io util 99.1 % が 99 % を超え、io qusize 30 が 20 を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OBServerディスクio_util：\${io_util_value_zh_cn}、OBServerディスクio_qusize：\${io_qusize_value}、OBServerディスクIO平均読み書き時間の合計：\${recover_value}
  * サンプル：アラート：OceanBaseサーバーIOハング、OBServerディスクio_util：80%、OBServerディスクio_qusize：15、OBServerディスクIO平均読み書き時間の合計：5秒

## システムへの影響

IOハングは書き込みと読み取りを停止させ、この動作はプロセスにとって致命的であり、データがディスクにフラッシュされず、OBServerノードが使用不能になる原因となります。

OBディスクはデータディスク(/data/1)、ログディスク(/data/log1)、インストールディスク(/home)に分かれており、このアラートはデータディスクとログディスクに対して有効です。データディスクまたはログディスクでIOハングが発生すると、OBServerノードはサービスを停止します。

## 考えられる原因

* OBディスクに不良ディスクが発生した場合。
* その他の原因。

## 対処方法

緊急処置：障害が発生したOBServerノードをオフラインにします。
