# sql_audit_collect_lost_percent_over_threshold sql_audit 采集丢点率超限告警

## 警報の概要

OCP-Agent sql_audit の診断データ収集における欠落率が一定のしきい値を超えた場合、このアラートがトリガーされます。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | sql_audit_collect_lost_percent |
| 指標の出典 | モニタリングAgentの自己監視統計情報。 |
| 収集指標 | <ul><li> sql_audit_input_collect_lost_total </li><li> sql_audit_input_collect_total_total </li></ul> |
| モニタリング式 | 100 * sum(rate(sql_audit_input_collect_lost_total{@LABELS}[@INTERVAL])) by (@GBLABELS) / sum(rate(sql_audit_input_collect_total_total{@LABELS}[@INTERVAL])) by (@GBLABELS) |
| 収集サイクル | 5秒 |

## ルール情報

| モニタリング式 | デフォルトしきい値（パーセンテージ） | 持続時間 | 検出サイクル | 解消サイクル |
| --- | --- | --- | --- | --- |
| sql_audit_collect_lost_percent | 20 | 0秒 | 60秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| --- | --- | --- |
| モニタリング指標の式に基づく | 警告 | ホスト |

## アラートテンプレート

* **アラート概要**
  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：host=xxx.xxx.xxx.xxx sql_audit 采集丢点率超限
* **アラート詳細**
  * テンプレート：クラスタ：${ob_cluster_name}、ホスト：${host}、アラート：sql_audit データ収集欠落率 ${value} が制限値 ${alarm_threshold} % を超えました。
  * サンプル：クラスタ：TEST、ホスト：xxx.xxx.xxx.xxx、アラート：sql_audit データ収集欠落率 23.238 % が制限値 20 % を超えました。
* **アラート回復**
  * テンプレート：アラート：${alarm_name}、sql_audit 采集丢点率：${value}
  * サンプル：アラート：sql_audit 采集丢点率超限、sql_audit 采集丢点率：10 %

## システムへの影響

sql_audit の診断収集データは、サービス内のSQL診断機能に使用されます。欠落率が高すぎると、SQL診断で一部のSQL情報が欠落し、その機能の使用に影響します。

## 考えられる原因

1. ホストのトラフィックが高く、モニタリングAgentの処理能力を超えてしまい、sql_auditデータの収集が追いつかない。
2. ノード上でSQL接続リクエストを受信するテナントと実際に実行されるテナントが一致しない。

## 解決策

該当ノードのモニタリングAgentプロセスのCPUおよびメモリ使用状況を確認します。使用率が高い場合、またはフル負荷状態になっている場合は、以下の方法で環境コンテキスト情報およびモニタリングAgentのログ（ocp_agent/log/monagent.log）を取得し、ファイルを運用保守担当者に提供します。環境コンテキスト情報の取得方法は以下の通りです：

```shell
PID=$(cat /home/admin/ocp_agent/run/ocp_monagent.pid)
SOCKET=$PID
# グルーチン性能データ
curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$PID.sock http://11/debug/pprof/goroutine?debug=1 --output /tmp/goroutine.txt
# cpu性能サンプリングデータ
curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$PID.sock http://localhost/debug/pprof/profile?seconds=30 --output pprof.profile.gz
# メモリサンプリングデータ
curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$PID.sock http://localhost/debug/pprof/heap --output pprof_heap.gz
```
