# os_tsar_cpu_util_hwm サーバーCPU利用率が上限を超えた場合

## アラートの概要

CPU利用率（util+steal）が90%を超えた場合にこのアラートが生成されます。

## アラートの仕組み

| パラメータ | 値 |
| --- | --- |
| モニタリング指標 | cpu_used_percent, cpu_steal |
| 指標の出典 | ホストの基本モニタリング、node_exporterから収集</br>topコマンドのcpu指標と同様に、util = user + system + nice + irq + softirq |
| 収集指標 | node_cpu_seconds_total |
| モニタリング式 | <li>cpu_used_percent：100 * (1 - sum(rate(node_cpu_seconds_total{mode=~"idle&#124;iowait",@LABELS}[@INTERVAL])) by (@GBLABELS))</li><li>cpu_steal：100 * sum(rate(node_cpu_seconds_total{mode="steal", @LABELS}[@INTERVAL])) by (@GBLABELS)</li> |
| 収集サイクル | 1秒 |

## ルール情報

| モニタリング式 | モニタリング指標の意味 | デフォルトのしきい値（単位：パーセンテージ） | 検出サイクル | 解消サイクル |
| --- | --- | --- | --- | --- |
| cpu_used_percent > 90 and cpu_steal < 20 | CPU steal：仮想マシンがCPUスライス時間を共有しますが、一定の制限（steal）を超えることがあります。</br>CPU利用率（util）は、以下を含みます：<li>user：ユーザースペースコードの実行時間の割合</li><li>system：カーネルスペースコードの実行時間の割合</li><li>nice：優先順位、デフォルトは0</li><li>irq：ハードウェア割り込みのCPU占有率</li><li>softirq：ソフトウェア割り込みのCPU占有率</li> | <li>cpu_used_percent: 90%</li><li>cpu_steal: 20%</li> | 10秒 | 5分 |

## アラートテンプレート

* **アラートの概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：svr_ip=xxx.xxx.xxx.xxx サーバーCPU利用率が上限を超えた場合

* **アラートの詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。CPU利用率 \${cpu_used_percent_value_zh_cn} が \${cpu_used_percent_alarm_threshold} % を超え、CPU steal \${cpu_steal_value_zh_cn} が \${cpu_steal_alarm_threshold} % を下回りました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：サーバーCPU利用率が上限を超えた場合。CPU利用率 90.186% が 90 % を超え、CPU steal 0 % が 20 % を下回りました。

* **アラートの回復**

  * テンプレート：アラート：${alarm_name}、サーバーCPU利用率：user、system、nice、irq、softirq、steal の合計：\${cpu_used_percent_value_zh_cn}、サーバーCPU steal利用率：\${cpu_steal_value_zh_cn}
  * 例：アラート：サーバーCPU利用率が上限を超えた場合、サーバーCPU利用率：user、system、nice、irq、softirq、steal の合計：80 %、サーバーCPU steal利用率：30 %

## システムへの影響

CPU利用率が長時間100%を維持すると、システムの安定性とパフォーマンスに深刻な影響を及ぼし、サービス停止に至る可能性があります。

## 考えられる原因

* ユーザー空間コードの実行によるCPU占有率が高すぎる。一般的にはアプリケーションプロセスの使用率が高いことが原因です。例：高並行性のリクエスト処理や大量データの処理など。
* カーネル空間CPU利用率が高すぎる。例：システムコールが多数発生している場合。
* ソフトインタラプトによるCPU占有率が高すぎる。例：ネットワーク攻撃など。

## 解決策

1. `top` コマンドを実行し、CPU利用率が高い項目を調査します。
2. OBServerノードのCPU利用率が高い場合、マージやダンプなどCPUを消費する操作が行われていないか確認します。CPU利用率が想定通りでない場合は、管理者に連絡して確認してもらいます。
