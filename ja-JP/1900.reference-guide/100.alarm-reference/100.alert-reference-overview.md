# 概要

OceanBaseクラウドプラットフォーム（OceanBase Cloud Platform、OCP）は、OceanBaseクラスタ、テナント、ホストなど、さまざまな観点からアラート監視サービスを提供します。ユーザーは組み込みのアラート項目を使用して基本的なアラート要件を満たすことができます。このマニュアルでは、各組み込みアラートの詳細について説明します。[新規アラートルールの作成](../../860.alert-management/300.manage-alert-rules/100.create-an-alert-rule.md)を通じて、ニーズに合わせたアラート項目を作成することもできます。

本章で説明するアラートの見出しは、**<UI-TERM key="ocp-v2.component.alarm.RuleDetail.AlarmItemName">アラート項目名</UI-TERM>** と **<UI-TERM key="ocp-v2.component.UploadPackageDrawer.Description">説明</UI-TERM>** で構成されています。例えば、「**ob_cannot_connected OBサーバー接続不可**」という見出しでは、**ob_cannot_connected** が **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.AlarmItemName">アラート項目名</UI-TERM>**、**OBサーバー接続不可** がアラートの **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.DescriptionOptional">説明</UI-TERM>** です。

本章では、以下の観点から組み込みアラート項目について説明します：

|   比較項目   |  説明   |
|--------|----------|
| アラートの説明   | 各アラートの意味とトリガーシナリオについて説明します。   |
| アラートの仕組み   | アラートが発生する原理を説明します。モニタリング指標値の出典に重点を置きます。モニタリング式によってトリガーされるアラートでは、そのアラートの仕組みの説明に以下の用語が含まれます： <li> **モニタリング指標** ：モニタリング指標値がアラート報告ルールを満たした場合にアラートがトリガーされます   </li><li> **指標の出典** ：特に断りのない限り、通常はOCP-Agentがsysテナントのシステムテーブルから取得します。クエリステートメントは各アラートの **指標の出典** に記載されています。   </li><li> **収集指標** ：**指標の出典** から取得し、モニタリング式に代入して計算することで、最終的に **モニタリング指標** の値が得られます。   </li><li> **モニタリング指標式** ：収集した指標とLABELSを組み合わせて演算し、最終的にモニタリング指標値を得ます（LABELS：フロントエンドインターフェースから送信されたLABELSと **指標の出典** 内のLABELSを照合することで、対象オブジェクトのデータを正確に取得します）。 GBLABELS：同一カテゴリのモニタリングデータを統合するために使用されます。   </li><li> **収集サイクル** ：OCP-Agentがsysテナントのシステムテーブルをクエリする周期  </li> 上記の用語間の関係：**収集指標** は、各 **収集サイクル** で **指標の出典** に記述された方法に従って値を取得し、その値を **モニタリング指標式** に代入して **モニタリング指標** の値を得ます。    |
| ルール情報   | 各アラートがトリガーするルールを紹介します。これには、**モニタリング指標**、**デフォルトしきい値**、**<UI-TERM key="ocp-performance-report.ReportTable.ActivityOverTime.ActivityOverTimeTable.Duration">持続時間</UI-TERM>**、**<UI-TERM key="ocp-v2.Alarm.Rule.New.AlarmCycle">アラート周期</UI-TERM>**、および **<UI-TERM key="ocp-v2.Alarm.Template.Detail.EliminationCycle">クリア周期</UI-TERM>** が含まれます。 <li> トリガールール：システムは各 **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.DetectionCycle">検査周期</UI-TERM>** ごとに **モニタリング指標** を一度検出します。**モニタリング指標** の値が **デフォルトしきい値** を超え、かつ **<UI-TERM key="ocp-v2.component.CardAbnormalTable.Duration">継続時間</UI-TERM>** で設定された値に達した場合、アラートが報告されます。**<UI-TERM key="ocp-v2.Alarm.Template.Detail.DetectionCycle">検査周期</UI-TERM>** のデフォルトは10秒です。アラートがトリガーされる前は10秒ごとに検出し、アラートがトリガーされた後は、各 **<UI-TERM key="ocp-v2.Alarm.Template.Detail.AlarmCycle">アラート周期</UI-TERM>** ごとに検出します。   </li><li> 解消ルール：アラートが継続して報告されず、持続時間が **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.EliminationCycle">周期の除去</UI-TERM>** で設定された時間に達すると、システムはこのアラートを自動的にクリアします。 </li>     |
| アラート情報   | 各アラートのトリガー方法、アラートレベル、範囲、およびアラート対象について説明します。トリガー方法には以下が含まれます： <li>式によるトリガー：モニタリング指標式によってトリガーされます。モニタリング指標値が報告条件を満たすとアラートがトリガーされます。一般的に、そのモニタリング指標は以下のいずれかから取得されます： </li><li> OCP-Agentがsysテナントのシステムテーブルから取得します。   </li><li> OCP-AgentがLinuxコマンドを使用してローカルホストから取得します。  </li> <li> エクスポーターから収集されたモニタリング指標から取得します。ブラウザで対応するインターフェースを呼び出すことで、エクスポーターで収集された指標を確認できます。例は以下のとおりです。ここで、`xxx.xxx.xxx.xxx` はOBServerノードのホストIPです。</li> <li> `http://xxx.xxx.xxx.xxx:62889/metrics/node/host` ホスト指標の表示  </li><li> `http://xxx.xxx.xxx.xxx:62889/metrics/node/ob` クラスタ指標の表示  </li><li> `http://xxx.xxx.xxx.xxx:62889/metrics/ob/perSecond` クラスタの1秒ごとの指標の表示   </li><li> `http://xxx.xxx.xxx.xxx:62889/metrics/ob/perMinute` クラスタの1分ごとの指標      </li><li> スケジュールタスクによるトリガー：OCP-Serverがスケジュールタスクを設定し、ローカルホストに対して対応するチェックを実行します。トリガー条件に合致する場合、アラートが報告されます。 </li>   |
| アラートテンプレート   | 各アラートの概要テンプレート、詳細テンプレート、概要詳細、および詳細例を紹介します。  |
| システムへの影響 | アラート発生時にシステムに与える可能性のある影響について説明します。  |
| 考えられる原因   | アラートの原因を説明し、問題の特定とアラートの処理を容易にします。   |
| 対処方法   | 各アラートに記載されている具体的な方法に従って対処できます。  |

デフォルトのしきい値が使用要件を満たさない場合は、アラートのしきい値を変更できます。使用シナリオで一部のアラートに注意を払う必要がない場合は、アラートのミュートを設定できます。[新規ミュート条件の作成](../../860.alert-management/800.manage-blocking-conditions/100.create-a-blocking-condition.md)を参照してください。

## 関連概念

**<UI-TERM key="ocp-v2.Alarm.Event.Detail.AlertObject">アラート対象</UI-TERM>**

アラートタスクが監視する主体であり、アラートに対応するオブジェクトを一意に識別します。OceanBaseクラスタ、マシン、またはサービスのいずれかになります。

アラート対象の形式はアラート項目の次元によって異なり、ラベル値またはラベル値の組み合わせである場合があります。例えば、`obregion=obocp:svr_ip=*.*.*.*` は、OceanBase OCPクラスタ上のサーバーを識別します。

**<UI-TERM key="ocp-v2.Alarm.Rule.AddAlarmMetricModal.AlertRange">アラート範囲</UI-TERM>**

アラート範囲は、特定のアラートに対応する範囲を定義するために使用され、指標範囲と一致します。例えば、CPU使用率が限度を超えることは、クラスタ全体の使用率が限度を超える、テナントのCPU使用率が限度を超える、マシンの使用率が限度を超えるなど、異なる範囲の意味を表すことがあります。

アラート範囲には、OBクラスタ OBCluster、OBテナント OBTenant、アプリケーションクラスタ AppCluster、サービス Service、サーバーホスト Host、プロセス Process（予約済みタイプ）が含まれます。

**<UI-TERM key="ocp-v2.Alarm.Event.AlarmLevel">アラートレベル</UI-TERM>**

各アラート項目には対応するアラートレベルがあります。

| **レベル** | **英語の意味** | **中国語の意味** | **色** |                                       **<UI-TERM key="ocp-v2.Detail.LoadBalance.AddObproxyLoadBalanceAppDrawer.Description">説明</UI-TERM>**                                       |
|--------|----------|----------|--------|------------------------------------------------------------------------------------|
| 1      | Down     | サービス停止       | 紫      | 完全に利用できません。直ちに介入して修正する必要があります。例：`OBサービス起動失敗`                                       |
| 2      | Critical | 重大       | 赤      | システム可用性が低下しています。緊急に修正し、完全な利用不能を防ぐ必要があります。例：`マシンメモリ使用率が90%を3分間超えています`                     |
| 3      | Alert    | 警告       | オレンジ      | システムはまだ利用可能ですが、まもなく利用不能状態に達するため、可用性の低下を防ぐ措置を講じる必要があります。例：`OBテナント接続数が上限の80%を超えています`             |
| 4      | Caution  | 注意       | 青      | トレンドから判断すると、システムの重要なパフォーマンス指標が低下していますが、警告をトリガーするレベルには達していません。この時点で調査を行うことで潜在的な問題を発見し、警告の発生を防ぐことができます（予約タイプで、現在対応するアラート項目はありません）。        |
| 5      | Info     | リマインダー   | 緑      | 操作に関するリマインダーです。本質的にはアラートではなく、通常は管理者が `クラスタのオフライン化操作` のような重要な操作を実行する場合に表示されます。このレベルのアラートが復旧した場合、アラート復旧の通知は生成されません。 |
