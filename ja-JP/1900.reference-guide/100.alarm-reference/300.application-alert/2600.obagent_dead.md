# obagent_dead Agentサービスが利用できません

## 警報の概要

OCP-Agentはホスト上にデプロイされるサービスプログラムの総称です。ocp_monagentはホストおよびOBServerノードの監視データを収集し、ocp_mgragentはOBServerノードの運用保守操作を担当します。ocp_agentdプロセスは、これら2つのサービスのデーモンプロセスです。デーモンプロセスが存在しない場合、OCP-Agentが継続的に正常にサービスを提供できる保証はありません。

この警報は、ホスト上のOCP-Agentプロセスが正常に動作しているかどうかを監視し、異常な場合にトリガーされます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>この警報は、OCP-Agentがまだ正常に監視データ収集サービスを提供している場合に報告されます。つまり、デーモンプロセスは存在しないものの、OCP-Agentサービスが監視するプロセスは引き続き正常に動作しています。</p>
</main>

## 警報の仕組み

| パラメータ       | 値      |
| ---------- | -------- |
| 監視指標   | host_agent_process_status、この指標はプロセスの状態を示します。指標値が`1`の場合は正常、`0`の場合は異常で、警報がトリガーされます。   |
| 監視式        | ```min(host_agent_process_status{@LABELS}) by (@GBLABELS)```    |
| 収集指標   | host_agent_process_status    |
| 指標ソース   | ocp_mgragentのステータスインターフェース`http://ip:62888/api/v1/agent/status``にリクエストすることで、ocp_agentd、ocp_monagent、ocp_mgragentプロセスの状態を取得できます。 |
| 収集周期   | 5秒     |

## ルール情報

| ------------------------- | -------- | -------- | -------- | -------- |
| host_agent_process_status | 0        | 60秒     | 15秒    | 5分   |

## システムへの影響

1. ocp_agentdプロセスが存在しない場合、OCP-Agent関連のプロセスは異常停止し、自動的に再起動されない可能性があります。これにより、以下の影響が発生します：

* ocp_monagentプロセスが異常なため、監視データを収集できず、アラートを報告できません。その結果、ユーザーはシステム内に存在するリスクを検出できません。

* ocp_mgragentプロセスが異常なため、OBServerノードに対する運用保守操作を実行できません。

## 考えられる原因

1. ocp_agentdプロセスは、一般的にホストのメモリ不足やディスク満杯などの理由で予期せず終了することがあります。
2. プログラムにバグがあり、ocp_agentdがプロセスの起動に何度も失敗した後、起動を試みなくなります。

## 解決策

1. ディスクまたはメモリの残量が不足していないか確認します。

   アラートが発生したホストにログインし、以下のコマンドを参照してディスクとメモリの使用状況を確認します。

   ```shell
   # ディスクの状況を確認します。/home/adminが配置されているディスクの使用率が100％に近いかどうか。
   df -B1

   # メモリ使用状況を確認します。残りのメモリが0に近いかどうか。
   free -g
   ```

   * ディスク使用率が100％に近い場合、以下の方法を参照してログをクリーンアップするか、ディスクを拡張してください。

     1. /home/admin/logs/配下でディスク容量を多く消費しているディレクトリを確認します。

        ```shell
        [root]#  du /home/admin/logs/
        4       /home/admin/logs/obproxy/minidump
        32      /home/admin/logs/obproxy/etc
        1261772 /home/admin/logs/obproxy/log
        1261812 /home/admin/logs/obproxy
        1261816 /home/admin/logs/
        ```

     2. そのディレクトリに移動し、古くからアーカイブされたログファイルを削除します。

        ```shell
        [root]# ll /home/admin/logs/obproxy/log
        [root]# cd /home/admin/logs/obproxy/log
        [root]# rm obproxy.67344.log.20210902*
        ```

     3. ocp_agentdプロセスを再起動します。

        ```shell
        [root]# cd /home/admin/ocp_agent
        [root]# python ocp_agent_ctl.py recover
        ```

   * 残りのメモリが0に近い場合、以下の方法を参照してメモリを解放し、その後プロセスを再起動してください。

     1. メモリの解放

        ```shell
        [root]# sync
        [root]# echo 1 > /proc/sys/vm/drop_caches
        [root]# echo 0 > /proc/sys/vm/drop_caches
        ```

     2. ocp_agentdプロセスの再起動。

        ```shell
        [root]# cd /home/admin/ocp_agent
        [root]# python ocp_agent_ctl.py recover
        ```

   * 残存メモリとディスク容量が十分である場合は、他の原因が考えられます。

2. その他の原因については、/home/admin/ocp_agent/log配下のocp_agentd.log、ocp_monagent.error.logおよびocp_mgragent.error.logのログとアラートの詳細情報を収集し、テクニカルサポートに連絡して原因を特定してください。

   * ocp_monagent.error.logプロセス内には、プログラムのクラッシュを引き起こした可能性のあるキーワード「panic」が含まれている場合があります。このキーワードを検索して、テクニカルサポートに提供してください。

     ```shell
     [root]# tail -1000 /home/admin/ocp_agent/log/ocp_monagent.error.log | grep -10 panic
     ```
