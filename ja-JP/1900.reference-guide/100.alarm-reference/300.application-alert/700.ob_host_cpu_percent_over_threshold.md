# ob_host_cpu_percent_over_threshold サーバーCPU利用率がしきい値を超えた場合

## アラートの概要

OBServerノードのCPU利用率がしきい値を超えると、このアラートがトリガーされます。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|---------|---------------|
| 監視指標 | cpu_percent。この指標は、OBServerノードが配置されているサーバーのCPU利用率を示し、利用率がしきい値を超えるとアラートがトリガーされます。 |
| 監視式 | `100 * (1 - sum(rate(node_cpu_seconds_total{mode="idle",@LABELS}[@INTERVAL])) by (@GBLABELS) / sum(rate(node_cpu_seconds_total{@LABELS}[@INTERVAL])) by (@GBLABELS))`</br>監視式では、LABELSを使用して異なるデータを区別します。LABELSには以下のものが含まれます：<li>user</li><li>idle</li><li>system</li><li>iowait</li><li>irq</li><li>nice</li><li>softIRQ</li><li>steal</li>ここで、idleはCPUがアイドル状態にある時間を表し、その他の状態の時間の合計はCPUの使用時間と見なすことができます。 |
| 取得指標 | node_cpu_seconds_total |
| データソース | node_exporterプロセスによって取得されます。  |
| 取得間隔 | 5秒 |

## ルール情報

|    監視指標         | デフォルトしきい値（単位：%） | 持続時間 | 検出周期 | 解消周期 |
|---------------------|------------|-------|-------|------|
| cpu_percent         | 90         | 60秒 | 10秒 | 5分 |

## アラート情報

|   アラートトリガー方法   | アラートレベル | 対象範囲  |
|------------|------|-----|
| 監視指標の式に基づく | 重大   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * 例：alarm_template_id=0:host=xxx.xxx.xxx.xxx サーバーCPU利用率がしきい値を超えた場合

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：CPU利用率 \${value_shown} が \${alarm_threshold} % を超えました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：サーバーCPU利用率がしきい値を超えた場合、CPU利用率 101.0 % が 100.0 % を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、サーバーCPU利用率：\${value_shown}
  * 例：アラート：サーバーCPU使用率が限度を超えました、サーバーCPU使用率：85%

## システムへの影響

CPU使用率が一時的に高くてもシステムへの影響は小さいですが、CPU使用率が継続的に高い状態が続くと、システムのスループットが低下し、リクエストのレイテンシが高くなります。

## 考えられる原因

一般的に以下のシナリオで発生します：

* OBServerノードで複雑なSQLが実行されています。

* ホスト上で実行されている他のプログラムがCPUを過度に占有しています。

## 解決策

1. observerプロセスのCPU占有率が高すぎることが原因かどうかを確認します。

   アラートが発生したOBServerノードで`top`コマンドを実行し、CPUリソースを過度に占有しているプロセスを確認します。

   * observerプロセスである場合、以下のアラートも同時に報告される可能性があります。

     * [ob_cpu_percent_over_threshold OB内部統計のCPU使用率が限度を超えました](../200.ob-alert/1400.ob_cpu_percent_over_threshold.md)

     * [tenant_cpu_percent_over_threshold OBテナントCPU使用率が限度を超えました](../200.ob-alert/2900.tenant_cpu_percent_over_threshold.md)

       OBServerノードで複雑なSQLが実行されると、observerプロセスのCPU占有率が高くなり、このアラートと本記事で説明するアラートが同時にトリガーされる可能性があります。

     まず、上記のアラートを解決するために関連ドキュメントを参照し、その後、本記事で説明するアラートが引き続き報告されるかどうかを観察します。

     * アラートが報告される場合、他の原因の可能性があります。次の手順を実行します。

     * アラートが報告されない場合、問題は解決されています。

   * 他のプロセスの場合、次の手順を実行します。

2. 他のプロセスのCPU占有率が高すぎる可能性があります。

   DBAまたは運用保守担当者に連絡し、業務に依存しないプロセスがある場合は、それを閉じることができます。
