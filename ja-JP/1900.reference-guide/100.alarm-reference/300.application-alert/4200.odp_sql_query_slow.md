# odp_sql_query_slow スロークエリSQL回数が上限を超えた場合

## 警報の概要

OBProxyのログを監視し、スローSQLが存在する場合にアラートを発報します。OBProxyのスローSQLのしきい値は50msです。

## 警報の仕組み

| パラメータ | 値   |
|------|------|
| 監視指標 | slow_sql_query_count。この指標はOBProxyで発生したスローSQLの回数を示します。パラメータ値がしきい値を超えるとアラートがトリガーされます。  |
| 監視式 | なし。  |
| 取得指標 | なし。 |
| 指標の出典 | OBProxyのログ`obproxy_slow.log`を監視し、スローSQLの発生回数を集計します。   |
| 取得サイクル | 5秒   |

## ルール情報

| 監視式 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
|------------|----------|---------|----------|----------|
| slow_sql_query_count | 0 | 0秒 | 60秒 | 5分 |

## アラート情報

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
|--------------|---------|------|
| 監視指標の式に基づく | 重大 | ホスト  |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：alarm_template_id=0:obproxy_cluster=obproxy_ocp:host=xxx.xxx.xxx.xxx:odp_schema=obcluster_test スロークエリSQL回数が上限を超えた場合

* **アラート詳細**

  * テンプレート：OBProxyインスタンス：\${obproxy_cluster}、デプロイメントユニット：\${host}、データベース：\${odp_schema}、アラート：データベースSQL実行でのスロークエリ回数 \${value} がしきい値 \${alarm_threshold} を超えました。
  * サンプル：OBProxyインスタンス：obproxy_ocp、デプロイメントユニット：xxx.xxx.xxx.xxx、データベース：obcluster_test、アラート：データベースSQL実行でのスロークエリ回数 1 がしきい値 0 を超えました。

* **アラートの復旧**

  * テンプレート：アラート：${alarm_name}、スロークエリSQL回数：\${value}
  * サンプル：アラート：スロークエリSQL回数が上限を超えた場合、スロークエリSQL回数：0

## システムへの影響

SQLの実行プロセスはシステムリソースを消費します。スローSQLの数が多すぎると、システムリソースの利用率が上昇し、システムのスループットに影響を与えます。同時に、SQLの実行が業務の期待に応えられないほど遅いため、業務システムにも影響が及びます。

## 考えられる原因

* 最適化が必要なSQLが存在する。例：大規模テーブルの結合クエリ、インデックスの欠落など。
* OBServerノードのリソース不足により、過度のリクエストを処理できず、SQLの実行速度が低下する。

## 解決策

1. OCPのテナント管理ページにある **<UI-TERM key="ocp-v2.SQLDiagnosis.Digest.SqlDiagnosis">SQL 診断</UI-TERM>** 機能を使用して、スローSQLの発生原因を診断します。業務SQLの問題が原因である場合は、インデックスをバインドしたり実行計画をバインドしたりすることができます。
2. OBServerノードのリソース使用率（CPU使用率、IOPSまたはIOレイテンシ、ネットワークスループットなど）が限度を超えていないか確認します。
