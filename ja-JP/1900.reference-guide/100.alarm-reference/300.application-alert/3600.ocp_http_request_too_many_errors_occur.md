# ocp_http_request_too_many_errors_occur OCP HTTPエラーリクエストが多すぎる

## アラートの概要

OCP HTTPの特定のインターフェース（URI）に対して、1秒あたりのエラーリクエスト数が平均して多すぎます。

## アラートの仕組み

| パラメータ | 値    |
|------|------|
| モニタリング指標 | ocp_http_request_error_count。この指標は、OCP HTTPの特定のインターフェースのエラーリクエスト数を示します。指標値がしきい値以上になるとアラートがトリガーされます。 |
| モニタリング式 | ```sum(rate(http_server_requests_seconds_count{status=~"4..\|5..",@LABELS}[60s])) by (@GBLABELS)```  |
| 取得指標 | http_server_requests_seconds_count |
| 指標ソース | OCP Serverの埋め込みデータ。 |
| 取得サイクル | 5秒 |

## ルール情報

| モニタリング指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
|----------|----------|---------|----------|----------|
| ocp_http_request_error_count | 1 | 120秒 | 15秒| 5分 |

## アラート情報

| アラートトリガー方式 | アラートレベル | 対象範囲 |
|--------------|---------|-------|
| モニタリング指標の式に基づく | 警告 | サービス |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * 例：alarm_template_id=0:status=500:uri=root:method=GET OCP HTTPエラーリクエストが多すぎる

* **アラート詳細**

  * テンプレート：[\${alarm_name}] OCP HTTPリクエストのuriは${uri}、メソッドは：${method}で、1秒あたり平均${value_shown}回の失敗が発生しています。
  * 例：[OCP HTTPエラーリクエストが多すぎる] OCP HTTPリクエストのuriは/pre_login_loading、メソッドは：GETで、1秒あたり平均11.416回の失敗が発生しています。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OCP HTTPの1秒あたりの平均エラーリクエスト数：\${value_shown}
  * 例：アラート：OCP HTTPエラーリクエストが多すぎる、OCP HTTPの1秒あたりの平均エラーリクエスト数：0

## システムへの影響

OCPの特定のインターフェースのエラー数が多すぎる場合、そのエラーが発生しているインターフェース（URI）が機能を停止している可能性があります。

## 考えられる原因

* ネットワークが不安定です。
* システム状態異常（メモリ不足、CPU使用率100%）。
* 外部からのリクエスト攻撃。
* 内部リクエストの呼び出しに誤りがあります。

## 解決策

1. アラートの詳細に記載されているリクエストURIに基づき、設定ミスなどによりインターフェースの呼び出しが過剰にエラーとなっていないか確認します。該当する場合は修正します。

2. 通常、人為的操作ではこのような頻度と回数でエラーリクエストが発生することはありません。アラートが発生した場合は、関連するログおよびアラート記録を整理し、管理者に連絡して調査を依頼します。
