# ic_server_connect_failed Inter-Connector サーバー接続失敗

## アラートの概要

マルチVPC（Virtual Private Cloud、専用ネットワーク）モードでは、OCPは複数のVPC上のOceanBaseクラスタを同時に管理する必要があります。OCPがこれらのVPC内の業務にアクセスできるのは、IC-ServerとIC-Agentによって確立されたVPC間のセキュリティチャネルを通じてです。IC-ServerはOCPにVIP（仮想IP）を提供し、他のVPCへのアクセスをプロキシします。

IC-Serverが接続できない場合、このアラートがトリガーされます。

![1217](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/3999600461/p371132.png)

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ       | 値         |
| ---------- | ---------- |
| 監視指標   | ic_server_health。この指標はヘルスチェックインターフェースからのフィードバック結果を示します。指標値が `1` の場合は接続可能、指標値が `0` の場合は接続不可でアラートがトリガーされます。   |
| 監視式       | `min(ic_server_health{@LABELS}) by (@GBLABELS)`    |
| 取得指標   | ic_server_health   |
| 指標ソース   | IC-Serverのヘルスチェックインターフェースにアクセスします。インターフェースURLは `http:// **IP** :8088/ok` です。ここで、IPはアラート監視のホストIPアドレスです。 |
| 取得サイクル   | 5秒     |

## ルール情報

| 監視指標         | デフォルトしきい値 | 持続時間 | アラートサイクル | 解消サイクル |
| ---------------- | -------- | -------- | -------- | -------- |
| ic_server_health | 0        | 120秒     | 15秒    | 5分   |

## アラート情報

| アラートトリガー方式         | アラートレベル | 対象範囲   |
| -------------------- | -------- | ------ |
| 監視指標の式に基づく | サービス停止     | サービス |

## アラートテンプレート

* **アラート概要**

  * テンプレート：OCPノード \${ocp_address} がIC-Server \${ic_server_address} に接続できません
  * 例：OCPノード xxx.xxx.xxx.1 がIC-Server xxx.xxx.xxx.2 に接続できません

* **アラート詳細**

  * テンプレート：OCPノード \${ocp_address} がIC-Server \${ic_server_address} に接続できません
  * 例：OCPノード xxx.xxx.xxx.1 がIC-Server xxx.xxx.xxx.2 に接続できません

* **アラートの復旧**

  * テンプレート：アラート：${alarm_name}、Inter Connector Serverは正常かどうか（アクセス可能かどうか）：\${recover_value}
  * サンプル：アラート：サーバー接続失敗、Inter Connector Serverは正常かどうか（アクセス可能かどうか）：1

## システムへの影響

OCPは、他のVPC内のOceanBaseクラスタおよび関連リソースを運用・管理できません。

## 考えられる原因

* IC-Serverがインストールされているホストに障害が発生し、IC-Serverに接続できない場合。

* ネットワークの問題により、OCPが個々のIC-Serverと接続できない場合。

## 解決策

1. IC-Serverがインストールされているホストにログインし、IC-Server関連のプロセスが正常に動作しているか、ログにエラーがないか確認します。

   1. IC-Serverホストにログインします。次の場合が発生した場合：

      * IC-Serverホストにログインできない場合は、まずホストの障害原因を確認し、ホストが正常にログイン可能であることを確保してください。

      * 正常にログインできる場合は、次の手順を実行します。

   2. 以下のコマンドを実行して、ic-serverプロセスが正常に動作しているか確認します。

      ```shell
      ps -ef|grep ic-server
      ```

      * プロセスが起動していない場合は、`supervisord restart ic-server` コマンドを実行して、このプロセスを再起動します。

      * プロセスが起動している場合は、次の手順を実行します。

   3. 以下のコマンドを実行して、IC-Serverのログ`~/logs/ic-server/server.log`にエラーがないか確認します。

      ```shell
      grep -r "error"
      ~/logs/ic-server/server.log
      ```

      `~/logs/ic-server/server.log` の "\~" は、IC-Serverのデプロイ状況に応じてパスを補完してください。

      * エラーログがある場合は、そのエラーログを参照してトラブルシューティングを行ってください。

      * エラーログがない場合は、次の手順を実行します。

2. OCPが個々のIC-Serverに接続できない原因がネットワークの問題によるものか確認してください。ネットワークの問題のトラブルシューティングについては、[ネットワーク障害のトラブルシューティング](../500.appendix/300.network-troubleshooting.md)を参照してください。

3. 上記の方法でも問題が解決しない場合は、技術サポートにお問い合わせください。
