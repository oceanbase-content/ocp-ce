# system_parameter_not_taken_effect システムパラメータ変更後は再起動が必要

## アラートの概要

OCPの一部のシステムパラメータは、変更後にOCPを再起動しないと変更が有効になりません。OCPの定期巡回検査で、「再起動が必要」とマークされたパラメータが変更されているにもかかわらず再起動が行われていないことが検出された場合、このアラートがトリガーされ、管理者に対してパラメータを有効にするためにOCPサービスを再起動するよう促します。

## アラートの仕組み

| パラメータ | 値 |
| -------- | ---------- |
| モニタリング指標 | N/A   |
| モニタリング式 | N/A |
| 取得指標 | N/A |
| 指標ソース | OCPアプリケーション内部イベント |
| 取得周期 | N/A |

OCP起動時にシステムパラメータをメモリにロードします（システムパラメータを変更するとデータベースの値のみが変更され、メモリ内の値は変更されません）。同時に、OCP内部では定期的な巡回検査タスクが起動し、メモリ内で「再起動が必要」（`needRestart() == true`）とマークされたパラメータを抽出してデータベースと比較します。不一致があるパラメータが存在する場合、そのパラメータが変更されているにもかかわらず再起動によって有効になっていないことを示し、このアラートイベントを生成します。

  * 例：サーバー：xxx.xxx.xxx.xxx、アラート：システムパラメータ変更後は再起動が必要、パラメータ名：[ocp.site.url, server.port]。

## システムへの影響

システムパラメータの変更後に再起動しないと、以下の影響が発生する可能性があります：

* 設定の不整合：データベースに記録されている設定値と実際の運用値が異なるため、運用保守担当者がシステムの動作を誤判断する可能性があります。

* 期待された機能が有効にならない：ポート番号やサイトURLなど、再起動が必要なパラメータの一部が期待通りに動作せず、システム機能に影響を与えています。

## 原因

* 管理者がOCPコンソールまたはAPIを使用して再起動が必要なシステムパラメータを変更しましたが、OCPサービスを再起動していません。

* システムパラメータを一括変更した後、再起動操作を忘れています。

## 解決策

1. アラート情報の確認：アラートに記載されているサーバーIP（host）とパラメータ名（system_parameter）から、有効になるべきパラメータを特定します。

2. パラメータ変更の確認：OCPコンソールのシステムパラメータ管理ページで、変更されたがまだ有効になっていないパラメータを確認し、直ちに再起動が必要かどうか評価します。

3. OCPサービスの再起動：適切な時間帯（業務負荷の低い時間帯を推奨）を選択して、対応するOCPノードのサービスを再起動し、パラメータを有効にします。複数ノードでデプロイされている場合は、すべてのOCPノードを順次再起動する必要があります。

4. 修正結果の検証：再起動完了後、パラメータが期待通りに有効になっていることを確認します。アラートは解消サイクル（300秒）内に自動的にクリアされます。
