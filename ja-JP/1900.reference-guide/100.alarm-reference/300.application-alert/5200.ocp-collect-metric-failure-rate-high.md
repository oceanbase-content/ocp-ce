# ocp_collect_metric_failure_rate_high OCP-Server 采集监控失败率过高

## アラートの概要

OCP-ServerはOCP-Agentのエクスポーターを収集します。収集失敗率がしきい値を超えた場合にこのアラートが生成されます。収集失敗率：収集失敗回数 / 收集回数。

## アラートの仕組み

| パラメータ | 値 |
| -------- | -------- |
| モニタリング指標 | collect_metric_failure_rate。この指標はOCP-Serverの収集監視失敗率を示し、失敗率がしきい値を超えるとアラートがトリガーされます。 |
| モニタリング式 | ```100 * sum(rate(ocp_monitor_collect_request_errors_total{@LABELS}[60s])) by (@GBLABELS) / sum(rate(ocp_monitor_collect_request_duration_ms_count{@LABELS}[60s])) by (@GBLABELS)``` |
| 収集指標 | ocp_monitor_collect_request_errors_total、ocp_monitor_collect_request_duration_ms_count |
| 指標ソース | OCP自己モニタリング。リクエスト`http://OCP-IP:8080/api/v2/actuator/prometheus``で確認。 |
| 収集サイクル | 5秒 |

## ルール情報

| モニタリング式 | デフォルトしきい値（単位：%） | 持続時間 | 検出サイクル | 解消サイクル |
| ---------- | -------- | ------- | -------- | ---------- |
| collect_metric_failure_rate | 10 | 180秒 | 15秒 | 5分 |

## アラート情報

| アラートトリガー方式 | アラートレベル | 対象範囲 |
| ------------ | ------- | ------ |
| モニタリング指標の式に基づく | 警告 | サービス |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:app=OCP OCP-Server 采集监控失败率过高

* **アラート詳細**

  * テンプレート：アラート：${alarm_name}。収集監視失敗率：${value_shown}。
  * サンプル：アラート：OCP-Server 采集监控失败率过高。収集監視失敗率：75.757 %。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}，収集監視失敗率：\${value_shown}
  * サンプル：アラート：OCP-Server 采集监控失败率过高，収集監視失敗率：5 %

## システムへの影響

モニタリングに依存するサービス、例えば、グラフィカルモニタリング、アラート、診断、巡回検査などが影響を受ける可能性があります。例：

1. グラフィカル画面での表示が途絶えたり、モニタリングデータが表示されなくなったりします。
2. アラートが有効にならず、異常発生時にアラートが生成されません。
3. 診断レポートや巡回検査レポートで異常原因が特定できません。

## 考えられる原因

* OCPメタデータベースのテナントリソース不足により、OCPで頻繁にfull GCが発生しています。ドキュメントに従って調査し、適切に拡張してください。詳細は、[MonitorDBリソース](../../../300.deployment-guide/100.deploying-enterprise-ocp/300.deployment/100.planning-resources/300.monitordb-resources.md)を参照してください。

* OCP-Agentのocp_monagentプロセス異常により、そのエクスポーター（API）へのアクセスが異常となります。`/home/admin/ocp_agent/log/monagent.log` のエラーメッセージを確認することで、さらに詳しく確認できます。

* OCP-Serverのログ（ocp.log）を確認し、エラー原因を特定します。ネットワーク上の問題などにより、アクセスタイムアウトが発生する場合があります（APIが1秒以内に応答しない場合、タイムアウトエラーと判定されます）。

* OCP-Agentが収集するデータ量が多すぎて、API応答がタイムアウトします。モニタリングデータが欠落しているホストでコマンドを実行し、具体的にどの程度のモニタリングデータが返されているかを確認します。データ量が多すぎる場合（10,000行でタイムアウトするのは異常です）、OCPバージョン（V4.2.0以降）をアップグレードする必要があります。

  ```shell
  sudo curl -s --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$(cat /home/admin/ocp_agent/run/ocp_monagent.pid).sock http://unix-socket-server/metrics/ob/basic | wc -l
  sudo curl -s --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$(cat /home/admin/ocp_agent/run/ocp_monagent.pid).sock http://unix-socket-server/metrics/ob/extra | wc -l
  ```

## 対処方法

1. リソース不足が原因の場合、ocp_monitorおよびocp_metaテナントを拡張する必要があります。
2. OCP-Agentが原因の場合、monitor_exporter_unavaliable、monagent_log_alarm、obagent_dead、host_unavailableなどの他のアラートが同時に発生することがよくあります。対応するアラートの対処方法を確認し、緊急時にはOCP-Agentの再起動または再インストールを試みることができます。
3. OCP-Agentバージョンをアップグレードします。OCP V4.2.1バージョンでは、診断データ中の0値データがフィルタリングされました。このデータは割合が高い場合があり、収集パフォーマンスに大きな影響を与える可能性があります。
