# binlog_process_dead Binlog Server プロセスが存在しない

## アラートの概要

このアラートは、Binlog Serverプロセスが存在するかどうかを監視し、存在しない場合にアラートを報告します。

## アラートの仕組み

以下の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|------------|-----------|
| 監視指標 | binlog_process_exists。この指標はBinlog Serverプロセスが存在するかどうかを示します。指標値が `1` の場合は存在し、`0` の場合はプロセスが存在せず、アラートがトリガーされます。 |
| 監視式 | ```process_exists{name="logproxy",@LABELS}``` |
| 取得指標 | binlog_process_exists |
| 指標ソース | このアラートの指標ソースはやや特殊で、OCP-Agentが以下のLinuxコマンドを実行してBinlog Serverプロセスの存在をチェックします。<br>`ps -ef\|grep -w logproxy\|grep -v grep\|wc -l` |
| 取得サイクル | 5秒 |

## ルール情報

| 監視指標 | デフォルトしきい値 | 継続時間 | 検出サイクル | 解消サイクル |
|-----------------------|----------|----------|----------|----------|
| binlog_process_exists | 0 | 30秒 | 10秒 | 5分 |

## アラート情報

| アラートトリガー方法 | アラートレベル | 対象範囲 |
|---------------------|----------|--------|
| 監視指標の式に基づく | サービス停止 | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * 例：alarm_template_id=0:binlog_cluster=binlog02-2000005:svr_ip=xxx.xxx.xxx.xxx Binlog Server プロセスが存在しない

* **アラート詳細**

  * テンプレート：Binlogクラスタ：${binlog_cluster}、ホスト：${host}、アラート：${alarm_name}。
  * 例：Binlogクラスタ：binlog02、ホスト：xxx.xxx.xxx.xxx、アラート：Binlog Server プロセスが存在しない。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、Binlog Server プロセスの生存状態：${recover_value}
  * サンプル：アラート：Binlog Server プロセスが存在しません、Binlog Server プロセスの生存状態：1

## システムへの影響

Binlog Server プロセスは Binlog インスタンスの管理を担当しており、単一ノードデプロイメントの場合、Binlog インスタンスの管理機能を失います。

## 考えられる原因

Binlog の MetaDB が利用できません。

## 解決策

1. OCP が Binlog Server プロセスを再起動したかどうか確認します。

   このアラートは、OCP 内のデフォルトの自動 Binlog Server プロセス再起動プランを実行するトリガーとなります。プランが正常に実行されたかどうか、および Binlog Server プロセスが正常に稼働しているかどうかを確認できます。

2. OCP が Binlog Server プロセスの起動に失敗した場合、以下の手順を参照してトラブルシューティングを行います：

   1. Binlog サービスの MetaDB が利用可能かどうか確認します。MetaDB が継続的に利用できない場合、Binlog Server プロセスが異常終了する可能性があります。
   2. Binlog Server プロセスのエラーログ、coredump ファイル、および Binlog Server プロセスの実行ログ `log/logproxy.log` などの情報を収集し、OCP テクニカルサポートに連絡してトラブルシューティングを依頼します。
