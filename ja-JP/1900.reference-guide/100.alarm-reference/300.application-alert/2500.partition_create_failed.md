# partition_create_failed パーティション作成失敗

## アラートの概要

このアラートは、メタデータベース（MetaDBおよびMonitorDBを含む）のパーティションガードタスクがパーティション作成に成功したかどうかを監視し、失敗した場合にアラートを報告します。

## アラートの仕組み

パーティションガードタスクは、ガード対象のテーブルのパーティション管理を行います。このタスクは1時間ごとに実行され、パーティション作成時に失敗するとアラートがトリガーされます。

## ルール情報

| モニタリング指標 | デフォルトしきい値 | 持続時間 | 検出サイクル | 解消サイクル |
| -------- | -------- | -------- | -------- | -------- |
| NA       | NA       | 0秒     | NA      | 1200秒   |

## アラート情報

| アラートトリガー方式 | アラートレベル | 対象範囲 |
| ------------ | -------- | ---- |
| OCP定期タスク | 警告     | サービス  |

## アラートテンプレート

* **アラート概要**

  * テンプレート: \${alarm_target} \${alarm_name}
  * 例: alarm_template_id=0:datasource=Monitordb:table_name=ob_hist_trans_stat_v2 パーティション作成失敗

* **アラート詳細**

  * テンプレート: ${alarm_target} ${alarm_name} パーティション(${partition_name})の作成に失敗しました。結果: ${result}。
  * 例: alarm_template_id=0:datasource=Monitordb:table_name=ob_hist_trans_stat_v2 パーティション作成失敗 パーティション(P20251021)の作成に失敗しました。結果：success。

## システムへの影響

パーティション作成失敗は、指定したパーティションデータの保存に失敗し、データ損失を引き起こす可能性があります。

## 考えられる原因

* データベース全体のパーティション数が上限を超えています。

* 既存のパーティションのパーティション値が新規作成するパーティションのパーティション値より大きいです。

## 対処方法

1. メタデータベースが配置されているサーバーのディスク容量が十分であることを確認します。

   メタデータベースが配置されているサーバーにログインし、`df -h` を実行して /data/1 ディレクトリの使用率を確認します。

   * 使用率が高すぎる場合（95% を超える場合）、`rm -rf ファイル名` コマンドを使用して、そのディレクトリ内の不要なファイルをクリーンアップします。

   * 使用率が正常な場合は、次の手順に進みます。

2. 既存のパーティションのパーティション値が新規作成するパーティションのパーティション値より大きくないか確認します。

   * そのテーブルのパーティションがすべてガーディアンタスクによって作成された場合、一般的にこの問題は発生しません。

   * コマンドラインで手動で作成したパーティションがある場合、このような状況が発生する可能性があります。以下の方法を参考に解決できます：

     1. 以下のコマンドを実行して、そのテーブルのパーティション値を確認し、実際に手動でパーティションを作成した履歴があるかどうかを確認します。

        ```sql
        obclient>show create table ob_hist_sql_audit_stat;
        CREATE TABLE `ob_hist_sql_audit_stat` (
          ...

          ...
         partition by range columns(`end_interval_time`)
        (partition DUMMY values less than (0),
        partition P202106 values less than (
        1625097600000000
        ),
        partition P202107 values less than (
        1627776000000000
        ),
        partition P202108 values less than (
        1630454400000000
        ),
        partition P202109 values less than (
        1633046400000000
        ))
        ```

        実行結果の less than の後の括弧内がパーティション値です。ガーディアンタスクによって作成されたパーティションのサイズは固定されているため、隣接するパーティション間のパーティション値の差も固定されています。差異が異常な場合、手動でパーティションが作成されたことがあり、次の手順を実行する必要があります。

     2. 以下のコマンドを参考に、ガーディアンタスクによって作成に失敗したパーティションを手動で作成します。ただし、パーティション値は、元々ガーディアンタスクによって作成されたパーティションの値以下に設定する必要があります。

        ```sql
        ALTER TABLE metric_table_space_view ADD PARTITION (PARTITION
        P20210902
         VALUES LESS THAN (
        xxxxxxxxxxxxxx
        ));
        ```

        ここで、**P20210902** はパーティション名で、アラートの詳細で確認できます。**xxxxxxxxxxxxxx** はパーティション値です。

        変更が成功したら、OCP上でそのアラートを手動でクリーンアップします。

        今回の手動作成により、今回のパーティション値が次回作成するパーティションの値を上回らないことが保証されます。次回パーティションを作成する際には、このアラートは報告されなくなります。

3. パーティション数が制限を超えていないか確認します。

   以下のコマンドを実行して、メタデータベースのパーティション数を確認します。

   ```sql
   select count(*) from oceanbase.gv$partition where table_id in (select table_id from oceanbase.gv$table where tenant_name = 'ocp_meta24' and database_name = 'ocp_monitor');
   ```

   実行結果が3000を超える場合、パーティション数が多すぎます。以下の方法で解決できます：

   * 以下のコマンドを参考に、不要なテーブルやパーティションを削除します。

     ```sql
     #テーブルを削除します。
     DROP TABLE table_name;

     #パーティションを削除します。ここで、P180625 はパーティション名です。
     alter table metric_table_space_perm drop partition(
     P180625
     );
     ```

   * メタデータベースが旧バージョンのOceanBaseクラスタの場合、2回の日次メジャーコンパクションを実行することでパーティションリソースを解放できます。

     コマンドラインでメジャーコンパクションをトリガーするには、[メジャーコンパクションのトリガー](https://www.oceanbase.com/docs/enterprise/oceanbase-database-cn/V2.2.30/10000000000371936)を参照してください。

パーティションガードタスク関連のテーブルの詳細については、[パーティションガードテーブル](../../../2100.appendix/300.daemon-task-managed-table.md)を参照してください。
