# ocp_remote_server_time_diff_too_large OCPとリモートホストの時刻差が大きすぎる

## アラートの概要

このアラートは、OCPサーバーのクロックとOCPが管理するリモートホストの時刻差を監視し、時刻差が許容範囲を超えた場合に報告します。

## アラートの仕組み

OCP-Serverは毎分1回のタイマーを設定しており、そのタイミングで`clockdiff -o {ip}`コマンドを実行して特定のリモートホストのクロックオフセットをチェックします。オフセットがしきい値を超えた場合にアラートがトリガーされます。しきい値はシステムパラメータ`ocp.host.check.clock-diff.max-diff`で制御され、デフォルトは50ミリ秒です。

| パラメータ | 値 |
| --------- | -------- |
| 監視指標 | clock_diff_milliseconds。この指標はOCPサーバーのクロックとOCPが管理するリモートホストの時刻差を示し、指標値がしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | ```max(abs(clock_diff_milliseconds{@LABELS})) by (@GBLABELS)``` |
| 取得指標 | clock_diff_milliseconds |
| 指標の出典 | OCP Server自身の統計から取得します。ローカルのcompute_hostテーブル内の各ホストに対してclockdiffを実行し、その結果に問題がある場合にアラートを報告します。      |
| 取得周期 | 5秒 |

## ルール情報

| 監視指標 | デフォルトのしきい値（単位：ミリ秒） | 持続時間 | 検出周期 | 解消周期 |
|----------|-----------------------|----------|---------|---------|
| clock_diff_milliseconds   | 50          | 30 秒  | 15 秒 | 5 分钟 |

## アラート情報

|   アラートのトリガー方法   | アラートレベル | 対象範囲  |
|------------|------|-----|
| 監視指標の式に基づく | 悪質   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：alarm_template_id=0:host=xxx.xxx.xxx.xxx OCPとリモートホストの時刻差が大きすぎる

* **アラート詳細**

  * テンプレート：OCPとリモートホスト(${host}、所属クラスタ：${ob_cluster_name})の時刻差が大きすぎます。現在の時刻差${value_shown}はしきい値${alarm_threshold}ミリ秒を超えています。
  * サンプル：OCPとリモートホスト(xxx.xxx.xxx.xxx、所属クラスタobcluster-1)の時刻差が大きすぎます。現在の時刻差1400ミリ秒はしきい値50ミリ秒を超えています。

* **アラートの回復**

  * テンプレート：\${alarm_target}、ホストとOCP-Serverのクロックオフセット：\${value_shown}
  * 例：OCPとリモートホストの時刻差が大きすぎます。現在の時刻差は1400ミリ秒で、許容範囲は最大50ミリ秒です。

## **システムへの影響**

* RPCリクエストの送信に失敗します。

* 権限付与に失敗する可能性があります。

* 一部の監視指標のクエリが異常になることがあります。

## 考えられる原因

一般的な原因は以下のとおりです：

* OCPサーバーのクロックが異常です。

* リモートホストのクロックが異常です。

## 解決策

1. OCPサーバーのクロックが正常かどうか確認します。

   OCP上で複数のこのアラートが同時に報告されていないか確認します。

   * いいえの場合は、手順2に進みます。

   * はいの場合、OCPサーバーのクロックが異常です。

     まず、OCPサーバーのクロックが正常であることを確認することを推奨します。

     OCPサーバーとクロックソース間のクロック同期に問題が発生している可能性があります。[host_ntp_offset_too_large サーバーとクロックソースのオフセットが大きすぎる](../300.application-alert/2000.host_ntp_offset_too_large.md) を参照して調査してください。

     5分待って、このアラートが引き続き報告されるかどうか観察します。

2. OCPが管理するホストのクロックに異常がないか確認します。

   * OCPが管理するホストが利用不可または接続できない可能性があります。その場合、以下のアラートが同時に報告されます。まず、ドキュメントを参照して以下のアラートを解決し、手動でホストとクロックソースのクロック同期をトリガーした後、5分待って、アラートが依然として報告されるかどうか観察します。

     * [ob_cannot_connected OBサーバーに接続できません](../200.ob-alert/100.ob_cannot_connected.md)

     * [ob_cluster_exists_inactive_server OBクラスタに非稼働OBServerノードが存在します](../200.ob-alert/400.ob_cluster_exists_inactive_server.md)

   * OCPが管理するホストとクロックソース間のクロック同期に異常がある可能性があります。[host_ntp_offset_too_large サーバーとクロックソースのオフセットが大きすぎる](../300.application-alert/2000.host_ntp_offset_too_large.md) を参照して、問題を特定し、対処してください。

   * OCPサーバーとホストのクロックに異常がなく、単にクロックが同期していない場合は、手動でクロック同期を直接トリガーできます。

     このサーバーにインストールされているクロック同期サービスに応じて、以下のコマンドのいずれかを実行してください。

     ```shell
     #NTPサービスを使用する場合は、このコマンドを使用して同期します。xxx.xxx.xxx.xxx はクロックソースのIPアドレスを表します。ご自身で設定してください。
     ntpdate xxx.xxx.xxx.xxx

     #Chronyサービスを使用する場合は、このコマンドを使用して同期します。時刻ソースが/etc/chrony.confファイルで設定されていることを確認してください。
     chronyc -a makestep
     ```
