# host_ntp_service_not_exist サーバーの時刻同期サービスが存在しません

## アラートの説明

OCPが管理するサーバーに時刻同期サービス（ChronyまたはNTP）がない場合にこのアラートがトリガーされます。

## アラートの仕組み

次の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|-------|----------------|
| 監視指標 | ntp_service_exist、ntp_service_available。ここで：<li>ntp_service_exist指標は時刻サービスの存在チェック結果を示します。指標値が`1`の場合は存在、`0`の場合は存在しないことを意味します。</li><li>ntp_service_availableは時刻サービスが利用可能かどうかを示します。指標値が`1`の場合は利用可能、`0`の場合は利用不可を意味します。</li>いずれかの指標値が`0`の場合、アラートがトリガーされます。   |
| 監視式 | <li>ntp_service_exist：`max(process_exists{name="ntpd",@LABELS}) by (@GBLABELS) + max(process_exists{name="chronyd",@LABELS}) by (@GBLABELS)`</li><li>ntp_service_available：`min(ntp_service_available{@LABELS}) by (@GBLABELS)`</li>   |
| 取得指標 | ntp_service_exist、ntp_service_available |
| 指標ソース | このアラートの指標ソースは特殊で、OCP-Agentが`pgrep chronyd`コマンドを使用してローカルの時刻同期サービスをチェックします。これには、Chronyサービスが存在するかどうかをチェックする`pgrep ntpd`とNTPサービスが存在するかどうかのチェックが含まれます。デフォルトでは、ローカルで使用されているのはChronyサービスであるため、OCP-AgentはChrony、次にNTPの順で時刻同期サービスの存在をチェックします。  |
| 取得周期 | 5秒 |

## ルール情報

| 監視指標 | デフォルトしきい値 | 持続時間 | チェック周期 | 解消周期 |
|------------------------|---------|----------|----------|----------|
| <li>ntp_service_exist</li><li>ntp_service_available</li> | ntp_service_exist == 0 or ntp_service_available == 0   | 0秒   | 10秒 | 5分 |

| アラートのトリガー方法 | アラートレベル | 対象範囲  |
|------------------|---------|-------|
| 監視指標の式に基づく | 極めて深刻 | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：alarm_template_id=0:host=xxx.xxx.xxx.xxx サーバーの時刻同期サービスが存在しません

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。サーバーの時刻同期サービス（ntpまたはchrony）が存在しません。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：サーバーの時刻同期サービスが存在しません。サーバーの時刻同期サービス（ntpまたはchrony）が存在しません。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、サーバーの時刻同期サービスが存在しません：\${recover_value}
  * サンプル：アラート：サーバー時刻同期サービスが存在しません、サーバー時刻同期サービスが存在しません：1

ここで、\${alarm_target} はアラートが発生したオブジェクトを表し、形式は svr_ip=xx.xx.xx.xx です。

## システムへの影響

一定期間稼働すると、サーバー間で時刻の不整合が発生し、結果としてOceanBaseクラスタが利用不能になる可能性があります。

## 考えられる原因

* サーバーに時刻同期サービス（ChronyまたはNTP）がインストールされていません。

* サーバーの時刻同期プロセス（chronydまたはntpd）が異常終了しました。

## 解決策

1. 以下のコマンドを実行して、サーバーに時刻同期サービス（ChronyまたはNTP）がインストールされていないか確認します。

   ```shell
   rpm -qa|grep chrony       #Chronyサービスがインストールされているか確認
   rpm -qa|grep ntp            #NTPサービスがインストールされているか確認
   ```

   * 関連するバージョン情報が返された場合、そのサービスは既にインストールされています。手順2に進んでください。

   * 情報が返されない場合、そのサービスはインストールされていません。ChronyとNTPの両方のサービスもインストールされていない場合は、まず時刻同期サービスをインストールしてください。

     ChronyとNTPのサービスのインストールと設定については、インターネット上で共有されている事例を参照してください。ここでは簡潔に説明します。

     1. 以下のコマンドを実行して時刻同期サービスをインストールします。ChronyとNTPのどちらか一方をインストールすればよいです。

        ```shell
        yum install -y chrony             #Chronyサービスをインストール
        yum install -y ntp                   #NTPサービスをインストール
        ```

     2. 以下のコマンドを実行して時刻同期サービスを起動します。

        ```shell
        systemctl start chronyd        #Chronyサービスを起動
        systemctl start ntpd             #NTPサービスを起動
        ```

     3. アラートを手動でクリアした後、アラートが引き続き報告されるかどうか観察します。引き続き報告される場合は、手順3を実行してください。

2. 以下のコマンドを実行して、時刻同期プロセス（chronydまたはntpd）が異常終了していないか確認します。

   ```shell
   systemctl status chronyd       #Chronyサービスの状態を確認
   systemctl status ntpd            #NTPサービスの状態を確認
   ```

   * 実行状況がactive（running）の場合は、手順3に進みます。

   * 実行状況がinactive（dead）の場合は、クロック同期サービスに異常が発生しています。以下の方法でサービスを再起動してください。

     ```shell
     systemctl restart chronyd        #Chronyサービスの再起動
     systemctl restart ntpd             #NTPサービスの再起動
     ```

     サービスを再起動した後、アラートを手動でクリアし、アラートが引き続き報告されるかどうか確認します。それでも報告される場合は、手順3を実行してください。

3. その他の原因については、テクニカルサポートにお問い合わせいただき、原因を特定してください。
