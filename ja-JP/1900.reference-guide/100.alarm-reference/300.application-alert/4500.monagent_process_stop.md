# monagent_process_stop ocp_monagentプロセスの停止

## アラートの概要

ocp_monagentプロセスが停止していないかどうかを監視します。

OCP-Agentプロセスは、OceanBase関連コンポーネントのプロセス起動時刻のタイムスタンプを監視します。タイムスタンプに変化があった場合、プロセスが停止または再起動したとみなされます。このアラートは、プロセスが一時的に停止したことを示すものであり、長時間停止していることを示すものではありません。プロセスが長時間停止している場合は、他の状態に関するアラートが発報されます。

対象プロセスは以下の通りです：

* observer：アラート項目はobserver_process_stopです
* obproxy：アラート項目はobproxy_process_stopです
* obproxyd.sh：アラート項目はobproxyd_process_stopです
* ocp_agentd：アラート項目はagentd_process_stopです
* ocp_mgragent：アラート項目はmgragent_process_stopです
* ocp_monagent：アラート項目はmonagent_process_stopです

## アラートの仕組み

| パラメータ | 値 |
|---------|----------|
| 監視指標 | monagent_boot_time_delta_seconds。この指標はocp_monagentプロセスの起動時刻のタイムスタンプの変化を示します。指標値がしきい値を超えた場合、プロセスが停止したとみなし、アラートをトリガーします。 |
| 監視式 | ```max(delta(process_boot_time_seconds{name="ocp_monagent",@LABELS}[@INTERVAL])) by (@GBLABELS)```  |
| 取得指標 | process_boot_time_seconds         |
| 指標の出典 | システムのブートタイムに、プロセスがシステム再起動から経過した時間差を加算した値が、プロセスの起動時刻となります。ここで、システムのブートタイムは、コマンド`cat /proc/stat`の実行結果におけるbtime値に相当します。プロセスがシステム再起動から経過した時間差は、コマンド`cat /proc/pid/stat`の実行結果の22列目の数値を100で割った値に相当します。  |
| 取得間隔 | 5秒 |

## ルール情報

| 監視指標 | デフォルトしきい値（単位：秒）  | 持続時間 | 検出サイクル | 解消サイクル |
|----------|----------------------|----------|----------|---------|
| monagent_boot_time_delta_seconds   | 10   | 0秒      | 20秒    | 5分     |

## システムへの影響

ocp_monagentは、OCP-Agentが監視データを収集するプロセスです。

1. プロセスが停止した後、すぐにデーモンプロセス（ocp_agentd）によって再起動された場合（最大3回の再起動試行）、OCPの業務への影響はほとんどありません。数秒間の監視データと、プロセス内部キャッシュされた監視データが失われ、キャッシュの再構築が必要になります。このキャッシュはOBServerの内部テーブルからクエリして取得します。プロセスが頻繁に再起動すると、キャッシュの実装によりキャッシュミスが発生し、OBServerに一定の負荷がかかります（通常、監視データ収集のQPSは20以内です）。

2. プロセスが停止した後、再起動されなかった場合、大量の監視データが欠落し、監視データに依存するアラートも無効になります（一部の状態系アラートは引き続き作動する可能性があります）。この場合、OBServerに問題が発生した場合、監視の履歴記録を保持できなくなります。

## 考えられる原因

* プロセスのメモリが2GiBを超えると、デーモンプロセスによって再起動されます。考えられる原因は以下の通りです：

  * QPSが高いため、収集データがメモリを多く占有する。
  * プロセスのメモリリーク。

* プロセスのBUGにより、実行エラーが発生し、予期せず終了する。

* 監視設定が誤っており、`/home/admin/ocp_agent/conf/module_config` にカスタム設定が存在し、構文（yaml）エラーがある。

* 予定されたアクティブ運用保守により、画面上でagentを再起動した場合。

## 対処方法

1. オペレーティングシステムの管理者ユーザーまたは `sudo` 権限を持つユーザーでOBServerサーバーにログインします。

2. `/home/admin/ocp_agent/bin/ocp_agentctl config -u monagent.limit.memory.quota=xxx` を実行して、ocp_monagentプロセスが使用できるメモリの上限を変更します。

3. ocp_agentを再起動します。

具体的な例は以下の通りです：

```json
-- ocp_monagentプロセスが使用できるメモリの上限を変更する
/home/admin/ocp_agent/bin/ocp_agentctl config -u monagent.limit.memory.quota=10240MB
{"successful":true,"message":"success","error":""}
-- 再起動コマンド
systemctl restart ocp_agent
-- 以下のコマンドを使用して、変更が有効になっているか確認できます
cat /sys/fs/cgroup/memory/ocp_agent/ocp_monagent/memory.limit_in_bytes
10737418240
cat /home/admin/ocp_agent/conf/config_properties/common_meta.yaml | grep -A4 monagent.limit.memory.quota
    - key: monagent.limit.memory.quota
      value: 10240MB
      valueType: string
      encrypted: false
      configVersion: "2025-09-24T16:51:33.747+08:00"
```
