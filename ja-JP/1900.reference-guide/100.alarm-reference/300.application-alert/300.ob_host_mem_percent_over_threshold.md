# ob_host_mem_percent_over_threshold サーバーのメモリ使用率がしきい値を超えた場合

## アラートの概要

OBServerノードが配置されているサーバーの物理メモリ全体の使用率がしきい値を超えた場合に、このアラートがトリガーされます。

## アラートの仕組み

以下の表は、このアラートの監視ロジックに関連する主要なパラメータを示しています。

| パラメータ | 値 |
|-------|-----------|
| 監視指標 | memory_percent。この指標はOBServerノードのメモリ使用率を表し、使用率がしきい値を超えた場合にアラートがトリガーされます。     |
| 監視式 | 内部ビューから収集。収集SQL：```(1 - (avg(node_memory_MemFree_bytes{@LABELS}) by (@GBLABELS) + avg(node_memory_Cached_bytes{@LABELS}) by (@GBLABELS) + avg(node_memory_Buffers_bytes{@LABELS}) by (@GBLABELS) + avg(node_memory_SReclaimable_bytes{@LABELS}) by (@GBLABELS)) / avg(node_memory_MemTotal_bytes{@LABELS}) by (@GBLABELS)) * 100'```    |
| 収集指標 | node_memory_MemFree_bytes、node_memory_Cached_bytes、node_memory_Buffers_bytes、node_memory_SReclaimable_bytes、node_memory_MemTotal_bytes     |
| データソース | このアラートの指標ソースは比較的特殊で、OCP-Agentがnode_exporterを通じて監視データを収集します。    |
| 収集周期 | 5秒       |

## ルール情報

|   監視指標         |     デフォルトしきい値（単位：%）     | 持続時間 | アラート周期 | 解消周期 |
|---------------------|----------|------|------|------|
| memory_percent     | <li>memory_percent > 95</li><li>memory_percent > 97</li>   | 0秒  | 10秒 | 5分 |

## アラート情報

|   アラートトリガー方法   | アラートレベル | 対象範囲  |
|-----------------|----------|--------|
| 監視指標の式に基づく | <li>memory_percent > 95：重大</li><li>memory_percent > 97：サービス停止</li>   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * 例：alarm_template_id=0:host=xxx.xxx.xxx.xxx サーバーのメモリ使用率がしきい値を超えた場合

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：\${alarm_name}。メモリ使用率 \${value_shown} が \${alarm_threshold} % を超えました。
  * 例：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：サーバーのメモリ使用率がしきい値を超えた場合。メモリ使用率 91 % が 90 % を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、サーバーのメモリ使用率：\${value_shown}
  * 例：アラート：サーバーのメモリ使用率が上限を超えました、サーバーのメモリ使用率：85%

## **システムへの影響**

サーバーのメモリが不足している場合、OBServerノードは正常に動作できません。

## **考えられる原因**

* observerプロセス以外のプロセスが他のメモリ集約型タスクを実行しています。

* OBServerノードの異常な動作によるものです。例：500テナントのメモリ使用量が上限を超えている場合など。

## **対処方法**

1. OBServerノードの状態が正常であることを確認します。

   クラスタの**<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">総覧</UI-TERM>**ページの**<UI-TERM key="ocp-v2.Component.OBServerList.ObserverList">OBServerリスト</UI-TERM>**でそのサーバーの状態を確認するか、そのOceanBaseクラスタのsysテナントに接続して以下のSQLステートメントを実行します。

   ```sql
   select status from __all_sever where svr_ip='your server ip';
   ```

   * 状態がinactiveの場合、observerプロセスの再起動を試みます。

   * 状態が「実行中」の場合は、他の問題です。次の手順に進んでください。

2. 上限を超えたメモリ使用量が日常業務によるものかどうかを確認します。

   OCPのホスト画面で、アラートが発生したOBServerノードのホストを見つけて詳細ページに移動し、**監視 \> ホストリソース**を選択します。この画面でメモリの折れ線グラフを確認します。

   * アラート時点でメモリ使用量が急激に上昇している場合、日常業務によるものではありません。次の手順に進んで調査を続けてください。

   * アラート時点でメモリ使用量が緩やかに上昇している場合、日常業務によるものです。

     [OBServerノードの交換](../../../600.cluster-functions/600.manage-an-observer/500.replace-observer.md)を参照し、メモリ容量の大きいOBServerノードに交換してください。

3. 以下のコマンドラインを実行し、メモリ使用量が多いプロセスを確認します。

   ```shell
   #メモリ使用量が最も高い上位5つのプロセスを、使用率の高い順に並べ替える
   ps -o %mem,pid,cmd  -ax | sort -rn | head -5
   ```

   * observerプロセス以外のプロセスがメモリを過剰に使用している場合、該当プログラムのメモリ使用量が高い原因を分析します。

     業務に影響しない場合、まずメモリを過剰に使用しているプロセスを停止できます。

   * observerプロセスがメモリを過剰に使用している場合、OBServerノードの異常な動作が原因である可能性があります。

     この場合、[ob_tenant500_mem_hold_over_threshold OB 500テナントのメモリ使用量が上限を超えています](../200.ob-alert/2500.ob_tenant500_mem_hold_over_threshold.md) のアラートが同時に報告されることがよくあります。まずはそのアラートを解決してください。5分後に本節のアラートが自動的にクリアされるかどうか観察してください。
