# host_agent_res_memory_over_threshold サーバーエージェントメモリ上限超過

## アラートの概要

エージェントの常駐メモリがしきい値を超えた場合に、このアラートがトリガーされます。

エージェントサービスは、監視エージェント（ocp_monagent）と運用エージェント（ocp_mgragent）に分かれており、OCPがOceanBaseデータベースを管理・監視するための重要なツールです。

## アラートの仕組み

| パラメータ   |    値       |
|---------|------------|
| 監視指標  | host_agent_resident_memory_gb。この指標はエージェントプロセスの常駐メモリを表し、エージェントプロセスのメモリがしきい値を超えた場合にアラートがトリガーされます。 |
| 監視式 | ```max(process_resident_memory_bytes{@LABELS}) by (@GBLABELS) / 1073741824```     |
| 取得指標  | process_resident_memory_bytes   |
| 指標ソース  | Prometheusが提供するプロセス監視に依存し、プロセス自身の監視から取得します。具体的には：<li>運用エージェント：`http://localhost:62888/metrics/stat`</li><li>監視エージェント：`http://localhost:62889/metrics/stat`</li>   |
| 取得間隔  | 5秒     |

## ルール情報

|         監視指標      | デフォルトしきい値（単位：GiB） | 持続時間 | 検出周期 | 解消周期 |
|-----------------------|--------|--------|---------|---------|
| host_agent_resident_memory_gb | 1.5  | 0秒    | 20秒    | 5分     |

## アラート情報

|   アラートトリガー方法   | アラートレベル | 対象範囲  |
|------------|----------|--------|
| 監視指標の式に基づく | 警告   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:host=xxx.xxx.xxx.xxx:process=ocp_monagent サーバーエージェントメモリ上限超過

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：エージェントプロセス：\${process}、常駐メモリ \${value_shown} が制限 \${alarm_threshold} GiB を超えました。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：エージェントプロセス：ocp_monagent、常駐メモリ 1.6 GiB が制限 1.5 GiB を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、サーバーエージェントの常駐メモリサイズ：\${value_shown}
  * サンプル：アラート：サーバーエージェントのメモリが上限を超えました。サーバーエージェントの常駐メモリサイズ：1.0 GiB

## システムへの影響

エージェントプロセスは、OCPがOceanBaseデータベースの運用・監視を行うための重要なツールであり、その安定性は極めて重要です。エージェントがシステムリソースを過度に消費すると、OceanBaseデータベースの動作に影響を与えます。

例えば、エージェントプロセスがメモリを過剰に占有すると、OceanBaseデータベースのメモリ不足を引き起こします。

## 考えられる原因

エージェントの想定メモリ使用量は1GB以内であるべきです。メモリ使用量が過多になる場合、考えられる原因は以下の通りです：

* プログラムにリソースリークが存在する場合。例えば、メモリリークやその他のリソースリーク（ファイルハンドルのリーク、ゴルーチンのリークなど）が発生している場合です。

* プロセスのリソース使用が不合理であることによる問題。

* 監視エージェントがSQLを実行してデータを収集する際、OceanBaseデータベースが異常に停止し、リソースが滞留してメモリ回収が適時に行われないことによる問題。

## 解決策

アラートが発生した場合、アラートの詳細を確認し、エージェントが占有するメモリを確認します。

* メモリ使用量が過大（10GBを超える）場合は、OceanBaseデータベースコンポーネントの正常な動作に影響を与えないよう、直ちにエージェントプロセスを再起動してください。

* エージェントが占有するメモリが許容範囲内（例えば2GB以内）の場合、OceanBaseデータベースの動作に一時的な影響はありません。以下の操作を実行できます：

  1. 環境コンテキスト情報を保存した後、直ちにエージェントを再起動します。

  2. 環境コンテキスト情報を運用保守担当者に提供します。情報には以下が含まれます：

     * 現在のプロセスが占有するメモリ、親子プロセスが占有するメモリ（ocp_agentdは現在のプロセスの親プロセスです）。

     * 現在のプロセスのメモリパフォーマンス分析ファイル。

       ```sql
       PID=$(cat /home/admin/ocp_agent/run/ocp_monagent.pid)
       SOCKET=$PID
       # ゴルーチンのパフォーマンスデータ
       curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$(cat /home/admin/ocp_agent/run/ocp_monagent.pid).sock http://localhost/debug/pprof/goroutine?debug=1 --output /tmp/goroutine.txt
       # CPUパフォーマンスサンプリングデータ
       curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$(cat /home/admin/ocp_agent/run/ocp_monagent.pid).sock http://localhost/debug/pprof/profile?seconds=30 --output pprof.profile.gz
       # メモリサンプリングデータ
       curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$(cat /home/admin/ocp_agent/run/ocp_monagent.pid).sock http://localhost/debug/pprof/heap --output pprof.heap.gz
       ```
