# ob_host_invalid_disk_exists OBServerに不良ディスクが存在する

## アラートの概要

ディスクに不良セクターが発生すると、OBServerはその障害（OBServerのデータディスクまたはログディスク）を検出し、ディスク障害としてマークします。

* 不良ディスクの検出は、OBServer内で参照カウントを持つブロックにのみ適用されます。ddコマンドで破損したのがデータブロックではない場合、不良ディスク検出ではこの破損ブロックは検出されません。
* 不良ディスクの検出は一定のリソースを消費するため、リソース消費を抑えるために、書き込みから2日以上経過したブロックのみを検査します。

## アラートの仕組み

| パラメータ   | 値     |
| -------- | -------- |
| モニタリング指標 | ob_disk_invalid_count。この指標はOBServerに不良ディスクが存在するかどうかを示し、値がしきい値を超えた場合にアラートがトリガーされます。 |
| モニタリング式 | ```sum(ob_disk_invalid_count{@LABELS}) by (@GBLABELS)```  |
| 取得指標 | ob_disk_invalid_count |
| 指標の出典 | 内部ビューから取得。取得SQL：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ count(1) as cnt from __all_virtual_disk_stat where is_disk_valid = 0 and svr_ip = ? and svr_port = ?``` |
| 取得サイクル | 5秒 |

## ルール情報

|        モニタリング指標        | デフォルトしきい値  | 持続時間 | アラートサイクル | 解消サイクル |
|------------------------|-----------|-------|-------|------|
| ob_disk_invalid_count  | 0         | 0秒    | 20秒    | 5分    |

| アラートのトリガー方法 | アラートレベル | 対象範囲 |
| ------------ | ------- | ------ |
| モニタリング指標の式に基づく | 重大 | ホスト |

## システムへの影響

ディスクの不良が検出されると、OBServerは自動的に終了します。考えられる影響：

1. 不良ディスクノードの業務リクエストが中断されます。過半数が保たれている限り、OBServerは引き続きサービスを正常に提供できます。
2. 可用性が低下します。例えば、3ノードのOceanBaseクラスタが2ノードのクラスタになると、可用性が下がります。この場合は、問題を速やかに修復するか、利用可能なノードを追加する必要があります。

## 考えられる原因

一般的な原因はありません。

## 解決策

1. ディスクの不良原因を確認できます：

   ```sql
   select * from __all_virtual_bad_block_table where svr_ip = ? and svr_port = ?
   ```

2. OBServerのログにキーワード`error occours on data disk or slog disk`が含まれていないか確認します。この関連ログアラートが生成されます。

3. 不良ディスクが発生すると、OBServerは自動的に終了します。ディスクの不良ブロックを修復してから、OBServerを再起動する必要があります。
