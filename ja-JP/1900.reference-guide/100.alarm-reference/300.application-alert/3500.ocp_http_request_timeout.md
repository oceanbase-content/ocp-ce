# ocp_http_request_timeout OCP HTTPインターフェースリクエストタイムアウト

## アラートの概要

OCP HTTPインターフェースのリクエスト遅延が長すぎ、平均リクエスト時間が5秒を超えた場合にアラートが発生します。

## アラートの仕組み

| パラメータ | 値 |
|------|------|
| モニタリング指標 | ocp_http_request_duration_seconds。この指標はOCP HTTPインターフェースリクエストのタイムアウト時間を示し、パラメータ値がしきい値以上の場合にアラートがトリガーされます。 |
| 指標ソース | OCP Serverの埋め込みデータ。 |
| 収集指標 | http_server_requests_seconds_sum、http_server_requests_seconds_count  |
| モニタリング式 | ```sum(rate(http_server_requests_seconds_sum{status="200",uri!~"/api/v2/software-package.*\|/api/v2/object-storage.*\|/api/v2/overview/status.*\|root",@LABELS}[60s])) by (@GBLABELS) / sum(rate(http_server_requests_seconds_count{status="200",uri!~"/api/v2/software-package.*\|/api/v2/object-storage.*\|/api/v2/overview/status.*\|root",@LABELS}[60s])) by (@GBLABELS)```    |
| 収集サイクル | 5秒 |

## ルール情報

| モニタリング指標 | デフォルトしきい値(単位：秒) | 持続時間 | 検出サイクル | 解消サイクル |
|----------|---------------------|----------|----------|---------|
| ocp_http_request_duration_seconds | 5 | 120秒 | 15秒 | 5分 |

## アラート情報

| アラートトリガー方式 | アラートレベル | 対象範囲 |
|--------------|---------|-------|
| モニタリング指標の式に基づく | 警告  | サービス |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：alarm_template_id=0:uri=/api/v2/time:method=GET OCP HTTPインターフェースリクエストタイムアウト。

* **アラート詳細**

  * テンプレート：[\${alarm_name}] OCP HTTPインターフェースのuriは${uri}、メソッドは：${method}、リクエスト時間${value_shown}が長すぎます。
  * サンプル：[OCP HTTPインターフェースリクエストタイムアウト] OCP HTTPインターフェースのuriは/api/v2/time、メソッドは：GET、リクエスト時間11秒は長すぎます。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OCP HTTPリクエスト時間：\${value_shown}
  * サンプル：アラート：OCP HTTPインターフェースリクエストタイムアウト、OCP HTTPリクエスト時間：3秒

## システムへの影響

OCPのAPIリクエストが遅くなり、ユーザーエクスペリエンスに影響を与えます。重症の場合はシステム機能に影響します。

## 考えられる原因

* ネットワークが不安定です。
* システム状態異常（メモリ不足、CPU使用率100%）。
* 業務コードが非効率的です。

## 解決策

1. 予想されたネットワークの変動やネットワーク遅延が原因である場合は、チェックのしきい値を引き上げることができます。

2. 遅延が大きすぎるエラーが頻繁に発生する場合。

   1. CPUサーバーの状態を確認し、CPUやメモリの状況が正常かどうかを確認します。実際の状況に応じて、適時調整できます。

   2. サーバーの状態はすべて正常でもリクエスト処理時間が依然として長い場合は、管理者に連絡し、ログを確認してインターフェースにパフォーマンス問題がないか調査してもらいます。
