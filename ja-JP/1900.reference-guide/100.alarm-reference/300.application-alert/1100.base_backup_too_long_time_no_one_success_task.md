# base_backup_too_long_time_no_one_success_task データバックアップが長時間にわたり成功しない場合

## アラートの概要

このアラートは、OceanBaseクラスタで長時間データバックアップが成功していない場合に発報されます。

## アラートの仕組み

OCP-Serverは毎分定期的なチェックタスクを設定しており、データバックアップが長時間成功しない場合にアラートをトリガーします。これには論理バックアップと物理バックアップが含まれます。また、直近の成功したデータバックアップタスクがn日前に行われた場合、nが閾値を超えるとアラートが発報されると理解することもできます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>アラートの閾値は<code>ocp.backup.alarm.base-backup-last-finished-threshold</code>パラメータで制御され、デフォルトは9日間です。また、バックアップポリシーの<strong>アラート閾値設定</strong>にある<strong>成功データバックアップなしのアラート日数</strong>でアラートの閾値を設定することもできます。</p>
</main>

* **アラート詳細**

  * テンプレート: クラスタ：${ob_cluster_name}[${ob_cluster_id}]、テナント：${tenant_name}、ホスト：${host}、アラート：${no_success_days_threshold}日間データバックアップが成功せず、最終成功日時：${last_success_time}、現在時刻：${current_time}。
  * サンプル: クラスタ：obcluster-1[1006]、テナント：tenant_A、ホスト：xxx.xxx.xxx.xxx、アラート：9日間データバックアップが成功せず、最終成功日時：2020-01-05 02:00:00、現在時刻：2020-01-15 01:00:00。

## システムへの影響

データ復元が遅延し、データの復元可能性にも影響を与える可能性があります。

## 考えられる原因

* 最近の手動バックアップタスクが失敗しました。

* 定期スケジュールされたバックアップタスクが失敗しました。

## 対処方法

* バックアップタスクが失敗しました。

  バックアップタスクのエラーメッセージを確認し、必要に応じてログを詳しく調査してエラーの原因を特定します。

  1. OCPクラウドプラットフォームにログインし、**クラスタ概要**ページの**<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>**から、確認したいクラスタ名をクリックします。

  2. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.src.constant.compute.BackupAndRestoration">バックアップと復元</UI-TERM>**をクリックします。

  3. 最近のデータバックアップタスクが失敗したかどうかを確認します。

     * 失敗した場合は、タスクの右側をクリックして原因を確認できます。

     * 最近データバックアップタスクがない場合は、バックアップスケジュールタスクの失敗の可能性のある原因に従って対処する必要があります。

* バックアップスケジュールタスクが失敗しました：

  1. OCPクラウドプラットフォームにログインし、**クラスタ概要**ページの**<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>**から、確認したいクラスタ名をクリックします。

  2. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.BackupAndRestoration">バックアップと復元</UI-TERM>**をクリックします。

  3. バックアップ・リストアメニューに対応するページで、バックアップスケジュール履歴の後ろにある**<UI-TERM key="ocp-v2.Detail.Report.ViewReports">表示</UI-TERM>**ボタンをクリックし、最近のスケジュールタスクに失敗がなかったかどうかを確認します。タスクのログを確認して原因を確定できます。
