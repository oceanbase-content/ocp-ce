# host_agent_open_fd_count_over_threshold サーバーエージェントのファイルハンドル数がしきい値を超えた

## アラートの概要

エージェントのファイルハンドル数がしきい値を超えた場合に、このアラートがトリガーされます。

エージェントサービスは、監視エージェント（ocp_monagent）と運用エージェント（ocp_mgragent）の2つに分かれており、OCPがOceanBaseデータベースを管理・監視するための重要なツールです。

## アラートの仕組み

| パラメータ   | 値     |
|-------|----------|
| 監視指標  | host_agent_open_fd_count。この指標はエージェントプロセスのファイルハンドル数を表し、指標値がしきい値を超えるとアラートがトリガーされます。     |
| 監視式         | ```max(process_open_fds{@LABELS}) by (@GBLABELS)```   |
| 取得指標  | process_open_fds   |
| 指標ソース  | Prometheusが提供するプロセス監視に依存し、プロセス自身の監視から取得します。ここで：<li>運用エージェント：`http://localhost:62888/metrics/stat`</li><li>監視エージェント：`http://localhost:62889/metrics/stat`</li> |
| 取得周期  | 5秒    |

## ルール情報

|       監視指標           | デフォルトしきい値 | 持続時間 | 検出周期 | 解消周期 |
|--------------------------|------|--------|------|------|
| host_agent_open_fd_count | 1000 | 0秒  | 20秒 | 5分 |

## アラート情報

|   アラートトリガー方法   | アラートレベル | 対象範囲  |
|------------|------|-----|
| 監視指標の式に基づく | 警告   | ホスト |

## アラートテンプレート

* **アラート概要**

  * テンプレート：\${alarm_target} \${alarm_name}
  * サンプル：alarm_template_id=0:host=xxx.xxx.xxx.xxx:process=ocp_monagent サーバーエージェントのファイルハンドル数がしきい値を超えた

* **アラート詳細**

  * テンプレート：クラスタ：\${ob_cluster_name}、ホスト：\${host}、アラート：エージェントプロセス：\${process}、ファイルハンドル数 \${value} が制限値 ${alarm_threshold} を超えました。
  * サンプル：クラスタ：obcluster-1、ホスト：xxx.xxx.xxx.xxx、アラート：エージェントプロセス：ocp_monagent、ファイルハンドル数 1200 が制限値 1000 を超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、サーバーエージェントのファイルハンドル数：\${value}
  * サンプル：アラート：サーバーエージェントのファイルハンドル数が上限を超えました、サーバーエージェントのファイルハンドル数：950

## システムへの影響

エージェントプロセスは、OCPがOceanBaseデータベースの運用・監視を行うための重要なツールであり、その安定性は極めて重要です。ファイルハンドル数はプロセスの安定性を測る重要な指標であり、ファイルハンドル数が増加し続ける場合、システムにリーク問題が存在する可能性があります。

## 考えられる原因

1. 監視エージェントの収集タスクにおいて、データベースの読み書きシナリオ、ログファイルの読み書きシナリオ、設定ファイルの読み書きシナリオなど、リソースのクローズが適時に行われない問題が発生している可能性があります。

2. 運用エージェントはOceanBaseデータベースのログを処理・追跡するため、潜在的なリソース問題が存在する可能性があります。

## 解決策

アラートが発生した場合、アラートの詳細を確認し、エージェントが使用するメモリまたはファイルハンドル数を確認します。

* メモリ使用量が過大（10GBを超える）またはファイルハンドル数がシステムのしきい値（65535）を超える場合は、エージェントプロセスを直ちに再起動し、問題がOceanBaseデータベースコンポーネントの正常な動作に影響を与えるのを防ぎます。

* エージェントが使用するメモリが許容範囲内（例：2G以下）の場合、OceanBaseデータベースの動作には一時的に影響しません。次の操作を実行できます：

  1. まず環境コンテキスト情報を保存し、その後すぐにエージェントを再起動することができます。

  2. 環境コンテキスト情報を運用担当者に提供します。情報には以下が含まれます：

     * 現在のプロセスが使用するメモリ、親子プロセスが使用するメモリ（ocp_agentdは現在のプロセスの親プロセスです）。

     * 現在のプロセスのメモリパフォーマンス分析ファイル。

       ```sql
       PID=$(cat /home/admin/ocp_agent/run/ocp_monagent.pid)
       SOCKET=$PID
       # グルーチンのパフォーマンスデータ
       curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$PID.sock http://11/debug/pprof/goroutine?debug=1 --output /tmp/goroutine.txt
       # CPUパフォーマンスサンプリングデータ
       curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$PID.sock http://localhost/debug/pprof/profile?seconds=30 --output pprof.profile.gz
       # メモリサンプリングデータ
       curl --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$PID.sock http://localhost/debug/pprof/heap --output pprof.heap.gz
       ```
