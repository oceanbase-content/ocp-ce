# ob_cluster_recyclebin_disk_used_over_threshold OceanBase リサイクルバインドのディスク使用量がしきい値を超えた場合

## アラートの概要

リサイクルバインドのデータ量が100 GiBを超えた場合にアラートが発報されます。

## アラートの仕組み

| パラメータ     | 値    |
| -------- | ------------ |
| モニタリング指標 | ob_database_disk_used_gb。この指標は、リサイクルバインドデータが占有するディスク容量を示します。指標値がしきい値を超えるとアラートがトリガーされます。  |
| モニタリング式 | ```sum(ob_database_disk_required_size{@LABELS}) by (@GBLABELS) / 1073741824```  |
| 取得指標 | ob_database_disk_required_size |
| 指標ソース | 内部ビューから取得。取得SQL：<li>OceanBase V4.0以前のバージョン：```select t1.tenant_id, t2.database_id, t3.database_name, sum(t1.data_size) as data_size, sum(t1.required_size) as required_size from (select tenant_id, table_id, sum(data_size) as data_size, sum(required_size) as required_size from __all_virtual_meta_table group by table_id) t1 left join (select tenant_id, table_id, database_id from __all_virtual_table) t2 on t1.tenant_id = t2.tenant_id and t1.table_id = t2.table_id left join (select tenant_id, database_id, database_name from gv$database) t3 on t2.tenant_id = t3.tenant_id and t2.database_id = t3.database_id group by t2.database_id```</li><li>OceanBase V4.0以降のバージョン：```select t1.tenant_id, t1.database_name, t3.object_id as database_id, sum(t2.data_size) as data_size, sum(t2.required_size) as required_size from (select tenant_id, database_name, table_id, tablet_id from cdb_ob_table_locations group by tenant_id, database_name, tablet_id) t1 left join (select tenant_id, tablet_id, svr_ip, svr_port, data_size, required_size from cdb_ob_tablet_replicas) t2 on t1.tenant_id = t2.tenant_id and t1.tablet_id = t2.tablet_id left join (select con_id, object_name ,object_id from CDB_OBJECTS where object_type = 'DATABASE') t3 on t1.tenant_id = t3.con_id and t1.database_name = t3.object_name group by t1.tenant_id, t1.database_name```</li> |
| 取得周期 | 5秒 |

## ルール情報

|          モニタリング指標              | デフォルトしきい値(単位：GiB) | 持続時間 | 検出周期 | 解消周期 |
|--------------------------------|-------------|------|------|------|
| ob_database_disk_used_gb       | 100         | 0秒  | 20秒 | 5分 |

| アラートトリガー方式 | アラートレベル | 対象範囲 |

| モニタリング指標の式に基づく | 警告 | クラスタ |

* **アラート概要**

  * テンプレート：${alarm_target} ${alarm_name}
  * サンプル：alarm_template_id=0:ob_cluster=Test-1 OceanBase リサイクルバインドのディスク使用量がしきい値を超えた場合

* **アラート詳細**

  * テンプレート：クラスタ：${ob_cluster_name}、アラート：${alarm_name}。リサイクルバインドのディスク使用量 ${value_shown} が ${alarm_threshold} GiBを超えました。
  * サンプル：クラスタ：Test、アラート：OceanBase リサイクルバインドのディスク使用量がしきい値を超えた場合。リサイクルバインドのディスク使用量 120 GiB が 100 GiBを超えました。

* **アラート回復**

  * テンプレート：アラート：${alarm_name}、OceanBase リサイクルバインドのディスク使用量：\${value_shown}
  * サンプル：アラート：OceanBase リサイクルバインドのディスク使用量がしきい値を超えた場合、OceanBase リサイクルバインドのディスク使用量：90 GiB

## システムへの影響

リサイクルバインはディスク容量を消費します。大量のデータをクリーンアップし、かつリサイクルバイン機能が有効な場合、多くのシステムリソースを無駄に消費します。

## 考えられる原因

* リサイクルバインが有効で、短期間に大量のデータをTruncateしたため、削除されたデータがリサイクルバインに入り、リサイクルバインのクリーンアップサイクルが長い場合。例：`alter system set recyclebin_object_expire_time='7d'` のように、7日後にデータがクリーンアップされます。

* リサイクルバインが有効で、一定期間に一定量のデータが蓄積された場合。リサイクルバインの自動クリーンアップポリシーが有効ではない場合。クリーンアップサイクルを設定する必要があります。

## 解決策

1. リサイクルバインを有効にする必要があるかどうか確認します：

   * リサイクルバインを有効または無効にするコマンド：`set GLOBAL recyclebin = on / off;`
   * リサイクルバインを有効または無効にするフラッシュバックコマンド：`set GLOBAL ob_enable_truncate_flashback = on /off;`

   リサイクルバインを有効にする必要がある場合、適切なリサイクルバインのクリーンアップサイクルを設定できます。例えば、`alter system set recyclebin_object_expire_time='7d'` のように、リサイクルバインに入ったデータは7日後にクリーンアップされます。

2. リサイクルバイン内のデータを手動でクリーンアップします：

   * リサイクルバイン内のオブジェクトを確認する：`SHOW RECYCLEBIN;`。
   * リサイクルバインから指定したデータベースを物理的に削除する：`PURGE DATABASE object_name;`。
   * リサイクルバインから指定したテーブルを完全に物理的に削除する：`PURGE TABLE object_name;`。
   * リサイクルバイン全体を空にする：`PURGE RECYCLEBIN;`。
