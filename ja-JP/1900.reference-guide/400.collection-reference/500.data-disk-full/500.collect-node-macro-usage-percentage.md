# ノードのマクロブロック利用率の収集

## 収集の概要

クラスタノードのマクロブロック利用率を照会し、利用率が低すぎないかどうかを判断します。

## 収集の原理

OceanBase V4.0.0 より前のバージョン：

```SQL
SELECT *, round(data_size_gb/required_size_gb*100,3) percentage 
FROM (
  SELECT svr_ip,svr_port, round(sum(occupy_size)/1024/1024/1024,5) data_size_gb , round(sum(used_size)/1024/1024/1024,5) required_size_gb
  FROM __all_virtual_storage_stat 
  WHERE store_type=1 
  GROUP BY svr_ip,svr_port
)
```

OceanBase V4.0.0 以降のバージョン：

```SQL
SELECT *, round(data_size_gb/required_size_gb*100,3) percentage
FROM (
  SELECT svr_ip,svr_port, round(sum(data_size)/1024/1024/1024,5) data_size_gb , round(sum(required_size)/1024/1024/1024,5) required_size_gb
  FROM __all_virtual_tablet_meta_table 
  GROUP BY svr_ip,svr_port
)
```

## 対処方法

空き領域が多いマクロブロックや、領域の利用率が低いマクロブロックがないか確認します。一般的な解決策はデータの再編成であり、再編成後にディスク領域が解放されます。操作手順は以下のとおりです：

1. パラメータ `alter table tablename set progressive_merge_num = 1` を変更します。
2. `alter system major freeze` を実行します。
3. メジャーコンパクション終了後、`progressive_merge_num = 0` を設定します。

<main id="notice" type='explain'>
<h4>説明</h4>
上記の操作は、ディスク使用量が膨らんだ少数のインデックスを持つテーブルにのみ適用されます。
</main>
