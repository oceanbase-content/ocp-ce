# ホストから「dump tenant info」キーワードを含むログの収集

## 収集の概要

ログが `observer.log` に指定されたテナント「dump tenant info.tenant」などのキーワードを含むかどうかを照会します。

## 収集の仕組み

OBServerログディレクトリ（デフォルトは `/home/admin/oceanbase/log`）内の `observer.log` ファイルを照会し、「dump tenant info.tenant={id:“」などのキーワードを含むINFOレベルのログが存在するかどうかを確認します。

以下のコマンドを実行して収集します。`ob_tenant_id` を対応するテナントIDに置き換えてください：

```shell
grep 'dump tenant info.tenant={id:${ob_tenant_id}' ${observer.log.path}/observer.log
```

テナントのキューがいっぱいになると（500テナントを例にすると）、テナントの仕様、スレッド、キュー、リクエスト統計などの情報を含む以下のようなログが表示されます：

```shell
observer.log.20171129181406:[2017-11-29 18:13:54.020089] INFO  [SERVER.OMT] ob_multi_tenant.cpp:533 [116676][Y0-0000000000000000] [lt=42] dump tenant info(tenant={id:500, 			unit_min_cpu:"10.000000000000", unit_max_cpu:"10.000000000000", slice:"0.000000000000", slice_remain:"0.000000000000", token_cnt:40, ass_token_cnt:40, lq_tokens:12, used_lq_tokens:0, stopped:false, idle_us:0, recv_hp_rpc_cnt:380082895, recv_np_rpc_cnt:0, recv_lp_rpc_cnt:0, recv_mysql_cnt:0, recv_task_cnt:0, recv_large_req_cnt:0, tt_large_quries:0, actives:40, workers:40, lq waiting workers:0, req_queue:total_size=65537 queue[0]=65537 queue[1]=0 queue[2]=0 queue[3]=0 queue[4]=0 queue[5]=0 , large queued:0})
```

<main id="notice" type='explain'>
<h4>説明</h4>
<li>OceanBaseがV4.xバージョンの場合、この種類のログは30秒ごとに出力されます。</li><li>OceanBaseがV3.xまたはV2.xバージョンの場合、この種類のログは10秒ごとに出力されます。</li>
</main>

このログは通常、テナントのキューにバックログが発生していないかどうかを判断するために使用されます。具体的なフィールドの説明は以下のとおりです：

* id：テナントID。
* unit_min_cpu：保証される最小CPUコア数。
* unit_max_cpu：制限される最大CPUコア数。
* slice：無意味。
* slice_remain：無意味。
* token_cnt：スケジューラーが割り当てたトークン数。1つのトークンは1つのワーカースレッドに変換される。
* ass_token_cnt：テナントが現在確認しているトークン数（token_cntに基づいて確認され、通常は両者は等しい）。
* lq_tokens：Large Queryトークンの数。token_cntに大規模リクエスト比率を掛けて設定する。
* used_lq_tokens：現在LQ Tokenを保持しているWorker数。
* stopped：テナントunitが削除中かどうか。
* idle_us：1ラウンド（10秒間）におけるワーカースレッドのアイドル時間の合計。いわゆるアイドルとは、実際には待機キューでの待機時間のみを統計している。
* recv_hp/np/lp_rpc_cnt：テナントが累計で受信した異なるレベルのRPCリクエスト数。hp（High）、np（Normal）、lp（Low）。
* recv_mysql_cnt：テナントが累計で受信したMySQLリクエスト数。
* recv_task_cnt：テナントが累計で受信した内部タスク数。
* recv_large_req_cnt：テナントが累計で予測した大規模リクエスト数。増加のみ可能で、リセットはされない。実際には再試行時に増加する。
* tt_large_quries：テナントが累計で処理した大規模リクエスト数。増加のみ可能で、リセットはされない。実際にはチェックポイントチェック時に増加する。
* actives：アクティブ状態のワーカースレッド数。
* workers：テナントが保持しているワーカースレッド数。実際にはworkers_このリストのサイズである。
* nesting workers：テナントが保持しているネストリクエスト専用スレッド数。合計7つのスレッドは7つのネストレベルに対応する。
* lq waiting workers：スケジューリングを待機中のワーカースレッド。
* req_queue：異なる優先度のワークキュー。数値が小さいほど優先度が高い。このフィールドは各優先度のキュー待ちリクエスト数を示す。
* large queued：現在予測されている大規模リクエストの数。
* multi_level_queue：ネストリクエストを格納するワークキュー。1～7は7つのネストレベルに対応する(queue[0]は現在未使用)。このフィールドは各レベルのキュー待ちリクエスト数を示す。
