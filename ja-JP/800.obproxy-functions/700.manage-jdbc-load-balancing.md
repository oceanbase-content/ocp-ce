# クライアント設定の管理

業務トラフィックのロードバランシングを実現するためには、クライアントドライバー（JDBCドライバーなど）に対応するトラフィック入口ノードとトラフィック配分ポリシーが必要です。**<UI-TERM key="ocp-v2.Detail.LoadBalance.ClientConfiguration">クライアント構成</UI-TERM>** を通じて、OBProxyクラスタのノード情報とロードバランシングポリシーをアプリケーション形式でクライアントプログラムと同期し、クライアントはアプリケーション設定情報を取得してロードバランシング機能を実装します。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **OBProxyメンテナンス** リソース権限。
* OBProxy **<UI-TERM key="ocp-v2.src.hook.useMenu.ClientConfiguration">クライアント設定</UI-TERM>** メニュー権限。

## アプリケーションの追加

1. OCPにログインします。

2. 左側のナビゲーションバーで **OBProxy** をクリックします。

3. クラスタリストから操作対象のOBProxyクラスタを選択し、OBProxyクラスタの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動します。

4. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Detail.LoadBalance.ClientConfiguration">クライアント構成</UI-TERM>** をクリックすると、デフォルトで **<UI-TERM key="ocp-v2.Detail.LoadBalance.ClientConfiguration">クライアント構成</UI-TERM>** の概要ページに入ります。
5. 右上の **<UI-TERM key="ocp-v2.Detail.LoadBalance.AddApplications">アプリの新規追加</UI-TERM>** をクリックし、右側のパネルにアプリケーション情報を入力します。

    |  パラメータ  |   説明   |
    |----------|----------|
    |  アプリケーション名   |  アプリケーションの名前。英字で始まり、大文字、小文字、数字、アンダースコアを含み、長さは4～32文字である必要があります。 <blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">注意</UI-TERM>**</br>アプリケーション名はグローバルに一意であり、OCP内に同じアプリケーション名は存在できません。</blockquote>      |
    |  説明   |   オプション。アプリケーションの関連説明。長さは0～256文字です。      |
    |  ロードバランシング   |  複数のロードバランシングポリシーを設定した場合、クライアントプログラムは以下のロードバランシング **<UI-TERM key="ocp-v2.Detail.LoadBalance.AddObproxyLoadBalanceAppDrawer.Strategy">戦略</UI-TERM>** の設定順序に従い、ローテーション方式でロードバランシング設定を使用します。アプリケーションには少なくとも1種類のロードバランシングポリシーを設定する必要があります。      |
    |  ポリシー   |  ロードのポリシーを選択します。**RANDOM**、**SERVERAFFINITY**、**ROTATION** の3種類のポリシーモードがあります。ポリシーは重複して選択できません。 <ul><li>RANDOM：ランダム</li> <li>SERVERAFFINITY：加重</li><li>ROTATION：ローテーション</li>  </ul>     |
    |  OBProxy   |  ロードバランシングポリシーの下のOBProxyリストを設定します。表示形式は `IPアドレス:ポート番号(重み)` で、複数選択が可能です。重みはロードバランシングが **SERVERAFFINITY** の場合にのみ使用され、1～10の範囲の数字を設定できます。数字が大きいほど重みが高くなります。       |
    |  グローバル設定   |  アプリケーション全体に関する情報を設定します。       |
    |  OBLB_RETRY_ALL_DOWNS  |  オプション。現在のアプリケーション配下のすべてのノードの接続試行回数を設定します。指定されたしきい値を超えた場合、接続例外をスローします。    |
    |  ノードブラックリスト追加ポリシー   |  ホストがブラックリストに追加されるポリシーを設定します。デフォルトでは無効です。NORMALとRETRYTIMESの2つのモードが含まれます。<ul><li>NORMAL：通常ポリシー。デフォルトポリシーです。ホストのconnectアクションでネットワーク例外がスローされた場合、ブラックリストに追加されます。他のパラメータは不要です。</li> <li>RETRYTIMES：時間帯内の再試行。一定期間内に特定回数再試行した場合、ブラックリストに追加されます。関連設定には **RETRYTIMES** と **DURATION** が含まれます。</li> </ul>    |
    |  DURATION   |   **<UI-TERM key="ocp-v2.Detail.LoadBalance.AddObproxyLoadBalanceAppDrawer.NodeBlacklistPolicy">ノードのブラックリスト追加ポリシー</UI-TERM>** で **RETRYTIMES** モードを選択した場合に表示されます。      |
    |  RETRYTIMES   |   **<UI-TERM key="ocp-v2.Detail.LoadBalance.AddObproxyLoadBalanceAppDrawer.NodeBlacklistPolicy">ノードのブラックリスト追加ポリシー</UI-TERM>** で **RETRYTIMES** モードを選択した場合に表示されます。      |
    |  ノードブラックリスト削除ポリシー   |   有効にすると、指定された時間経過後にノードがブラックリストから削除されます。      |
    |  TIMEOUT   |   **<UI-TERM key="ocp-v2.Detail.LoadBalance.AddObproxyLoadBalanceAppDrawer.NodeRemovalBlacklistPolicy">ノードのブラックリスト削除ポリシー</UI-TERM>** を有効にした場合に表示されます。デフォルトポリシーで、ノードがブラックリストに滞在する時間を設定します。TIMEOUTを超えた時間が経過すると、ブラックリストから削除されます。      |

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/402-cn/%E6%96%B0%E5%A2%9E%E8%B4%9F%E8%BD%BD%E5%9D%87%E8%A1%A1%E5%BA%94%E7%94%A8.png)

6. **<UI-TERM key="ocp-v2.Detail.Component.UpgradeModal.Determine">確定</UI-TERM>** をクリックします。

## アプリケーションの変更

1. OCPにログインします。

2. 左側のナビゲーションバーで **OBProxy** をクリックします。

3. クラスターリストで操作対象のOBProxyクラスタを選択し、OBProxyクラスタの**<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">総覧</UI-TERM>**ページに移動します。

4. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.src.hook.useMenu.ClientConfiguration">クライアント設定</UI-TERM>**をクリックすると、デフォルトで**<UI-TERM key="ocp-v2.src.hook.useMenu.ClientConfiguration">クライアント設定</UI-TERM>**の概要ページが表示されます。

5. 編集対象のアプリケーションを選択し、アプリケーションの右上隅にある**<UI-TERM key="ocp-v2.Detail.LoadBalance.Edit">編集</UI-TERM>**をクリックします。

6. ポップアップパネルで関連情報を変更し、**<UI-TERM key="ocp-v2.User.Oracle.UserList.Determine">確定</UI-TERM>**をクリックして保存します。

## アプリケーションの削除

1. OCPにログインします。

2. 左側のナビゲーションバーで**OBProxy**をクリックします。

3. クラスターリストで操作対象のOBProxyクラスタを選択し、OBProxyクラスタの**<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">総覧</UI-TERM>**ページに移動します。

4. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.Detail.LoadBalance.ClientConfiguration">クライアント構成</UI-TERM>**をクリックすると、デフォルトで**<UI-TERM key="ocp-v2.src.hook.useMenu.ClientConfiguration">クライアント設定</UI-TERM>**の概要ページが表示されます。

5. 削除対象のアプリケーションを選択し、アプリケーションの右上隅にある**<UI-TERM key="ocp-v2.User.Oracle.UserList.Delete">削除</UI-TERM>**をクリックします。

6. ポップアップダイアログで**<UI-TERM key="ocp-v2.User.MySQL.Delete">削除</UI-TERM>**をクリックします。

    <main id="explain" type='explain'>
    <h4>説明</h4>
    <p>削除後は、クライアントプログラムがこの設定を参照してロードバランシング機能を実装できなくなります。慎重に操作してください。</p>
    </main>
