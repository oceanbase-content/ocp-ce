# OBProxyクラスタの移出

このページでは、OBProxyクラスタの移出操作について説明します。他のOCPでこのOBProxyクラスタを引き継ぐ場合は、このセクションを参照して移出してください。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>OBProxyクラスタを移出すると、当該クラスタは現在のOCPの管理から外れます。慎重に操作してください。</p>
</main>

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **OBProxy管理** リソース権限。
  * OBProxy **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* 移出対象のクラスタが **RUNNING** 状態であること。

* ホストに他のサービスがデプロイされている場合、OBProxyクラスタを移出する際に、そのクラスタのサービスをデプロイしたホストをOCPから同時に削除することは許可されません。

* 現在のOceanBaseクラスタとOBProxyクラスタが同一のホストを共有している場合、移出/引き継ぎのシナリオでは、以下の操作順序を必ず守ってください。詳細については、[OCPデータセンター移行](../../1850.ocp-om-best-practices/750.ocp-idc-migration.md)を参照してください。

   1. OBProxyクラスタを移出します。
   2. [OceanBaseクラスタの移出](../../600.cluster-functions/300.manage-a-cluster/650.migrate-a-cluster.md)。
   3. [OceanBaseクラスタの引き継ぎ](../../600.cluster-functions/300.manage-a-cluster/400.take-over-a-cluster.md)。
   4. [OBProxyの引き継ぎ](../400.manage-a-obproxy-server/200.take-over-an-obproxy.md)。

## 手順

OBProxyクラスタを移出するには、以下の2つの方法があります：

* **方法1**：**OBProxy** ページに移動し、操作対象のOBProxyクラスタをクラスタリストから選択します。**...** にカーソルを合わせ、**OBProxyクラスタの移出** をクリックします。

* **方法2**：OBProxyクラスタの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動し、**...** にカーソルを合わせ、**OBProxyクラスタの移出** をクリックします。

以下の手順は、**方法2** を例に説明します。

### ステップ1：移出クラスタページにアクセスする

1. OCPにログインします。

2. 左側のナビゲーションバーで **OBProxy** をクリックします。

3. クラスタリストから操作対象のOBProxyクラスタを選択し、OBProxyクラスタの **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** ページに移動します。

4. **...** にカーソルを合わせ、**<UI-TERM key="ocp-v2.Detail.Overview.MoveOutOfTheCluster.1">クラスタの移行</UI-TERM>** をクリックします。

### ステップ2：移出情報の設定

OBProxyクラスタを移出する前に、以下の操作を実行してください：

1. OBProxyクラスタで使用されているロードバランサーの関連情報をエクスポートします。

   **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.ExportSqlButton.Export">エクスポート</UI-TERM>** または **<UI-TERM key="ocp-v2.component.MoveOutClusterDrawer.MoveOut">管理対象から外す</UI-TERM>** をクリックし、ロードバランサー関連データをエクスポートします。OBProxy上で既存のロードバランシング構成を引き続き使用したい場合は、このOBProxyを引き継ぐ際にこのファイルをインポートすることで、同じロードバランシング情報の重複設定を回避できます。詳細については、[OBProxyの引き継ぎ](../200.create-an-obproxy-cluster.md)を参照してください。

2. ホストを選択し、このクラスタサービスをデプロイするホストをOCPから削除します。

   新しいOCPでそのOBProxyを引き継ぐ前に、古いOCPからホストを削除する必要があります。**<UI-TERM key="ocp-v2.page.Host.HostList">ホスト一覧</UI-TERM>** でも削除操作を実行できます。詳細については、[ホストの削除](../../850.host-features/100.manage-a-host/550.delete-a-host.md)を参照してください。

3. 入力ボックスに **move out** と入力し、**<UI-TERM key="ocp-v2.src.hook.usePreCheckSteps.NextStep">次のステップ</UI-TERM>** をクリックします。

### ステップ3：移出前の事前チェックの実行

システムは、環境がOBProxyクラスタの移出に必要な最低要件を満たしているかどうかを検証します。チェック項目の実行に失敗した場合は、ヒントに従って以下の操作を実行できます：

* **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.Skip">スキップする</UI-TERM>**：この操作は現在のチェック項目をスキップします（特別なシナリオ向けに設計されています）。関連するチェック項目が製品仕様を満たしていることを必ず確認してください。そうでない場合、後続のプロセスが失敗する可能性があります。スキップすると、そのチェック項目の状態は **<UI-TERM key="ocp-v2.src.constant.auditEvent.Failed">失敗</UI-TERM>** から **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Warning">警告</UI-TERM>** に変更されます。
* **<UI-TERM key="ocp-v2.Sop.Main.TaskCard.Retry">再試行</UI-TERM>**：失敗の原因と最適化の推奨事項に基づいて問題を調査・修正します。修正後、**<UI-TERM key="ocp-v2.src.constant.task.TryAgain">再試行</UI-TERM>** をクリックして、失敗したチェック項目を再度実行します。
* **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**：すべての問題が調査・修正されたら、すべて再試行をクリックして、失敗したすべてのチェック項目を再度実行します。

### ステップ4：タスクの詳細を確認する

移出タスクが送信された後、ポップアップウィンドウ内の **<UI-TERM key="ocp-v2.src.constant.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックして進捗状況を確認できます。

タスクの状態が **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** となり、かつ **OBProxy** ページの **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** にそのOBProxyクラスタが表示されなくなった場合、移出は成功です。
