# OBProxyクラスタの再起動

このページでは、OBProxyクラスタ内のすべてのOBProxyを再起動する操作について説明します。クラスタを再起動すると、OBProxyクラスタ内のすべてのOBProxyが同時に再起動されます。

現在のOBProxyクラスタが業務を担っている場合は、現在設定されているロードバランシングに基づき、[OBProxyの再起動](../400.manage-a-obproxy-server/400.restart-an-obproxy.md)の方法で、クラスタ内のOBProxyを数回に分けて再起動することを推奨します。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **OBProxyメンテナンス** リソース権限。
  * OBProxy **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* OBProxyがV3.2.1以下のバージョンの場合は、強制再起動のみサポートされます。OBProxyがV3.2.1以上のバージョンの場合は、**<UI-TERM key="ocp-v2.Detail.Component.RestartModal.ForceRestart">強制再起動</UI-TERM>** と **<UI-TERM key="ocp-v2.src.constant.backup.Restart">再起動</UI-TERM>** の2つのモードをサポートします。

* **<UI-TERM key="ocp-v2.src.constant.oceanbase.Restart.4">再起動</UI-TERM>** は、OBProxyクラスタ内のすべてのOBProxyの状態が **<UI-TERM key="ocp-v2.src.constant.compute.Running">実行中</UI-TERM>** の場合にのみサポートされます。それ以外の場合は、**<UI-TERM key="ocp-v2.Component.CgroupEditModal.ForceRestart">強制再起動</UI-TERM>** のみサポートされます。

* **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.ForceRestart">強制再起動</UI-TERM>** のプロセスでは、すべてのOBProxyが停止します。業務負荷の少ない時間帯に実行することを推奨します。

## 手順

OBProxyクラスタの再起動には、以下の2つのエントリがあります：

* **エントリ1**：**OBProxy** ページに移動し、クラスタリストから操作対象のOBProxyクラスタを選択し、**その他 > すべて再起動** をクリックします。
* **エントリ2**：OBProxyクラスタの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動し、**<UI-TERM key="ocp-v2.page.OBProxy.RestartAll">すべて再起動</UI-TERM>** をクリックします。

以下の手順は **エントリ2** を例に説明します：

1. OCPにログインします。

2. 左側のナビゲーションバーで **OBProxy** をクリックします。

3. クラスタリストから操作対象のOBProxyクラスタを選択し、OBProxyクラスタの **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** ページに移動します。

4. **<UI-TERM key="ocp-v2.Detail.Overview.RestartAll">すべて再起動</UI-TERM>** をクリックします。

   ![09162146](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/%E5%85%A8%E9%83%A8%E9%87%8D%E5%90%AF.png)

5. ポップアップウィンドウで再起動モードを選択します。モードには **<UI-TERM key="ocp-v2.src.constant.compute.Restart">再起動</UI-TERM>** と **<UI-TERM key="ocp-v2.Component.CgroupEditModal.ForceRestart">強制再起動</UI-TERM>** があります。

   * **<UI-TERM key="ocp-v2.Component.ZoneList.Restart">再起動</UI-TERM>**（推奨）：デフォルトでは、再起動は業務によるデータベースへのアクセスを中断しません。業務に長時間トランザクションが存在する場合は、適切な `hot_upgrade_exit_timeout` パラメータ値を設定するか、アプリケーション接続に再試行メカニズムを備えることを推奨します。
   * **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.ForceRestart">強制再起動</UI-TERM>**：このOBproxy接続を介したクライアントは終了され、一部の業務が中断されます。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E9%87%8D%E5%90%AFobproxy%E9%9B%86%E7%BE%A4.png)

6. タスクが送信された後、ポップアップウィンドウの **<UI-TERM key="ocp-v2.src.constant.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、再起動の進捗状況を確認できます。

   当該タスクの状態が **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** であり、かつクラスタの **<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">総覧</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ObproxyList">OBProxyリスト</UI-TERM>** において、すべてのOBProxyの状態が **<UI-TERM key="ocp-v2.page.Information.Running">実行中</UI-TERM>** である場合、再起動は成功です。
