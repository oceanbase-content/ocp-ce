# OBProxyの再起動

このページでは、OBProxyを再起動する操作について説明します。OBProxyの再起動処理により、そのOBProxyのサービスが停止します。慎重に操作してください。

現在のOBProxyクラスタでロードバランシング管理が設定されており、かつクラスタ内に正常な他のOBProxyが存在する場合は、ロードバランシング管理を通じて業務リクエストをOBProxyクラスタ内の他のOBProxyにスケジュールすることができます。これにより、該当OBProxyの再起動による業務中断を回避できます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **OBProxyメンテナンス** リソース権限。
  * OBProxy **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* OBProxyがV3.2.1以下のバージョンの場合は、強制再起動のみサポートされます。OBProxyがV3.2.1以上のバージョンの場合は、**<UI-TERM key="ocp-v2.Component.CgroupEditModal.ForceRestart">強制再起動</UI-TERM>** と **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.Restart">再起動</UI-TERM>** の2つのモードをサポートします。

* **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Running">実行中</UI-TERM>** 状態のOBProxyのみが **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.Restart">再起動</UI-TERM>** をサポートします。その他の状態では **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.ForceRestart">強制再起動</UI-TERM>** のみサポートされます。

* **<UI-TERM key="ocp-v2.Component.CgroupEditModal.ForceRestart">強制再起動</UI-TERM>** の過程でOBProxyはサービスを停止します。業務負荷の少ない時間帯での実行を推奨します。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **OBProxy** をクリックします。

3. クラスタリストから操作対象のOBProxyクラスタを選択し、OBProxyクラスタの **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページに移動します。

4. OBProxyリストから再起動するOBProxyを選択し、**<UI-TERM key="ocp-v2.Component.ServiceName.Operation">操作</UI-TERM>** 列で **詳細 > 再起動** を選択します。

   ![1116](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/%E9%87%8D%E5%90%AFobproxy.png)

   複数のOBProxyを選択して **<UI-TERM key="ocp-v2.src.constant.obproxy.BatchRestart">一括再起動</UI-TERM>** をクリックすることもできます。

   ![1114](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/%E6%89%B9%E9%87%8F%E9%87%8D%E5%90%AFobproxy.png)

   OBProxyクラスタ内のすべてのOBProxyを再起動する必要がある場合は、[OBProxyクラスタの再起動](../300.manage-a-obproxy-cluster/700.restarts-all-obproxy-nodes-in-the-obproxy-cluster.md)を実行してください。

5. ポップアップウィンドウで再起動モードを選択します。**<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.Restart">再起動</UI-TERM>** と **<UI-TERM key="ocp-v2.Component.CgroupEditModal.ForceRestart">強制再起動</UI-TERM>** が含まれます。

   * **<UI-TERM key="ocp-v2.src.util.component.Restart">再起動</UI-TERM>**（推奨）：デフォルトでは、再起動は業務によるデータベースへのアクセスを中断しません。業務に長時間トランザクションが存在する場合は、適切な `hot_upgrade_exit_timeout` パラメータ値を設定するか、アプリケーション接続に再試行メカニズムを備えることを推奨します。
   * **<UI-TERM key="ocp-v2.Component.CgroupEditModal.ForceRestart">強制再起動</UI-TERM>**：このOBproxyに接続されたクライアントは終了され、一部の業務が中断します。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E9%87%8D%E5%90%AFobproxy%E9%9B%86%E7%BE%A4.png)

6. タスクが送信された後、ポップアップウィンドウの **<UI-TERM key="ocp-v2.src.component.TaskLabel.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、再起動の進捗状況を確認できます。

   そのタスクの状態が **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** であり、かつクラスタの **<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">総覧</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ObproxyList">OBProxyリスト</UI-TERM>** におけるそのOBProxyの状態が **実行中** である場合、再起動は成功です。
