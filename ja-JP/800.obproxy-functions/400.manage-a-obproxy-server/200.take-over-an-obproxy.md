# OBProxyの引き継ぎ

このセクションでは、OBProxyを現在OCPが管理しているOBProxyクラスタに引き継ぐ方法について説明します。現在のOCPに含まれていないOBProxyは、引き継ぎ待ちのOBProxyと呼ばれます。引き継ぎ対象のOBProxyが接続するOBProxyクラスタをターゲットOBProxyクラスタと呼びます。OBProxyがターゲットOBProxyクラスタに接続されると、そのクラスタと共に現在のOCPによって運用管理されることになります。

<main id="explain" type='explain'>
<h4>説明</h4>
<p>OBProxyの引き継ぎ時には再起動が行われます。OBProxyの再起動は業務接続に影響を与えるため、慎重に操作してください。</p>
</main>

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **OBProxyメンテナンス** リソース権限。
  * OBProxy **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* 引き継ぎ対象のOBProxyは以下の条件を満たしている必要があります：

  * バージョンがV1.8.0以上であること。

  * rpmパッケージによる標準インストールであること。

  * 所在ホスト上にこのobproxyプロセスが1つだけ存在すること。

  * OCPが配置されているネットワークからアクセス可能であること。

  * 所在ホストがOCPに追加済みであること。ホストの追加については、[ホストの追加](../../850.host-features/100.manage-a-host/200.add-a-host.md)を参照してください。

* 現在のOCP内には、条件を満たすターゲットOBProxyクラスタが既に存在すること。ターゲットOBProxyクラスタが満たす必要がある条件は以下の通りです：

  * **<UI-TERM key="ocp-v2.OBProxy.New.StartupMode">起動方法</UI-TERM>** が、引き継ぎ対象のOBProxyと一致していること。

    つまり、ターゲットOBProxyクラスタの起動方式がConfigUrlの場合、引き継ぎ対象のOBProxyの起動方式もConfigUrlでなければなりません。

  * **接続可能なOceanBaseクラスタ** が、引き継ぎ対象のOBProxyの接続可能なOceanBaseクラスタを含むか、それと等しいこと。

    * 起動方式がConfigUrlの場合、引き継ぎ対象のOBProxyの接続可能なOceanBaseクラスタは、ターゲットOBProxyクラスタの接続可能なOceanBaseクラスタリストに含まれている必要があります。

    * 起動方式がRsListの場合、引き継ぎ対象のOBProxyの接続可能なOceanBaseクラスタは、ターゲットOBProxyクラスタの接続可能なOceanBaseクラスタと完全に同じでなければなりません。

  現在のOCPに条件を満たすOBProxyクラスタがない場合は、まず [OBProxyクラスタの作成](../../500.quickstart/800.quickstart-create-an-obproxy-cluster.md) を参照して、条件を満たす空のOBProxyクラスタを作成してください。

## 注意事項

* 現在のOBProxyクラスタがV4.0以上のバージョンの場合、V4.0.0以上のバージョンのOBProxyのみの引き継ぎをサポートします。現在のOBProxyクラスタがV3.x以下のバージョンの場合、V1.8以上、V4.0.0未満のバージョンのOBProxyのみの引き継ぎをサポートします。

* ソースOCPとターゲットOCPの `ocp.config-url.site.url` 構成パラメータの値が一致し、OBProxyクラスタ名が同じで、すべての起動パラメータが動的更新をサポートする（再起動不要）場合、引き継ぎ時のOBProxyサービスの再起動を回避できます。

## 手順

OBProxyの引き継ぎには以下の2つの方法があります：

* **方法1**：OBProxyの **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** で、そのOBProxyを引き継げるクラスタを見つけ、対応する操作列の **<UI-TERM key="ocp-v2.Detail.Overview.ConnectingTubeObproxy">OBProxyを引き継ぐ</UI-TERM>** をクリックします。
* **方法2**：**<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** で、そのOBProxyを引き継げるクラスタの名前をクリックし、そのOBProxyクラスタの **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページに移動します。**<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページの右上にある **<UI-TERM key="ocp-v2.Detail.Overview.ConnectingTubeObproxy">OBProxyを引き継ぐ</UI-TERM>** をクリックします。

以下の手順は **方法2** を例に説明します：

1. OCPにログインします。

2. 左側のナビゲーションバーで **OBProxy** をクリックします。

3. **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** で、該当するOBProxyを引き継ぐクラスタ名をクリックし、OBProxyの **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページに移動します。

4. **<UI-TERM key="ocp-v2.page.OBProxy.ConnectingTubeObproxy">OBProxyを引き継ぐ</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.page.OBProxy.ConnectingTubeObproxy">OBProxyを引き継ぐ</UI-TERM>** インターフェースに移動します。

     <!-- ![08261706](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E6%8E%A5%E7%AE%A1obproxy-1.png) -->

5. **<UI-TERM key="ocp-v2.page.OBProxy.ConnectingTubeObproxy">OBProxyを引き継ぐ</UI-TERM>** インターフェースで、引き継ぐOBProxyが存在するホストを選択します。

    | パラメータ  |    説明   |
    |---------------|--------------|
    | **root@proxysysパスワード**  | OBProxy管理者アカウントのパスワードを入力します。これはオプションです。引き継ぐOBProxyのroot@proxysysパスワードを以前変更していない場合は、入力不要です。<main id="explain" type='explain'><h4>説明</h4><p>複数のOBProxyを引き継ぐ場合、複数のOBProxyのroot@proxysysパスワードが一致しない場合は、パスワードが同じものをグループ化して、グループごとに引き継ぐことを推奨します。</p></main>  |
    | **<UI-TERM key="ocp-v2.Cluster.Import.OBServerTable.ComputerRoom">データセンター</UI-TERM>**     | OBProxyが存在するデータセンターです。一つのOBProxyは一つのデータセンターにのみ存在できます。  |
    | **<UI-TERM key="ocp-v2.OBProxy.New.DeployMode.Models">機種</UI-TERM>**    | オプションです。モデルを選択すると、後のホストリストがモデルに応じてフィルタリングされます。   |
    | **<UI-TERM key="ocp-v2.src.component.AddArbitrationDrawer.Host">ホスト</UI-TERM>** | OBProxyが存在するホストを選択します。|
    | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SqlPort">SQL ポート</UI-TERM>** | OBProxyが存在するホストのSQLポートを選択します。 |
    | **ロードバランシング設定** | オプションです。手動入力とインポートの2通りの方法をサポートしています。<ul><li>**OBLB** をクリックし、OBLBサービス関連情報を手動で入力します。パラメータの説明については、[ロードバランシングの管理](../300.manage-a-obproxy-cluster/300.manage-load-balancing.md)を参照してください。</li><li>右側の **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Import">インポート</UI-TERM>** ボタンをクリックし、OBProxyクラスタ移出時にエクスポートしたロードバランサーデータファイルをアップロードします。OCPはファイル内のロードバランシング情報を自動的に入力します。ファイルのエクスポート詳細については、[OBProxyクラスタの移出](../300.manage-a-obproxy-cluster/450.migrate-an-obproxy-cluster.md)を参照してください。</li></ul> |

   <!-- ![08261753](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/%E6%8E%A5%E7%AE%A1obproxy%E6%96%B0.png) -->

6. **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.NextStep">次のステップ</UI-TERM>** をクリックすると、システムは引き継ぐOBProxyに対して事前チェックを実行し、その結果を事前チェック画面に表示します。

   * チェックに失敗したOBProxyが存在する場合、引き継ぎを実行できません。この場合、以下の操作が可能です：

     * 実際の状況に応じて、チェックに失敗したOBProxyを削除し、事前チェックに合格したOBProxyのみを引き継ぎます。

     * **<UI-TERM key="ocp-v2.Detail.TakeOver.CheckResult">検査結果</UI-TERM>** 列の **<UI-TERM key="ocp-v2.Detail.TakeOver.Reason">原因</UI-TERM>** にマウスカーソルを合わせると、事前チェックに失敗した理由を確認できます。修正後、**<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">再確認する</UI-TERM>** をクリックします。

     <!-- ![09011346](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/%E9%A2%84%E6%A3%80%E6%9F%A5%E4%B8%8D%E9%80%9A%E8%BF%87%E5%8E%9F.png) -->

   * リスト内のすべてのOBProxyの事前チェック結果が合格であれば、ステップ7を実行できます。

     <!-- ![09011337](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/%E9%A2%84%E6%A3%80%E6%9F%A5%E9%80%9A%E8%BF%87.png) -->

7. **全て引き継ぐ** ボタンをクリックし、**<UI-TERM key="ocp-v2.Detail.TakeOver.TakeoverConfirmation">引き継ぎの確認</UI-TERM>** パネルでOBProxyの引き継ぎ情報を確認します。

   * 引き継ぐOBProxy上に接続可能なOceanBaseクラスタが存在する場合、OBProxyを引き継ぐと、そのOBProxy上の接続可能なOceanBaseクラスタがOBProxyクラスタに同期され追加されます。

   * ホストが存在するOBProxyの一部のパラメータ値がOBProxyクラスタと一致しない場合、引き継ぎはできません。OBProxyパラメータの変更に同意する必要があります。**<UI-TERM key="ocp-v2.Detail.TakeOver.AgreeToModify">変更に同意</UI-TERM>** をクリックすると、ホストが存在するOBProxyのパラメータはすべてOBProxyクラスタのパラメータと一致するように変更されます。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E6%8E%A5%E7%AE%A1%E7%A1%AE%E8%AE%A4.png) -->

8. 引き継ぎダイアログボックスに **confirm** と入力し、**<UI-TERM key="ocp-v2.Detail.TakeOver.ConfirmTakeover">引き継ぎの確認</UI-TERM>** をクリックして、引き継ぎタスクを送信します。

9. 引き継ぎタスクの実行が成功するのを待ちます。タスクが完了すると、引き継ぎは完了です。

   <main id="explain" type='explain'>
   <h4>説明</h4>
   <p>管理を容易にするため、ターゲットOBProxyが引き継がれた後、そのroot@proxysysパスワードは、所属するOBProxyクラスタのroot@proxysysパスワードに統一されます。</p>
   </main>
