# ユーザーおよび権限の概要

OCPは組織単位でリソースを分離し、組織管理機能を提供します。実際のビジネスニーズに応じて、組織内のロールやユーザーを管理・権限付与することが可能です。

## アーキテクチャの紹介

OCPは **システム管理者 > 組織管理者 > ユーザー** の3層管理アーキテクチャを採用しており、具体的なアーキテクチャ図は以下のとおりです：

## 組織

実際のアプリケーションシナリオにおいて、組織は重要な論理的概念として大きな役割を果たします。例えば、大規模なグループ企業では、それぞれの子会社に正確に対応させることができます。各子会社は所属する組織に基づいて自己関連のリソースを管理し、相互に干渉しないようにします。また、規模の大きな会社では、異なる部門を異なる組織と見なすことで、部門ごとのリソースの独立した管理を実現できます。ユーザーは複数の組織を作成することで、異なる組織間のリソース分離を実現できます。異なる組織は、それぞれ明確なリソース境界を持つ独立した「リソース空間」となり、リソース管理の安全性と精度を向上させます。

組織内では、組織管理者は特別なロールであり、自身の組織およびその組織と共有されたすべてのリソースに対する権限を持ち、組織内の各種リソースの管理や権限・ロール管理などの操作を行うことができます。

OCPの組織には、デフォルト組織とカスタム組織が含まれます。

* **デフォルト組織**

    **default** はOCPに組み込まれているデフォルト組織であり、他の組織を作成する前に、システム内に現存するすべてのリソースはデフォルト組織に格納されます。

* **カスタム組織**

    ユーザーは特定のニーズやビジネスシナリオに基づいてカスタム組織を作成し、既存の組織を通じてリソース設定を共有することができます。例えば、異なる組織間で異なるクラスタのリソース設定を共有することで、組織間のリソース分離を実現します。

**<UI-TERM key="ocp-v2.Auth.Role.AddRole.Organization">組織</UI-TERM>** リストで組織を検索し、組織名、作成日時などの情報を確認し、一般的な運用保守操作を実行できます。詳細については、[新規組織の作成](100.manage-a-organization/100.create-a-organization.md)、[リソースの表示](100.manage-a-organization/200.view-organization-resource.md)、[リソース設定の共有](100.manage-a-organization/400.shared-resource-configuration.md)、[組織の編集](100.manage-a-organization/300.edit-a-organization.md)、[組織の削除](100.manage-a-organization/500.delete-a-organization.md) を参照してください。

## ロール

ロールは一連の権限の集合であり、ロールがユーザーに割り当てられて初めて実際に有効になります。ロールが割り当てられた各ユーザーは、自身の権限範囲内でのみ操作を行うことができ、非専門家による誤操作や情報漏洩を防ぎ、情報セキュリティと伝統的なセキュリティを実現します。

OCPのロールには、デフォルトロールとカスタムロールが含まれます。

* **<UI-TERM key="ocp-v2.Auth.User.New.DefaultRole">デフォルトのロール</UI-TERM>**

    デフォルトロールはシステムに組み込まれている事前設定のロールであり、一般的なユーザー権限管理要件を基本的に網羅しています。例えば、全管理権限を持つシステム管理者ロールADMIN、全読み取り専用権限を持つADMIN_VIEWERロールなどがあります。

    OCPのすべての[デフォルトロール](200.manage-a-role/600.ocp-default-roles.md)および対応する権限は、**システム管理 \> ユーザー管理** の **<UI-TERM key="ocp-v2.Scan.ReportTable.ZoneInfoTable.Role">ロール</UI-TERM>** タブで確認できます。

* **<UI-TERM key="ocp-v2.Auth.Role.CustomRole">カスタムロール</UI-TERM>**

    カスタムロールは、ユーザーがOCP内で自定義で作成するロールです。初期のデフォルトロールと比較して、より細かい粒度の管理権限を持たせることができます。例えば、指定されたユーザーが指定されたクラスタ、指定されたクラスタ内の指定されたテナントのみを閲覧できるように指定することができます。デフォルトロールと組み合わせて使用することで、多様な認可ポリシーを提供できます。

**<UI-TERM key="ocp-v2.Scan.ReportTable.ZoneInfoTable.Role">ロール</UI-TERM>** リストでロールを検索し、ロール名、所属組織、リソース権限、メニュー権限、割り当て済みユーザーなどの情報を確認し、一般的な運用保守操作を実行できます。詳細については、[新規ロールの作成](200.manage-a-role/100.create-a-role.md)、[ロールのコピー](200.manage-a-role/400.copy-a-role.md)、[ロールの表示](200.manage-a-role/200.view-a-role.md)、[ロールの編集](200.manage-a-role/300.edit-a-role.md)、[ロールの削除](200.manage-a-role/500.delete-a-role.md) を参照してください。

## ユーザー

ユーザーはOCPプラットフォームの使用者、機能システムの操作者です。ロールは一連の権限（リソースとメニューを含む）の集合であり、権限の担い手です。各ユーザーは少なくとも1つのロールを持たなければならず、それらのロールに含まれる権限を持っている必要があります。これにより、OCPプラットフォーム上で対応する操作を実行できます。ユーザーの権限は、彼が演じるすべてのロールの権限の並集です。同時に、ユーザーは特定の組織に属している必要があります。OCPは、異なる組織間でOceanBaseクラスタ、テナント、ホストなどのリソース分離を実現し、エンタープライズレベルの権限・ロール管理要件を満たします。

OCPのユーザーには、デフォルトユーザーとカスタムユーザーが含まれます。

* **デフォルトユーザー**

    OCPプラットフォームの初期アカウントであるadminは、システム管理者ロールを持つユーザーであり、OCPプラットフォームのすべてのクラスタと機能モジュールに対する管理権限を有しています。

* **カスタムユーザー**

    システム管理者は他のユーザーを作成し、1つ以上のロールを割り当てることができます。これにより、業務アーキテクチャにおいて対応する職能を担わせることができます。例えば、組織管理者権限を持つORG_ADMINのユーザーを作成し、組織管理者に代わって他のユーザーを作成させることができます。

**<UI-TERM key="ocp-v2.Auth.User.New.User">ユーザー</UI-TERM>** リストでユーザーを検索し、ユーザー名、ロール、メール、組織、部門、ロックなどの情報を確認し、一般的な運用保守操作を実行できます。詳細については、[ログイン履歴の表示](300.manage-a-user/700.view-logon-history.md)、[ユーザーの作成](300.manage-a-user/100.create-a-user.md)、[ユーザーの表示](300.manage-a-user/200.view-the-user-details-page.md)、[ユーザーの編集](300.manage-a-user/300.edit-a-user.md)、[ユーザーのコピー](300.manage-a-user/400.copy-a-user.md)、[ユーザーパスワードの変更](300.manage-a-user/500.change-user-password.md)、[ユーザーの削除](300.manage-a-user/600.delete-a-user.md)を参照してください。

## 適用シナリオ

OCPの**<UI-TERM key="ocp-v2.Auth.Role.Detail.UserManagement">ユーザー管理</UI-TERM>** 機能を初めて使用する場合は、以下の権限付与プロセスを参考にユーザーの権限を管理できます：

1. （オプション）[組織の作成](100.manage-a-organization/100.create-a-organization.md) および組織への [リソース構成の共有](100.manage-a-organization/400.shared-resource-configuration.md)。
2. [ロールの作成](200.manage-a-role/100.create-a-role.md) およびロールへのリソース権限とメニュー権限の割り当て。
3. [ユーザーの作成](300.manage-a-user/100.create-a-user.md) およびユーザーへのロールの選択。

## 機能の制限

OCPの現在のバージョンでは、**<UI-TERM key="ocp-v2.page.Information.InformationCollection">情報収集</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Plan.PlanManagement">緊急対応プラン管理</UI-TERM>**、**<UI-TERM key="ocp-v2.src.hook.useMenu.InspectionService">ヘルスチェックサービス</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Alarm.Alarm">アラートセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.src.component.AddOBCredentialModal.CredentialManagement">認証情報管理</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Property.SystemParameters">システムパラメータ</UI-TERM>** に対するきめ細かい権限制御は行われていません。具体的には以下のとおりです：

* OCPにログインしたユーザーがいずれかのリソースに対する読み取り専用権限を持っている場合、**<UI-TERM key="ocp-v2.page.Information.InformationCollection">情報収集</UI-TERM>**、**<UI-TERM key="ocp-v2.src.hook.useMenu.PlanManagement">緊急対応プラン管理</UI-TERM>**、**<UI-TERM key="ocp-v2.src.hook.useMenu.InspectionService">ヘルスチェックサービス</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Alarm.Alarm">アラートセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">タスクセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.src.util.menu.SystemParameters">システムパラメータ</UI-TERM>** の関連情報を参照できます。ユーザーがいずれかのリソースに対するメンテナンス権限を持っている場合、**<UI-TERM key="ocp-v2.page.Information.InformationCollection">情報収集</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Plan.PlanManagement">緊急対応プラン管理</UI-TERM>**、**<UI-TERM key="ocp-v2.src.hook.useMenu.InspectionService">ヘルスチェックサービス</UI-TERM>**、**<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">アラートセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">タスクセンター</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Property.SystemParameters">システムパラメータ</UI-TERM>** を管理できます。

* OCPにログインしたユーザーがクラスタ、テナント、ホスト、またはOBProxyのいずれかのリソースに対する読み取り専用権限を持っている場合、**<UI-TERM key="ocp-v2.src.component.AddHostCredentialDrawer.CredentialManagement">認証情報管理</UI-TERM>** 内のすべての資格情報に対する読み取り専用権限を持ちます。ユーザーがクラスタ、テナント、ホスト、またはOBProxyのいずれかのリソースに対するメンテナンス権限を持っている場合、**<UI-TERM key="ocp-v2.src.component.AddOBCredentialModal.CredentialManagement">認証情報管理</UI-TERM>** 内のすべての資格情報の更新権限を持ちます。
