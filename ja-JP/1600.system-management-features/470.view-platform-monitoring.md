# プラットフォーム監視の表示

OCP自体のアプリケーション監視は、システムの安定稼働、運用効率の向上、ユーザーエクスペリエンスの最適化を図るための重要な取り組みです。OCP自体の実行状態をリアルタイムで監視することで、サービス異常、リソースボトルネック、およびAgentアクセス異常、ネットワーク遅延、フルGCなどの潜在的な障害を迅速に検出し、管理プラットフォーム自体の問題がOceanBaseデータベースの正常な管理に影響を与えるのを防ぎ、事業継続性を確保します。

監視データはリソース最適化の根拠ともなります。CPUやメモリなどのリソース使用率を分析し、リソース割り当てを適切に調整することで、システム全体のパフォーマンスを向上させることができます。同時に、ログとメトリクスの詳細な分析により、運用保守担当者は問題の根本原因を迅速に特定し、障害を正確に修復することができ、障害対応時間を大幅に短縮できます。さらに、継続的な監視データの蓄積はシステム性能の傾向予測に役立ち、事業の成長ニーズに応じた事前のスケールアウトとアップグレード計画を立てることができ、ユーザーにより信頼性が高く、効率的で、運用コストの低いデータベース管理サービスを提供します。

## 前提条件

* プラットフォーム監視の有効化または無効化操作を実行する際は、現在OCPにログインしているユーザーが**ADMIN**ロール権限を持っていることを確認してください。
* プラットフォーム監視データを表示する際は、現在OCPにログインしているユーザーが**ADMIN**または**ADMIN_VIEWER**ロール権限を持っていることを確認してください。

## 注意事項

OCPプラットフォーム監視を有効にすると、多くのリソースを消費する可能性があります。実際のリソース状況に応じて、有効にするかどうかを選択してください。

## 手順

### プラットフォーム監視の有効化

1. OCPにログインします。
2. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">システム管理</UI-TERM>** > **<UI-TERM key="ocp-v2.src.hook.useMenu.PlatformMonitoring">プラットフォーム監視</UI-TERM>** を選択し、**<UI-TERM key="ocp-v2.pages.PlatformMonitor.EnablePlatformMonitoring">プラットフォーム監視を有効にする</UI-TERM>**をクリックします。
3. ダイアログボックスで**<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.Open">有効にする</UI-TERM>**をクリックします。
4. （オプション）パフォーマンス監視データが正常に表示されるようにするため、プラットフォーム監視機能を有効にした後は、[OCPの起動と停止](../300.deployment-guide/100.deploying-enterprise-ocp/400.deployment-faq/600.starting-and-stopping-ocp.md)（Enterprise版）または[OCPの再起動](../300.deployment-guide/200.deploying-community-ocp/700.deploy-appendix/300.restart-ocp.md)（Community版）を参照して、手動でOCPサービスを再起動することを推奨します。

### プラットフォーム監視の詳細の表示

プラットフォーム監視を有効にすると、プラットフォーム監視ページに移動し、OCPプラットフォームの監視詳細を確認できます。

* OCPプラットフォームの基本情報を確認します。

  | パラメータ  | 説明  |
  |-------|-------|
  | OCPクラスタ名 | 現在のOCPクラスタ名。OCPマルチクラスタモードでのみ表示されます。  |
  | ID         | 現在のOCPクラスタID。OCPマルチクラスタモードでのみ表示されます。   |
  | バージョン番号     | 現在のOCPのバージョン番号。 |
  | 現在のアクセスアドレス  | 現在のOCPのアクセスアドレス。 |

* OCPプラットフォームのアクセスアドレスの詳細を確認します。

  | パラメータ  | 説明 |
  |-------|------|
  | アクセスアドレス | OCPのアクセスアドレス。コピーが可能です。|
  | ステータス     | 現在のOCPの稼働状態。 |
  | 実行時間 | OCPサービスが起動してから現在までの継続実行時間。 |
  | 起動時間 | OCPサービスの直近の起動時間。 |

* OCPプラットフォームの監視データを確認します。

  * **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**：

      | モニタリング項目          | モニタリング指標  | モニタリング指標の意味 | 単位 |
      |-----------------|----------|-----------|---------|
      | CPU利用率      | system_cpu_usage | OCP CPU利用率  | %  |
      | ディスク使用率      | disk_percent     | OCPディスク使用率  | % |
      | システム負荷(1分)  | system_load_average | OCP 1分間のシステム負荷  | -  |
      | 利用可能なプロセッサ数  | system_cpu_count  | OCP 利用可能なプロセッサ数 | -  |
      | JVM GC回数     | gc_total         | OCP JVM回数   | - |
      | JVM GC時間     | gc_time          | OCP JVM時間   | μs |
      | JVMメモリ使用量  | <li>jvm_heap_memory_used_bytes</li><li>jvm_nonheap_memory_used_bytes</li>  | <li>jvm_heap_memory_used_bytes：OCP JVM使用済みヒープメモリサイズ</li><li>jvm_nonheap_memory_used_bytes: OCP JVM使用済みヒープ外メモリサイズ</li>  | Byte |
      | JVMメモリ利用率  | <li>jvm_heap_memory_used_percent</li><li>jvm_nonheap_memory_used_percent</li> | <li>jvm_heap_memory_used_percent：OCP JVM使用済みヒープメモリ利用率</li><li>jvm_nonheap_memory_used_percent：OCP JVM使用済みヒープ外メモリ利用率</li> | % |
      | JVM起動時間    | process_start_time_seconds | OCP JVM起動時間 | s |
      | JVM実行時間    | process_uptime_seconds     | OCP JVM実行時間 | s |
      | JVMメモリ構成    | <li>used</li><li>committed</li><li>max</li>  | <li>used: OCP JVM使用済みメモリ</li><li>committed: OCP JVM使用可能メモリ（使用済みを含む）</li><li>max: OCP JVM最大割り当て可能メモリ</li> | byte |

  * **HTTPリクエスト**：

      | モニタリング項目  | サブ指標  | 指標の意味 | 単位   |
      |---------------|-----------|---------|--------|
      | 1秒あたりの平均HTTPリクエスト処理成功数     | success_count | OCPでの1秒あたりの平均HTTPリクエスト処理成功数 | - |
      | 1秒あたりの平均HTTPリクエスト処理失敗数     | fail_count    | OCPでの1秒あたりの平均HTTPリクエスト処理失敗数 | - |
      | 成功したHTTPリクエスト1回あたりの平均処理時間     | success_time  | OCPで成功したHTTPリクエスト1回あたりの平均処理時間 | s |
      | HTTPリクエスト1回あたりの平均処理時間         | fail_time     | OCPで失敗したHTTPリクエスト1回あたりの平均処理時間 | s |

  以下の機能により、トレンドグラフでのパフォーマンス監視データの表示と分析がより容易になります。

  * デフォルトでは1つのホストのデータのみが表示されます。ホストリストから切り替えて表示することができます。
  * **<UI-TERM key="ocp-v2.Detail.Session.List.Refresh">更新する</UI-TERM>** をクリックすると、監視データを1回だけ更新できます。
  * 自動更新を有効にすることができます。有効にすると、選択した頻度で監視データが自動的に更新されます。
  * 特定の期間を選択することで、その期間内の監視データを取得できます。
  * トレンドグラフ上の任意の時点にカーソルを合わせると、その時点の詳細データを確認できます。カーソルをドラッグして範囲を選択すると、システムはその範囲のトレンド情報を拡大表示し、その期間における該当指標の詳細なトレンドを確認できます。このトレンドグラフをダブルクリックすると元に戻ります。
  * 他のサブ指標アイコンをクリックしてグレーアウトさせると、トレンドグラフにその指標情報が表示されなくなります。
  * すべてのモニタリング項目では、各サブ指標の最大値(max)、平均値(avg)、現在値(current)の表示をサポートしています。**max**、**avg**、または **current** をクリックすると、その列のデータを昇順または降順に並べ替えることができます。

### プラットフォーム監視の停止

ページの右上隅にある **プラットフォーム監視を停止** をクリックすると、OCPプラットフォームの監視データ収集を停止できます。プラットフォーム監視を停止した後は、監視データ収集によるリソースの無駄遣いを避けるため、[OCPの起動と停止](../300.deployment-guide/100.deploying-enterprise-ocp/400.deployment-faq/600.starting-and-stopping-ocp.md)（Enterprise版）または [OCPの再起動](../300.deployment-guide/200.deploying-community-ocp/700.deploy-appendix/300.restart-ocp.md)（Community版）を参照して、手動でOCPサービスを再起動することを推奨します。

## 関連操作

* *HTTPリクエスト** 関連の監視チャートでは、サブ指標はデフォルトでプラットフォームトップ10のHTTPリクエストが表示されます。**システム管理** > **システムパラメータ** で `ocp.self.monitor.http.top.count` パラメータを変更することで、HTTPリクエストのトップ数を変更できます。
