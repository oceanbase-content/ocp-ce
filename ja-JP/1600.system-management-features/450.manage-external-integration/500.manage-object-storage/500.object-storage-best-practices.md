# オブジェクトストレージのベストプラクティス

このドキュメントでは、AIクラスタ、Logserviceクラスタとオブジェクトストレージの連携方法について説明します。これにより、共有ストレージアーキテクチャのデプロイと管理を迅速に開始できます。

## アーキテクチャ概要

OceanBase AIクラスタは、ストレージとコンピューティングの分離（Shared Storage）アーキテクチャを採用しています。データ面はオブジェクトストレージとログサービス（Logservice）が共同で支え、より高い伸縮性を実現します。

### コアコンポーネント

| コンポーネント | 役割 | 関係 | 説明 |
|------|------|------|------|
| **オブジェクトストレージ** | データ永続化層 | 1:N | すべての業務データ（ベースラインデータ + 増分データ）を保存し、データの最終的な帰属先となります。1つのオブジェクトストレージ構成は複数のAIクラスタで使用できますが、各クラスタのデータは異なるディレクトリパスで分離されます |
| **Logserviceクラスタ** | ログサービス層 | 1:1 | ログの永続化機能を提供し、コンピュートノードと高可用性要件を分離し、AZ間の災害復旧をサポートします。1つのLogserviceクラスタは1つのAIクラスタにのみ紐づけ可能です |
| **AIクラスタ** | コンピューティングサービス層 | - | ローカルキャッシュディスクのみを保持し、読み書きサービスを提供します。データは必要に応じてオブジェクトストレージから取得します |

```
┌─────────────────────────────────────────────────────────┐
│                      OCP管理プラットフォーム                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│    オブジェクトストレージ構成                                          │
│         │                                               │
│         ▼                                               │
│    Logserviceクラスタ ◄─── ログ永続化 / AZ間災害復旧          │
│         │                                               │
│         ▼                                               │
│    AIクラスタ（コンピュートノード） ◄─── ローカルキャッシュディスク                    │

│         └───────────┬───────────────┘                   │
│                     │                                    │
│                     ▼                                    │

│                                                         │

```

<main id="notice" type='explain'>
<h4>説明</h4>
<p>複数のAIクラスタが1つのオブジェクトストレージ構成を共有できますが、各クラスタのデータは異なるディレクトリパスで分離され、互いに影響しません。AIクラスタを作成する際は、各クラスタに独立したディレクトリパスを指定することを推奨します。</p>

## 手順

### ステップ1：オブジェクトストレージ構成を作成する

AIクラスタを作成する前に、外部連携モジュールでオブジェクトストレージを設定する必要があります。

1. OCPにログインし、**<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">システム管理</UI-TERM>** > **<UI-TERM key="ocp-v2.page.External.ExternalIntegration">外部統合</UI-TERM>** > **<UI-TERM key="ocp-v2.Overview.components.BasicInformation.ObjectStorage">オブジェクトストレージ</UI-TERM>**に移動します。
2. **<UI-TERM key="ocp-v2.ObjectStorage.Component.CreateDataSourceModal.NewObjectStorageConfiguration">新規オブジェクトストレージ設定</UI-TERM>**をクリックします。
3. 設定情報を入力します：
   * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.MaterializedView.Name">名称</UI-TERM>**：カスタム設定名を入力します。異なる業務や環境を区別するための識別可能な名前を設定することを推奨します。
   * **<UI-TERM key="ocp-v2.ObjectStorage.Component.CreateDataSourceModal.TypeOfAgreement">契約の種類</UI-TERM>**：S3/OSS/OBSを選択します。
   * **Endpoint**：オブジェクトストレージのアクセスアドレスです。
   * **<UI-TERM key="ocp-v2.ObjectStorage.Component.CreateDataSourceModal.Region">リージョン</UI-TERM>**：オブジェクトストレージのリージョンです。リージョン情報がない場合は任意の値を入力できます。
   * **AccessKey ID/Secret**：アクセス認証情報です。

詳細な操作手順については、[オブジェクトストレージ設定の作成](200.create-an-object-storage.md)を参照してください。

### ステップ2：Logserviceクラスタの作成

LogserviceクラスタはAIクラスタにログサービス機能を提供し、AIクラスタと一対一の関係にあります。

1. OCPにログインし、**組織** > **Logservice インスタンス**に移動します。
2. **<UI-TERM key="ocp-v2.Cluster.New.CreateACluster">クラスタを作成する</UI-TERM>**をクリックします。
3. クラスタ情報を入力します。必要に応じて、パラメータテンプレートを適用できます。
4. 作成を完了するためにクリックします。

詳細な操作手順については、[Logserviceクラスタの作成](../../../855.logservice-instance-functions/300.manage-a-logservice-cluster/200.create-a-logservice-cluster.md)を参照してください。

### ステップ3：AIクラスタの作成

AIクラスタを作成する際に、オブジェクトストレージとLogserviceを関連付けます。

1. OCPにログインし、**<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.Cluster">クラスタ</UI-TERM>** > **<UI-TERM key="ocp-v2.Cluster.New.CreateACluster">クラスタを作成する</UI-TERM>**に移動します。
2. **<UI-TERM key="ocp-v2.New.Content.ClusterTypeSelector.AiCluster">AIクラスタ</UI-TERM>**タイプを選択します。
3. 基本情報（クラスタ名、パスワード、バージョンなど）を設定します。
4. 作成済みのオブジェクトストレージ設定を選択します。
5. 作成済みのLogserviceクラスタを選択します。
6. 作成を完了するためにクリックします。

詳細な操作手順については、[AIクラスタの作成](../../../600.cluster-functions/200.create-a-cluster/300.create-an-ai-cluster.md)を参照してください。

## その他の関連操作

### AccessKeyの切り替え

AccessKey認証情報を定期的に更新する際は、以下のプロセスを推奨します：

1. **新規オブジェクトストレージ設定の作成**：新しい認証情報を使用する設定を作成します。
2. **クラスタ参照の変更**：AIクラスタのオブジェクトストレージを新しい設定に切り替えます。
3. **有効化までの待機**：少なくとも1時間待機し、すべてのノードで認証情報の更新が完了することを確認します。
4. **古い設定の削除**：クラスタが正常に動作していることを確認した後、古い設定を削除します。

詳細な操作手順については、オブジェクトストレージ設定の編集を参照してください。

### クラスタの削除

AIクラスタを削除する際には、以下の点に注意してください：

* AIクラスタを削除しても、オブジェクトストレージ上のデータは削除されません。
* 関連するLogServiceクラスタはDEPRECATED（非推奨）状態になります。
* オブジェクトストレージの設定は保持され、他のクラスタで使用できます。
