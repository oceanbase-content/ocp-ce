# サービスグループの新規作成

このセクションでは、アービトレーションサービスグループを新規作成する方法について説明します。アービトレーションサービスプロセスのクラッシュ、OceanBaseとアービトレーションサービス間の通信障害、およびアービトレーションサービスが稼働しているホストのダウンなどの場合、システムは優先設定に基づき、数秒単位でクラスタのアービトレーションサービスアドレスを切り替えることで、アービトレーションサービスの高可用性を実現します。

サービスグループを新規作成する前に、アービトレーションサービスのリソース構成（CPU/メモリ/ディスク容量）を適切に評価し、異常時に単一のアービトレーションサービスがサービスグループ内の全業務負荷をサポートできない状況を回避してください。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionはこの機能をサポートしていません。</p>
</main>

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **アービトレーションサービスのメンテナンス** リソース権限。
* クラスタ **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.component.ModifyClusterParameterDrawer.Cluster">クラスタ</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.component.HostSelect.ArbitrationService">アービトレーションサービス</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.ServiceGroup">サービスグループ</UI-TERM>** タブをクリックし、**<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.ServiceGroup">サービスグループ</UI-TERM>** リストページに移動します。

4. 右上の **サービスグループの新規作成** をクリックします。

5. **<UI-TERM key="ocp-v2.Cluster.Arbitration.CreateAServiceGroup">サービスグループを新規作成</UI-TERM>** パネルで、アービトレーションサービスグループの基本情報を設定します。

    |  パラメータ         |   説明   |
    |---------------|----------|
    |  サービスグループ名    | 英字で始まり、英字または数字で終わる2～32文字の長さが可能です。英字、数字、アンダースコアを含むことができます。   |
    |  アービトレーションサービスアドレス  | リストから既存のアービトレーションサービスアドレスを選択できます。選択したアービトレーションサービスのバージョンは一致している必要があります。少なくとも2つ以上のアドレスを選択することを推奨します。または、リストの下部で **<UI-TERM key="ocp-v2.src.component.ArbitrationServiceSelect.CreateArbitrationService">新規アービトレーションサービス</UI-TERM>** をクリックして、必要なバージョンのアービトレーションサービスを作成することもできます。  |
    |  置換優先順位    | デフォルトで最も高い優先順位は1に設定されています。このグループ内の他のアービトレーションサービスに異常が発生した場合、システムはデフォルトで優先順位1のアービトレーションサービスアドレスを使用して置換を試みます。優先順位1のアービトレーションサービスが利用不可またはリソース不足の場合にのみ、システムは優先順位2のアービトレーションサービスアドレスを使用し、同様にアービトレーションサービスを置き換えます。<br>システムは、**<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.CreateArbitrationGroup.ArbitrationServiceAddress">アービトレーションサービスのアドレス</UI-TERM>** を追加した順序に基づいてデフォルトで優先順位を付けます。アービトレーションサービスアドレスの上部をドラッグして、上下に移動させることで優先順位を調整できます。   |
    |  異常置換条件  | 単一のOceanBaseクラスタが自動的にアービトレーションサービスを切り替えるトリガー条件を設定します。具体的には以下の3種類が含まれます：<ul><li>デフォルトトリガー条件：テナント（2F1A/4F1A）の半数のレプリカがアービトレーションサービスに接続できない場合に適用されます。この場合、**異常継続時間** を設定することで、システムによるアービトレーションサービスアドレスの自動置換をトリガーできます。**異常継続時間** のデフォルト値は10秒で、最大値は3600秒に設定できます。0の場合は、Unit数または割合のルールに該当する場合に即座にトリガーされます。</li><li>Unit切断数トリガー条件：OceanBaseクラスタ内で指定された数のUnit Serverがアービトレーションサービスと切断された場合に適用されます。デフォルトでは、1つのUnitが切断され、かつ **異常継続時間** が10秒を超えた場合に、システムによるアービトレーションサービスアドレスの自動置換がトリガーされます。</li><li>Unit切断割合トリガー条件：OceanBaseクラスタ内で指定された割合のUnit Serverがアービトレーションサービスと切断された場合に適用されます。デフォルトでは、50%以上のUnitが切断され、かつ **異常継続時間** が10秒を超えた場合に、システムによるアービトレーションサービスアドレスの自動置換がトリガーされます。</li></ul> |
    |  備考          | オプションです。アービトレーションサービスグループに関連する説明を補足します。   |
    |  自動実行      | アービトレーションサービスアドレスの置換を自動実行するかどうかを選択します。  |

6. **<UI-TERM key="ocp-v2.Statistics.components.EditAutoBasicInfoDrawer.Ok">確定</UI-TERM>** をクリックします。
