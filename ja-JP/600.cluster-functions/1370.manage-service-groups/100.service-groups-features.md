# サービスグループの概要

OceanBase V4.1バージョンでは、アービトレーションサービス機能が提供されています。アービトレーションサービスは、その低いリソース消費と強力なマルチクラスタサポートにより、2F1A/4F1Aアーキテクチャなど、より低コストなOceanBaseデータベースの高可用性ソリューションを実現しています。このアーキテクチャにより、企業はリソースコストを効果的に管理しつつ、データベースシステムの優れた高可用性を確保し、システムのコストパフォーマンスを大幅に向上させることができます。

しかし、見逃せないのは、アービトレーションサービスの運用過程において単一障害点のリスクが存在することです。アービトレーションサービスに障害が発生した場合、障害が継続する間、OceanBaseクラスタの高可用性は避けられず低下し、ビジネスの継続性と安定性に悪影響を及ぼす可能性があります。

この課題に効果的に対応するため、OceanBaseはアービトレーションサービスグループを構築することで、あるアービトレーションサービスノードに異常が発生した場合、関連するクラスタを他の正常なアービトレーションサービスノードへ秒単位で迅速に切り替えることが可能になります。これにより、OceanBaseクラスタは様々な複雑な状況下でも安定して稼働し、ビジネスへの影響を防ぐことが最大限に保証されます。

## アービトレーションサービスグループとは

アービトレーションサービスグループには複数のアービトレーションサービスが含まれており、特定のアービトレーションサービスが利用不能と検出された場合、OCPは自動的に関連するクラスタをグループ内の他のアービトレーションサービスに切り替えます。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01232128.png)

上図のように、アービトレーションサービスグループは、**<UI-TERM key="ocp-v2.Component.ArbitrationServerList.ArbitrationServiceList">アービトレーションサービス一覧</UI-TERM>** と **切り替えポリシー** の2部分で構成されています。

### アービトレーションサービスリスト

アービトレーションサービスグループ内のアービトレーションサービスには優先順位属性が設定されており、関連するOceanBaseクラスタが切り替えポリシーをトリガーすると、優先順位の高いアービトレーションサービスに優先的に切り替えられます。もし第一優先順位のリソースが不足している場合、一部のOceanBaseクラスタは次の優先順位のアービトレーションサービスに移行されます。

### 切り替えポリシー

切り替えポリシーは、Unit切断ポリシーと持続時間の2部分で構成されています。

* Unit切断ポリシーには以下の3種類が含まれます：

  * デフォルトポリシー：OceanBaseクラスタ内のテナントの半数のレプリカがアービトレーションサービスと切断された場合に適用されます。
  * Unit数：OceanBaseクラスタ内の指定されたUnit Serverがアービトレーションサービスと切断された場合に適用されます。
  * Unit割合：OceanBaseクラスタ内の指定された割合のUnit Serverがアービトレーションサービスと切断された場合に適用されます。

* 持続時間：OceanBaseクラスタがUnit切断ポリシーをトリガーしてから、いくつ後に切り替えを実施するかを示します。

## 前提条件

OCPにログインしているユーザーが以下の権限を持っていることを確認してください。これらの権限がない場合は、アービトレーションサービスグループのリストを表示できません：

* **アービトレーションサービス読み取り専用** リソース権限。
* クラスタ **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

## サービスグループリストの表示

OCPにログインした後、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.Cluster.Arbitration.Cluster.1">クラスタ</UI-TERM>** をクリックして、**<UI-TERM key="ocp-v2.Cluster.Component.RepalceDrawer.ArbitrationService">アービトレーションサービス</UI-TERM>** タブに移動し、さらに **<UI-TERM key="ocp-v2.Detail.Component.ReplaceArbitrationServerDrawer.ServiceGroup">サービスグループ</UI-TERM>** タブをクリックすると、**サービスグループリスト** ページに入ります。

アービトレーションサービスリストページには、アービトレーションサービスグループの **<UI-TERM key="ocp-v2.page.Overview.Host">ホスト</UI-TERM>**、**<UI-TERM key="ocp-v2.Component.ArbitrationServerList.Priority">優先順位</UI-TERM>**、**<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.ServicePort">サービスポート</UI-TERM>**、**<UI-TERM key="ocp-v2.component.ParameterTemplate.Note">備考</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Package.Version">バージョン</UI-TERM>**、**<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.UpgradeArbitrationGroup.AssociatedCluster">関連クラスタ</UI-TERM>**、**<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.CreateArbitrationGroup.ExceptionReplacementCondition">異常置換条件</UI-TERM>**、**<UI-TERM key="ocp-v2.Plan.Component.UpdateDrawer.AutomaticExecution">自動実行</UI-TERM>**、**<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.LastChangeTime">最終更新日時</UI-TERM>**、**<UI-TERM key="ocp-v2.Instance.Overview.Status">ステータス</UI-TERM>** が表示されます。ここでは、ホストIPアドレスとクラスタ名でアービトレーションサービスを検索できます。

* 各ホストのホストIPアドレスをクリックすると、ホスト監視ページに移動します。詳細については、[ホストパフォーマンスの表示](../../880.manage-performance-monitoring/100.performance-monitoring-overview/300.view-host-performance.md)、[ホストリソースの表示](../../880.manage-performance-monitoring/100.performance-monitoring-overview/700.view-host-resources.md)、[ホストプロセスの表示](../../880.manage-performance-monitoring/100.performance-monitoring-overview/750.view-host-process.md)を参照してください。

* アービトレーションサービスに関連付けられたクラスタのクラスタ名をクリックすると、クラスタの概要ページに移動します。詳細については、[クラスタ詳細ページの概要](../300.manage-a-cluster/200.overview-of-the-cluster-details-page.md)を参照してください。

* **<UI-TERM key="ocp-v2.Statistics.components.AutoCollectionDrawer.Status">ステータス</UI-TERM>**でフィルタリングし、サービスグループ情報を確認できます。

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01232201.png)
