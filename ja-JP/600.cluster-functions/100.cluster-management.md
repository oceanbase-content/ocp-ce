# クラスタ管理

OceanBaseデータベースクラスタは、1つまたは複数のリージョンで構成され、リージョンは1つまたは複数のゾーンで構成され、ゾーンは1台または複数のサーバーで構成されます。リージョンは物理的な都市または地域に対応しています。OceanBaseデータベースクラスタが複数のリージョンで構成されている場合、データベースのデータとサービス機能は地域レベルの災害復旧能力を備えます。クラスタが1つのリージョンしかない場合、都市全体の障害が発生すると、データベースのデータとサービス機能に影響が出ます。ゾーンは、独立したネットワークと電源供給による災害復旧能力を備えたデータセンターに対応しています。1つのリージョン内の複数のゾーン間では、OceanBaseデータベースクラスタはゾーン障害時の災害復旧能力を備えます。通常、OceanBaseデータベースクラスタの1つのゾーン内にはデータのコピーが1つだけ存在します。クラスタ全体が1つのゾーンしかない場合、クラスタには災害復旧能力がありません。実際の運用環境でデータセンターが1つしかなく、その中に数台のマシンしかない場合でも、その数台のマシンを仮想的なゾーンに分割することができます。OceanBaseデータベースはこれらの仮想的なゾーン間で災害復旧能力を備えます。

OceanBaseデータベースの革新的な災害復旧能力として、3リージョン・5データセンター構成で都市レベルの災害をロスレスで許容し、同一都市内の3データセンター構成でデータセンターレベルの障害をロスレスで許容する機能があります。OceanBaseデータベースは、複数のリージョンまたはゾーンにデータのコピーを保持し、Paxos一貫性プロトコルを用いてレプリカ間の強整合性を保証することで、都市レベルの災害やデータセンター障害が発生した場合でも、データの信頼性とデータベースサービスの可用性を両立し、信頼性と可用性のバランスを実現します。

OceanBaseデータベースのロスレス災害復旧能力は、クラスタの運用保守作業も容易にします。データセンターやサーバーの交換・修理が必要な場合、該当するデータセンターやサーバーを直接オフラインにして交換・修理を行い、新しいデータセンターやサーバーを追加するだけで済みます。OceanBaseデータベースシステムは自動的にデータの複製とバランシングを行うため、このプロセス全体でデータベースサービスの利用に影響は出ません。

OceanBaseデータベースクラスタの各サーバーではobserverプロセスが実行され、observerプロセスはリソース管理やテナント作成、データ分散管理、データレプリカ間のPaxosプロトコル、集中型または分散型のデータクエリと変更など、データベースサービスの各機能を担当します。OCPは、ocp_agentと共にobserverプロセスを自動起動する機能をサポートしています。マシンが再起動すると、observerが自動的に起動し、マシン再起動前の状態に復旧します。詳細については、[OCP Agentプロセス](../850.host-features/100.manage-a-host/800.ocp-agent-process.md)を参照してください。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っている場合にのみ、クラスタの概要データを表示できます：

* **クラスタ読み取り専用** または **テナント読み取り専用** のリソース権限。
* クラスタ **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

## クラスタ概要

OCPクラウドプラットフォームにログインした後、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.Alarm.LogFilter.Cluster">クラスタ</UI-TERM>** をクリックすると、システムはデフォルトで **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** ページに移動します。

**<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** ページには、現在ログインしているユーザーのクラスタ概要情報が表示されます。これには、**<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.Component.PerformanceTop5.TopPerformanceIndicators">パフォーマンスメトリクストップ5</UI-TERM>**、および **<UI-TERM key="ocp-v2.src.component.MergeTimeTop5.TopClusterMergeTimes">クラスタメジャーコンパクション時間 Top5</UI-TERM>** が含まれます。

同時に、[クラスタの引き継ぎ](../600.cluster-functions/300.manage-a-cluster/400.take-over-a-cluster.md)やクラスタの作成操作も行えます。クラスタの作成には、**中央集約型の作成**、**分散型クラスタの作成**、および **AIクラスタの作成** の3つの方法があります。

* **中央集約型の作成**

  中央集約型とは、OceanBaseデータベースが単一のサーバーまたはコンピュータ上にデプロイされたデータベースシステムを指します。すべてのコアコンポーネント（データベースエンジン、ストレージ、トランザクション処理など）は、同一の物理または仮想ホスト上で実行されます。分散型クラスタと比較して、中央集約型は小型化、軽量化の特徴があり、OceanBaseデータベースをより簡潔かつ迅速に利用できるようにします。詳細については、[中央集約型の作成](../600.cluster-functions/200.create-a-cluster/200.create-a-standalone-centralized-cluster.md)を参照してください。

  <main id="notice" type='explain'>
  <h4>説明</h4>
  <p>中央集約型モードは、OceanBase V4.1.0以降のバージョンでのみサポートされています。</p>
  </main>

* **分散型クラスタの作成**

  分散型クラスタは、OceanBaseデータベースの分散形態であり、複数のホスト、ゾーン、OBServerノードをサポートし、マルチレプリカデータ保護もサポートしています。中央集約型と比較して、分散型クラスタは金融機関で求められる水準の高可用性とスムーズなスケーラビリティを備えており、Oracle/MySQLモードとの高い互換性があります。データセキュリティ要件が高いコア業務システムに適しています。詳細については、[分散型クラスタの作成](../600.cluster-functions/200.create-a-cluster/100.create-a-distributed-cluster.md)を参照してください。

* **AIクラスタの作成**

  AIクラスタは、OceanBaseデータベースの共有ストレージ形態（ストレージとコンピューティングの分離）であり、オブジェクトストレージ（S3/OSS/COS/OBS）を主要なデータ永続化媒体として使用し、ローカルディスクはキャッシュとしてのみ使用されます。分散型クラスタと比較して、AIクラスタはコンピューティングとストレージの分離を実現し、ストレージの弾力的なスケーラビリティやローカルディスク使用量の低減などの利点があります。AI大規模モデルの推論などのシナリオに適しています。詳細については、[AIクラスタの作成](../600.cluster-functions/200.create-a-cluster/300.create-an-ai-cluster.md)を参照してください。

### クラスタリスト

クラスタリストエリアには、各クラスタの **クラスタ名:クラスタID**、**<UI-TERM key="ocp-v2.page.Host.Label">タグ</UI-TERM>**、**<UI-TERM key="ocp-v2.Backup.SecondaryBackup.Data.State">ステータス</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.Operation">操作</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.AllocatedCpu">割り当てられたCPU</UI-TERM>**、**<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">割り当て済みのメモリ</UI-TERM>**、**<UI-TERM key="ocp-v2.Resource.Component.Block.UsedDisks">データディスクはすでに使用されています</UI-TERM>**、**<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.NumberOfTenants">テナント数</UI-TERM>**、**OceanBaseバージョン番号**、**<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DeploymentMode">デプロイモード</UI-TERM>**、**<UI-TERM key="ocp-v2.Alarm.Shield.CreationTime">作成日時</UI-TERM>**、および **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.AlarmInformation">アラート情報</UI-TERM>** などが表示されます。ここでは、クラスタ名の一括検索がサポートされており、各クラスタ名はスペースで区切られています。

* 各クラスタの名前をクリックすると、そのクラスタの詳細ページに移動します。詳細については、[クラスタ詳細ページの概要](../600.cluster-functions/300.manage-a-cluster/200.overview-of-the-cluster-details-page.md)を参照してください。
* クラスタ名の横にあるコピーボタンをクリックすると、クラスタ名をコピーできます。
* クラスタが **<UI-TERM key="ocp-v2.src.constant.binlog.OM">運用中</UI-TERM>** 状態の場合、**<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.Operation">操作</UI-TERM>** 列の **<UI-TERM key="ocp-v2.src.component.TaskLabel.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、クラスタ運用のタスク詳細ページに移動します。タスク詳細ページでは、タスクログの表示、ロールバック、再試行などの操作を行えます。詳細については、[タスクの管理](../1600.system-management-features/600.manage-tasks.md)を参照してください。
* クラスタラベルにカーソルを合わせると、そのクラスタのすべてのラベル情報を確認できます。編集アイコンをクリックしてラベルを管理することもできます。操作の詳細については、[ラベルの管理](../1600.system-management-features/300.manage-tags/100.tags-overview.md)を参照してください。

### パフォーマンス指標Top5

**<UI-TERM key="ocp-v2.Cluster.Component.PerformanceTop5.TopPerformanceIndicators">パフォーマンスメトリクストップ5</UI-TERM>** エリアには、特定の期間内に特定のパフォーマンス指標の合計が最も大きい上位5つのクラスタが表示されます。業務ニーズに応じて、表示するパフォーマンス指標と対応する時間範囲を選択できます。右上のアイコンをクリックすると、アイコンを拡大して見ることができます。

<!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E6%80%A7%E8%83%BD%E6%8C%87%E6%A0%87top5.png) -->

* 選択可能なパフォーマンス指標は以下のとおりです：**QPS（time/s）、SQL応答時間（us）、アクティブセッション数**、および **CPU使用率（%）**。

  |     指標     |                                       説明                                       |
  |------------|--------------------------------------------------------------------------------|
  | QPS        | Query Per Second、現在のOCPが管理するクラスタの1秒あたりの処理リクエスト数で、OceanBaseクラスタシステムがSQLリクエストを処理する性能を反映します。単位はtime/sです。 |
  | SQL応答時間     | クラスタSQLの平均クエリ応答時間を表示します。単位はusです。                                                           |
  | アクティブセッション数      | 単位時間内のアクティブセッションの総数を表示します。                                                                |
  | CPU使用率（%） | クラスタ内のすべてのOBServerのCPU使用率の平均値を表示します。                                                |

* 選択可能な期間は以下のとおりです： **<UI-TERM key="ocp-v2.SQLDiagnosis.Digest.LastHour">最近1時間</UI-TERM>**、**<UI-TERM key="ocp-v2.component.TenantMonitorTop5.LastDay">最近1日</UI-TERM>**、および **<UI-TERM key="ocp-v2.component.TenantMonitorTop5.LastWeek">最近1週間</UI-TERM>**。

### クラスタメジャーコンパクション時間トップ5

**<UI-TERM key="ocp-v2.src.component.MergeTimeTop5.TopClusterMergeTimes">クラスタメジャーコンパクション時間 Top5</UI-TERM>** セクションでは、直近3日間におけるメジャーコンパクション時間の平均値が大きい順に並べた上位5つのクラスタを棒グラフで表示します。メジャーフリーズ（Major Freeze）は動的データと静的データを統合する操作であり、時間がかかります。ダンプによって生成された増分データが一定量に達すると、メジャーコンパクション操作によってメジャーバージョンの統合が実現されます。

直近3日間にクラスタメジャーコンパクションが発生していない場合、このセクションは空になります。右上のアイコンをクリックすると、アイコンを拡大して表示できます。
