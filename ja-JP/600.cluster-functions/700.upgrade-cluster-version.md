# バージョンアップグレード

このセクションでは、OCPを使用してOceanBaseクラスタをアップグレードする手順について説明します。OceanBaseのアップグレード方法はバージョンに密接に関連しているため、具体的なアップグレードの詳細については、OceanBase公式Webサイトの該当バージョンの[クラスタのアップグレード](https://docs.oceanbase.com/oceanbase-database)を参照してください。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* OceanBaseクラスタがV4.0未満のバージョンの場合、V4.0未満のバージョンへのアップグレードのみをサポートします。

* [ソフトウェアパッケージのアップロード](../1500.manage-software-packages/100.upload-a-software-package.md) を参照して、アップグレードパスに必要なすべてのRPMパッケージをアップロードしてください。例：`oceanbase-x.x.x-YYYYMMDDhhmmss.el7.x86_64.rpm` または `oceanbase-x.x.x-YYYYMMDDhhmmss.el7.aarch64.rpm`。

* 2F1R（つまり、2つのフル機能レプリカ + 1つの読み取り専用レプリカ）はローリングアップグレードをサポートしていないため、2F1Rデプロイメント方式のクラスタでは、RレプリカをFレプリカに変換する必要があります。

* スタンドアロンをアップグレードする場合、[ソフトウェアパッケージのアップロード](../1500.manage-software-packages/100.upload-a-software-package.md) を参照して、対象バージョンのLIBS依存パッケージをアップロードしてください。

* クラスタ内のすべてのテナントでメジャーコンパクションを一度実行した後、クラスタバージョンをアップグレードすることを推奨します。

## アップグレードポリシー

* アップグレード対象のクラスタがV4.x未満のバージョンで、かつ関連するプライマリ/スタンバイクラスタが存在する場合、プライマリ/スタンバイクラスタも対象クラスタとして一緒にアップグレードされます。

* アップグレード対象のクラスタがV4.x以上のバージョンの場合：

  * **プライマリ/スタンバイのカスケードデプロイメントシナリオ**

    アップグレードポリシーは下流から上流の順序に従う必要があります。最終端のスタンバイテナントが配置されているクラスタを優先的にアップグレードし、データ同期リンクの安定性を確保することで、バージョンの違いによる同期異常を回避することを推奨します。

  * **プライマリ/スタンバイテナントシナリオ**

    2つのクラスタのテナント間にプライマリ/スタンバイ関係が存在する場合、以下の手順を参考にアップグレードを実行することを推奨します：

    1. テナントタイプの統一。アップグレード開始前に、[プライマリ/スタンバイテナントの日常切り替え](../1200.manage-disaster-recovery/100.switching-primary-and-standby-tenants/100.daily-active-standby-tenant-switchover.md) 操作を実行し、2つのクラスタのテナントタイプが一致していることを確認してください。つまり、どちらもプライマリテナントであるか、どちらもスタンバイテナントであるかのどちらかです。テナントタイプが既に一致している場合は、この手順をスキップしてください。

       <main id="notice" type='notice'>
       <h4>注意</h4>
       <p>この操作により、業務の接続が切断されます。プライマリ/スタンバイテナントに事前にService Nameを設定し、アプリケーションの再接続メカニズムを構築することを推奨します。</p>
       </main>

    2. スタンバイテナントが配置されているクラスタのアップグレード。現在のスタンバイテナントが配置されているクラスタのバージョンを優先的にアップグレードします。OceanBaseのCLOGログの後方互換性により、スタンバイテナントが配置されているクラスタをアップグレードした後でも、ログ同期メカニズムの正常な動作が保証されます。

    3. プライマリテナントが配置されているクラスタのアップグレード。プライマリテナントが配置されているクラスタをアップグレードし、2つのクラスタのバージョンが一致するようにします。プライマリ/スタンバイテナントが配置されているクラスタのバージョンが一致しない期間を可能な限り短縮し、同期異常のリスクを低減するようにしてください。

    4. 業務の再配置。アップグレード完了後、[プライマリ/スタンバイテナントの日常切り替え](../1200.manage-disaster-recovery/100.switching-primary-and-standby-tenants/100.daily-active-standby-tenant-switchover.md) 操作を実行し、業務要件に応じてプライマリ/スタンバイテナントの関係を再配置します。テナントタイプが既に一致している場合は、この手順をスキップしてください。

       <main id="notice" type='notice'>
       <h4>注意</h4>
       <p>この操作により、業務の接続が切断されます。プライマリ/スタンバイテナントに事前にService Nameを設定し、アプリケーションの再接続メカニズムを構築することを推奨します。これにより、業務が最終的に想定通りに配置されることを保証します。</p>
       </main>

## 注意点

* モードが同じデータベース間でのみバージョンアップグレードをサポートします。つまり、スタンドアロンはより高いバージョンのスタンドアロンにのみ、分散クラスタはより高いバージョンの分散クラスタにのみアップグレードできます。

* OceanBase V4.2.1以降では、DBLink機能を使用してリモートのOracleデータベースにアクセスする場合、クラスタ内のすべてのOBServerノードにOCI-12.2をインストールし、設定する必要があります。また、OceanBase V4.2.1未満からV4.2.1以上にアップグレードする場合も、既に設定されているOCI-11.2をOCI-12.2に再設定する必要があります。[OCIのインストールと設定](https://docs.oceanbase.com/oceanbase-database/V4.2.5-install-and-configure-oci)を参照してください。

* Zoneのアップグレード順序を調整することを選択した場合は、以下の点に注意してください：

  * OceanBase 4.Xはプライマリ/スタンバイテナントのみをサポートしています。アップグレード前に、システムがクラスタアップグレード操作を容易に行えるよう、プライマリテナントを同一クラスタに切り替えることを推奨します。

  * OceanBase 2.X/OceanBase 3.Xは、プライマリクラスタのZoneアップグレード順序の設定のみをサポートしています。スタンバイクラスタが存在する場合、優先的にスタンバイクラスタがアップグレードされ、スタンバイクラスタはデフォルトの順序でアップグレードされ、アップグレード中は停止しません。

  * プライマリクラスタのアップグレードタスクの実行を開始した後、タスクフローの**Stop Zone**手順の前に、アップグレード操作を続行するかどうか手動で確認する必要があります。タスクフローの詳細については、[タスクの管理](../1600.system-management-features/600.manage-tasks.md)を参照してください。同時に、異常動作によるクラスタアップグレードの問題を避けるため、できるだけ早くアップグレード操作を完了することを推奨します。

* アップグレード中はDDLが無効になります。クラスタに動的パーティションテーブルが存在する場合、アップグレード時間が長すぎるとパーティション数が不足する可能性があります。アップグレード前に関連するテーブルのパーティションが十分であるか確認し、事前にパーティションを作成しておいてください。

## 手順

### ステップ１：クラスタバージョンアップグレードページに移動する

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.Cluster">クラスタ</UI-TERM>** をクリックすると、システムはデフォルトで **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** で、操作対象のクラスタを選択し、そのクラスタ名をクリックします。

4. クラスタの **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページに移動し、右上の **...** アイコンをクリックして、**<UI-TERM key="ocp-v2.Topo.TopoGraph.UpgradedVersion">バージョンをアップグレード</UI-TERM>** を選択します。

### ステップ2：アップグレード情報を設定する

1. 現在アップグレード準備中のOceanBaseクラスタの情報を確認します。これには、`クラスタ名:クラスタID`、OceanBaseのバージョン、CPUアーキテクチャが含まれます。

2. プロセスを停止する前にダンプ操作を実行するかどうかを選択します。この操作を実行すると、プロセス停止の応答時間が長くなりますが、OBServerの復旧時間を大幅に短縮できます。

3. お客様のビジネスの実際の状況に応じて、アップグレード方法を選択してください。

   * **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.RollingUpgradeRecommended">ローリングアップグレード</UI-TERM>**：アップグレード中にサービスを停止しません。優先的に選択することを推奨します。
   * **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.StopServiceUpgrade">サービス停止を伴うアップグレード</UI-TERM>**：アップグレード中にサービスが停止します。慎重に選択してください。ゾーン数が3未満の場合、ローリングアップグレードでは過半数を構成できないため、**<UI-TERM key="ocp-v2.Component.UpgradeDrawer.StopServiceUpgrade">サービス停止を伴うアップグレード</UI-TERM>** を選択することを推奨します。

4. アップグレードバージョンから、OceanBaseのターゲットバージョンを選択します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p><ul>
   <li>単一マシンでは、<b>サービス停止アップグレード</b>のみをサポートします。</li>
   <li>現在のバージョンより高いソフトウェアパッケージのバージョンのみを選択できます。</li>
   <li>ソフトウェアパッケージのバージョンを選択すると、システムは現在のクラスタのハードウェアアーキテクチャに適合するインストールパッケージが存在するかどうかをチェックします。指定されたアーキテクチャのインストールパッケージが欠けている場合、アップグレードはできません。</li>
   </ul></p>
   </main>

5. 実際のニーズに応じて、クラスタ内のゾーンごとに異なるソフトウェアパッケージタイプを切り替えます。ゾーンの元のソフトウェアパッケージタイプに基づいて、互換性のあるソフトウェアパッケージを選択してアップグレードすることができます。

6. **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.UpgradeMethod">アップグレード方法</UI-TERM>** で **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.RollingUpgradeRecommended">ローリングアップグレード</UI-TERM>** を選択した場合、ゾーンのアップグレード順序を調整できます。

   デフォルトでは、まずRSリーダーノードが配置されているゾーンがアップグレードされ、残りのゾーンはクラスタ概要の **<UI-TERM key="ocp-v2.Component.ZoneList.ZoneList">ゾーンリスト</UI-TERM>** の順序で順次アップグレードされます。ドラッグ＆ドロップでアップグレード順序を調整できます。

7. **<UI-TERM key="ocp-v2.src.hook.usePreCheckSteps.NextStep">次のステップ</UI-TERM>** をクリックします。

### ステップ3：アップグレード前の事前チェックを実行する

1. アップグレード前の事前チェックを実行します。システムは、環境がクラスタアップグレードの最低要件を満たしているかどうかを検証します。チェック項目の実行に失敗した場合、ヒントに従って以下の操作を実行できます：

    * **<UI-TERM key="ocp-v2.page.Package.Upload">アップロード</UI-TERM>**：特定のチェック項目が失敗した場合に表示されます。ヒントに従い、**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.Upload">アップロード</UI-TERM>** をクリックして、必要なソフトウェアパッケージを手動でアップロードしてください。
    * **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.Skip">スキップする</UI-TERM>**：この操作は、現在のチェック項目をスキップします（特別なシナリオ向けに設計されています）。関連するチェック項目が製品仕様を満たしていることを必ず確認してください。そうでない場合、後続のプロセスが失敗する可能性があります。スキップすると、そのチェック項目のステータスは **<UI-TERM key="ocp-v2.NewVersion.Report.copy.Warning">警告</UI-TERM>** に変更されます。
    * **<UI-TERM key="ocp-v2.Sop.Main.TaskCard.Retry">再試行</UI-TERM>**：失敗の原因と最適化の提案に基づいて問題を調査・修正します。修正後、**<UI-TERM key="ocp-v2.Detail.Log.LogCard.ReRun">再試行</UI-TERM>** をクリックして、失敗したチェック項目を再実行します。
    * **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**：すべての問題が調査・修正されたら、**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>** をクリックして、すべての失敗したチェック項目を再実行します。

2. 実行失敗のチェック項目がなくなったら、**<UI-TERM key="ocp-v2.Cluster.Import.Next">次のステップ</UI-TERM>** をクリックします。

### ステップ4：アップグレードパスを確認する

アップグレードパス上のすべてのバージョンのRPMパッケージが存在するか確認します。アップグレードパスに必要なRPMパッケージが欠けている場合は、[ソフトウェアパッケージのアップロード](../1500.manage-software-packages/100.upload-a-software-package.md)を参照して手動でアップロードしてください。

アップグレードパスが完全であることを確認した後、**アップグレード** をクリックします。

### ステップ5：アップグレードタスクを確認する

1. ポップアップウィンドウ内の **<UI-TERM key="ocp-v2.page.Welcome.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、アップグレードの進捗状況を確認できます。アップグレード時には、メインタスクと複数のサブタスクが生成されます。メインタスクは、バイナリを置き換える必要がある各アップグレードノードに基づいて、必要なバイナリファイルを段階的に置き換えるための複数のサブタスクを生成します。

   * メインタスク：アップグレードパス内でバイナリファイルを置き換える必要がある各アップグレードノードごとに、必要なバイナリファイルを段階的に置き換えるためのサブタスクを生成します。`Submit cluster upgrade task` はサブタスクを生成するものです。`Wait dag success` はサブタスクの実行完了を待つものです。`Submit cluster upgrade task` と `Wait dag success` の組み合わせは、アップグレードパス内にバイナリを置き換えるノードがいくつあるかに応じて、複数回実行される可能性があります。

    <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E4%B8%BB%E4%BB%BB%E5%8A%A1.png) -->

   * サブタスク：すべてのOceanBaseクラスタバージョンをアップグレードします。主に、事前チェックスクリプト、アップグレードPreスクリプト、OBServerノードの置き換え、アップグレードPostスクリプト、バージョンチェックなどを含むアップグレードスクリプトの実行です。

    <!-- ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E5%AD%90%E4%BB%BB%E5%8A%A1.png) -->

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>OCPはOceanBaseクラスタのアップグレードタスクのロールバックをサポートしていません。タスクを手動でスキップまたはロールバックしないでください。</p>
    </main>

2. タスクの状態が **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** であり、かつ **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.Cluster">クラスタ</UI-TERM>** ページの **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** 内のそのクラスタの状態がすべて **<UI-TERM key="ocp-v2.src.constant.tenant.Running">実行中</UI-TERM>** である場合、アップグレードは成功したことを意味します。

## 次のステップ

クラスタのアップグレードが完了したら、必ずクラスタに対して手動でフルバックアップを1回実行してください。クラスタバックアップの詳細については、[今すぐクラスタバックアップを実行する](../1100.backup-and-restoration-functions/400.backup-now/100.back-up-cluster-now.md)を参照してください。
