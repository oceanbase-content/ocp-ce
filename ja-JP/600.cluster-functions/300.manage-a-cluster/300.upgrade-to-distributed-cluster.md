# 分散型クラスタへの拡張

このセクションでは、単一マシンをオンラインで分散型クラスタに拡張する方法について説明します。

## 背景

* クラスタを単一ゾーン・複数ホストモードに拡張する場合、OceanBaseサービスの計算能力のみが拡張され、複数レプリカによる高可用性は備えられません。開発・テスト環境に適しています。
* クラスタを偶数ゾーンモードに拡張する場合、データの高可用性要件を満たせず、データセキュリティ上のリスクがあります。設定を調整し、奇数のアベイラビリティゾーン構成を維持するか、クラスタ/テナントでアービトレーションサービスを有効にすることを推奨します。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* 拡張対象の単一マシンが **正常に稼働** していること。

* 拡張操作を実行する前に、以下の条件を満たす分散型OceanBaseソフトウェアパッケージをアップロードしていることを確認してください：

  * ソフトウェアパッケージ名に `standalone` の識別子が含まれていないこと。
  * ソフトウェアパッケージのバージョンが、単一マシンのバージョン番号と、先頭から4つの数値部分がすべて一致していること。例：単一マシンと分散型OceanBaseがどちらもV4.2.5.4の場合。
  * ソフトウェアパッケージのシステムアーキテクチャが単一マシンと一致していること。

## 注意事項

* 単一マシンシステムを分散型クラスタに拡張する操作はリスクが高く、業務アクセスが中断されるため、OceanBaseの技術者のサポートを受けながら実施することを推奨します。
* 操作前に、公式ドキュメント [単一マシンクラスタから分散型クラスタへの拡張に関する注意事項](https://www.oceanbase.com/docs/common-oceanbase-database-standalone-1000000003360376) をよくお読みください。現在のデータベースバージョンが分散型クラスタへの拡張をサポートしているかどうかを確認してください。確認せずに操作すると、クラスタが使用不能になる可能性があります。

## 注意事項

クラスタでCgroupが有効になっている場合、拡張時に選択したホストのOSカーネルバージョンが5.1.0未満の場合は、クラスタのCgroupを無効にすることを推奨します。そうでない場合、システムのパフォーマンス低下や不安定を引き起こす可能性があります。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.component.MonitorSearch.Cluster">クラスタ</UI-TERM>** を選択すると、システムはデフォルトで **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** で、操作対象のクラスタを選択し、そのクラスタ名をクリックします。

4. クラスタの **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページに移動し、**<UI-TERM key="ocp-v2.Detail.Overview.UpgradeADistributedCluster">分散クラスタの拡張</UI-TERM>** をクリックします。

5. 右側に表示されるパネルで、以下の情報を設定します。

    * 拡張に関する情報を設定します：

      システムはデフォルトで **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.NewZone">新規追加ゾーン</UI-TERM>** の方法で拡張されますが、**<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">OBServerの新規追加</UI-TERM>** タブをクリックすると、クラスタを単一Zone・複数ホストモードに拡張することができます。**<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">ゾーンを追加</UI-TERM>** モードでは、複数のZoneを追加する必要がある場合、下部の **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.NewZone">新規追加ゾーン</UI-TERM>** ボタンをクリックして、複数のZone情報を追加できます。

      | **<UI-TERM key="ocp-v2.Detail.SqlAudit.Configuration">設定</UI-TERM>**  |   **<UI-TERM key="ocp-v2.Auth.Role.Detail.Description">説明</UI-TERM>**    |
      |---------|-------|
      | Zone名 | デフォルトはzone_n(nは1から順に増加する整数)です。クリックしてカスタマイズ可能です。**<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.AddObserver">OBServerの追加</UI-TERM>** の方法で拡張する場合、Zone名の編集はサポートされません。    |
      | データセンター      | ホストが配置されているデータセンター。**<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.AddObserver">OBServerの追加</UI-TERM>** の方法で拡張する場合、データセンターの編集はサポートされません。    |
      | マシンタイプ      | オプションです。追加するホストのマシンタイプを指定します。マシンタイプを選択すると、ホストリストがそのマシンタイプに応じてフィルタリングされます。   |
      | ソフトウェアパッケージタイプ | ホストのOceanBaseソフトウェアパッケージタイプを選択します。<ul><li>選択後、CPUアーキテクチャはソフトウェアパッケージタイプに応じてフィルタリングされます。</li><li>**<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.AddObserver">OBServerの追加</UI-TERM>** の方法で拡張する場合、ソフトウェアパッケージタイプの編集はサポートされません。</li></ul>  |
      | CPUアーキテクチャ  | ホストのCPUアーキテクチャを選択します。同一Zone内のCPUアーキテクチャは統一する必要があります。**<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">OBServerの新規追加</UI-TERM>** の方法で拡張する場合、CPUアーキテクチャの編集はサポートされません。   |
      | ホスト      | 複数のホストを選択できます。<ul><li>ドロップダウンリストに選択可能なホストがない場合、[ホストの追加](../../850.host-features/100.manage-a-host/200.add-a-host.md)操作を実行できます。</li><li>本番環境では、OceanBaseデータベースではログディスク容量をホストメモリ容量の3倍以上に設定することを推奨します。また、パフォーマンス上の問題を避けるため、データディレクトリとログディレクトリを同じディスクにマウントすることは推奨されません。</li></ul> |
      | テナント設定  | **<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">ゾーンを追加</UI-TERM>** の方法で拡張する場合、現在のクラスタ内のテナントごとにレプリカ関連情報を一括設定できます。各テナントごとに個別にレプリカを追加する必要はありません。<ul><li>設定対象のレプリカ情報には、レプリカタイプ、Unit仕様、Unit数が含まれます。</li><li>1行の設定では1つのテナントのみ追加できます。複数のテナントを設定する必要がある場合、**<UI-TERM key="ocp-v2.component.ZoneFormCardList.AddTenants">テナントの新規追加</UI-TERM>** をクリックして複数行を追加してください。</li><li>Unit数は選択したテナントに基づいて自動入力され、編集はサポートされません。</li></ul>   |

    * カスタム設定を行う：OBServerノードのOSに属するユーザー、パス、ポートを設定します。詳細については、[分散型クラスタの新規作成](../200.create-a-cluster/100.create-a-distributed-cluster.md)の **<UI-TERM key="ocp-v2.Content.CustomSettings.CustomConfiguration">カスタム設定</UI-TERM>** の説明を参照してください。

    * OBServer起動パラメータの設定：パラメータの詳細については、[OceanBase構成パラメータ](https://docs.oceanbase.com/oceanbase-database/V4.2.1-system-parameters-list)を参照してください。

   <!-- ![09161742](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/01161721.png) -->

6. 完了後、**<UI-TERM key="ocp-v2.component.FilterDropdown.Determine">確定</UI-TERM>** をクリックします。

   ポップアップウィンドウの **<UI-TERM key="ocp-v2.src.constant.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、新規作成の進捗状況を確認できます。また、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>** でもこのタスクの進捗状況を確認できます。
