# 概要

診断収集データ量が過大になると、Agentのメモリ上限を超えて頻繁に再起動することがあります。この場合、現在ではコマンドラインで設定ファイルのパラメータを変更し、再度プッシュする方法しかありません。しかし、このような非標準的な操作方法は、設定の不整合によるAgentのアップグレード失敗や設定のリセットなど、いくつかの問題を引き起こす可能性があります。

そのため、OCPではGUIを用いたパラメータ設定管理機能を提供しています。このセクションを参照し、**<UI-TERM key="ocp-v2.component.OperationConfig.OMConfiguration">運用設定</UI-TERM>** ページでOCP関連の収集および運用パラメータを確認し、一元的に管理することができます。

## パラメータ一覧の説明

OCPでサポートされている収集および運用保守パラメータは、**<UI-TERM key="ocp-v2.component.OperationConfig.List.SqlDiagnosticCollection">SQL 診断収集</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.parameter.TransactionDiagnosticCollection">トランザクション診断収集</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.parameter.ActiveSessionHistoryCollection">アクティブセッション履歴の収集</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.parameter.PerformanceMonitoringParameters">パフォーマンス監視パラメータ</UI-TERM>**、および**バックアップパラメータ**の5つのカテゴリに分類されます。これらはそれぞれ、OCPのSQL診断機能、トランザクション診断機能、アクティブセッション履歴機能、パフォーマンス監視機能、およびバックアップ機能に対応しています。

### SQL診断収集

**<UI-TERM key="ocp-v2.src.constant.parameter.SqlDiagnosticCollection">SQL 診断収集</UI-TERM>**は、主にテナントおよび診断サービス内のSQL診断モジュールに基礎データを提供します。

| パラメータ名 | パラメータタイプ | デフォルト値 | 値の範囲 | パラメータ説明 |
|--------|----------|--------|--------|-----------|
| monagent.pipeline.sql.audit.status | String | active | - | sql_audit診断収集スイッチ。選択可能な値はactive/inactiveです。|
| monagent.limit.memory.fuse.percent | Double | 0.8 | [0.1, 1.0] | メモリ使用量に基づいて診断データ収集を停止するしきい値です。計算方法はocp_monagentプロセスの現在のメモリ使用量 / ocp_monagentプロセスのメモリ上限です。しきい値を超えた場合、診断データの収集を停止します。収集負荷が高い場合は、しきい値を適宜引き上げることができます。|
| monagent.ob.sql.audit.collect.batch.size | Int | 4000 | [500, 20000] | sql_auditの1回のクエリで内部ビューを参照する数です。収集負荷が高い場合、この値を引き上げることで効率を向上させることができます。|
| monagent.ob.slow.sql.threshold | String | 100ms | -| スロークエリの報告しきい値です。このしきい値を超えるSQLはMonitorDBにスロークエリとして報告されます。スロークエリが多すぎる場合、しきい値を調整して報告数を減らすことができます。|
| monagent.ob.sql.transaction.timeus.threshold | Int | 500000 | [10000, 300000000] | 大規模トランザクションの時間しきい値です。単位はμsです。このしきい値を下回るトランザクションSQLは報告されません。大規模トランザクションが多すぎる場合、しきい値を調整して報告数を減らすことができます。 |
| monagent.ob.sql.transaction.log.size.byte | Int | 524288 | [1024, 1073741824] | 大規模トランザクションのログサイズしきい値です。単位はByteです。このしきい値を下回るトランザクションSQLは報告されません。大規模トランザクションが多すぎる場合、しきい値を調整して報告数を減らすことができます。|
| monagent.pipeline.plan.monitor.status | String | active | - | パラレルSQL収集スイッチです。選択可能な値はactive/inactiveです。 |
| monagent.pipeline.slow.sql.status | String | active | - | スロークエリ収集スイッチです。選択可能な値はactive/inactiveです。 |
| monagent.ob.sql.diagnose.collect.query.timeout | String | 10s | - | 診断収集クエリSQLのタイムアウト時間です。sql_audit、sql_plan、sql_plan_monitorのクエリSQLを含みます。 |
| monagent.pipeline.sql.plan.status | String | active | - | 実行計画収集スイッチです。選択可能な値はactive/inactiveです。 |
| monagent.ob.sql.plan.collect.batch.size | Int | 4000 | [500, 20000] | 実行計画収集時の1回のクエリで内部ビューを参照する数です。収集負荷が高い場合、この値を引き上げることで効率を向上させることができます。 |
| monagent.ob.sql.plan.monitor.collect.batch.size | Int | 4000 | [500, 20000] | パラレルSQL収集時の1回のクエリで内部ビューを参照する数です。収集負荷が高い場合、この値を引き上げることで効率を向上させることができます。 |
| monagent.pipeline.monitor.user.collect | Bool | false | - | agent自身のユーザーがsysテナントに対して実行したクエリのSQL情報を収集するかどうかを示します。デフォルトではオフですが、問題の調査時にオンにすることができます。 |
| monagent.pipeline.empty.query.sql.collect | Bool | false | - | query_sqlが空のsql_auditレコードを収集するかどうかを示します。デフォルトではオフですが、問題の調査時にオンにすることができます。 |

### トランザクション診断収集

**<UI-TERM key="ocp-v2.component.OperationConfig.List.TransactionDiagnosticCollection">トランザクション診断収集</UI-TERM>**は、主にテナントおよび診断サービス内のトランザクション診断モジュールに基礎データを提供します。

| パラメータ名 | パラメータタイプ | デフォルト値 | 値の範囲 | パラメータ説明 |
|--------|----------|--------|--------|-----------|
| monagent.pipeline.transaction.status | String | active | - | トランザクション収集スイッチです。選択可能な値はactive/inactiveです。 |
| monagent.ob.sql.transaction.collect.batch.size | Int | 4000 | [500, 20000] | トランザクション収集時の1回のクエリで内部ビューを参照する数です。収集負荷が高い場合、この値を引き上げることで効率を向上させることができます。 |
| monagent.ob.sql.transaction.collect.join.global.transaction | Bool | true | - | トランザクション情報収集時にグローバルトランザクションテーブルにJOINするかどうかを示します。これにより、XAトランザクションなどの情報を収集することができます。 |
| monagent.ob.sql.transaction.collect.query.timeout | String | 5s | - | トランザクション収集クエリSQLのタイムアウト時間です。 |

### アクティブセッション履歴収集

**<UI-TERM key="ocp-v2.src.constant.parameter.ActiveSessionHistoryCollection">アクティブセッション履歴の収集</UI-TERM>**は、主にテナントおよび診断サービス内のセッション管理モジュールに基礎データを提供します。

| パラメータ名 | パラメータタイプ | デフォルト値 | 値の範囲 | パラメータ説明 |
|--------|----------|--------|--------|-----------|
| monagent.pipeline.session.status | String | active | - | アクティブセッション収集スイッチです。選択可能な値はactive/inactiveです。 |
| monagent.ob.session.event.collect.batch.size | Int | 4000 | [500, 20000] | アクティブセッション収集時の1回のクエリで内部ビューを参照する数です。収集負荷が高い場合、この値を引き上げることで効率を向上させることができます。 |
| monagent.ob.session.event.collect.query.timeout | String | 10s | - | アクティブセッション収集クエリSQLのタイムアウト時間です。 |

### パフォーマンス監視

**パフォーマンス監視収集**は、主にクラスタ、テナント、およびOBProxyのパフォーマンス監視モジュールに基礎データを提供します。

| パラメータ名 | パラメータタイプ | デフォルト値 | 値の範囲 | パラメータ説明 |
|--------|----------|--------|--------|-----------|
| monagent.pipeline.ob.status | String | active | - | パフォーマンス監視の収集スイッチで、active/inactiveを選択可能です。 |
| monagent.pipeline.tenant.disk.collect.disabled | Bool | false | - | テナントおよびそれより細かい粒度のディスクデータを収集するかどうか。SQLパフォーマンス問題が発生した場合は、オフにすることを推奨します。 |
| monagent.collector.ob.extra.interval | String | 60s | - | パフォーマンス監視の分単位の収集頻度です。 |
| monagent.second.metric.cache.update.interval | String | 5s | - | パフォーマンス監視の秒単位の収集頻度です。 |

### バックアップ

**バックアップ収集**は主にクラスタとテナントのバックアップモジュールに基礎データを提供します。

| パラメータ名 | パラメータタイプ | デフォルト値 | 値の範囲 | パラメータ説明 |
|--------|----------|--------|--------|-----------|
| backup.dump.physical.file.timeout | Int    | 30 | [10, 300] | 物理バックアップファイルのダンプタイムアウト時間で、単位は秒です。 |
| backup.storage.s3.use.path.style  | Bool   | true | - | S3ストレージがパススタイルアクセスを使用するかどうか。 |

## パラメータ管理操作

**<UI-TERM key="ocp-v2.Detail.Overview.OMConfiguration">運用管理設定</UI-TERM>**ページでは、クラスタに対して以下の基本的な管理操作を実行できます：

* [パラメータの管理](200.manage-om-configuration-parameters.md)：運用設定パラメータの有効化/無効化、パラメータ値の変更、検索、変更されたパラメータの表示をサポートします。
* [パラメータ変更履歴の表示](300.view-om-configuration-parameters-history.md)：現在のクラスタで開始されたすべての運用設定パラメータの変更履歴を表示します。
* [OCP Agentリソースの設定](400.configuring-ocp-agent-resources.md)：クラスタ内のすべてのOCP Agentに統一的にリソースを割り当てます。
