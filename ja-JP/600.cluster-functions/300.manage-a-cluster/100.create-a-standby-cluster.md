# スタンバイクラスタの作成

プライマリクラスタがある場合、現在のクラスタに対してスタンバイクラスタを作成できます。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise Editionにのみ適用されます。OCP Community Editionは、プライマリクラスタの新規作成のみをサポートします。</p>
</main>

## 前提条件

* 現在OCPにログインしているユーザーが **ADMIN** 機構または **ORG_ADMIN** 機構であること。
* プライマリクラスタのバージョンがV2.2.50以上、V4.0.0未満であること。

## 手順

### ステップ１：クラスタ作成ページにアクセスする

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.component.CardAbnormalTable.Cluster">クラスタ</UI-TERM>** をクリックすると、システムはデフォルトで **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. 以下の2つの方法でスタンバイクラスタの作成ページにアクセスできます。

   * **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** ページで、**<UI-TERM key="ocp-v2.page.Welcome.CreateACluster">クラスタを作成する</UI-TERM>** をクリックし、**<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.BasicInformation">基本情報</UI-TERM>** > **<UI-TERM key="ocp-v2.Cluster.New.ClusterType">クラスタタイプ</UI-TERM>** から **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.SecondaryCluster">スタンバイクラスタ</UI-TERM>** を選択します。

   * **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** ページで、スタンバイクラスタを追加するクラスタを選択し、そのクラスタ名をクリックします。**<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** ページの右上の **...** をクリックし、**<UI-TERM key="ocp-v2.Cluster.Detail.CreateAStandbyCluster">新規スタンバイクラスタ</UI-TERM>** を選択します。

### ステップ2：クラスタの基本情報を設定する

**<UI-TERM key="ocp-v2.Tenant.New.CreateACluster">クラスタを作成する</UI-TERM>** ページで、スタンバイクラスタの基本情報を設定します。

基本情報の入力説明は以下のように表示されます：

|       構成       |     説明      |
|----------------|-----------|
| **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.ClusterType">クラスタタイプ</UI-TERM>**       | **<UI-TERM key="ocp-v2.src.constant.oceanbase.StandbyCluster">スタンバイクラスタ</UI-TERM>** を選択する場合は、プライマリクラスタが既に作成されていることを確認してください。 |
| **<UI-TERM key="ocp-v2.Cluster.New.OcpToWhichThePrimary">プライマリクラスタ所属 OCP</UI-TERM>**          | プライマリクラスタが属するOCPクラスタを選択します。|
| **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.MasterCluster">プライマリクラスタ</UI-TERM>**        | プライマリクラスタを選択すると、システムはそのプライマリクラスタに属するスタンバイクラスタを作成します。  |
| **スタンバイクラスタOceanBaseバージョン**  | プライマリクラスタと同じOceanBaseバージョンを選択します。<ul><li>リストに該当バージョンがある場合は、リストから直接選択します。</li><li>それ以外の場合は、リスト下部の **バージョンを追加** をクリックしてアップロードできます。</li> </ul>   |

### ステップ3：クラスタのデプロイメントモード情報を設定する

システムはデフォルトで3つのZoneの情報を追加します。デプロイするクラスタのZone数が3つより多い場合は、下部の **<UI-TERM key="ocp-v2.Detail.Component.AddReplicaModal.NewZone">新規追加ゾーン</UI-TERM>** ボタンをクリックしてZone情報を追加できます。デプロイするクラスタのZone数が3つ未満の場合は、Zoneの後ろにある削除アイコンをクリックできます。

各Zoneに必要な設定情報と説明は以下の表のとおりです。

|   構成   |  描述   |
|----------|---------|
| **<UI-TERM key="ocp-v2.Cluster.New.ZoneName">ゾーン名</UI-TERM>**    | デフォルトのままでもカスタマイズでもかまいません。Zone名は英字で始める必要があり、大文字・小文字、数字、アンダースコアをサポートし、長さは2～32文字です。複数ZoneのOceanBaseクラスタをデプロイする場合、少なくとも1つのZoneはプライマリZoneのRegionと同じである必要があります。  |
| **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ComputerRoom">データセンター</UI-TERM>**     | Zoneが存在するデータセンターです。1つのZoneは1つのデータセンターにのみ存在できます。  |
| **<UI-TERM key="ocp-v2.OBProxy.New.ModelOptional">機種</UI-TERM>**    | オプションです。モデルを選択すると、後続のホストリストがモデルに応じてフィルタリングされます。   |
| **<UI-TERM key="ocp-v2.page.Host.CpuArchitecture">CPUアーキテクチャ</UI-TERM>**    |  選択した **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBaseのバージョン</UI-TERM>** に複数の異なるアーキテクチャのインストールパッケージが存在する場合、このソフトウェアパッケージに対応するホストのハードウェアアーキテクチャを選択する必要があります。<blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">注意</UI-TERM>**</br><ul><li>デフォルトのアーキテクチャタイプは最初のインストールパッケージのアーキテクチャタイプで、切り替えが可能です。指定したアーキテクチャに切り替えると、**<UI-TERM key="ocp-v2.src.constant.auditEvent.Host">ホスト</UI-TERM>** リストにそのアーキテクチャのホストが表示されます。</li><li>異なるZoneに異なるアーキテクチャを設定する場合、混合アーキテクチャデプロイメントモードでは安定性とパフォーマンスの問題が発生する可能性があるため、慎重に操作してください。</li></blockquote> |
| **<UI-TERM key="ocp-v2.component.ZoneFormCardList.Host">ホスト</UI-TERM>**  | 複数のホストを選択するか、ホストの追加操作を行うことができます。   |
| **Root Service の場所**     | RootServiceが配置されるマシンとして、IPアドレスを1つ選択する必要があります。複数レプリカのOceanBaseクラスタでは、各Zoneにroot Serviceを指定する必要があります。   |

### ステップ4：Cgroupを有効にする

Cgroupは主にOceanBaseクラスタ内のテナント間およびテナント内のCPUリソース分離に使用されます。実際のビジネスタイプに応じて、クラスタでCgroupを有効にするかどうかを選択し、より強力なCPU/IOPSの分離を実現できます。作成するOceanBaseクラスタがV4.0以降のバージョンの場合、システムはデフォルトでCgroupを有効にします。

* Cgroupを有効にすると、パフォーマンスが約7%低下します。ビジネスシナリオが単一テナント、小規模構成(<14C)であり、かつより高いデータベースパフォーマンスが必要な場合は、Cgroupを無効にすることを推奨します。
* ホストのOSカーネルバージョンが5.1.0未満の場合、クラスタのCgroupを無効にすることを推奨します。そうでない場合、システムのパフォーマンスが低下したり不安定になったりする可能性があります。
* ホストのOSカーネルバージョンが4.1.9未満の場合、クラスタでテナントを作成できません。この場合、システムはデフォルトでCgroupを無効にし、Cgroupスイッチは表示されません。

### ステップ5：CPUオーバーコミット量を設定する

異なる業務シナリオの負荷が重複する場合、OceanBaseクラスタは運用中に過負荷状態に陥る可能性があります。その結果、異なるテナント間でスレッドがCPUを競合し、実際の業務シナリオの処理速度が低下することがあります。システム内の異なるテナントの負荷が制御された形で交互に実行されるようにするために、CPUリソースの設定時にオーバーコミットを設定することでリソース利用率を向上させることができます。

**<UI-TERM key="ocp-v2.Cluster.New.CpuOversoldSettings">CPUオーバーコミット設定</UI-TERM>** モジュールでは、スライダーまたは入力ボックスを使用してオーバーコミット率を設定できます。デフォルト値は120%で、値の範囲は101%〜200%です。

<main id="notice" type='explain'>
<h4>説明</h4>
<p><ul><li>CPUのオーバーコミット割り当ては、OceanBase 4.0以降のバージョンでのみサポートされています。適切に設定することで、ハードウェアリソースを最大限に活用できます。</li><li>CPUオーバーコミット機能はCgroupに依存しています。CPUオーバーコミット枠を設定する前に、クラスタでCgroupを有効にしてください。</li></ul>
</p></main>

### ステップ6：クラスタパラメータの設定

**<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.ParameterSettings">パラメータ設定</UI-TERM>**モジュールを開くと、クラスタパラメータをカスタマイズして設定できます。

* **<UI-TERM key="ocp-v2.Tenant.New.BasicSettings">基本設定</UI-TERM>**で負荷タイプを設定した場合、システムはその負荷タイプに対応するパラメータテンプレートをデフォルトで選択します。

* 図①のように、起動パラメータ項目を追加し、それぞれに値を設定できます。

* また、図②のように、**<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">パラメータテンプレートを選択</UI-TERM>**をクリックしてパラメータテンプレートを選択することもできます。システムはテンプレート内のパラメータと設定を自動的にここに入力します。クラスタパラメータテンプレートが作成されていない場合は、**新規クラスタテンプレート**をクリックしてクラスタ用にパラメータテンプレートを作成できます。詳細については、[クラスタパラメータテンプレートの管理](../1400.cluster-parameters-template-management.md)を参照してください。

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E5%8F%82%E6%95%B0%E6%A8%A1%E6%9D%BF.png)

   システムは以下の6種類の組み込みテンプレートを提供しており、テンプレートには一般的なパラメータ設定が含まれています。これらのテンプレートを直接適用してクラスタの初期設定を行うことができます。システムの組み込みテンプレートについての詳細は以下のとおりです。

   | テンプレート | 説明 |
   |------|--------|
   | COMPLEX_OLTP デフォルトパラメータテンプレート   | **Complex OLTP**負荷タイプに対応します。このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。   |
   | HTAP デフォルトパラメータテンプレート   | **HTAP**負荷タイプに対応します。このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。 |
   | KV デフォルトパラメータテンプレート   | **OBKV**負荷タイプに対応します。このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。   |
   | EXPRESS_OLAP デフォルトパラメータテンプレート | **Express OLAP**負荷タイプに対応します。このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。 |
   | OLAP デフォルトパラメータテンプレート   | **OLAP**負荷タイプに対応します。このテンプレートはOceanBase V4.3.0以降のバージョンでのみ適用されます。   |
   | 2.2.77 デフォルトパラメータテンプレート   | OceanBaseクラスタV2.2.77バージョンでの使用を推奨するパラメータ設定です。本番環境での使用に適しています。   |

<main id="notice" type='explain'>
<h4>説明</h4>
<p>クラスタレベルのCPU、メモリ、データディスク、ログディスクの使用についてカスタマイズした変更が必要な場合は、以下のパラメータを設定してください：<code>cpu_count</code>、<code>memory_limit_percentage</code>、<code>system_memory</code>、<code>data_disk_usage_limit_percentage</code>、<code>datafile_size</code>、<code>clog_disk_usage_limit_percentage</code>、<code>log_disk_size</code>。各パラメータの説明については、OceanBase公式Webサイトの<a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000640281">クラスタ構成パラメータ一覧</a>を参照してください。</p></main>

### ステップ7：ユーザー、パス、ポートの設定

**<UI-TERM key="ocp-v2.Cluster.New.CustomSettings">カスタム設定</UI-TERM>**モジュールでは、クラスタレベルのユーザー設定（オペレーティングシステムの所有者ユーザーなど）、パス設定（ソフトウェアインストールパス、データディスクパス、ログディスクパスなど）、ポート設定（SQLポート、RPCポートなど）を行うことができます。

1. オペレーティングシステムの所有者ユーザーの設定：

   このユーザーは、OBServerのインストールと実行を設定するためのオペレーティングシステムユーザーであり、編集はサポートされていません。`ocp.operation.default.os.user`パラメータのデフォルト設定を調整することでこのユーザーを変更できます。このパラメータの変更は、分散クラスタの作成、[単一マシンの作成](../200.create-a-cluster/200.create-a-standalone-centralized-cluster.md)、[OBProxyクラスタの作成](../../800.obproxy-functions/200.create-an-obproxy-cluster.md)、[アービトレーションサービスの作成](../1350.manage-arbitration-services/200.create-arbitration-services.md)時にのみ反映され、既存のクラスタの他の設定には影響しません。

2. 関連パスの設定：

   |   設定   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**   | <ul><li>**オペレーティングシステムの所有者ユーザー**がadminの場合、**<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**はデフォルトで`/home/admin/oceanbase`に設定され、カスタマイズ可能です。</li><li>**オペレーティングシステムの所有者ユーザー**がadmin以外の場合、**<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**はデフォルトで`/opt/oceanbase/oceanbase`に設定され、カスタマイズ可能です。</li></ul>   |
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DataDiskPath">データディスクのパス</UI-TERM>**       | デフォルトは`/data/1`で、カスタマイズ可能です。  |
   | **<UI-TERM key="ocp-v2.Cluster.New.LogDiskPath">ログディスクのパス</UI-TERM>**   | デフォルトは`/data/log1`で、パスはカスタマイズ可能です。本番環境では、OceanBaseデータベースではログディスク容量をホストメモリ容量の3倍以上に設定することを推奨します。同時に、パフォーマンス上の問題を避けるため、データディレクトリとログディレクトリを同一のディスクにマウントすることは推奨されません。<main id="notice" type='explain'><h4>説明</h4>OCP 4.3.0 BP1以降、以下のバージョンのOceanBaseクラスタを作成する場合、slogディレクトリはログディスクに配置され、データディスクとは紐づけされなくなりました。この場合、<code>log_disk_size=0</code>を設定すると、clog専用と見なされ、デフォルトで<code>log_disk_percentage</code>が90%に設定されます。slogとclogが配置されるディスクのサイズが40GiB未満の場合、slog用に予約された空き容量が4GiBに満たなくなり、slogの書き込みに影響を与える可能性があります。<ul><li>V4.2.4.0 ≤ OceanBase ＜ V4.3.0.0</li><li>OceanBase ≥ V4.3.1.0</li></ul>slogに関する詳細は、<a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000819002">OBServerノードのインストールディレクトリ構造</a>を参照してください。</main>      |

3. ポートの設定：

   |   設定   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Cluster.New.SqlPort">SQLポート</UI-TERM>**        | デフォルトは2881で、カスタマイズ可能です。  |
   | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.RpcPort">RPCポート</UI-TERM>**   | デフォルトは2882で、カスタマイズ可能です。     |

4. 設定完了後、**<UI-TERM key="ocp-v2.Cluster.New.Test">テスト</UI-TERM>** をクリックし、入力したパスとポートが使用可能か確認します。

    * テストに合格した場合、**<UI-TERM key="ocp-v2.Content.BasicInformation.ModifyDataStorageModal.NewCreation">新設</UI-TERM>** をクリックします。
    * テストに失敗した場合、表示されたメッセージに従ってトラブルシューティングを行います。

### ステップ8：設定情報を確認する

1. 右側のパネルで、設定したクラスタ情報に誤りがないか確認し、**<UI-TERM key="ocp-v2.src.hook.usePreCheckSteps.NextStep">次のステップ</UI-TERM>** をクリックします。

2. 作成前の事前チェックを実行し、システムはお使いの環境がスタンバイクラスタ作成の最低要件を満たしているか検証します。チェック項目の実行に失敗した場合は、表示された指示に従って以下の操作を実行できます：

    * **<UI-TERM key="ocp-v2.page.Package.Upload">アップロード</UI-TERM>**：特定のチェック項目が失敗した場合にのみ表示されます。表示された指示に従い、**<UI-TERM key="ocp-v2.Detail.Component.UpgradeObproxiesModal.Upload">アップロード</UI-TERM>** をクリックして、必要なソフトウェアパッケージを手動でアップロードしてください。
    * **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.Skip">スキップする</UI-TERM>**：この操作は現在のチェック項目をスキップします（特別なシナリオ向けに設計されています）。関連するチェック項目が製品仕様を満たしていることを必ず確認してください。そうでない場合、後続のプロセスが失敗する可能性があります。スキップした後、そのチェック項目の状態は **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.Warning">警告</UI-TERM>** に変わります。
    * **<UI-TERM key="ocp-v2.src.constant.task.TryAgain">再試行</UI-TERM>**：失敗の原因と最適化の推奨事項に基づいて問題を調査・修正し、修正後に **<UI-TERM key="ocp-v2.Sop.Main.TaskCard.Retry">再試行</UI-TERM>** をクリックして、失敗したチェック項目を再度実行します。
    * **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**：すべての問題が調査・修正されたら、**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>** をクリックして、失敗したすべてのチェック項目を再度実行します。

3. 実行失敗のチェック項目がなくなったら、**<UI-TERM key="ocp-v2.Component.New.NewCreation">新規作成</UI-TERM>** をクリックします。

   新規クラスタタスクを送信すると、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>** でそのタスクの実行進捗状況を確認できます。
