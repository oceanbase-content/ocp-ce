# クラスタの引き継ぎ

クラスタの引き継ぎ操作を実行することで、CLI操作または他のOCPで作成されたクラスタを現在のOCPに引き継ぎ、現在のOCPを通じて新しく引き継いだクラスタの運用・管理を継続できます。

## 前提条件

* 現在ログインしているOCPのユーザーが **ADMIN** ロールまたは **ORG_ADMIN** ロールであることを確認してください。

* 引き継ぐOceanBaseクラスタ内のすべてのOBServerノードが正常に稼働していることを確認してください。

* OceanBaseクラスタを引き継ぐ際は、プライマリクラスタ優先の原則に従ってください：

  * 単一OCPシナリオでクラスタを引き継ぐ場合は、まずOceanBaseプライマリクラスタを引き継ぎ、次にOceanBaseスタンバイクラスタを引き継ぎます。
  * OCPマルチクラスタシナリオでクラスタを引き継ぐ場合は、まずあるOCPでOceanBaseプライマリクラスタを引き継ぎ、その後任意のOCPでOceanBaseスタンバイクラスタを引き継ぎます。

* 引き継ぐOceanBaseクラスタ内のテナントサービス名とシステム内の既存サービス名は、すべて一意である必要があります。そうでない場合、引き継ぎ後にそのクラスタ内でサービス名が競合するテナントは、サービス名の状態が **無効** に設定されます。サービス名の詳細については、[サービス名の管理](../../700.tenant-functions/600.manage-a-tenant/800.manage-service-name.md)を参照してください。

* 引き継ぐクラスタがobdデプロイメントの場合、引き継ぎ前に [OCPを使用してobdデプロイメントのクラスタを引き継ぐ](https://docs.oceanbase.com/obd/V2.10.1-use-ocp-to-take-over-a-cluster-deployed-by-obd) を参照し、そのクラスタが引き継ぎ条件を満たしているか確認する必要があります。

* 引き継ぐOceanBaseクラスタにアービトレーションサービスが設定されている場合、引き継ぎを実行する前に、まずそのアービトレーションサービスを移出し、新しいOCPに引き継いでください。詳細については、[アービトレーションサービスの移出](../1350.manage-arbitration-services/700.migrate-an-arbitration-service.md)および[アービトレーションサービスの引き継ぎ](../1350.manage-arbitration-services/250.take-over-arbitration-serveices.md)を参照してください。

## 注意事項

* 各OceanBaseクラスタは、1つのOCPによってのみ管理できます。クラスタを引き継いだ後、そのクラスタは元のOCPでは正常に運用・監視できなくなります。引き継ぐ前に慎重に評価してください。引き継ぐ前に、まずクラスタの移出操作を行うことを推奨します。詳細については、[クラスタの移出](650.migrate-a-cluster.md)を参照してください。
* OceanBaseクラスタを引き継ぐ際、リソースの統一管理を実現するため、OCPはクラスタ配下のOBServerに対応するホストも同時に引き継ぎます。
  * ホストが使用する認証情報が一致している場合は、クラスタ引き継ぎの **事前チェック** ステップでホストを一括して引き継ぐことができます。
  * ホストが使用する認証情報が一致しない場合は、まず [ホストの追加](../../850.host-features/100.manage-a-host/200.add-a-host.md) で対応するホストを個別に引き継ぎ、その後クラスタを引き継ぎます。
* 現在のOceanBaseクラスタとOBProxyクラスタが同一のホストを共有している場合、移出/引き継ぎのシナリオでは、以下の操作順序を必ず守ってください。詳細については、[OCPデータセンターの移行](../../1850.ocp-om-best-practices/750.ocp-idc-migration.md)を参照してください。
   1. [OBProxyクラスタの移出](../../800.obproxy-functions/300.manage-a-obproxy-cluster/450.migrate-an-obproxy-cluster.md)。
   2. [OceanBaseクラスタの移出](650.migrate-a-cluster.md)。
   3. OceanBaseクラスタの引き継ぎ。
   4. [OBProxyの引き継ぎ](../../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md)。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.constant.alarm.Cluster">クラスタ</UI-TERM>** を選択すると、システムはデフォルトで **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** ページで、右上の **<UI-TERM key="ocp-v2.page.Cluster.TakeOverTheCluster">クラスタを引き継ぐ</UI-TERM>** をクリックします。

4. **<UI-TERM key="ocp-v2.Cluster.Import.ConnectToACluster">クラスタ接続</UI-TERM>** ページでクラスタ接続情報を入力します。**<UI-TERM key="ocp-v2.Cluster.Import.DirectlyConnected">直接接続</UI-TERM>** と **OBProxy** の2種類の接続方法をサポートしています。

   * **直接接続：** クラスタの接続 **<UI-TERM key="ocp-v2.page.OBProxy.Endpoint">アクセスアドレス</UI-TERM>**、クラスタの接続 **<UI-TERM key="ocp-v2.Scan.ReportTable.ServerInfoTable.Port">ポート</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">root@sys パスワード</UI-TERM>** を入力し、**proxyroアカウントのパスワードを入力する** かどうかを選択した後、**<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">次のステップ</UI-TERM>** をクリックします。

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>proxyroアカウントのパスワードは、OBProxyがOceanBaseクラスタにアクセスするために使用されます。ここで入力することで、proxyroパスワードの統一性を確保できます。proxyroアカウントの詳細については、<a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">proxyroアカウント管理</a>を参照してください。</p>
      </main>

   * **OBProxy：** クラスタの接続 **<UI-TERM key="ocp-v2.MultiCluster.Detail.Endpoint">アクセスアドレス</UI-TERM>**、クラスタの接続 **<UI-TERM key="ocp-v2.Cluster.Import.Port">ポート</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.Component.SwitchModal.ClusterName">クラスタ名</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.Import.ClusterIdOptional">クラスタ ID（任意）</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">root@sys パスワード</UI-TERM>** を入力します。また、OBProxyがOceanBaseクラスタにアクセスするために使用されるproxyroアカウントのパスワードを **入力するかどうか** を選択できます。**<UI-TERM key="ocp-v2.Detail.ResourceManager.CreateResourcePlan.NextStep">次のステップ</UI-TERM>** をクリックします。

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p><ul><li>引き継ぐクラスタがスタンバイクラスタの場合、クラスタIDは必須です。プライマリ・スタンバイ両方のクラスタを引き継ぐ必要がある場合は、まずプライマリクラスタを引き継ぎ、その後スタンバイクラスタを引き継ぎます。</li><li>proxyroアカウントのパスワードは、OBProxyがOceanBaseクラスタにアクセスするために使用されます。ここで入力することで、proxyroパスワードの統一性を確保できます。proxyroアカウントの詳細については、<a href="../../800.obproxy-functions/300.manage-a-obproxy-cluster/900.proxyro-user-management.md">proxyroアカウント管理</a>を参照してください。</li></ul></p>
      </main>

5. クラスタに接続すると、**<UI-TERM key="ocp-v2.Cluster.Component.ConfirmClusterDrawer.PreCheck">事前チェック</UI-TERM>** ページに移動し、システムが、クラスタの引き継ぎ要件を満たしているかどうかを自動的にチェックします。

   * クラスタ内の一部のOBServerに対応するホストがOCPによって管理されていない場合、関連情報を入力して、ホストを一括で引き継ぎます。
   * 実際の状況に応じて、**<UI-TERM key="ocp-v2.src.component.OcpAgentConfig.OcpAgentConfiguration">OCP Agentの設定</UI-TERM>** モジュールでOCP Agentポート、OCP Mgragentポート、およびOCP Monagentの仕様を設定し、ポートの占有やリソース不足による引き継ぎ失敗を防ぎます。

      <main id="notice" type='explain'>
      <h4>説明</h4>
      <p>高負荷業務やストレステストのシナリオでは、リソース不足によるOOM（メモリ不足）や監視データの損失を防ぐため、OCP Agentのリソース構成を向上させることを推奨します。</p>
      </main>

   * 事前チェックに失敗した場合、ページの指示に従ってOBServerノードの設定を変更し、変更後に **<UI-TERM key="ocp-v2.Cluster.Import.ReCheck">再確認する</UI-TERM>** をクリックします。

6. 事前チェックに合格したら、**<UI-TERM key="ocp-v2.Cluster.Import.Takeover">引き継ぐ</UI-TERM>** をクリックして引き継ぎタスクを開始します。結果ページでタスクの実行進捗を確認するか、クラスタ概要ページに戻ることができます。

## 次のステップ

* 引き継ぐクラスタにロードタイプが既に設定されている場合、クラスタを引き継いだ後、クラスタの **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページで再度ロードタイプを設定する必要があります。
* クラスタ内のテナントでTDE暗号化が有効になっている場合、クラスタを引き継いだ後、現在のOCP内で関連するテナントのTDE暗号化設定を完了してください。そうでない場合、OBServerの追加、新しいスタンバイテナントの作成、新しい暗号化テーブルスペースの作成などの機能が利用できなくなります。
* クラスタを引き継いだ後、元のクラスタまたはテナントのバックアップポリシーに基づいて、対応するバックアップポリシーを再設定してください。

## 関連操作

OCPがデータベースに接続するには、認証情報管理に対応する認証情報文字列が存在する必要があるため、クラスタの引き継ぎが完了した後、<a href="650.migrate-a-cluster.md">クラスタのエクスポート</a>で取得したクラスタ認証情報ファイルをこのOCPにインポートすることができます。これにより、クラスタの認証情報を一括でアップロードできます。具体的な操作手順については、<a href="../../1600.system-management-features/100.manage-password-box/300.import-a-credential.md">認証情報のインポート</a>を参照してください。
