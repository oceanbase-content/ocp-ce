# アービトレーションサービスの新規作成

このセクションでは、ホスト上にアービトレーションサービスを新規作成する方法について説明します。

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>この内容はOCP Enterprise版にのみ適用されます。OCP Community版はこの機能をサポートしていません。</p>
</main>

## 前提条件

* 現在OCPにログインしているユーザーが **ADMIN** ロールまたは **ORG_ADMIN** ロールであること。

* アービトレーションサービスを新規作成する際、選択したホストにOceanBaseクラスタが既にデプロイされていないこと。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Alarm.LogFilter.Cluster">クラスタ</UI-TERM>** をクリックします。システムはデフォルトで **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.Plan.Component.PlanTemplateTable.ArbitrationService">アービトレーションサービス</UI-TERM>** タブをクリックし、**<UI-TERM key="ocp-v2.src.constant.information.ArbitrationService">アービトレーションサービス</UI-TERM>** リストページに移動します。

4. 右上の **<UI-TERM key="ocp-v2.src.component.AddArbitrationDrawer.CreateArbitrationService">新規アービトレーションサービス</UI-TERM>** をクリックします。

5. **<UI-TERM key="ocp-v2.Cluster.Arbitration.CreateArbitrationService">新規アービトレーションサービス</UI-TERM>** パネルで、アービトレーションサービスの基本情報を設定します。

    |  パラメータ   |   説明   |
    |---------|----------|
    |ホスト   |  アービトレーションサービスをデプロイするホストを選択します。同一ホスト上で複数のアービトレーションサービスプロセスを起動できます。IPアドレスでホストを検索できるほか、[ホストの追加](../../850.host-features/100.manage-a-host/200.add-a-host.md) をクリックして利用可能なホストを追加することもできます。   |
    |サービスバージョン   |  リストから既存のOceanBaseクラスタバージョンを選択できます。選択したバージョンのハードウェアアーキテクチャは **<UI-TERM key="ocp-v2.component.alarm.AlarmTargetLabel.Host">ホスト</UI-TERM>** のアーキテクチャと一致している必要があります。また、ソフトウェアパッケージはV4.1以降のバージョンのみサポートしています。リストの下部で **バージョンの追加** をクリックし、必要なバージョンのソフトウェアパッケージをアップロードすることもできます。  |
    |OS所有者ユーザーの設定|OBServerのインストールおよび実行に使用するOSユーザーを設定します。編集はサポートされていません。[システムパラメータの変更](../../1600.system-management-features/500.manage-system-parameter/200.modify-system-parameters.md) を参照し、`ocp.operation.default.os.user` パラメータのデフォルト設定を調整することで、このユーザーを修正できます。<main id="notice" type='explain'><h4>説明</h4><code>ocp.operation.default.os.user</code> パラメータを変更しても、その変更は <a href="../200.create-a-cluster/100.create-a-distributed-cluster.md">分散型クラスタの作成</a>、<a href="../../800.obproxy-functions/200.create-an-obproxy-cluster.md">OBProxyクラスタの作成</a>、および <b>アービトレーションサービスの作成</b> の際にのみ反映され、既存のクラスタの他の設定には影響しません。</li></ul></main>|
    |ソフトウェアパス   |  ソフトウェアのインストールパスです。ホスト内のこのパスに対する **<UI-TERM key="ocp-v2.Cluster.New.Writing">書く</UI-TERM>** 権限が必要です。<ul><li>  **OS所有者ユーザー** が admin の場合、**<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>** はデフォルトで `/home/admin/oceanbase` となり、カスタムパスの設定も可能です。</li><li>**OS所有者ユーザー** が admin 以外の場合、**<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>** はデフォルトで `/opt/oceanbase/oceanbase` となり、カスタムパスの設定も可能です。</li></ul> |
    |サービスポート   |  デフォルトは2882ですが、実際の状況に応じて変更できます。選択したポートが使用されていないことを確認する必要があります。   |
    |説明   |  オプションです。アービトレーションサービスに関する補足説明を記述します。   |
    |パラメータ設定   | アービトレーションサービスの起動パラメータを設定します。関連するパラメータの説明については、本文末の **起動パラメータの説明** を参照してください。   |

6. **<UI-TERM key="ocp-v2.Detail.Component.FailoverDrawer.Determine">確定</UI-TERM>** をクリックします。ポップアップウィンドウ内のタスクIDをクリックすると、タスクの実行状態を確認できます。

    システムは入力された情報を検証します。検証に失敗した場合、ページの指示に従ってトラブルシューティングまたは修正を行うことができます。

## 起動パラメータの説明

以下の表は、OCPアービトレーションサービスの関連する起動パラメータを紹介したものです。より詳細なパラメータの説明については、[OceanBaseパラメータ](https://docs.oceanbase.com/oceanbase-database/V4.2.1-system-parameters-list)を参照してください。

|  パラメータ   |   機能の説明   |   説明   |
|---------|----------|----------|
| cpu_count |  CPU数  | OceanBaseデータベースを単独でデプロイする場合は、この値を設定する必要はありません。アービトレーションサービスは、マシンのCPU数を自動的に取得します。この値は、アービトレーションサービス内部の特定スレッドプールのスレッド数に影響します。  |
|   enable_syslog_recycle   |  ログファイルの自動リサイクルを有効にするかどうか。デフォルト値は`False`、推奨値は`True`  |   このパラメータを設定しない場合、OCPは自動的にパラメータ値を`True`に設定します。既にこのパラメータを手動で設定している場合、システムは設定された値を優先します。`max_syslog_file_count`パラメータを同時に設定して、保持するログファイルの数を指定することもできます。<main id="notice" type='notice'><h4>注意</h4>このパラメータは有効にすることを推奨します。無効の場合、ログディスクが満杯になり、アービトレーションサービスが利用不能になる可能性があります。</main>  |
| log_disk_percentage  |  Redoログがその配置ディスクの総容量に占める割合。デフォルト値は0   |  値の規則：<li>ログとデータが同一ディスクを共有する場合、Redoログがその配置ディスクの総容量に占める割合は30%です。</li><li>ログとデータがそれぞれ専用ディスクを持つ場合、Redoログがその配置ディスクの総容量に占める割合は90%です。</li> |
| log_disk_size  | Redoログディスクのサイズ。デフォルト値は0  |  この構成パラメータの値が0の場合、`log_disk_percentage`構成パラメータで設定された値に基づいてログディスク容量が割り当てられます。  |
|   max_syslog_file_count   |   最大で保持するログファイル数。デフォルト値は0、推奨値は100   |  このパラメータを設定しない場合、OCPは自動的にパラメータ値を100に設定します。既にこのパラメータを手動で設定している場合、システムは設定された値を優先します。    |
| memory_limit  |  OBServerプロセスが使用可能なメモリの上限。デフォルト値：ホスト物理メモリ × `memory_limit_percentage`  | OceanBase V4.1.0 BP1以降、アービトレーションサービスモードで起動する場合、このパラメータは最低1GBに設定できます。安定性の観点から、アービトレーションサービスモード以外で起動する場合、最低値は引き続き4GBです。 |
|  syslog_io_bandwidth_limit | 1秒間に出力されるログ量の上限。上限を超えるシステムログは破棄されます。デフォルト値は30MB |  必要に応じて調整できます。  |
| syslog_level  |   ログレベル。デフォルト値は`WDIAG`  |   デフォルト値のままにすることを推奨します。 |
|   system_memory   |   システムがテナントID`500`のテナント用に予約するメモリ容量。デフォルト値は0MB   |   デフォルト値のままにすることを推奨します。    |
| __easy_memory_limit |  単一observerノードへのRPCパケット送信メモリ上限。デフォルト値は4GB |  OceanBase V4.1.0 BP1以降、このパラメータの最小値は256MBに変更されました。   |
