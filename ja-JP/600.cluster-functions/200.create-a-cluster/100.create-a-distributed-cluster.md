# 分散型クラスタの作成

分散型クラスタは、OceanBaseのエンタープライズ向けネイティブ分散データベースアーキテクチャです。金融機関で求められる水準の高可用性とスムーズなスケーラビリティを備え、Oracle/MySQLモードとの高い互換性があります。データセキュリティに対する要求が高いコア業務システムに適しています。

ビジネスニーズに応じて、管理対象の分散型プライマリクラスタを作成できます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OCPでは、他のタイプのクラスタの作成もサポートしています：<ul><li><a href="200.create-a-standalone-centralized-cluster.md">集中型クラスタの作成</a>：集中型と分散型を統合したアーキテクチャに基づき、中小規模の業務シナリオに適しています。</li><li><a href="300.create-an-ai-cluster.md">AIクラスタの作成</a>：ストレージとコンピューティングを分離したアーキテクチャで、オブジェクトストレージをデータ永続化媒体として使用し、AI時代のワークロード専用に設計されています。</li></ul></p>
</main>

<main id="notice" type='notice'>
<h4>機能の適用範囲</h4>
<p>OCP Community版は、新規プライマリクラスタの作成のみをサポートしています。</p>
</main>

## 背景

* クラスタの **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.DeploymentMode">デプロイモード</UI-TERM>** が単一ゾーン・マルチホストの場合、OceanBaseサービスの計算能力のみが拡張され、複数レプリカによる高可用性は提供されません。開発・テスト環境に適しています。
* クラスタの **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.DeploymentMode">デプロイモード</UI-TERM>** が偶数ゾーンの場合、データの高可用性要件を満たせず、データセキュリティ上のリスクがあります。設定を調整し、奇数のアベイラビリティゾーン構成を維持するか、クラスタ/テナントでアービトレーションサービスを有効にすることを推奨します。

## 前提条件

* 現在OCPにログインしているユーザーが **ADMIN** ロールまたは **ORG_ADMIN** ロールであること。

* （オプション）マルチレプリカのOceanBaseクラスタを作成する場合、現在のOCP内に利用可能なOBProxyクラスタが存在している必要があります。以下のリンクを参照してOBProxyクラスタを新規作成できます。

  * [OBProxyクラスタの作成](../../800.obproxy-functions/200.create-an-obproxy-cluster.md)

  * [OBProxyの引き継ぎ](../../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md)

## 手順

### クラスタ作成ページへのアクセス

1. OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.component.alarm.Search.Cluster">クラスタ</UI-TERM>** をクリックして、**<UI-TERM key="ocp-v2.Cluster.Import.Cluster">クラスタ</UI-TERM>** の概要ページに移動します。実際のビジネスシナリオに基づいて、以下のいずれかの手順でクラスタ作成ページに移動します。

   1. 管理可能なクラスタがない場合、システムは **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブで新規クラスタの作成を促します。そのメッセージ内の **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">クラスタを作成する</UI-TERM>** をクリックします。

   2. 既に管理可能なクラスタがある場合、**<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブの右上隅にある **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">クラスタを作成する</UI-TERM>** をクリックします。

2. **<UI-TERM key="ocp-v2.page.Welcome.CreateACluster">クラスタを作成する</UI-TERM>** ページで、**<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">分散型クラスタ</UI-TERM>** モードを選択します。

### クラスタ基本情報の設定

分散型クラスタを作成するために必要な基本情報は以下のとおりです：

| 構成項目 | 説明 |
|-----|-------|
| **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.ClusterType">クラスタタイプ</UI-TERM>**          | **<UI-TERM key="ocp-v2.Cluster.New.MasterCluster">プライマリクラスタ</UI-TERM>** を選択します。  |
| **<UI-TERM key="ocp-v2.Component.DisconnectDrawer.ClusterName">クラスタ名</UI-TERM>**          | 管理対象のクラスタ名をカスタマイズします。クラスタ名は英字で始まり、英字または数字で終わる必要があります。英字、数字、アンダースコアを含むことができ、長さは2～32文字です。|
| **<UI-TERM key="ocp-v2.Cluster.New ROOTSysPassword">root@sysパスワード</UI-TERM>**    | カスタム設定またはランダム生成がサポートされています。パスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さは8～32文字</li><li>少なくとも数字(0～9)、大文字(A～Z)、小文字(a～z)、特殊文字の4種類のうち3種類を含みます。サポートされている特殊文字は <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code> です。  </li></ul>   |
| **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.ObVersion">OceanBaseのバージョン</UI-TERM>**         | リストから既存のOceanBaseクラスタバージョンを選択するか、リストの下部で **バージョンの追加** をクリックしてOceanBaseのバージョンをアップロードできます。  |
| **OBProxyクラスタの関連付け** | 複数レプリカのOceanBaseクラスタを作成する場合は、OBProxyクラスタの関連付けスイッチをオンにして、そのOceanBaseクラスタにOBProxyクラスタを関連付けることを推奨します。関連付け後、業務に関連するSQLリクエストは対応するレプリカに正確に転送されるため、OceanBaseデータベースへのアクセス効果は単一マシンデータベースへのアクセスに匹敵します。 </br>1. デフォルトではproxyroユーザーが使用されて関連付けられるため、ユーザー名とパスワードを入力する必要はありません。 </br>  2. ドロップダウンリストから関連付けるOBProxyクラスタを選択します。ドロップダウンリストに関連付け可能なOBProxyクラスタがない場合は、本記事の **前提条件** の説明を参照してOBProxyクラスタを追加してください。</br>関連付けるOBProxyクラスタには、以下の制限条件があります：<ul><li>OceanBaseクラスタとネットワークが一致し、かつ空でないOBProxyクラスタのみを選択できます。</li><li>OceanBaseクラスタのバージョンがV4.0以上の場合、V4.0.0以上のバージョンのOBProxyクラスタのみを関連付けることができます。</li></ul>    |
| **<UI-TERM key="ocp-v2.Tenant.New.LoadType">ワークロードタイプ</UI-TERM>**  | クラスタの負荷タイプを選択できます。負荷タイプは主にSQLクエリの判断時間に影響します(パラメータ：large_query_threshold)。OLTPタイプの負荷のRTに大きな影響を与える可能性があるため、慎重に選択する必要があります。OCPは5種類のクラスタ負荷タイプをサポートしており、具体的な説明は以下のとおりです。<ul><li>**Express OLTP**：貿易、決済基幹システム、インターネット高スループットアプリケーションなどのワークロードに適しています。外部キーなどの制約がなく、ストアドプロシージャ、長トランザクション、大規模トランザクション、複雑な結合、複雑な副問い合わせもありません。<br>バージョン制限：OceanBase V4.2.5以上に適用されます。</li><li>**HTAP**：OLAPとOLTPのハイブリッドワークロードに適しています。通常、アクティブな運用データ、不正検出、パーソナライズド提案から即時の洞察を得るために使用されます。<br>バージョン制限：OceanBase V4.2.5以上に適用されます。</li><li>**OLAP**：リアルタイムデータウェアハウス分析シナリオに使用されます。<br>バージョン制限：OceanBase V4.3.0以上に適用されます。</li><li>**Complex OLTP**：銀行、保険システムなどのワークロードに適しています。これらは通常、複雑な結合、複雑な相関副問い合わせ、PLで記述されたバッチ処理ジョブ、長トランザクション、大規模トランザクションを伴います。短時間で実行されるクエリでは、パラレル実行が使用されることがあります。<br>バージョン制限：OceanBase V4.2.5以上に適用されます。</li><li>**OBKV**：キー値ワークロードやHBaseライクなワイドカラムワークロードに使用されます。これらのワークロードは通常、非常に高いスループットを持ち、レイテンシに敏感です。<br>バージョン制限：OceanBase V4.2.5以上に適用されます。</li></ul>   |

### Cgroupの設定

Cgroupは主にOceanBaseクラスタ内のテナント間およびテナント内のCPUリソース分離に使用されます。実際のビジネスタイプに応じて、クラスタでCgroupを有効にするかどうかを選択し、より強力なCPU/IOPSの分離を実現できます。作成するOceanBaseクラスタがV4.0以降のバージョンの場合、システムはデフォルトでCgroupを有効にします。

* Cgroupを有効にすると、パフォーマンスが約7%低下します。ビジネスシナリオが単一テナント、小規模構成(<14C)であり、かつより高いデータベースパフォーマンスが必要な場合は、Cgroupを無効にすることを推奨します。
* ホストのOSカーネルバージョンが5.1.0未満の場合、クラスタのCgroupを無効にすることを推奨します。そうでない場合、システムのパフォーマンス低下や不安定を引き起こす可能性があります。
* ホストのOSカーネルバージョンが4.1.9未満の場合、クラスタでテナントを作成できません。この場合、システムはデフォルトでCgroupを無効にし、Cgroupスイッチは表示されません。

### CPUオーバーコミットの設定

異なるビジネスシナリオの負荷が重なると、OceanBaseクラスタの運用中に過負荷などが発生し、異なるテナント間でスレッド間でCPUリソースの競合が生じ、結果として業務処理が遅くなることがあります。システム内の異なるテナント負荷が制御可能に交互に実行されるようにするため、CPUリソースの設定時にオーバーコミットを設定することでリソース利用率を向上させることができます。

<main id="notice" type='explain'>
<h4>説明</h4>
<p><ul><li>CPUのオーバーコミット割り当ては、OceanBase V4.0以降のバージョンでのみサポートされています。適切に設定することで、ハードウェアリソースを最大限に活用できます。</li><li>CPUオーバーコミット機能はCgroupに依存しています。CPUオーバーコミット率を設定する前に、クラスタでCgroupを有効にしてください。</li></ul>
</p></main>

**<UI-TERM key="ocp-v2.Cluster.New.CpuOversoldSettings">CPUオーバーコミット設定</UI-TERM>** モジュールでは、スライダーまたは入力ボックスを使用してオーバーコミット率を設定できます。デフォルト値は120%で、値の範囲は101%～200%です。

### JVM環境依存サービスの設定

**JVM環境依存サービス**を有効にすると、OBServerはJNI（Java Native Interface）フレームワークを通じて外部テーブル、Java UDF、ODPSリモートアクセスなどの機能と連携できます。

<main id="notice" type='notice'>
<h4>注意</h4>
<p><ul><li>JVM環境依存サービスの設定は、OceanBase V4.3.5.1以降のバージョンでのみサポートされています。</li><li><a href='https://docs.oceanbase.com/oceanbase-database/V4.4.2-deploy-oceanbase-java-sdk-environment'>OceanBaseデータベースJAVA SDK環境のデプロイ</a>を参照し、<a href='../../1500.manage-software-packages/100.upload-a-software-package.md'>ソフトウェアパッケージのアップロード</a>機能を使用して、サービスが依存するJARパッケージライブラリを事前にアップロードし、OBServerが正常にロードして使用できるようにしてください。</li><li>このサービスはJava環境に依存します。クラスタ内にJava環境がまだ設定されていないマシンがある場合は、ご自身で設定してください：<ul><li>ホストがaarch64（ARM64）アーキテクチャの場合は、OpenJDKが15以降であることを確認してください。</li><li>ホストがその他のアーキテクチャの場合は、OpenJDKが11以降であることを確認してください。</li></ul>
</p></main>

1. サービスタイプを設定します。

   OCPはODPS外部テーブル、HDFS外部テーブル、Java UDF、ODPS Catalog、MySQL外部テーブルプラグインの5種類のサービスをサポートしており、サービスによってOceanBaseクラスタのバージョン要件が異なります。詳細は次の表を参照してください。

   | サービスタイプ        | OceanBaseバージョン要件  |
   |-----------------|-----------------|
   | ODPS外部テーブル       | [V4.3.5.1, +∞)  |
   | HDFS外部テーブル       | [V4.3.5.1, +∞)  |
   | Java UDF        | [V4.3.5.1, +∞)  |
   | ODPS Catalog    | [V4.4.0, +∞)    |
   | MySQL外部テーブルプラグイン   | [V4.4.1, +∞)   |

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>サービスタイプを設定する際、ODPS外部テーブル、HDFS外部テーブル、Java UDF、ODPS Catalogの4種類のサービスタイプはデフォルトで有効になっており、無効にすることはできません。</p></main>

2. JVMメモリを設定します。

   適切なJVMメモリ設定は、Javaアプリケーションの安定性とパフォーマンスに直接影響します。JVMメモリを設定することで、OceanBaseクラスタ内でJavaアプリケーションを実行するために必要なメモリを確保できます。OBServerノードのメモリ仕様に応じて、事前定義されたJVMメモリ設定オプションは以下のとおりです：

   | OBServerノードのメモリ容量  | -Xmx/-Xms            | -Dio.netty.maxDirectMemory  | JVMメモリ合計  |
   |--------------------|----------------------|-----------------------------|--------------|
   | 16 GiB             | 512 MiB              | 512 MiB                     | 1 GiB        |
   | 32 GiB             | 1 GiB                | 1 GiB                       | 2 GiB        |
   | 70 GiB             | 3 GiB                | 3 GiB                       | 6 GiB        |

3. JAVA_HOMEパスを設定します。

   JVM環境依存サービスを有効にした後、手動でJAVA_HOMEパスを入力する必要があります。クラスタ内のすべてのOBServerのJAVA_HOMEパスが完全に一致していることを必ず確認してください。

### クラスタパラメータの設定

**<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.ParameterSettings">パラメータ設定</UI-TERM>**モジュールを開くと、クラスタパラメータをカスタマイズして設定できます。

* **<UI-TERM key="ocp-v2.Tenant.New.BasicSettings">基本設定</UI-TERM>**で負荷タイプを設定した場合、システムはその負荷タイプに対応するパラメータテンプレートをデフォルトで選択します。

* 起動パラメータ項目を追加し、それぞれに値を設定することができます。

* また、**<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">パラメータテンプレートを選択</UI-TERM>**をクリックし、パラメータテンプレートを選択することもできます。システムは、テンプレート内のパラメータと設定を自動的にここに入力します。クラスタパラメータテンプレートが作成されていない場合は、**新規クラスタテンプレート**をクリックして、クラスタのためにパラメータテンプレートを作成できます。詳細については、[クラスタパラメータテンプレートの管理](../1400.cluster-parameters-template-management.md)を参照してください。

   | KV Default Parameter Template   | **OBKV** ロードタイプに対応しており、このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用可能です。   |

### ユーザー、パス、ポートの設定

**<UI-TERM key="ocp-v2.Cluster.New.CustomSettings">カスタム設定</UI-TERM>**モジュールでは、クラスタレベルのユーザー設定（オペレーティングシステムの所有者ユーザーなど）、パス設定（ソフトウェアインストールパス、データディスクパス、ログディスクパスなど）、およびポート設定（SQLポート、RPCポートなど）を実行できます。

1. オペレーティングシステム所有者ユーザーの設定：

   このユーザーは、OBServerのインストールと実行を行うオペレーティングシステムのユーザーであり、編集はサポートされていません。`ocp.operation.default.os.user`パラメータのデフォルト設定を調整することでこのユーザーを変更できます。このパラメータの変更は、分散クラスタの作成、[単一マシンの作成](200.create-a-standalone-centralized-cluster.md)、[AIクラスタの作成](300.create-an-ai-cluster.md)、[OBProxyクラスタの作成](../../800.obproxy-functions/200.create-an-obproxy-cluster.md)、および[アービトレーションサービスの作成](../1350.manage-arbitration-services/200.create-arbitration-services.md)時にのみ反映され、既存のクラスタの他の設定には影響しません。

2. 関連パスの設定：

   |   設定   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**   | <ul><li>**オペレーティングシステム所有者ユーザー**がadminの場合、**<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**はデフォルトで`/home/admin/oceanbase`に設定され、カスタマイズ可能です。</li><li>**オペレーティングシステム所有者ユーザー**がadmin以外の場合、**<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**はデフォルトで`/opt/oceanbase/oceanbase`に設定され、カスタマイズ可能です。</li></ul>   |
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DataDiskPath">データディスクのパス</UI-TERM>**       | デフォルトは`/data/1`で、カスタマイズ可能です。  |
   | **<UI-TERM key="ocp-v2.Cluster.New.LogDiskPath">ログディスクのパス</UI-TERM>**   | デフォルトは`/data/log1`で、カスタムパスをサポートします。本番環境では、OceanBaseデータベースではログディスク容量をホストメモリ容量の3倍以上に設定することを推奨します。また、ディスク使用量の収集問題を回避するため、データディレクトリ、インストールディレクトリ、ログディレクトリを異なるディスクにマウントすることを推奨します。<main id="notice" type='explain'><h4>説明</h4>OCP 4.3.0 BP1以降、以下のバージョンのOceanBaseクラスタを作成する場合、slogディレクトリはログディスクに配置され、データディスクとは紐づけられなくなりました。この場合、<code>log_disk_size=0</code>を設定すると、clog専用と見なされ、デフォルトで<code>log_disk_percentage</code>は90%に設定されます。もしslogとclogが配置されるディスクのサイズが40GiB未満の場合、slog用に予約される空き容量は4GiBに満たず、slogの書き込みに影響を与える可能性があります。<ul><li>V4.2.4.0 ≤ OceanBase < V4.3.0.0</li><li>OceanBase ≥ V4.3.1.0</li></ul>slogに関する詳細は、<a href="https://docs.oceanbase.com/oceanbase-database/V4.2.1-observer-installation-directory-structure">OBServerノードのインストールディレクトリ構造</a>を参照してください。</main>      |

3. ポートの設定：

   |   設定   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Cluster.New.SqlPort">SQLポート</UI-TERM>**        | デフォルトは2881で、カスタマイズ可能です。  |
   | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.RpcPort">RPCポート</UI-TERM>**   | デフォルトは2882で、カスタマイズ可能です。     |

4. 設定完了後、**<UI-TERM key="ocp-v2.Cluster.New.Test">テスト</UI-TERM>**をクリックし、入力したパスとポートが利用可能か確認します。

### 設定情報の確認

1. 右側のパネルで、設定したクラスタ情報に誤りがないことを確認し、**<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">次のステップ</UI-TERM>**をクリックします。

2. 作成前の事前チェックを実行し、システムは環境が分散プライマリクラスタの作成に必要な最低要件を満たしているか検証します。チェック項目の実行に失敗した場合、ヒントに従って以下の操作を行うことができます：

    * **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.Upload">アップロード</UI-TERM>**：特定のチェック項目が失敗した場合にのみ表示されます。ヒントに従い、**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.Upload">アップロード</UI-TERM>**をクリックして、必要なソフトウェアパッケージを手動でアップロードしてください。
    * **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.SetToSuccessful">スキップ</UI-TERM>**：この操作は現在のチェック項目をスキップします（特殊なシナリオ向け）。関連するチェック項目が製品仕様を満たしていることを必ず確認してください。そうでない場合、後続のプロセスが失敗する可能性があります。スキップ後、そのチェック項目の状態は**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.Warning">警告</UI-TERM>**に変わります。
    * **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.ReRun">再試行</UI-TERM>**：失敗の原因と最適化の提案に基づいて問題を調査・修正し、修正後に**<UI-TERM key="ocp-v2.Sop.Main.TaskCard.Retry">再試行</UI-TERM>**をクリックして、失敗したチェック項目を再実行します。
    * **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**：すべての問題が調査・修正された後、**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**をクリックして、すべての失敗したチェック項目を再実行します。

3. 実行失敗のチェック項目がなくなったら、**<UI-TERM key="ocp-v2.External.Component.CreateEsDataSource.New">新規作成</UI-TERM>**をクリックします。

   新規クラスタタスクを送信すると、**<UI-TERM key="ocp-v2.External.AIModel.MissionCenter">タスクセンター</UI-TERM>**でそのタスクの実行進捗を確認できます。
