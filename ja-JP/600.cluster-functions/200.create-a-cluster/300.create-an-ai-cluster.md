# AIクラスタの作成

OceanBase Database AIは、ストレージとコンピューティングを分離したアーキテクチャを採用した新世代の分散データベースであり、AI時代のワークロードに特化しています。AIクラスタは、オブジェクトストレージ（例：S3）をデータ永続化の主要な媒体とし、コンピューティングノードにはローカルキャッシュディスクのみを保持することで、ストレージとコンピューティングの分離を実現します。これにより、弾力的なスケーラビリティや低コストなストレージといった利点が得られます。

本記事では、AIクラスタの作成方法について説明します。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>OCPでは、他のタイプのクラスタの作成もサポートしています：<ul><li><a href="100.create-a-distributed-cluster.md">分散型クラスタの作成</a>：エンタープライズ向けのネイティブ分散データベースアーキテクチャで、金融級の高可用性とスムーズなスケーラビリティを備えています。</li><li><a href="200.create-a-standalone-centralized-cluster.md">集中型</a>：集中型と分散型を統合したアーキテクチャに基づき、中規模から小規模のビジネスシナリオに適しています。</li></ul></p>
</main>

## 背景

AIクラスタはストレージとコンピューティングを分離したアーキテクチャを採用しており、作成前に以下の依存コンポーネントを準備する必要があります：

* **オブジェクトストレージ**：AIクラスタのデータ永続化メディアであり、すべての業務データを格納します。事前にOCPの**システム管理 > 外部連携**でオブジェクトストレージの設定を作成しておく必要があります。詳細については、[オブジェクトストレージの概要](../../1600.system-management-features/450.manage-external-integration/500.manage-object-storage/100.object-storage-overview.md)を参照してください。

* **Logserviceクラスタ**：AIクラスタにログサービス機能を提供し、AIクラスタと一対一の関係にあります。事前に作成しておく必要があります。詳細については、[Logserviceクラスタの新規作成](../../855.logservice-instance-functions/300.manage-a-logservice-cluster/200.create-a-logservice-cluster.md)を参照してください。

### Shared-Nothing分散クラスタとの比較

AIクラスタは共有ストレージ(Shared Storage)アーキテクチャを採用しており、従来のShared-Nothing分散クラスタとの主な違いは以下の通りです：

* **データストレージ**：ベースラインデータとメタデータはオブジェクトストレージに保存され、ローカルデータディスクではありません。ローカルディスクはキャッシュディスクとしてのみ使用され、ホットデータをキャッシュします。
* **オブジェクトストレージ**：クラスタ作成時にオブジェクトストレージの接続情報（Bucket名、Endpoint、アクセスキーなど）を指定する必要があります。カーネルはBootstrapフェーズでオブジェクトストレージ情報をクラスタに注入します。
* **キャッシュディスク管理**：`datafile_size`と`datafile_disk_percentage`パラメータを使用してローカルキャッシュディスク容量を制御します。従来のモードではデータファイルサイズを制御します。
* **テナントリソース**：テナント作成時に`DATA_DISK_SIZE`（キャッシュディスク容量）や`MAX_NET_BANDWIDTH`（最大ネットワーク帯域幅）などのフィールドが追加されました。これらは共有ストレージモードでテナントのキャッシュ容量を割り当てるために使用されます。

### メモリ計画

AIクラスタとLogserviceクラスタを同一マシンにデプロイする場合（ハイブリッド環境）、両者のメモリ使用量を事前に計画し、メモリ不足を防ぐ必要があります。推奨設定は以下の通りです：

  * **Logserviceクラスタ**：Logserviceクラスタ作成時に`memory_limit`パラメータを設定し、メモリ使用量を制限します。ログ量と業務要件に応じて、Logserviceのメモリを適切な範囲に制限することを推奨します。

  * **AIクラスタ**：AIクラスタ作成時にも`memory_limit`パラメータを設定し、メモリ使用量を制限します。業務負荷と同時実行要件に応じて、AIクラスタのメモリリソースを適切に割り当てます。

## 前提条件

* 現在OCPにログインしているユーザーが **ADMIN** 機構または **ORG_ADMIN** 機構であること。

* 利用可能なオブジェクトストレージサービス（Alibaba Cloud OSS、AWS S3、Tencent Cloud COS、Huawei Cloud OBSなど）を準備し、対応するアクセス資格情報を取得していること。

* オブジェクトストレージの設定が完了していること。オブジェクトストレージサービスは以下の条件を満たしている必要があります。詳細については、[オブジェクトストレージの設定](../../1600.system-management-features/450.manage-external-integration/500.manage-object-storage/200.create-an-object-storage.md)を参照してください。

  * オブジェクトストレージへのアクセスに使用するAccessKey IDとAccessKey Secretを取得済みであること。
  * Bucketを作成済みで、そのBucketに正常にアクセスできること。
  * オブジェクトストレージのEndpointアドレスを取得済みであること。

* LogServiceクラスタの作成が完了していること。詳細については、[LogServiceクラスタの作成](../../855.logservice-instance-functions/300.manage-a-logservice-cluster/200.create-a-logservice-cluster.md)を参照してください。

* （オプション）作成したAIクラスタがOBProxy経由でアクセスされる場合、現在のOCP内に利用可能なOBProxyクラスタが存在している必要があります。以下のリンクを参照してOBProxyクラスタを追加できます。

  * [OBProxyクラスタの作成](../../800.obproxy-functions/200.create-an-obproxy-cluster.md)

  * [OBProxyの引き継ぎ](../../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md)

## 手順

### クラスタ作成ページへのアクセス

1. OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.components.commercial.NodeAllocationSection.Cluster">クラスタ</UI-TERM>** をクリックして、**<UI-TERM key="ocp-v2.page.Overview.Cluster">クラスタ</UI-TERM>** の概要ページに移動します。実際のビジネスシナリオに応じて、新規クラスタの作成エントリを見つけます。

   1. 管理可能なクラスタがない場合、システムは **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブで新規クラスタの作成を促します。そのヒントメッセージ内の **<UI-TERM key="ocp-v2.Tenant.New.CreateACluster">クラスタを作成する</UI-TERM>** をクリックします。

   2. 既に管理可能なクラスタがある場合は、**<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** タブの右上隅にある **<UI-TERM key="ocp-v2.page.Welcome.CreateACluster">クラスタを作成する</UI-TERM>** をクリックします。

2. **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">クラスタを作成する</UI-TERM>** ページで、**<UI-TERM key="ocp-v2.src.constant.oceanbase.AiCluster">AIクラスタ</UI-TERM>** を選択します。

### クラスタ基本情報の設定

AIクラスタを作成するために必要な基本情報は以下のとおりです：

| パラメータ  |   説明   |
|-------|-------|
| **<UI-TERM key="ocp-v2.pages.Kubernetes.ClusterName">クラスタ名</UI-TERM>**          | 管理対象のクラスタ名をカスタマイズします。クラスタ名は英字で始まり、英字または数字で終わる必要があります。英字、数字、アンダースコアを含み、長さは2～32文字である必要があります。|
| **<UI-TERM key="ocp-v2.Cluster.New.RootSysPassword">root@sysのパスワード</UI-TERM>**    | カスタム設定またはランダム生成が可能です。パスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さが8～32文字です。</li><li>少なくとも数字(0～9)、大文字(A～Z)、小文字(a～z)、特殊文字の4種類のうち3種類を含みます。サポートされている特殊文字は <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code> です。  </li></ul>   |
| **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBaseのバージョン</UI-TERM>**         | リストから既存のOceanBaseクラスタバージョンを選択します。リストに必要なバージョンがない場合は、リストの下部にある **バージョンの追加** をクリックしてアップロードできます。<main id="notice" type='explain'><h4>説明</h4>AIクラスタはOceanBase AIクラスタバージョンのみをサポートしています。shared_storageモードをサポートするバージョンを選択してください。</main>  |
| **OBProxyクラスタの関連付け** | OBProxyを介してAIクラスタにアクセスする必要がある場合は、OBProxyクラスタの関連付けスイッチをオンにして、このOceanBaseクラスタにOBProxyクラスタを関連付けることができます。<ul><li>デフォルトではproxyroユーザーが関連付けられます。ユーザー名とパスワードを入力する必要はありません。</li><li>ドロップダウンリストから関連付けるOBProxyクラスタを選択します。ドロップダウンリストに関連付け可能なOBProxyクラスタがない場合は、本記事の **前提条件** の説明を参照してOBProxyクラスタを追加してください。</li></ul>関連付けるOBProxyクラスタには、以下の制限があります：<ul><li>OceanBaseクラスタとネットワークが一致し、かつ空でないOBProxyクラスタのみを選択できます。</li><li>V4.0.0以降のバージョンのOBProxyクラスタのみをサポートしています。</li></ul>    |

### クラスタのデプロイメントモードの設定

デフォルトでは2つのZoneの情報が追加されます。デプロイするクラスタのZone数が2つより多い場合は、下部の **<UI-TERM key="ocp-v2.components.LogServiceZoneFormList.AddZone">ゾーンを追加</UI-TERM>** ボタンをクリックしてZone情報を追加できます。デプロイするクラスタのZone数が2つ未満の場合は、Zoneの後ろにある削除アイコンをクリックできます。

各Zoneに設定が必要な情報とその説明は、次の表のとおりです。

|   設定   |  描述   |
|-----|-------|
| **<UI-TERM key="ocp-v2.Component.UpgradeDrawer.PackageSystemList.ZoneName">ゾーン名</UI-TERM>**    | デフォルトのままでも、カスタマイズでもかまいません。Zone名は英字で始まる必要があり、大文字小文字、数字、アンダースコアをサポートし、長さは2～32文字です。  |
| **<UI-TERM key="ocp-v2.src.component.IdcSelect.ComputerRoom">データセンター</UI-TERM>**     | Zoneが存在するデータセンターです。1つのZoneは1つのデータセンターにのみ存在できます。  |
| **<UI-TERM key="ocp-v2.OBProxy.New.DeployMode.Models">機種</UI-TERM>**    | オプションです。機種を選択すると、後続のホストリストが機種に応じてフィルタリングされます。   |
| **<UI-TERM key="ocp-v2.Cluster.New.CpuArchitecture">CPUアーキテクチャ</UI-TERM>**    |  **<UI-TERM key="ocp-v2.Detail.Component.UpgradeModal.ObVersion">OceanBase バージョン</UI-TERM>** で複数の異なるアーキテクチャのインストールパッケージが存在する場合、このソフトウェアパッケージに対応するホストのハードウェアアーキテクチャを選択する必要があります。<main id="notice" type='notice'><h4>注意</h4>異なるZoneに異なるアーキテクチャを設定する場合、ハイブリッドアーキテクチャのデプロイメントモードでは安定性とパフォーマンスの問題が発生する可能性があるため、慎重に操作してください。</main> |
| **<UI-TERM key="ocp-v2.src.constant.monitor.Host">ホスト</UI-TERM>**  | 複数のホストを選択するか、ホストの追加操作を行うことができます。   |
| **Root Serviceの場所**     | Root Serviceが配置されるマシンとしてIPアドレスを選択する必要があります。マルチレプリカのOceanBaseクラスタでは、各Zoneにroot Serviceを指定する必要があります。   |
| **<UI-TERM key="ocp-v2.Tenant.New.ZonePrioritySorting">ゾーン優先順位</UI-TERM>**  | クラスタのsysテナントのプライマリレプリカの分散に優先順位を指定するかどうかを選択します。<ul><li>指定した場合、最も高い優先順位を持つZoneがPrimary Zoneと見なされ、それは1つだけになります。</li><li>指定しない場合、デフォルトでprimary_zone=RANDOM（ランダム分散）になります。</li></ul>    |

### データストレージ

AIクラスタはストレージとコンピューティングを分離したアーキテクチャを採用しており、データは主にオブジェクトストレージに保存されます。このモジュールは、AIクラスタのデータストレージ関連パラメータを設定するために使用されます。

|   設定   |  描述   |
|-----|-------|
| **オブジェクトストレージ設定**    | Access Key、Secret Key、Endpointなどの接続情報を含む、既に作成されたオブジェクトストレージ設定を選択します。  |
| **ストレージディレクトリ**     | データのオブジェクトストレージ内の保存パスを指定します。形式は`s3://my-bucket/my-data`です。   |
| **Logserviceクラスタ**    | AIクラスタにログサービスを提供するために、既に作成されたLogserviceクラスタを選択します。   |

<main id="notice" type='explain'>
<h4>説明</h4>
<p>AIクラスタを作成する前に、事前にOCPでオブジェクトストレージ設定とLogserviceクラスタを作成する必要があります。</p></main>

### CPUオーバーコミットの設定

異なる業務シナリオの負荷が重複する場合、OceanBaseクラスタは運用中に過負荷状態に陥る可能性があります。これにより、異なるテナント間でスレッドがCPUを競合し、実際の業務シナリオの処理速度が低下することがあります。システム内の異なるテナントの負荷が制御可能に交互に実行されるようにするために、CPUリソースの設定時にオーバーコミットを設定することでリソース利用率を向上させることができます。

**CPUオーバーコミット設定**モジュールでは、スライダーまたは入力ボックスを使用してオーバーコミット率を設定できます。デフォルト値は120%で、値の範囲は101%〜200%です。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>CPUのオーバーコミット割り当ては、OceanBase 4.0以降のバージョンでのみサポートされています。</p></main>

### JVM環境依存サービスの設定

**JVM環境依存サービス**を有効にすると、OBServerはJNI（Java Native Interface）フレームワークを通じて外部テーブル、Java UDF、ODPSリモートアクセスなどの機能と連携できます。

<main id="notice" type='notice'>
<h4>注意</h4>
<p><ul><li>JVM環境依存サービスの設定は、OceanBase V4.3.5.1以降のバージョンでのみサポートされています。</li><li><a href='https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003976539'>OceanBaseデータベースJAVA SDK環境のデプロイ</a>を参照し、事前に<a href='../../1500.manage-software-packages/100.upload-a-software-package.md'>ソフトウェアパッケージのアップロード</a>機能を使用して、サービスに依存するJARパッケージライブラリをアップロードし、OBServerが正常にロードして使用できることを確認してください。</li><li>このサービスはJava環境に依存します。クラスタ内にJava環境がまだ設定されていないマシンがある場合は、ご自身で設定してください：<ul><li>ホストがx86_64アーキテクチャの場合は、OpenJDKが15以降であることを確認してください。</li><li>ホストがその他のアーキテクチャの場合は、OpenJDKが11以降であることを確認してください。</li></ul>
</p></main>

1. サービスタイプを設定します。

   OCPはODPS外部テーブル、HDFS外部テーブル、Java UDF、ODPS Catalog、MySQL外部テーブルプラグインの5種類のサービスをサポートしており、サービスによってOceanBaseクラスタのバージョン要件が異なります。詳細は以下の表を参照してください。

   | サービスタイプ        | OceanBaseバージョン要件  |
   |-----------------|-----------------|
   | ODPS外部テーブル       | [V4.3.5.1, +∞)  |
   | HDFS外部テーブル       | [V4.3.5.1, +∞)  |
   | Java UDF        | [V4.3.5.1, +∞)  |
   | ODPS Catalog    | [V4.4.0, +∞)    |
   | MySQL外部テーブルプラグイン   | [V4.4.1, +∞)   |

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>サービスタイプを設定する際、ODPS外部テーブル、HDFS外部テーブル、Java UDF、ODPS Catalogの4種類のサービスタイプはデフォルトで有効になっており、無効にすることはできません。</p></main>

2. JVMメモリを設定します。

   適切なJVMメモリ設定は、Javaアプリケーションの安定性とパフォーマンスに直接影響します。JVMメモリを設定することで、OceanBaseクラスタ内でJavaアプリケーションの基本的な実行ニーズを確保できます。OBServerノードのメモリ仕様に応じて、事前定義されたJVMメモリ設定オプションは以下のとおりです：

   | OBServerメモリノード  | -Xmx/-Xms            | -Dio.netty.maxDirectMemory  | JVMメモリ合計  |
   |--------------------|----------------------|-----------------------------|--------------|
   | 16 GiB             | 512 MiB              | 512 MiB                     | 1 GiB        |
   | 32 GiB             | 1 GiB                | 1 GiB                       | 2 GiB        |
   | 70 GiB             | 3 GiB                | 3 GiB                       | 6 GiB        |

3. JAVA_HOMEパスを設定します。

   JVM環境依存サービスを有効にした後、手動でJAVA_HOMEパスを入力する必要があります。クラスタ内のすべてのOBServerのJAVA_HOMEパスが完全に一致していることを必ず確認してください。

### クラスタパラメータの設定

**<UI-TERM key="ocp-v2.Component.AddZoneDrawer.ParameterSettings">パラメータ設定</UI-TERM>**モジュールでは、クラスタパラメータをカスタマイズして設定できます。

* **<UI-TERM key="ocp-v2.New.Content.ParameterSettings.AddStartupParameters">起動パラメータを追加</UI-TERM>**をクリックすると、起動パラメータ項目を個別に追加し、パラメータ値を設定できます。

* `memory_limit`パラメータを設定します。具体的なパラメータ値と取り得る範囲については、カーネルドキュメントを参照してください。

* **テンプレートを選択して自動入力**をクリックすると、ドロップダウンリストからパラメータテンプレートを選択できます。システムはテンプレート内のパラメータ設定をここに自動入力します。

  * システムは以下の6種類の組み込みテンプレートを提供しており、テンプレートには一般的なパラメータ設定が含まれています。これらのテンプレートを直接適用してクラスタの初期設定を行うことができます。システムの組み込みテンプレートについての詳細は以下のとおりです。

    | テンプレート |  説明 |
    |------|------|
    | COMPLEX_OLTPパラメータテンプレート   | **Complex OLTP**負荷タイプに対応しており、このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。   |
    | KVパラメータテンプレート   |  **OBKV**負荷タイプに対応しており、このテンプレートはOceanBase V4.2.5以降のバージョンでのみ適用されます。   |
    | OLAPパラメータテンプレート   |  デフォルトテンプレートで、**OLAP**負荷タイプに対応しており、このテンプレートはOceanBase V4.3.0以降のバージョンでのみ適用されます。   |

  * **新しいクラスターパラメータテンプレートを作成**をクリックすることもできます。これにより、クラスター専用のパラメータテンプレートを作成できます。詳細については、[クラスターパラメータテンプレートの管理](../1400.cluster-parameters-template-management.md)を参照してください。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>AIクラスター（shared-storageモード）では、以下のパラメータの意味が従来のクラスター（shared-nothingモード）とは異なります：<ul><li><code>datafile_size</code>：データファイルサイズではなく、サーバーレベルのキャッシュ容量を設定します。</li><li><code>datafile_disk_percentage</code>：サーバーレベルで利用可能なキャッシュ容量がディスク総容量に占める割合を設定します。範囲は[0, 99]です。</li><li><code>datafile_next</code>、<code>datafile_maxsize</code>、<code>_datafile_usage_upper_bound_percentage</code>、<code>_datafile_usage_lower_bound_percentage</code>：shared-storageモードではサポートされていません。</li></ul>クラスターレベルのCPU、メモリ、およびキャッシュディスクの使用についてカスタマイズした変更が必要な場合は、以下のパラメータを設定してください：<code>cpu_count</code>、<code>memory_limit_percentage</code>、<code>system_memory</code>、<code>datafile_size</code>、<code>datafile_disk_percentage</code>。具体的なパラメータの説明については、OceanBase公式Webサイトの<a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000640281">クラスターパラメータ一覧</a>を参照してください。
</p></main>

### カスタム設定

**<UI-TERM key="ocp-v2.OBProxy.New.CustomSettings">カスタム設定</UI-TERM>**モジュールでは、クラスタレベルのユーザー設定（オペレーティングシステムの所有者ユーザーなど）、パス設定（ソフトウェアインストールパス、キャッシュディスクパスなど）、ポート設定（SQLポート、RPCポートなど）を実行できます。

1. オペレーティングシステム所有者ユーザーの設定：

   このユーザーは、OBServerのインストールと実行を行うオペレーティングシステムのユーザーであり、編集はサポートされていません。`ocp.operation.default.os.user`パラメータのデフォルト設定を調整することで、このユーザーを変更できます。このパラメータの変更は、[分散型クラスタの作成](100.create-a-distributed-cluster.md)、[集中型クラスタの作成](200.create-a-standalone-centralized-cluster.md)、AIクラスタの作成、[OBProxyクラスタの作成](../../800.obproxy-functions/200.create-an-obproxy-cluster.md)、および[アービトレーションサービスの作成](../1350.manage-arbitration-services/200.create-arbitration-services.md)時にのみ反映され、既存のクラスタの他の設定には影響しません。

2. 関連パスの設定：

   |   設定   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**   | <ul><li>**オペレーティングシステム所有者ユーザー**がadminの場合、**<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**はデフォルトで`/home/admin/oceanbase`に設定され、カスタマイズ可能です。</li><li>**オペレーティングシステム所有者ユーザー**がadmin以外の場合、**<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**はデフォルトで`/opt/oceanbase/oceanbase`に設定され、カスタマイズ可能です。</li></ul>   |
   | **<UI-TERM key="ocp-v2.components.MainContent.CacheDiskPath">キャッシュディスクのパス</UI-TERM>**       | デフォルトは`/data/1`で、カスタマイズ可能です。AIクラスタでは、ローカルディスクがキャッシュディスクとして使用され、ホットベースラインデータやダンプデータをキャッシュしますが、すべてのデータを永続的に保存するわけではありません。  |

3. 関連ポートの設定：

   |   設定   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Component.OBServerList.SqlPort">SQLポート</UI-TERM>**        | デフォルトは2881で、カスタマイズ可能です。  |
   | **<UI-TERM key="ocp-v2.Component.OBServerList.RpcPort">RPCポート</UI-TERM>**   | デフォルトは2882で、カスタマイズ可能です。     |

4. 設定完了後、**<UI-TERM key="ocp-v2.OBProxy.New.Test">テスト</UI-TERM>**をクリックし、入力したパスとポートが使用可能か確認します。

   * テストに合格した場合、**<UI-TERM key="ocp-v2.components.ModifyLogServiceDataStorageModal.NewCreation">新規作成</UI-TERM>**をクリックします。
   * テストに不合格の場合、表示されたメッセージに従ってトラブルシューティングを行います。

### クラスタ情報の確認

1. 右側のパネルで設定したクラスタ情報に誤りがないことを確認し、**<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step1.NextStep">次のステップ</UI-TERM>**をクリックします。

2. 作成前の事前チェックを実行し、システムは環境がAIクラスタの最低要件を満たしているか検証します。チェック項目の実行に失敗した場合、表示された指示に従って以下の操作を行うことができます：

    * **<UI-TERM key="ocp-v2.component.UploadPackageDrawer.Upload">アップロード</UI-TERM>**：特定のチェック項目が失敗した場合にのみ表示されます。表示された指示に従い、**<UI-TERM key="ocp-v2.page.Package.Upload">アップロード</UI-TERM>**をクリックして、必要なソフトウェアパッケージを手動でアップロードしてください。
    * **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.Skip">スキップする</UI-TERM>**：この操作は現在のチェック項目をスキップします（特別なシナリオ向けに設計されています）。関連するチェック項目が製品仕様を満たしていることを必ず確認してください。そうでない場合、後続のプロセスが失敗する可能性があります。スキップした後、そのチェック項目のステータスは**<UI-TERM key="ocp-v2.RealtimeMonitor.View3D.ResourceDrawer.Warning">警告</UI-TERM>**に変更されます。
    * **<UI-TERM key="ocp-v2.Sop.Main.TaskCard.Retry">再試行</UI-TERM>**：失敗の原因と最適化の推奨事項に基づいて問題を調査・修正し、修正後に**<UI-TERM key="ocp-v2.Main.components.StepActionBar.Retry">再試行</UI-TERM>**をクリックして、失敗したチェック項目を再度実行します。
    * **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**：すべての問題が調査・修正されたら、**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**をクリックして、失敗したすべてのチェック項目を再度実行します。

3. 実行失敗のチェック項目がなくなったら、**<UI-TERM key="ocp-v2.ObjectStorage.Component.Main.NewCreation">新規作成</UI-TERM>**をクリックします。

   新規クラスタタスクを送信すると、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>**でそのタスクの実行進捗状況を確認できます。
