# Zoneの追加

管理しているクラスタに新しいZoneを追加できます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* お使いのOceanBaseクラスタが現在のOCPで管理されていること。

  現在のOCPで管理されていない場合は、[クラスタの引き継ぎ](../300.manage-a-cluster/400.take-over-a-cluster.md)を参照して、OceanBaseクラスタを現在のOCPに引き継いでください。

* OceanBaseクラスタEnterprise Editionは、新しいZoneの追加をサポートしていません。

## 注意事項

クラスタでCgroupが有効な場合、新しく追加するZoneにOSカーネルバージョンが5.1.0未満のホストが存在すると、クラスタのCgroupを無効にすることを推奨します。無効にしない場合、システムのパフォーマンス低下や不安定を引き起こす可能性があります。

クラスタがAIクラスタ（共有ストレージ形態）の場合、新しく追加するZone内のOBServerノードは `ob_startup_mode=shared_storage` モードで起動し、ローカルディスクはキャッシュとしてのみ使用され、データはオブジェクトストレージに永続化されます。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-performance-report.pages.AWR.Cluster">クラスタ</UI-TERM>** をクリックすると、システムはデフォルトで **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** で操作対象のクラスタを選択し、そのクラスタ名をクリックします。

4. クラスタの **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページに移動し、右上の **<UI-TERM key="ocp-v2.Topo.TopoGraph.NewZone">ゾーンを追加</UI-TERM>** をクリックします。

5. ポップアップダイアログで、Zone情報を設定します。

   デフォルトでは1つのZone情報が追加されます。複数のZoneを追加する必要がある場合は、下部の **<UI-TERM key="ocp-v2.Cluster.Detail.NewZone">ゾーンの追加</UI-TERM>** ボタンをクリックして、複数のZone情報を追加できます。

   設定が必要なZone情報は以下の表のとおりです。

   | **<UI-TERM key="ocp-v2.Detail.SqlAudit.Configuration">設定</UI-TERM>**  |  **<UI-TERM key="ocp-v2.Auth.Role.Detail.Description">説明</UI-TERM>**   |
   |-----------|-----------------|
   | Zone名 | デフォルトはzone_n(nは1から始まる整数)です。Zone名をクリックしてカスタマイズできます。      |
   | データセンター      | ホストが配置されるデータセンターを選択します。    |
   | マシンタイプ      | オプションです。追加するホストのマシンタイプを指定します。マシンタイプを選択すると、ホストリストがマシンタイプでフィルタリングされます。 |
   | ソフトウェアパッケージタイプ | OceanBaseのソフトウェアパッケージタイプを選択します。選択後、CPUアーキテクチャがソフトウェアパッケージタイプでフィルタリングされます。  |
   | CPUアーキテクチャ  | ホストのCPUアーキテクチャ(ARMまたはX86)を選択します。<main id="notice" type='explain'><h4>説明</h4><p>対応するアーキテクチャのOceanBase RPMパッケージが存在する場合にのみ、対応するCPUアーキテクチャを選択できます。</p></main>    |
   | ホスト      | 複数のホストを選択できます。本番環境では、OceanBaseデータベースではログディスク容量をホストメモリ容量の3倍以上に設定することを推奨します。また、パフォーマンスの問題を避けるため、データディレクトリとログディレクトリを同一のディスクにマウントすることは推奨されません。 |
   | テナント設定  | 現在のクラスタ内のテナントに対して一括でレプリカ情報を設定できます。各テナントごとに個別にレプリカを追加する必要はありません。<ul><li>設定するレプリカ情報には、レプリカタイプ、Unit仕様、Unit数が含まれます。</li><li>各行では1つのテナントのみ追加できます。複数のテナントを設定する場合は、**<UI-TERM key="ocp-v2.component.ZoneFormCardList.AddTenants">テナントの新規追加</UI-TERM>** をクリックして複数行を追加してください。</li><li>Unit数は選択したテナントに基づいて自動的に入力され、編集はできません。</li></ul>   |
   | カスタム設定  | OBServerノードのOSに属するユーザー、パス、ポートを設定します。詳細については、[分散型クラスタの作成](../200.create-a-cluster/100.create-a-distributed-cluster.md)または[AIクラスタの作成](../200.create-a-cluster/300.create-an-ai-cluster.md)の**<UI-TERM key="ocp-v2.Content.CustomSettings.CustomConfiguration">カスタム設定</UI-TERM>**に関する説明を参照してください。    |
   | パラメータ設定  | Zone内のすべてのOBServerの起動パラメータを設定します。パラメータの詳細については、[OceanBaseパラメータ](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000218691)を参照してください。<br>OBServerの起動パラメータが設定されていない場合は、デフォルトでクラスタ作成時の起動パラメータが使用されます。    |

   ![09161742](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/01161721.png)

6. 完了後、**<UI-TERM key="ocp-v2.Monitor.AddMonitor.MetricTable.Ok">確定</UI-TERM>** をクリックします。

   ポップアップウィンドウの **<UI-TERM key="ocp-v2.Plan.Component.PlanExecuteTable.ViewTasks">タスクを確認</UI-TERM>** ボタンをクリックすると、新規作成の進捗状況を確認できます。また、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>** でこのタスクの進捗状況を確認できます。

   このタスクの状態が **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** となり、かつクラスタの **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Component.ZoneList.ZoneList">ゾーンリスト</UI-TERM>** において、そのZoneの状態が **<UI-TERM key="ocp-v2.src.constant.tenant.Running">実行中</UI-TERM>** となったら、新規作成は成功です。
