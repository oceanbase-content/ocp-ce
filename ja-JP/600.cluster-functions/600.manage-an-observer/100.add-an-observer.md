# OBServerノードの追加

管理しているクラスタにOBServerノードを追加することで、クラスタの拡張を実現できます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** メニュー権限。

* お使いのOceanBaseクラスタが現在のOCPで管理されていること。

  もしお使いのOceanBaseクラスタが現在のOCPで管理されていない場合は、[クラスタの引き継ぎ](../300.manage-a-cluster/400.take-over-a-cluster.md)を参照して、OceanBaseクラスタを現在のOCPに引き継いでください。

* OceanBase集中型Enterprise版は、OBServerノードの追加をサポートしていません。

## 注意事項

クラスタでCgroupが有効な場合、新規追加されるOBServerノードにOSカーネルバージョンが5.1.0未満のホストが含まれていると、クラスタのCgroupを無効にすることを推奨します。そうでない場合、システムのパフォーマンス低下や不安定を引き起こす可能性があります。

クラスタがAIクラスタ（共有ストレージ形態）の場合、新規追加されるOBServerノードは `ob_startup_mode=shared_storage` モードで起動し、ローカルディスクはキャッシュとしてのみ使用され、データはオブジェクトストレージに永続化されます。

## クラスタへのOBServerノードの追加

複数のZoneに同時にOBServerノードを追加する場合に適用されます。

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.Cluster">クラスタ</UI-TERM>** をクリックすると、システムはデフォルトで **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** で、操作対象のクラスタを選択し、そのクラスタ名をクリックします。

4. クラスタの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動し、右上の **<UI-TERM key="ocp-v2.Cluster.Detail.AddObserver">OBServerを追加する</UI-TERM>** をクリックします。

5. **<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.AddObserver.1">OBServerを追加する</UI-TERM>** パネルで、以下の情報を設定します。

   * OBServer情報の設定：

      | **<UI-TERM key="ocp-v2.Detail.SqlAudit.Configuration">設定</UI-TERM>**  |   **<UI-TERM key="ocp-v2.Auth.Role.Detail.Description">説明</UI-TERM>**    |
      |---------|-------|
      | Zone名  | 所属Zoneの設定と一致させる必要があり、変更はサポートされていません。 |
      | データセンター       | 所属Zoneの設定と一致させる必要があり、変更はサポートされていません。 |
      | マシンタイプ      | オプションです。追加するホストのマシンタイプを指定します。マシンタイプを選択すると、ホストリストがマシンタイプでフィルタリングされます。   |
      | CPUアーキテクチャ   | 所属Zoneの設定と一致させる必要があり、変更はサポートされていません。 |
      | ソフトウェアパッケージタイプ | 所属Zoneの設定と一致させる必要があり、デフォルトでは変更はサポートされていません。<ul><li>システムが現在のOceanBase内のソフトウェアパッケージタイプを認識できない場合、OSバージョンに応じて適切なソフトウェアインストールパッケージを手動で選択する必要があります。</li><li>システムに該当タイプのソフトウェアパッケージが欠けている場合、**<UI-TERM key="ocp-v2.src.hook.usePackageOperatingSystemCheck.UploadSoftwarePackage">ソフトウェアパッケージをアップロード</UI-TERM>** をクリックして関連するソフトウェアパッケージをアップロードしてください。そうでない場合、OBServerをインストールできません。</li></ul> |
      | ホスト      | 複数のホストIPを選択できます。<ul><li>ドロップダウンリストで選択可能なホストがない場合、[ホストの追加](../../850.host-features/100.manage-a-host/200.add-a-host.md)操作を実行できます。</li><li>本番環境では、OceanBaseデータベースではログディスク容量をホストメモリ容量の3倍以上に設定することを推奨します。また、パフォーマンス問題を避けるため、データディレクトリとログディレクトリを同一のディスクにマウントすることは推奨されません。</li></ul> |

   * カスタム設定：OBServerノードのOSに属するユーザー、パス、ポートを設定します。詳細については、[分散型クラスタの新規作成](../200.create-a-cluster/100.create-a-distributed-cluster.md)または[AIクラスタの作成](../200.create-a-cluster/300.create-an-ai-cluster.md)の **<UI-TERM key="ocp-v2.Content.CustomSettings.CustomConfiguration">カスタム設定</UI-TERM>** 関連説明を参照してください。
   * パラメータ設定：OBServerの起動パラメータを設定します。詳細については [OceanBase構成パラメータ](https://docs.oceanbase.com/oceanbase-database/V4.2.1-system-parameters-list)を参照してください。

    <!-- ![11181812](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/01161715.png) -->

6. 完了後、**<UI-TERM key="ocp-v2.component.Compaction.MergePolicyDrawer.Ok">確定</UI-TERM>** をクリックします。

   ポップアップウィンドウの **<UI-TERM key="ocp-v2.src.component.TaskLabel.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、タスクの進捗状況を確認できます。また、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>** でもそのタスクの進捗を見ることができます。

   タスクの状態が **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** になり、かつクラスタの **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Component.OBServerList.ObserverList">OBServerリスト</UI-TERM>** にある対応するOBServerノードの状態がすべて **<UI-TERM key="ocp-v2.Detail.Statistics.utils.Running">実行中</UI-TERM>** になっていれば、タスクは成功です。

## 指定したZoneにOBServerノードを追加する

OBServerノードを追加するZoneが単一のみの場合に適用されます。

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.component.CardAbnormalTable.Cluster">クラスタ</UI-TERM>** をクリックすると、システムはデフォルトで **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** で操作対象のクラスタを選択し、そのクラスタ名をクリックします。

4. クラスタの **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Component.ZoneList.ZoneList">ゾーンリスト</UI-TERM>** エリアに移動し、OBServerノードを追加するZoneを選択します。対応する **<UI-TERM key="ocp-v2.page.Host.Operation">操作</UI-TERM>** 列で、**<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.AddObserver">OBServerを追加</UI-TERM>** をクリックします。

5. **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">OBServerの新規追加</UI-TERM>** パネルで、以下の情報を設定します。

   |  パラメータ  |  説明  |
   |--------|--------|
   | ソフトウェアパッケージタイプ  |  デフォルトでは現在のZoneの設定と一致します。システムが現在のOceanBaseクラスタのソフトウェアパッケージタイプを認識できない場合は、オペレーティングシステムのバージョンに応じて適切なパッケージを手動で選択する必要があります。  |
   | OBServer情報 |  追加するホストのマシンタイプを指定し、具体的なホストを選択します（複数選択可能）。デフォルトではOBServerノードは1つだけ追加されます。複数のOBServerノードを追加する必要がある場合は、下部の **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.AddObserver">OBServerの新規追加</UI-TERM>** ボタンをクリックしてください。<ul><li>追加先のZoneのCPUアーキテクチャと一致するホストのみを選択できます。</li><li>本番環境では、OceanBaseデータベースではOBServerのログディスク容量をホストメモリ容量の3倍以上に設定することを推奨します。同時に、パフォーマンス上の問題を避けるため、データディレクトリとログディレクトリを同一のディスクにマウントすることは推奨されません。</li></ul>  |
   | カスタム設定  | OBServerノードのオペレーティングシステムの所有者ユーザー、パス、ポートを設定するために使用されます。詳細については、[分散型クラスタの新規作成](../200.create-a-cluster/100.create-a-distributed-cluster.md)または[AIクラスタの作成](../200.create-a-cluster/300.create-an-ai-cluster.md)の **<UI-TERM key="ocp-v2.Content.CustomSettings.CustomConfiguration">カスタム設定</UI-TERM>** 項目の説明を参照してください。 |
   | パラメータ設定 | OBServerの起動パラメータを設定します。詳細については [OceanBaseパラメータ](https://docs.oceanbase.com/oceanbase-database/V4.2.1-system-parameters-list)を参照してください。 |

   <!-- ![09161748](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/432/%E6%96%B0%E5%A2%9Eobserver.png) -->

6. 完了後、**<UI-TERM key="ocp-v2.Statistics.components.EditAutoBasicInfoDrawer.Ok">確定</UI-TERM>** をクリックします。
