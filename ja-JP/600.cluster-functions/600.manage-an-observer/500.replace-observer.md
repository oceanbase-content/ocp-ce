# OBServerノードの置換

OBServerノードの置換では、新しいホストにOBServerノードをインストールし、現在のOBServerノードを置き換えます。このページでは、問題のあるOBServerノードを除外するか、低パフォーマンスのOBServerノードを高性能なノードに置き換える方法について説明します。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* お使いのOceanBaseクラスタが現在のOCPで管理されていること。

  もしそうでない場合は、[クラスタの引き継ぎ](../300.manage-a-cluster/400.take-over-a-cluster.md)を参照して、OceanBaseクラスタを現在のOCPに引き継いでください。

* レプリカ数が3以上のOceanBaseクラスタであれば、OBServerノードの置換操作を実行できます。それ以外の場合は、この操作の実行は推奨されません。

* スタンドアロンではOBServerノードの置換はサポートされていません。

## 注意事項

クラスタでCgroupが有効になっている場合、置き換えるOBServerノードの中にOSカーネルバージョンが5.1.0未満のホストが存在する場合は、クラスタのCgroupを無効にすることを推奨します。そうでない場合、システムのパフォーマンス低下や不安定を引き起こす可能性があります。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-performance-report.pages.AWR.Cluster">クラスタ</UI-TERM>** をクリックすると、システムはデフォルトで **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** で、操作対象のクラスタを選択し、そのクラスタ名をクリックして、クラスタの **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページに移動します。

4. **<UI-TERM key="ocp-v2.Component.OBServerList.ObserverList">OBServerリスト</UI-TERM>** エリアで、置き換えたいOBServerノードの操作列にある **<UI-TERM key="ocp-v2.Cluster.Component.RepalceDrawer.Replace">置き換え</UI-TERM>** をクリックします。

5. 以下の説明を参考に置き換え情報を入力し、入力完了後に **<UI-TERM key="ocp-v2.src.constant.oceanbase.Replacement">置き換え</UI-TERM>** をクリックします。

   1. インストールパッケージのタイプを選択します。デフォルトでは、現在のOceanBaseクラスタのソフトウェアインストールパッケージタイプと一致します。システムが現在のOceanBaseクラスタのソフトウェアパッケージタイプを認識できない場合は、OSバージョンに応じて適切なパッケージを手動で選択する必要があります。
   2. 置き換え先のホストを選択します。ドロップダウンリストに選択可能なホストがない場合は、[ホストの追加](../../850.host-features/100.manage-a-host/200.add-a-host.md)操作を実行できます。
   3. OBServerノードのOS所有者ユーザー、パス、ポートを設定するためのカスタム設定を行います。詳細については、[分散型クラスタの新規作成](../200.create-a-cluster/100.create-a-distributed-cluster.md)の **<UI-TERM key="ocp-v2.New.Content.CustomSettings.CustomConfiguration">カスタム設定</UI-TERM>** の関連説明を参照してください。
   4. OBServer起動パラメータを設定します。パラメータの詳細については、[OceanBase構成パラメータ](https://docs.oceanbase.com/oceanbase-database/V4.2.1-system-parameters-list)を参照してください。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <ul>
    <li>現在のクラスタのハードウェアアーキテクチャに一致するホストのみを選択でき、そのホストは元のホストと同じデータセンター内にある必要があります。</li>
    <li>ホストがオフライン状態の場合、クリーンアップ操作は実行できません。置換機能はクリーンアップ手順をスキップし、ホスト環境のクリーンアップは手動で行う必要があります。</li>
    <li>本番環境では、OceanBaseデータベースではログディスク容量をホストメモリ容量の3倍以上に設定することを推奨します。また、パフォーマンス上の問題を避けるため、データディレクトリとログディレクトリを同一のディスクにマウントすることは推奨されません。</li>
    </ul>
   </main>

6. ポップアップウィンドウ内の **<UI-TERM key="ocp-v2.src.component.TaskLabel.ViewTasks">タスクを確認する</UI-TERM>** ボタンをクリックすると、置換の進捗状況を確認できます。また、**<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">タスクセンター</UI-TERM>** でもこのタスクの進捗を確認できます。

   タスクの状態が **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>** であり、かつクラスタの **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">概要</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Component.OBServerList.ObserverList">OBServerリスト</UI-TERM>** 内の置き換え後のOBServerノードの状態が **<UI-TERM key="ocp-v2.Detail.Statistics.utils.Running">実行中</UI-TERM>** の場合、置換は成功です。
