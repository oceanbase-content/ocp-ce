# ログのクエリ

ログクエリ機能を使用すると、オブジェクト範囲、ログタイプ、ログレベル、および時間範囲に基づいて、OBServerノード、アービトレーションサービス、OBProxy、Binlog Server、Binlogインスタンス、ホスト、およびOCP Agentのログを表示できます。また、OCPは指定されたテキストに対して、ログキーワードの通常一致および正規表現一致をサポートしています。

ログ分析を通じて、選択したオブジェクトのエラーログや状態異常なコンポーネントを確認し、詳細な分析を実施できます。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **クラスタ読み取り専用**、**テナント読み取り専用**、**OBProxy読み取り専用**、**アービトレーションサービス読み取り専用**、**Binlogサービス読み取り専用**、または**ホスト読み取り専用** のいずれかのリソース権限。
* ログ検索 **<UI-TERM key="ocp-v2.component.HostSelect.All">すべて</UI-TERM>** メニュー権限。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **システム管理 \> ログ検索** を選択します。

   システムはデフォルトで **<UI-TERM key="ocp-v2.page.QueryLog.LogQuery">ログクエリ</UI-TERM>** ページに入ります。このページには、以下の方法でもアクセスできます。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>以下の方法で <strong>ログクエリ</strong> ページにアクセスした場合、システムはアクセス経路に応じて、クエリ条件の <strong>オブジェクト範囲</strong> と <strong>ログタイプ</strong> を自動的に入力します。</p>
    </main>

   * クラスタ **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** ページの右上隅で、**...** をクリックし、**<UI-TERM key="ocp-v2.page.QueryLog.DownloadAllLogs">ログをダウンロードする</UI-TERM>** を選択します。

   * クラスタ **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Component.OBServerList.ObserverList">OBServerリスト</UI-TERM>** で、**...** をクリックし、**<UI-TERM key="ocp-v2.src.constant.task.DownloadLogs">ログをダウンロードする</UI-TERM>** を選択します。

   * 左側のナビゲーションバーの **<UI-TERM key="ocp-v2.src.component.ModifyTagResourceDrawer.Host">ホスト</UI-TERM>** をクリックし、ホストリストで複数の **<UI-TERM key="ocp-v2.Scan.ReportTable.ServerInfoTable.IpAddress">IPアドレス</UI-TERM>** を選択します。ページの右下をクリックすると、**<UI-TERM key="ocp-v2.page.Host.BatchDownloadLogs">ログの一括ダウンロード</UI-TERM>** ボタンが表示されます。

   * OBProxyクラスタ **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>** ページの右上隅で、**...** をクリックし、**<UI-TERM key="ocp-v2.Detail.Overview.DownloadAllLogs">すべてのログをダウンロードする</UI-TERM>** を選択します。

   * OBProxyクラスタ **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページの **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ObproxyList">OBProxyリスト</UI-TERM>** で、**<UI-TERM key="ocp-v2.component.CardAbnormalTable.Operation">操作</UI-TERM>** 列の **<UI-TERM key="ocp-v2.Component.OBServerList.DownloadLogs">ログをダウンロードする</UI-TERM>** ボタンをクリックします。

3. **<UI-TERM key="ocp-v2.page.QueryLog.LogQuery">ログクエリ</UI-TERM>** ページでクエリ条件を設定します。

   ![1216](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/403-cn/%E6%97%A5%E5%BF%97%E6%9F%A5%E8%AF%A2.png)

   | 条件カテゴリ  |設定の説明 |
   |-------|-------|
   | オブジェクト範囲  | 必須項目です。ログクエリの範囲を選択します。 <ul><li> 前方の枠でログクエリの対象を選択します。選択肢は **<UI-TERM key="ocp-v2.src.constant.inspection.OceanbaseCluster">OceanBase クラスタ</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Cluster.ArbitrationService">アービトレーションサービス</UI-TERM>**、**<UI-TERM key="ocp-v2.Alarm.Event.ObproxyCluster">OBProxyクラスタ</UI-TERM>**、**Binlog Server**、**<UI-TERM key="ocp-v2.Task.TaskObjectAndType.BinlogInstance">Binlog インスタンス</UI-TERM>**、**<UI-TERM key="ocp-v2.Monitor.AddMonitor.CollectTable.Host">ホスト</UI-TERM>** です。 </li>  <li> 後方の枠でそのオブジェクトの具体的なサーバーを選択します。複数選択可能です。ログクエリの対象が **<UI-TERM key="ocp-v2.src.component.ModifyTagResourceDrawer.Host">ホスト</UI-TERM>** の場合、選択されたサーバーはクラスタ単位で表示されます。</li></ul> |
   | ログタイプ  | 必須項目です。ログタイプについては、下記の **ログタイプの説明** を参照してください。  <ul><li>  前方の枠でログの大分類を選択します。選択肢は **<UI-TERM key="ocp-v2.src.constant.log.ObLog">OBログ</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.log.ArbitrationServiceLog">アービトレーションサービスログ</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.alarm.ObproxyLogs">OBProxyログ</UI-TERM>**、**Binlog Serverログ</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.log.BinlogInstanceLogs">Binlogインスタンスログ</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.compute.HostLogs">ホストログ</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.compute.OcpAgentLog">OCP Agentログ</UI-TERM>** です。 </li>  <li>  後方の枠で、そのログタイプの中から確認したい具体的なログファイルを選択します。複数選択可能です。</li>   </ul>   |
   | ログレベル  |確認したいログレベルを選択します。選択肢は：ERROR、WARN、INFO、WDIAG、EDIAG、TRACE、DEBUG です。複数選択可能です。 |
   | 時間範囲  |デフォルトは過去1時間です。左側の枠で、過去5分/10分/15分/30分、過去1/3/6/12/24時間、または過去7日という範囲を簡単に定義できます。また、右側の時間開始枠で時間範囲をカスタマイズすることもできます。 |
   | キーワード   |ログクエリ時に、このキーワードを含むログがフィルタリングされます。複数のキーワードに対して正規表現一致と通常一致をサポートしています。 |
   | 除外キーワード |ログクエリ時に、このキーワードを含むログが除外されます。複数のキーワードを除外することをサポートしています。  |

4. **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Query">クエリ</UI-TERM>** ボタンをクリックします。

   インターフェースの下部には、クエリ条件に一致するログレコードが表示されます。

   ![18](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/403-cn/%E6%97%A5%E5%BF%97%E8%AF%A6%E6%83%85.png)

   * ① の場所でサーバーを切り替えることで、異なるサーバー上のログ詳細を確認できます。

   * ② の場所でログファイルを切り替えることができます。

5. ③ の **<UI-TERM key="ocp-v2.Detail.Log.LogCard.DownloadLogs">ログをダウンロードする</UI-TERM>** ボタンをクリックします。

   このサーバー上で選択（入力）した条件を満たすすべてのログをダウンロードできます。

## ログタイプの説明

ログタイプの情報は以下のとおりです：

|     ログタイプ       |  説明  |
|--------------------|--------|
| OBログ            | `OceanBase クラスタインストールパス/log/` ディレクトリ下のすべてのログで、`observer`、`rootservice`、`election`、`alert` の4種類に細分化されます。   |
| アービトレーションサービスログ       | `アービトレーションサービスインストールパス/log/` ディレクトリ下のすべてのログで、`arbitration_observer`、`arbitration_rootservice`、`arbitration_election` の3種類に細分化されます。 |
| OBProxyログ       | `/home/admin/logs/obproxy/log/` ディレクトリ下のすべてのログで、`obproxy`、`obproxy_digest`、`obproxy_stat`、`obproxy_slow`、`obproxy_limit`、`obproxy_diagnosis`、`obproxy_xflush`、`obproxy_error` の8種類に細分化されます。  |
| Binlog Serverログ | `Binlog クラスタインストールパス/log/` ディレクトリ下のすべてのログで、`binlog_server_deploy`、`binlog_server_logproxy`、`binlog_server_out` の3種類に細分化されます。  |
| Binlogインスタンスログ    | `Binlog クラスタインストールパス/run/インスタンス名/log` ディレクトリ下のすべてのログで、`binlog_service_instance`、`binlog_service_init`、`binlog_service_libobcdc`、`binlog_service_libobcdc_stderr` の4種類に細分化されます。 |
| ホストログ           | `/var/log` パス下の **message-日付** ファイル。  |
| OCP Agentログ     | `/home/admin/ocp_agent/log/` ディレクトリ下のすべてのログで、`mgragent`、`monagent`、`agentctl`、`agentd` の4種類に細分化されます。|
