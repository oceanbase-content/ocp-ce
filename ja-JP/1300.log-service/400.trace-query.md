# リンクのクエリ

このセクションでは、OCPを使用して、業務サイドで特定の時間を超えて実行されたTraceをクエリする方法について説明します。SQL診断で異常なSQLのSQL IDを取得した場合、またはログクエリページで異常なログのSQL Trace IDを取得した場合、取得した情報をクエリ条件として使用して詳細なリンク情報を確認できます。呼び出しチェーンの完全な情報により、問題の特定と最適化が容易になります。

## 背景

OceanBaseは分散データベースです。1回のデータベースリクエストやトランザクション処理は、複数のOceanBaseインスタンスにまたがる可能性があります。同時に、典型的なデプロイメントアーキテクチャでは、OBProxyやデータベースドライバー(JDBCやlibobclientなど)も関与します。1回のデータベースリクエストは、データベースドライバーからOBProxy、そして1つまたは複数のOceanBaseインスタンスで実行され、中間のネットワークリンクも関与します。呼び出しチェーンの複雑さが原因で、異常やパフォーマンス問題の特定が困難になります。

フルリンクトレース機能は、上記の問題を解決するために提供されています。OceanBaseとOBProxyは、Traceログを通じて、リンク間の上流・下流関係、および重要な実行ステップのコンテキスト情報と実行時間を記録します。OCPはこれらのログを収集・処理・保存した後、ユーザーにリンクの検索および表示機能を提供します。設定した条件に基づいてリンクを検索し、リンク全体の詳細情報を直感的に確認することで、問題の迅速な特定が容易になります。詳細については、[フルリンクトレースを体験する](https://www.oceanbase.com/docs/enterprise-oceanbase-database-cn-10000000000886284)を参照してください。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、**OBProxy読み取り専用**、**アービトレーションサービス読み取り専用**、**Binlogサービス読み取り専用**、または**ホスト読み取り専用** のいずれかのリソース権限。
  * ログ検索 **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.All">すべて</UI-TERM>** メニュー権限。

* OpenSearchクラスタがデプロイ済みであること。詳細については、[OpenSearch関連説明](../1300.log-service/500.opensearch-docker.md)を参照してください。
* リンククエリ関連パラメータが設定済みであること。詳細については、[リンククエリパラメータの設定](../1300.log-service/300.configuration-trace-paremeters.md)を参照してください。
* リンククエリは、OceanBase V4.0以降のバージョンのテナントでのみサポートされます。

## 手順

1. OCPにログインします。
2. 左側のナビゲーションバーで **システム管理 \> ログ検索** を選択します。
3. **<UI-TERM key="ocp-v2.page.Log.LinkQuery">リンククエリ</UI-TERM>** タブをクリックし、**<UI-TERM key="ocp-v2.Component.SQLTable.LinkQuery">リンククエリ</UI-TERM>** インターフェースに入ります。
4. **<UI-TERM key="ocp-v2.Log.Trace.LinkQuery">リンククエリ</UI-TERM>** インターフェースでクエリ条件を設定することで、対象Traceの特定を支援します。

   ![1216](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E9%93%BE%E8%B7%AF%E6%9F%A5%E8%AF%A21.png)

   クエリ条件の説明は以下のとおりです。

   | 条件カテゴリ  |設定説明 |
   |-------|-------|
   | 時間範囲  | デフォルトは過去1時間です。 左側のボックスで、過去5分/10分/15分/30分または過去1時間/3時間/6時間/12時間/24時間の範囲をすばやく定義するか、右側の開始時間ボックスでカスタムの時間範囲を設定できます。 |
   | 対象テナント  | 必須項目です。クエリする具体的なテナントを選択します。 |
   | 検索内容   | SQL IDまたはSQL Trace IDを入力します。リンククエリ時に、そのIDの下にあるすべてのTraceがフィルタリングされます。 |
   | 実行時間 | デフォルトは0 msです。時間を設定でき、実行時間がこの設定値を超えるTraceが表示されます。 |

5. **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Query">クエリ</UI-TERM>** ボタンをクリックします。

   インターフェースの下部に、クエリ条件に一致するリンクが表示されます。

   ![18](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E9%93%BE%E8%B7%AF%E6%9F%A5%E8%AF%A2.png)

   * 検索内容にSQL IDを入力してクエリ条件として検索する場合、同じSQL IDの下のSQL実行時間の分布図およびすべてのリンク情報を確認できます。

      ![18](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E9%93%BE%E8%B7%AF%E6%9F%A5%E8%AF%A2-sqlid.png)

   * クエリ条件としてSQLトレースIDを入力して検索すると、その実行のパス情報を確認できます。

      ![18](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E9%93%BE%E8%B7%AF%E6%9F%A5%E8%AF%A2-traceid.png)

6. パスのTraceIdをクリックし、パス詳細ページに移動してパスデータおよびspanの詳細を確認します。

   * スパンノードのタイムライン上にカーソルを合わせると、ポップアップウィンドウにそのspanの詳細情報が表示されます。
      ![18](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E9%93%BE%E8%B7%AF%E8%AF%A6%E6%83%851.png)

   * sql_compileノードのタイムライン上にカーソルを合わせると、ポップアップウィンドウにそのSQLのSQL IDが追加で表示されます。

      SQL IDをクリックすると、SQL詳細ページに移動し、そのSQLの実行状況、実行計画、バインドされたインデックス、およびレート制限の有無を確認できます。詳細については、[SQLの詳細を見る](../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。

      ![18](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/%E9%93%BE%E8%B7%AF%E8%AF%A6%E6%83%852.png)

7. パスのSQLIDをクリックすると、**SQL詳細ページ**に移動し、SQLの詳細を確認できます。詳細については、[SQLの詳細を見る](../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/1000.view-sql-details.md)を参照してください。
