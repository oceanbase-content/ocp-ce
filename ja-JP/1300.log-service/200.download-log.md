# ログのダウンロード

このページでは、ログをダウンロードする手順について説明します。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **クラスタ読み取り専用**、**テナント読み取り専用**、**OBProxy読み取り専用**、**アービトレーションサービス読み取り専用**、**Binlogサービス読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
* ログ検索 **<UI-TERM key="ocp-v2.Detail.Analyze.TimesChart.All">すべて</UI-TERM>** メニュー権限。

## ダウンロード範囲

複数のページのログダウンロードエントリから、**<UI-TERM key="ocp-v2.page.QueryLog.LogQuery">ログクエリ</UI-TERM>** ページに移動し、フィルタ条件に基づいて特定の範囲のログを選択してダウンロードできます。ログダウンロードエントリは以下のとおりです：

* クラスタ **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>** ページで、右上のメニューアイコンにカーソルを合わせ、ドロップダウンリストから **<UI-TERM key="ocp-v2.Component.OBServerList.DownloadLogs">ログをダウンロードする</UI-TERM>** をクリックします。

* OBProxyクラスタ **<UI-TERM key="ocp-v2.page.Overview.Overview">概要</UI-TERM>** ページで、右上のメニューアイコンにカーソルを合わせ、ドロップダウンリストから **<UI-TERM key="ocp-v2.Detail.Overview.DownloadAllLogs">すべてのログをダウンロードする</UI-TERM>** をクリックします。

* ホスト **<UI-TERM key="ocp-v2.Restore.SamplingStrategy.Detail.BasicInformation">基本情報</UI-TERM>** タブで、**<UI-TERM key="ocp-v2.src.constant.task.DownloadLogs">ログをダウンロードする</UI-TERM>** をクリックします。

* **<UI-TERM key="ocp-v2.page.Log.LogService">ログサービス</UI-TERM>** の **<UI-TERM key="ocp-v2.page.QueryLog.LogQuery">ログクエリ</UI-TERM>** ページで、ログ検索結果の右上隅にある **<UI-TERM key="ocp-v2.Detail.Overview.DownloadLogs">ログのダウンロード</UI-TERM>** をクリックします。

## 時間の選択

現在から最近の5分、10分、15分、30分、1時間、3時間、6時間、12時間、24時間、7日間のいずれかの期間を選択するか、ログに含まれるデータの開始時刻と終了時刻をカスタマイズして選択できます。

## 対象範囲

特定のホストのログを表示する範囲を選択できます。表示範囲は、**<UI-TERM key="ocp-v2.Task.TaskObjectAndType.OceanbaseCluster">OceanBase クラスタ</UI-TERM>**、**<UI-TERM key="ocp-v2.src.constant.plan.ArbitrationService">アービトレーションサービス</UI-TERM>**、**<UI-TERM key="ocp-v2.Component.ClusterFilter.ObproxyCluster">OBProxyクラスタ</UI-TERM>**、**Binlog Server**、**<UI-TERM key="ocp-v2.Component.BinlogService.BinlogInstance">Binlogインスタンス</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.TakeOver.Host">ホスト</UI-TERM>** です。

## ログタイプ

ログタイプの情報は以下のとおりです：

|     ログタイプ       |  説明  |
|--------------------|--------|
| OBログ            | `OceanBaseクラスタインストールパス/log/` ディレクトリ内のすべてのログで、`observer`、`rootservice`、`election`、`alert` の4種類に細分化されます。    |
| アービトレーションサービスログ       | `アービトレーションサービスインストールパス/log/` ディレクトリ内のすべてのログで、`arbitration_observer`、`arbitration_rootservice`、`arbitration_election` の3種類に細分化されます。 |
| OBProxyログ       | `/home/admin/logs/obproxy/log/` ディレクトリ内のすべてのログで、`obproxy`、`obproxy_digest`、`obproxy_stat`、`obproxy_slow`、`obproxy_limit`、`obproxy_diagnosis`、`obproxy_xflush`、`obproxy_error` の8種類に細分化されます。  |
| Binlog Serverログ | `Binlogクラスタインストールパス/log/` ディレクトリ内のすべてのログで、`binlog_server_deploy`、`binlog_server_logproxy`、`binlog_server_out` の3種類に細分化されます。  |
| Binlogインスタンスログ    | `Binlogクラスタインストールパス/run/インスタンス名/log` ディレクトリ内のすべてのログで、`binlog_service_instance`、`binlog_service_init`、`binlog_service_libobcdc`、`binlog_service_libobcdc_stderr` の4種類に細分化されます。 |
| ホストログ           | `/var/log` パス下の **message-日付** ファイル。  |
| OCP Agentログ     | `/home/admin/ocp_agent/log/` ディレクトリ内のすべてのログで、`mgragent`、`monagent`、`agentctl`、`agentd` の4種類に細分化されます。|

## キーワード

キーワードを含む、または除外する条件に基づいてログをフィルタリングできます。システムは対応するキーワードと厳密に一致します。大文字小文字は区別されません。この操作はオプションです。

* キーワードを含む：ログ検索時に、このキーワードを含むログがフィルタリングされます。複数のキーワードに対して正規表現マッチングと通常マッチングをサポートします。
* キーワードを除外する：ログ検索時に、このキーワードを含むログがフィルタリングされます。複数のキーワードの除外をサポートします。

複数のキーワードに対して正規表現マッチングと通常マッチングをサポートし、ログ検索時にそのキーワードを含むログがフィルタリングされます。キーワードを除外することを選択した場合、ログ検索時にそのキーワードを含むログがフィルタリングされ、複数のキーワードの除外をサポートします。この操作はオプションです。

## ログレベル

ログレベルのドロップダウンリストから、ログのアラートレベルを選択できます。ERROR、WARN、INFO、WDIAG、EDIAG、TRACE、DEBUG の7つのレベルがあります。この操作はオプションです。
