# OBProxyクラスタの作成

基本情報、デプロイメントモード、詳細設定などの情報を入力することで、新しいOBProxyクラスタを作成できます。これは、OBProxyの追加やOceanBaseクラスタとの接続に使用されます。

## 前提条件

* 現在OCPにログインしているユーザーが **ADMIN** ロールまたは **ORG_ADMIN** ロールであること。
* RPCポートの設定は、V4.3.0以降のOBProxyバージョンでのみサポートされます。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **OBProxy** をクリックし、OBProxyページに移動します。

3. 右上の **OBProxyクラスタを作成** をクリックし、**OBProxyクラスタの作成** ページに移動します。

4. OBProxyクラスタの **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.BasicInformation">基本情報</UI-TERM>** を設定します。

   | パラメータ  | 説明  |
   |------|------|
   | クラスタ名        | 実際の業務状況に応じて、英字で始まるクラスタ名をカスタマイズできます。英字、数字、アンダースコアを含めることができます。 |
   | ソフトウェアバージョン      | OBProxyソフトウェアのバージョンを選択します。<ul><li> リストに該当するバージョンがある場合は、リストから直接選択します。   </li><li> ない場合は、リストの下部にある **バージョンを追加** をクリックしてアップロードできます。</li> </ul><main id="notice" type='explain'><h4>説明</h4><p>選択できるのはV1.8.0以降のパッケージのみです。セキュリティ上の理由から、V3.1.0以降のソフトウェアパッケージを選択することを推奨します。</p></main> |
   | root@proxysys パスワード  | root@proxysysアカウントは、OBProxyにログインしてproxy自体のパラメータ管理などを行うために使用されます。ここでは、このアカウントのパスワードを設定する必要があります。カスタムまたはランダム生成がサポートされています。パスワードは以下の複雑さ要件を満たす必要があります：<ul><li>長さは8～32文字です。</li><li>少なくとも数字（0～9）、大文字（A～Z）、小文字（a～z）、特殊文字の4種類のうち3種類を含みます。サポートされている特殊文字は <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code> です。  </li></ul>  |
   | proxyroアカウントのパスワードを入力する場所  | OBProxyの **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareVersion">ソフトウェアバージョン</UI-TERM>** がV4.0未満の場合に表示されます。proxyroアカウントはOBProxyがOceanBaseクラスタにアクセスするために使用されます。入力しない場合は、proxyroアカウントのデフォルトパスワードを使用して接続します。パスワード形式要件は以下のとおりです：<ul><li>長さは8～32文字です。</li><li>少なくとも数字（0～9）、大文字（A～Z）、小文字（a～z）、特殊文字の4種類のうち3種類を含みます。</li><li>サポートされている特殊文字は <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code> です。  </li></ul>  |
   | ロードバランシング管理  | ロードバランシング管理を有効にすると、OBLBを設定することでOBProxyクラスタのロードバランシング機能を向上させることができます。<ul><li>OBLBサービス：ホスト上に既に設定されているOBLBサービスを選択するか、**<UI-TERM key="ocp-v2.Detail.Component.OBLBServerSelect.AddOblbService">OBLBサービスを追加する</UI-TERM>** ボタンをクリックして、右側のパネルで新しいOBLBサービスを作成します。詳細については、[ロードバランシングの管理](../800.obproxy-functions/300.manage-a-obproxy-cluster/300.manage-load-balancing.md) の **新しいロードバランシング** を参照してください。<ul><li>OBLBサービスのアドレス：OBLBのサービスアドレス。</li><li>OBLBサービスのポート：デフォルトは9090ですが、実際の状況に応じて変更できます。</li><li>ユーザー名とパスワード：OBLBサービスのユーザー名とパスワードで、OBLBインターフェースを呼び出す認証情報として使用されます。</li></ul></li><li>VIP：OBLBの具体的なVIPアドレスを選択します。</li><li>アクセスポート：OBLBのアクセスポートで、デフォルトは2883です。カスタムポート番号をサポートしています。</li><li>ポートタイプ：アクセスポートのタイプで、RPCとSQLの2種類をサポートしています。</li><li>ドメイン設定（オプション）：VIPとポートを指すための設定情報です。プラットフォームはVIPとドメインのマッピング関係を提供していないため、ドメイン解決サービスをご自身で準備する必要があります。</li><li>備考（オプション）：追加の説明情報を補足します。</li></ul><main id="notice" type='explain'><h4>説明</h4><p><ul><li><b>ロードバランシング管理</b> 機能はOCP Enterprise Editionにのみ適用され、OCP Community Editionは現在サポートされていません。</li><li><b>ロードバランシング管理</b> 内の <b>Alibaba Cloud SLB</b> はプライベートクラウド環境でのみ適用されます。ベンダーの導入担当者にお問い合わせください。</li><li>OBLBとOBProxyが同じホストでサービスをデプロイする場合、OBLBのアクセスポートはOBProxyのSQLポートと同じにすることはできません。そうでないと、アプリケーションはデータベースに接続できません。</li></ul></p></main> |
   | アクセスアドレス       | **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">ロードバランシング管理</UI-TERM>** がオフの場合に表示されます。これはOBProxyクラスタのアクセスアドレスであり、テナントの接続文字列の生成にのみ使用され、実際の使用には影響しません。ロードバランシングはご自身で設定する必要があります。VIPアドレスの場合は、ご自身で申請し、OBProxy Serverにバインドする必要があります。  |
   | アクセスポート       | **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">ロードバランシング管理</UI-TERM>** がオフの場合に表示されます。デフォルトは2883ですが、VIPの実際のポート番号に応じて入力する必要があります。  |
   | 起動方式       | このOBProxyクラスタの起動方式です。取り得る値： <ul><li> ConfigUrl：マルチクラスタ起動方式です。つまり、このOBProxyクラスタは複数のOceanBaseクラスタにアクセスできます。   </li><li> RsList：シングルクラスタ起動方式です。つまり、このOBProxyクラスタはOBProxyクラスタ作成時に指定された1つのOceanBaseクラスタにのみアクセスできます。OBProxyクラスタ作成後に接続可能なOceanBaseクラスタを追加することはできません。</li>    </ul>    |
   | 接続可能なOceanBaseクラスタ | このOBProxyクラスタがアクセス可能なOceanBaseクラスタを設定します。このOBProxyクラスタとネットワークが一致するOceanBaseクラスタのみを選択できます。 <ul><li> **<UI-TERM key="ocp-v2.OBProxy.New.StartupMode">起動方法</UI-TERM>** がConfigUrlに設定されている場合、このパラメータは必須ではありません。クラスタ作成後、[接続可能なOceanBaseクラスタの追加](../800.obproxy-functions/300.manage-a-obproxy-cluster/200.add-a-connectable-oceanbase-cluster.md) から追加できます。   </li><li> **<UI-TERM key="ocp-v2.Detail.TakeOver.StartupMode">起動方法</UI-TERM>** がRsListに設定されている場合、このパラメータは必須です。ドロップダウンリストから対応するクラスタを選択します。 </li><li> パスワードボックスにそのクラスタのproxyroユーザーの接続認証情報が存在する場合、proxyroユーザーがデフォルトで選択されます。   </li><li>パスワードボックスにそのクラスタのproxyroユーザーの接続認証情報が存在しない場合、**新規接続** をクリックして、そのクラスタのproxyroユーザーのために接続認証情報を作成してください。 </li> </ul>   |

   <!-- ![08261923](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01242021.png) -->

5. （オプション）**<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">OBProxyをデプロイ</UI-TERM>** を設定します。

   OBProxyクラスタ作成時にOBProxyをデプロイする必要がある場合は、この手順で設定できます。それ以外の場合はこの手順をスキップし、クラスタ作成後に [OBProxyの引き継ぎ](../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md) または [OBProxyの追加](../800.obproxy-functions/400.manage-a-obproxy-server/100.add-an-obproxy.md) を通じてクラスタにOBProxyを追加できます。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>この手順をスキップした場合、作成されたOBProxyクラスタは空のクラスタとなり、そのOBProxyクラスタに <a href="../800.obproxy-functions/300.manage-a-obproxy-cluster/200.add-a-connectable-oceanbase-cluster.md">接続可能なOceanBaseクラスタを追加</a>することはできません。</p>
   </main>

   1. **<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">OBProxyをデプロイ</UI-TERM>** のスイッチをオンにします。

   2. 下表を参照してデプロイメント情報を入力します。

      | パラメータ  |    説明   |
      |---------------|--------------|
      | **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">データセンター</UI-TERM>**     | OBProxyが存在するデータセンターです。1つのOBProxyは1つのデータセンターにのみ存在できます。  |
      | **<UI-TERM key="ocp-v2.Detail.TakeOver.Models">機種</UI-TERM>**    | オプションです。モデルを選択すると、後のホストリストがモデルに応じてフィルタリングされます。   |
      | **OBProxyホストの選択** | OBProxyのデプロイに使用するホストを選択します。複数選択が可能です。同時に、**<UI-TERM key="ocp-v2.src.component.AddHostDrawer.AddHost">ホストを追加する</UI-TERM>** をクリックして、クラスタにさらにホストを追加することもできます。 |

      <!-- ![08261945](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/403-ce/%E9%83%A8%E7%BD%B2obproxy.png) -->

      システムはデフォルトで2台分のホスト選択欄を表示しており、これらを設定することで2つのOBProxyをデプロイできます。

      * より多くをデプロイする場合は、**<UI-TERM key="ocp-v2.Detail.Component.AddOBProxyDrawer.AddObproxy">OBProxyを追加する</UI-TERM>** をクリックしてホストを追加します。

      * 1つのOBProxyのみをデプロイする場合は、ホストの後ろにある削除アイコンをクリックしてそのホストを削除できます。

6. OBProxyクラスタの起動パラメータを設定します。

   * 起動パラメータ項目を追加し、それぞれに値を設定できます。OBProxyのパラメータについては、[OBProxyパラメータ説明](../800.obproxy-functions/900.obproxy-parameters-description.md)を参照してください。

   * または、**<UI-TERM key="ocp-v2.page.Tenant.ParameterTemplate">パラメータテンプレート</UI-TERM>** をクリックしてパラメータテンプレートを選択すると、システムがそのテンプレートのパラメータと設定を自動的にここに入力します。クラスタのパラメータテンプレートが作成されていない場合は、**新規OBProxyパラメータテンプレート** をクリックしてOBProxyクラスタのためのパラメータテンプレートを作成できます。詳細については、[OBProxyパラメータテンプレートの管理](../800.obproxy-functions/800.manage-obproxy-parameter-templates.md)を参照してください。

   <!-- ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01242047.png) -->

   システムは以下の2種類の組み込みテンプレートを提供しており、これらのテンプレートには一般的なパラメータ設定が含まれています。これらのテンプレートを直接適用してOBProxyクラスタの初期設定を行うことができます。

   | テンプレート      | 説明    |
   |-----------|---------|
   | 4.2.1 デフォルトパラメータテンプレート    |  OBProxy V4.2.1バージョンでの使用を推奨するパラメータ設定です。本番環境での使用に適しています。   |
   | カラムストアレプリカデフォルトパラメータテンプレート |  カラムストア読み取り専用レプリカでの使用を推奨するパラメータ設定です。本番環境での使用に適しています。 |

7. **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.CustomSettings">カスタム設定</UI-TERM>** を開き、クラスタポート、オペレーティングシステムの所有者ユーザー、パスを設定します。

   |   設定   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Scan.ReportTable.ZoneInfoTable.SqlPort">SQLポート</UI-TERM>**        | デフォルトは2883で、カスタマイズ可能です。  |
   | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ExporterPort">Exporter ポート</UI-TERM>**   | デフォルトは2884で、カスタマイズ可能です。     |
   | **<UI-TERM key="ocp-v2.Detail.Component.AddOBProxyDrawer.RpcPort">RPCポート</UI-TERM>**        | OBProxy V4.3.0.0以降のバージョンでのみこのポートの設定がサポートされています。デフォルトは2885で、カスタマイズ可能です。   |
   | **オペレーティングシステムの所有者ユーザー**     | OBProxyのインストールと実行を行うオペレーティングシステムのユーザーを設定します。編集はサポートされていません。[システムパラメータの変更](../1600.system-management-features/500.manage-system-parameter/200.modify-system-parameters.md)の `ocp.operation.default.os.user` を使用してデフォルト設定を調整できます。このユーザーを変更した場合、その影響は[分散型クラスタの作成](../600.cluster-functions/200.create-a-cluster/100.create-a-distributed-cluster.md)、OBProxyクラスタの作成、および[アービトレーションサービスの作成](../600.cluster-functions/1350.manage-arbitration-services/200.create-arbitration-services.md)にのみ及び、既存のクラスタの他の設定には影響しません。  |
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>**   | <ul><li> **オペレーティングシステムの所有者ユーザー** がadminの場合、**<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>** のデフォルトは `/home/admin/obproxy` です。カスタムパスをサポートします。</li><li>**オペレーティングシステムの所有者ユーザー** がadmin以外の場合、**<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">ソフトウェアのインストールパス</UI-TERM>** のデフォルトは `/opt/oceanbase/obproxy` です。カスタムパスをサポートします。</li></ul>  設定完了後、**<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">テスト</UI-TERM>** をクリックして、パスが使用可能かどうか確認します。使用できない場合は、テスト結果に基づいてトラブルシューティングを行うか、他の使用可能なパスに変更することができます。 |

8. **<UI-TERM key="ocp-v2.OBProxy.New.Submitted">送信</UI-TERM>** をクリックして、OBProxyクラスタの作成を開始します。

   <main id="notice" type='explain'>
   <h4>説明</h4>
   <p>obproxyをインストールする際、システムは関連するインストールディレクトリの権限が正しいかどうかチェックします。現在、<code>/home/admin/logs/obproxy</code> ディレクトリおよびその親ディレクトリが指定されたユーザー（デフォルトはadmin）に対して読み取り権限と実行権限を持っているかどうかを再帰的にチェックすることをサポートしています。持っていない場合、ログに「check directory xxx permission failed, reason: xxx」というエラーが報告されます。</p>
   </main>
