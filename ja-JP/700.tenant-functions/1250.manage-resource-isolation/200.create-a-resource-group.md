# リソースグループの作成

テナント間でのリソース競合を防ぎ、ビジネスの安定した運用を保証するために、OceanBaseデータベースはテナント間のリソースを分離し、リソースグループを通じてテナントのリソース使用量を制限します。まずリソースグループを作成し、その後リソース管理計画を作成することができます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス**または**テナントメンテナンス**のリソース権限。
  * テナントの**<UI-TERM key="ocp-v2.src.hook.useMenu.ResourceIsolation">リソースの隔離</UI-TERM>**メニュー権限。

* リソース分離機能はCgroupに依存しています。テナントが属するクラスタでCgroupを有効にしておいてください。
* リソースグループの作成はOceanBase V4.1以降のバージョンでのみサポートされています。
* システムSYSテナントに対してリソース分離を行うことは推奨されません。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.Backup.Restore.RestoreTask.Tenant">テナント</UI-TERM>**を選択します。システムはデフォルトで**<UI-TERM key="ocp-v2.page.Tenant.TenantList">テナント一覧</UI-TERM>**タブに移動します。

3. **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.TenantList">テナント一覧</UI-TERM>**で操作対象のテナントを選択し、そのテナント名をクリックして、テナントの**<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>**ページに移動します。

4. 左側に表示されるナビゲーションバーで**<UI-TERM key="ocp-v2.Detail.ResourceManager.ResourceIsolation">リソースの隔離</UI-TERM>**をクリックし、そのテナントの**<UI-TERM key="ocp-v2.Detail.ResourceManager.QuarantinePlan">隔離計画</UI-TERM>**ページに移動します。

5. **<UI-TERM key="ocp-v2.ResourceManager.ResourceGroupTab.CreateAResourceGroup">リソースグループの作成</UI-TERM>**ボタンをクリックし、ポップアップウィンドウでリソースグループに関する情報を設定します。

    |  パラメータ  |  説明   |
    |--------|---------|
    |  リソースグループ名      |  新しいリソースグループ名を入力できます。リソースグループ名は英字、数字、アンダースコアの組み合わせで、長さは2～24文字です。       |
    |  備考      |  （オプション）リソースグループの備考情報を設定します。任意の文字をサポートし、長さは1000文字以内です。      |
    |  リソース分離方式     |  設定するリソース分離方式を選択します。**<UI-TERM key="ocp-v2.ResourceManager.ResourceGroupTab.CreateResourceGroup.UserResourceIsolation">ユーザーリソースの分離</UI-TERM>**、**<UI-TERM key="ocp-v2.ResourceManager.ResourceGroupTab.BackgroundTaskIsolation">バックグラウンドタスクの分離</UI-TERM>**、**SQLリソース分離**が含まれます。複数選択が可能で、複数選択した場合は対応するオプションの設定方法が表示されます。|
    |  ユーザーリソース分離 |  ドロップダウンリストからリソース分離を行うユーザーを選択し、ユーザーとリソースグループのマッピング関係を指定します。これにより、そのユーザーが実行するすべてのSQLが、対応するリソースグループに割り当てられたリソースを使用します。<main id="notice" type='notice'><h4>注意</h4><p>1人のユーザーは1つのリソースグループにのみ属することができます。現在のユーザーが他のリソースグループで使用されている場合は、選択できません。</p></main>|
    |  バックグラウンドタスク分離 |  ドロップダウンリストから、現在サポートされているFUNCTIONを選択し、バックグラウンドタスクとリソースグループのマッピング関係を指定します。これにより、各バックグラウンドタスクが使用するリソースが分離されます。現在8種類のバックグラウンドタスクをサポートしています。詳細は[リソース分離の概要](100.resource-isolation-overview.md)の**<UI-TERM key="ocp-v2.ResourceManager.ResourceGroupTab.CreateResourceGroup.ResourceIsolationMethod">リソース分離方式</UI-TERM>**の関連説明を参照してください。 <main id="notice" type='notice'><h4>注意</h4><p>1つのFUNCTIONは1つのリソースグループにのみ属することができます。現在のFUNCTIONが他のリソースグループで使用されている場合は、選択できません。</p></main>      |
    |  SQLリソース分離 |  SQLの観点からビジネスを異なるリソースグループに紐づけるために使用されます。例えば、WHERE句を指定することで、異なる注文のSQLが異なるリソースグループのリソースを使用するようにします。<br>column式を入力することができ、複数の式を入力することもできます。式は比較的曖昧なため、**<UI-TERM key="ocp-v2.ResourceManager.ResourceGroupTab.CreateResourceGroup.ViewExamples">例を見る</UI-TERM>**をクリックすると、SQLの記述上の注意点や記述例を見ることができます。<main id="notice" type='notice'><h4>注意</h4><p>SQL式が他のリソースグループの設定と重複する場合、他のリソースグループのSQL式の設定が上書きされます。</p></main>       |

6. **<UI-TERM key="ocp-v2.Detail.Parameter.List.Submitted">送信</UI-TERM>**をクリックします。
