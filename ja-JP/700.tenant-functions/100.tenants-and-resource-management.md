# テナントとリソース管理

このページでは、テナントとリソース管理に関する概念について説明します。

OceanBaseデータベースはマルチテナントの分散型データベースであり、1つのクラスタ内で複数の独立したテナントを作成できます。各テナントは独立したデータベースサービスであり、必要なハードウェアリソースを指定して、データベースサービスのアカウント、テーブル、ストアドプロシージャなどのオブジェクトを作成できます。テナントのハードウェアリソースはリソースプール（Resource Pool）という形で記述され、リソースプールはリソースユニット（Resource Unit）で構成されます。リソースユニットとは、データベースサービス内部で割り当てられるCPU、メモリ、ハードディスクなどのハードウェアリソースです。

テナントを作成する前に、そのテナントが使用するリソース範囲を定める必要があります。リソースプールとリソースユニットは、テナントのリソース分離とロードバランシングの要件を満たすことができます。

## リソースユニット（Resource Unit）

リソースユニットはCPU、メモリ、ストレージ容量、IOPSなどの物理リソースに対応し、OceanBaseデータベースサービス内部のリソースコンテナです。リソースユニットはクラスタ内で自動的にロードバランシングされ、どのリソースユニットも、そのサイズを収容できる十分なリソースを持つサーバーに配置されます。クラスタ内のサーバーがダウンする前に、その上のリソースユニットは他のサーバーに移行する必要があります。クラスタ内の他のサーバーのリソースが、ダウンする予定のサーバーのリソースユニットを収容するには不十分な場合、サーバーのダウンは正常に完了できません。

## リソースユニット構成（Resource Unit Config）

リソースユニット構成は、リソースユニットの設定情報を記述するもので、各リソースユニット構成はCPU、メモリ、ストレージ容量、IOPSの仕様を1種類ずつ記述します。リソース構成の変更により、リソースユニットの計算リソースを動的に調整し、それによって対応するテナントのリソースを調整できます。

<h4>説明</h4>
<p>クラスタがAIクラスタ（共有ストレージ形態）の場合、リソースユニット構成に以下のフィールドが追加されます：<ul><li><b>DATA_DISK_SIZE</b>：テナントキャッシュディスク容量。デフォルト値はMAX(min cpu * 2GB, memory size * 2)、最小値は2 * cpu（GB）です。</li><li><b>MAX_NET_BANDWIDTH</b>：最大ネットワーク帯域幅。</li><li><b>NET_BANDWIDTH_WEIGHT</b>：ネットワーク帯域幅の重み。</li></ul></p>

## リソースプール（Resource Pool）

リソースプールは、同じリソースユニット構成を持つ複数のリソースユニットで構成されます。1つのリソースプールは1つのテナントにのみ属します。1つのテナントは1つ以上のリソースプールを持つことができ、これらのリソースプールの集合が、そのテナントが使用可能なすべての物理マシンリソースを記述します。1つのテナントは同一のサーバー上に最大1つのリソースユニットを持つことができます。

## リソースユニットの均等化

OceanBaseデータベースは、テナントのリソースユニットをクラスタ内のサーバー間で均等化します。1つのテナントが1つ以上のリソースプールで記述される複数のリソースユニットを持つ場合、各ゾーン内でのリソースユニットの基本的な均等化ポリシーは以下の通りです：

* 同一テナントの複数のリソースユニットは、異なるサーバーに均等に分散されます。

* サーバーのストレージ使用率が一定のしきい値を超えた場合、リソースユニットの交換または移行により、ストレージ使用率のウォーターマークを引き下げます。

* リソースユニットのCPUおよびメモリ仕様に基づき、リソースユニットの交換または移行により、CPUおよびメモリの平均ウォーターマークを引き下げます。
