# テナントのBinlogサービスの管理

Binlogサービスは、OceanBaseのトランザクションログを収集し、MySQL Binlogに変換するサービスです。このセクションでは、テナントのBinlogサービスの管理方法について説明します。これには、Binlogサービスの開始/停止、Binlog設定の変更、およびテナントのBinlogサービスの削除が含まれます。

## 前提条件

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタメンテナンス** または **テナントメンテナンス** のリソース権限。
  * テナントの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** メニュー権限。

* **<UI-TERM key="ocp-v2.src.constant.compute.NormalOperation">正常に稼働</UI-TERM>** 状態のテナントでのみ、Binlogサービスの開始をサポートします。
* テナントが属するクラスタのV3.xバージョンはV3.2.4.4以上、V4.xバージョンはV4.1.0.2以上である必要があります。

## Binlogサービスの開始

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.constant.plan.Tenant">テナント</UI-TERM>** を選択すると、システムはデフォルトで **<UI-TERM key="ocp-v2.page.Tenant.TenantList">テナント一覧</UI-TERM>** タブに移動します。

3. **<UI-TERM key="ocp-v2.component.TenantList.TenantList">テナント一覧</UI-TERM>** で、操作対象のテナントを選択し、そのテナント名をクリックして、テナントの **<UI-TERM key="ocp-v2.Detail.Overview.Overview">概要</UI-TERM>** ページに移動します。

4. **<UI-TERM key="ocp-v2.Alarm.Event.Detail.BasicInformation">基本情報</UI-TERM>** モジュールで、Binlogサービスの後ろにある **<UI-TERM key="ocp-v2.Component.BinlogService.Activate">有効にする</UI-TERM>** をクリックします。

5. ダイアログボックスで以下の情報を設定します。

    | パラメータ               | 説明                |
    |--------------------|--------------|
    | 関連Binlogクラスタ    | テナントに関連付けるBinlogクラスタを選択します。稼働中のBinlogクラスタのみ選択可能です。  |
    | 関連OBProxyクラスタ   | このテナントが関連付けられているOBProxyクラスタを選択します。OBProxyのバージョン番号はV4.2.1.0以上である必要があります。  |
    | 保持期間(時間)    | このテナントのBinlogログの保存期間です。この期間を超えるとログファイルの自動クリーンアップが開始されます。1以上の整数を入力してください。上限は8760です。 |
    | ディスク容量上限(GiB) | このテナントのBinlogログが使用する容量の保護値です。この値を超えるとログファイルの自動クリーンアップが開始されます。1以上の整数を入力してください。上限は102400です。 |
    | インスタンスレプリカ数          | テナントのインスタンスレプリカを設定します。Binlogサービスは、このクラスタのBinlog Server数に基づいてインスタンスレプリカを自動的に分散配置します。1つのBinlog Serverが業務テナントの1つのBinlogインスタンスレプリカのみを担当することを推奨します。同時に、単一の業務テナントは最大5つのインスタンスレプリカをサポートします。 |
    | Binlog開始時刻の設定  | 特定の時間を開始時刻として選択し、履歴時点のトランザクションログを変換するためのBinlogインスタンスを作成できます。選択した時間に対応するClogファイルが存在し、有効な状態であることを必ず確認してください。そうでない場合、Binlogインスタンスの作成に失敗します。選択しない場合、デフォルトで現在時刻が開始時刻として使用され、Binlogインスタンスが作成されます。  |

## その他の操作

Binlogサービスを開始した後、業務ニーズに応じて、テナントのBinlogサービスに対してその他の操作を実行できます。例えば、Binlog設定の変更、Binlogインスタンスの表示、およびBinlogサービスの停止などです。

* **<UI-TERM key="ocp-v2.page.Binlog.BinlogService">Binlogサービス</UI-TERM>** の **<UI-TERM key="ocp-v2.page.Credential.Binlog.Operation">操作</UI-TERM>** > **<UI-TERM key="ocp-v2.Component.BinlogService.ModifyBinlogConfiguration">Binlog設定の変更</UI-TERM>** をクリックすると、関連付けられたOBProxyクラスタ、Binlogの保持期間(時間)、およびディスク容量上限(GiB)の変更が可能です。
* **<UI-TERM key="ocp-v2.Detail.Overview.BinlogService">Binlogサービス</UI-TERM>** の **<UI-TERM key="ocp-v2.Detail.Component.LinkList.Operation">操作</UI-TERM>** > **<UI-TERM key="ocp-v2.Component.BinlogService.ViewBinlogInstances">Binlogインスタンスを表示する</UI-TERM>** をクリックすると、Binlogインスタンスの概要ページに移動し、インスタンスの詳細情報を確認できます。詳細については、[Binlogインスタンスの表示](../../820.binlog-service-fuctions/400.manage-binlog-instance/100.binlog-instance-overview.md)を参照してください。
* **<UI-TERM key="ocp-v2.page.Binlog.BinlogService">Binlogサービス</UI-TERM>** の **<UI-TERM key="ocp-v2.Oracle.UserOrRoleDetail.Operation">操作</UI-TERM>** > **<UI-TERM key="ocp-v2.Component.BinlogService.DisableBinlogService">Binlogサービスの停止</UI-TERM>** をクリックすると、Binlogサービスを停止できます。Binlogサービスを停止すると、生成されたすべてのログファイルが削除され、使用していたストレージ容量も解放されます。
