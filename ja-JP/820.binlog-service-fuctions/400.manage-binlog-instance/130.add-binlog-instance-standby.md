# インスタンスレプリカの追加

このセクションでは、ビジネステナントにインスタンスレプリカを追加する方法について説明します。「プライマリ1/スタンバイN」モードを利用することで、プライマリインスタンスとスタンバイインスタンス間のデータ同期を保証し、Binlogサービスの高可用性をさらに向上させることができます。単一のBinlog Serverはビジネステナントの1つのBinlogインスタンスレプリカのみを担当し、単一のビジネステナントは最大5つのインスタンスレプリカをサポートします。

## 前提条件

* ビジネステナントでBinlogサービスが有効になっていること。詳細については、[テナントのBinlogサービスの管理](../../700.tenant-functions/600.manage-a-tenant/700.manage-binlog-service-of-a-tenant.md)を参照してください。

* 現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **Binlogサービスメンテナンス** リソース権限。
  * Binlogサービス **Binlogクラスタ概要** メニュー権限。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.page.Binlog.BinlogService">Binlogサービス</UI-TERM>** をクリックすると、システムはデフォルトでBinlogの **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** ページに移動します。

3. **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** で、操作対象のBinlogクラスタを選択し、そのクラスタ名をクリックします。

4. **<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterOverview">Binlogクラスタの概要</UI-TERM>** ページで、右上の **<UI-TERM key="ocp-v2.Binlog.Component.AddInstanceModal.AddACopyOfAn">新しいインスタンスレプリカを追加</UI-TERM>** をクリックします。

5. **<UI-TERM key="ocp-v2.Detail.Overview.AddACopyOfAn">新しいインスタンスレプリカを追加</UI-TERM>** ダイアログボックスで、ビジネステナントを指定し、レプリカ数とホスト情報を設定します。

   すべてのインスタンスレプリカを同一ホストにデプロイするか、**<UI-TERM key="ocp-v2.Binlog.Component.AddInstanceModal.AddInstanceReplica">インスタンスレプリカを追加</UI-TERM>** ボタンをクリックして、異なるホストにインスタンスレプリカをデプロイすることもできます。

6. **<UI-TERM key="ocp-v2.component.FormEditTable.Add">新規追加</UI-TERM>** をクリックして、タスクを送信します。

   **<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">タスクセンター</UI-TERM>** でタスクの進捗状況を確認できます。タスクの状態が **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SuccessfulExecution">実行に成功しました</UI-TERM>** になったら、追加は成功です。
