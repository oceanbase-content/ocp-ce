# ホスト上のBinlogインスタンスのクリーンアップ

Binlog Serverを削除した後、このセクションを参照してホスト上のBinlogインスタンスを完全にクリーンアップできます。

## 前提条件

* ホスト上のBinlog ServerはOCPの管理画面から削除され、その削除タスクが正常に完了していること。
* ホストは今後運用を終了する予定であるか、またはホスト上のBinlog関連コンテンツを完全にクリーンアップしたい場合。
* ホスト上にBinlogインスタンスのレプリカが存在し、そのBinlogインスタンスは今後も正常に使用する必要がある場合。ホスト上にBinlogインスタンスが存在するかどうかは、以下の2つの方法で確認できます：
  * 方法1：OCPにログインし、**<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterOverview">Binlogクラスタの概要</UI-TERM>** > **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceList">Binlogインスタンス一覧</UI-TERM>** でインスタンス情報を確認します。
  * 方法2：ホストにログインして `ps -ef | grep binlog_instance` を実行します。ホスト上の各Binlogインスタンスレプリカには、それぞれ1つのbinlog_instanceプロセスが対応しています。

## 手順

理解しやすくするため、以下では削除されたBinlog Serverが配置されていたホストを **<UI-TERM key="ocp-v2.component.ZoneFormCardList.Host">ホスト</UI-TERM>** と呼びます。

### ステップ1：Binlogインスタンスのレプリカ数を確認する

**管理画面で確認する**

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogService">Binlogサービス</UI-TERM>** をクリックすると、システムはデフォルトでBinlogの **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">クラスタ一覧</UI-TERM>** ページに移動します。

3. **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** で、確認したいBinlogクラスタを選択してクリックすると、**<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogClusterOverview">Binlogクラスタの概要</UI-TERM>** ページに移動します。

4. **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceList">Binlogインスタンス一覧</UI-TERM>** エリアで、Binlogインスタンスのレプリカ数を確認します。**<UI-TERM key="ocp-v2.alarm.FormListWithExclude.BinlogNodeWithExclude.NodeIp">ノードIP</UI-TERM>** の数がレプリカ数です。

![レプリカ数](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E8%8A%82%E7%82%B9ip.png)

**コマンドラインで確認する**

任意のホストにログインし、以下のSQLを実行して、現在操作対象のBinlogインスタンスのレプリカ数が1より大きいかどうかを確認します。以下の例のように、テナント `tenant1` には合計2つのBinlogインスタンスレコードがあり、現在のレプリカ数は2であることを示しています。ここでは：

* `cluster_name`：OceanBaseクラスタ名。
* `tenant_name`：テナント名。

```sql
MySQL [(none)]> SHOW BINLOG INSTANCES FOR cluster_name.tenant_name;
```

### ステップ2：新しいBinlogインスタンスレプリカを作成する（レプリカ数が1の場合のみ実行）

以下のSQLを実行して、別のホスト上に新しいBinlogインスタンスレプリカを作成します。ここでは：

* `binlog_instance_name` ：新しいBinlogインスタンスのインスタンス名で、Binlogクラスタ内で一意である必要があります。
* `cluster_name` ：OceanBaseクラスタ名。
* `tenant_name` ：OceanBaseテナント名。
* `CLUSTER_URL` ：Binlogサービスを有効にしたテナントが属するクラスタのconfig_urlを入力します。これはクラスタ概要で確認できます。詳細については、[クラスタの詳細を見る](../../600.cluster-functions/300.manage-a-cluster/200.overview-of-the-cluster-details-page.md)を参照してください。
* `CLUSTER_USER` ：OCPがテナントにBinlogサービスを有効にする際に作成されたsysテナントのcdcroユーザー、またはcdcroと同じ権限を持つ他のユーザーの使用を推奨します。
* `CLUSTER_PASSWORD` ：`CLUSTER_USER` ユーザーのパスワード。
* `IP` ：新規インスタンスレプリカのBinlog Serverアドレス。

```sql
CREATE BINLOG INSTANCE `binlog_instance_name` FOR `cluster_name`.`tenant_name` CLUSTER_URL = ?, CLUSTER_USER = ?, CLUSTER_PASSWORD = ?, IP = ?;
```

### ステップ3：ホスト上のBinlogインスタンスがマスターインスタンスの場合は、マスター切り替えを実行する

現在のホスト上のBinlogインスタンスがマスターインスタンスかどうかを判断します：

1. 任意のホストにログインし、以下のSQLを実行します。表示される情報がマスターインスタンスの情報であり、インスタンス名はstatus列の`binlog_instance`にあります。インスタンス名から、現在のホスト上のBinlogインスタンスがマスターインスタンスかどうかを判断できます。ホスト上のBinlogインスタンス名は、**ステップ1**で確認できます。ここでは：

   * `cluster_name` ：OceanBaseクラスタ名。
   * `tenant_name` ：テナント名。

    ```sql
    MySQL [(none)]> SHOW BINLOG STATUS FOR TENANT cluster_name.tenant_name;
    *************************** 1. row ***************************
    cluster: ob0709
    tenant: tenant1
    status: {"binlog_instance":"ad6tev7wc6","resources_metrics":{"client_id":"/home/admin/binlogservice/run/ad6tev7wc6","fd_count":83,"pid":370592,"cpu_status":{"cpu_count":22,"cpu_used_ratio":0.0009103322518058121},"disk_status":{"disk_total_size_mb":500923,"disk_usage_size_process_mb":0,"disk_used_ratio":0.0,"disk_used_size_mb":32945},"memory_status":{"mem_total_size_mb":178796,"mem_used_ratio":0.005386026576161385,"mem_used_size_mb":963},"network_status":{"network_rx_bytes":25383,"network_wx_bytes":25026}},"binlog_files":[{"binlog_name":"mysql-bin.000001","binlog_size":155}]}
    1 row in set (0.01 sec)
    ```

2. 現在のホスト上のBinlogインスタンスがマスターインスタンスの場合は、`SWITCH MASTER INSTANCE TO new_master_instance_name FOR TENANT cluster_name.tenant_name` を実行してマスター切り替えを行います。ここでは：

   * `new_master_instance_name` ：新しいマスターインスタンスに切り替える計画のインスタンス名。
   * `cluster_name` ：OceanBaseクラスタ名。
   * `tenant_name` ：テナント名。

    ```sql
    MySQL [(none)]> SWITCH MASTER INSTANCE TO c5410cbup4 FOR TENANT ob0709.tenant1;
    Query OK, 0 rows affected (0.01 sec)
    ```

### ステップ4：ホスト上のBinlogインスタンスレプリカを削除する

`DROP BINLOG INSTANCE instance_name FORCE` を実行して、ホスト上のBinlogインスタンスレプリカを削除します。ここで、`instance_name` はそのホスト上のBinlogインスタンスのインスタンス名です。

```sql
MySQL [(none)]> DROP BINLOG INSTANCE c5410cbup4 FORCE;
Query OK, 0 rows affected (0.00 sec)
```
