# Binlogサービスの概要

Binlogサービスは、OceanBaseのトランザクションログを収集し、MySQL Binlogに変換するサービスであり、主にリアルタイムデータサブスクリプションなどのシナリオで利用されます。OCPは、GUIベースの単一マシンデプロイメントまたはクラスタモードでのBinlog Serviceデプロイメントをサポートしており、Binlogクラスタおよびインスタンスに対する基本的な運用保守操作を実行できます。同時に、OCPはBinlog Serviceの監視・アラート機能をサポートしており、Binlogクラスタのリソース使用状況ビューを提供し、アラートとの連携も可能です。これにより、問題の迅速な特定と解決が容易になります。

## 背景

MySQLでは、Binlogはデータサブスクリプションを実現するための出発点となります。ユーザーはパフォーマンスへの影響とリソース消費を抑えてBinlogログを有効にすることができ、多くのダウンストリーム業務シナリオを実現できます。

OceanBase Binlog Serviceは、MySQL Binlog機能との互換性を提供するために導入された機能であり、既存のMySQL Binlog増分解析システムを再利用してOceanBase MySQLモードの増分データを同期することをサポートします。これにより、二次開発や新しい環境の構築は不要です。Binlog ServiceはMySQL Binlog V4バージョンのプロトコルと整合性があり、同じ機能（複数のサブスクリプション接続のサポートなど）、特性（GTID取得モードのサポートなど）を備えており、Binlogログ内のデータの一意性も保証します。既存のMySQLベースの増分データサブスクリプションソリューションをシームレスに使用し、OceanBaseに切り替えることができます。

<h4>注意</h4>
<p>OceanBaseが提供するBinlogサービスは、現在、プライマリ/スタンバイ構成や増分復元などのシナリオには適用されません。</p>

## アーキテクチャの紹介

**<UI-TERM key="ocp-v2.Component.BinlogService.BinlogCluster">Binlogクラスタ</UI-TERM>**

Binlogクラスタは、1つまたは複数のBinlog Serverで構成される統一された外部サービスです。Binlogクラスタ内に複数のBinlog Serverが存在する場合、テナントのBinlogサービスが起動すると、ロードバランシングのロジックに基づいて適切なBinlog Serverが選択されます。任意の1台のBinlog Serverに障害が発生した場合、他の正常なBinlog ServerがそのBinlogサービスを引き継ぎます。

**Binlog Server**

Binlog Serverは、ノード上の複数のBinlogインスタンスを管理し、SQLリクエストを処理します。複数のBinlog Server間では、MetaDBを通じて情報が共有されます。Binlog ServerはカスタムSQL APIの処理をサポートしており、主にBinlogインスタンスの管理操作を行います。

**Binlog Instance**

Binlog Instanceはテナント粒度のBinlogインスタンスであり、Binlogログの生成と送信を担当し、MySQLプロトコルに従ってTCP監視を開始し、SQLリクエストを処理します。1つのOceanBase Binlogインスタンスは、MySQLインスタンスに類似します。同一テナント内の複数のOceanBase Binlogインスタンスは、MySQLのプライマリ/スタンバイインスタンスに類似し、`SHOW MASTER STATUS` などのMySQL Binlog関連のSQL、プロトコル、変数を処理することをサポートします。

## OCPを使用したBinlogサービスの利用

### サービス制限

Binlog Serviceは、各サービスおよびテナントモードに対して以下の制限があります：

* OBServerバージョンはV4.1.0.1以上が必要です。
* OBProxyバージョンはV4.2.1以上が必要です。V4.3.1.0-402024062810またはV4.2.1.0-20240604114727の使用を推奨します。
* Binlog ServiceバージョンはV4.0.0以上が必要です。
* MetaDBバージョンは2.2.77 (Built Feb 14 2022 18:11:59)以上が必要です。
* テナントはMySQLモードのみをサポートします。

### 環境準備

1. 現在、Binlogサービスはjq、mysql、java、diffに依存しています。事前にホスト上で手動でインストールする必要があります。インストールの例は以下のとおりです。実際の環境に応じてインストールしてください：

    ```bash
    # 1. jq
    sudo yum install jq

    # 2. mysql
    sudo yum install mysql

    # 3. java
    # もしお使いの環境にJavaがインストールされている場合は、環境変数を設定してください。
    sudo yum install java-1.8.0-openjdk*
    echo "export JAVA_HOME=/usr/lib/jvm/java-1.8.0" >> /etc/profile
    echo "export JRE_HOME=${JAVA_HOME}/jre" >> /etc/profile
    echo "export CLASSPATH=${JAVA_HOME}/lib:${JRE_HOME}/lib:${CLASSPATH}" >> /etc/profile
    echo "export PATH=${JAVA_HOME}/bin:${JRE_HOME}/bin:${PATH}" >> /etc/profile

    # 4. diff
    sudo yum install diffutils
    ```

    ここで、`echo "export JAVA_HOME=/usr/lib/jvm/java-1.8.0" >> /etc/profile` では、環境に実際に存在するJavaのディレクトリを指定する必要があります。これは、`ls /lib/jvm | grep java` または `which java` コマンドで確認できます。

2. 依存関係が正常にインストールされているか確認します：

    ```bash
    # 1. jq
    command -v jq

    # 2. mysql
    command -v mysql

    # 3. java
    echo $JAVA_HOME

    # 4. diff
    command -v diff
    ```

### クイックスタート

以下の手順を参考に、OCP上でBinlogサービスを利用できます：

1. バージョン要件を満たすOceanBaseクラスタ、OceanBaseテナント、およびOBProxyクラスタを作成します。

    詳細については、[クラスタの作成](../600.cluster-functions/200.create-a-cluster/100.create-a-distributed-cluster.md)、[テナントの作成](../700.tenant-functions/300.create-a-tenant.md)、および[OBProxyクラスタの作成](../800.obproxy-functions/200.create-an-obproxy-cluster.md)を参照してください。

2. OceanBase Binlogサービスの機能は、別途提供されるBinlogコンポーネントに依存しています。Binlogクラスタを作成することで、関連コンポーネントを取得できます。

    詳細については、[Binlogクラスタの作成](200.create-a-binlog-cluster.md)を参照してください。

3. OceanBaseテナントでBinlogサービスを有効にし、OceanBaseのトランザクションログを収集してMySQL Binlogに変換するサービスを利用します。

    詳細については、[テナントのBinlogサービスの管理](../700.tenant-functions/600.manage-a-tenant/700.manage-binlog-service-of-a-tenant.md)を参照してください。
