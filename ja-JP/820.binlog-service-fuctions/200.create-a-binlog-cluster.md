# Binlogクラスタの作成

Binlogクラスタは、1つまたは複数のBinlog Serverで構成される統一された外部サービスです。Binlogクラスタ内に複数のBinlog Serverが存在する場合、テナントのBinlogサービス起動時にはロードバランシングのロジックに基づいて適切なBinlog Serverが選択されます。任意の1台のBinlog Serverに障害が発生した場合、他の正常なBinlog ServerがそのBinlogサービスを引き継ぎます。

ビジネスニーズに応じて、管理対象のBinlogクラスタを新規作成できます。

## 前提条件

現在OCPにログインしているユーザーが **ADMIN** ロールまたは **ORG_ADMIN** ロールを持つこと。

## 手順

1. OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogService">Binlogサービス</UI-TERM>** をクリックします。

2. Binlogの **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">クラスタ一覧</UI-TERM>** ページに移動し、右上の **<UI-TERM key="ocp-v2.Binlog.New.CreateABinlogCluster">Binlogクラスタを作成する</UI-TERM>** をクリックします。

3. **<UI-TERM key="ocp-v2.page.Binlog.CreateABinlogCluster">Binlogクラスタを作成する</UI-TERM>** ページで、クラスタの基本情報を設定します。

     |構成パラメータ|説明|
     |-----|-------|
     | **<UI-TERM key="ocp-v2.page.Binlog.BinlogClusterName">Binlogクラスタ名</UI-TERM>**          | 管理するBinlogクラスタのカスタム名です。クラスタ名は英字で始まり、英字または数字で終わる必要があります。英字、数字、アンダースコアを含み、長さは2～32文字である必要があります。|
     | **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareVersion">ソフトウェアバージョン</UI-TERM>**         | Binlogクラスタのソフトウェアパッケージバージョンを選択します。リストに利用可能なソフトウェアパッケージがない場合、リストの下部にある **<UI-TERM key="ocp-v2.src.component.PackageSelect.UploadASoftwarePackage">ソフトウェアパッケージをアップロード</UI-TERM>** をクリックしてアップロードできます。  |
     | **<UI-TERM key="ocp-v2.Detail.Overview.Endpoint">アクセスアドレス</UI-TERM>**          | Binlogクラスタのアクセスアドレスを入力します。これはOBProxyと現在のBinlogクラスタ間の通信要求転送およびロードバランシングに使用されます。   |
     | **<UI-TERM key="ocp-v2.TakeOver.Component.LoadBalancer.AccessPort">アクセスポート</UI-TERM>** | Binlogクラスタのアクセスポートです。デフォルトは **2983** で、カスタマイズ可能です。   |

4. MetaDB情報を設定します。

   MySQLテナントの関連情報を入力する必要があります。これはBinlogサービスのメタ情報を格納するために使用されます。業務クラスタは使用しないことを推奨します。

     | 構成パラメータ | 説明 |
     |------|---------|
     | アクセス方法 | Binlog MetaDBのアクセス方法です。クラスタの実際の接続方式に応じて選択できます。  |
     | **<UI-TERM key="ocp-v2.Cluster.Import.ClusterName">クラスタ名</UI-TERM>**    | 既存のOceanBaseクラスタをBinlogサービスのMetaDBとして選択します。選択したクラスタのバージョン番号はV2.2.77(Built Feb 14 2022 18:11:59)以上である必要があります。|
     | **<UI-TERM key="ocp-v2.Detail.Component.CloneTenantModal.TenantName">テナント名</UI-TERM>**    | クラスタ内の特定のMySQLテナントを選択します。   |
     | **<UI-TERM key="ocp-v2.Binlog.New.DatabaseUsername">データベースユーザー名</UI-TERM>**        | MySQLテナント内の特定のユーザーを選択します。rootユーザー以外を使用する場合は、**<UI-TERM key="ocp-v2.src.hook.useMenu.SafetyManagement">安全管理</UI-TERM>** > **<UI-TERM key="ocp-v2.src.component.AddBinlogCredentialModal.CredentialManagement">認証情報管理</UI-TERM>** に移動して、現在のユーザーの資格情報を追加し、十分な権限を付与してください。  |
     | **<UI-TERM key="ocp-v2.Detail.Overview.DatabaseName">データベース名</UI-TERM>**          | MetaDBデータベースの名前を入力します。デフォルトは `binlog_database` です。カスタム名をサポートし、長さは2～64文字で、数字(0～9)、大文字(A～Z)、小文字(a～z)、アンダースコア(_)、ハイフン(-)を含むことができます。   |
     | アクセスアドレス | Binlog MetaDBのアクセスアドレスです。Binlog MetaDBのアクセスアドレスをOBProxyクラスタのアクセスアドレスに設定するか、ロードバランシングデバイスからVIPアドレスを申請してOBProxy Serverにバインドすることを推奨します。これにより、アクセスの安定性とセキュリティが向上します。  |
     | アクセスポート | Binlog MetaDBのアクセスポートです。  |

5. Binlogクラスタをデプロイします。

   各Binlogクラスタは複数のBinlog Serverで構成されています。各Binlog Serverに必要な設定情報とその説明は以下のとおりです。

   |   構成   |  説明   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">データセンター</UI-TERM>**     | Binlog Serverが存在するデータセンターです。1つのBinlog Serverは1つのデータセンターにのみ存在できます。  |
   | **<UI-TERM key="ocp-v2.OBProxy.New.DeployMode.Models">機種</UI-TERM>**    | オプションです。機種を選択すると、後続のホストリストが機種に応じてフィルタリングされます。   |
   | **<UI-TERM key="ocp-v2.Detail.TakeOver.Host">ホスト</UI-TERM>**  | 複数のホストを選択するか、ホストの追加操作を行うことができます。   |

6. Binlogクラスタの起動パラメータを設定します。

   * 起動パラメータ項目を1つずつ追加し、値を設定することができます。

   * また、**<UI-TERM key="ocp-v2.page.Tenant.ParameterTemplate">パラメータテンプレート</UI-TERM>** をクリックしてパラメータテンプレートを選択することもできます。システムはテンプレート内のパラメータと設定を自動的にここに入力します。クラスタパラメータテンプレートが作成されていない場合は、**新規Binlogパラメータテンプレート** をクリックしてBinlogクラスタ用にパラメータテンプレートを作成できます。詳細については [Binlogパラメータテンプレートの管理](600.manage-binlog-parameter-templates.md) を参照してください。

   <!-- ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01242114.png) -->

   システムは以下の5種類の組み込みテンプレートを提供しており、各テンプレートには一般的なパラメータ設定が含まれています。これらのテンプレートを直接適用することで、Binlogクラスタの初期設定を行うことができます。

   | テンプレート      | 説明    |
   |-----------|---------|
   | トップレベルパフォーマンスパラメータテンプレート  | 推定リソース使用量 16コア 10GiB、推定RPS 20万～25万、4.2.0以降のバージョンでのみ適用可能です。    |
   | スーパーパフォーマンスパラメータテンプレート  | 推定リソース使用量 12コア 9GiB、推定RPS 15万～20万、4.2.0以降のバージョンでのみ適用可能です。 |
   | アドバンスドパフォーマンスパラメータテンプレート  | 推定リソース使用量 8コア 9GiB、推定RPS 10万～15万、4.2.0以降のバージョンでのみ適用可能です。    |
   | ミディアムパフォーマンスパラメータテンプレート  | 推定リソース使用量 4コア 8256MiB、推定RPS 8万～10万、4.2.0以降のバージョンでのみ適用可能です。    |
   | デフォルトパフォーマンスパラメータテンプレート  | 推定リソース使用量 2コア 8224MiB、推定RPS 5万～6万、4.2.0以降のバージョンでのみ適用可能です。    |

7. **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.CustomSettings">カスタム設定</UI-TERM>**モジュールでは、ソフトウェアのインストールパスをカスタマイズできます。パスはデフォルトで `/home/admin/binlogservice` ですが、変更は可能です。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E8%87%AA%E5%AE%9A%E4%B9%89%E8%AE%BE%E7%BD%AE.png) -->

8. **<UI-TERM key="ocp-v2.src.constant.iam.Create">作成する</UI-TERM>**をクリックします。

9. 作成前の事前チェックを実行し、システムは環境がBinlogクラスタの最低要件を満たしているかどうかを検証します。チェック項目の実行に失敗した場合は、ヒントに従って以下の操作を実行できます：

    * **<UI-TERM key="ocp-v2.Detail.Log.LogCard.SetToSuccessful">スキップする</UI-TERM>**：この操作は現在のチェック項目をスキップします（特別なシナリオ向けに設計されています）。関連するチェック項目が製品仕様を満たしていることを必ず確認してください。そうでない場合、後続のプロセスの実行が失敗する可能性があります。スキップすると、そのチェック項目の状態は **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.Warning">警告</UI-TERM>** に変わります。
    * **<UI-TERM key="ocp-v2.src.constant.task.TryAgain">再試行</UI-TERM>**：失敗の原因と最適化の推奨事項に基づいて問題を調査・修正し、修正後に **<UI-TERM key="ocp-v2.Sop.Main.TaskCard.Retry">再試行</UI-TERM>** をクリックして、失敗したチェック項目を再度実行します。
    * **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>**：すべての問題が調査・修正されたら、**<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">すべて再試行</UI-TERM>** をクリックして、失敗したすべてのチェック項目を再度実行します。

10. 実行失敗のチェック項目がなくなったら、**<UI-TERM key="ocp-v2.External.Component.CreateSlsDataSource.New">新規作成</UI-TERM>** をクリックします。新しいBinlogクラスタタスクを送信すると、**<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">タスクセンター</UI-TERM>** でそのタスクの実行進捗状況を確認できます。

## クラスタリストの概要

クラスタの作成が完了すると、**<UI-TERM key="ocp-v2.page.Cluster.ClusterList">クラスタ一覧</UI-TERM>** でBinlogクラスタの関連情報を確認できます。これには、**<UI-TERM key="ocp-v2.page.Binlog.BinlogClusterName">Binlogクラスタ名</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.State">ステータス</UI-TERM>**、**<UI-TERM key="ocp-v2.page.Binlog.AllocatedCpu">CPU割り当て済</UI-TERM>**、**<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">割り当て済みのメモリ</UI-TERM>**、**<UI-TERM key="ocp-v2.Detail.Resource.Trend.UsedDisks">データディスクはすでに使用されています</UI-TERM>**、**<UI-TERM key="ocp-v2.Binlog.Component.UpgradeBinlogModal.VersionNumber">バージョン番号</UI-TERM>**、**<UI-TERM key="ocp-v2.Cluster.Arbitration.CreationTime">作成日時</UI-TERM>**、および **<UI-TERM key="ocp-performance-report.ReportTables.ParameterStatInfo.ZoneParamInfoTable.ModificationTime">更新日時</UI-TERM>** が含まれます。

* クラスタ名をクリックすると、Binlogクラスタの概要ページに移動します。詳細については、[Binlogクラスタの概要を表示する](300.manage-a-binlog-cluster/100.binlog-cluster-overview.md)を参照してください。
* **<UI-TERM key="ocp-v2.Backup.SecondaryBackup.Log.State">ステータス</UI-TERM>** でBinlogクラスタをフィルタリングできます。

## 関連操作
