# アラートイベントの管理

この章では、アラートイベントの詳細を表示する方法と、そのアラートイベントを一時的にミュートする方法について説明します。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **クラスタ読み取り専用**、**テナント読み取り専用**、**OBProxy読み取り専用**、**アービトレーションサービス読み取り専用**、**Binlogサービス読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
* アラートセンターの **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.All">すべて</UI-TERM>** メニュー権限。

## アラートイベントの表示

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">アラートセンター</UI-TERM>** をクリックします。

3. システムはデフォルトで **<UI-TERM key="ocp-v2.page.Alarm.AlarmEvent">アラートイベント</UI-TERM>** タブに移動します。

4. クエリボックスにクエリ条件を設定すると、**<UI-TERM key="ocp-v2.page.Alarm.AlarmEvent">アラートイベント</UI-TERM>** リストにクエリ条件に一致するすべてのアラートイベントが返されます。アラート時間、アラートアプリケーション、アラート対象、アラートレベル、キーワードに基づいてアラートイベントを正確に検索できます。

    アラートリストで：

    * **アクティブイベント** と **履歴イベント** タブをクリックすると、アラートイベントリストを切り替えることができます。

    * **<UI-TERM key="ocp-v2.src.constant.parameter.Export">エクスポート</UI-TERM>** をクリックすると、クエリ条件に一致するすべてのアラートイベントをローカルにエクスポートできます。

    * アラートイベントにメッセージプッシュが設定されている場合、**<UI-TERM key="ocp-v2.Alarm.Event.MessagePush">プッシュ通知</UI-TERM>** 列の **未成功** をクリックすると、アラートイベントの詳細を見ることができます。

    * アラートイベントにメッセージプッシュが設定されていない場合、**<UI-TERM key="ocp-v2.Alarm.Event.MessagePush">プッシュ通知</UI-TERM>** 列の **メッセージプッシュ未設定** をクリックすると、アラートプッシュの設定を行うことができます。詳細については、[新規アラートプッシュの作成](600.manage-alert-push/100.create-an-alert-push.md)を参照してください。

5. 表示したいアラートイベントを選択し、アラートの説明をクリックすると、アラートイベントの詳細ページに移動します。

   1. アラートの **<UI-TERM key="ocp-performance-report.pages.Report.Content.BasicInformation">基本情報</UI-TERM>** を確認します。これには、ID、アプリケーション、オブジェクトタイプ、アラート対象、アラートルール、ソース、発生時間、回復時間、アラート分類、最終アラート時間が含まれます。

       * **<UI-TERM key="ocp-v2.Alarm.Event.Detail.AlertObject">アラート対象</UI-TERM>** の名前をクリックすると、アラート対象の詳細情報を見ることができます。
       * **<UI-TERM key="ocp-v2.Alarm.Rule.AlertRules">アラートルール</UI-TERM>** の名前をクリックすると、そのアラートルールの詳細情報を見ることができます。アラートルールを変更する必要がある場合は、ルールの詳細ページの **<UI-TERM key="ocp-v2.Alarm.Rule.New.EditAlertRules">アラートルールの編集</UI-TERM>** ボタンをクリックして調整できます。詳細については、[アラートルールの変更](300.manage-alert-rules/400.edit-an-alert-rule.md)を参照してください。

   2. **<UI-TERM key="ocp-v2.page.Alarm.AlarmEvent">アラートイベント</UI-TERM>** の詳細情報を確認します。

      * **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ViewAlertHandlingSuggestions">アラートの推奨処理方法を確認する</UI-TERM>** をクリックすると、この種のアラートに関する処理推奨事項を見ることができます。
      * **<UI-TERM key="ocp-v2.components.licenseFiles.ImportLicenseModal.Analysis">解析</UI-TERM>** ボタンをクリックすると、AIアシスタントからこのアラートに関するインテリジェントな解釈を得ることができます。AIアシスタントについては、[AIアシスタント](../1075.ai-management/100.ai-overview.md)を参照してください。

   3. **<UI-TERM key="ocp-v2.page.Alarm.AlarmEvent">アラートイベント</UI-TERM>** 関連情報を確認します。これには、**アラート時間**、**<UI-TERM key="ocp-v2.page.Overview.AlarmLevel">アラートレベル</UI-TERM>**、および **<UI-TERM key="ocp-v2.component.alarm.RuleDetail.AlertStatus">アラート状態</UI-TERM>** が含まれます。

   4. アラートのトリガー方式がモニタリング指標の式に基づく場合、そのモニタリング指標のトレンドグラフを表示できます。

   5. **<UI-TERM key="ocp-v2.Alarm.Event.Detail.AlertMessage">アラートメッセージ</UI-TERM>** リストでアラートメッセージの通知履歴を確認します。

## アラートのミュート

確認する必要のないアラートメッセージについては、以下の2つの方法を参考に迅速にミュートできます。アラートをミュートすると、設定された終了時間まで、そのアラートはミュート期間中に報告されません。具体的な設定方法については、[新規ミュート条件の作成](800.manage-blocking-conditions/100.create-a-blocking-condition.md)を参照してください。

* アラートリストで、操作列の **ミュート** をクリックします。
* アラートイベントの詳細ページで、右上の **<UI-TERM key="ocp-v2.Alarm.Event.Detail.MaskAlarm">アラートの無効化</UI-TERM>** をクリックします。

## アラートの解消

アラートイベントが解決した場合、以下の2つの方法を参考にアラートメッセージを解消できます。アラートを解消すると、そのアラートのステータスは **<UI-TERM key="ocp-v2.src.constant.alarm.Resolved">解決済み</UI-TERM>** に変わり、**<UI-TERM key="ocp-v2.Alarm.Event.HistoricalAlerts">履歴アラート</UI-TERM>** リストに追加されます。この時点では、そのアラートに対していかなる操作も行えません。

* ログアラートタイプで、アラートが1回だけ発生し、手動で確認が必要なアクティブなアラートイベントについては、アクティブアラートリストの操作列の **<UI-TERM key="ocp-v2.Alarm.Event.Solution">解決する</UI-TERM>** をクリックします。
* アラートイベントの詳細ページで、右上の **<UI-TERM key="ocp-v2.Alarm.Event.Solution">解決する</UI-TERM>** をクリックします。

## 関連操作

受信するアラートイベントが多すぎる場合、必要に応じてアラートをクリーンアップできます。

1. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">システム管理</UI-TERM>** **\>** **<UI-TERM key="ocp-v2.Detail.Parameter.ParameterManagement">パラメータ管理</UI-TERM>** をクリックします。

2. パラメータリストで `ocp.alarm.notification.expired-days` パラメータを検索し、アラートアーカイブ日数を設定します。

    パラメータ設定後、アーカイブ日数を超えたアラートメッセージやアラートイベントの履歴記録は削除されます。主に以下の期限切れデータが含まれます：

    * `ocp2_alarm_notification`
    * `ocp_alarm_event_notification`
    * `ocp2_alarm_event_history`
    * `ocp_alarm_event_record`
    * `ocp2_alarm_filter`（クリーンアップされたデータは `ocp2_alarm_filter_history` に書き込まれます。ルール情報はそれほど多くないため、履歴テーブルはクリーンアップする必要はありません）。
