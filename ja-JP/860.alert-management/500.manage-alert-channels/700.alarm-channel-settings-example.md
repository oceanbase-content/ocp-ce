# アラートチャネル設定例

このドキュメントは、アラートチャネルとアラートプッシュの設定方法を説明するものです。細部は見落とされがちですが、実際の運用では頻繁に利用されます。

## 適用シナリオ

以下のシナリオでは、このドキュメントの内容が関係します：

1. 異なるアラートを異なる担当者に送信する場合。

2. JSON形式のアラートメッセージを送信する場合。

3. アラートメッセージのみを受信し、アラート復旧メッセージは受信しない場合。

4. アラートが正常に送信されたかどうかを確認する場合。

## アラートチャネルとアラートプッシュ

アラートチャネルとは、アラートメッセージを送信する媒体のことで、例えばDingTalkグループメッセージや顧客のアラートプラットフォームへの送信などが該当します。

アラートチャネルとアラートプッシュを設定することで、異なるアラートを異なる担当者に送信することが可能になります（まず特定のチャネルを通じて送信し、他のシステムで担当者に対応付けます。例：夜間当直グループ、DBAグループなど）。

## 指定言語のアラートメッセージを送信する

現在のOCPは、簡体字中国語、繁体字中国語、英語の3つの言語をサポートしており、アラートメッセージもこれら3つの言語を設定できます。異なる言語のメッセージを送信する必要がある場合は、アラートプッシュで設定します。

アラートメッセージを購読する際にチャネルに異なる送信言語を設定することで、運用保守スタッフの個別のメッセージニーズに対応できます。現在サポートされている設定項目は、zh_CN（簡体字中国語）、zh_TW（繁体字中国語）、en_US（英語）です。

## JSON形式のアラートメッセージを送信する

メッセージはアラートメッセージと復旧メッセージの2種類があり、処理方法が異なります。

* アラートメッセージ

  現在、OCPのアラートチャネル設定ページでは、アラートメッセージテンプレートと集約メッセージテンプレートを設定できます。これらのメッセージテンプレートはDingTalkグループメッセージに適用されます。JSON形式のメッセージを受信する必要がある場合は、以下の設定を行います。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>アラートメッセージは1つの言語で送信するだけなので、アラートプッシュルールの設定時にその言語のアラートを購読すればよいです。</p>
   </main>

  1. アラートメッセージテンプレートと集約メッセージテンプレートをどちらもJSON形式に設定します。

  2. メッセージ送信時に${message_json}メッセージテンプレート変数を参照します。${message_json}$は前の手順で設定したJSON形式のメッセージ`${message_json}`です。message_jsonはエスケープ済みのメッセージであり、再包装することはできません。例えば`{"content": ${message_json}}`は有効なJSON文字列ではありません。

   <main id="notice" type='notice'>
    <h4>注意</h4>
    <ul>
    <li>ステップ1でJSON形式のメッセージテンプレートを設定していない場合、ステップ2で設定するメッセージ内容は <code>{&quot;content&quot;: &quot;${message_json}&quot;}</code> となります。${message_json} は文字列ではなくJSON文字列であるため、二重引用符を付ける必要があります。</li>
    <li>${alarm_summary} および ${alarm_description} には、エスケープされていない文字が含まれている可能性があります。例えば、OceanBaseのログアラートでは、アラート内容には常に引用符や改行文字が含まれています。この場合、${alarm_summary} と ${alarm_description} を含む ${message_json} は有効なJSON構造ではないため、同様にメッセージ内容を <code>{&quot;content&quot;: &quot;${message_json}&quot;}</code> と設定する必要があります。</li>
    </ul>
   </main>

* メッセージの復元

  メッセージの復元テンプレートは、現在画面上での設定は提供されていません。コマンドラインを使用してmetadbのデータを変更する必要があります。操作手順は以下のとおりです：

  1. ocp_metaテナントのocpデータベースにログインします。

      ```shell
      obclient -hxxx.xxx.xxx.xxx -P2883 -ur***@ocp_meta#ob_cluster -p****** -Docp
      ```

  2. ocp2_alarm_channelテーブルの `recover_message_template_i18n` フィールドを更新します。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <p><code>recover_message_template_i18n</code> は文字列型で、格納されるデータはJSON構造です。</p>
      </main>
      ```sql
        update ocp2_alarm_channel set recover_message_template_i18n='{"recover_message_template_en_us":"OCP Alert Recovery Notification ${alarm_name}\n  - Target: ${alarm_target}\n  - Details: ${alarm_description}\n  - Recovered at: ${alarm_resolved_at} \n    ","recover_message_template_zh_tw":"OCP Warning Recovery Notification ${alarm_name}\n  - Warning Target: ${alarm_target}\n  - Warning Details: ${alarm_description}\n  - Recovery Time: ${alarm_resolved_at}\n    ","recover_message_template_zh_cn":"OCP Alert Recovery Notification ${alarm_name}\n  - Alert Target: ${alarm_target}\n  - Alert Details: ${alarm_description}\n  - Recovery Time: ${alarm_resolved_at}\n    ","recover_message_template_ja_jp":"OCPアラート復旧通知 ${alarm_name}\n  - 対象: ${alarm_target}\n  - 詳細: ${alarm_description}\n  - 復旧日時: ${alarm_resolved_at}\n    "}' where id = ;
      ```

  デフォルトの設定は以下のとおりです：

  ```SQL
  # 英文テンプレートのメッセージ復元テンプレート
  [Alert Recovery Notification]
  - Target ${alarm_target}
  - Details ${alarm_description}
  - Recovered at ${alarm_resolved_at}

  ## 簡体中文のメッセージ復元テンプレート
  【OCP アラート復旧通知】
  - アラート対象 ${alarm_target}
  - アラート詳細 ${alarm_description}
  - 復旧時間 ${alarm_resolved_at}

  ## 繁体中文のメッセージ復元テンプレート
  【OCP 警示復旧通知】
  - 警示対象 ${alarm_target}
  - 警示詳細 ${alarm_description}
  - 復旧時間 ${alarm_resolved_at}
  ```

アラートプッシュを設定する際に、アラート復元メッセージの受信を有効にするかどうかを設定できます。

## アラート送信結果の検証

OCPバージョンがV3.3.0未満の場合、送信がターゲットに成功したかどうかのみを成功の基準とし、アラートメッセージの返却結果は検証されませんでした。応答結果にエラーコードや失敗を示すフィールドが含まれている場合、OCPはそれを検証する必要があります。そのため、OCP V3.3.0バージョンでは、`ocp2_alarm_channel`に`response_validation`フィールドが追加され、検証に使用されます。その検証ルールは以下の通りです：

* 返却結果がJSON形式の場合、`response_validation`もJSON文字列（デフォルトは"{}"）に設定し、両者が一致するかどうかを比較します。アラートメッセージの返却内容には、`response_validation`のすべてのkey-value内容が含まれている必要があります。例えば、DingTalkグループメッセージチャネルの`response_validation`フィールドを`{"errcode":0,"errmsg":"ok"}`に設定した場合、エラーコードが0であれば送信結果は成功を示します。

* 返却結果がJSONでない場合、`response_validation`は返却結果と同じでなければなりません。

  <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>スクリプトチャネルの返却結果には標準エラーと標準出力が含まれます。スクリプトの標準エラーを優先的に<code>response_validation</code>と照合します。スクリプトの標準エラー（stderr）が空の場合、スクリプトの標準出力（stdout）を<code>response_validation</code>と照合します。スクリプトの仕様は以下の通りです：</p>
    <ol>
    <li>スクリプトがアラートメッセージの送信に失敗した場合、応答結果を標準エラーに出力します。</li>
    <li>プログラムが標準エラーに情報を出力していない場合、応答結果を標準出力にのみ出力します。スクリプトで他のログを出力すると、送信失敗と誤判断される可能性があります。</li>
    </ol>
  </main>

したがって、OCPをアップグレードした後は、以下の操作が必要です：

1. `response_validation`に適切な値を設定します。

2. アラートチャネルのスクリプトに出力ログが存在するか確認し、応答ボディを標準エラーまたは標準出力にのみ出力するよう変更する必要があります。

WebインターフェースでHTTPチャネルまたはスクリプトチャネルを設定する場合は、「Response検証情報」フィールドを設定する必要があります。その他のタイプのアラートチャネルには固定の組み込み設定があり、Webインターフェースでの設定は不要です。
