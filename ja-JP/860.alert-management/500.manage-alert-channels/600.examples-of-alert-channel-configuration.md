# アラートチャネル設定例を見る

このドキュメントでは、一般的なアラートチャネルの設定例を挙げています。参考にしてください。

## DingTalkチャネル

DingTalkグループのボットのWebhookを利用してグループメッセージの送信を実現できます。DingTalkアラートチャネルを設定するには、以下の2つの操作が必要です：

* アラートを受信するDingTalkグループにボットを設定します。
* OCPでDingTalkチャネル情報を設定します。

### DingTalkグループボットの設定

1. PCで、アラート通知を受信するDingTalkグループを開きます。

2. 上部メニューバーの**グループ設定**ボタンをクリックします。

3. ポップアップパネルで、**インテリジェントグループアシスタント > ボットを追加**をクリックします。

4. **グループボット**ポップアップウィンドウで、![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E8%AE%BE%E7%BD%AE%E5%9B%BE%E6%A0%871.png)をクリックし、追加するボットを選択します。

5. **<UI-TERM key="ocp-v2.Plan.Component.PlanTemplateTable.Custom">カスタマイズ</UI-TERM>**ボットをクリックし、**ボット詳細**ポップアップウィンドウで**<UI-TERM key="ocp-v2.alarm.FormListWithExclude.OBServerWithExclude.Add">追加</UI-TERM>**をクリックします。

6. **ボット名**および**<UI-TERM key="ocp-v2.Tenant.New.SecuritySettings">セキュリティ設定</UI-TERM>**を含むボット情報を設定します。

   セキュリティ設定には、**カスタムキーワード**、**署名**、**IPアドレス範囲**の3種類のモードがあります。[カスタムボットのセキュリティ設定](https://open.dingtalk.com/document/robots/customize-robot-security-settings)を参照し、必要に応じて1つを選択して設定してください。ここでは**カスタムキーワード**を例とします。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E6%B7%BB%E5%8A%A0%E6%9C%BA%E5%99%A8%E4%BA%BA1.png) -->

7. **「カスタムボットサービスおよび免責事項」を読み、同意しました。**にチェックを入れ、**<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>**をクリックします。

8. **ボットの追加**ダイアログで、生成されたボットのWebhookアドレスをコピーし、**<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Complete">完成しました</UI-TERM>**をクリックします。

### DingTalkチャネル情報の設定

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">アラートセンター</UI-TERM>**をクリックします。

3. **<UI-TERM key="ocp-v2.Alarm.Subscriptions.New.AlarmChannel">アラートチャネル</UI-TERM>**タブをクリックします。

4. アラートチャネルタブで、**<UI-TERM key="ocp-v2.Alarm.Channel.New.CreateAChannel">新規チャネル</UI-TERM>**をクリックします。

5. チャネルの**<UI-TERM key="ocp-v2.Detail.Overview.BasicInformation">基本情報</UI-TERM>**を設定します。

   |  パラメータ  |  説明    |
   |------|-------|
   |チャネルタイプ|**<UI-TERM key="ocp-v2.src.constant.alarm.Dingtalk">DingTalk</UI-TERM>**を選択します。|
   |チャネル名  |  アラートチャネルの名前。    |
   |  Webhookアドレス  |  DingTalkボット設定後に生成されたWebhookアドレス、すなわち**DingTalkグループボットの設定**の**手順8**でコピーしたアドレスです。       |
   |  署名キー  |  オプションです。DingTalkボットのセキュリティ設定で**署名**モードを選択した後に取得した署名キー文字列です。        |
   |  指定ユーザー  |  オプションです。DingTalkグループメンバーの携帯電話番号。       |
   | プロキシ        |  オプションです。アラート情報を送信するプロキシを入力してください。形式は`http:ip:port`です。ここで、ipはプロキシサーバーのIP、portはアラート送信に使用するポートです。プロキシサーバーのIPがxxx.xxx.xxx.xxxで、アラートメッセージの送信にポート80を使用する場合は、`http:xxx.xxx.xxx.xxx:80`と設定できます。 <main id="notice" type='explain'><h4>説明</h4><p>HTTPチャネルのみがプロキシ設定を必要とします。</p></main>   |

6. **<UI-TERM key="ocp-v2.Alarm.Channel.New.SendTestMessages">テストメッセージを送信</UI-TERM>** をクリックし、アラートが正常に送信されるか確認します。

7. 送信に成功した場合、**<UI-TERM key="ocp-v2.Detail.Parameter.List.Submitted">送信</UI-TERM>** をクリックします。

## カスタムスクリプトチャネル

カスタムスクリプトチャネルは、特殊なアラート連携シナリオに対応するために設計されています。一般的に、HTTPでの設定が不可能である場合や、アラート形式に特別な要件がある場合に使用されます。スクリプト内で独自のロジックをカスタマイズできます。例えば、アラート時間の変換や、サードパーティアラートゲートウェイのデフォルトパラメータの追加など、カスタムスクリプトチャネルを通じて実現できます。

* 基本情報：チャネルタイプに「カスタムスクリプト」を選択し、その他のオプションは具体的なニーズに応じて選択します。

* チャネル設定：

  * スクリプト内容：[OCP アラートテンプレートタグ](../900.ocp-alert-template-variables.md) を参照し、スクリプト内でタグとして参照します。

  * Response検証情報：アラートスクリプトの記述が不適切であったり、API応答が不規則だったり（送信失敗でも200応答コードを返す）した場合に、ユーザーがアラートを受け取れない、アラートが漏れるなどの問題を防ぐために使用されます。アラートスクリプトから出力される情報は、有効なものが1回だけである必要があります（API応答コードまたはAPI応答ボディのいずれか）。OCPが情報の一致を検証します。正規表現マッチングとJSONキー値ペアマッチングをサポートしています。検証フィールドとAPIが返す内容が一致しない場合、OCPはアラート送信失敗と判断し、再送信を試みます。ユーザーは既にメッセージを受信済みで、インターフェース上で失敗と判定されただけの場合、ユーザーに複数回のアラートが届く可能性があります。検証ルールは以下の通りです：

    * 返された結果がJSON形式の場合、Response検証情報もJSON文字列（デフォルトは`{}`）に設定し、両者が等しいかどうかをマッチングします：APIが返す内容には、Response検証情報のすべてのkey-value内容が含まれている必要があります。例えば、APIが`{"成功的标志1":"成功","错误码":0,"当前时间戳":"2023-09-12T10:00:00+8:00"}`を返した場合、Response検証情報は以下のいずれかの設定が可能です：`{"成功的标志1":"成功","错误码":0}`、`{"成功的标志1":"成功"}`、`{"错误码":0}`。
    * 返された結果がJSONでない場合、Response検証情報は返された結果と同じである必要があります。例えば、API応答結果がsuccessの場合、Response検証情報は`success`に設定する必要があります。API応答結果が`success:2023-09-12T10:00:00+8:00`の場合、Response検証情報は正規表現`success.*`に設定する必要があります。
    * 現在、返された結果がJSON形式かどうかは、先頭が`{`、末尾が`}`であることのみで判断しています。応答結果がちょうどこの状況になっていて、JSON形式ではない場合、システムが誤って判断する可能性があります。

* アラートメッセージテンプレート：

  ```javascript
  OCP アラート通知-単一アラート
  - 名前：${alarm_name}
  - レベル：${alarm_level}
  - アラート対象：${alarm_target}
  - 概要：${alarm_summary}
  - 生成時間：${alarm_active_at}
  - 詳細：${alarm_description}
  - OCPリンク：${alarm_url}
  ```

* アラート回復メッセージテンプレート：

  ```javascript
  OCP アラート回復通知 ${alarm_name}
  - アラート対象：${alarm_target}
  - アラート詳細：${alarm_description}
  - 回復時間：${alarm_resolved_at}
  ```

* アラートメッセージ集約テンプレート：

  ```javascript
  OCP アラート通知-複数アラート
  - 名前：${alarm_name}
  - レベル：${alarm_level}
  - アラート数：${alarm_count}
  - 集約グループ：${alarm_group_by}
  - アラート対象：${alarm_target}
  - 生成時間：${alarm_active_at}
  ```

* スクリプトファイル名：システムにはデフォルトでカスタムスクリプトのサンプルとして `alarm_send_script_demo.sh` があります。これを基に変更するか、**Pythonスクリプトの例** および **Bashスクリプトの例** を参考に新しいカスタムスクリプトを追加することができます。ファイルを変更または新規作成する際は、そのスクリプトファイルが各OCPの `/home/admin` ディレクトリに配置されていることを確認してください。

* テストメッセージの送信：スクリプトをデバッグする際は、テストメッセージを送信してテストできます。デフォルトのメッセージ内容はスクリプト内の変数 `${message}` を使用します。この変数が送信されるメッセージ本文に含まれていることを確認してください。カスタムスクリプトの送信成功の判定ロジックはケースによって異なるため、システムではスクリプトが正常に実行されれば送信成功とみなします。ただし、ブラウザの開発者モードでは、ユーザーはテストメッセージに対応する _test リクエストのResponse内容を確認してデバッグできます。

### Pythonスクリプトの例

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-

# 注意：スクリプトの最初の行は、shebangで実行プログラムを指定する必要があります。pythonとbashのみサポートされています。

import json
import requests
import os
import sys

ACCESS_TOKEN = "Ding Talk Token"

def send_alarm():
    """
    os.environを使って環境変数からアラート関連の値を取得できます。
    サポートされている変数の一覧については、「OCP アラートテンプレート変数」を参照してください。
    """
    message = os.environ['message']
    data = {
        "msgtype": "markdown",
        "markdown": {
            "text": message
        }
    }
    resp = requests.post("https://oapi.dingtalk.com/robot/send?access_token=" + ACCESS_TOKEN, json=data)
    resp.close()
    response = json.loads(resp.text)

    # 実行結果を標準エラー(stderr)または標準出力(stdout)に出力します。これはアラートが正常に送信されたかどうかの検証に使用されます。優先的にstderrを検証します。
    if not response['errcode'] == 0:
        sys.stderr.write(resp.text)
    else:
        print(resp.text)

def main():
    """
    送信成功時、戻り値は0です。
    送信失敗時、エラーはstderrに出力され、戻り値は0以外になります。
    """
    try:
        send_alarm()
        return 0
    except Exception as e:
        sys.stderr.write(str(e))
        return 1

if __name__ == "__main__":
    sys.exit(main())
```

### Bashスクリプト例

```bash
#!/usr/bin/env bash

# should contains shebang in first line, only python/bash are supported

# this function defines to how to assembly request by yourself according to your requirements
# this demo shows you how to send alarm to ding ding
function send() {
    # this token is ding ding group token, please apply and assign it to variable token
    token='Ding Talk Token'
    URL="https://oapi.dingtalk.com/robot/send?access_token=$token"

    # if message is json format, use "'"${message}"'" or "${message}", do not wrapper a new json body
    # if message is not json format, use "${message}"
    # do not use '${message}'
    # print the response to stderr or stdout, which will be validated if success, validate stderr firstly.
    curl -s -X POST ${URL} -H 'Content-Type: application/json' -d '{"msgtype":"text","text":{"content":"'"${message}"'"}}'

    return $?
}

# invoke function to
send
```
