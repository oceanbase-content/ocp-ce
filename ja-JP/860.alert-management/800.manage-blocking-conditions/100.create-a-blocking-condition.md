# ブロッキング条件の作成

この章では、アラートをブロックする方法について説明します。

## 背景

[アラートイベントの表示](../700.view-an-alert-event.md)に記述されているように、**<UI-TERM key="ocp-v2.page.Alarm.AlarmEvent">アラートイベント</UI-TERM>**タブでアラートを迅速にブロックできますが、アラートイベントが発生しているアラート項目のみをブロックできます。この章では、より柔軟で包括的なブロック方法を紹介します。気にしないアラートに対しては、事前に対処できます。

ブロッキング条件の作成が完了すると、システムはその条件に従ってアラートをブロックします。このブロックは30秒以内に有効になります。

## 前提条件

現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

* **クラスタメンテナンス**、**テナントメンテナンス**、**OBProxyメンテナンス**、**アービトレーションサービスメンテナンス**、**Binlogサービスメンテナンス**、または**ホストメンテナンス**のいずれかのリソース権限。
* アラートセンターの**<UI-TERM key="ocp-v2.alarm.FormListWithExclude.TenantWithExclude.All">すべて</UI-TERM>**メニュー権限。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.src.hook.useMenu.AlarmCenter">アラートセンター</UI-TERM>**を選択します。

3. **<UI-TERM key="ocp-v2.Alarm.Event.Detail.MaskAlarm">アラートの無効化</UI-TERM>**タブをクリックします。

4. アラートのブロックタブで、**<UI-TERM key="ocp-v2.Alarm.Shield.CreateAShieldingCondition">新規マスクルール作成</UI-TERM>**をクリックします。

5. **<UI-TERM key="ocp-v2.Alarm.Shield.CreateAShieldingCondition">新規マスクルール作成</UI-TERM>**ダイアログで、ブロッキング条件を設定します。

   |  ブロッキング条件  |    設定説明    |
   |--------|--------|
   | アプリケーション     | アラートの出所。OceanBase、OBProxy、OCP、OMS、OBLB、OBDNS、およびログから選択できます。   |
   | ブロック対象タイプ   | 実際のニーズに応じて、ブロック範囲を全部、テナント、またはサーバーから選択します。オプションの表示は、選択したアプリケーションによって異なります。   |
   | ブロック対象   | 実際のニーズに応じて、具体的なアラート対象を選択します。</br>全体のオブジェクトを選択した場合、右側の**<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ClusterWithExclude.ExcludeObjects">除外対象</UI-TERM>**をチェックすることで、ブロック不要のオブジェクトを除外できます。  |
   |アラートブロックルール   | ブロックするアラートを選択します。複数選択可能です。|
   | タグ  | 指定されたメトリクスに対するブロックをサポートします。例えば、スローSQLアラートでは、SQL IDでフィルタリングできます。最大8つのタグを追加できます。<br>アラートのブロックタグの表示方法については、[アラートのよくある質問](../../2000.faq/500.common-issues.md)の**アラートタグはどのように見るのですか？**の章を参照してください。 |
   | ブロック終了時間   | アラートブロックの終了時間を設定します。終了時間まで、ブロックされたアラートは報告されません。必須項目です。 <ul><li>ボックス内をクリックして、終了時間をカスタマイズできます。</li><li> ボックス後ろの時間もクリックできます。例えば、**<UI-TERM key="ocp-v2.src.constant.alarm.Hours">6時間</UI-TERM>**をクリックすると、システムは現在時刻に6時間を加算してボックスに入力します。</li>    |
   | 毎日のブロック時間帯 | 毎日のブロック時間帯スイッチをオンにし、開始時間と終了時間を設定します。システムは毎日の該当時間帯にアラートをブロックします。   |
   | 備考 | ブロックルールの説明を追加することで、後の参照や識別、再利用が容易になります。   |

   特定のアラートをブロックする必要がある場合、**<UI-TERM key="ocp-v2.component.TagLabel.Label">タグ</UI-TERM>**を追加してアラートを正確に照合できます。例えば、**adminMT**クラスタの**meta2**テナントの特定のスローSQLアラートをブロックする場合、詳細な設定は以下のとおりです：

      * （オプション）**タグ名**を“ob_cluster”、タグ値をクラスタ名“**adminMT**”として追加します。
      * （オプション）**タグ名**を“ob_cluster_id”、タグ値をクラスタID“**15**”として追加します。クラスタIDの指定は、プライマリ/スタンバイクラスタを区別するために使用されます。
      * （オプション）**タグ名**を“tenant_name”、タグ値をテナント名“**meta2**”として追加します。
      * **タグ名**を“sql_id”、タグ値をそのスローSQLのSQL IDとして追加します。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>アラートがすべてのタグを満たす場合にのみ、システムはそれをマスクします。上記の設定における <strong>オプション</strong> の情報は、タグの理解と使用を深めるためのものであり、実際の運用ではこの部分の設定を省略することができます。</p>
   </main>

   ![Image 128](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/alerts/%E6%96%B0%E5%BB%BA%E5%B1%8F%E8%94%BD%E6%9D%A1%E4%BB%B61-1.png)

6. **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.Ok">確定</UI-TERM>** をクリックします。

   システムは **マスク条件** リストを返し、そのリストに新しいマスク条件としてデータが追加されます。

   **マスク条件** リストには、すべてのアラートマスク設定が表示されます。**<UI-TERM key="ocp-v2.src.constant.alarm.InEffect">有効</UI-TERM>** または **<UI-TERM key="ocp-v2.src.constant.inspection.Expired">期限切れ</UI-TERM>** のマスクリストを表示するよう選択できます。デフォルトでは、ログインユーザーが作成したアラートマスク設定が表示されます。

   <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>アラートマスク条件を作成しても、即時に反映されない場合があります。最大で30秒かかることがあります。</p>
   </main>
