# OBKV_Redisの表示

このページでは、テナントのOBKV_Redisタイプの監視データを表示する方法について説明します。OBKV-Redisは、OceanBaseデータベースV4.2.5バージョンからサポートされた機能であり、OceanBaseデータベースを基盤として開発された、Redisプロトコルと完全に互換性のある永続化キャッシュデータベースです。OBKV-Redisは、従来のRedis + RDSの高コスト、スケーラビリティの低さ、運用保守と管理の複雑さ、データの一貫性とセキュリティの保証が難しいといった課題を解決することを目的としています。OBKV-RedisのP99は10ms以内であり、80%のシナリオにおけるレイテンシとスループットの要件を満たしています。

以下の2つのエントリからOBKV_Redisの監視データを表示できます：

* **エントリ1**：OCPにログインし、テナント概要ページに移動した後、左側のナビゲーションバーの**<UI-TERM key="ocp-v2.Instance.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**をクリックします。

* **エントリ2**：OCPにログインし、左側のナビゲーションバーで**<UI-TERM key="ocp-v2.src.hook.useMenu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**をクリックし、**<UI-TERM key="ocp-v2.Task.TaskObjectAndType.OceanbaseTenants">OceanBase テナント</UI-TERM>**タブに移動します。

## 前提条件

* **エントリ1**でテナントOBKV_Redisの監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**または**テナント読み取り専用**のリソース権限。
  * テナントの**<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**メニュー権限。

* **エントリ2**でテナントOBKV_Redisの監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、または**ホスト読み取り専用**のいずれかのリソース権限。
  * パフォーマンス監視の**<UI-TERM key="ocp-v2.Detail.Component.RestartModal.All">すべて</UI-TERM>**メニュー権限。

## バージョン制限

* **OBKV_Redis**監視データの表示は、OceanBase V4.2.5.1以降のバージョンでのみサポートされています。

* <b>応答時間</b>監視指標において、詳細指標項目<code>99-all</code>、<code>95-all</code>、<code>90-all</code>が適用されるOceanBaseのバージョンは[V4.2.5.1, V4.3.0.0)、[V4.3.4.1, +∞)です。

## 注意事項

監視データが空の場合、クラスタの**概要** > **···** > **運用保守設定** > **パラメータ管理** > **パフォーマンス監視パラメータ**に移動し、`monagent.pipeline.obkv.collect.disabled`パラメータの値が`false`かどうか確認してください。`false`はOBKV監視データの収集を許可していることを意味し、`true`はその逆を意味します。

## 手順

以下の手順は**エントリ1**を例としています：

1. OCPにログインします。

2. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.src.constant.plan.Tenant">テナント</UI-TERM>**を選択します。システムはデフォルトで**<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.TenantList">テナント一覧</UI-TERM>**タブに移動します。

3. **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.TenantList">テナント一覧</UI-TERM>**で操作対象のテナントを選択し、テナント名をクリックして、テナントの**<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概要</UI-TERM>**ページに移動します。

4. 左側に表示されるナビゲーションバーで**<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**をクリックします。

5. **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">データフィルタリング</UI-TERM>**エリアで、監視データのフィルタリング条件を設定します。

   フィルタリング条件の説明は以下の表のとおりです：

   |     フィルタ条件  |  説明  |
   |---------------|---------|
   | 更新  | モニタリングデータを更新します。自動更新を有効にできますが、デフォルトでは無効です。自動更新を有効にすると、更新頻度を設定できます。|
   | 時間の選択（モニタリングウィンドウとも呼ばれる） | 自動更新モードでは表示されません。特定の期間を選択すると、その期間内のデータを返します。  |
   | テナント | 特定のテナントを選択して、そのテナントのモニタリングを行います。  |
   | Zone  | デフォルトではすべてのZoneをモニタリングします。|
   | OBServer | デフォルトではすべてのOBServerノードをモニタリングします。|

6. **OBKV_Redis** タブをクリックし、そのタブで関連するモニタリングデータを確認します。

   * OCPは、テナントとUnitの2つの次元でモニタリングデータを表示できます。デフォルトではテナント次元で表示されます。異なる次元では表示可能なモニタリング指標が異なります。
   * システムはデフォルトで現在の次元のすべてのモニタリング項目を表示します。特定のモニタリング項目に注目する必要がない場合は、エリアの右側にある **<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">選択したグラフ</UI-TERM>** パネルで該当するモニタリング項目のチェックを外すことができます。
   * すべてのモニタリング項目は、各サブ指標の最大値（max）、平均値（avg）、現在値（current）の表示をサポートしています。
   * すべてのモニタリング項目の具体的な意味と値の出典については、[モニタリング指標の概要](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md) を参照してください。統計範囲に複数のOBServerノードが含まれる場合は、集約値が表示されます。

   以下の機能は、トレンドグラフで詳細なパフォーマンスモニタリングデータをより良く表示および分析するのに役立ちます。

   <!-- ![Image 114](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1725.png) -->

   * 他のサブ指標データの表示と非表示：カーソルを指標エリアに合わせ、マウスホイールを上下にスクロールすると、トレンドグラフに表示されているすべてのサブ指標データを見ることができます。他のサブ指標のアイコンをクリックして灰色にすると、その指標情報はトレンドグラフに表示されません。

   * トレンドグラフ上の特定の時刻にカーソルを合わせると、その時刻の詳細データを見ることができます。カーソルをドラッグして範囲を選択すると、システムはその範囲のトレンド情報を拡大表示します。そこでその期間における指標の詳細なトレンドを確認できます。このトレンドグラフをダブルクリックすると元に戻ります。

   * トレンドグラフの拡大：トレンドグラフの右上にある拡大アイコンをクリックします。上記の詳細データの表示とサブ指標の表示・非表示の機能は、拡大したトレンドグラフでも同様に適用されます。

   * モニタリング指標の編集：トレンドグラフの右上にある編集アイコンをクリックすると、注目したいサブ指標のみを表示するよう選択できます。

   * 統計レベルの異なるモニタリングデータのドリルダウン表示：**<UI-TERM key="ocp-performance-report.pages.AWR.Tenant">テナント次元</UI-TERM>** タブで、テナントのモニタリングデータに異常が見つかった場合、例えば応答時間が高すぎる場合、ドリルダウン分析を通じて、応答時間の異常を引き起こしたサーバーを特定できます。トレンドグラフの右上にある **<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">ドリルダウン分析</UI-TERM>** アイコンをクリックすると、ドリルダウン分析の詳細を見ることができます。**OBKV_Redis** でサポートされているドリルダウンの次元は、**テナント \> OBServer** です。

       上記の詳細データの表示とサブ指標の表示・非表示の機能は、ドリルダウンページのトレンドグラフでも同様に適用されます。さらに、以下の操作も可能です：

       * ドリルダウンページでフィルタ条件を再設定できます。設定していない場合は、上位レベルの設定が自動的に継承されます。

       * 当該指標にサブ指標が存在する場合、サブ指標を選択して表示することができます。

       * トレンドグラフには **ホストパフォーマンスモニタリングへ** 機能が提供されています。**ホストパフォーマンスモニタリングへ** のリンクにカーソルを合わせ、表示したいホストを選択すると、関連するホストの **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** ページに移動し、ホストのモニタリング詳細を確認できます。

   * SQLリクエスト分析の表示：**<UI-TERM key="ocp-v2.src.constant.monitor.ResponseTime">応答時間（RT）</UI-TERM>** のトレンドグラフで、トレンドグラフの右上にある **<UI-TERM key="ocp-v2.component.MetricChart.Item.SqlRequestAnalysis">SQLリクエスト分析</UI-TERM>** アイコンをクリックすると、リクエスト分析の詳細を見ることができます。詳細については [リクエスト分析の表示](../../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/1300.view-request-analysis.md) を参照してください。
