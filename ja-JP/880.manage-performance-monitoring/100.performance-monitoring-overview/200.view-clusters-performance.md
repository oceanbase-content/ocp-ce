# データベースのパフォーマンスを表示する

OCPでは、さまざまな観点からクラスタ内のパフォーマンス監視データを確認できます。以下の2つの方法で表示できます：

* **方法1**：OCPにログインし、クラスタ概要ページに移動して、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.Instance.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックします。

* **方法2**：OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.hook.useMenu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックします。システムはデフォルトで **<UI-TERM key="ocp-v2.Task.TaskObjectAndType.OceanbaseCluster">OceanBase クラスタ</UI-TERM>** セクションに移動します。

## 前提条件

* **方法1** でクラスタのデータベースパフォーマンス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.src.util.menu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** メニュー権限。

* **方法2** でクラスタのデータベースパフォーマンス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
  * パフォーマンス監視 **<UI-TERM key="ocp-v2.component.common.BinlogClusterSelect.All">すべて</UI-TERM>** メニュー権限。

## バージョン制限

* <b>SQL応答時間</b> 監視指標において：

  * サブ指標項目 <code>99-all</code>、<code>95-all</code> が適用されるOceanBaseバージョンは [V4.2.1.7, V4.2.2.0)です。
  * サブ指標項目 <code>commit</code>、<code>rollback</code> が適用されるOceanBaseバージョンは [V4.2.5.3, V4.3.0.0)、[V4.3.5.2, +∞)です。

* **QPS** 監視指標において、サブ指標項目 <code>commit</code>、<code>rollback</code> が適用されるOceanBaseバージョンは [V4.2.5.3, V4.3.0.0)、[V4.3.5.2, +∞)です。

* <b>トランザクションログ処理時間</b> 監視指標において：

  * サブ指標項目 <code>write_disk</code> が適用されるOceanBaseバージョンは [-∞, V4.1.0.3)です。
  * サブ指標項目 <code>clog_write</code> が適用されるOceanBaseバージョンは [V4.1.0.3, +∞)です。

* <b>物理I/O回数</b>、<b>物理I/O処理時間</b>、<b>物理I/Oスループット</b> 監視指標において、サブ指標項目 <code>clog_read</code>、<code>clog_write</code> が適用されるOceanBaseバージョンは [V4.1.0.3, +∞)です。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>クラスタがAIクラスタ(共有ストレージ形態)の場合、データベースパフォーマンス監視におけるデータディスク関連の指標はキャッシュディスクの指標として表示され、<b>オブジェクトストレージIOPS</b> および <b>オブジェクトストレージ帯域幅</b> の監視指標が追加され、オブジェクトストレージの読み書き性能を監視するために使用されます。</p>
</main>

## 手順

以下の手順は **方法2** を例に説明します。

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.page.Monitor.Monitoring">パフォーマンス監視</UI-TERM>** を選択します。

3. システムはデフォルトで **<UI-TERM key="ocp-v2.Component.ClusterFilter.OceanbaseCluster">OceanBase クラスタ</UI-TERM>** タブに移動します。

4. **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">データフィルタリング</UI-TERM>** エリアで、監視データのフィルタリング条件を設定します。

   フィルタリング条件の説明は以下の表のとおりです：

   |     フィルタリング条件  |  説明  |
   |---------------|---------|
   | 更新  | 監視データを更新します。自動更新を有効にすることができますが、デフォルトでは無効です。自動更新を有効にした場合、更新頻度を設定できます。|
   | 時間の選択（別名：監視ウィンドウ） | 自動更新モードでは表示されません。特定の期間を選択すると、その期間内のデータが返されます。  |
   | クラスタ  | 特定のクラスタを選択して、そのクラスタを監視します。  |
   | Zone  | デフォルトではすべてのZoneを監視します。|
   | OBServer | デフォルトではすべてのOBServerノードを監視します。|

5. システムはデフォルトで **データベースパフォーマンス** タブに移動し、このタブでクラスタのデータベースパフォーマンス監視データを確認します。

   ![1126](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/433/202411181453.png)

   * OCPは、クラスタ、テナント、OBServer、Unitの4つの次元でデータベースパフォーマンス監視データを表示することをサポートしています。デフォルトではクラスタ次元で表示されます。異なる次元では、表示可能な監視指標が異なります。
   * システムはデフォルトで現在の次元のすべての監視項目を表示します。特定の監視項目に注目する必要がない場合は、エリアの右側にある **<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">選択したグラフ</UI-TERM>** パネルで、その監視項目のチェックを外すことができます。
   * すべての監視項目は、各サブ指標の最大値（max）、平均値（avg）、現在値（current）を表示することをサポートしています。
   * すべての監視項目の具体的な意味と値の出典については、[監視指標の概要](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md)を参照して理解することができます。

   以下の機能は、トレンドグラフでのパフォーマンス監視データの視覧と分析をより良く支援します。画像と以下の説明を組み合わせて理解してください。

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1127.png)

   1. 他のサブ指標データの表示と非表示：指標エリアにカーソルを合わせ、マウスホイールを上下にスワイプすると、トレンドグラフに表示されているすべてのサブ指標データを見ることができます。他のサブ指標のアイコンをクリックしてグレーアウトさせると、その指標情報はトレンドグラフに表示されなくなります。

   2. トレンドグラフ上の任意の時刻にカーソルを合わせると、その時刻の詳細データを見ることができます。カーソルをドラッグして範囲を選択すると、システムはその範囲のトレンド情報を拡大表示し、その期間における指標の詳細なトレンドを見ることができます。このトレンドグラフをダブルクリックすると元に戻ります。

   3. 特定のトレンドグラフの拡大：トレンドグラフの右上隅にある拡大アイコンをクリックします。上記の図の①、②の機能は、拡大されたトレンドグラフでも同様に適用されます。

   4. 監視指標の編集：トレンドグラフの右上隅にある編集アイコンをクリックすると、注目するサブ指標のみを表示するよう選択できます。

   5. 統計レベルの下げによる異なる次元の監視データの表示：**<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.ClusterDimension">クラスタの次元</UI-TERM>** タブで、クラスタの監視データに異常が見つかった場合、例えばSQL応答時間が高すぎる場合、統計レベルを下げて分析することで、応答時間の異常を引き起こしたサーバーを特定できます。トレンドグラフの右上隅にある **<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">ドリルダウン分析</UI-TERM>** アイコンをクリックします。統計レベルを下げることができる次元は、**クラスタ \> テナント \> OBServer** です。

      上記の図の①、②の機能は、統計レベルを下げたページのトレンドグラフでも同様に適用されます。さらに、以下の操作もできます：

      1. 統計レベルを下げたページでフィルタリング条件を再設定します。設定していない場合は、上位レベルの設定が自動的に継承されます。

      2. 当該指標にサブ指標が存在する場合、サブ指標を選択して表示することができます。または、図に示すように①または②をクリックして異なる次元に統計レベルを下げ、さらに分析することもできます。

      3. 当該指標がテナントまたはホストのパフォーマンスに関連している場合、トレンドグラフには関連するテナントまたはホストの **<UI-TERM key="ocp-v2.Host.Detail.Surveillance">監視</UI-TERM>** ページへの直接ジャンプボタンが提供されます。

         * テナント **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** ページへのジャンプ：トレンドグラフの右上隅にある **<UI-TERM key="ocp-v2.Detail.Component.DirectToTenantList.GoToTenantPerformanceMonitoring">テナントのパフォーマンス監視に移動</UI-TERM>** リンクにマウスカーソルを合わせ、対応するテナントを選択してクリックするだけです。

         * ホスト **<UI-TERM key="ocp-v2.Detail.Realtime.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** ページへのジャンプ：トレンドグラフの右上隅にある **ホストパフォーマンス監視へ** リンクにマウスカーソルを合わせ、対応するホストを選択してクリックするだけです。

6. （オプション）モニタリングデータの収集間隔を設定します。

   現在のOCPでは、1秒単位のモニタリングデータはデフォルトで1秒ごとに収集されます。この収集頻度は、OCP ServerのパフォーマンスおよびMonitorDBのストレージ性能に高い要件を課します。モニタリングデータに対する要件がそれほど高くない場合、config_properties内のocp(metric.collect.interval.secondの値を変更することでモニタリングデータの収集間隔を設定し、リソース使用量を削減して全体の管理規模を拡大できます。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>現在、設定可能な値は1、5、10、15のみです。上記以外の数値を入力した場合、システムは自動的に適応します：</p>
    <ul>
    <li>1未満の場合はすべて1に統一されます。</li>
    <li>[1,5)区間は下位互換性により1になります。</li>
    <li>[5,10)区間は下位互換性により5になります。</li>
    <li>[10,15)区間は下位互換性により10になります。</li>
    <li>その他はすべて15に統一されます。</li>
    </ul>
    </main>

   設定変更後、OCPは即座に新しい収集間隔でデータを収集を開始します。モニタリングデータの表示間隔は、収集間隔の3倍になります（収集間隔が1秒の場合は除く）。例えば、収集間隔が5秒の場合、1秒単位でクエリされたモニタリングデータの表示間隔は15秒になります。
