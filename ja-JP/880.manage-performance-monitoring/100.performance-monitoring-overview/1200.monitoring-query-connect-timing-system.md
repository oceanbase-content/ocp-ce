# モニタリングクエリの外部時系列システムへの連携

OCP V4.3.0から、モニタリングクエリはユーザーが既に利用している時系列システム（PrometheusやSLS MetricStoreなど）と連携できるようになりました。これにより、ocp-serverが監視データの収集・計算を担当する負荷が軽減され、クエリインターフェースのスループットが向上します。ターゲットアドレスや認証情報などを簡単に設定するだけで、すぐに利用できます。

## 前提条件

* Agentのモニタリング時系列データをAgent Remote pushやPushgatewayなどの方式で収集済みであること。詳細については、[モニタリングクエリの外部時系列システムへの連携](../../2000.faq/400.common-monitoring-problems/400.ocp-agent-data-push-scheme.md)を参照してください。

* OCPコンテナから対応する時系列システムへのネットワークが確立されていること。

## Prometheusとの連携

OCPでPrometheusデータソースを設定し有効化する方法については、[OCPモニタリングのPrometheusへの統合](../../1850.ocp-om-best-practices/1550.prometheus-http-sd.md)を参照してください。設定完了後、OCPはPrometheusのモニタリングデータにリアルタイムでアクセスできるようになります。

Prometheus関連の設定はすべて`meta`テナントの`config_properties`テーブルにあります。関連する設定の説明は以下の通りです：

| key  |  組み込み  |  必須  |  リブート後に反映  |  説明  |
|------|------------|------------|---------------|--------|
|  `ocp.monitor(metric.service.type`  |  はい    |  はい    |  はい    |  モニタリングクエリのデータソースタイプ。デフォルトは`LOCAL`で、MonitorDBを表します。ここではPROMETHEUSに設定する必要があります（大文字小文字は問いません）。  |
|  `ocp.monitor(metric.collect.service.type`  |  はい    |  はい    |  はい    |  モニタリングの収集タイプ。デフォルトは`LOCAL`で、グレースケール用にMonitorDBに別途データを書き込むことを意味します。MonitorDBにデータを書き込みたくない場合、ここではPROMETHEUSに設定する必要があります（大文字小文字は問いません）。  |
|  `ocp.monitor.query.prometheus.address`  |  いいえ    |  はい    |  はい    |  Prometheusサービスのデプロイメントアドレス。例：`127.0.0.1`。 |
|  `ocp.monitor.query.prometheus.port`  |  いいえ    |  はい    |  はい    |  Prometheusサービスのポート番号。例：`9090`。  |
|  `ocp.monitor.query.prometheus.authentication.username`  |  いいえ    |  いいえ    |  はい    |  Prometheus query APIに対するHttpリクエストの認証ユーザー名。設定しなくても構いません。  |
|  `ocp.monitor.query.prometheus.authentication.password`  |  いいえ    |  いいえ    |  はい    |  Prometheus query APIに対するHttpリクエストの認証パスワード。設定しなくても構いません。  |
|  `ocp.monitor.query.prometheus.connect.timeout`  |  いいえ    |  いいえ    |  はい    |  Prometheus query APIに対するHttpリクエストでソケット接続を確立する際のタイムアウト時間。単位はms。デフォルト値は3000msです。  |
|  `ocp.monitor.query.prometheus.read.timeout`  |  いいえ    |  いいえ    |  はい    |  Prometheus query APIに対するHttpリクエストで応答を待機する際のタイムアウト時間。単位はms。デフォルト値は3000msです。  |

## SLSとの連携

SLS関連の設定はPrometheusと類似しています。説明は以下の通りです：

|  key  |  組み込み  |  必須  |  リブート後に反映  |  説明  |
|-------|------------|-----------|---------------|----------|
|  `ocp.monitor.metric.service.type`  |  はい    |  はい    |  はい    |  モニタリングクエリのデータソースタイプ。デフォルトは`LOCAL`で、MonitorDBを表します。ここではSLSに設定する必要があります（大文字小文字は問いません）。  |
|  `ocp.monitor.metric.collect.service.type`  |  はい    |  はい    |  はい    |  モニタリングの収集タイプ。デフォルトは`LOCAL`で、グレースケール用にMonitorDBに別途データを書き込むことを意味します。MonitorDBにデータを書き込みたくない場合、ここではSLSに設定する必要があります（大文字小文字は問いません）。  |
|  `ocp.monitor.query.sls.end-point`  |  いいえ    |  はい    |  はい    |  SLSサービスのアクセスポイント。  |
|  `ocp.monitor.query.sls.sls-project` |  いいえ    |  はい    |  はい    |  SLSプロジェクトのスペース。  |
|  `ocp.monitor.query.sls.sls-metricstore`  |  いいえ    |  はい    |  はい    |  SLSのMetricStore。  |
|  `ocp.monitor.query.sls.access-key`  |  いいえ    |  はい    |  はい    |  SLSのAccessKey ID。  |
|  `ocp.monitor.query.sls.access-secret`  |  いいえ    |  はい    |  はい    |  SLSのAccessKey Secret。  |
|  `ocp.monitor.query.sls.connect.timeout`  |  いいえ    |  いいえ    |  はい    |  SLS query APIに対するHttpリクエストでソケット接続を確立する際のタイムアウト時間。単位はms。デフォルト値は3000msです。  |
|  `ocp.monitor.query.sls.read.timeout`  |  いいえ    |  いいえ    |  はい    |  SLS query APIに対するHttpリクエストで応答を待機する際のタイムアウト時間。単位はms。デフォルト値は3000msです。  |

非組み込みメトリクスはデフォルトで`config_properties`テーブルに設定されていないため、システムパラメータではこれらのメトリクスを確認したり設定したりすることはできません。その場合、初回使用時に以下のSQLを使用して、コマンドラインでレコードを挿入する必要があります。

`ocp.monitor.query.sls.sls-metricstore`を例にします：

```sql
INSERT INTO `config_properties` (`key`, `value`, `need_restart`, `description`) VALUES ('ocp.monitor.query.sls.sls-metricstore', 'ob_metricstore', 1, 'SLS metricStore');
```

すべての設定を更新した後、OCPを再起動すると、OCPのWeb画面に表示される監視データやアラートなどで使用されているデータソースが、対応するSLSサービスに置き換えられていることが確認できます。
