# OBServerのパフォーマンスの表示

OCPでは、さまざまな観点からOBServerの各種パフォーマンス監視データを確認できます。以下の2つの方法で表示できます：

* **方法1**：OCPにログインし、クラスタ概要ページに移動して、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.src.hook.useMenu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックします。

* **方法2**：OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックします。システムはデフォルトで **<UI-TERM key="ocp-v2.Information.Detail.CreateCollectDrawer.OceanbaseCluster">OceanBase クラスタ</UI-TERM>** タブに移動します。

## 前提条件

* **方法1** でOBServerのパフォーマンス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** メニュー権限。

* **方法2** でOBServerのパフォーマンス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
  * パフォーマンス監視 **<UI-TERM key="ocp-v2.Auth.Role.Detail.All">すべて</UI-TERM>** メニュー権限。

## 手順

以下の手順は **方法2** を例に説明します。

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.util.menu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** を選択します。

3. システムはデフォルトで **<UI-TERM key="ocp-v2.src.constant.auth.OceanbaseCluster">OceanBase クラスタ</UI-TERM>** タブに移動します。

4. **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">データフィルタリング</UI-TERM>** エリアで、監視データのフィルタリング条件を設定します。

   フィルタリング条件の説明は以下の表のとおりです：

   |     フィルタリング条件  |  説明  |
   |---------------|---------|
   | 更新  | 監視データを更新します。自動更新を有効にすることができますが、デフォルトでは無効です。自動更新を有効にした場合、更新頻度を設定できます。|
   | 選択時間（別名：監視ウィンドウ） | 自動更新モードでは表示されません。特定の期間範囲を選択し、その期間内のデータを返します。  |
   | クラスタ  | 特定のクラスタを選択し、そのクラスタを監視します。  |
   | Zone  | デフォルトではすべてのZoneを監視します。|
   | OBServer | デフォルトではすべてのOBServerノードを監視します。|

5. **OBServerパフォーマンス** タブをクリックし、OBServerのパフォーマンス監視データを確認します。統計範囲に複数のOBServerノードが含まれる場合、複数のOBServerノードの集計値が表示されます。

   * OCPは、クラスタとOBServerの2つの観点からOBServerのパフォーマンス監視データを表示することをサポートしています。デフォルトではクラスタ単位で表示されます。異なる観点で表示できる監視指標は異なります。
   * システムはデフォルトで現在の観点におけるすべての監視項目を表示します。特定の監視項目に注目する必要がない場合、エリアの右側にある **<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">選択したグラフ</UI-TERM>** パネルで、その監視項目のチェックを外すことができます。
   * すべての監視項目では、各細分化指標の最大値（max）、平均値（avg）、現在値（current）の表示をサポートしています。
   * すべてのモニタリング項目の具体的な意味と値の出典については、[モニタリング指標の概要](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md)を参照してください。

   以下の機能を利用すると、トレンドグラフ上でのパフォーマンス監視データの表示と分析がより容易になります。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1712.png) -->

   1. 他の詳細指標データの表示と非表示：指標エリアにカーソルを合わせ、マウスホイールを上下にスクロールすると、トレンドグラフに表示されているすべての詳細指標データを確認できます。他の詳細指標のアイコンをクリックしてグレーアウトすると、その指標情報はトレンドグラフに表示されなくなります。

   2. トレンドグラフ上の特定の時点にカーソルを合わせると、その時点の詳細データを確認できます。カーソルをドラッグして範囲を選択すると、システムはその範囲のトレンド情報を拡大表示し、その期間における指標の詳細なトレンドを確認できます。このトレンドグラフをダブルクリックすると元に戻ります。

   3. 特定のトレンドグラフの拡大：トレンドグラフの右上隅にある拡大アイコンをクリックします。上記の詳細データの表示とサブ指標の表示・非表示の機能は、拡大したトレンドグラフでも同様に適用されます。

   4. モニタリング指標の編集：トレンドグラフの右上隅にある編集アイコンをクリックすると、注目すべき詳細指標のみを表示するよう選択できます。

   5. ドリルダウンして異なる次元の監視データを確認する：**<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.ClusterDimension">クラスタの次元</UI-TERM>**タブで、クラスタの監視データに異常が見られた場合（例えば、プロセスのCPU使用率が高すぎる場合）、ドリルダウン分析を通じて、応答時間の異常を引き起こしたサーバーを特定できます。トレンドグラフの右上隅にある**<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">ドリルダウン分析</UI-TERM>**アイコンをクリックします。**OBServer パフォーマンス**でサポートされているドリルダウン次元は、**クラスタ \> ホスト**です。

      上記の詳細データの表示とサブ指標の表示・非表示の機能は、ドリルダウンページのトレンドグラフでも同様に適用されます。さらに、以下の操作も可能です：

      1. ドリルダウンページでフィルタ条件を再設定します。設定していない場合は、上位レベルの設定が自動的に継承されます。

      2. 当該指標に詳細指標が存在する場合、詳細指標を選択して確認できます。

      3. 当該指標がホストのパフォーマンスに関連している場合、**ホストパフォーマンス監視へ**リンクにカーソルを合わせ、対応するホストを選択してクリックすると、ホストの**<UI-TERM key="ocp-v2.src.hook.useMenu.Monitoring">監視</UI-TERM>**ページにジャンプできます。

6. （オプション）監視収集間隔を設定します。

   現在のOCPでは、1秒単位の監視データ収集はデフォルトで1秒ごとに行われます。この収集頻度は、OCP ServerのパフォーマンスおよびMonitorDBのストレージ性能に高い要件を課します。監視データに対する要件がそれほど高くない場合、config_properties内のocp.metric.collect.interval.secondのvalueを変更することで監視データ収集間隔を設定し、リソース使用量を削減して全体の管理規模を拡大できます。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>現在、設定可能なvalueは1、5、10、15のみです。上記に記載されていない他の数値を入力した場合、システムは自動的に適応します：</p>
    <ul>
    <li>1未満の場合は一律に1に設定されます。</li>
    <li>[1,5)区間は切り捨てにより1に設定されます。</li>
    <li>[5,10)区間は切り捨てにより5に設定されます。</li>
    <li>[10,15)区間は切り捨てにより10に設定されます。</li>
    <li>その他の場合は一律に15に設定されます。</li>
    </ul>
    </main>

   設定変更後、OCPは即座に新しい収集間隔でデータを収集し始めます。監視データの表示間隔は、収集間隔の3倍に設定されます（収集間隔が1秒の場合は除く）。例えば、収集間隔が5秒の場合、1秒単位でクエリされた監視データの表示間隔は15秒となります。
