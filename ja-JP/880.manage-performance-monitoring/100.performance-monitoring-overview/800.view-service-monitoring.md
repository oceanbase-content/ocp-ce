# サービス監視の表示

OCPはOBProxyクラスタのサービス監視機能を提供します。関連する監視データは、以下の2つの方法で確認できます：

* **方法1**：OCPにログインし、OBProxyの概要ページに移動して、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックします。

* **方法2**：OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックして、**<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterWithExclude.ObproxyCluster">OBProxyクラスタ</UI-TERM>** タブに移動します。

## 前提条件

* **方法1** でOBProxyクラスタのサービス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **OBProxy読み取り専用** リソース権限。
  * OBProxy **<UI-TERM key="ocp-v2.src.util.menu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** メニュー権限。

* **方法2** でOBProxyクラスタのサービス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **OBProxy読み取り専用** リソース権限。
  * パフォーマンス監視 **<UI-TERM key="ocp-v2.page.Task.All">すべて</UI-TERM>** メニュー権限。

## バージョン制限

<b>RPCセッション数</b>、<b>RPCリクエスト数</b>、<b>RPCリクエスト時間</b> の監視指標が適用されるOBProxyのバージョンは [V4.0.0.0, +∞) です。

## 手順

以下の手順は **方法2** を例に説明します。

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** を選択します。

3. **<UI-TERM key="ocp-v2.src.component.ModifyTagResourceDrawer.ObproxyCluster">OBProxyクラスタ</UI-TERM>** タブをクリックします。

4. **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">データフィルタリング</UI-TERM>** エリアで、監視データのフィルタリング条件を設定します。

   フィルタリング条件の説明は以下の表のとおりです：

   |     フィルタリング条件  |  説明  |
   |---------------|---------|
   | 更新  | 監視データを更新します。自動更新を有効にできますが、デフォルトでは無効です。自動更新を有効にした場合、更新頻度を設定できます。|
   | 時間範囲（別名：監視ウィンドウ） | 自動更新モードでは表示されません。特定の期間を選択すると、その期間内のデータを返します。  |
   | クラスタ | 特定のOBProxyクラスタを選択して、そのクラスタを監視します。  |

5. **<UI-TERM key="ocp-v2.Detail.Monitor.ServiceMonitoring">サービス監視</UI-TERM>** タブに移動して、関連する監視データを確認します。

   1. **接続されたOceanBaseクラスタデータ** エリアで、現在のOBProxyクラスタとそれがプロキシしているOceanBaseクラスタ間の相互接続性能状況を確認します。

      * データはデフォルトで最大値（max）が表示されますが、平均値（avg）または最小値（min）に切り替えることができます。
      * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.ColumnManager.ColumnManagement">カラム管理</UI-TERM>** をクリックすると、表示する監視指標情報を選択できます。
      * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.ViewAll">すべてを見る</UI-TERM>** をクリックすると、接続されたOceanBaseクラスタのすべてのリクエスト解析データを確認できます。

   2. **OBProxy IPデータ** エリアでは、現在のOBProxyクラスタ内の各OBProxyノードのパフォーマンス状況を確認できます。

      * データはデフォルトで最大値（max）が表示されますが、平均値（avg）または最小値（min）に切り替えることができます。
      * **<UI-TERM key="ocp-v2.Component.filter.ColumnManagement">カラム管理</UI-TERM>** をクリックすると、表示する監視指標情報を選択できます。
      * **<UI-TERM key="ocp-v2.SQLDiagnosis.Component.SQLDetail.ViewAll">すべてを見る</UI-TERM>** をクリックすると、OBProxy IPのサービスリクエスト解析データを確認できます。

   3. **<UI-TERM key="ocp-v2.Detail.Monitor.Monitor.Overview">総覧</UI-TERM>** エリアでは、現在のOBProxyクラスタの監視トレンドグラフを確認できます。これには、**TPS**、**QPS**、**クライアント接続**、**サーバー接続**、**SQL応答時間**、**OBProxyメモリ**、**OBProxy CPU使用率**、**OBProxyファイルハンドル数**、**OBProxyスレッド数**、**エラーログ**、**ルーティングテーブル**、**バイト数**、**RPCセッション数**、**RPCリクエスト数**、および **RPCリクエスト処理時間** が含まれます。

        * すべての監視項目について、各サブ指標の最大値（max）、平均値（avg）、および現在値（current）を表示できます。
        * すべての監視項目の具体的な意味と値の出典については、[監視指標の概要](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md)を参照してください。

        以下の機能を利用すると、トレンドグラフ上で詳細なパフォーマンス監視データをより効果的に確認および分析できます。画像と以下の説明を組み合わせてご確認ください。

        ![Image 114](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/442/04161448.png)

        1. 特定の指標の特定の期間の詳細なトレンドを確認する：マウスでその範囲をドラッグして選択すると、システムはその範囲のトレンド情報を拡大表示します。このトレンドグラフをダブルクリックすると元に戻ります（上図の①参照）。

        2. 他のサブ指標のデータを非表示にする：他のサブ指標のアイコンをクリックして灰色にすると、その指標情報はトレンドグラフに表示されなくなります（上図の②参照）。

        3. 特定の時点の詳細データを確認する：マウスカーソルをトレンドグラフ上の特定の時点に合わせます（上図の③参照）。

        4. トレンドグラフの右上隅にある拡大アイコンをクリックすると、トレンドグラフを拡大できます（上図の④参照）。上記の①、②、③の機能は、他の監視トレンドグラフにも同様に適用されます。

        5. 監視指標を編集する：トレンドグラフの右上隅にある編集アイコンをクリックすると、注目すべきサブ指標のみを表示するよう選択できます（上図の⑤参照）。

        6. ドリルダウンして異なる次元の監視データを確認する：監視データに異常が見られた場合、例えばTPSが高すぎる場合、ドリルダウン分析を通じて、応答時間の異常を引き起こしたOBProxy IPを特定できます。トレンドグラフの右上隅にある **<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">ドリルダウン分析</UI-TERM>** アイコンをクリックすると、ドリルダウン分析の詳細を確認できます（上図の⑥参照）。

           上図の①、②、③の機能は、ドリルダウンページのトレンドグラフにも同様に適用されます。さらに、以下の操作も可能です：

           * ドリルダウンページでフィルター条件を再設定します。設定していない場合は、上位レベルの設定が自動的に継承されます。

           * 当該指標にサブ指標が存在する場合、サブ指標を選択して確認できます。
