# OBKV_Tableの表示

このページでは、テナントのOBKV_Tableタイプの監視データを表示する方法について説明します。OBKV-Tableは、OceanBaseの基盤エンジンをベースとしたマルチモデルNoSQLデータベースサービスであり、テーブル、キー・バリュー、ワイドカラムの3種類のデータモデルを提供し、大量の構造化および半構造化データの低コストストレージをサポートしています。メタデータ、注文、請求書、プロファイル、ソーシャル、フィードストリーム、ログ、リスク管理などのビジネスシナリオに適しています。OBKV-TableとSQLは、同じ階層にある2つの計算層として機能し、同じOceanBase分散ストレージにアクセスします。このRDBMSとNoSQLが統合されたアーキテクチャでは、OBKV-Tableを使用して簡単かつ迅速なDMLを実行しながら、同じデータに対してSQLを使用して複雑なクエリを並行して実行できます。

以下の2つの方法でOBKV_Tableの監視データを表示できます：

* **方法1**：OCPにログインし、テナントの概要ページに移動して、左側のナビゲーションバーの**<UI-TERM key="ocp-v2.Instance.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**をクリックします。

* **方法2**：OCPにログインし、左側のナビゲーションバーで**<UI-TERM key="ocp-v2.page.Monitor.Monitoring">パフォーマンス監視</UI-TERM>**をクリックして、**<UI-TERM key="ocp-v2.component.AddChartDrawer.ChartConfigPanel.OceanbaseTenants">OceanBaseテナント</UI-TERM>**タブに移動します。

## 前提条件

* **方法1**でテナントのOBKV_Table監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**または**テナント読み取り専用**のリソース権限。
  * テナントの**<UI-TERM key="ocp-v2.page.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**メニュー権限。

* **方法2**でテナントのOBKV_Table監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、または**ホスト読み取り専用**のいずれかのリソース権限。
  * パフォーマンス監視の**<UI-TERM key="ocp-v2.Auth.Role.All">すべて</UI-TERM>**メニュー権限。

## バージョン制限

* **OBKV_Table**監視データの表示は、OceanBase V3.2.4.4以降のバージョンでのみサポートされています。
* <b>応答時間</b>監視指標において、詳細指標項目<code>99-all</code>、<code>95-all</code>、<code>90-all</code>が適用されるOceanBaseのバージョンは[V4.2.1.7, V4.2.2.0)、[V4.2.5.0, V4.3.0.0)、[V4.3.4.1, +∞)です。

## 注意事項

監視データが空の場合、クラスタの**概要** > **···** > **運用保守設定** > **パラメータ管理** > **パフォーマンス監視パラメータ**に移動し、`monagent.pipeline.obkv.collect.disabled`パラメータの値が`false`かどうかを確認してください。`false`はOBKV監視データの収集を許可することを意味し、`true`はその逆を意味します。

## 手順

1. OCPにログインします。

2. 左側のナビゲーションバーで**<UI-TERM key="ocp-v2.page.Overview.Tenant">テナント</UI-TERM>**を選択すると、システムはデフォルトで**<UI-TERM key="ocp-v2.page.Tenant.TenantList">テナント一覧</UI-TERM>**タブに移動します。

3. **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.TenantList">テナント一覧</UI-TERM>**で操作対象のテナントを選択し、テナント名をクリックして、テナントの**<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">概要</UI-TERM>**ページに移動します。

4. 左側に表示されるナビゲーションバーで**<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**をクリックします。

5. **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">データフィルタリング</UI-TERM>**エリアで、監視データのフィルタリング条件を設定します。

   フィルタリング条件の説明は以下の表のとおりです：

   |     フィルタリング条件  |  説明  |
   |---------------|---------|
   | 更新  | モニタリングデータを更新します。自動更新を有効にできますが、デフォルトでは無効です。自動更新を有効にすると、更新頻度を設定できます。|
   | 時間の選択（モニタリングウィンドウとも呼ばれる） | 自動更新モードでは表示されません。特定の期間を選択し、その期間内のデータを取得します。  |
   | テナント | 特定のテナントを選択し、そのテナントのモニタリングを行います。  |
   | Zone  | デフォルトではすべてのZoneをモニタリングします。|
   | OBServer | デフォルトではすべてのOBServerノードをモニタリングします。|

6. **OBKV_Table** タブをクリックし、そのタブで関連するモニタリングデータを確認します。

   * OCPは、テナントとUnitの2つの次元でモニタリングデータを表示できます。デフォルトではテナント次元で表示されます。異なる次元では表示可能なモニタリング指標が異なります。
   * システムはデフォルトで現在の次元におけるすべてのモニタリング項目を表示します。特定のモニタリング項目に注目する必要がない場合は、領域の右側にある **<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">選択したグラフ</UI-TERM>** パネルで該当するモニタリング項目のチェックを外すことができます。
   * すべてのモニタリング項目では、各サブ指標の最大値（max）、平均値（avg）、現在値（current）を表示できます。
   * すべてのモニタリング項目の具体的な意味と値の出典については、[モニタリング指標の概要](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md) を参照してください。統計範囲に複数のOBServerノードが含まれる場合は、集約値が表示されます。

   以下の機能は、トレンドグラフ上で詳細なパフォーマンスモニタリングデータをより良く確認し、分析するのに役立ちます。

   <!-- ![Image 114](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1725.png) -->

   * 他のサブ指標のデータの表示と非表示：カーソルを指標エリアに合わせ、マウスホイールを上下にスクロールすると、トレンドグラフに表示されているすべてのサブ指標データを確認できます。他のサブ指標のアイコンをクリックしてグレーアウトさせると、その指標情報はトレンドグラフに表示されなくなります。

   * カーソルをトレンドグラフ上の特定の時刻に合わせると、その時刻の詳細データを確認できます。カーソルをドラッグして特定の領域を選択すると、システムはその領域のトレンド情報を拡大表示します。そこで、その期間におけるその指標の詳細なトレンドを確認できます。このトレンドグラフをダブルクリックすると元に戻ります。

   * トレンドグラフの拡大：トレンドグラフの右上にある拡大アイコンをクリックします。上記の詳細データの表示とサブ指標の表示・非表示の機能は、拡大されたトレンドグラフでも同様に適用されます。

   * モニタリング指標の編集：トレンドグラフの右上にある編集アイコンをクリックすると、注目したいサブ指標のみを表示するよう選択できます。

   * 統計レベルの異なるモニタリングデータのドリルダウン表示：**<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.Tenant">テナント次元</UI-TERM>** タブで、テナントのモニタリングデータに異常が見られた場合、例えば応答時間が高すぎる場合、ドリルダウン分析を通じて、応答時間の異常を引き起こしているサーバーを特定できます。トレンドグラフの右上にある **<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">ドリルダウン分析</UI-TERM>** アイコンをクリックすると、ドリルダウン分析の詳細を確認できます。**OBKV_Table** でサポートされているドリルダウンの次元は、**テナント \> OBServer** です。

       上記の詳細データの表示とサブ指標の表示・非表示の機能は、ドリルダウンページのトレンドグラフでも同様に適用されます。さらに、以下の操作も可能です：

       * ドリルダウンページでフィルター条件を再設定します。設定していない場合は、上位レベルの設定が自動的に継承されます。

       * 当該指標にサブ指標が存在する場合、サブ指標を選択して確認できます。

       * トレンドグラフには **ホストパフォーマンスモニタリングへ** 機能が提供されています。**ホストパフォーマンスモニタリングへ** のリンクにカーソルを合わせ、確認したいホストを選択すると、関連するホストの **<UI-TERM key="ocp-v2.Detail.Realtime.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** ページに移動し、ホストのモニタリング詳細を確認できます。

   * SQLリクエスト分析の表示：**<UI-TERM key="ocp-v2.src.constant.monitor.ResponseTime">応答時間（RT）</UI-TERM>** のトレンドグラフで、トレンドグラフの右上にある **<UI-TERM key="ocp-v2.component.MetricChart.Item.SqlRequestAnalysis">SQLリクエスト分析</UI-TERM>** アイコンをクリックすると、リクエスト分析の詳細を確認できます。詳細については [リクエスト分析の表示](../../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/1300.view-request-analysis.md) を参照してください。
