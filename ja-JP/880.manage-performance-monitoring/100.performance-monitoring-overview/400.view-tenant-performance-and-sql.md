# パフォーマンスとSQLの表示

このページでは、OCPにおけるテナントのパフォーマンスとSQLの監視機能について説明します。以下の2つの方法で確認できます：

* **方法1**：OCPにログインし、テナント概要ページに移動して、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.src.util.menu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックします。

* **方法2**：OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.src.hook.useMenu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックして、**<UI-TERM key="ocp-v2.src.component.ModifyTagResourceDrawer.OceanbaseTenants">OceanBaseテナント</UI-TERM>** セクションに移動します。

## 前提条件

* **エントリ1** からテナントのパフォーマンスおよびSQLパフォーマンス監視データを表示する場合は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用** または **テナント読み取り専用** リソース権限。
  * テナント **<UI-TERM key="ocp-v2.page.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** メニュー権限。

* **エントリ2** からテナントのパフォーマンスおよびSQLパフォーマンス監視データを表示する場合は、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
  * パフォーマンス監視 **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterAndHostWithExclude.All">すべて</UI-TERM>** メニュー権限。

* <b>応答時間</b> 監視チャートを表示するには、事前に <b>テナント</b> > <b>パラメータ管理</b> で以下のパラメータを設定しておく必要があります：

  * <code>query_response_time_stats=true</code>（統計スイッチをオンにする）

  * <code>query_response_time_range_base=2</code>（統計間隔を設定する）

  * <code>query_response_time_flush=true</code>（統計間隔の変更を有効にするためにフラッシュする）

## バージョン制限

* <b>SQL実行時間</b> 監視指標が適用されるOceanBaseバージョンは [V3.2.4.1, V4.0.0.0)、[V4.1.0.0, +∞)です。

* <b>SQL実行段階</b> 監視指標が適用されるOceanBaseバージョンは [V4.2.0.0, V4.3.0.0)です。ここで：

  * サブ指標項目 <code>in_committing</code>、<code>in_storage_read</code>、<code>in_storage_write</code>、<code>in_remote_das_execution</code> が適用されるOceanBaseバージョンは [V4.2.1.0, V4.3.0.0)です。
  * サブ指標項目 <code>in_plsql_compilation</code>、<code>in_plsql_execution</code> が適用されるOceanBaseバージョンは [V4.2.2.0, V4.3.0.0)です。

* <b>clog同期遅延</b> 監視指標が適用されるOceanBaseバージョンは [V2.2.76, V4.0.0.0)です。

* <b>フロントワークロード</b>、<b>バックグラウンドワークロード</b> 監視指標が適用されるOceanBaseバージョンは [V4.2.0.0, V4.3.0.0)です。

* <b>DB Time</b> 監視指標が適用されるOceanBaseバージョンは [V4.2.2.0, V4.3.0.0)です。

* <b>並列実行ワーカースレッド利用率</b> 監視指標はOceanBaseバージョン [V4.0.0.0, +∞)に適用されます。

* <b>応答時間</b> 監視指標では：

  * サブ指標項目 <code>99-all</code>、<code>95-all</code> が適用されるOceanBaseバージョンは [V4.2.1.7, V4.2.2.0)、[V4.2.5.0, V4.3.0.0)、[V4.3.3.0, +∞)です。
  * サブ指標項目 <code>commit</code>、<code>rollback</code> が適用されるOceanBaseバージョンは [V4.2.5.3, V4.3.0.0)、[V4.3.5.2, +∞)です。

* **QPS** 監視指標では、サブ指標項目 <code>commit</code>、<code>rollback</code> が適用されるOceanBaseバージョンは [V4.2.5.3, V4.3.0.0)、[V4.3.5.2, +∞)です。
* <b>RPCリクエスト成功率</b>、<b>GTSリクエスト数</b>、<b>RPCネットワーク遅延</b>、<b>RPC配信失敗</b> 監視指標が適用されるOceanBaseバージョンは [V2.2.70, +∞)です。

<main id="notice" type='explain'>
<h4>説明</h4>
<p>テナントが属するクラスタがAIクラスタ(共有ストレージ形態)の場合、パフォーマンスおよびSQL監視におけるデータディスク関連の指標はキャッシュディスクの指標として表示され、オブジェクトストレージの読み書き性能を監視するために <b>オブジェクトストレージIOPS</b> および <b>オブジェクトストレージ帯域幅</b> 監視指標が追加されます。</p>

## 手順

以下の手順では、**エントリ2**を例に説明します。

1. OCPにログインします。

2. 左側のナビゲーションバーで、**<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**を選択します。

3. **<UI-TERM key="ocp-v2.Information.Detail.CreateCollectDrawer.OceanbaseTenants">OceanBase テナント</UI-TERM>**タブを選択します。

4. **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">データフィルタリング</UI-TERM>**エリアで、監視データのフィルタリング条件を設定します。

   フィルタリング条件の説明は以下の表のとおりです：

   |     フィルタリング条件  |  説明  |
   |---------------|---------|
   | 更新  | 監視データを更新します。自動更新を有効にすることができますが、デフォルトでは無効です。自動更新を有効にすると、更新頻度を設定できます。|
   | 選択時間（別名：監視ウィンドウ） | 自動更新モードでは表示されません。特定の期間を選択して、その期間内のデータを返します。  |
   | テナント | 特定のテナントを選択して、そのテナントを監視します。  |
   | Zone  | デフォルトではすべてのZoneを監視します。|
   | OBServer | デフォルトではすべてのOBServerノードを監視します。|

5. システムはデフォルトで**パフォーマンスとSQL**タブに移動し、このタブでテナントのパフォーマンスとSQLの監視データを確認します。

   * OCPは、テナントとUnitの2つの次元で監視データを表示することをサポートしています。デフォルトではテナント次元で表示されます。異なる次元では、表示可能な監視指標が異なります。
   * システムはデフォルトで現在の次元のすべての監視項目を表示します。特定の監視項目に注目する必要がない場合は、エリアの右側にある**<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">選択したグラフ</UI-TERM>**パネルで、その監視項目のチェックを外すことができます。
   * すべての監視項目は、各サブ指標の最大値（max）、平均値（avg）、現在値（current）の表示をサポートしています。
   * すべての監視項目の具体的な意味と値の出典については、[監視指標の概要](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md)を参照してください。統計範囲に複数のOBServerノードが含まれる場合は、集約値が表示されます。

   以下の機能は、トレンドグラフで詳細なパフォーマンス監視データをより良く確認し、分析するのに役立ちます。画像と以下の説明を組み合わせて理解してください。

   ![Image 114](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1725.png)

   * 他のサブ指標のデータの表示と非表示：カーソルを指標エリアに合わせ、マウスホイールを上下にスクロールすると、トレンドグラフに表示されているすべてのサブ指標データを確認できます。他のサブ指標のアイコンをクリックして灰色にすると、その指標情報はトレンドグラフに表示されなくなります。

   * カーソルをトレンドグラフの特定の時刻に合わせると、その時刻の詳細データを確認できます。カーソルをドラッグして範囲を選択すると、システムはその範囲のトレンド情報を拡大表示し、その期間の指標の詳細なトレンドを確認できます。このトレンドグラフをダブルクリックすると元に戻ります。

   * トレンドグラフの拡大：トレンドグラフの右上隅にある拡大アイコンをクリックします。上記の図の①、②の機能は、拡大されたトレンドグラフでも同様に適用されます。

   * 監視指標の編集：トレンドグラフの右上隅にある編集アイコンをクリックすると、注目すべきサブ指標のみを表示するよう選択できます。

   * 組み込みダウンで異なる次元の監視データを確認する：**<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.Tenant">テナント次元</UI-TERM>**タブで、テナントの監視データに異常が見られた場合、例えばテナントの応答時間が高すぎる場合、組み込みダウン分析を通じて、応答時間の異常を引き起こしたサーバーを特定できます。トレンドグラフの右上隅にある**<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">ドリルダウン分析</UI-TERM>**アイコンをクリックすると、組み込みダウン分析の詳細を確認できます。**パフォーマンスとSQL**でサポートされている組み込みダウンの次元は、**テナント \> OBServer**です。

       上記の図の①、②の機能は、組み込みダウンページのトレンドグラフでも同様に適用されます。さらに、以下の操作もできます：

       * 組み込みダウンページでフィルタリング条件を再設定します。設定していない場合は、上位レベルの設定が自動的に継承されます。

       * その指標にサブ指標が存在する場合、サブ指標を選択して確認できます。

       * トレンドグラフにはSQL検索機能が提供されています。対応するリンクをクリックすると、テナントのTopSQL診断の詳細を確認できます。

       * **ホストのパフォーマンス監視へ**機能を提供します。**ホストのパフォーマンス監視へ**リンクにカーソルを合わせ、表示したいホストを選択すると、該当ホストの**<UI-TERM key="ocp-v2.page.Monitor.PerformanceMonitoring">パフォーマンス監視</UI-TERM>**ページに移動し、ホストの監視詳細を確認できます。

   * SQLリクエスト分析の表示：<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.ResponseTime">応答時間（RT）</UI-TERM>**トレンドグラフで、トレンドグラフの右上隅にある**<UI-TERM key="ocp-v2.component.MetricChart.Item.SqlRequestAnalysis">SQLリクエスト分析</UI-TERM>**アイコンをクリックすると、リクエスト分析の詳細を確認できます。詳細については、[リクエスト分析の表示](../../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/1300.view-request-analysis.md)を参照してください。

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>SQLリクエスト分析は、<strong>応答時間</strong>のみで表示できます。</p>
     </main>

   * セッション分析の表示：<UI-TERM key="ocp-v2.src.constant.monitor.Sessions">セッション数</UI-TERM>**トレンドグラフで、トレンドグラフの右上隅にある**<UI-TERM key="ocp-v2.component.MetricChart.Item.SessionAnalysis">セッション分析</UI-TERM>**アイコンをクリックすると、セッション分析の詳細を確認できます。詳細については、[テナントセッションの管理](../../1000.diagnosis-and-tuning-fuctions/300.manage-session/100.manage-tenant-sessions.md)を参照してください。

     <main id="notice" type='explain'>
     <h4>説明</h4>
     <p>セッション分析は、<strong>セッション数</strong>のみで表示できます。</p>
     </main>
