# ホストのパフォーマンスを表示する

OCPでは、さまざまな観点からホストのパフォーマンス監視データを確認できます。以下の3つのエントリから確認できます：

* **エントリ1**：OCPにログインし、クラスタ概要ページに移動して、左側のナビゲーションバーの **<UI-TERM key="ocp-v2.Detail.Monitor.Title.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** をクリックします。

* **エントリ2**：OCPにログインし、ホスト詳細ページに移動して、**<UI-TERM key="ocp-v2.src.hook.useMenu.Monitoring">監視</UI-TERM>** タブをクリックします。システムはデフォルトで **<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.HostPerformance">ホストパフォーマンス</UI-TERM>** タブに移動します。

* **エントリ3**：OCPにログインし、左側のナビゲーションバーで **<UI-TERM key="ocp-v2.page.Monitor.Monitoring">パフォーマンス監視</UI-TERM>** をクリックします。システムはデフォルトで **<UI-TERM key="ocp-v2.page.Overview.OceanbaseCluster">OceanBase クラスタ</UI-TERM>** タブに移動します。

## 前提条件

* **エントリ1** からホストのパフォーマンス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用** リソース権限。
  * クラスタ **<UI-TERM key="ocp-v2.Detail.Realtime.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** メニュー権限。

* **エントリ2** からホストのパフォーマンス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
  * ホスト **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ArbitrationServiceWithExclude.All">すべて</UI-TERM>** メニュー権限。

* **エントリ3** からホストのパフォーマンス監視データを表示する場合、現在OCPにログインしているユーザーが以下の権限を持っていることを確認してください：

  * **クラスタ読み取り専用**、**テナント読み取り専用**、または **ホスト読み取り専用** のいずれかのリソース権限。
  * パフォーマンス監視 **<UI-TERM key="ocp-v2.Detail.Analyze.All">すべて</UI-TERM>** メニュー権限。

* ホストのパフォーマンス監視を **クラスタ > パフォーマンス監視** および **<UI-TERM key="ocp-v2.src.util.menu.PerformanceMonitoring">パフォーマンス監視</UI-TERM>** エントリから表示する場合のみ、ドリルダウン機能がサポートされます。**ホスト > 監視** エントリのパフォーマンス監視にはドリルダウン機能がありません。
* **ホスト > 監視** エントリでは、多次元でのパフォーマンス監視チャートの表示はサポートされていません。

## 手順

以下の手順は **エントリ3** を例に説明します。

1. OCPにログインします。

2. 左側のナビゲーションバーで **<UI-TERM key="ocp-v2.page.Monitor.Monitoring">パフォーマンス監視</UI-TERM>** を選択します。

3. システムはデフォルトで **<UI-TERM key="ocp-v2.Component.ClusterFilter.OceanbaseCluster">OceanBase クラスタ</UI-TERM>** タブに移動します。

4. **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">データフィルタリング</UI-TERM>** エリアで、監視データのフィルタリング条件を設定します。

   フィルタリング条件の説明は以下の表のとおりです：

   |     フィルタリング条件  |  説明  |
   |---------------|---------|
   | 更新  | 監視データを更新します。自動更新を有効にできますが、デフォルトは無効です。自動更新を有効にした場合、更新頻度を設定できます。|
   | 時間の選択（モニタリング期間とも呼ばれる） | 自動更新モードでは表示されません。特定の期間を選択すると、その期間内のデータが返されます。  |
   | クラスタ  | 特定のクラスタを選択し、そのクラスタの監視を行います。  |
   | Zone  | デフォルトではすべてのZoneを監視します。|
   | OBServer | デフォルトではすべてのOBServerノードを監視します。|

5. **<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.HostPerformance">ホストパフォーマンス</UI-TERM>**タブをクリックして、ホストパフォーマンス監視データを確認します。統計範囲に複数のOBServerノードが含まれる場合、その複数のOBServerノードの集計値が表示されます。

   * OCPは、クラスタとホストの2つの次元でホストパフォーマンス監視データを表示することをサポートしており、デフォルトではクラスタ次元で表示されます。異なる次元では、表示可能な監視指標が異なります。
   * システムはデフォルトで現在の次元におけるすべての監視項目を表示します。特定の監視項目に注目する必要がない場合は、エリアの右側にある**<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">選択したグラフ</UI-TERM>**パネルで、その監視項目のチェックを外すことができます。
   * すべての監視項目は、各サブ指標の最大値（max）、平均値（avg）、現在値（current）の表示をサポートしています。
   * すべての監視項目の具体的な意味と値の出典については、[監視指標の概要](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md)を参照して理解することができます。

   以下の機能は、トレンドグラフ上でのパフォーマンス監視データの視覚化と分析をより効果的に行うのに役立ちます。

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1647.png) -->

   1. 他のサブ指標データの表示と非表示：指標領域にカーソルを合わせ、マウスホイールを上下にスクロールすると、トレンドグラフに表示されているすべてのサブ指標データを見ることができます。他のサブ指標のアイコンをクリックして灰色にすると、その指標情報はトレンドグラフに表示されなくなります。

   2. トレンドグラフ上の特定の時刻にカーソルを合わせると、その時刻の詳細データを見ることができます。カーソルをドラッグして範囲を選択すると、システムはその範囲のトレンド情報を拡大表示し、その期間における指標の詳細なトレンドを確認できます。このトレンドグラフをダブルクリックすると元に戻ります。

   3. トレンドグラフの拡大：トレンドグラフの右上隅にある拡大アイコンをクリックします。上記の詳細データの表示とサブ指標の表示・非表示の機能は、拡大されたトレンドグラフでも同様に適用されます。

   4. 監視指標の編集：トレンドグラフの右上隅にある編集アイコンをクリックすると、注目すべきサブ指標のみを表示するよう選択できます。

   5. ドリルダウンによる異なる次元の監視データの確認：**<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.ClusterDimension">クラスタの次元</UI-TERM>**タブで、クラスタの監視データに異常が見られた場合（例えばCPU使用率が高すぎる場合）、ドリルダウン分析を通じて、応答時間の異常を引き起こしたサーバーを特定することができます。トレンドグラフの右上隅にある**<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">ドリルダウン分析</UI-TERM>**アイコンをクリックします。**<UI-TERM key="ocp-v2.Monitor.AddMonitor.AddMonitorDrawer.HostPerformance">ホストパフォーマンス</UI-TERM>**でサポートされているドリルダウンの次元は、**クラスタ \> ホスト**です。

      上記の詳細データの表示とサブ指標の表示・非表示の機能は、ドリルダウンページのトレンドグラフでも同様に適用されます。さらに、以下の操作も可能です：

      1. ドリルダウンページでフィルタ条件を再設定します。設定していない場合は、上位レベルの設定が自動的に継承されます。

      2. その指標にサブ指標が存在する場合、サブ指標を選択して確認することができます。

      3. その指標がホストパフォーマンスに関連している場合、**ホストパフォーマンス監視へ**リンクにカーソルを合わせ、対応するホストを選択してクリックすると、ホストの**<UI-TERM key="ocp-v2.src.hook.useMenu.Monitoring">監視</UI-TERM>**ページにジャンプできます。

6. （オプション）監視収集間隔を設定します。

   現在のOCPの秒単位の監視収集は、デフォルトで1秒ごとに1回行われます。この収集頻度は、OCP ServerのパフォーマンスおよびMonitorDBのストレージ性能に高い要件を課します。監視データに対する要求がそれほど高くない場合、config_properties内のocp.metric.collect.interval.secondのvalueを変更することで監視収集間隔を設定し、リソース使用量を削減し、全体の管理規模を拡大できます。

    <main id="notice" type='explain'>
    <h4>説明</h4>
    <p>現在、設定可能なvalueは1、5、10、15のみです。上記以外の数値を入力した場合、システムは自動的に適応します：</p>
    <ul>
    <li>1未満の場合は一律に1に設定されます。</li>
    <li>[1,5)区間は切り捨てにより1に設定されます。</li>
    <li>[5,10)区間は切り捨てにより5に設定されます。</li>
    <li>[10,15)区間は切り捨てにより10に設定されます。</li>
    <li>その他の場合は一律に15に設定されます。</li>
    </ul>
    </main>

   設定変更後、OCPは新しい収集間隔で直ちにデータの収集を開始します。モニタリングデータの表示間隔は、デフォルトで収集間隔の3倍となります（収集間隔が1秒の場合は除く）。例えば、収集間隔が5秒の場合、1秒単位でクエリされたモニタリングデータの表示間隔は15秒となります。
