# テナント内でリモート実行されたSQLを特定する方法

OceanBaseでは、各業務テーブルには1つのプライマリレプリカと複数のスタンバイレプリカが存在します。外部に強整合性の読み書きサービスを提供できるのはプライマリレプリカのみであり、スタンバイレプリカは弱整合性の読み取りサービスを提供できます。

業務上の強整合性読み書きリクエストがOceanBaseクラスタに送信される際、それはプライマリレプリカが配置されているマシンにルーティングされます。ルーティングに問題が発生し、リクエストがスタンバイレプリカに送信された場合、SQLが実際にプライマリレプリカのマシンに到達し、プライマリレプリカがサービスを提供するまでに、OceanBaseクラスタ内部で1回の転送リクエストが発生します。同時に、実行結果はルーティングの前段階にあったスタンバイレプリカに返され、そこからクライアントに返されます。この方式では、リモート実行によりネットワーク転送が2回増えるため、SQLの応答時間が長くなります。そのため、このようなSQLについては分析処理を行う必要があります。

TopSQLの**<UI-TERM key="ocp-v2.Component.filter.ColumnManagement">カラム管理</UI-TERM>**をクリックし、**リモート計画の割合(%)**を選択して、**リモート計画の割合(%)**列でソートするように選択します。
