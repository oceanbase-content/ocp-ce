# テナント内で実行エラーが発生したSQLを特定する方法

業務のメンテナンス中には、業務や業務テーブルに対して様々な調整や変更を加えることがあり、その結果、業務用SQLが無効になる場合があります。また、本来は正常に実行されていたSQLが、業務負荷の増加やデータ量の増大により、実行失敗を引き起こす可能性もあります。このような場合、SQLの実行状態を迅速に把握し、業務への損失を防ぐ必要があります。

TopSQLの**<UI-TERM key="ocp-v2.Component.filter.ColumnManagement">カラム管理</UI-TERM>**をクリックし、エラー統計に関連するオプションを選択します。これには、**エラー回数**、**<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.ErrorPercentage">エラー率</UI-TERM>**、**タイムアウトエラー**、**メモリ不足エラー**、**構文エラー**、**キー値競合エラー**、**データ長過ぎエラー**、**未知列エラー**、**トランザクションロールバックエラー**が含まれます。そして、**エラー回数**列でソートすることを選択します。
