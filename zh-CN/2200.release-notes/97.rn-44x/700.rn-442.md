# OCP V4.4.2

## V4.4.2 BP2

### 版本信息

* **版本号：** V4.4.2 BP2

* **前置版本：** V4.4.2 BP1

* **版本发布日期：** 2026 年 8 月 12 日

### 主要修复问题


修复了 OCP 监控模块周期性刷新内部资源时旧资源未被正确释放，导致 OCP 进程内存随运行时间持续增长的内存泄漏问题。该问题在大规模集群环境下更容易触发（监控对象越多，单次泄漏占用的资源越多，内存增长速度越快），尤其在启用 SLS/Prometheus 监控数据源的环境中影响更为明显，长期运行可能导致 OCP 进程内存耗尽而 OOM，影响管控稳定性。建议使用 4.4.1.x / 4.4.2.x 版本、尤其是管理大规模集群或启用了 SLS/Prometheus 监控数据源的用户尽快升级；若短时间内无法升级，请联系技术支持人员。



## V4.4.2

OCP V4.4.2 正式发布！本次升级已全面适配主备强同步模式，并大幅完善监控告警功能，为企业用户带来更稳定、高效、安全的数据库管理体验。

**核心亮点**：

* **主备同步**：租户级主备库支持 **最大可用** 和 **最大保护** 两种保护模式，帮助用户构建更加完善可靠的容灾解决方案。
* **外部集成**：支持将监控数据通过可视化方式对接 Prometheus，方便用户复用现有基础设施，同时降低 OCP 系统自身的工作负载。
* **AI 功能优化**：根据用户提问，智能推荐 3 个关联性较强的问题选项，帮助用户明确需求，提升回答精准度和用户满意度。

### 关键特性解读

#### 主备强同步（实验特性）

为满足用户业务场景中对高可用性和数据一致性的严格要求，OceanBase 通过实现 **最大保护** 模式和 **最大可用** 模式达到主备库强同步能力，从而提供更可靠、更安全的数据服务，满足 `RPO=0` 的高标准要求。

| 特性 | 最大保护模式 | 最大可用模式 |
| -------- | --------- | --------- |
| 同步机制 | 事务需要在主库和所有强同步备库上的 REDO 日志都持久化成功后，才能向客户端返回提交成功。 | 与最大保护模式相同，事务需等待 REDO 日志在主库和强同步备库上都持久化成功后提交。 |
| 可用性保障 | 当强同步备库不可用时，主库会自动停止写服务，防止数据不一致。 | 当检测到强同步备库故障时，系统自动降级为最大性能模式，优先保证主库服务的可用性。 |
| 适用场景 | 对数据一致性要求极高的金融核心系统、交易结算系统等。 | 对可用性和一致性都有较高要求的业务系统。 |

OCP 提供了全面的容灾管理能力，支持以下关键功能：

* **模式管理**：支持同步模式与保护模式的灵活切换，包含由 **最大性能** 变更为 **最大可用**/**最大保护** 模式，以及由 **最大可用**/**最大保护** 模式变更为 **最大性能** 模式等。
* **切换操作**：支持日常切换/批量日常切换、容灾切换/批量容灾切换，降低用户在容灾以及演练等场景下的操作难度。
* **架构调整**：支持主备解耦操作，满足业务灵活部署需求。
* **可视化监控**：通过主备拓扑图展示，直观呈现主备一主多备、级联等架构以及同步状态。

### 新功能

#### 基础运维

**集群管理**：透明数据加密（TDE）功能适配江南科友 KMS 服务，为用户提供更强大的数据保护方案，支持的 OceanBase 版本为：[V4.2.5.4, V4.3.0.0)、[V4.3.5.2, +∞)。

#### 监控告警

* 支持采集仲裁服务日志并基于日志报错进行告警。
* OBProxy 支持监控指标的逐层下钻分析，帮助用户快速定位问题和深入了解系统状态。
* 支持 clog hang 日志类型告警，并提供具体原因分析和解决方案，避免因该问题造成业务中断。
* 为 SQL 类型告警规则（如 `oas_anomaly_sql_from_{*}` 等）配置告警屏蔽时，支持更多的过滤标签项，如数据库名、用户名等。
* 支持日志流缺主告警，支持的 OceanBase 版本范围为：[V4.0.0.0, +∞)。
* 支持对 `oas_anomaly_sql_from_{*}` 等告警规则配置不同集群的独立阈值参数，确保监控策略与各集群实际运行状态相匹配。
* 监控图表支持降序展示，便于查看性能瓶颈。

#### 容灾管理

* 支持租户级主备库保护模式 **最大可用** 和 **最大保护**，方便用户构建更加可靠的容灾解决方案，支持的 OceanBase 版本范围为：[V4.4.2.1, +∞)。
* 支持在主备租户概览页支持暂停/开启日志同步功能，并新增状态、保护模式、保护级别等属性展示。
* 支持在集群概览页展示主备租户的历史延时信息，方便用户结合时间维度分析延迟问题。
* 提升 10+ 租户场景下执行批量日常切换的效率。

#### 平台化能力

* **安全**：兼容 Tectia SSH Client/Server 商业版本。

* **外部集成**：支持将监控数据通过可视化方式对接 Prometheus，方便用户复用已有基础设施以及降低 OCP 自身压力。

### 产品优化

#### 租户管理

支持 Unit 缩容预检查，降低因租户内存不足造成业务影响的可能性。

#### OBProxy

迁出 OBProxy 前检查 `obproxy_config_server_url` 格式是否符合 OCP 规范并进行提示：**OBProxy 配置服务器 URL（obproxy_config_server_url）格式校验失败。建议迁出后修正配置，请注意，配置变更后会导致OceanBase 数据库出现短暂的服务中断**。

#### Binlog 服务

优化 OCP 对 logproxy 进程异常的状态同步机制，确保异常发生时监控界面能实时、准确地展示相应状态。

#### 其他

* OCP-Agent 默认指定 `/bin/bash` 执行 shell 命令，解决部分操作系统因使用其他类型 shell 而造成脚本无法正常执行的问题。
* OCP OpenAPI 接口支持基于 SHA256 的安全签名认证，防止请求篡改和未经授权访问。
* 透明数据加密（TDE）表空间内的表增加 schema 属性。
* **外部集成** > **大模型** 设置系统模型时，Rerank 模型支持选择为空。
* **集群管理** > **运维配置** > **OCP Agent 资源配置**、**主机** > **变更 OCP Agent 规格** 以及 **主机管理** > **新增主机** 页面增加提示语：**在高业务负载或压力测试场景下，建议提升 OCP Agent 的资源规格配置，以防止因资源不足导致 OOM 或监控数据丢失**。

### 产品行为变更

* **性能监控** 页面的时间选择器增加 **近 5 分钟**、**近 10 分钟**、**近 7 天** 3 种时间范围，同时移除使用频率较低的 **近 1 分钟** 选项，提升用户查询效率。
* 去除无效告警规则 `ob_log_server_hang_due_to_trx_lock`。

### 主要修复问题

OCP V4.4.2 版本主要修复如下问题：

* 修复了 OCP 多节点模式下，**OBProxy 客户端连接使用率超限** 告警在部分节点触发失败的问题。
* 修复了发起恢复时 OCP Agent 生成的 `ob_admin` 解析命令不准确的问题。
* 修复了当租户参数模板中包含 `max_allowed_packet` 参数时租户创建失败的问题。
* 修复了巡检报告中 OceanBase 数据盘文件类型数据错误的问题。
* 修复了因 root@sys 密码包含特殊字符导致 OBShell 启动失败的问题。
* 修复了在采集 `ob_cluster_arbitration_active` 指标时 `monagent.limit.memory.quota` 配置未生效的问题。
* 取消上传软件包时增加相关操作提示。
* 修复了 **凭据管理** 的 UI 及 Label 名称在 OCP 中英文界面不一致的问题。
* 修复了 OCP-Agent 因 `ocp_agent.service` 中的路径与实际路径不一致而导致自动重启异常的问题。

## 版本使用限制

### 硬件要求

OCP-Server 可以安装在物理机上，也支持安装运行在 Docker 容器中。OCP-Server 支持多节点高可用部署模式。

OCP-Server 节点最低硬件要求如下表所示。

| 硬件 | 要求 |
|------|------|
| CPU | <li>X86_64，8 核</li><li>ARM aarch 64 架构，8 核</li> |
| 内存 | 可用内存 16 GiB |
| 网卡 | 万兆网卡 |

OCP-Agent 自身占用资源很少，对安装节点硬件资源没有特别要求。
