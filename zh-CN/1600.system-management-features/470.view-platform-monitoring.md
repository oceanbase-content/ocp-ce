# 查看平台监控

OCP 对自身进行应用监控，是保障系统稳定运行、提升运维效率、优化用户体验的关键举措。通过实时监控 OCP 自身运行状态，用户可第一时间发现服务异常、资源瓶颈及潜在故障，如 Agent 访问异常、网络延迟，full GC 等，避免因管理平台自身问题影响 OceanBase 数据库的正常管理，保障业务连续性。

监控数据还能为资源优化提供依据，通过分析 CPU、内存等资源占用率，合理调整资源分配，提升系统整体性能。同时，借助日志与指标的深度分析，运维人员可快速定位问题根源，实现故障精准修复，大幅缩短故障处理时间。此外，持续的监控数据积累有助于预测系统性能趋势，提前规划扩容与升级，满足业务增长需求，为用户提供更可靠、高效、低运维成本的数据库管理服务。

## 前提条件

* 执行开启或关闭平台监控操作时，请确保当前登录 OCP 的用户具有 **ADMIN** 角色权限。
* 查看平台监控数据时，请确保当前登录 OCP 的用户具有 **ADMIN** 或 **ADMIN_VIEWER** 角色权限。

## 注意事项

开启 OCP 平台监控可能会耗费较多资源，请根据实际资源情况选择是否开启。

## 操作步骤

### 开启平台监控

1. 登录 OCP 。
2. 在左侧导航栏选择 **系统管理** > **平台监控** ，单击 **开启平台监控**。
3. 单击对话框中的 **开启**。
4. （可选）为保证性能监控数据正常展示，在开启平台监控功能后，建议您参考 [启动和停止 OCP](../300.deployment-guide/100.deploying-enterprise-ocp/400.deployment-faq/600.starting-and-stopping-ocp.md)（企业版） 或 [重启 OCP](../300.deployment-guide/200.deploying-community-ocp/700.deploy-appendix/300.restart-ocp.md)（社区版）手动重启 OCP 服务。

### 查看平台监控详情

开启平台监控后，即可进入平台监控页面查看 OCP 平台监控详情。

* 查看 OCP 平台基本信息。

  | 参数  | 说明  |
  |-------|-------|
  | OCP 集群名 | 当前 OCP 集群的名称，仅 OCP 多集群模式下展示。  |
  | ID         | 当前 OCP 集群的 ID，仅 OCP 多集群模式下展示。   |
  | 版本号     | 当前 OCP 的版本号。 |
  | 当前访问地址  | 当前 OCP 的访问地址。 |

* 查看 OCP 平台访问地址详情。

  | 参数  | 说明 |
  |-------|------|
  | 访问地址 | OCP 的访问地址，支持复制。|
  | 状态     | 当前 OCP 的运行状态。 |
  | 运行时间 | OCP 服务从启动到当前时刻持续运行的时长。 |
  | 启动时间 | OCP 服务最近一次的启动时间。 |

* 查看 OCP 平台监控数据。

  * **性能监控**：

      | 监控项          | 监控指标  | 监控指标含义 | 单位 |
      |-----------------|----------|-----------|---------|
      | CPU 使用率      | system_cpu_usage | OCP CPU 使用率  | %  |
      | 磁盘使用率      | disk_percent     | OCP 磁盘使用率  | % |
      | 系统负载（1m）  | system_load_average | OCP 每 1 分钟内的系统负载  | -  |
      | 可用处理器个数  | system_cpu_count  | OCP 可用处理器个数 | -  |
      | JVM GC 次数     | gc_total         | OCP JVM 次数   | - |
      | JVM GC 耗时     | gc_time          | OCP JVM 耗时   | s |
      | JVM 内存使用大小  | <li>jvm_heap_memory_used_bytes</li><li>jvm_nonheap_memory_used_bytes</li>  | <li>jvm_heap_memory_used_bytes：OCP JVM 已使用堆内存大小</li><li>jvm_nonheap_memory_used_bytes: OCP JVM 已使用堆外内存大小</li>  | Byte |
      | JVM 内存使用率  | <li>jvm_heap_memory_used_percent</li><li>jvm_nonheap_memory_used_percent</li> | <li>jvm_heap_memory_used_percent：OCP JVM 已使用堆内存使用率</li><li>jvm_nonheap_memory_used_percent：OCP JVM 已使用堆外内存使用率</li> | % |
      | JVM 启动时间    | process_start_time_seconds | OCP JVM 启动时间 | s |
      | JVM 运行时间    | process_uptime_seconds     | OCP JVM 运行时间 | s |
      | JVM 内存分布    | <li>used</li><li>committed</li><li>max</li>  | <li>used: OCP JVM 已使用内存</li><li>committed: OCP JVM 内存可使用内存（包含已使用的）</li><li>max: OCP JVM 最大可申请内存</li> | byte |

  * **HTTP 请求**：

      | 监控项  | 细分指标  | 指标含义 | 单位   |
      |---------------|-----------|---------|--------|
      | 平均每秒 http 请求执行成功次数     | success_count | OCP 平均每秒 http 请求执行成功次数 | - |
      | 平均每秒 http 请求执行失败次数     | fail_count    | OCP 平均每秒 http 请求执行失败次数 | - |
      | 平均每次 http 请求执行成功耗时     | success_time  | OCP 平均每次 http 请求执行成功耗时 | s |
      | 平均每次 http 请求执行耗时         | fail_time     | OCP 平均每次 http 请求执行失败耗时 | s |

  下述功能能够帮您更好的在趋势图中查看和分析性能监控数据，您可结合图片及下述文字理解：

  * ①：默认仅展示一个主机的数据，您可通过主机列表进行切换查看。
  * ②：单击 **刷新**，可对监控数据进行单次刷新。
  * ③：支持开启自动刷新，开启后，监控数据将根据所选频率进行自动刷新。
  * ④：支持选择某一段时间范围，用于返回这段时间范围内的监控数据。
  * ⑤：将光标悬停于趋势图中某时刻，可查看某时刻详细数据；拖拽光标选中某区域，系统会放大显示该区域的趋势信息，您可查看该指标的在此时间段的详细趋势，双击该趋势图可恢复。
  * ⑥：单击其它细分指标标识，使其置灰，趋势图中将不展示该指标信息。
  * ⑦：所有监控项均支持展示每个细分指标的最大值（max）、平均值（avg）和当前值（current）。单击 **max**、**avg** 或 **current**，可对该列数据进行升序排序或降序排序。

### 关闭平台监控

单击页面右上角的 **关闭平台监控**，即可关闭采集 OCP 平台监控数据。关闭平台监控后，为避免监控采集造成的资源浪费，建议您参考 [启动和停止 OCP](../300.deployment-guide/100.deploying-enterprise-ocp/400.deployment-faq/600.starting-and-stopping-ocp.md)（企业版） 或 [重启 OCP](../300.deployment-guide/200.deploying-community-ocp/700.deploy-appendix/300.restart-ocp.md)（社区版）手动重启 OCP 服务。
