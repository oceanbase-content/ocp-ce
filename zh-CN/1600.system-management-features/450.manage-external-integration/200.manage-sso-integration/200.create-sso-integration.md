# 新建 SSO 集成

OCP 内置了账号体系，您可参考本页面在 OCP 中配置外部集成服务，并通过 SSO 登录到 OCP 首页。

## 前提条件

* 您已参考 [外部集成概述](100.external-integration-overview.md) 了解 SSO 的概念介绍及授权流程。
* 请确保当前登录 OCP 的用户为 **ADMIN** 角色。
* 用户已部署授权服务。

## 注意事项

* OAUTH/OIDC 集成只支持授权码模式。
* OAUTH/OIDC 退出登录时，只清除 OCP 应用的登录态，不会清理 SSO 系统的登录态。

## 配置说明<a id="parameter"></a>

### Client Authentication Method

Client Authentication Method（客户端认证方法） 是指在 OAuth2、OIDC 或其他 API 安全协议中，客户端应用向授权服务器证明其身份的方式。您可根据客户端的类型以及安全需求选择合适的认证方法。

#### client_secret_basic

* 方式：使用 HTTP Basic 认证。
* 实现：将 client-id 和 client-secret 进行 Base64 编码，放入 HTTP 请求头的 Authorization: Basic ... 中。

#### client_secret_post

* 方式：将凭据作为 POST 请求体参数。
* 实现：在请求体中包含 client_id 和 client_secret 参数。

#### client_secret_jwt

* 方式：使用基于对称密钥（Client Secret）签名的 JWT。
* 实现：客户端生成一个包含声明的 JWT，并使用 client_secret 进行签名，作为认证凭据。

#### private_key_jwt

* 方式：使用基于非对称密钥（私钥）签名的 JWT。
* 实现：客户端使用自己的私钥对 JWT 签名，授权服务器通过预先配置的公钥进行验签。

#### none

* 方式：不进行客户端认证。
* 适用场景：通常用于公共客户端（Public Client，如移动端或 SPA 应用），这些应用无法安全地存储 Secret，常配合 PKCE 流程使用。

### User Info Authentication Method

OAuth2 中的 User Info Authentication Method 指的是客户端在请求用户信息（User Info）端点时，向服务器验证自身身份的方式。常见的三种方法如下：

#### Query

将客户端凭证（如 client_id 和 client_secret）作为查询参数附加在 URL 中传递。

例如：

```GET /user_info?access_token=xxx&client_id=abc&client_secret=def```

此方式不推荐，因 URL 可能被日志记录或缓存，存在泄露风险。

#### Header

使用 HTTP Authorization 头进行认证，通常采用 Base64 编码的 client_id:client_secret 作为 Basic Auth 信息。

例如：

```Authorization: Basic base64encode(client_id:client_secret)```

此方式较为安全，但需确保通信过程加密（如 HTTPS）。

#### Form

在请求体中以表单形式提交客户端凭证。

例如：

```http
POST /user_info
Content-Type: application/x-www-form-urlencoded
client_id=abc&client_secret=def
```

此方式常见于 client_credentials 授权类型，需配合 Content-Type 头使用。

### 用户信息数据结构类型

#### FALT

FALT 方式表示平铺，假设用户字段为 username，如下返回格式即为平铺：

```json
{
"username":"xxx"
}
```

#### NESTED

NESTED 方式表示嵌入，即 username 嵌入在 userInfo 结构里面。当用户信息数据结构类型选择 NESTED 时，获取嵌套用户数据处需要填写 userInfo，继而再设置用户名字段：

```json
{
    "userInfo":{
        "username":"xxx"
    }
}
```
