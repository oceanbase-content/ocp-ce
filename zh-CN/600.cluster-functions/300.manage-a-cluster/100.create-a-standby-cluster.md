# 新建备集群

如果您有一个主集群，您可以为当前集群创建一个备用集群。

<main id="notice" type='notice'>
<h4>功能适用性</h4>
<p>该内容仅适用于 OCP 企业版，OCP 社区版仅支持新建主集群。</p>
</main>

## 前提条件

* 当前登录 OCP 的用户为 **ADMIN** 角色或 **ORG_ADMIN** 角色。
* 主集群版本为 V2.2.50 及以上、V4.0.0 以下。

## 操作步骤

### 步骤一：进入创建集群页面

1. 登录 OCP 。

2. 在左侧导航栏单击 **<UI-TERM key="ocp-v2.component.CardAbnormalTable.Cluster">集群</UI-TERM>** ，系统默认进入 **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">集群列表</UI-TERM>** 页签。

3. 您可以通过以下 2 种方式进入创建备集群的页面。

   * 在 **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">集群列表</UI-TERM>** 页面，单击 **<UI-TERM key="ocp-v2.page.Welcome.CreateACluster">创建集群</UI-TERM>** ，在 **基本信息** > **集群类型** 中选择 **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.SecondaryCluster">备集群</UI-TERM>**。

   * 在 **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">集群列表</UI-TERM>** 页面，选择待添加备集群的集群并单击其集群名，单击 **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">概览</UI-TERM>** 页面的右上角的 **...** ，选择 **<UI-TERM key="ocp-v2.Cluster.Detail.CreateAStandbyCluster">新建备集群</UI-TERM>** 。

### 步骤二：设置集群基础信息

在 **<UI-TERM key="ocp-v2.Tenant.New.CreateACluster">创建集群</UI-TERM>** 页面，设置备集群基础信息。

基础信息填写说明如下标所示：

|       配置       |     描述      |
|----------------|-----------|
| **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.ClusterType">集群类型</UI-TERM>**       | 选择 **<UI-TERM key="ocp-v2.src.constant.oceanbase.StandbyCluster">备集群</UI-TERM>** ，请确保主集群已创建。 |
| **主集群所属 OCP**          | 选择主集群所属的 OCP 集群。|
| **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.MasterCluster">主集群</UI-TERM>**        | 选择主集群，系统将创建属于该主集群的备集群。  |
| **备集群 OceanBase 版本**  | 选择与主集群相同的 OceanBase 版本。<ul><li>若列表中有该版本，则从列表中直接选择。</li><li>否则，可通过单击列表下方的 **添加版本** 来上传。</li> </ul>   |

### 步骤三：设置集群部署模式信息

系统默认添加 3 个 Zone 的信息，如果您希望部署的集群 Zone 的个数大于 3 个，您可以在下方单击 **新增 Zone** 按钮，增加 Zone 信息；如果部署的集群 Zone 的个数小于 3 个，您可以单击 Zone 后面的删除图标。

每个 Zone 需要配置的信息及说明如下表所示。

|   配置   |  描述   |
|----------|---------|
| **<UI-TERM key="ocp-v2.Cluster.New.ZoneName">Zone 名称</UI-TERM>**    | 可保持默认也可自定义。Zone 名称必须以英文字母开头，支持大小写字母、数字和下划线，长度为 2\~32。部署多 Zone 的 OceanBase 集群必须有一个 Zone 与主 Zone 的 Region 相同。  |
| **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ComputerRoom">机房</UI-TERM>**     | Zone 所在的机房，一个 Zone 只能存在于一个机房。  |
| **<UI-TERM key="ocp-v2.OBProxy.New.ModelOptional">机型</UI-TERM>**    | 可选项。如果选择了机型，后面主机列表会根据机型进行过滤。   |
| **<UI-TERM key="ocp-v2.page.Host.CpuArchitecture">CPU 架构</UI-TERM>**    |  当选择的 **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBase 版本</UI-TERM>** 中存在多个不同架构的安装包时，需选择匹配此软件包的主机硬件架构。<blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">注意</UI-TERM>**</br><ul><li>默认架构类型为第一个安装包的架构类型，支持切换。切换指定架构后，**<UI-TERM key="ocp-v2.src.constant.auditEvent.Host">主机</UI-TERM>** 列表中即展示该架构的主机。</li><li>若为不同的 Zone 设置不同的架构时，混合架构部署模式可能存在稳定性与性能问题，请谨慎操作。</li></blockquote> |
| **<UI-TERM key="ocp-v2.component.ZoneFormCardList.Host">主机</UI-TERM>**  | 您可以选择多个主机，或进行添加主机的操作。   |
| **Root Service 位置**     | 您需选择一个 IP 作为 RootService 所在的机器。多副本的 OceanBase 集群，其每个 Zone 都需指定一个 root Service。   |

### 步骤四：开启 Cgroup

Cgroup 主要用于 OceanBase 集群内租户之间以及租户内的 CPU 资源隔离，您可根据实际业务类型选择是否为集群开启 Cgroup，以实现更强的 CPU/IOPS 隔离性。当您创建的 OceanBase 集群为 V4.0 及以上版本时，系统会默认开启 Cgroup。

* 开启 Cgroup 会造成大约 7% 的性能下降，若您的业务场景为单租户、小规格（<14C）以及需要更高的数据库性能时，建议您关闭 Cgroup。
* 若主机的操作系统内核版本低于 5.1.0，建议关闭集群 Cgroup，否则可能会引起系统性能下降或不稳定。
* 若主机的操作系统内核版本低于 4.1.9，集群将无法创建租户，此时系统将默认关闭 Cgroup 且不显示 Cgroup 开关。

### 步骤五：配置 CPU 超卖额度

当不同业务场景的负载出现交叠，OceanBase 集群在运行过程中可能会产生负载过载等情况，会出现不同租户间进行线程竞争 CPU 的现象，进而导致实际业务场景变慢。为保证系统不同的租户负载可以有控制地交错运行，配置 CPU 资源时可以进行超卖设置来提升资源利用率。

在 **<UI-TERM key="ocp-v2.Cluster.New.CpuOversoldSettings">CPU 超卖设置</UI-TERM>** 模块，您可通过滑动块或输入框配置超卖比例，默认值为 120%，取值范围为 101%~200%。

<main id="notice" type='explain'>
<h4>说明</h4>
<p><ul><li>仅 OceanBase 4.0 及其以上版本支持对 CPU 进行超卖分配，在合理配置下，您可以充分地利用硬件资源。</li><li>CPU 超卖功能依赖 Cgroup，在配置 CPU 超卖额度前，请先为集群开启 Cgroup。</li></ul>
</p></main>

### 步骤六：配置集群参数

打开 **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.ParameterSettings">参数设置</UI-TERM>** 模块，您可自定义配置集群参数。

* 当您在 **<UI-TERM key="ocp-v2.Tenant.New.BasicSettings">基本设置</UI-TERM>** 中配置了负载类型时，系统将默认选择与负载类型对应的参数模板。

* 您可通过如图 ① 处，逐个添加启动参数项并为其配置值。

* 也可通过如图 ② 处，单击 **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">选择参数模板</UI-TERM>** ，然后选择一个参数模板，系统会将模板中的参数连同配置自动填充到此处。在未创建集群参数模板的情况下，您可单击 **新建集群模板**，为集群创建参数模板，详情可参考 [管理集群参数模板](../1400.cluster-parameters-template-management.md)。

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/430/%E5%8F%82%E6%95%B0%E6%A8%A1%E6%9D%BF.png)

   系统提供如下 6 种内置模板，模板中包含了常用的参数设置，您可直接应用该模板进行集群的初始化设置。关于系统内置模板，具体说明如下。

   | 模板 | 说明 |
   |------|--------|
   | COMPLEX_OLTP 默认参数模板   |  对应 **Complex OLTP** 负载类型，该模板仅适用于 OceanBase V4.2.5 及以上版本。   |
   | HTAP 默认参数模板   |   对应 **HTAP** 负载类型，该模板仅适用于 OceanBase V4.2.5 及以上版本。 |
   | KV 默认参数模板   |  对应 **OBKV** 负载类型，该模板仅适用于 OceanBase V4.2.5 及以上版本。   |
   | EXPRESS_OLAP 默认参数模板 | 对应 **Express OLAP** 负载类型，该模板仅适用于 OceanBase V4.2.5 及以上版本。 |
   | OLAP 默认参数模板   |  对应 **OLAP** 负载类型，该模板仅适用于 OceanBase V4.3.0 及以上版本。   |
   | 2.2.77 默认参数模板   |   OceanBase 集群 V2.2.77 版本推荐使用的参数设置，供生产环境使用。   |

<main id="notice" type='explain'>
<h4>说明</h4>
<p>如您对集群级别的 CPU、内存、数据盘以及日志盘的使用有定制化变更诉求，请设置参数：<code>cpu_count</code>、 <code>memory_limit_percentage</code>、<code>system_memory</code>、 <code>data_disk_usage_limit_percentage</code>、<code>datafile_size</code>、<code>clog_disk_usage_limit_percentage</code>、<code>log_disk_size</code>，具体参数说明请参考 OceanBase 官网 <a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000640281">集群配置项总览</a>。</p></main>

### 步骤七：配置用户、路径及端口

在 **<UI-TERM key="ocp-v2.Cluster.New.CustomSettings">自定义设置</UI-TERM>** 模块，支持您执行集群级别用户配置（如操作系统属主用户）、路径设置（如软件安装路径、数据盘路径、日志盘路径）以及端口设置（如 SQL 端口、RPC 端口）。

1. 配置操作系统所属主用户：

   该用户为配置安装、运行 OBServer 的操作系统用户，不支持编辑。您可通过调整 `ocp.operation.default.os.user` 参数的默认配置来修改此用户，该参数的修改仅在创建分布式集群、[创建单机](200.create-a-standalone-centralized-cluster.md)、[创建 OBProxy 集群](../../800.obproxy-functions/200.create-an-obproxy-cluster.md) 和 [创建仲裁服务](../1350.manage-arbitration-services/200.create-arbitration-services.md) 时产生影响，不影响已有集群的其他配置。

2. 配置相关路径：

   |   配置   |  描述   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SoftwareInstallationPath">软件安装路径</UI-TERM>**   | <ul><li>当 **操作系统所属主用户** 为 admin 时，**<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">软件安装路径</UI-TERM>** 默认为 `/home/admin/oceanbase`，支持自定义。</li><li>当 **操作系统所属主用户** 为非 admin 时，**<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">软件安装路径</UI-TERM>** 默认为 `/opt/oceanbase/oceanbase`，支持自定义。</li></ul>   |
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DataDiskPath">数据盘路径</UI-TERM>**       | 默认为 `/data/1`，支持自定义。  |
   | **<UI-TERM key="ocp-v2.Cluster.New.LogDiskPath">日志盘路径</UI-TERM>**   | 默认为 `/data/log1`，支持自定义路径。生产环境下，OceanBase 数据库建议日志盘空间为主机内存空间的三倍以及以上；同时，为了避免出现性能问题，不建议数据目录和日志目录挂载在同一块磁盘上。<main id="notice" type='explain'><h4>说明</h4>从 OCP 4.3.0 BP1 开始，当创建如下版本的 OceanBase 集群时，slog 目录将置于日志盘中，不再与数据盘绑定。此时若配置 <code>log_disk_size=0</code>，会被视为 clog 独占，即默认 <code>log_disk_percentage</code> 为 90%。如果 slog 与 clog 所在磁盘的大小小于 40GiB，此时为 slog 预留的空间则不足 4GiB，可能会影响 slog 的写入。<ul><li>V4.2.4.0 ≤ OceanBase ＜ V4.3.0.0</li><li>OceanBase ≥ V4.3.1.0</li></ul>更多 slog 相关说明，请参见 <a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000000819002">OBServer 节点安装目录结构</a>。</main>      |

3. 配置端口：

   |   配置   |  描述   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Cluster.New.SqlPort">SQL 端口</UI-TERM>**        | 默认为 2881，支持自定义。  |
   | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.RpcPort">RPC 端口</UI-TERM>**   | 默认为 2882，支持自定义。     |

4. 配置完成后，单击 **<UI-TERM key="ocp-v2.Cluster.New.Test">测试</UI-TERM>**，校验所填路径及端口是否可用。

    * 若测试通过，单击 **<UI-TERM key="ocp-v2.Alarm.Template.New.Submit">提交</UI-TERM>** 。
    * 若测试不通过，可根据提示信息进行排查处理。

### 步骤八：确认配置信息

1. 在右侧面板中确认所配置的集群信息是否无误，单击 **下一步** 。

2. 执行创建前的预检查，系统将验证您的环境是否满足创建备集群的最低要求。若检查项执行失败，可根据提示进行如下操作：

    * **上传**：当 JVM 环境依赖服务的软件包缺失时，可单击 **上传** 手动上传所需软件包。
    * **跳过**：此操作将跳过当前检查项（专为特殊场景设计），请务必确保相关检查项已满足产品规范要求，否则可能导致后续流程执行失败。跳过后，该检查项的状态将变更为 **警告**。
    * **重试**：重新运行失败的检查项，即先回滚再执行，成功后将继续执行下游子检查项。
    * **全部重试**：重新运行所有失败的检查项。

3. 待不存在执行失败的检查项后，单击 **新建**。

   提交新建集群任务后，您可在 **任务中心** 中查看该任务的执行进度。
