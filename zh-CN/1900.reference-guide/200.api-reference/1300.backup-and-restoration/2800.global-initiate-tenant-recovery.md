# 全局发起租户恢复

## 功能说明

该接口用于从全局视图发起租户恢复。可将 [解析全局备份信息](2700.parse-global-backup-info.md) 接口解析出的离线租户恢复到当前 OCP 管理的目标集群，源集群无需由当前 OCP 管理。

与现有"发起租户/库/表恢复"接口（`POST /api/v2/ob/clusters/{id}/backup/restore`）相比，本接口的请求路径无需指定源集群 ID，适用于跨 OCP 等全局离线恢复场景。

接口模型同时包含 `ONLINE` 和 `OFFLINE` 两种分支；全局离线恢复场景下 `backupTenantStatus` 固定使用 `OFFLINE`，并填写 `restoreOfflineTenantRequiredParam`。

## 调用说明

### 接口约束

* 调用者需要通过 OCP 应用服务鉴权。
* 调用者需要对目标集群拥有更新权限，并对所选解析主机拥有读取权限。

### 请求路径

`POST /api/v2/backup/restore`

### 请求参数

**RestoreTenantParam 的数据结构**

| 参数 | 类型 | 必选 | 示例值 | 描述 |
| --- | --- | --- | --- | --- |
| backupTenantStatus | String | 是 | OFFLINE | 备份租户状态。取值为 `ONLINE` 或 `OFFLINE`；全局离线恢复固定传 `OFFLINE`。 |
| restoreOnlineTenantRequiredParam | Object | 否 | - | 在线租户恢复参数。全局离线恢复时省略。 |
| restoreOfflineTenantRequiredParam | Object | 条件必选 | - | `backupTenantStatus` 为 `OFFLINE` 时必选。 |

**RestoreOfflineTenantRequiredParam 的数据结构**

| 参数 | 类型 | 必选 | 示例值 | 描述 |
| --- | --- | --- | --- | --- |
| backupMode | String | 是 | PHYSICAL_BACKUP | 备份模式。取值为 `PHYSICAL_BACKUP` 或 `LOGICAL_BACKUP`，应使用解析结果中的值。 |
| backupClusterName | String | 是 | prod_cluster | 备份源集群名称，取自解析结果的 `clusterName`。 |
| backupObClusterId | Long | 物理备份必选 | 1001 | 备份源集群在 OceanBase 中的集群 ID，取自解析结果的 `obClusterId`。 |
| backupTenantName | String | 是 | tenant_a | 备份源租户名称，取自解析结果的 `tenantName`。 |
| backupObTenantId | Long | 否 | 1002 | 备份源租户在 OceanBase 中的租户 ID，取自解析结果的 `obTenantId`。建议传入。 |
| restoreClusterId | Long | 是 | 2001 | 目标集群在当前 OCP 中的集群 ID。注意该字段不是源集群的 `obClusterId`。 |
| obBackupStorageBaseInfo | Object | 是 | - | 数据备份存储信息，应与解析接口使用的存储信息一致。数据结构参见 [解析全局备份信息](2700.parse-global-backup-info.md) 中的 **ObBackupStorageBaseInfo 的数据结构**。 |
| hostIdList | LongArray | 全局恢复必选 | [3001] | 数据备份解析主机 ID 列表，应与解析接口使用的主机一致。 |
| logStorageMode | String | 否 | SAME_AS_DATA | 日志备份存储模式，含义与解析接口相同。`INDEPENDENT` 仅适用于 `PHYSICAL_BACKUP`。建议显式传入。 |
| logBackupStorageBaseInfo | Object | 条件必选 | - | `logStorageMode` 为 `INDEPENDENT` 时必选。 |
| logHostIdList | LongArray | 否 | [3002] | 独立日志备份解析主机 ID 列表。省略或传空数组时复用 `hostIdList`。 |
| restoreEndTime | DateTime | 是 | 2026-09-09T09:30:00+08:00 | 恢复时间，必须位于解析结果的实际可恢复区间内。 |
| restoreTenantInfoParam | Object | 是 | - | 目标租户定义，详情参见 **RestoreTenantInfoParam 的数据结构**。 |
| storageId | Long | 否 | 10 | 当前 OCP 中已有备份存储配置的 ID。应用服务调用时仍应传入完整存储信息。 |
| addSource | Boolean | 否 | false | 是否使用已加载的指定恢复源。全局离线恢复默认值为 `false`。 |

**RestoreTenantInfoParam 的数据结构**

| 参数 | 类型 | 必选 | 示例值 | 描述 |
| --- | --- | --- | --- | --- |
| id | Long | 否 | - | 目标租户 ID。全租户离线恢复时省略。 |
| name | String | 是 | tenant_a_restore | 目标租户名称，不能与目标集群中已有租户重名。必须以字母开头，只能包含字母、数字和下划线，长度为 2～64 个字符。 |
| primaryZone | String | 否 | zone1 | 目标租户的 Primary Zone。 |
| zones | Array | 是 | - | 目标租户的 Zone 和资源池配置，至少传入一个。 |
| ├─ name | String | 是 | zone1 | Zone 名称。 |
| ├─ replicaType | String | 是 | FULL | 副本类型。取值包括 `FULL`、`LOGONLY`、`READONLY` 和 `COLUMNSTORE`。 |
| ├─ resourcePool | Object | 是 | - | 资源池配置。 |
| ├─ resourcePool.unitSpecName | String | 是 | S1 | 当前目标集群中已有的 Unit 规格名称。 |
| ├─ resourcePool.unitCount | Long | 是 | 1 | Unit 数量。 |
| restoreMethod | String | 否 | full | 恢复方式。取值为 `full` 或 `quick`，默认值为 `full`；`quick` 要求 OceanBase 版本不低于 V4.3.3。 |
| enableDynamicPartition | Boolean | 否 | true | 是否开启动态分区，默认值为 `true`；该能力要求 OceanBase 版本不低于 V4.3.5.2。 |

### 解析结果与恢复参数映射

| `/backup/info` 返回字段 | `/backup/restore` 请求字段 | 说明 |
| --- | --- | --- |
| `contents[].clusterName` | `backupClusterName` | 源集群名称。 |
| `contents[].obClusterId` | `backupObClusterId` | 源集群的 OceanBase 集群 ID。物理备份恢复必传。 |
| `contents[].tenantBackupInfos[].tenantName` | `backupTenantName` | 源租户名称。 |
| `contents[].tenantBackupInfos[].obTenantId` | `backupObTenantId` | 源租户的 OceanBase 租户 ID。 |
| `...obRecoverableSectionItems[].backupMode` | `backupMode` | 选择 `RECOVERABLE` 节点对应的备份模式。 |
| `...realRecoverableTimeInterval` | `restoreEndTime` | 在 `startTime` 与 `endTime` 之间选择恢复时间。 |
| 解析请求中的 `obBackupStorageBaseInfo` | 同名字段 | 两次调用使用相同的数据备份存储信息。 |
| 解析请求中的 `hostIdList` | 同名字段 | 两次调用使用能够访问备份存储的当前 OCP 主机。 |
| 解析请求中的日志存储字段 | 同名字段 | 使用独立日志存储时保持配置一致。 |

<main id="notice" type='notice'>
<h4>注意</h4>
<p>不要把解析结果中的 <code>clusterId</code> 当作 <code>restoreClusterId</code>。跨 OCP 离线备份的 <code>clusterId</code> 通常为空；<code>restoreClusterId</code> 应填写目标集群在当前 OCP 中的 ID。</p>
</main>

### 返回结果

**基础数据结构**

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| data | Object | 恢复任务提交结果，详情参见 **BackupCommonResponse 的数据结构**。 |
| successful | Boolean | 请求是否成功。 |
| timestamp | DateTime | 服务端完成请求的时间戳。 |
| duration | Long | 服务端处理请求的时间，单位为毫秒。 |
| status | Integer | 符合 HTTP Status 规范的状态码。 |
| traceId | String | 请求的 Trace ID，用于排查问题。 |
| server | String | 响应请求的 OCP 节点地址。 |

**BackupCommonResponse 的数据结构**

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| obBackupTaskType | String | 任务类型。该接口成功时为 `RESTORE`。 |
| backupObjectOpsResultList | Array | 操作结果列表。 |
| ├─ obBackupObjectList | Array | 操作对象列表，可能为空。 |
| ├─ beSuccessful | Boolean | 是否成功提交该操作。 |
| ├─ taskIdList | LongArray | 恢复任务 ID 列表。 |
| ├─ errorCode | Object | 备份恢复错误码，成功时可能为空。 |
| ├─ hint | String | 提示信息，成功时可能为空。 |

## 示例

### 请求示例

以下示例使用 [解析全局备份信息](2700.parse-global-backup-info.md) 接口解析出的 OSS 物理备份，将 `tenant_a` 恢复到当前 OCP 的目标集群：

`POST /api/v2/backup/restore`

```json
{
  "backupTenantStatus": "OFFLINE",
  "restoreOfflineTenantRequiredParam": {
    "backupMode": "PHYSICAL_BACKUP",
    "backupClusterName": "prod_cluster",
    "backupObClusterId": 1001,
    "backupTenantName": "tenant_a",
    "backupObTenantId": 1002,
    "restoreClusterId": 2001,
    "obBackupStorageBaseInfo": {
      "backupStorageType": "BACKUP_STORAGE_OSS",
      "storageUrl": "example-bucket/obbackup",
      "ossAccessKey": {
        "endpoint": "oss-cn-hangzhou.aliyuncs.com",
        "accessKeyId": "${ACCESS_KEY_ID}",
        "accessKeySecret": "${ACCESS_KEY_SECRET}"
      }
    },
    "hostIdList": [3001],
    "logStorageMode": "SAME_AS_DATA",
    "restoreEndTime": "2026-09-09T09:30:00+08:00",
    "restoreTenantInfoParam": {
      "name": "tenant_a_restore",
      "primaryZone": "zone1",
      "zones": [
        {
          "name": "zone1",
          "replicaType": "FULL",
          "resourcePool": {
            "unitSpecName": "S1",
            "unitCount": 1
          }
        }
      ],
      "restoreMethod": "full",
      "enableDynamicPartition": true
    },
    "addSource": false
  }
}
```

### 返回示例

```json
{
  "data": {
    "obBackupTaskType": "RESTORE",
    "backupObjectOpsResultList": [
      {
        "beSuccessful": true,
        "taskIdList": [4001]
      }
    ]
  },
  "duration": 51,
  "server": "10.0.0.10",
  "status": 200,
  "successful": true,
  "timestamp": "2026-09-09T10:05:00.051+08:00",
  "traceId": "5962f337662d4043"
}
```

## 注意事项

* 两个接口中的存储信息和解析主机应保持一致，否则恢复前校验可能无法复现解析结果。
* `successful=true` 和 HTTP 200 仅表示接口处理成功；恢复接口还需要根据 `taskIdList` 对应的任务状态判断最终结果。
* 解析接口返回的数据备份点、日志备份区间和 `RECOVERABLE` 区间含义不同。提交恢复时应使用 `RECOVERABLE.realRecoverableTimeInterval`，不要只依据单个数据备份点选择时间。
* 对象存储的网络连通性、权限和 Region 配置由调用方环境决定，接口开放本身不会替调用方建立跨环境网络或授权。
