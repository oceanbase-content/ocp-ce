# ob_tenant_log_stream_replica_absent OceanBase 租户日志流缺副本

## 告警描述

<main id="notice" type='explain'>
<h4>说明</h4>
此告警仅针对 V4.0.0.0 及以上版本的 OceanBase 集群生效。
</main>

该告警用于识别租户内日志流（LS）副本数不足的风险场景：当某个日志流的实际副本数小于租户 locality 推导的期望副本数时，判定该日志流处于缺副本状态；当租户内存在任意缺副本日志流时触发告警。

## 告警原理

该告警基于 OCP 采集链路新增指标实现，核心逻辑如下：

1. 从 `DBA_OB_TENANTS` 获取租户的 locality，通过统计 @ 个数推导期望副本数（expected_replica_count）。

2. 从 `CDB_OB_LS` 获取租户内日志流（过滤 creating、create_abort 状态）。

3. 从 `CDB_OB_LS_LOCATIONS` 按 (zone, replica_type) 去重后统计每个日志流实际副本数。

4. 对比 “实际副本数” 与 “期望副本数”，统计租户内缺副本日志流数量，生成采集指标 log_stream_replica_absent_count。

5. 通过表达式 `max(log_stream_replica_absent_count{@LABELS}) by (@GBLABELS)` 生成监控指标 tenant_log_stream_replica_absent_count，并对应告警指标元数据 ob_tenant_log_stream_replica_absent_count。

6. 当表达式 tenant_log_stream_replica_absent_count > 0 持续满足时触发告警。

下表列出了该告警监控逻辑中涉及的关键参数。

| 参数      | 值       |
| --------- | -------- |
| 监控指标 | tenant_log_stream_replica_absent_count，该指标表示租户内缺副本的日志流个数，当数量大于阈值时触发告警。 |
| 监控表达式 | `max(log_stream_replica_absent_count{@LABELS}) by (@GBLABELS)` |
| 采集指标 | log_stream_replica_absent_count |
| 指标来源 | OCP Agent 在 RootService 节点执行 SQL，统计每个租户缺副本日志流个数（log_stream_replica_absent_count）。<br>采集 SQL：```sql
SELECT /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(5000000) */ t.tenant_id, t.tenant_name, COUNT(DISTINCT CASE WHEN (r.replica_count IS NULL OR r.replica_count < t.expected_replica_count) THEN ls.ls_id ELSE NULL END) as cnt FROM (SELECT tenant_id, tenant_name, LENGTH(locality) - LENGTH(REPLACE(locality, '@', '')) as expected_replica_count FROM DBA_OB_TENANTS WHERE tenant_type IN ('SYS', 'USER') AND locality IS NOT NULL) t INNER JOIN CDB_OB_LS ls ON t.tenant_id = ls.tenant_id AND ls.status NOT IN ('creating', 'create_abort') LEFT JOIN (SELECT tenant_id, ls_id, COUNT(DISTINCT CONCAT(zone, ':', replica_type)) as replica_count FROM CDB_OB_LS_LOCATIONS WHERE zone IS NOT NULL AND replica_type IS NOT NULL GROUP BY tenant_id, ls_id) r ON ls.tenant_id = r.tenant_id AND ls.ls_id = r.ls_id GROUP BY t.tenant_id, t.tenant_name``` |
| 采集周期 | 60 秒 |

## 对系统的影响

* 对 OceanBase 租户的影响：日志流副本不足会降低数据高可用冗余能力，故障场景下可能放大服务风险。

* 对 OCP 的影响：OCP 会持续产生该租户维度的风险告警，提示运维侧尽快完成副本恢复。

* 对业务的影响：短期内业务可能仍可用，但在节点/机房异常等场景下容灾能力下降，存在进一步可用性风险。

## 可能原因

* 某些副本节点异常下线或不可达。

* 副本补齐/迁移任务未完成。

* 租户 locality 配置与当前副本分布不匹配。

* Zone 级资源不足导致副本无法按预期创建。

## 处理方法

1. 检查租户 locality 与目标副本策略是否正确。

2. 检查 `CDB_OB_LS_LOCATIONS` 中异常日志流的副本分布，定位缺失副本所在 Zone/节点。

3. 恢复异常节点或补足资源后，执行副本补齐/均衡（如 rebalance）使日志流副本恢复到期望值。

4. 持续观察指标 tenant_log_stream_replica_absent_count，确认恢复为 0 后告警自动消除。
