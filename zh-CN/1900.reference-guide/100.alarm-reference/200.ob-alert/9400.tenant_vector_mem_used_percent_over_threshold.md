# tenant_vector_mem_used_percent_over_threshold Oceanbase 租户向量索引数据实际内存使用百分比超限

## 告警描述

<main id="notice" type='explain'>
<h4>说明</h4>
此告警仅针对 V4.3.5.3 及以上版本的 OceanBase 集群生效。
</main>

该告警表示 OceanBase 集群下，租户向量索引数据实际内存使用百分比超限。

## 告警原理

下表列出了该告警监控逻辑中涉及的关键参数。

| 参数    | 值    |
|---------|-------|
| 监控指标    | ob_tenant_vector_mem_used_percent，该指标表示租户向量索引数据实际内存使用百分比，当指标值大于阈值时触发告警。  |
| 监控表达式  | `100 * sum(ob_tenant_vector_mem_used{@LABELS}) by (@GBLABELS) / sum(ob_tenant_vector_mem_limit{@LABELS}) by (@GBLABELS)` |
| 采集指标    | <li>ob_tenant_vector_mem_used：租户向量索引数据内存使用。</li><li>ob_tenant_vector_mem_limit：租户向量索引数据内存上限。</li> |
| 数据来源    | SQL 采集：`select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ tenant_id,svr_ip,svr_port,vector_mem_hold,vector_mem_used,vector_mem_limit from GV$OB_VECTOR_MEMORY`。<br>该 SQL 运行在每个集群的 sys 租户下，`vector_mem_hold`、`vector_mem_used`、`ector_mem_limit` 依次是内存占用大小、内存使用大小、内存分配上限。 |
| 采集周期    | 5 秒 |

## 规则信息

| 监控指标  | 默认阈值（单位：%）  | 持续时间  | 检测周期  | 消除周期 |
|-----------|---------------------|-----------|-----------|---------|
| ob_tenant_vector_mem_used_percent  | 该指标存在两个默认阈值：<li>ob_tenant_vector_mem_used > 70</li><li>ob_tenant_vector_mem_limit > 85</li>  | 0 秒  | 10 秒  | 5 分钟 |

## 告警信息

| 告警触发方式  | 告警等级  | 范围    |
|---------------|----------|---------|
| 基于监控指标的表达式  | <li>ob_tenant_vector_mem_used > 70：警告</li><li>ob_tenant_vector_mem_limit > 85：严重</li>  | 租户 |

## 告警模板

* **告警概述**

  * 模板：${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:ob_cluster_name=obcluster:ob_cluster_id=4:tenant_name=mysql host=xx.xx.xx.xx OceanBase 租户向量索引数据实际内存使用百分比超限

* **告警详情**

  * 模板：集群：${ob_cluster_name}，租户：${tenant_name}，告警：${alarm_name}。向量索引数据实际使用内存百分比 ${value_shown} 超过 ${alarm_threshold} %。
  * 样例：集群：obcluster，租户：mysql，告警：OceanBase 租户向量索引数据实际内存使用百分比超限。向量索引数据实际使用内存百分比 90% 超过70 %。

* **告警恢复**

  * 模板：告警：${alarm_name}，OceanBase 租户向量索引数据实际内存使用百分比超限：${value_shown}
  * 样例：告警：OceanBase 租户向量索引数据实际内存使用百分比超限，OceanBase 租户向量索引数据内存使用百分比：10%

## 对系统的影响

* 达到或接近 100% 后向量索引无法继续写入，会导致相关表的 insert，对向量的 update 失败。
* 达到或接近 100% 会导致向量查询劣化无法恢复。
* 达到或接近 100% 可能导致向量索引后台异步任务反复重试，消耗 CPU/IO，进一步降低系统性能。

## 可能原因

* 用户使用 HNSW 系列索引，新增数据量超过向量索引内存能支持的规格。
* 用户使用 HNSWSQ 或 HNSWBQ 索引，短时间写入大量增量数据，来不及进行量化压缩。
* 大量向量异步任务同时执行，导致内存暂时升高。

## 处理方法

1. 通过 `INDEX_VECTOR_MEMORY_ESTIMATE` 函数估算内存使用是否合理，函数相关介绍可参考 [INDEX_VECTOR_MEMORY_ESTIMATE](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004479891)。
2. 查询后台并发异步任务数量，相关视图说明可参考 [oceanbase.DBA_OB_VECTOR_INDEX_TASKS](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004478170)。
3. 按照步骤 1、步骤 2 中的结果进行判断，若是租户向量内存配置不合理，则需进行内存扩容；若是后台并发异步任务数量太多，可调整异步任务并发数，相关配置项说明可参考 [vector_index_optimization_concurrency](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000004478805)。
