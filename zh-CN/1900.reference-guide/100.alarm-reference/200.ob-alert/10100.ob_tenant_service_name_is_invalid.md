# ob_tenant_service_name_is_invalid 租户服务名非法

## 告警描述

该告警监测 OceanBase 集群中各租户的服务名（Service Name）状态是否合法。当 OCP 检测到某个租户的服务名状态为 INVALID 并持续一定时间后，上报告警。

租户服务名是 OceanBase V4.2.4.0 版本开始引入的功能，用于标识租户的数据库服务。服务名要求全局唯一，若多个租户（排除同一主备关系内的租户）使用了相同的服务名，则会产生冲突，导致服务名状态变为 INVALID。

## 告警原理

下表列出了该告警监控逻辑中涉及的关键参数。

| 参数 | 值 |
| -------- | --------- |
| 监控指标 | ob_tenant_service_name_status |
| 监控表达式 | `max(ob_tenant_service_name_status{@LABELS}) by (@GBLABELS)` |
| 采集指标 | ob_tenant_service_name_status |
| 指标来源 | OCP 定时任务 CheckAllTenantServiceNameConflictTask 遍历所有租户，检查 MetaDB 中 `ob_tenant` 表的 `service_name` 和 `service_name_status` 字段。租户数据最初从 OceanBase 系统视图 `CDB_OB_SERVICES` 同步而来。 |
| 采集周期 | 60 秒 |

OCP 通过定时任务 `TenantSchedules.syncAllTenantInfo()` 每 60 秒从 OceanBase 集群的 `CDB_OB_SERVICES` 视图同步租户服务名信息到 MetaDB，并通过 `analyzeTenantServiceNameStatus()` 方法分析服务名是否存在冲突，将状态标记为 VALID、INVALID 或 DISABLED。

另一个定时任务 `TenantSchedules.checkAllTenantServiceNameConflict()` 每 60 秒遍历所有租户，对每个已配置服务名的租户判断其状态：

* 若服务名非空且状态为 INVALID，发布指标值 1；

* 否则发布指标值 0。

监控指标 ob_tenant_service_name_status 的值为 1 时，表示该租户的服务名非法，持续 120 秒后触发告警。

## 规则信息

| 监控指标 | 默认阈值 | 持续时间 | 检测周期 | 消除周期 |
| -------- | --------- | --------- | --------- | --------- |
| ob_tenant_service_name_status | 1 | 120 秒 | 60 秒 | 5 分钟 |

## 告警信息

| 告警触发方式 | 告警等级 |  范围 |
| ------------ | ------- | -------- |
|  基于监控指标的表达式 | 严重 | 租户 |

## 告警模板

* **告警概述**
  * 模板：${alarm_target} ${alarm_name}
  * 样例：ob_cluster=obcluster-1:tenant_name=mytenant 租户服务名非法

* **告警详情**
  * 模板：OceanBase 集群 ${ob_cluster_name} 租户 ${tenant_name} 的服务名非法，当前服务名状态为 INVALID，请检查服务名是否存在冲突并尽快修改租户服务名
  * 样例：OceanBase 集群 obcluster-1 租户 mytenant 的服务名非法，当前服务名状态为 INVALID，请检查服务名是否存在冲突并尽快修改租户服务名

其中，${alarm_target} 表示产生告警的对象，格式为 ob_cluster=xxxxxxx:tenant_name=xxxxxxx。

## 对系统的影响

租户服务名处于 INVALID 状态意味着存在服务名冲突，可能导致以下影响：

* 应用程序通过服务名连接数据库时可能路由到错误的租户，造成数据访问异常。

* 在主备切换（Failover/Switchover）场景下，服务名冲突可能导致业务流量无法正确切换到新的主租户。

* OBProxy 或连接管理组件依赖服务名进行路由时，可能出现连接失败或连接到错误实例的问题。

## 可能原因

常见于以下几种情况：

* 主备切换后的服务名冲突：执行 Failover 后，原主租户的服务名未及时置为 INVALID，新主租户与原主租户使用了相同的服务名。OCP 在 Failover 流程中会通过 InvalidTenantServiceNameTask 自动将原主租户的服务名置为 INVALID 并触发告警。

* 手动配置了重复的服务名：管理员在不同集群或不同租户上手动设置了相同的 Service Name，但这些租户不在同一主备关系内。

* 多集群管理下的跨集群冲突：在 OCP 管理的多个集群中，不同集群的租户使用了相同的服务名，OCP 的全局冲突检测标记其为 INVALID。

* 租户同步异常：OCP 与 OceanBase 集群之间的租户信息同步出现延迟或异常，导致服务名状态判断不准确。

## 处理方法

1. 确认告警涉及的租户信息。在 OCP 告警详情中获取集群名（ob_cluster_name）和租户名（tenant_name），定位到具体的租户。

2. 查看服务名冲突详情。登录 OCP，进入对应租户的详情页面，查看当前租户的 Service Name 及其状态。同时检查是否有其他租户使用了相同的 Service Name。也可以在 OceanBase 集群的 sys 租户下执行以下 SQL 查看服务名信息：

   ```sql
   SELECT TENANT_ID, SERVICE_NAME, SERVICE_STATUS FROM CDB_OB_SERVICES;
   ```

3. 检查是否为主备切换导致。

   * 若为 Failover/Switchover 后触发的告警，确认原主租户的服务名是否需要修改。通常需要将原主租户（已降为备租户）的服务名修改为新的唯一名称，或清空其服务名。

   * 可通过以下 SQL 修改租户服务名：

     ```sql
     -- 在 sys 租户下执行
     ALTER SYSTEM MODIFY SERVICE '<old_service_name>' TO '<new_service_name>' TENANT = '<tenant_name>';
     ```

4. 检查是否为手动配置冲突。

   * 若非主备切换场景，排查是否有管理员在不同租户上手动配置了相同的服务名。

   * 修改其中一个租户的服务名，确保所有租户的服务名在 OCP 管理范围内全局唯一（同一主备关系内的租户除外）。

5. 等待告警自动消除。修改服务名后，OCP 会在下一个同步周期（60 秒）重新分析服务名状态。若冲突已消除，service_name_status 将更新为 VALID，指标值恢复为 0。告警将在指标恢复正常后最多 5 分钟（resolve_timeout_seconds: 300）内自动消除。

6. 若以上方法均无法解决，联系 OCP 技术支持人员排查。
