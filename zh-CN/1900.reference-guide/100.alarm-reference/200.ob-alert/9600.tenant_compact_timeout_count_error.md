# tenant_compact_timeout_count_error OceanBase 租户长时间未转储分区（sstable）数

## 告警描述

该告警检测 OceanBase 租户长时间未转储分区（sstable）个数。当存在冻结时间很久没释放的 Frozen Memtable 时，表示 Memtable 无法正常转储或者无法释放。

## 告警原理

Memtable 在冻结时，会为 Frozen Memtable 设置一个 `END_SCN`，这个时间与当时的系统时间较为接近。当这个 Frozen Memtable 转储完成并完成内存释放后，便无法在 `GV$OB_SSTABLES` 视图中观察到。

下表列出了该告警监控逻辑中涉及的关键参数。

|  参数        |  值      |
|--------------|----------|
|  监控指标    |  ob_tenant_compact_timeout_count，该指标表示租户长时间未转储分区（sstable）个数，当数量大于阈值时触发告警。   |
|  监控表达式  |  `sum(ob_tenant_sstable_compact_timeout_count{@LABELS}) by (@GBLABELS)`   |
|  采集指标    |  ob_tenant_sstable_compact_timeout_count   |
|  数据来源    |  SQL 采集：```select /*+ MONITOR_AGENT NO_REWRITE READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(20000000) */ a.tenant_id,b.svr_ip,b.svr_port,count(*) as cnt from DBA_OB_TENANTS a join ( select * from GV$OB_SSTABLES where table_type = 'MEMTABLE' and is_active='NO' ) as b on a.tenant_id = b.tenant_id and (TIMESTAMP_TO_SCN(now()) - end_log_scn) > 1800 * 1000 * 1000 * 1000 group by b.tenant_id,b.svr_ip,b.svr_port```<br>该 SQL 运行在每个集群的 sys 租户下，单个 sstable 转储超过 1800 秒即被统计。   |
|  采集周期    |  5 秒   |

## 对系统的影响

可能导致内存超限，或者 clog 无法正常回收而致使 clog 磁盘爆。

## 可能原因

* 转储任务堆积，转储任务消耗速度不及转储任务添加速度。
* 转储任务执行失败。
* 转储成功但 Memtable 无法释放，与内部逻辑有关。
* 分区不满足转储的条件，比如转储 sstable 个数超限，无法再添加新 sstable。

## 处理方法

* 若转储任务堆积，可参考如下命令添加转储队列线程：

    ```sql
    alter system set compaction_high_thread_score = xxx tenant xxx;
    ```

* 可通过 `V$OB_COMPACTION_DIAGNOSE_INFO` 视图或 `GV$OB_COMPACTION_DIAGNOSE_INFO` 视图查看租户是否存在转储失败的记录，参考命令如下：
  
  ```sql
  select * from oceanbase.GV$OB_COMPACTION_DIAGNOSE_INFO where tenant_id = xxx;
  ```
