# ob_tenant_name_mismatch OceanBase 租户的租户名发生变化

## 告警描述

该告警用于发现 OceanBase 租户在集群中的实际名称与 OCP 元数据库中记录的租户名不一致。当 OCP 同步租户信息时发现某租户在 OceanBase 侧已被重命名，而 OCP 侧仍为旧名称时触发此告警，提示管理员关注并同步租户名。

## 告警模板

* **告警概述**
  * 模板：${alarm_target} ${alarm_name}
  * 样例：ob_cluster=obcluster1:tenant_name=old_tenant:ob_tenant_id=1001 OceanBase 租户的租户名发生变化

* **告警详情**
  * 模板：集群：${ob_cluster_name}，租户：${tenant_name}:${ob_tenant_id}，告警：${alarm_name}。租户 ${tenant_name}:${ob_tenant_id} 的租户名变为 ${actual_tenant_name}。
  * 样例：集群：obcluster1，租户：old_tenant:1001，告警：OceanBase租户的租户名发生变化。租户 old_tenant:1001 的租户名变为 new_tenant。

## 对系统的影响

租户名不一致可能导致：

* OCP 展示的租户名有误：控制台、监控等仍显示旧租户名，与 OceanBase 实际租户名不符，易造成误操作或误判。

* 同步与运维受限：如果租户名不一致，OCP 会跳过租户信息的同步，元信息可能过时，部分依赖租户名的运维或更新可能失败。

## 可能原因

* 在 OceanBase 侧执行了 `ALTER TENANT ... RENAME GLOBAL_NAME TO ...` 等重命名操作，OCP 未随之更新。

* 多环境/多 OCP 管理同一集群时，某一侧单独修改了租户名，导致 OCP 元数据与集群实际不一致。

## 处理方法

1. 确认告警信息：根据告警中的集群名（ob_cluster_name）、OCP 侧租户名（tenant_name）、租户 ID（ob_tenant_id）和实际名称（actual_tenant_name）确认是哪一个租户发生了重命名。

2. 确认是否为预期变更：在 OceanBase 中确认该租户当前名称：

   ```sql
   SELECT tenant_id, tenant_name FROM oceanbase.DBA_OB_TENANTS WHERE tenant_id = <ob_tenant_id>;
   ```

   若 tenant_name 已为 actual_tenant_name，则说明是 OceanBase 侧已改名、OCP 未同步。

3. 在 OCP 控制台该租户的详情/编辑页，将租户名修改为 actual_tenant_name（与 OceanBase 一致），保存后等待下一次同步，告警应能消除。

4. 若希望保留 OCP 侧名称：则需要在 OceanBase 侧将该租户名改回 OCP 中记录的名称（需评估对业务连接串、应用配置的影响），改回后再次同步，告警会消除。

5. 验证：确认 OCP 上该租户名称与 OceanBase 中一致后，告警将在消除周期（300 秒）内自动清除；若仍存在，检查是否有多条历史告警或其它租户也存在名称不一致。
