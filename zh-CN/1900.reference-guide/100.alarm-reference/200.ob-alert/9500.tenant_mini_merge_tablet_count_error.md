# tenant_mini_merge_tablet_count_error OceanBase 租户转储 sstable 个数超限的 tablet 数

## 告警描述

<main id="notice" type='explain'>
<h4>说明</h4>
此告警仅针对 V4.2.0.0 及以上版本的 OceanBase 集群生效。
</main>

该告警检测 OceanBase 租户转储 sstable 个数超限的 tablet 个数。

## 告警原理

OceanBase 存储中每个分区的 sstable 的个数会设置上限，当 sstable 数量超过高水位（默认 56 个）时，便不能添加新的 sstable，由此可能导致不能进行 Mini Compaction。
Minor Compaction 会将满足条件的转储 sstable 进行 Compaction，将多个 sstable 合成一个以此减少 sstable 的数量。因此，当转储 sstable 个数超过告警水位线时，您需关注 Minor Compaction 的执行情况。

下表列出了该告警监控逻辑中涉及的关键参数。

|  参数  |  值   |
|--------|-------|
| 监控指标    |  ob_tenant_mini_merge_tablet_count，该指标表示租户转储 sstable 个数超限的 tablet 数，当数量大于阈值时触发告警。  |
| 监控表达式  |  `sum(ob_tenant_mini_merge_tablet_count{@LABELS}) by (@GBLABELS)`  |
| 采集指标    |  ob_tenant_mini_merge_tablet_count  |
| 数据来源    |  SQL 采集：```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) QUERY_TIMEOUT(20000000) */x.tenant_id,x.svr_ip,x.svr_port,count(*) as cnt from (select tenant_id,svr_ip,svr_port,tablet_id,count(*) as cnt from GV$OB_SSTABLES where  table_type = 'MINOR' or table_type = 'MINI' group by tenant_id,svr_ip,svr_port,tablet_id having cnt >=30) as x where x.cnt >0 group by x.tenant_id,x.svr_ip,x.svr_port```<br>该 SQL 运行在每个集群的 sys 租户下，当租户下每个 tablet 的转储 sstable 个数大于等于 30 时即被统计。  |
| 采集周期    |  5 秒  |

## 对系统的影响

当转储 sstable 个数超过高水位（默认为 56 个）时，便不能添加新 sstable，并导致不能进行 Mini Compaction。后续可能影响 Memtable 转储及释放内存，内存超限则会导致写入限速甚至停写。

## 可能原因

* Minor Compaction 任务队列积压，消耗速度不及任务添加的速度。
* 由于内部某些限制，导致 Minor Compaction 无法调度。

## 处理方法

* 若原因为 Minor Compaction 任务队列积压，可参考如下命令调大租户 Minor Compaction 队列线程：

    ```sql
    alter system set compaction_mid_thread_score = xxx tenant xxx;
    ```

* 若为其它原因，可参考 [SSTable 数量太多的问题排查](https://www.oceanbase.com/knowledge-base/oceanbase-database-1000000000994204?back=kb) 文档进行排查和处理。
