# monitor_exporter_unavaliable 服务器存在监控采集异常

## 告警描述

该告警用于监控 exporter 的采集状态。当监控指标 monitor_exporter_avaliable 的值为 0（不可用）并持续时间达到阈值后，触发告警。

常见 exporter 类型（按主机实际部署服务决定）包括：

* OBServer 监控：`/metrics/node/ob`、`/metrics/ob/basic`、`/metrics/ob/extra`
* OBProxy 监控：`/metrics/node/obproxy`、`/metrics/obproxy`
* 主机监控：`/metrics/node/host`
* Agent 自监控：`:62888/metrics/stat`、`:62889/metrics/stat`
* Binlog/LogProxy 监控：`/metrics/logproxy`、`/metrics/node/logproxy`

示例：

* 若主机同时部署 OBServer + OBProxy，通常会有上述前 4 类 exporter；
* 若主机还部署了 Binlog 服务，会额外增加 LogProxy 相关 exporter。

## 告警原理

ocp_meta 租户的 `ocp_exporter_address` 表记录了每个 exporter 的信息，当 exporter 状态（status 字段）为 inactive 时，可能采集不到监控数据，需要引起关注。

下表列出了该告警监控逻辑中涉及的关键参数。

| 参数       | 值                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| 监控指标   | monitor_exporter_avaliable，该指标表示 exporter 状态是否可用，指标值为 `1` 表示可用；指标值为 `0` 表示不可用，并触发告警。    |
| 监控表达式 | ```min(monitor_exporter_avaliable{@LABELS}) by (@GBLABELS)``` |
| 采集指标   | monitor_exporter_avaliable     |
| 指标来源   | 由 OCP-Server 在 MetaDB 中采集内存中 exporter 的状态，需注意 `ocp_exporter_address` 表中的状态有一定的延迟。   |
| 采集周期   | 5 秒    |

## 规则信息

| 监控指标                   | 默认阈值 | 持续时间 | 检测周期 | 消除周期 |
| -------------------------- | -------- | -------- | -------- | -------- |
| monitor_exporter_avaliable | 0        | 300 秒   | 15 秒    | 5 分钟   |

## 告警信息

| 告警触发方式         | 告警等级 | 范围   |
| -------------------- | -------- | ------ |
| 基于监控指标的表达式 | 警告     | 主机 |

## 告警模板

关于告警触发的消息提醒，您需关注如下注意事项：

* 同一主机下存在多个异常 exporter 时，系统会默认按照主机维度合并为一条告警，您可通过 OCP 系统参数 ocp.alarm.exporter.host-merge.enabled 关闭该合并功能。
* 合并后告警详情中会动态罗列出该主机下异常 exporter 列表、异常开始时间、最近一次告警时间。

* **告警概述**

  * 模板：\${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:host=xxx.xxx.xxx.xxx:exporter=/metrics/obproxy 服务器存在监控采集异常

* **告警详情**（未合并，单 exporter 告警场景）

  * 模板：主机：\${host}，告警：监控 exporter \${exporter_addr}（类型：\${exporter_type}，采集间隔：${scrape_interval} 秒）异常。
  * 样例：主机：xxx.xxx.xxx.xxx，告警：监控 exporter <http://xxx.xxx.xxx.xxx:62889/metrics/ob/basic>（类型：OB_CLUSTER，采集间隔：1> 秒）异常。

* **告警详情**（主机维度合并场景，由系统动态生成）

  * 模板：
    * 主机：\${host}，告警：该主机有 \${exporter_count} 个监控 exporter 异常。
    * 详情：
      * \${exporter_addr}，异常开始时间：\${exporter_start_time}，最近一次告警时间：\${exporter_last_time}
      * \${exporter_addr}，异常开始时间：\${exporter_start_time}，最近一次告警时间：\${exporter_last_time}
      * \${exporter_addr}，异常开始时间：\${exporter_start_time}，最近一次告警时间：\${exporter_last_time}

  * 样例：
    * 主机：xxx.xxx.xxx.xxx，告警：该主机有 3 个监控 exporter 异常。
    * 详情：
      * http://xxx.xxx.xxx.xxx:62889/metrics/ob/basic，异常开始时间：2026-03-30 10:00:00，最近一次告警时间：2026-03-30 10:05:00
      * http://xxx.xxx.xxx.xxx:62889/metrics/obproxy，异常开始时间：2026-03-30 10:01:00，最近一次告警时间：2026-03-30 10:05:00
      * http://xxx.xxx.xxx.xxx:62889/metrics/logproxy，异常开始时间：2026-03-30 10:02:00，最近一次告警时间：2026-03-30 10:05:00

* **告警恢复**

  * 模板：告警：${alarm_name}，监控 exporter 是否正常：\${recover_value}
  * 样例：告警：服务器存在监控采集异常，监控 exporter 是否正常：1

其中，${alarm_target} 为告警对象：

* 合并开启（默认）：按主机聚合，格式为 `alarm_template_id=0:host=<ip>`。
* 合并关闭：按单 exporter 触发，格式为 `alarm_template_id=0:host=<ip>:exporter=<path>`。

## 对系统的影响

OCP 界面无相应的监控数据，无法实时看到系统运行情况，此外监控相关的告警也无法正常上报。

## 可能原因

* 监控采集程序 OCP-Agent 异常，未返回监控数据。

* 网络不通，导致 OCP 无法访问监控地址。

## 处理方法

ocp_exporter_address 表记录了 exporter 的状态，但其状态更新可能延后：如果状态变更为 inactive ， OCP 会减少采集 exporter ，故偶发的 exporter 可不用不会立即更新 ocp_exporter_address 中 exporter 的状态。

1. 可以在故障的机器上请求 unix-socket 接口来确认是否可以访问 exporter 。

   ```shell
   sudo curl -s --unix-socket /home/admin/ocp_agent/run/ocp_monagent.$(cat /home/admin/ocp_agent/run/ocp_monagent.pid).sock http://unix-socket-server/metrics/ob/basic
   ```

2. 排除 OCP 到故障机器的网络原因：在 OCP 机器上执行如下命令确认监控采集地址 exporter 是否可以访问。

   ```shell
   curl http://xxx.xxx.xxx.xxx:62889/metrics/ob/basic
   ```

   * 不可以访问，则可能是网络问题。

     可参考 [网络故障排查](../500.appendix/300.network-troubleshooting.md) 自行排查网络是否故障，确保 OCP 与该机器之间的网络是连通的。

   * 可以访问，则是采集进程 OCP-Agent 出现故障。

     可参考 [OCP-Agent 运维脚本](../../../850.host-features/100.manage-a-host/900.ocp-agent-o-m-scripts.md) 排查并解决。
