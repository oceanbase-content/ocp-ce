# host_process_cpu_bind_core_is_invalid CPU 绑核配置不一致

## 告警描述

该告警监测主机上 OBServer 或 OBProxy 进程的 CPU 绑核配置是否与 OCP 元数据库中记录的绑核配置一致，当两者不一致时触发告警。

## 告警原理

| 参数     | 值      |
| -------- | -------- |
| 监控指标 | host_process_cpu_bind_core_alarm_status |
| 监控表达式 | `max(host_process_cpu_bind_core_alarm_status{@LABELS}) by (@GBLABELS)` |
| 采集指标 | host_process_cpu_bind_core_alarm_status  |
| 指标来源 | OCP 主动检测 |
| 采集周期 | 60 秒 |

OCP 定时对主机上的 OBServer/OBProxy 进程进行绑核配置一致性检查。具体原理如下：

1. OCP 从元数据库中获取该主机上所有已配置的 CPU 绑核信息（CpuBindCoreConfigEntity）和对应的服务器状态信息（CpuBindCoreServerStateEntity）。

2. 对于每一条绑核配置，OCP 通过 OCP-Agent 实际进程当前查询的 CPU 绑核范围（通过进程 PID 调用 `taskset -pc pid` 命令获取）。

3. 将实际绑核范围与元数据库中记录的期望绑核范围进行对比。

4. 如果实际范围与期望范围不一致，则将指标 host_process_cpu_bind_core_alarm_status 设为 1（告警状态）；否则设为 0（正常状态）。

当指标值等于 1 时，满足触发条件，产生告警。

## 规则信息

| 监控指标 | 默认阈值 | 持续时间 | 检测周期 | 消除周期 |
| ---------- | ------- | -------- | -------- | -------- |
| host_process_cpu_bind_core_alarm_status  | 1 | 120 秒 | 60 秒 | 5 分钟 |

## 告警信息

| 告警触发方式 |  告警等级 |  范围 |
| ------------ | -------- |-------|
| 基于监控指标的表达式 | 警告 | 主机 |

## 告警模板

* **告警概述**
  * 模板：${alarm_target} ${alarm_name}
  * 样例：ob_cluster=-1:svr_ip=xxx.xxx.xxx.xxx OceanBase CPU 绑核配置不一致

* **告警详情**
  * 模板：集群 ID: ${ob_cluster_id}，主机 IP：${host_ip}，当前绑核配置不一致，请检查主机 CPU 绑核配置信息并尽快修改 CPU 绑核配置信息
  * 样例：集群 ID: -1，主机 IP：xxx.xxx.xxx.xxx，当前绑核配置不一致，请检查主机 CPU 绑核配置信息并尽快修改 CPU 绑核配置信息

* **告警恢复**
  * 模板：告警：${alarm_name}，CPU 绑核配置不一致：${value_shown}
  * 样例：告警：CPU 绑核配置不一致，CPU 绑核配置不一致：0

## 对系统的影响

CPU 绑核配置不一致意味着进程实际使用的 CPU 核心与预期规划不符，可能造成以下影响：

* 资源争用：多个进程可能共享相同的 CPU 核心，导致互相竞争 CPU 资源，影响性能稳定性。

* 性能下降：进程未绑定到预期的 CPU 核心，可能导致 NUMA 跨节点访存，增加延迟。

* 隔离性降低：CPU 绑核的核心目的是实现资源隔离，配置不一致将导致隔离策略失效。

## 可能原因

* 主机上的进程被手动重启，重启后绑核配置未生效或未正确重新绑定。

* taskset 配置被手动修改。

## 处理方法

1. 确认告警信息：根据告警中的集群 ID（ob_cluster_id）和主机 IP（svr_ip）定位到具体的主机和进程。

2. 检查当前绑核配置：

   ```bash
   # 查看 observer 进程的绑核信息，obproxy 进程的查询方式与此类似
   ps -ef | grep observer
   taskset -pc <observer_pid>
   ```

3. 对比期望配置：在 OCP 控制台中查看该主机对应进程的 CPU 绑核配置，与实际查到的绑核范围进行对比，确认不一致的具体内容。

4. 修复绑核配置：

   * 方式一（推荐）：通过 OCP 控制台重新下发 CPU 绑核配置，OCP 会通过 OCP-Agent 自动完成绑核操作。

   * 方式二：在主机上手动使用 taskset 命令重新绑定 CPU 核心：

     ```bash
     taskset -pc <cpu_range> <PID>
     ```

5. 验证修复结果：修复后等待下一个检测周期（60 秒），观察告警是否自动消除。如果配置已一致，告警将在消除周期（300 秒）内自动清除。
