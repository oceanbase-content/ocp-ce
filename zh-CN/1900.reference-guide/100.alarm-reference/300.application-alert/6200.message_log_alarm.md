# message_log_alarm 系统 message 日志

## 告警描述

该告警用于监控主机上的系统 message 日志（通常为 Linux 的 `/var/log/messages` 或 journal 中的内核/系统消息）。默认规则在日志中匹配到 NVMe 超时相关内核消息（如 `kernel: nvme.*timeout`）时触发，用于提示管理员主机可能存在 NVMe 盘或驱动异常。

## 告警原理

| 参数 | 值 |
| -------- | -------- |
| 监控指标 | host_message_log / os_message_log（日志型） |
| 监控表达式 | `{"excludeKeywords":{"relation":"Or","keywords":[]},"includeKeywords":{"relation":"Or","keywords":["kernel: nvme.*timeout"]},"logLevels":[],"metric":"os_message_log"}` |
| 采集指标 | 系统 message 日志（server_type 对应 kern / os_message_log） |
| 指标来源 | OCP-Agent 采集主机系统/内核日志   |
| 采集周期 | 无，日志产生即评估。   |

该告警为日志型（Log）告警，在主机侧由日志采集与告警过滤完成。流程简述如下：

1. 日志采集：OCP-Agent 在主机上采集系统 message 日志（如 `/var/log/messages` 或通过 journal 等），并为每条日志打上对应 server_type（如与 os_message_log 对应的 kern）、filename 等标签。

2. 告警过滤：OCP 下发的告警规则中包含 message_log_alarm 的 Log 表达式，默认配置为 `metric: "os_message_log"`、`includeKeywords: ["kernel: nvme.*timeout"]`、`logLevels: []`（不按日志级别过滤）。

3. 匹配即告警：当某条系统日志内容匹配包含关键字（默认即 NVMe 超时相关）时，构造告警并上报 OCP，告警类型为 message_log_alarm，并携带集群、主机、日志类型、文件名、关键字、错误码、日志内容等标签。

默认规则：仅按包含关键字匹配，不限制日志级别；默认关键字为正则 `*kernel: nvme.timeout`，用于识别内核输出的 NVMe 超时类消息。

## 规则信息

| 监控指标  | 默认阈值  | 持续时间  | 检测周期  | 消除周期  |
|-----------|----------|------------|----------|----------|
| host_message_log / os_message_log（日志型）  | N/A  | N/A  | N/A  | 5 分钟  |

## 告警信息

| 告警触发方式  | 告警等级  | 范围  |
|---------------|----------|-------|
| 日志匹配规则  | 严重  | 主机  |

## 告警模板

* **告警概述**

  * **模板**：${alarm_target} ${alarm_name}
  * **样例**：ob_cluster=obcluster1:host=xxx.xxx.xxx.xxx 系统 message 日志

* **告警详情**

  * **模板**：[${alarm_name}] 集群：${ob_cluster_name}，主机：${host}，日志类型：${server_type}，日志文件：${filename}，日志级别：${log_level}，关键字=${keyword}，错误码=${error_code}，日志详情=${error_message}。
  * **样例**：[系统 message 日志] 集群：obcluster1，主机：xxx.xxx.xxx.xxx，日志类型：kern，日志文件：/var/log/messages，日志级别：，关键字=kernel: nvme.*timeout，错误码=，日志详情=kernel: nvme0n1: I/O 0xffff... timeout。

* **告警恢复**

  * **模板**：告警：${alarm_name}，系统 message 日志 ${value_shown}
  * **样例**：告警：系统 message 日志，系统 message 日志 已恢复

## 对系统的影响

系统 message 中出现 NVMe 超时类日志通常表示：

* **NVMe 设备或链路异常**：盘或控制器响应超时，可能导致 I/O 延迟升高、超时错误或掉盘。
* **存储稳定性风险**：若持续出现，可能发展为掉盘、RAID 降级或数据不可用。
* **对数据库的影响**：若 OceanBase 数据或日志位于该 NVMe 上，可能引发实例卡顿、日志写失败或宕机。

## 可能原因

1. NVMe 盘故障或者 PCIe 链路不稳定。
2. 主机负载或 I/O 压力过大导致偶发超时。

## 处理方法

1. **确认告警内容**：根据告警中的主机、filename、keyword、error_message 定位到具体主机和日志行（如 `/var/log/messages` 或 journal）。

2. **查看主机系统日志**：登录告警主机，查看系统/内核日志中的 NVMe 相关记录。

   ```bash
   grep -i nvme /var/log/messages
   # 或
   journalctl -k | grep -i nvme
   dmesg | grep -i nvme
   ```

3. **确认涉及设备**：从日志中确认超时对应的设备名（如 nvme0n1、nvme1n1），并查看块设备与挂载点。

   ```bash
   lsblk
   nvme list
   ```

4. **硬件与驱动排查**：检查该 NVMe 设备状态。

5. **业务与存储隔离**：若确认为问题盘，在业务允许的情况下将 OceanBase 数据/日志迁移到其他盘，或更换/下线该盘后再观察告警是否消失。

6. （可选）**调整规则**：若需监控其他系统 message 内容，可在 OCP 告警规则中修改 message_log_alarm 的 includeKeywords 或 excludeKeywords；若需忽略部分 NVMe 相关告警，可增加排除关键字。

7. **验证**：问题消除且不再产生匹配日志后，告警会在消除周期（5 分钟）内自动清除。
