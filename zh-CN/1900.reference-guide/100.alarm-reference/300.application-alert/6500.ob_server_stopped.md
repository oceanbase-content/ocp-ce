# ob_server_stopped 服务器停止服务

## 告警描述

该告警监测 OceanBase 集群中 OBServer 节点是否处于停止服务（stopped）状态。当 OBServer 的 stop_time 不为空（即执行过 `STOP SERVER` 操作），且停服时长大于 0 秒时触发告警。

## 告警原理

| 参数 | 值 |
| -------- | --------- |
| 监控指标 | ob_server_stopped_duration_seconds |
| 监控表达式 | `max(ob_server_stopped_duration_seconds{@LABELS}) by (@GBLABELS)` |
| 采集指标 | ob_server_stopped_duration_seconds |
| 指标来源 | OCP-Agent 采集自 OBServer 内部视图 |
| 采集周期 | N/A |

OCP-Agent 通过 SQL 定期查询 OBServer 的服务状态，具体原理如下：

1. 对于 OceanBase V4.0 以下版本，OCP-Agent 查询 `__all_server` 视图，通过 stop_time 字段计算停服时长：当 stop_time 为 0 时指标值为 0；否则指标值为（当前时间 - stop_time）的秒数。

2. 对于 OceanBase V4.0 及以上版本，OCP-Agent 查询 `DBA_OB_SERVERS` 视图，通过 STOP_TIME 字段计算停服时长：当 STOP_TIME 为 NULL 时指标值为 0；否则指标值为当前时间与 STOP_TIME 的秒级差值。

3. 同时采集 status 字段作为标签，反映 OBServer 当前的运行状态。

当指标值 ob_server_stopped_duration_seconds > 0 时，满足触发条件，产生告警。

## 规则信息

| 监控指标 | 默认阈值 | 持续时间 | 检测周期 | 消除周期 |
| ---------- | -------- | -------- | -------- | -------- |
| ob_server_stopped_duration_seconds  | 0 | 60 秒 | 10 秒 | 300 秒 |

## 告警信息

| 告警触发方式 | 告警等级 | 范围 |
| ------------ | ------- | -------- |
| 基于监控指标的表达式 | 停服  | 主机  |

## 对系统的影响

OBServer 停止服务意味着该节点不再对外提供数据库服务，可能造成以下影响：

* 服务中断：该节点上承载的 Leader 副本需要进行选举切换，切换期间相关分区短暂不可用。

* 可用性降低：集群中可用节点减少，如果多个节点同时停服，可能无法形成 Paxos 多数派，导致集群整体不可用。

* 负载不均衡：停服节点上的流量被转移到其他节点，可能导致剩余节点负载升高。

## 可能原因

* 运维人员主动执行了 `ALTER SYSTEM STOP SERVER` 操作（如计划内维护、节点隔离）。

* 通过 OCP 控制台对节点执行了停止操作。

* OBServer 进程异常退出后状态被标记为 stopped。

## 处理方法

1. 确认停服原因：确认该节点是否为计划内维护导致的停服。如果是计划内操作，可忽略此告警，待维护完成后恢复服务即可。

2. 检查节点状态：通过 SQL 查看集群中各节点状态：

   ```sql
   SELECT SVR_IP, SVR_PORT, ZONE, STATUS, START_SERVICE_TIME, STOP_TIME
   FROM oceanbase.DBA_OB_SERVERS;
   ```

3. 恢复节点服务：

   * 方式一（推荐）：通过 OCP 控制台对该节点执行启动服务操作。

   * 方式二：通过 SQL 命令启动节点：

     ```sql
     ALTER SYSTEM START SERVER 'xxx.xxx.xxx.xxx:2882';
     ```

4. 检查节点健康状况：恢复服务前，确认节点的 observer 进程正常运行、网络连通性正常、日志同步无延迟：

   ```bash
   ps -ef | grep observer
   ```

   ```sql
   SELECT SVR_IP, ROLE, SCN_TO_TIMESTAMP(END_SCN)
   FROM oceanbase.GV$OB_LOG_STAT WHERE TENANT_ID = 1 ORDER BY LS_ID, ROLE;
   ```

5. 验证修复结果：恢复服务后，确认节点 STATUS 变为 ACTIVE，告警将在消除周期（300 秒）内自动清除。
