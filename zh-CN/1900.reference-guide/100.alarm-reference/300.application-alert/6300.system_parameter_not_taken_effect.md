# system_parameter_not_taken_effect 系统参数修改后需要重启生效

## 告警描述

OCP 部分系统参数在修改后需要重启 OCP 才能生效，当 OCP 定时巡检发现某些标记为 “需要重启” 的参数已被修改但未进行重启时，触发此告警，提醒管理员重启 OCP 服务以使参数生效。

## 告警原理

| 参数 | 值 |
| -------- | ---------- |
| 监控指标 | N/A   |
| 监控表达式 | N/A |
| 采集指标 | N/A |
| 指标来源 | OCP 应用内部事件 |
| 采集周期 | N/A |

OCP 启动时会加载系统参数到内存中（系统参数修改时只会修改数据库的值，而不修改内存值），同时 OCP 内部会启动一个定时巡检任务，筛选出内存中标记为 “需要重启”（`needRestart() == true`）的参数和数据库进行对比，如果存在不一致的参数，说明有参数已修改但未重启生效，构造该告警事件。

## 告警模板

* **告警概述**
  * 模板：${alarm_target} ${alarm_name}
  * 样例：svr_ip=xxx.xxx.xxx.xxx 系统参数修改后需要重启生效

* **告警详情**
  * 模板：服务器：${host}，告警：系统参数修改后需要重启生效，参数名：${system_parameter}。
  * 样例：服务器：xxx.xxx.xxx.xxx，告警：系统参数修改后需要重启生效，参数名：[ocp.site.url, server.port]。

## 对系统的影响

系统参数修改后未重启生效，可能造成以下影响：

* 配置不一致：数据库中记录的配置值与实际运行值不同，可能导致运维人员对系统行为产生误判。

* 预期功能未生效：部分需要重启才能生效的参数（如端口号、站点 URL 等）未按预期工作，影响系统功能。

## 原因

* 管理员通过 OCP 控制台或 API 修改了需要重启才能生效的系统参数，但尚未重启 OCP 服务。

* 批量修改系统参数后遗漏了重启操作。

## 处理方法

1. 确认告警信息：根据告警中的服务器 IP（host）和参数名（system_parameter）定位到待生效的参数。

2. 确认参数变更：在 OCP 控制台的系统参数管理页面确认哪些参数已修改但未生效，评估是否需要立即重启。

3. 重启 OCP 服务：选择合适的时间窗口（建议在业务低峰期）重启对应 OCP 节点的服务，使参数生效：如果是多节点部署，需逐一重启所有 OCP 节点。

4. 验证修复结果：重启完成后，确认参数已按预期生效。告警将在消除周期（300 秒）内自动清除。
