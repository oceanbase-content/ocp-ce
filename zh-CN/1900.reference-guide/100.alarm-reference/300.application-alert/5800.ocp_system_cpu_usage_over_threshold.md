# ocp_system_cpu_usage_over_threshold OCP 节点 CPU 使用率超限

## 告警描述

该告警表示 OCP 节点 CPU 使用率超限。

## 告警原理

下表列出了该告警监控逻辑中涉及的关键参数。

| 参数  | 值  |
|--------|-------|
| 监控指标   | ocp_system_cpu_usage，该指标表示 OCP 节点 CPU 使用率，当使用率大于阈值时触发告警。  |
| 监控表达式  | 100 * sum(system_cpu_usage{@LABELS}) by (@GBLABELS)   |
| 采集指标   | system_cpu_usage |
| 指标来源   | OCP 进程使用 spring-boot-starter-actuator 组件收集 CPU 数据，该指标通常通过操作系统提供的工具或库（例如，在 Linux 上使用 `uptime` 命令或读取 `/proc/stat` 文件）来获取。|
| 采集周期   | 5 秒   |

## 规则信息

| 监控指标  | 默认阈值（单位：%）  | 持续时间  | 检测周期  | 消除周期  |
|-----------|----------------------|-----------|-----------|----------|
| ocp_system_cpu_usage  | 该指标存在两个默认阈值：<li>ocp_system_cpu_usage > 90</li><li>ocp_system_cpu_usage > 80</li>  | 60 秒  | 10 秒  | 5 分钟  |

## 告警信息

| 告警触发方式  | 告警等级  | 范围  |
|---------------|-----------|-------|
| 基于监控指标的表达式  | <li>ocp_system_cpu_usage > 90：严重</li><li>ocp_system_cpu_usage > 80：警告</li> | 服务  |

## 告警模板

* **告警概述**

  * 模板：${alarm_target} ${alarm_name}
  * 样例：alarm_template_id=0:svr_ip=xx.xx.xx.xx:svr_port=8080 OCP 节点 CPU 使用率超限

* **告警详情**

  * 模板：告警：${alarm_name}，CPU 百分比 ${value_shown} 超过 ${alarm_threshold} %。
  * 样例：告警：OCP 节点 CPU 使用率超限，CPU 百分比 99 % 超过 95 %。

* **告警恢复**

  * 模板：告警：${alarm_name}，OCP 节点 CPU 使用率超限：${value_shown}
  * 样例：告警：OCP 节点 CPU 使用率超限，OCP 节点 CPU 使用率超限：10 %

## 对系统的影响

OCP 节点 CPU 超过一定限制，会导致系统在处理其它正常请求时耗时较久，并可能导致请求失败，影响用户的正常使用。

## 可能原因

* OCP 缩容导致 CPU 使用率飙升。
* 修改了参数管理中的某些参数，导致 OCP 监控采集、告警检测、备份恢复、集群运维等操作占用 CPU 过多。

## 处理方法

1. 登录 OCP，在左侧导航栏选择 **系统管理** > **平台监控**，查看 OCP 平台的性能监控和 HTTP 请求监控，观察内存、磁盘、系统负载等相关性能指标知否正常。
2. 在 OCP 宿主机执行 `top` 命令，查看 CPU 占用率，可尝试从机器、网络层面定位问题。
3. 为 OCP 增加 CPU 资源，重启 OCP 后观察是否恢复。
