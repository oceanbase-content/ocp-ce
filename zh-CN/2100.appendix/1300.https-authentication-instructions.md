# HTTPS 认证说明

OCP 支持通过白屏功能将 OCP 监控集成到 Prometheus 中。但需注意的是，OCP 与 Prometheus 的认证方式需保持一致，若 OCP 的认证方式为 HTTPS，Prometheus 的认证方式也必须为 HTTPS。

本节将为您介绍如何为 OCP 与 Prometheus 添加 HTTPS 认证。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>HTTPS 认证方式比较繁琐，非必要不建议使用。</p>
</main>

## Prometheus 添加 TLS

详情可参考 Prometheus 官网说明：[https://prometheus.ac.cn/docs/guides/tls-encryption/](https://prometheus.ac.cn/docs/guides/tls-encryption/)

在为 Prometheus 配置 TLS 加密时，您需注意如下几点：

1. 生成的 `prometheus.crt`、`prometheus.key`、`prometheus-ca.pem` 需要注册到 Prometheus 中。

2. `web.yml` 文件添加以下配置（`/etc/` 为 Docker 容器内部的路径）：

   ```yaml
   tls_server_config:
     cert_file: /etc/prometheus/prometheus.crt
     key_file: /etc/prometheus/prometheus.key
   ```

3. 在 Docker 启动命令中添加以下参数：

   ```bash
   -v /home/admin/docker/prometheus/prometheus.crt:/etc/prometheus/prometheus.crt
   -v /home/admin/docker/prometheus/prometheus.key:/etc/prometheus/prometheus.key
   ```

## OCP 添加 TLS

登录 OCP，在系统参数中修改 `ocp.site.url` 为 `https://ip:port`。

## OCP 如何添加 Prometheus 的证书

1. 在任意能连接的 Prometheus 服务器上执行如下命令，导出服务器证书，其中 `IP:9090` 为 Prometheus 地址：

   ```bash
   openssl s_client -connect IP:9090 -servername IP </dev/null 2>/dev/null | openssl x509 -out /tmp/prometheus-server.pem
   ```

2. 将服务器证书导入到运行 OCP JDK 的 `cacerts` 中，其中路径、密码按实际情况进行修改，默认密码多为 `changeit`：

   ```bash
   keytool -importcert -noprompt -alias prometheus-61315353-9090 -file /tmp/prometheus-server.pem -cacerts -storepass changeit
   ```

3. 验证证书是否导入成功：

   ```bash
   keytool -list -cacerts -storepass changeit | grep prometheus
   ```

4. 重启 OCP 容器，即可在外部集成中使用 `https://` 形式访问 Prometheus。

## Prometheus 如何添加 OCP 的证书

### 步骤一：确认 OCP HTTPS 8443 端口的证书类型

在可以访问 OCP 的服务器上执行如下命令：

```bash
openssl s_client -connect $OCP_IP:8443 -servername $OCP_IP </dev/null 2>/dev/null | openssl x509 -noout -issuer -subject -dates
```

查看 `Issuer`，确保 Prometheus 的 `ca_file` 文件中包含该 Issuer 的公钥证书（包括第三方 CA 颁发的证书和自签名证书）。

将服务器证书进行保存，以便于对比：

```bash
openssl s_client -connect $OCP_IP:8443 -servername $OCP_IP </dev/null 2>/dev/null | openssl x509 > /tmp/ocp-8443-cert.pem
```

### 步骤二：将自签名/单文件存放进 ca_file

若 OCP 为自签名证书（Issuer 与 Subject 是同一套 DN），则 `ca_file` 中应包含这张服务器证书的 PEM（与 `/tmp/ocp-8443-cert.pem` 内容一致即可），例如：

```bash
cp /tmp/ocp-8443-cert.pem /path/on/prometheus/ocp-for-prometheus-ca.pem
```

您需在 `prometheus.yml` 中进行如下配置：

```yaml
tls_config:
  ca_file: /path/on/prometheus/ocp-for-prometheus-ca.pem
```

<main id="notice" type='notice'>
<h4>注意</h4>
<p>请勿将其它机器的 CA、或 Prometheus 自身的证书添加到 <code>prometheus.yml</code> 中，否则将会报错 <code>unknown authority</code>。</p>
</main>

### 步骤三：将 OCP 证书同步至 Docker

在 Docker 中执行如下命令：

```bash
-v /home/admin/docker/prometheus/ocp-for-prometheus-ca.pem:/etc/prometheus/ocp-for-prometheus-ca.pem
```

启动 Docker 后，请注意观察 Prometheus 日志，如果出现 OCP 访问失败，那代表 OCP 证书仍存在问题。

### 步骤四：临时跳过 OCP TLS 认证

在 `prometheus.yml` 中添加 `insecure_skip_verify: true`，并重启 Prometheus 服务：

```yaml
scrape_configs:
  - job_name: 'ocp_sd'
    scheme: 'http'
    fallback_scrape_protocol: "PrometheusText1.0.0"
    tls_config:
      insecure_skip_verify: true
      # ca_file: /etc/prometheus/ocp-for-prometheus-ca.pem
    http_sd_configs:
      - url: 'https://xx.xx.xx.xx:8080/api/v2/monitor/prometheus_sd'
        tls_config:
          insecure_skip_verify: true
        basic_auth:  # 访问 OCP 获取 prometheus_sd 中所有 target
          username: "******"
          password: "******"
    basic_auth:  # 控制访问所有 Target
      username: "******"
      password: "******"
```

## 常见问题

**启动后发现 OCP 的 Prometheus 端口仍无法访问，如何解决？**

该问题产生的原因是 OCP 与 OCP-Agent 支持的传输协议不同，OCP 支持了 HTTPS 认证方式，但是 OCP-Agent 仅支持 HTTP 认证方式。您可参考如下临时方案，在 `prometheus.yml` 中单独添加一个 job 进行解决：

```yaml
- job_name: 'ocp_self'
  scheme: 'https'
  fallback_scrape_protocol: "PrometheusText1.0.0"  # prometheus 3.x 才有这个参数，2.x 的时候注意删除这个参数
  metrics_path: '/api/v2/actuator/prometheus'
  tls_config:
    insecure_skip_verify: true
  static_configs:
    - targets: ['xx.xx.xx.xx:8443']  #这里是 OCP 的 TLS 地址
  basic_auth:
    username: "******"
    password: "******"
