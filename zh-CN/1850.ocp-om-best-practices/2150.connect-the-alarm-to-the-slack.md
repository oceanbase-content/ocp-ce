# 将告警对接到 Slack 群聊

您可使用 Slack 群聊接收告警消息，通过机器人发送消息到 Slack 群，所有群成员都可以看到告警消息。

## 应用场景

OCP 的告警消息会推送给 Slack 群中的机器人，由机器人将告警消息发送到群里。对接 Slack 机器人只需提供 Slack 机器人的 Webhook 地址即可。同时，您可使用部分增强功能，如：定义消息 markdown 格式，可以对告警名加粗、告警信息按列表展示等。

## 前提条件

* 请确保当前登录 OCP 的用户具备如下权限：

  * **集群维护**、**租户维护**、**OBProxy 维护**、**仲裁服务维护**、**Binlog 服务维护** 或 **主机维护** 任一资源权限。
  * 告警中心 **全部** 菜单权限。

* 已创建 Slack 群聊，并且添加 Webhook，添加到 Slack 对应群聊中。

* 获取到 Webhook 后需确保网络畅通，可参考如下命令发送一条测试消息：

  ```bash
  # YOU_WEBHOOK_URL_HERE：在 Webhook 生成链接，例如：https://hooks.slack.com/services/XXX/XXX/XXX
  curl -X POST -H 'Content-type: application/json' --data '{"text":"Hello, World!"}' YOU_WEBHOOK_URL_HERE
  ```

  收到的消息结果如下：

  ![测试消息效果](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/01261415.png)

## 注意事项

Slack 消息的长度限制通常约为 3000 字符，无明确官方频率限制，但会存在平台级限流，建议在 OCP 告警通道中打开聚合配置，多条消息聚合一条消息发送。

## 操作步骤

1. 在左侧导航栏中，单击 **告警中心**。

2. 在告警中心页面，单击 **告警通道**。

3. 在告警通道页签下，单击 **新建通道**。

4. 配置 Slack 告警通道。

   1. 基本配置。

      | 选择项 | 是否必选 | 描述 |
      |--------|----------|------|
      | 通道类型     | 是 | 下拉选择 **Slack**。 |
      | 通道名       | 是 | 自定义通道名称，方便后续识别。 |
      | Webhook 地址 | 是 | Slack 机器人的访问地址，获取方式请参见 [创建 Slack 群聊并获取 Webhook 地址](../2100.appendix/1100.create-a-slack-group-chat.md)。 |

   2. 消息配置。

      1. 选择告警消息格式，支持 **文本** 和 **Json** 两种格式。

      2. 根据实际所需，对告警消息进行个性化配置。

         1. 配置告警 **消息模板**，系统所推送的消息将依照您所配置的模板样式进行展示。
         2. 在 **重复告警配置** 中，为相同告警设置发送次数和时间间隔，用于控制同一个告警是否重复发送告警消息以及告警消息的发送频率。其中，告警时间间隔默认为 600 秒，最小取值为 300 秒，所配置的值需大于或等于告警规则中的检测周期。
         3. 选择是否开启 **告警消息聚合** 功能。开启消息聚合，可以避免一段时间内告警发送过多，导致重要消息被淹没。开启告警消息聚合后，系统将依照您所配置的模板样式及间隔发送告警消息。

      3. 根据实际所需，对恢复消息进行个性化配置。
         1. 配置告警 **消息模板**，系统所推送的消息将依照您所配置的模板样式进行展示。
         2. 选择是否开启 **恢复消息聚合** 功能。开启消息聚合，可以避免一段时间内恢复消息发送过多，导致重要消息被淹没。开启恢复消息聚合后，系统将依照您所配置的模板样式及间隔发送恢复消息。

5. 单击 **发送测试消息**，测试当前配置的告警通道是否可以成功发送告警消息。
6. 若测试消息发送成功，单击 **提交**，完成配置。

## 常见问题

### 消息限流

**如何处理被限流导致消息发送失败，关键字如：“由于活动数量很大，我们不会显示来自此传入 webhook 集成的一些消息。”，英文类似："Due to high activity, we will not display some messages from this incoming webhook integration."）。**

Slack 消息的长度限制通常约为 3000 字符，无明确官方频率限制，但会存在平台级限流。限流后所有发往 Slack 的消息都会失败，存在一定的隐患，解决方法：

* **告警通道开启聚合功能**：同类告警、相同告警在聚合周期内只发送一次告警。
* **推送限流**：OCP 推送设置中提供了限流策略，支持按天、小时进行限流（限流维度为推送配置+告警通道）。
* **黑屏调整**：修改 `ocp.alarm.event.resend-interval-seconds` 系统配置，默认 3 分钟产生一次告警事件。

以上步骤可以有效减少告警消息数量，降低告警被限流的可能性；但是瞬时产生大量不同告警可能会被限流。

### 网络不通

**如何处理用户环境不能直接访问 Slack API 的问题？**

首先通过 curl 测试是否能发送测试消息，如果网络不通，需要调试下 OCP 和 Webhook 链接之间的连通性。

### 升级迁移

**升级或者迁移后，如何更新告警推送？**

Slack Webhook 是一种新增的告警推送，理论上不需要对 HTTP、脚本、钉钉等通道做什么操作，如果需要切换到 Slack 通道，直接新增即可。

### Response 校验信息失败

**如何解决 Response 校验信息失败？**

设置 Response 校验信息失败是为了防止脚本编写不规范导致用户收不到告警、漏发告警等问题。要求告警脚本里输出有且仅有一次有效信息（可以是 API 响应码，也可以是 API 响应体），OCP 来校验信息是否匹配，支持正则匹配、json 键值对匹配。

Slack 机器人 API 返回的为 json 内容，故应使用 json 键值对匹配。Slack 群消息通道的 Response 校验信息应设置为：`ok`，脚本通道中不应输出除 Response 外的其他内容（如 curl 命令应加上 `-s` 参数防止输出进度信息）。
