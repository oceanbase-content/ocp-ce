# 标准运维流程概述

标准运维流程（Standard Operating Procedure，SOP）是 OCP 提供的标准化故障恢复与数据重建功能。针对 OceanBase 数据库运维中常见的复杂操作场景，SOP 将多步骤的运维流程编排为标准化的任务模板，支持自动执行与手动触发相结合的混合模式，帮助您安全、高效地完成故障恢复操作。

<main id="notice" type='notice'>
<h4>功能适用性</h4>
<p>该内容仅适用于 OCP 企业版，OCP 社区版不提供此功能。</p>
</main>

## 权限说明

SOP 权限不通过角色配置中的权限项勾选，而是由系统根据登录用户的身份自动判定。不同身份的用户可执行的操作如下：

| 身份 | 可执行操作 |
|------|-----------|
| 系统管理员（ADMIN） | 查看和操作全部 SOP 任务。 |
| 组织管理员（ORG_ADMIN） | 查看和操作本组织内的全部 SOP 任务。 |
| 只读管理员（ADMIN_VIEWER） | 仅能查看，不能创建、编辑、启动或执行。default 组织的只读管理员可查看全部任务，其他组织的只读管理员只能查看本组织任务。 |
| 其他登录用户 | 只能查看和操作自己创建的 SOP 任务，与角色中是否配置 SOP 无关。 |

未登录用户不能访问 SOP。

<main id="notice" type='explain'>
<h4>说明</h4>
<p>SOP 不作为独立权限项出现在角色配置中。</p>
</main>

### 与集群/租户权限的关系

SOP 接口放行之后，创建、启动、执行仍会校验操作对象的资源权限。例如对集群没有 **更新** 权限时，即使能打开 SOP 页面，也无法对该集群真正创建或执行 SOP 任务。

## 前提条件

* 当前登录 OCP 的用户具备 **集群管理**、**租户管理** 或 **主机管理** 任一资源权限（用于操作目标资源）。
* 集群/租户/主机的 **更新** 权限（用于创建、启动或执行步骤）。

## 功能简介

SOP 提供了多种预置的标准运维流程模板，每种模板包含一组按顺序执行的标准步骤。您可以根据业务场景选择合适的流程类型，配置步骤的自动执行属性，并在需要时通过人工确认推进流程。

SOP 的主要特点包括：

* **流程模板化**：每种 SOP 类型均提供预置的标准步骤模板，步骤的执行顺序、类型和标识均已固定，确保操作规范性。
* **自动与手动结合**：支持为每个步骤配置是否自动执行。自动执行步骤会在前一步完成后自动触发；非自动执行步骤不会自动触发，需手动执行下一步推进。
* **过程可追溯**：每个步骤的执行状态、开始/结束时间、关联任务、重试次数和错误信息均有完整记录，便于问题定位与审计。
* **灵活的故障处理**：步骤执行失败时支持重试单个失败步骤或全部失败步骤；非自动执行步骤可在执行前修改自动执行开关或步骤参数。

## 任务列表

您可在 **标准流程** 页面查看所有 SOP 任务，包括任务名称、任务类型、执行对象、执行进度、创建时间、创建人、开始时间、结束时间和状态等信息。

* 在搜索框中输入任务名称，可对任务进行模糊查询。
* 单击任务名称或 **执行详情**，可查看该任务的执行详情，包括步骤配置、执行状态和步骤执行信息，详情参见 [查看标准运维流程执行详情](300.view-sop-execution-details.md)。
* 支持新建标准运维流程任务，详情参见 [新建标准运维流程](200.create-a-sop-task.md)。

### 任务状态说明

| 状态 | 说明 |
|------|------|
| 待执行（NOT_STARTED） | 任务已创建但尚未启动执行。 |
| 等待确认（WAITING_CONFIRM） | 任务执行中，当前步骤需要手动执行下一步推进。 |
| 执行中（RUNNING） | 任务正在执行中，当前步骤正在自动执行。 |
| 失败（FAILED） | 任务执行过程中出现失败步骤。 |
| 已结束（COMPLETED） | 任务所有启用步骤均已成功完成。 |

## SOP 类型说明

OCP 当前支持以下 3 种标准运维流程类型：

### 副本异常开启仲裁服务

用于在集群内副本出现异常时，通过开启仲裁服务来保障租户的可用性。该流程包含确认操作对象、添加仲裁服务、删除租户副本、删除 OBSERVER、开启租户仲裁服务和验证租户仲裁服务可用等步骤。需指定目标集群及仲裁服务或仲裁服务组。

### OBSERVER 异常后数据重建

用于在 OBSERVER 节点故障后，通过删除故障节点并添加新节点的方式完成数据重建。该流程包含确认操作对象、删除租户副本、删除 OBSERVER、强制删除主机（可选）、添加 OBSERVER、添加租户副本和验证租户副本重建成功等步骤。支持预选替代主机。

### 重建备租户

用于在备租户数据异常或损坏时，通过备份主租户数据并重新创建备租户的方式完成恢复。该流程包含确认操作对象、备份主租户、主备解耦、锁定原备租户、删除原备租户、新建备租户和验证主备同步等步骤。主备同步方式支持基于网络（NETWORK）和基于归档（LOG_BACKUP）两种模式。
