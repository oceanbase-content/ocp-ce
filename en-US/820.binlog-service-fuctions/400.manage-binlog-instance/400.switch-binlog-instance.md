# Switch primary and standby instances

This topic describes how to switch primary and standby instances. When the primary instance is unavailable, you can switch the standby instance to primary to take over the Binlog service.

In OCP, you can switch primary and standby instances in the following two ways:

* **Method 1**: Go to the **<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** page. In the **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceList">Binlog Instance List</UI-TERM>** list, find the standby instance you want to switch and click **... > Switch** in its Actions column.
* **Method 2**: Go to the **<UI-TERM key="ocp-v2.Instance.Overview.BinlogInstanceOverview">Binlog Instance Overview</UI-TERM>** page of the standby instance. Click **... > Switch** in the upper-right corner.

## Prerequisites

* Ensure the current OCP user has the following permissions:

  * The **Binlog Service Maintenance** resource permission.
  * The **Binlog Cluster Overview** menu permission for the Binlog service.

* The Binlog instance to be switched is a standby instance, and the corresponding Binlog cluster is in the **RUNNING** state.

## Procedure

The following procedure uses **Method 2** as an example.

1. Log in to OCP.

2. In the left navigation bar, click **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogService">Binlog Service</UI-TERM>**. The system goes to the **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page by default.

3. On the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page, select the target Binlog cluster and click its name to go to the **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** page.

4. In the **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceList">Binlog Instance List</UI-TERM>** section, find the standby Binlog instance you want to switch and click its name.

5. On its **<UI-TERM key="ocp-v2.Instance.Overview.BinlogInstanceOverview">Binlog Instance Overview</UI-TERM>** page, click **... > Switch** in the upper-right corner.

6. In the dialog box, select the switching method and click **<UI-TERM key="ocp-v2.src.constant.binlog.Switch">Switch</UI-TERM>**.

   * **<UI-TERM key="ocp-v2.Binlog.Component.InstanceSwitchoverModal.CutMasterRecommend">Switchover (recommended)</UI-TERM>**: A new connection will be created on the new primary instance, while the old connection remains on the old primary instance, without interrupting access to the old primary instance.
   * **<UI-TERM key="ocp-v2.Binlog.Component.InstanceSwitchoverModal.StopTheServiceAndCut.1">Downtime Switchover</UI-TERM>**: Access to the old primary instance is interrupted, causing the service to become unavailable.

   You can view the task execution progress in **<UI-TERM key="ocp-v2.External.AIModel.MissionCenter">Task Center</UI-TERM>**. The switch is successful when the task status is **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SuccessfulExecution">Completed</UI-TERM>** and the instance status is **<UI-TERM key="ocp-v2.src.constant.tenant.NormalOperation">Running</UI-TERM>**.
