# Switch primary and standby instances

This topic describes how to switch primary and standby instances. When the primary instance is unavailable, you can switch the standby instance to the primary instance to take over the Binlog service.

In OCP, you can switch primary and standby instances in the following two ways:

* **Method 1**: Go to the **<UI-TERM key="ocp-v2.Detail.Overview.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** page of a Binlog cluster, select the standby instance to be switched in the **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceList">Binlog Instance List</UI-TERM>** list, and click **... > Switch** in the Actions column.
* **Method 2**: Go to the **<UI-TERM key="ocp-v2.Instance.Overview.BinlogInstanceOverview">Binlog Instance Overview</UI-TERM>** page of the standby instance, and click **... > Switch** in the upper-right corner.

## Prerequisites

* You have logged in to OCP as a user who has the following permissions:

  * The **Binlog Service Maintenance** permission.
  * The **Binlog Cluster Overview** permission for the Binlog service.

* The Binlog instance to be switched is a standby instance, and the Binlog cluster corresponding to the instance is in the **Normal** state.

## Procedure

The following steps are based on **Method 2**.

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.constant.plan.BinlogService">Binlog Service</UI-TERM>**. The **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** list, find the target Binlog cluster and click its name. The **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogClusterOverview">Binlog Cluster Overview</UI-TERM>** page automatically appears.

4. In the **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.BinlogInstanceList">Binlog Instance List</UI-TERM>** section, find the standby instance to be switched, and click its name.

5. On the **<UI-TERM key="ocp-v2.Instance.Overview.BinlogInstanceOverview">Binlog Instance Overview</UI-TERM>** page, click **... > Switch** in the upper-right corner.

6. In the dialog box that appears, select a switching method and click **<UI-TERM key="ocp-v2.src.constant.binlog.Switch">Switch</UI-TERM>**.

   * **<UI-TERM key="ocp-v2.Binlog.Component.InstanceSwitchoverModal.CutMasterRecommend">Switchover (recommended)</UI-TERM>**: New connections are established with the new primary instance, while existing connections remain on the original primary instance. This ensures uninterrupted access to the original primary instance.
   * **<UI-TERM key="ocp-v2.Binlog.Component.InstanceSwitchoverModal.StopTheServiceAndCut.1">Downtime Switchover</UI-TERM>**: This will interrupt access to the original primary instance, causing temporary unavailability for the business.

   You can view the task progress in the **<UI-TERM key="ocp-v2.src.hook.useMenuOptions.TaskCenter">Task Center</UI-TERM>**. When the task status is **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.SuccessfulExecution">Completed</UI-TERM>** and the instance status is **<UI-TERM key="ocp-v2.src.constant.backup.NormalOperation">Running</UI-TERM>**, the switch is successful.
