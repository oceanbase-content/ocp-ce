# Create a Binlog Cluster

A Binlog cluster is a unified external service composed of one or more Binlog Servers. In scenarios where multiple Binlog Servers exist within the cluster, when a tenant's Binlog service starts, it will select an appropriate Binlog Server based on load balancing logic. If any Binlog Server fails, its Binlog service will be taken over by another healthy Binlog Server.

You can create a new Binlog cluster for management based on your business needs.

## Prerequisites

The current user logged in to OCP has the **ADMIN** or **ORG_ADMIN** role.

## Procedure

1. Log in to OCP and click **<UI-TERM key="ocp-v2.src.hook.useMenu.BinlogService">Binlog Service</UI-TERM>** in the left navigation bar.

2. On the Binlog **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page, click **<UI-TERM key="ocp-v2.Binlog.New.CreateABinlogCluster">Create Binlog Cluster</UI-TERM>** in the upper-right corner.

3. On the **<UI-TERM key="ocp-v2.page.Binlog.CreateABinlogCluster">Create Binlog Cluster</UI-TERM>** page, configure the basic cluster information.

     |Parameter|Description|
     |-----|-------|
     | **<UI-TERM key="ocp-v2.page.Binlog.BinlogClusterName">Binlog Cluster Name</UI-TERM>** | The name of the Binlog cluster to be managed. The cluster name must start with a letter and end with a letter or number, can contain letters, numbers, and underscores, and be 2 to 32 characters long.|
     | **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareVersion">Software Version</UI-TERM>** | Select the software package version for the Binlog cluster. If no packages are available, you can click **<UI-TERM key="ocp-v2.src.component.PackageSelect.UploadASoftwarePackage">Upload Software Package</UI-TERM>** at the bottom of the list to upload one.  |
     | **<UI-TERM key="ocp-v2.Detail.Overview.Endpoint">Access Address</UI-TERM>** | Enter the access address of the Binlog cluster. This address is used for request forwarding and load balancing when OBProxy communicates with the current Binlog cluster.   |
     | **<UI-TERM key="ocp-v2.TakeOver.Component.LoadBalancer.AccessPort">Access Port</UI-TERM>** | The access port of the Binlog cluster. The default is **2983**, which can be customized.   |

4. Configure MetaDB information.

   You need to enter the relevant information of a MySQL tenant to store the metadata of the Binlog Service. It is recommended not to use a production cluster.

     | Parameter | Description |
     |------|---------|
     | Access Method | The access method for the Binlog MetaDB. Choose based on the actual connection method of the cluster.  |
     | **<UI-TERM key="ocp-v2.Cluster.Import.ClusterName">Cluster Name</UI-TERM>** | Select an existing OceanBase cluster as the MetaDB for the Binlog Service. The version of the selected cluster must be V2.2.77 (Built Feb 14 2022 18:11:59) or later.|
     | **<UI-TERM key="ocp-v2.Detail.Component.CloneTenantModal.TenantName">Tenant Name</UI-TERM>** | Select a specific MySQL tenant within the cluster.   |
     | **<UI-TERM key="ocp-v2.Binlog.New.DatabaseUsername">Database Username</UI-TERM>** | Select a specific user from the MySQL tenant. If using a non-root user, go to **<UI-TERM key="ocp-v2.src.hook.useMenu.SafetyManagement">Security management</UI-TERM>** > **<UI-TERM key="ocp-v2.src.component.AddBinlogCredentialModal.CredentialManagement">Credential Management</UI-TERM>** to add credentials for the current user and grant it sufficient permissions.  |
     | **<UI-TERM key="ocp-v2.Detail.Overview.DatabaseName">Database Name</UI-TERM>** | Enter the name of the MetaDB database. The default is `binlog_database`. Supports a custom name, 2 to 64 characters long, containing digits (0-9), uppercase letters (A-Z), lowercase letters (a-z), underscores (_), and hyphens (-).   |
     | Access Address | The access address of the Binlog MetaDB. It is recommended to configure the access address of the Binlog MetaDB as the access address of the OBProxy cluster, or apply for a VIP address from the load balancing device and bind it to the OBProxy Server to improve access stability and security.  |
     | Access Port | The access port of the Binlog MetaDB.  |

5. Deploy the Binlog cluster.

   Each Binlog cluster consists of multiple Binlog Servers. The information required for each Binlog Server and its description are as follows.

   | Parameter | Description |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">IDC</UI-TERM>** | The data center where the Binlog Server is located. A Binlog Server can only exist in one data center.  |
   | **<UI-TERM key="ocp-v2.OBProxy.New.DeployMode.Models">Model</UI-TERM>** | Optional. If a host type is selected, the host list will be filtered accordingly.   |
   | **<UI-TERM key="ocp-v2.Detail.TakeOver.Host">Host</UI-TERM>** | You can select multiple hosts or add new hosts.   |

6. Configure startup parameters for the Binlog cluster.

   * You can add startup parameter items one by one and configure values for them as shown in position ① in the figure.

   * Alternatively, as shown in position ② in the figure, click **<UI-TERM key="ocp-v2.page.Tenant.ParameterTemplate">Parameter Templates</UI-TERM>** to select a parameter template. The system will automatically fill in the parameters and configurations from the template here. If no cluster parameter template has been created, you can click **Create Binlog Parameter Template** to create one for the Binlog cluster. For details, see [Manage Binlog parameter templates](600.manage-binlog-parameter-templates.md).

   <!-- ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01242114.png) -->

   The system provides the following five built-in templates, which contain common parameter settings. You can directly apply these templates to initialize your Binlog cluster.

   | Template | Description |
   |-----------|---------|
   | Top-Level Performance Parameters Template | Estimated resource usage: 16C 10GiB, estimated RPS: 200,000~250,000. Applicable only to version 4.2.0 and later. |
   | Super Performance Parameters Template | Estimated resource usage: 12C 9GiB, estimated RPS: 150,000~200,000. Applicable only to version 4.2.0 and later. |
   | Advanced Performance Parameters Template | Estimated resource usage: 8C 9GiB, estimated RPS: 100,000~150,000. Applicable only to version 4.2.0 and later. |
   | Medium Performance Parameters Template | Estimated resource usage: 4C 8256MiB, estimated RPS: 80,000~100,000. Applicable only to version 4.2.0 and later. |
   | Default Performance Parameters Template | Estimated resource usage: 2C 8224MiB, estimated RPS: 50,000~60,000. Applicable only to version 4.2.0 and later. |

7. In the **<UI-TERM key="ocp-v2.Component.UpgradeDistributedClusterDrawer.CustomSettings">Custom Settings</UI-TERM>** section, you can customize the software installation path. The default path is `/home/admin/binlogservice`, which supports customization.

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/431/%E8%87%AA%E5%AE%9A%E4%B9%89%E8%AE%BE%E7%BD%AE.png) -->

8. Click **<UI-TERM key="ocp-v2.component.PreCheckDrawer.Create">Create</UI-TERM>**.

9. Perform a pre-check before creation. The system verifies whether your environment meets the minimum requirements for creating a Binlog cluster. If a check item fails, you can perform the following operations as prompted:

    * **<UI-TERM key="ocp-v2.src.constant.task.SetToSuccessful">Skip</UI-TERM>**: This skips the current check item (designed for special scenarios). Ensure the related check items meet product specification requirements; otherwise, subsequent process execution may fail. After skipping, the status of that check item changes to **<UI-TERM key="ocp-v2.src.constant.task.Warning">Warning</UI-TERM>**.
    * **<UI-TERM key="ocp-v2.Detail.Log.LogCard.ReRun">Retry</UI-TERM>**: Troubleshoot and fix the issue based on the failure reason and optimization suggestions. After fixing it, click **<UI-TERM key="ocp-v2.src.constant.task.ReRun">Retry</UI-TERM>** to rerun the failed check item.
    * **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">Retry All</UI-TERM>**: After all issues are troubleshooted and fixed, click **<UI-TERM key="ocp-v2.component.PreCheck.CheckResult.RetryAll">Retry All</UI-TERM>** to rerun all failed check items.

10. When no check items fail, click **<UI-TERM key="ocp-v2.ObjectStorage.Component.CreateDataSourceModal.NewCreation">Create</UI-TERM>**. After submitting the new Binlog cluster task, you can view its execution progress in **<UI-TERM key="ocp-v2.External.AIModel.MissionCenter">Task Center</UI-TERM>**.

## Overview of the cluster list

After a cluster is created, you can view its information in the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** list. The information includes the **<UI-TERM key="ocp-v2.page.Binlog.BinlogClusterName">Binlog Cluster Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.SQLDiagnosis.Outline.State">Status</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Binlog.AllocatedCpu">Allocated CPU</UI-TERM>**, **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">Memory</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Resource.Trend.UsedDisks">Data Disk Used</UI-TERM>**, **<UI-TERM key="ocp-v2.Binlog.Component.UpgradeBinlogModal.VersionNumber">Version</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.Arbitration.CreationTime">Created At</UI-TERM>**, and **<UI-TERM key="ocp-performance-report.ReportTables.ParameterStatInfo.ZoneParamInfoTable.ModificationTime">Modified At</UI-TERM>**.

* Click a cluster name to go to its overview page. For more information, see [View the overview of a Binlog cluster](300.manage-a-binlog-cluster/100.binlog-cluster-overview.md).
* You can filter Binlog clusters by **<UI-TERM key="ocp-v2.Backup.SecondaryBackup.Log.State">Status</UI-TERM>**.
