# Create MetaDB

Before deploying OCP, you must create the MetaDB component for OCP in OAT. If you want to use an already deployed MetaDB, you can refer to [Take over MetaDB](https://www.oceanbase.com/docs/enterprise-oat-doc-cn-10000000001092554) to take over MetaDB into OAT.

This section describes how to create MetaDB in OAT.

## Prerequisites

Before creating MetaDB, confirm the following information:

* You have installed OAT and logged in using a super administrator or O&M personnel account. For more information, see [Install OAT](../../200.prepare-the-deployment-environment/100.install-oat.md).
* You have added the server where MetaDB is to be installed. For more information, see [Add a server](../../200.prepare-the-deployment-environment/200.standardized-host.md).
* Your server meets the resource requirements for installing MetaDB.

## Procedure

### Step 1: Go to the Create MetaDB page

1. Log in to OAT.

2. In the left navigation bar, click **Product Service > Components**.

3. On the **Component Management** page, click **Create Component** in the upper-right corner and select **Create MetaDB**.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%88%9B%E5%BB%BAmetadb1.png)

### Step 2: Configure basic information

The basic information required for MetaDB is as follows:

| Parameter | Description |
| -------- | --------- |
| MetaDB Image | Docker image file of MetaDB. Click **Manage Image Files** in the drop-down list to add the image file via **Local Scan** or **Remote Connection** in the pop-up panel.<ul><li>We recommend that you use **Local Scan**. You need to upload the image file to the oat container.`/data/images`Directory. If you mounted the host directory when starting OAT, you can directly copy the MetaDB image to the mapped directory on the host.</li><li>**Remote connection** is for scenarios where the image repository is accessible. For **Image repository**, enter the Docker repository address, for example,`reg.docker.alibaba-inc.com/xxx/xxx`; **Image tag**: Enter the image version number, for example,`3.3.9-x64`; **Architecture** is selected based on actual conditions.</li></ul> |
| Component Name | The name of the component. It must be unique and cannot duplicate other component names. The default name is metadb. |
| Custom Zone | To enable custom zones, you need to specify the zone name, IDC, server, and Root Server location. <main id="notice" type='explain'><h4>Note</h4>This parameter and the <b>Server</b> parameter are mutually exclusive. After you enable custom zones, the server parameters will be automatically hidden.</main> |
| Configure the arbitration service | You can freely enable or disable arbitration service. When enabling it, you can select an existing arbitration service. If no arbitration service has been created in advance or no existing one is selected, you can also click the Create Arbitration Service button to create a new one by entering the relevant information.<main id="notice" type='explain'><h4>Note</h4><ul><li>The arbitration service can be configured only when the <b>MetaDB Image</b> is set to V4.x.</li><li>When selecting an existing arbitration service, only an arbitration service with the same architecture as the MetaDB image is supported.</li><li>When creating a new arbitration service, the arbitration service image must have the same architecture as the MetaDB image, and the server usage must be set to Arbitration Service or OceanBase Product Service.</li></ul></main> |
| Server | The IP address of the server on which you want to install MetaDB. If you need to deploy a multi-node MetaDB, you can select multiple IP addresses. In this case, one instance of MetaDB will be installed on each selected server. |
| CPU | The number of CPU cores available to the MetaDB on the server. The default value is 32. |
| Memory | The memory available for MetaDB on the server, which is 90 GiB by default. |
| The name of the MetaDB cluster. | The cluster name of MetaDB. |
| root@sys password | The password of the root user in the sys tenant. |

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/02271047.png)

### Step 3 (Optional): Configure the installation path

The directory information to be configured is as follows:

| Parameter | Description |
| -------- | --------- |
| Installation Directory | The installation path of MetaDB. Default value:`/home/admin/oceanbase`, which supports custom directories. |
| Data Directory | Data storage path of MetaDB. Default value:`/data/1`, supporting custom directories. |
| Log Directory | Log storage path of MetaDB. Default value:`/log/1`, supporting custom directories. |
| Backup Directory | Optional. The backup directory of the MetaDB. The default value is empty. You can specify a custom directory. |

![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/metadb%E5%AE%89%E8%A3%85%E8%B7%AF%E5%BE%841.png)

### Step 4 (Optional): Configure startup parameters

The startup parameters to be configured are as follows:

| Parameter | Description |
| -------- | --------- |
| MySQL Port | MySQL port of MetaDB. Default value: 2881. |
| RPC Port | The RPC port of MetaDB, with a default value of 2882. |
| OBProxy Service Port | The service port of OBProxy, with a default value of 2883. |
| SSH Port | The SSHD port in the MetaDB container. Default value: 2022. OCP deploys the OCP Agent by connecting to this SSHD port. |
| Root Password | The password of the root user in the MetaDB container. |

![3](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/441/02271116.png)

<main id="notice" type='explain'>
<h4>Note</h4>
<ul>
<li>The CPU and memory resources required for MetaDB are the cumulative values of the resources for <a href="../100.planning-resources/200.metadb-resources.md">MetaDB</a>, <a href="../100.planning-resources/300.monitordb-resources.md">MonitorDB</a>, the sys tenant, system_memory, and OBProxy. When allocating resources to MetaDB, it is recommended that you reserve a margin in addition to the required resources (the sys tenant itself also occupies certain resources).</li>
<li>When configuring the installation path for MetaDB, ensure that the data directory, installation directory, and log directory are empty, and the user owning these directories is admin.</li>
<li>In the same MetaDB cluster, ensure that the hardware architecture of the images remains consistent (currently, OAT does not support heterogeneity).</li>
</ul>
</main>

### Step 5: Submit the creation task

1. After configuring MetaDB, click **<UI-TERM key="ocp-v2.Settings.Component.ModifyUserInfoDrawer.Submit">Submit</UI-TERM>**. If your configuration is incorrect, you can click **<UI-TERM key="ocp-v2.Alarm.Subscriptions.Reset">Reset</UI-TERM>** to restore the default configuration with one click.

2. After submitting the creation of MetaDB, go to **System and Security** > **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">Task Center</UI-TERM>**, and click the task name to view detailed task information.
