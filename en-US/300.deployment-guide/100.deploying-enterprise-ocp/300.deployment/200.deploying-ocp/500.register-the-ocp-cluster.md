# Register an OCP cluster

This topic describes how to bind a standby OCP cluster to a primary OCP cluster when you log in to the standby OCP cluster for the first time in multi-cluster mode of OCP. If you are not in multi-cluster mode, skip this topic.

## Prerequisites

* You have created primary and standby OCP clusters in multi-cluster mode.

  * You have deployed the primary and standby OCP clusters by following the procedure in [Install OCP](300.install-ocp.md).

  * To convert multiple single-node OCP clusters in standard mode to multi-cluster OCP, you can refer to [Multi-cluster mode switch](../../../../1200.manage-disaster-recovery/300.ocp-multi-cluster-mode/900.multi-cluster-mode-switch.md) to convert one cluster into the primary cluster and convert the remaining single-node OCP clusters in standard mode into standby clusters.

  <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>In this scenario, there must be no OceanBase primary clusters with the same name in the primary and standby OCP clusters.</p>
  </main>

* You have obtained the JDBC connection information for the primary cluster's MetaDB.

## Procedure

1. On the login page of the standby OCP cluster, enter the **<UI-TERM key="ocp-v2.page.Settings.Profile.Username">Username</UI-TERM>** and **<UI-TERM key="ocp-v2.Auth.User.New.Password">Password</UI-TERM>**, and click **<UI-TERM key="ocp-v2.page.Login.Login">Log On</UI-TERM>**.

   The system enters the **<UI-TERM key="ocp-v2.MultiCluster.RegisterOcp.WelcomeToMultiClusterMode">Welcome to Multi-cluster mode</UI-TERM>** interface.

   <!-- ![07271009](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/8712537261/p298450.png) -->

2. Enter the parameters in the **Connection Information for Primary OCP MetaDB** section.

   | Parameter | Description |
   |------|--------------------------------------------|
   | Host Address | The IP address of the node where the primary OCP MetaDB resides. For example: xxx.xxx.xxx.xxx.       |
   | Port | The access port for the primary OCP MetaDB. For example: 2881.                 |
   | Username | The username for accessing the primary OCP MetaDB. For example: ocp@ocp_meta#ocp321.  |
   | Password | The password for the user accessing the primary OCP MetaDB. For example: aA\*\*\*\*\*\*1j . |
   | Database | The database name of the primary OCP MetaDB. For example: meta_01.              |

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The information in the table is the JDBC connection information for the MetaDB, which can also be used to access this MetaDB in the background. If binding to the primary OCP fails, you can use the following command to access this MetaDB in the background for basic troubleshooting.</p>
   </main>

   ```sql
   ###Execute the obclient command on the client to connect to the database server
   obclient -hxxx.xxx.xxx.xxx -P2881 -u<username>@<tenant name#cluster name> -paA******1j -Dmeta_01
   ```

3. Click **<UI-TERM key="ocp-v2.MultiCluster.RegisterOcp.BindToPrimaryOcp">Bind to Leader OCP</UI-TERM>**.

   If the system switches to business mode, this standby OCP cluster is bound to the primary OCP cluster.

   If this primary OCP cluster is also bound to other standby OCPs, due to the primary-standby data synchronization interval set by the `ocp.multi-cluster.replication.interval.seconds` parameter, other standby OCPs may not be immediately displayed in the **<UI-TERM key="ocp-v2.MultiCluster.Detail.ActiveStandbyList">OCPs</UI-TERM>** of this standby OCP. For details, see the description of **<UI-TERM key="ocp-v2.MultiCluster.Detail.ActiveStandbyList">OCPs</UI-TERM>** in [Primary-standby details page description](../../../../1200.manage-disaster-recovery/300.ocp-multi-cluster-mode/100.overview-of-multi-cluster-mode.md).
