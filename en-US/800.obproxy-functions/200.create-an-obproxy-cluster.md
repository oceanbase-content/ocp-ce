# Create an OBProxy cluster

You can create a new OBProxy cluster by specifying basic information, deployment mode, advanced settings, and other details. The cluster can be used to add OBProxy instances or to connect with an OceanBase cluster.

## Prerequisites

* The current user logged in to OCP has the **ADMIN** or **ORG_ADMIN** role.
* Only OBProxy versions V4.3.0 and later support configuring the RPC port.

## Procedure

1. Log in to OCP.

2. In the left-side navigation pane, click **OBProxy** to go to the OBProxy page.

3. Click **Create OBProxy Cluster** in the upper-right corner to go to the **Create OBProxy Cluster** page.

4. Configure the **<UI-TERM key="ocp-v2.component.StepsMoveOutCluster.Step2.BasicInformation">Basic Information</UI-TERM>** of the OBProxy cluster.

   | Parameter | Description |
   |------|------|
   | Cluster Name | You can customize the cluster name based on your actual business needs. It must start with a letter and can contain letters, numbers, and underscores. |
   | Software Version | Select the OBProxy software version.<ul><li>If the version is available in the list, select it directly from the list.   </li><li>Otherwise, you can click **Add Version** at the bottom of the list to upload it.</li> </ul><main id="notice" type='explain'><h4>Note</h4><p>You can only select software packages of version V1.8.0 or later. For security reasons, we recommend that you select a software package of version V3.1.0 or later.</p></main> |
   | root@proxysys Password | The root@proxysys account is used to log in to OBProxy for parameter management of the proxy itself. You need to configure the password for this account here. You can use a custom password or a randomly generated one. The password must meet the following complexity requirements:<ul><li>It must be 8 to 32 characters long.</li><li>It must contain at least three of the four types: digits (0 to 9), uppercase letters (A to Z), lowercase letters (a to z), and special characters. Supported special characters are <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>.  </li></ul>  |
   | Enter the ProxyRO Account Password | This field is displayed when the **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareVersion">Software Version</UI-TERM>** of OBProxy is earlier than V4.0. The ProxyRO account is used for OBProxy to access the OceanBase cluster. If you do not enter a password, the default password of the ProxyRO account is used for connection. The password must meet the following requirements:<ul><li>It must be 8 to 32 characters long.</li><li>It must contain at least three of the four types: digits (0 to 9), uppercase letters (A to Z), lowercase letters (a to z), and special characters.</li><li>Supported special characters are <code>~!@#%^&*_-+=\|(){}[]:;,.?/</code>.  </li></ul>  |
   | Load Balancing Management | After you enable load balancing management, you can configure OBLB to improve the load balancing capability of the OBProxy cluster.<ul><li>OBLB Service: You can select an existing OBLB service configured on the host, or click **<UI-TERM key="ocp-v2.Detail.Component.OBLBServerSelect.AddOblbService">Add OBLB Service</UI-TERM>** to create a new OBLB service in the right panel. For details, see **Create Load Balancer** in [Manage Load Balancing](300.manage-a-obproxy-cluster/300.manage-load-balancing.md).<ul><li>OBLB Service Address: The address of the OBLB service.</li><li>OBLB Service Port: The default value is 9090. You can change it as needed.</li><li>Username and Password: The username and password of the OBLB service, which are used for authentication when calling the OBLB interface.</li></ul></li><li>VIP: Select the specific VIP address of the OBLB service.</li><li>Access Port: The access port of the OBLB service. The default value is 2883. You can specify a custom port number.</li><li>Port Type: The type of the access port. Valid values: RPC and SQL.</li><li>Domain Name Configuration (Optional): The configuration information used to resolve the VIP address to a domain name. The platform does not provide a mapping between VIPs and domain names. You must prepare your own domain name resolution service.</li><li>Remarks (Optional): Additional explanatory information.</li></ul><main id="notice" type='explain'><h4>Note</h4><p><ul><li>The <b>Load Balancing Management</b> feature is available only in OCP Enterprise Edition. OCP Community Edition does not support it.</li><li><b>Alibaba Cloud SLB</b> in <b>Load Balancing Management</b> is available only in Apsara Stack environments. Contact the original vendor's delivery and implementation personnel.</li><li>When OBLB and OBProxy are deployed on the same host, the access port of OBLB cannot be the same as the SQL port of OBProxy. Otherwise, the application cannot connect to the database.</li></ul></p></main> |
   | Access Address | This field is displayed when **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">Manage Load Balancer</UI-TERM>** is disabled. It is the access address of the OBProxy cluster and is used only to generate the tenant connection string. It does not affect actual usage. You need to configure load balancing yourself. If it is a VIP address, you also need to apply for it and bind it to the OBProxy Server.  |
   | Access Port | This field is displayed when **<UI-TERM key="ocp-v2.OBProxy.New.LoadBalancingManagement">Manage Load Balancer</UI-TERM>** is disabled. The default value is 2883. You need to fill in the actual port of the VIP.  |
   | Startup Mode | The startup mode of the OBProxy cluster. Valid values: <ul><li> ConfigUrl: Multi-cluster startup mode. This means the OBProxy cluster can access multiple OceanBase clusters.   </li><li> RsList: Single-cluster startup mode. This means the OBProxy cluster can only access the OceanBase cluster specified when it was created. No additional connectable OceanBase clusters can be added after the OBProxy cluster is created.</li>    </ul>    |
   | Connectable OceanBase Clusters | Set the OceanBase clusters that this OBProxy cluster can access. You can only select OceanBase clusters that have the same network as this OBProxy cluster. <ul><li> When **<UI-TERM key="ocp-v2.OBProxy.New.StartupMode">Startup Method</UI-TERM>** is set to ConfigUrl, this parameter is optional. After the cluster is created, you can add clusters by using [Add Connectable OceanBase Cluster](300.manage-a-obproxy-cluster/200.add-a-connectable-oceanbase-cluster.md).   </li><li> When **<UI-TERM key="ocp-v2.Detail.TakeOver.StartupMode">Startup Method</UI-TERM>** is set to RsList, this parameter is required. Select the corresponding cluster from the drop-down list. </li><li> If the password box contains the connection credentials for the proxyro user of that cluster, the proxyro user is selected by default.   </li><li>If the password box does not contain the connection credentials for the proxyro user of that cluster, click **Create Connection** to create connection credentials for the proxyro user of that cluster. </li> </ul>   |

5. (Optional) Configure **<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">Deploy OBProxy</UI-TERM>**.

   If you want to deploy OBProxy when creating the OBProxy cluster, you can configure it in this step. Otherwise, you can skip this step and add OBProxy to the cluster after the cluster is created by using [Take Over OBProxy](400.manage-a-obproxy-server/200.take-over-an-obproxy.md) or [Add OBProxy](400.manage-a-obproxy-server/100.add-an-obproxy.md).

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>If you skip this step, the OBProxy cluster you create will be an empty cluster. In this case, you cannot <a href='300.manage-a-obproxy-cluster/200.add-a-connectable-oceanbase-cluster.md'>add a connectable OceanBase cluster</a> to this OBProxy cluster.</p>
   </main>

   1. Turn on the switch to configure **<UI-TERM key="ocp-v2.OBProxy.New.DeploymentObproxy">Deploy OBProxy</UI-TERM>**.

   2. Refer to the following table to fill in the deployment information.

      | Parameter | Description |
      |---------------|--------------|
      | **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">IDC</UI-TERM>**     | The data center where the OBProxy is located. An OBProxy can exist only in one data center.  |
      | **<UI-TERM key="ocp-v2.Detail.TakeOver.Models">Host Type</UI-TERM>**    | Optional. If you select a model, the host list will be filtered accordingly.   |
      | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.Host">Host</UI-TERM>** | Select the host(s) to deploy OBProxy. Multiple selections are supported. You can also click **<UI-TERM key="ocp-v2.Detail.Overview.AddObproxy">Add OBProxy</UI-TERM>** to add more hosts to the cluster. |

      ![08261945](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/403-ce/%E9%83%A8%E7%BD%B2obproxy.png)

      The system displays the selection of two hosts by default, which is sufficient to deploy two OBProxies.

      * To deploy more, click **<UI-TERM key="ocp-v2.Detail.Component.AddOBProxyDrawer.AddObproxy">Add OBProxy</UI-TERM>** to add a host.

      * If you only want to deploy 1 OBProxy, you can click the delete icon next to the host as shown in the figure above to remove that host.

6. Configure startup parameters for the OBProxy cluster.

   * You can add startup parameter items one by one and configure their values as shown at position ① in the figure. For details about OBProxy parameters, see [OBProxy parameters](900.obproxy-parameters-description.md).

   * You can also click **<UI-TERM key="ocp-v2.page.Tenant.ParameterTemplate">Parameter Template</UI-TERM>** as shown in Figure ② to select a parameter template. The system will automatically fill in the parameters and configurations from the template here. If no cluster parameter template has been created, you can click **Create OBProxy Parameter Template** to create one for the OBProxy cluster. For details, see [Manage OBProxy parameter templates](800.manage-obproxy-parameter-templates.md).

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/435/01242047.png)

   The system provides the following two built-in templates, which contain common parameter settings. You can directly apply these templates for the initialization settings of your OBProxy cluster.

   | Template | Description |
   |-----------|---------|
   | 4.2.1 Default Parameter Template | Recommended parameter settings for OBProxy V4.2.1, intended for production environments. |
   | Columnstore Replica Default Parameter Template | Recommended parameter settings for columnstore read-only replicas, intended for production environments. |

7. Open **<UI-TERM key="ocp-v2.Component.AddOBServerDrawer.CustomSettings">Custom Settings</UI-TERM>** to configure the cluster port, the primary user of the operating system, and paths.

   | Configuration | Description |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Scan.ReportTable.ZoneInfoTable.SqlPort">SQL Port</UI-TERM>** | Default is 2883, supports customization. |
   | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ExporterPort">Exporter Port Number</UI-TERM>** | Default is 2884, supports customization. |
   | **<UI-TERM key="ocp-v2.Detail.Component.AddOBProxyDrawer.RpcPort">RPC Port</UI-TERM>** | This port is supported only for OBProxy V4.3.0.0 and later. Default is 2885, supports customization. |
   | **Primary User of Operating System** | Configures the OS user for installing and running OBProxy. Cannot be edited. You can adjust the default configuration via the [Modify system parameter](../1600.system-management-features/500.manage-system-parameter/200.modify-system-parameters.md) `ocp.operation.default.os.user`. After modification, it only affects [Creating distributed clusters](../600.cluster-functions/200.create-a-cluster/100.create-a-distributed-cluster.md), [Creating standalone clusters](../600.cluster-functions/200.create-a-cluster/200.create-a-standalone-centralized-cluster.md), creating OBProxy clusters, and [Creating arbitration services](../600.cluster-functions/1350.manage-arbitration-services/200.create-arbitration-services.md), without affecting other configurations of existing clusters. |
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SoftwareInstallationPath">Software Installation Path</UI-TERM>** | <ul><li> When **Primary User of Operating System** is admin, **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">Software Installation Path</UI-TERM>** defaults to `/home/admin/obproxy`, supports custom paths.</li><li>When **Primary User of Operating System** is non-admin, **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">Software Installation Path</UI-TERM>** defaults to `/opt/oceanbase/obproxy`, supports custom paths.</li></ul>  After configuration, click **<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">Test</UI-TERM>** to verify if the path is available. If not, you can troubleshoot based on the test results or modify the path to another available one. |

8. Click **<UI-TERM key="ocp-v2.OBProxy.New.Submitted">Submit</UI-TERM>** to start creating the OBProxy cluster.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>When installing OBProxy, the system checks whether the permissions for the involved installation directories are correct. Currently, it recursively checks whether the <code>/home/admin/logs/obproxy</code> directory and its parent directory have read and execute permissions for the specified user (default is admin). If not, an error "check directory xxx permission failed, reason: xxx" is reported in the logs.</p>
   </main>
