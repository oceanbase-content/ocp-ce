# What's New

OCP V4.5.0 is officially released! This upgrade focuses on the capability building of **OceanBase AI**: it adds support for OceanBase AI clusters (with shared storage architecture) and builds the foundational capabilities they depend on — **Object Storage External Integration** and **Full Lifecycle Management for LogService components** — to help users centrally manage and maintain databases and their supporting components in AI scenarios on OCP.

**Key Highlights**:

* **OceanBase AI Version Compatibility**: Adds full lifecycle support for creating, operating, and monitoring OceanBase AI clusters (with shared storage architecture and a kernel version of at least 4.6.2.0).
* **Object Storage External Integration**: Adds external integration for object storage management. It centrally maintains connection information and credentials for the object storage (such as S3) relied upon by AI and LogService clusters, supports connectivity verification, and AK/SK rotation.
* **LogService Component Management**: Adds full lifecycle management capabilities for LogService clusters, including creation, start-stop-restart, scaling (Zone/Server), and AK rotation.

## Key Feature Overview

### OceanBase AI Version Compatibility

To enable users to centrally manage both traditional OceanBase clusters and AI versions (with shared storage architecture) on OCP, this release introduces new adaptations for AI clusters:

* **Version Requirement**: The current minimum supported OceanBase kernel version for AI clusters is **4.6.2.0**. Clusters with a lower version will be intercepted and prompted during creation/verification.

* **Operation and Maintenance Capability**: Supports creating AI clusters, automatically issuing instructions to bind object storage during Zone scaling, unit specification operation and maintenance, and installing/uninstalling dedicated AI software packages.

* **Monitoring Adaptation**: Distinguishes collection items and chart units for shared storage (SS) mode, and fixes the display issue of monitoring charts when there is no data.

* **Feature Limitations** (The following capabilities are currently not supported for AI clusters. Clear prompts will be displayed during operations):

  * Creating Oracle-compatible tenants is not supported.

  * Creating primary/standby (Standby) tenants is not supported. Disaster recovery is temporarily unavailable.

  * Cluster takeover (Takeover) is not supported.

  * Stopping a single Zone is not supported.

### Object Storage External Integration (New, for AI clusters/LogService dependent services)

Both OceanBase AI clusters and LogService clusters rely on object storage (such as S3) to store data. This time, unified object storage management capabilities are added under "External Integration":

* Supports adding/editing/deleting object storage integration configurations, and centrally maintains connection information such as Endpoint, Bucket, AK/SK.

* Supports object storage connectivity verification (including Endpoint format verification) to identify configuration issues in advance.

* Supports viewing object storage reference relationships by user (AI cluster / LogService cluster).

* Supports replacing object storage AK/SK and adapts to kernel key rotation SQL rules, automatically completing synchronization on the cluster side during the rotation process.

### Full Lifecycle Management for LogService (Log Service) Components (New)

Adds comprehensive management capabilities for LogService clusters and merges the three component categories of OBProxy, Binlog, and LogService into a unified "Components" menu in the main menu:

* **Cluster management**: Create, delete, start, stop, restart, and synchronize the status of clusters.

* **Elastic scaling**: Batch add, delete, start, stop, and restart zones; batch add, delete, start, and stop servers.

* **Parameter management**: Create, edit, and delete parameter metadata and templates; perform online parameter changes for clusters.

* **Security**: Perform pre-validation and rotation of object storage access keys and secret keys; manage organizational permissions (with multi-level visibility).

* **Observability**: Collect monitoring metrics, define alert rules, and query logs dedicated to the LogService.

## New features

### Cluster management

Operations that are not supported for AI clusters (such as creating Oracle or primary/standby tenants, taking over a cluster, stopping a single zone, etc.) are now consolidated into clear error messages to reduce the risk of misoperations.

Monitoring metric collection and chart display have been optimized for shared storage modes to avoid abnormal empty data displays in charts.

LogService clusters now support organizational permission management. In multi-level organizational structures, visibility can be controlled based on permissions.

### Main menu adjustments

OBProxy, Binlog, and LogService have been merged from separate menus into a single "Components" menu.

The original "Log Service" feature has been renamed "Log Search" due to a naming conflict with the LogService component.
