# Create a cluster

You can create a distributed primary/standby cluster to be managed.

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>OCP Community Edition supports creating only primary clusters. </p>
</main>

## Prerequisites

* The user used to log in to the OCP has the **Create Cluster** permission.

* (Optional) If you want to create a multi-replica OceanBase cluster, an OBProxy cluster must already exist in the OCP. You can follow the steps below to add an OBProxy cluster:

  * [Create an OBProxy cluster](../800.obproxy-functions/200.create-an-obproxy-cluster.md)

  * [Take over an OBProxy](../800.obproxy-functions/400.manage-a-obproxy-server/200.take-over-an-obproxy.md)

* Only a running primary cluster can create a standby cluster. The OceanBase version must be V2.2.50 or later and V4.0.0 or earlier.

## Procedure

1. Log in to the OCP console. On the left-side navigation pane, find the entry to create a cluster based on your business scenario.

   1. If you do not have a manageable cluster, you will be prompted to create a cluster on the **<UI-TERM key="ocp-v2.Detail.Component.DeleteModal.Cluster">Cluster</UI-TERM>** page. Click **<UI-TERM key="ocp-v2.Tenant.New.CreateACluster">Create Cluster</UI-TERM>** in the prompt box.

   2. If you already have a manageable cluster, click **New Cluster** in the upper-right corner of the **<UI-TERM key="ocp-v2.component.ModifyClusterParameterDrawer.Cluster">Cluster</UI-TERM>** page.

2. On the **Create Cluster** page, select **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** from the mode drop-down list.

3. Set the basic information of the cluster.

   * **Create a primary cluster**

      ![Image 175](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/420/%E5%88%9B%E5%BB%BA%E4%B8%BB%E9%9B%86%E7%BE%A4.png)

      The following table describes the parameters on the page.

     | Parameter  | Description |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.ClusterType">Cluster Type</UI-TERM>**          | Select **<UI-TERM key="ocp-v2.component.common.ClusterSelect.MasterCluster">Primary Cluster</UI-TERM>**.  |
     | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.ClusterName">Cluster Name</UI-TERM>**          | The name of the cluster to be managed. The cluster name must start with an English letter and end with an English letter or a number. It can contain English letters, numbers, and underscores, and must be 2 to 32 characters long. |
     | **<UI-TERM key="ocp-v2.Cluster.Import.RootSysPassword">Root@sys Password</UI-TERM>**    | The password can be customized or randomly generated. The password must meet the following complexity requirements: <ul><li>It must be 8 to 32 characters long.</li><li>It must contain at least two uppercase letters, two lowercase letters, two digits, and two special characters. </li><li>The special characters are \~!@#%\^\&\*_-+=\`\|(){}\[\]:;',.?/  </li></ul>   |
     | **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBase version</UI-TERM>**         | You can select an existing OceanBase cluster version from the list or click **<UI-TERM key="ocp-v2.src.component.PackageSelect.AddVersion">Add Version</UI-TERM>** below the list to upload an OceanBase version.  |
     | **Associate with OBProxy Cluster** | If you create a multi-replica OceanBase cluster, we recommend that you enable the **Associate with OBProxy Cluster** option to associate the OceanBase cluster with an OBProxy cluster. After the association, your SQL requests will be accurately forwarded to the corresponding replica, allowing you to access OceanBase Database as if it were a standalone database. </br>1. By default, the proxyro user is used for the association. You do not need to specify the username and password. </br>  2. Select the OBProxy cluster from the drop-down list. If the drop-down list is empty, add an OBProxy cluster as described in the **Prerequisites** section of this topic. <blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">Caution</UI-TERM>**</br>When the OceanBase version of the cluster selected in **<UI-TERM key="ocp-v2.Detail.Component.UpgradeModal.ObVersion">OceanBase version</UI-TERM>** is V4.0 or later, only OBProxy clusters of V4.0.0 or later can be associated with it. </blockquote>    |

   * **Create a standby cluster**

      ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/Image%209.png)

      The following table describes the parameters on the page:

     |       Parameter       |                                                                                         Description                                                                                          |
     |----------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
     | **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.ClusterType">Cluster Type</UI-TERM>**       | Select **<UI-TERM key="ocp-performance-report.ReportTables.BasicInfo.ClusterInfoTable.SecondaryCluster">Standby Cluster</UI-TERM>**.                                                                                                                                                              |
     | **<UI-TERM key="ocp-v2.Cluster.New.MasterCluster">Primary Cluster</UI-TERM>**        | Select the primary cluster. The system will create a standby cluster under the primary cluster.                                                                                                                                                              |
     | **OceanBase Version of Standby Cluster**  | Select the same OceanBase version as the primary cluster. <ul><li> If the version is available in the list, select it from the list.   </li><li> Otherwise, click **<UI-TERM key="ocp-v2.src.component.PackageSelect.AddVersion">Add Version</UI-TERM>** below the list to upload it. </li> </ul>   |

4. Set the deployment mode of the cluster.

   By default, three zones are added. If you want to deploy the cluster across more than three zones, click **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Add">Add</UI-TERM>** to add a zone. If you want to deploy the cluster across fewer than three zones, click the delete icon of the corresponding zone.

   ![10](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E9%83%A8%E7%BD%B2%E6%A8%A1%E5%BC%8F1.png)

   The following table describes the parameters to be set for each zone.

   |   Parameter   |  Description   |
   |-----|-------|
   | **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.ZoneName">Zone Name</UI-TERM>**    | You can keep the default or customize it. The zone name must start with an English letter and support uppercase and lowercase letters, numbers, and underscores. It must be 2 to 32 characters long. A multi-zone OceanBase cluster must have a zone that has the same region as the primary zone.  |
   | **<UI-TERM key="ocp-v2.OBProxy.New.DeployMode.ComputerRoom">IDC</UI-TERM>**     | The computer room where the zone is located. A zone can exist in only one computer room.  |
   | **<UI-TERM key="ocp-v2.Cluster.New.Models">Host Type</UI-TERM>**    | The model of the server. It is a reference parameter for filtering hosts.   |
   | **<UI-TERM key="ocp-v2.Component.OBServerList.OBServerModal.CpuArchitecture">CPU Architecture</UI-TERM>**    |  When multiple installation packages of different architectures are available for the selected **<UI-TERM key="ocp-v2.Cluster.New.ObVersion">OceanBase version</UI-TERM>**, you need to select the architecture that matches the host hardware architecture. <blockquote>**<UI-TERM key="ocp-v2.src.constant.alarm.Small">Caution</UI-TERM>**</br><ul><li>The default architecture type is the architecture type of the first installation package. You can switch the architecture type. After the switch, the **<UI-TERM key="ocp-v2.src.constant.auditEvent.Host">Host</UI-TERM>** list displays hosts of the specified architecture. </li><li>If different zones are assigned different architectures, the hybrid architecture deployment mode may encounter stability and performance issues. Proceed with caution. </li></blockquote> |
   | **<UI-TERM key="ocp-v2.Component.InstallService.Host">Host</UI-TERM>**  | You can select multiple hosts or add a host.   |
   | **Root Service IP Address**     | You need to select an IP address as the location of the Root Service. For a multi-replica OceanBase cluster, you need to specify the Root Service IP address for each zone.   |
   | **<UI-TERM key="ocp-v2.Tenant.New.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>**  **(This parameter is unavailable when you create a standby cluster.)**  | You can specify the priority for distributing the primary replica of the sys tenant of the cluster. <ul><li>If specified, the zone with the highest priority is considered the primary zone and must be unique. The priority is sorted in descending order. </br>1. Select one or more zones in the left-side pane. The zones available for selection are all the zones in the current cluster. </br>2. Click the \> button in the middle pane. The selected zones are then moved to the **<UI-TERM key="ocp-v2.Cluster.New.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>** pane. Zones with the same priority have equal chances of becoming the primary zone. </br>3. Repeat steps a and b to add zones of lower priorities. </br>4. You can drag the zones in the **<UI-TERM key="ocp-v2.Detail.Component.ModifyPrimaryZoneDrawer.ZonePrioritySorting">Zone Priority Rankings</UI-TERM>** pane to change the priority. </li><li>If not specified, the first zone created is assigned the highest priority. </li></ul>    |
   | **<UI-TERM key="ocp-v2.Detail.Component.AddArbitrationServerDrawer.AddArbitrationService">Add Arbitration Service</UI-TERM>** |  You can enable this option to add an arbitration service for the cluster. You can select an existing arbitration service from the service drop-down list or click **Add Service** to create a new arbitration service for the cluster. For more information, see [Add an arbitration service](../600.cluster-functions/400.manage-arbitration-services/800.add-arbitration-services.md).  <blockquote>**<UI-TERM key="ocp-v2.Alarm.Group.Description">Description</UI-TERM>**</br>Only primary clusters of OceanBase Database V4.1.0 and later can have an arbitration service added. </blockquote>  |

5. Open the **<UI-TERM key="ocp-v2.Component.ZoneList.AddOBServerDrawer.ParameterSettings">Parameter Settings</UI-TERM>** pane and configure the cluster parameters.

    * You can add startup parameters and configure their values one by one as shown in Figure ①.

    * Alternatively, you can click **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">Select Parameter Template</UI-TERM>** in Figure ② to browse and select a parameter template. The parameters in the template will be automatically filled into the parameters section.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>When OceanBase Database V2.2.77 is installed, we recommend that you use the built-in <strong>2.2.77 Version Parameter Template</strong>. This template contains common parameter settings of OceanBase Database V2.2.77. You can apply this template for the initial setup of a cluster. </li>
    <li>If no parameter template is created, you can click <strong>Create Cluster Template</strong> to create a parameter template. For more information, see <a href="../600.cluster-functions/1200.cluster-parameters-template-management.md">Cluster Parameter Template Management</a>. </li>
    </ul>
    </main>

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE1.png)

6. Open **Custom Configuration** and configure the operating system's owner user, paths, and ports.

   * Configure the owner user:

      The user who configures and runs OBServer on the operating system. The user cannot be edited. You can refer to [Modify system parameters](../1600.system-management-features/300.manage-system-parameter/200.modify-system-parameters.md) to modify the `ocp.operation.default.os.user` parameter and change the default user.

      <main id="notice" type='explain'>
      <h4>Note</h4>After you modify the <code>ocp.operation.default.os.user</code> parameter, the modification only takes effect when you create a distributed cluster, [create an OBProxy cluster](../800.obproxy-functions/200.create-an-obproxy-cluster.md), or [create an arbitration service](../600.cluster-functions/400.manage-arbitration-services/200.creat-arbitration-services.md). It does not affect the configurations of existing clusters.
      </main>

   * Configure the paths:

      |   Parameter   |  Description   |
      |-----|-------|
      | **<UI-TERM key="ocp-v2.OBProxy.New.SoftwareInstallationPath">Software Installation Path</UI-TERM>**   | <ul><li> When the **OS Owner User** is admin, the default value of **<UI-TERM key="ocp-v2.Cluster.New.SoftwareInstallationPath">Software Installation Path</UI-TERM>** is `/home/admin/oceanbase`. Custom paths are supported. </li><li>When the **OS Owner User** is not admin, the default value of **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">Software Installation Path</UI-TERM>** is `/opt/oceanbase/oceanbase`. Custom paths are supported. </li></ul>   |
      | **<UI-TERM key="ocp-v2.Detail.Overview.DataDiskPath">Data Disk Path</UI-TERM>**       | The default value is `/data/1`. Custom paths are supported.  |
      | **<UI-TERM key="ocp-v2.Detail.TakeOver.ExporterPort">Exporter Port Number</UI-TERM>**   | The default value is `/data/log1`. Custom paths are supported.     |

      After the paths are configured, click **<UI-TERM key="ocp-v2.Settings.Credential.Host.Test">Test</UI-TERM>** to verify whether the paths are available. If not, you can troubleshoot the issues based on the test results or change the paths to available ones.

      ![11](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E9%85%8D%E7%BD%AE%E8%B7%AF%E5%BE%841.png)

   * Configure the ports:

      |   Parameter   |  Description   |
      |-----|-------|
      | **<UI-TERM key="ocp-v2.OBProxy.New.SqlPort">SQL Port Number</UI-TERM>**        | The default value is 2881. Custom ports are supported.  |
      | **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.ExporterPort">Exporter Port Number</UI-TERM>**   | The default value is 2882. Custom ports are supported.     |

      After the ports are configured, click **<UI-TERM key="ocp-v2.Settings.Credential.Cluster.Test">Test</UI-TERM>** to verify whether the ports are occupied. If the ports are occupied, you need to configure available ports.

      ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E7%AB%AF%E5%8F%A3%E9%85%8D%E7%BD%AE1.png)

7. After the tests are successful, click **<UI-TERM key="ocp-v2.ResourceManager.ResourceGroupTab.CreateResourceGroup.Submit">Submit</UI-TERM>**.

8. In the **<UI-TERM key="ocp-v2.Cluster.New.ConfirmSubmissionInformation">Confirm Information</UI-TERM>** dialog box, click **<UI-TERM key="ocp-v2.Alarm.Template.New.Ok">OK</UI-TERM>** after you verify that the information is correct.

   You can view the task execution progress in the **System Management > Tasks** page.
