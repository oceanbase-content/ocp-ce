# SSL Link Encryption

## Scenarios

1. **End-to-end SSL authentication**: SSL authentication is used to establish connections and encrypt data transmission between business applications, OBProxy, and OceanBase.
2. **OBProxy SSL authentication**: SSL authentication is used to establish connections and encrypt data transmission between business applications and OBProxy.
3. **OceanBase SSL authentication**: SSL authentication is used to establish connections and encrypt data transmission between business applications and OceanBase.

The following figure shows the end-to-end SSL authentication process between OceanBase and OBProxy.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1542.png)

## Prerequisites

**Certificate application and issuance**

1. Apply for a CA root certificate from a trusted CA certificate authority and ensure that the CA root certificate has not expired.
2. Use the CA root certificate to issue a server certificate and ensure that the server certificate has not expired. Retain the certificate and private key.
3. After completing the above steps, you will obtain three PEM-formatted files (file type must be PEM, file name is not limited): CA root certificate (ca.pem), server certificate (server.pem), and server private key (server-key.pem).

For more information about how to use the CA root certificate to issue a server certificate, see [Considerations](#server-certificate-issuance).

**SSL link encryption**

1. OceanBase and OBProxy clusters must be in the **normal running** state.
2. The OceanBase cluster must be of V4.0.0.0 or later.

## Technical principles

### Enable SSL authentication for OceanBase

**Step 1: Upload certificate files**

Before enabling SSL authentication for OceanBase, you must place the CA root certificate, server certificate, and server private key in the `${run_path}/wallet` directory of each OBServer node. After SSL authentication is enabled for OceanBase, OCP will automatically place the certificate files on new OBServer nodes when you add, reinstall, replace, or add a zone to OceanBase.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>After OCP takes over an OceanBase cluster with SSL authentication enabled, the new OCP instance may not have the certificate files of the cluster. In this case, OCP cannot upload the certificate files to new OBServer nodes in the scenarios mentioned above. To resolve this issue, you can re-upload the certificate files to OCP or update the SSL certificate.</p>
</main>

**Step 2: Enable SSL authentication**

OceanBase supports two types of SSL authentication: RPC SSL authentication and SQL SSL authentication. RPC SSL authentication restricts whether OceanBase can establish an RPC connection with an OBServer through SSL authentication. SQL SSL authentication restricts whether OceanBase can establish an SQL connection with an OBServer through SSL authentication. Both protocols use the same certificate.

To enable RPC SSL authentication, execute the following SQL statements:

```sql
# Specify the SSL certificate retrieval method. Only file is supported. The certificate is retrieved from a local file. If this parameter is not specified, the value is an empty string.
ALTER SYSTEM SET ssl_external_kms_info = '{"ssl_mode":"file"}';

# Set the authentication method for OceanBase as a server and a client for RPC connections:
# When OceanBase is an RPC server, it can establish both SSL and non-SSL connections. If this parameter is not specified, the value is ALL.
ALTER SYSTEM SET rpc_server_authentication_method = 'ALL';

# When OceanBase is an RPC client, it can only establish SSL connections. If this parameter is not specified, the value is NONE.
ALTER SYSTEM SET rpc_client_authentication_method = 'SSL_NO_ENCRYPT';

# Enable SQL RPC authentication.
ALTER SYSTEM SET ssl_client_authentication = True;

# Set the TLS protocol version.
ALTER SYSTEM SET sql_protocol_min_tls_version = "TLSv1.1";
```

### Enable SSL authentication for OBProxy

**Step 1: Upload certificate files**

Similar to OceanBase, you must upload the three files to the `${run_path}/wallet` directory of each OBProxy server node. In the scenario where you add an OBProxy server node, OCP will automatically place the certificate files on the new OBProxy server node.

**Step 2: Enable SSL authentication**

1. Connect to OBProxy as the OBProxy administrator user root@proxysys and execute the following SQL statement to configure the absolute path of the certificate.

    ```sql
    update proxyconfig.security_config set CONFIG_VAL= '{"sourceType" : "FILE", "CA" : "/xxx/wallet/ca.pem", "publicKey": "/xxx/wallet/proxy-cert.pem", "privateKey" : "/xxx/wallet/proxy-key.pem"}' where APP_NAME = 'obprox
    ' and VERSION = '1';
    ```

2. Enable SSL authentication.

    ```sql
    # Enable client SSL authentication. After this parameter is enabled, business applications can connect to OBProxy through SSL authentication.
    alter proxyconfig set enable_client_ssl=true;

    # Enable server SSL authentication. After this parameter is enabled, OBProxy can connect to OceanBase through SSL authentication.
    alter proxyconfig set enable_server_ssl=true;
    ```

SSL authentication is not mandatory between the client and OBProxy. Both SSL and non-SSL authentication methods can be used to establish a connection. If SSL authentication is enabled for OBProxy, it can also connect to OceanBase clusters with or without SSL authentication enabled. When OBProxy establishes a connection, it will negotiate with OceanBase to determine the connection method.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Typically, OBProxy and all associated OceanBase clusters use the same certificate. Since enterprises usually have only one CA certificate, OCP does not perform additional checks when associating OBProxy with OceanBase clusters. This scenario is left to the user to ensure.</p>
</main>

## Considerations

### Server certificate issuance

When using a CA root certificate to issue a server certificate, OceanBase and OBProxy have specific requirements for the server certificate issuance process.

1. When generating the private key for the server certificate, specify a key length of 2048. Here is an example:

    ```shell
    openssl genkey -algorithm RSA -out server-key.pem -pkeyopt rsa_keygen_bits:2048
    ```

2. If both OceanBase and OBProxy are enabled for SSL authentication and they use the same server certificate, the certificate must serve as both a client certificate and a server certificate. Therefore, the **Extended Key Usage** of the certificate must include both `Client Authentication` and `Server Authentication`. You can verify this by running the following command:

    ```sql
    openssl x509 -in ServerCertificateFilePath -text -noout
    ```

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1617.png)

3. If you need to issue a subordinate certificate, make sure to specify that the subordinate certificate is a CA certificate when using the CA root certificate. You can verify this by running the following command:

    ```shell
    openssl x509 -in SubordinateCertificateFilePath -text -noout
    ```

    The presence of `CA:TRUE` indicates that the subordinate certificate is a CA certificate and can be used to issue other certificates.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1618.png)

### Full SSL authentication

When both OceanBase and OBProxy are enabled for SSL authentication, they will use mutual SSL authentication. On the OceanBase side, you need to manually set the tenant parameter `ob_ssl_invited_common_names` by appending the `cn` field from the OBProxy certificate's subject to this parameter. Otherwise, OBProxy will not be able to access the tenant.

For more details, see [ob_ssl_invited_common_names](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015566).

## Procedure

**Step 1: Upload the certificate group**

On the certificate management page of OCP, upload the CA root certificate, server certificate, and server private key as a single certificate group.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1628.png)

**Step 2: Enable SSL link encryption**

Go to the security configuration page of OceanBase/OBProxy and enable SSL link encryption for OceanBase/OBProxy.
