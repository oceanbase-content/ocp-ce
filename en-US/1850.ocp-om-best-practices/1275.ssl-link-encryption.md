# SSL Encryption

## Scenarios

1. **SSL authentication for the entire chain**: SSL authentication is used to establish connections and encrypt data transmission in the business application > OBProxy > OceanBase chain.
2. **SSL authentication for OBProxy**: SSL authentication is separately enabled for the OBProxy cluster, using it to establish connections and encrypt data transmission in the business application > OBProxy chain.
3. **SSL authentication for OceanBase**: SSL authentication is separately enabled for the OceanBase cluster, using it to establish connections and encrypt data transmission in the business application > OceanBase cluster.

The following figure shows the SSL authentication for the entire chain of OceanBase and OBProxy:

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1542.png)

## Prerequisites

**Certificate application and issuance**

1. Obtain a CA root certificate from an authoritative certificate authority and ensure that the certificate has not expired.
2. Use the CA root certificate to issue a server certificate and ensure that the certificate has not expired. Retain the certificate and private key.
3. After completing the above steps, three PEM-formatted files (with any file name) are generated: the CA root certificate (ca.pem), the server certificate (server.pem), and the server private key (server-key.pem).

When using a CA root certificate to issue a server certificate, pay attention to the [considerations](#parameter).

**SSL encryption for links**

1. The OceanBase and OBProxy clusters must be in the **RUNNING** state.
2. The OceanBase cluster must be V4.0.0.0 or later.

## Technical principles

### Enable SSL authentication for OceanBase Database

**Step 1: Upload certificate files**

Before enabling SSL authentication for OceanBase Database, you must place the CA root certificate, server certificate, and server private key in the `${run_path}/wallet` directory on each OBServer. After enabling SSL authentication for OceanBase Database, OCP will automatically upload the certificate files to the new OBServer when you add an OBServer, reinstall an OBServer, replace an OBServer, or add a zone.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>After OCP takes over a cluster with SSL authentication enabled, the certificate files for the cluster may not be available in the new OCP. In this case, OCP will not be able to upload the certificate files to the new OBServer in the described scenarios. To resolve this issue, you can re-upload the certificate files or update the SSL certificate in OCP.</p>
</main>

**Step 2: Enable the SSL switch**

OceanBase Database supports RPC SSL authentication and SQL SSL authentication. These settings control whether OceanBase establishes RPC and SQL connections through SSL authentication. Both protocols use the same set of certificates.

To enable RPC SSL authentication, use the following SQL statements:

```sql
# Specify the method for obtaining the SSL certificate. Only 'file' is supported, which means the certificate is obtained from a local file. If this parameter is left empty, the certificate is not obtained.
ALTER SYSTEM SET ssl_external_kms_info = '{"ssl_mode":"file"}';

# Set the RPC authentication method for OceanBase Database as both a server and a client:
# As an RPC server, OceanBase can establish both SSL and non-SSL connections. If this parameter is left empty, the value is 'ALL'.
ALTER SYSTEM SET rpc_server_authentication_method = 'ALL';

# As an RPC client, OceanBase can only establish SSL connections. If this parameter is left empty, the value is 'NONE'.
ALTER SYSTEM SET rpc_client_authentication_method = 'SSL_NO_ENCRYPT';

# Enable the SQL RPC authentication switch.
ALTER SYSTEM SET ssl_client_authentication = True;

# Set the TLS protocol version.
ALTER SYSTEM SET sql_protocol_min_tls_version = "TLSv1.1";
```

### Enable SSL authentication for OBProxy

**Step 1: Upload certificate files**

Similar to OceanBase Database, you must upload the three files to the `${run_path}/wallet` directory on all OBProxy servers. In the scenario where you add an OBProxy server, OCP will also upload the certificate files to the new OBProxy server.

**Step 2: Enable SSL authentication**

1. Connect to OBProxy using the root@proxysys administrator user and execute the following SQL statement to set the absolute path of the certificate:

    ```sql
    update proxyconfig.security_config set CONFIG_VAL= '{"sourceType" : "FILE", "CA" : "/xxx/wallet/ca.pem", "publicKey": "/xxx/wallet/proxy-cert.pem", "privateKey" : "/xxx/wallet/proxy-key.pem"}' where APP_NAME = 'obprox
    ' and VERSION = '1';
    ```

2. Enable the SSL authentication switch.

    ```sql
    # Enable client SSL authentication. After this is enabled, applications can connect to OBProxy through SSL authentication.
    alter proxyconfig set enable_client_ssl=true;

    # Enable server SSL authentication. After this is enabled, OBProxy can connect to OceanBase through SSL authentication.
    alter proxyconfig set enable_server_ssl=true;
    ```

Client and OBProxy SSL authentication is not mandatory. Connections can be established using both SSL and non-SSL authentication methods. If OBProxy is enabled for SSL authentication, it can also be associated with OceanBase clusters that are not enabled for SSL authentication. When OBProxy establishes a connection, it will negotiate the connection method with OceanBase.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Typically, OBProxy uses the same set of certificates for all associated OceanBase clusters. Since enterprises usually have only one CA certificate, when associating OBProxy with an OceanBase cluster, OCP does not perform additional checks. Users are responsible for ensuring this setup.</p>
</main>

## Considerations

### Server certificate signing<a id="parameter"></a>

When using the CA root certificate to sign the server certificate, OceanBase and OBProxy have special requirements for the server certificate signing process.

1. When generating the private key for the server certificate, the key length must be specified as 2048. Example:

    ```shell
    openssl genkey -algorithm RSA -out server-key.pem -pkeyopt rsa_keygen_bits:2048
    ```

2. If both OceanBase and OBProxy are enabled for SSL authentication and they use the same server certificate, this certificate serves as both the client certificate and the server certificate. The **Extended Key Usage** of the certificate must include both `Client Authentication` and `Server Authentication`. You can run the following command to verify this:

    ```sql
    openssl x509 -in server certificate file path -text -noout
    ```

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1617.png)

3. If you have a secondary certificate requirement, note that when using the CA root certificate to sign the secondary certificate, you must specify that the secondary certificate is a CA certificate. You can run the following command to verify this:

    ```shell
    openssl x509 -in secondary certificate file path -text -noout
    ```

    `CA:TRUE` indicates that the secondary certificate is a CA certificate, which can be used to sign other certificates.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1618.png)

### End-to-end SSL authentication

When both OceanBase and OBProxy are enabled for SSL authentication, OBProxy and OceanBase will use mutual SSL authentication. On the OceanBase side, you need to manually set the tenant parameter `ob_ssl_invited_common_names` to append the `cn` field from the OBProxy certificate to this parameter. Otherwise, OBProxy will be unable to access the tenant.

For more information, see [ob_ssl_invited_common_names](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015566).

## Procedure

**Step 1: Upload the certificate group**

On the certificate management page of OCP, upload the CA root certificate, server certificate, and server private key to form a certificate group.

![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1628.png)

**Step 2: Enable SSL encryption**

Go to the security configuration page of OceanBase or OBProxy and enable SSL encryption for OceanBase or OBProxy.
