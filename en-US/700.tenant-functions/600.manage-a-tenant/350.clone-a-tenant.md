# Clone a tenant

This topic describes how to clone a tenant. You can clone a new tenant from a specified tenant. The number of resource units and the distribution of units across OBServer nodes in the cloned new tenant are consistent with those of the source tenant.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>Starting from OceanBase Database V4.3.x, we recommend that you do not use the primary tenant cloning feature. Starting from OceanBase V4.4.2 BP2, if you attempt to clone the primary tenant, the system will directly report an error and the operation cannot be completed. If you have already used the primary tenant cloning feature in a production environment, please contact the OceanBase Technical Support Team promptly for risk assessment and migration guidance to avoid impacting your business due to subsequent version upgrades.</p>
<p>The standby tenant cloning feature is an experimental feature. Before using it, please ensure you understand its usage boundaries and associated risks. The primary application scenario for standby tenant cloning is standby database drills.</p>
</main>

You can clone a tenant by using one of the following two methods:

* Clone a tenant on the **Tenant List** page.

* Clone a tenant on the **Overview** page of the specified tenant.

## Prerequisites

* Ensure the current user logged in to OCP has the following permissions:

  * **Cluster Maintenance** resource permission.
  * Permission to access the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** menu for tenants.

* The source tenant has been configured for log archiving by referring to [Create a tenant-level backup strategy](../../1100.backup-and-restoration-functions/500.regular-backup/200.manage-tenant-backup-strategy/100.creat-a-tenant-backup-stategy.md).

## Considerations

* The status of the source tenant must be Running or Locked.
* Only the tenant's own configuration, such as resource units, can be cloned; service names and tags are not supported.
* When cloning a primary tenant, ensure the cluster to which the primary tenant belongs is V4.3.0.0 or later. When cloning a standby tenant, ensure the cluster to which the standby tenant belongs is V4.3.2.0 or later.

## Procedure

1. Log in to OCP.

2. In the left navigation bar, select **<UI-TERM key="ocp-v2.Backup.SecondaryBackup.Data.Tenant">Tenant</UI-TERM>**. The system goes to the **<UI-TERM key="ocp-v2.component.TenantList.TenantList">Tenants</UI-TERM>** tab by default.

3. On the **<UI-TERM key="ocp-v2.component.TenantList.TenantList">Tenants</UI-TERM>** page, find the target tenant and click **<UI-TERM key="ocp-v2.component.TenantList.Clone">Clone</UI-TERM>** in the Actions column.

4. In the dialog box that appears, configure the relevant information for the new tenant. The details are as follows.

    * **<UI-TERM key="ocp-v2.Detail.Component.CloneTenantModal.TenantName">Tenant Name</UI-TERM>**: The name of the cloned new tenant. It must start with a letter and end with a letter or number, can contain letters, numbers, and underscores, and be 2 to 32 characters long.
    * **<UI-TERM key="ocp-v2.Detail.Component.CloneTenantModal.WhetherToCloneTenantParameters">Clone Tenant Parameters</UI-TERM>**: Whether to use the same parameter configuration as the source tenant. This is enabled by default.
    * **<UI-TERM key="ocp-v2.Tenant.Detail.CopyDetails">Replica Details</UI-TERM>**: Configure the unit specifications for the cloned new tenant. Since unit specifications affect cloning speed, the system will default to using the higher-specification unit of the source tenant, and the unit specifications must be consistent across zones.
    * **<UI-TERM key="ocp-v2.Detail.Component.CloneTenantModal.Whitelist">Allowlist</UI-TERM>**: By default, this is consistent with the source tenant. You can modify it after cloning the tenant on the tenant overview page.
    * **<UI-TERM key="ocp-v2.Detail.Component.CloneTenantModal.DumpBeforeCloningATenant">Perform a Minor Compaction before Cloning Tenant</UI-TERM>**: If you want to clone the tenant immediately, you can choose to perform a minor compaction before cloning. Performing a minor compaction prolongs the response time for stopping processes but significantly shortens OBServer recovery time.

5. Click **<UI-TERM key="ocp-v2.User.Oracle.UserList.Determine">OK</UI-TERM>**.
