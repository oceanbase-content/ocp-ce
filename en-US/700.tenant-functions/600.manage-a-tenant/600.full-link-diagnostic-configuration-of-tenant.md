# Configure end-to-end tracing for a tenant

This topic describes how to enable or disable end-to-end tracing for a tenant and provides usage instructions.

## Background information

After enabling end-to-end tracing, you can:

* Query the link diagnosis results of abnormal SQL statements in **<UI-TERM key="ocp-v2.page.Log.LogService">Log Services</UI-TERM>** > **<UI-TERM key="ocp-v2.Log.Trace.LinkQuery">Trace Query</UI-TERM>**. For more information, see [Query links](../../1300.log-service/400.trace-query.md).
* In **<UI-TERM key="ocp-v2.Detail.Monitor.SqlDiagnosis">SQL Diagnosis</UI-TERM>** > **SlowSQL** > **<UI-TERM key="ocp-v2.Component.SQLDetail.SQLTraceTable.SqlSampling">SQL Sampling</UI-TERM>**, select to view the call chain. For more information, see [Diagnose SlowSQL](../../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/600.slowsql-diagnostics.md).

OCP V4.2.1 introduces support for end-to-end tracing configuration at the tenant and session levels. You can enable or disable it for specified objects as needed.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>By default, end-to-end tracing impacts the performance of OceanBase Database services by about 2%. It is recommended to disable this feature in performance-critical scenarios.</p>
</main>

## Prerequisites

* Ensure the current OCP user has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * Permission to access the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** menu for the tenant.

* End-to-end tracing related configurations have been enabled. For details, see [Configure link query parameters](../../1300.log-service/300.configuration-trace-paremeters.md).

## Configure end-to-end tracing for a tenant

You can enable or disable end-to-end tracing on the tenant overview page.

<main id="notice" type='explain'>
  <h4>Note</h4>
  <ul><li>A business tenant that is locked cannot have end-to-end tracing enabled (except for the sys tenant).</li><li>Having end-to-end tracing enabled (for a tenant or session) does not prevent the business tenant from being locked. The end-to-end tracing feature is disabled by default.</li><li>Having end-to-end tracing enabled (for a tenant or session) does not prevent the business tenant from being deleted.</li><li>Disabling tenant-level end-to-end tracing also disables end-to-end tracing for all sessions under the tenant.</li><li>Changes to tenant-level end-to-end tracing apply to all sessions under the tenant.</li></ul>
</main>

1. Log in to OCP.

2. In the left navigation bar, select **<UI-TERM key="ocp-v2.src.constant.plan.Tenant">Tenant</UI-TERM>**. The system enters the **<UI-TERM key="ocp-v2.page.Tenant.TenantList">Tenants</UI-TERM>** tab by default.

3. On the **<UI-TERM key="ocp-v2.page.Tenant.TenantList">Tenants</UI-TERM>** page, select the target tenant and click its name to go to the tenant **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page.

4. Click the **...** icon in the upper-right corner and select **<UI-TERM key="ocp-v2.src.component.TraceConfigModal.FullLinkDiagnosticConfiguration">End-to-end Tracing Configuration</UI-TERM>**.

    <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/OAS/%E5%85%A8%E9%93%BE%E8%B7%AF%E8%BF%BD%E8%B8%AA-2.png) -->

5. Configure the parameters.

    <!-- ![2](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/422/OAS/%E5%85%A8%E9%93%BE%E8%B7%AF%E8%BF%BD%E8%B8%AA-1.png) -->

    | Parameter | Description |
    |-----|------|
    | Tracking Level | Valid values: Level 1, Level 2, and Level 3. Level 1 is coarse-grained at the module level, and Level 3 is the finest-grained. |
    | Sampling Ratio | Default: 10%. Value range: 0–100%. |
    | Sampling Content | <ul><li>ALL: Print all sampled logs that hit the sampling threshold.</li><li>ONLY_SLOW_QUERY: Print to the log file only those slow queries that are sampled. Discard others. For this printing strategy, "slow" refers to the slow query threshold provided by the server (default value).</li><li>SAMPLE_AND_SLOW_QUERY: Print sampled slow queries (as specified in ONLY_SLOW_QUERY), and print sampled logs with a probability of one in ten thousand (as specified in ALL). In this case, you must set force flush. </li></ul> |
    | Enable/Disable | Enabled by default. If disabled, the end-to-end tracing feature is disabled. |

## Configure end-to-end tracing at the session level

You can enable or disable the end-to-end tracing feature through the end-to-end tracing configuration on the Session Management page.

* If tenant-level end-to-end tracing is enabled, you can individually disable the switch for a single session.
* Changes to session-level end-to-end tracing apply only to the current session.

Procedure:

1. Log in to OCP.

2. In the left-side navigation pane, choose **<UI-TERM key="ocp-v2.page.Information.Tenant">Tenant</UI-TERM>**. The system goes to the **<UI-TERM key="ocp-v2.component.TenantList.TenantList">Tenants</UI-TERM>** tab by default.

3. On the **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.TenantList">Tenants</UI-TERM>** page, find the target tenant and click its name to go to the tenant **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page.

4. In the left-side navigation pane of the tenant page, choose **<UI-TERM key="ocp-v2.Detail.Realtime.SessionManagement">Sessions</UI-TERM>**.

5. In the tenant session list, find the target session, and choose **<UI-TERM key="ocp-v2.src.util.component.More">More</UI-TERM>** > **<UI-TERM key="ocp-v2.src.component.TraceConfigModal.FullLinkDiagnosticConfiguration">End-to-end Tracing Configuration</UI-TERM>**.
