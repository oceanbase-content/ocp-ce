# Overview of the Tenant Details Page

On the details page of a specific tenant, you can perform operations such as deleting the tenant, adding replicas, changing the password, locking the tenant, and copying the tenant. You can also view the basic information of the current tenant, as well as view replica details, modify zone priorities, and manage allowlists.

OCP supports creating primary and standby tenants associated with each other across different clusters. When a tenant has a primary-standby relationship, note the following:

* When you modify tenant configurations, the changes may affect the synchronization efficiency between the primary and standby tenants and the performance of the tenants. It is recommended to keep the configurations of the primary and standby tenants consistent.
* When the synchronization mode between the primary and standby tenants is set to <b>Network Synchronization</b> and log archiving is not enabled for the primary tenant, there is a risk that redo logs of the primary tenant may not be synchronized to the standby database in time and may be overwritten. It is recommended to enable log archiving for the primary tenant.

## Prerequisites

Ensure the current OCP user has the following permissions:

* **Cluster Read-Only** or **Tenant Read-Only** resource permission.
* Permission to access the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** menu.

* Click the copy button next to **<UI-TERM key="ocp-v2.Detail.Capacity.TenantName">Tenant Name</UI-TERM>** to copy the tenant name.

* Click **<UI-TERM key="ocp-v2.Detail.Report.ViewReports">View</UI-TERM>** next to **Tenant Connection String** to manage the connection string in a pop-up window.

  * Copy connection string: After an OBProxy is associated with the tenant's cluster, click the copy button on the right side of the connection string to use it for connection.

  * Add/delete custom connection strings: Click **<UI-TERM key="ocp-v2.component.ZoneFormCardList.Add">Add</UI-TERM>** at the bottom of the connection string list to customize tenant connection string information, facilitating unified management of tenant addresses. When a custom connection string is no longer applicable, click **<UI-TERM key="ocp-v2.Settings.Credential.OBProxy.Delete">Delete</UI-TERM>** in the Actions column to remove it.

  * Associate OBProxy cluster: Click **Associate OBProxy Cluster** to go to the overview page of the tenant's cluster and associate an OBProxy cluster with it. Additionally, for primary and standby tenants, the system supports **<UI-TERM key="ocp-v2.Component.ServiceName.ServiceNameModal.ChangeTheServiceNameOfTheActiveAnd">Sync Service Names of Primary and Standby Tenants</UI-TERM>**.

## View primary-standby tenant relationship

View the details of the primary-standby relationship of a tenant, including information such as **<UI-TERM key="ocp-v2.src.constant.tenant.MasterTenant">Primary Tenant</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Component.PrimaryAndBackupTenantList.StandbyTenant">Standby Tenant</UI-TERM>**, **<UI-TERM key="ocp-v2.pages.PlatformMonitor.Status">Status</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Component.PrimaryAndBackupTenantList.SynchronousMode">Synchronization Method</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.ProtectionMode.PrimaryAndSecondaryProtectionMode">Primary-Standby Protection Mode</UI-TERM>**, **<UI-TERM key="ocp-v2.HeaderExtra.TenantSwitchModal.useColumns.ProtectionLevel">Protection Level</UI-TERM>**, and **Log Latency**.

* The **<UI-TERM key="ocp-v2.Host.Detail.Basic.State">Status</UI-TERM>** of primary-standby synchronization is divided into the following five categories:

  * **<UI-TERM key="ocp-v2.src.constant.tenant.NormalSynchronization">Normal Synchronization</UI-TERM>**: Primary-standby synchronization is running normally, and data is continuously synchronized from the primary tenant.
  * **<UI-TERM key="ocp-v2.src.constant.tenant.SynchronizationException">Synchronization Error</UI-TERM>**: Abnormal conditions such as the OceanBase version of the primary tenant being later than that of the standby tenant, the primary tenant being deleted, the log source being inaccessible, or the log source being unreachable.
  * **<UI-TERM key="ocp-v2.src.constant.tenant.LogConflict">Log Conflict</UI-TERM>**: Conflicts occur between restored logs and those in the standby tenant. The logs in the standby tenant and at the log source are inconsistent at the same LSN.
  * **<UI-TERM key="ocp-v2.src.constant.tenant.SynchronizationPause">Synchronization Suspended</UI-TERM>**: Primary-standby synchronization is actively paused.
  * **<UI-TERM key="ocp-v2.src.constant.tenant.LogMissing">Logs are missing.</UI-TERM>**: Logs at the log source are missing.

* Click **<UI-TERM key="ocp-v2.Overview.components.MasterSlaveTenantListCard.ChangeTheActiveStandbyProtection">Change Primary-Standby Protection Mode</UI-TERM>** in the upper-right corner to change the primary-standby protection mode. For more information, see [Change the primary-standby protection mode](620.change-protection-mode.md).

* Click **<UI-TERM key="ocp-v2.Detail.Component.PrimaryAndBackupTenantList.ViewDelay">View Latency</UI-TERM>** in the Actions column to view the historical log synchronization latency. By default, the system displays the latency data for the last hour. You can customize the time range to view by using the time filter.

* Click **Pause Synchronization/Resume Synchronization** in the Actions column to pause or resume the synchronization between the primary and standby tenants.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>The <b>Primary-standby Tenant Relationship</b> data is displayed only if the tenant has a primary-standby relationship and the cluster to which the tenant belongs is V4.2.0.0 or later. Some of this information or actions are displayed only when specific conditions are met, as follows:
<li><b>View Latency</b>: The cluster version of the tenant must be [V4.2.0.0, ~).</li>
<li><b>Pause Synchronization/Resume Synchronization</b>: The cluster version of the tenant must be [V4.2.0.0, ~), and the primary-standby protection mode must be <b>Maximum Performance</b>.</li>
<li><b>Primary-standby Protection Mode/Protection Level</b>: The cluster version of the tenant must be [V4.4.2.1, V4.5.0.0) or [V4.6.2.0, ~).</li>
<li><b>Change Primary-standby Protection Mode</b>: The tenant must be a normally running primary tenant, and the cluster version of the tenant must be [V4.4.2.1, V4.5.0.0) or [V4.6.2.0, ~).</li></p>
</main>
