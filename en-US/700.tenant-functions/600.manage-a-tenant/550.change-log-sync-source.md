# Change the synchronization configuration

In disaster recovery scenarios such as primary-standby and cascading setups, OCP supports freely switching the synchronization configuration for a standby tenant. This facilitates cross-region switchover drills and enhances the relationship management capability between primary and standby tenants.

This section provides detailed instructions on how to change the synchronization configuration for a standby tenant.

## Prerequisites

* Only normally running standby tenants support changing the synchronization configuration.

* Ensure the current OCP user has at least the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * Permission to access the **Overview** menu of the tenant.

* Ensure the primary-standby protection mode of the current tenant is set to **Maximum Performance**.

## Background information

When changing the synchronization configuration for a standby tenant, the following restrictions apply to the selected new source tenant:

* The new source tenant can be any upstream tenant, peer tenant, or downstream tenant at the same level as the current standby tenant, but downstream tenants of the current standby tenant cannot be selected.
* When the synchronization method between primary and standby tenants is **Archived-Based**, the new source tenant must have archive backup enabled. If its archive information is incomplete, manual supplementation is required when changing the synchronization configuration.
* Before changing the synchronization configuration, ensure the consistency of logs between the primary and standby tenants; otherwise, the primary-standby relationship may not be established.

## Procedure

1. Log in to OCP.

2. In the left navigation bar, select **<UI-TERM key="ocp-v2.Alarm.Event.Detail.Tenant">Tenant</UI-TERM>**. The system enters the **<UI-TERM key="ocp-v2.component.TenantList.TenantList">Tenants</UI-TERM>** page by default.

3. Select the standby tenant to operate on and click its name to enter the tenant's **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page.

4. Click the **...** icon in the upper-right corner and select **Change Synchronization Configuration**.

5. In the dialog box that appears, select a new source tenant and a synchronization method, and confirm whether the new tenant topology meets expectations.

    * **<UI-TERM key="ocp-v2.src.constant.tenant.NetworkBased">Network-based Synchronization</UI-TERM>** synchronizes logs over the RPC network between OBServer nodes. The standby tenant can directly read the primary tenant's logs via `IP + port`.
    * **Archived-Based** synchronizes logs through shared storage. The primary tenant writes logs to network disks or OSS storage, and the standby tenant reads data from the shared storage.

6. Click **<UI-TERM key="ocp-v2.Component.StorageConfigCard.Test">Test</UI-TERM>** to verify whether the log backup information of the new source tenant is complete.

    * If the test passes, proceed to the next step.
    * If the test fails, refine the relevant configuration as prompted on the page. After configuration, retest.

7. Click **<UI-TERM key="ocp-v2.AIModel.Component.LinkAiModel.Save">Save</UI-TERM>**.

8. Confirm whether the primary and standby logs are consistent. If they are, click **<UI-TERM key="ocp-v2.component.OperationConfig.ModifyAgentConfig.Change">Change</UI-TERM>**.
