# Enable Asymmetric Zone

Enabling asymmetric zone allows you to flexibly configure the number of replicas across different zones, reducing scaling costs during promotional events and alleviating unit traffic anomalies caused by zone-level failures.

This topic describes how to enable asymmetric zone for a tenant in OCP. Once enabled, asymmetric zone cannot be disabled; proceed with caution.

## Prerequisites

* Ensure the current OCP user has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * Permission to access the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** menu for the tenant.

* Ensure the current tenant is not the `sys` tenant.

## Considerations

* Asymmetric zone can only be enabled if the tenant's cluster version is one of the following; if the cluster version is V3.x, asymmetric zone is automatically supported by default and does not need to be manually enabled.

  * [V4.2.5.5, V4.3.0.0)
  * [V4.4.2.0, V4.5.0.0)

* To control the number of log streams and reduce the computational complexity of scaling, under the asymmetric zone architecture, the number of full-featured replica units for a tenant in each zone cannot exceed two types.

## Procedure

1. Log in to OCP.

2. In the left navigation bar, select **<UI-TERM key="ocp-v2.src.constant.plan.Tenant">Tenant</UI-TERM>**. The system defaults to the **<UI-TERM key="ocp-v2.page.Tenant.TenantList">Tenants</UI-TERM>** tab.

3. On the **<UI-TERM key="ocp-v2.page.Tenant.TenantList">Tenants</UI-TERM>** page, find the target tenant and click its name to go to the tenant **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page.

4. Click the **...** icon in the upper-right corner and select **Enable Asymmetric Zone**.

5. In the dialog box that appears, click **<UI-TERM key="ocp-v2.Alarm.Channel.Detail.Enable">Enable</UI-TERM>**.
