# ob_server_sstable_percent_over_threshold OceanBase server data disk usage over threshold

## Description
------------------------------------

This alert is triggered when the proportion of data disk space used for storing data files on an OBServer exceeds the threshold.
<main id="notice" type='explain'>
<h4>Note</h4>
<p>By default, the data disk is mounted to the <code>/data/1</code> directory.</p>
</main>
  </main>

When you create an OceanBase cluster, the data disk is initialized and the size of disk space for storing data files is specified.
## Principle
Principle
------------------------------

|     Parameter     |   Value      |
|-------------------|-----------|
| Metric            | ob_server_disk_percent, which indicates the data disk usage of the OBServer. When this value exceeds the threshold, this alert is triggered.    |
| Metric expression | ```100 * (sum(ob_disk_total_bytes{@LABELS}) by (@GBLABELS) - sum(ob_disk_free_bytes{@LABELS}) by (@GBLABELS)) / sum(ob_disk_total_bytes{@LABELS}) by (@GBLABELS)``` |
| Collected metric  | ob_disk_total_bytes and ob_disk_free_bytes   |
| Source            | Collected from internal views. The collection SQL is as follows:<ul><li>For OceanBase Database V4.0 and earlier: ```select /*+ MONITOR_AGENT READ_CONSISTENCY(WEAK) */ total_size, free_size from __all_virtual_disk_stat where svr_ip = ? and svr_port = ?```</li><li>For OceanBase Database V4.0 and later: ```select /* MONITOR_AGENT */ data_disk_capacity, (data_disk_capacity - data_disk_in_use) as data_disk_in_free, log_disk_capacity, log_disk_assigned, log_disk_in_use from V$OB_SERVERS where svr_ip = ? and svr_port = ?```</li></ul>  |
| Collection cycle  | 5 seconds    |
| Metric expression | 100 \* (sum(total_size{metric_group="all_virtual_disk_stat",@LABELS}) by (@GBLABELS) - sum(free_size{metric_group="all_virtual_disk_stat",@LABELS}) by (@GBLABELS)) / sum(total_size{metric_group="all_virtual_disk_stat",@LABELS}) by (@GBLABELS) |
## Alert rule

|     Metric       | Default threshold (unit: %) | Duration  | Detection cycle | Elimination cycle |
|--------------------|--------------------|----------|----------|---------|
| ob_disk_percent    | <li>ob_disk_percent > 97</li><li>ob_disk_percent > 85</li>  | 0 seconds  | 20 seconds | 5 minutes |

## Alert information
| ob_disk_percent{app="OB"} | 85                          | 0 seconds | 60 seconds      | 5 minutes         |

|---------------------------------------|-------------|--------|
| Based on the expression of the metric | <li>ob_disk_percent > 97: Critical</li><li>ob_disk_percent > 85: Warning</li>   | Host |

## Alert templates
|---------------------------------------|-------------|--------|
| Based on the expression of the metric | Critical    | Server |

**Alert templates**
----------------------------------------

* **Overview**
  * Template: \${alarm_target} \${alarm_name}
  * Example: ob_cluster=obcluster-1:svr_ip=xxx.xxx.xxx.xxx Excessive data disk usage of the OceanBase server

* **Details**
  * Template: Cluster: \${ob_cluster_name}, Host: \${host}, Alert: \${alarm_name}. The data disk usage is \${value_shown}%, exceeding the threshold of \${alarm_threshold} %.
  * Example: Cluster: obcluster-1, Host: xxx.xxx.xxx.xxx, Alert: Excessive data disk usage of the OceanBase server. The data disk usage is 86.0%, exceeding the threshold of 85.0%.

* **Alert recovery**
  * Template: Alert: ${alarm_name}, OceanBase Server data disk usage: \${value_shown}
  * Example: Alert: Excessive data disk usage of the OceanBase server, OceanBase Server data disk usage: 80%

## Impact on the system
---------------------------------------------

If the data disk space is insufficient, new data cannot be written to the data disk.

## Resolution

**Suggested solutions**
--------------------------------------------

Perform the following steps to solve the problem:

1. Delete unwanted tenants, databases, and tables.

2. Empty the recycle bin, and perform two cluster compaction tasks to release resources.

3. Migrate units to another OBServer. If no other OBServer is available, add OBServers to scale out the cluster.

Run the following SQL commands to view the table storage space of a tenant:

```sql
-- Specify the tenant ID.
set @tenant_id=1001

-- Applies to OceanBase 1.x
select  b.table_name,sum(a.required_size)/1024/1024/1024 required_GB,sum(row_count) as rows from __all_meta_table a, __all_table b where a.table_id = b.table_id and a.zone = 'zone_name' and a.tenant_id = @tenant_id group by a.table_id order by required_GB desc;

-- Applies to OceanBase 2.x and 3.x
select c.database_name, b.table_name,sum(a.required_size)/1024/1024/1024  required_GB,sum(row_count)  as  rows  from  __all_virtual_meta_table  a inner join  __all_virtual_table  b on a.table_id=b.table_id inner join __all_virtual_database c on b.database_id=c.database_id where b.table_type<>5 and a.zone  =  'zone_name'  and  a.tenant_id  = @tenant_id group  by  a.table_id  order  by required_GB  desc;
```
