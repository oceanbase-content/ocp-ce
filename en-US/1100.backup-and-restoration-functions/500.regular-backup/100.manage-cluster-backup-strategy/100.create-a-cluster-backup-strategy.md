# Create a cluster-level backup policy

Cluster-level backup policies apply only to tenants that have not configured a tenant-level backup policy. You can configure a cluster-level backup policy for such tenants to enable unified management.

You can create a cluster-level backup policy through any of the following three methods:

* **Method 1**: Log in to OCP, go to **Backup and Recovery > Backup**, and select **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>** from the **<UI-TERM key="ocp-v2.Backup.Overview.Welcome.CreateABackupPolicy">New Backup Strategy</UI-TERM>** drop-down list in the upper-right corner of the page.

* **Method 2**: Log in to OCP, go to the cluster **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page, select **<UI-TERM key="ocp-v2.src.constant.package.BackupAndRestoration">Backup & Restore</UI-TERM>** from the left navigation pane, and click **<UI-TERM key="ocp-v2.Detail.Backup.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>**.

* **Method 3**: Log in to OCP, go to the tenant **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page, select **<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">Backup & Restore</UI-TERM>** from the left navigation pane, and click **<UI-TERM key="ocp-v2.Backup.BackupStrategy.New.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>**.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>You can use <b>Method 3</b> to create a cluster-level backup policy only when neither the tenant nor its cluster has a backup policy.</p>
</main>

## Prerequisites

* When creating a cluster-level backup strategy via **Entry 1**, ensure the current OCP user has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * Backup and Restore **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.Backup">Backup</UI-TERM>** menu permissions.

* When creating a cluster-level backup strategy via **Entry 2**, ensure the current OCP user has the following permissions:

  * **Cluster Maintenance** resource permissions.
  * Cluster **<UI-TERM key="ocp-v2.src.util.menu.BackupAndRestoration">Backup</UI-TERM>** menu permissions.

* When creating a cluster-level backup strategy via **Entry 3**, ensure the current OCP user has the following permissions:

  * **Cluster Maintenance** or **Tenant Maintenance** resource permissions.
  * Tenant **<UI-TERM key="ocp-v2.Backup.Guide.BackupAndRestoration">Backup & Restore</UI-TERM>** menu permissions.

* OceanBase does not support backing up tenants that are locked.

## Procedure

The following steps use **Entry 1** as an example.

1. In the left navigation bar, click **<UI-TERM key="ocp-v2.Detail.Backup.BackupAndRestoration">Backup & Restore</UI-TERM>** **\>** **<UI-TERM key="ocp-v2.src.constant.backup.Backup">Backup</UI-TERM>**.

2. On the **<UI-TERM key="ocp-v2.Component.BackupStrategyCard.Backup">Backup</UI-TERM>** page, hover the cursor over **<UI-TERM key="ocp-v2.src.constant.backup.CreateABackupPolicy">New Backup Strategy</UI-TERM>** and click **<UI-TERM key="ocp-v2.Backup.AddClusterStrategy.CreateAClusterLevelBackupPolicy">Create Cluster-level Backup Strategy</UI-TERM>**.

3. Select the backup cluster from the drop-down list.

   * If the backup cluster version is earlier than V2.2.60, the backup method is **<UI-TERM key="ocp-v2.Backup.Component.BackupNowDrawer.LogicalBackup">Logical Backup</UI-TERM>**.

   * If the backup cluster version is V2.2.60 or later, the backup method is **<UI-TERM key="ocp-v2.src.constant.backup.PhysicalBackup">Physical Backup</UI-TERM>**.

4. Configure the storage settings by specifying the following parameters, then click **<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">Test</UI-TERM>**.

   * For logical backup, select the storage configuration configured in [Install Service](../../1000.manage-backup-and-recovery-service/200.installation-services.md).

     If the backup service is not installed, you must install it first. For installation instructions, see [Install Service](../../1000.manage-backup-and-recovery-service/200.installation-services.md).

   * For physical backup, you can customize the configuration or select an existing one. When customizing, refer to the parameters below; when selecting an existing configuration, click **<UI-TERM key="ocp-v2.Backup.Component.StorageConfigDropdown.SelectAnExistingConfiguration">Select Existing Configuration</UI-TERM>** to automatically populate the following parameters.

The default is **Same as data backup**, which means using the same storage configuration as data backup. If you need to use a different storage path, select **Configure separately** and set it up as described above for data backup storage.

5. Configure the scheduling settings.

   * Schedule Cycle: Choose weekly or monthly. When the schedule cycle is monthly, you can select at most 10 days.

   * After disabling log backup for physical backup, the system starts log backup before data backup begins and shuts it down after data backup completes.

   <main id="notice" type='explain'>
   <h4>Note</h4>

   </main>
