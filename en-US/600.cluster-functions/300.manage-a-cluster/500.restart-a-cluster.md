# Restart the cluster

You can restart the observer processes of all nodes or those in some zones in the cluster as needed.

## Prerequisites

* You have logged in to the OCP console. You have the following permissions:

  * **Cluster Maintenance** permissions.
  * Permissions to access the **Cluster** menu.

* The OceanBase cluster to be restarted is a multi-replica cluster with at least three replicas. In this way, the OceanBase cluster will be restarted in rotation without interrupting the business.

  If the OceanBase cluster has less than three replicas, the business will be interrupted during the restart. We recommend that you proceed with caution.

* You can only perform a **forced restart** on a standalone or centralized database.

## Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, find the target cluster and click its name.

4. On the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page of the cluster, click the **More** icon in the upper-right corner and select **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.RestartTheCluster">Restart Cluster</UI-TERM>**.

5. In the dialog box that appears, configure the restart settings and click **<UI-TERM key="ocp-v2.src.constant.obproxy.Restart">Restart</UI-TERM>**.

   * Select the restart scope: **<UI-TERM key="ocp-v2.Auth.Role.util.All">All</UI-TERM>**, a specific zone, or multiple zones.

     * If you select **<UI-TERM key="ocp-v2.Alarm.LogFilter.All">All</UI-TERM>**, the observer process on all nodes in the cluster will be restarted.

     * If you select one or more zones, the observer process in these zones will be restarted.

   * Select the restart mode: **<UI-TERM key="ocp-v2.Component.BinlogInstanceList.Restart">Restart</UI-TERM>** or **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.ForceRestart">Force Restart</UI-TERM>**.

     * Restart: The business access is not interrupted.

     * Force Restart: The business access is interrupted, causing service unavailability.

   * Specify whether to perform a minor compaction before stopping the process (the default). Performing a minor compaction before stopping the process increases the response time but significantly reduces the recovery time of the OBServer node.

   ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/421/%E9%87%8D%E5%90%AF%E9%9B%86%E7%BE%A4.png)

6. After you submit the restart task, you can click **<UI-TERM key="ocp-v2.src.constant.ViewTasks">View Tasks</UI-TERM>** in the pop-up dialog box to view the restart progress.

   You can also view the task progress in **<UI-TERM key="ocp-v2.Layout.BasicLayout.TaskCenter">Task Center</UI-TERM>**.

   When the task status changes to **<UI-TERM key="ocp-v2.page.Overview.Complete">Completed</UI-TERM>** and the status of the **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** column on the **<UI-TERM key="ocp-v2.Component.ZoneList.ZoneList">Zones</UI-TERM>** page of the cluster is **<UI-TERM key="ocp-v2.Detail.Log.TaskGraph.Running">Running</UI-TERM>**, the restart is successful.
