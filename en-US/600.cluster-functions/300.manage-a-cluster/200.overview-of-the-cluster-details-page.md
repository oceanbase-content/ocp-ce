# View cluster details

On the specific cluster page, you can view the basic information, resource usage, alert overview, system events in the last 7 days, zone list, OBServer list, and arbitration service list of the current cluster. You can also perform routine maintenance operations on the cluster.

## Prerequisites

Ensure the current OCP user has the following permissions:

* **Cluster Read-Only** resource permission.
* Permission to access the cluster **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** menu.

## View basic information

On the cluster overview page, you can view basic cluster information, including **Cluster Name, Cluster ID, Cluster Type, OceanBase Version Number, Number of Regions, Deployment Mode, CPU Architecture, Cgroup Configuration, CPU Overcommitment, Number of Machines, Load Type, Number of Partitions, Number of Tenants, Creator, Start Time, Online Duration, OBProxy Cluster, Protection Mode, Software Installation Path, Data Disk Path**, **ConfigUrl**, and **<UI-TERM key="ocp-v2.page.Host.Label">Tag</UI-TERM>**.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>For an AI cluster (shared storage), the **<UI-TERM key="ocp-v2.Cluster.New.DataDiskPath">Data Disk Path</UI-TERM>** field displays as **Cache Disk Path**, and additional object storage-related information such as **Object Storage Type** and **Bucket URI** is displayed.</p>
</main>

## View resource utilization

In the resource utilization section, you can view the current cluster's **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedCpu">CPU</UI-TERM>**, **<UI-TERM key="ocp-v2.Resource.Component.Block.AllocatedMemory">Memory</UI-TERM>**, and **<UI-TERM key="ocp-v2.Cluster.Component.WaterLevel.DiskUsed">Data Disk Used</UI-TERM>**. You can manage the cluster based on its current resource utilization.

<main id="notice" type='explain'>
<h4>Note</h4>
<p><li>If CPU overcommitment is enabled for the cluster, the maximum and minimum allocated CPU cores are displayed in the resource utilization section.</li><li>For an AI cluster (shared storage), <b>Data Disk Used</b> is displayed as <b>Cache Disk Used</b>, reflecting the usage of the local cache disk.</li></p>
</main>

## View system events from the last 7 days

In **<UI-TERM key="ocp-v2.Detail.Component.Event.SystemEventsInTheLast">System Events in Last 7 Days</UI-TERM>**, you can set query conditions as needed to view system events from the past seven days.

* You can set the search time at position ① in the figure.

* You can set the event name to search for at position ② in the figure.

* You can set the module to search for at position ③ in the figure.

* You can sort events in ascending or descending order by start time at position ④ in the figure.

The system will display the system events you want to view in the list based on the conditions you have set.

## View the OBServer list

In the OBServer list, you can view information about each OBServer node, including **IP Address, SQL Port, RPC Port, Zone, Host Type, Start Time, Online Duration, Resource Usage (CPU, Memory, Log Disk, Data Disk)**, and **<UI-TERM key="ocp-v2.Host.Detail.Basic.State">Status</UI-TERM>**.

* When an OBServer node is unavailable, hover your cursor over the unavailable icon to view the duration, cause, and suggested solution for its unavailability.

* You can perform operations such as **Restart, Stop Service, Stop Process, Reinstall, Replace, Delete**, and **<UI-TERM key="ocp-v2.Detail.Log.LogCard.DownloadLogs">Download Logs</UI-TERM>** on an OBServer node. For more information, see [Restart an OBServer node](../600.manage-an-observer/200.restart-observer.md), [Stop an OBServer service](../600.manage-an-observer/300.stop-observer-service.md), [Stop an OBServer process](../600.manage-an-observer/400.stop-observer-process.md), [Reinstall an OBServer node](../600.manage-an-observer/600.reinstall-observer.md), [Replace an OBServer node](../600.manage-an-observer/500.replace-observer.md), [Delete an OBServer node](../600.manage-an-observer/700.delete-observer.md), and [Download logs](../../1300.log-service/200.download-log.md).

## Protection Modes

<main id="notice" type='explain'>
<h4>Note</h4>
<p>The protection mode applies only to traditional clusters (in shared-nothing mode). AI clusters (in shared-storage mode) do not support primary/standby architecture.</p>
</main>

* Maximum Performance: Ensures maximum performance of the primary cluster while protecting user data. In this mode, log transmission between all standby clusters and the primary cluster is asynchronous.

* Maximum Availability Mode: Normally, one and only one standby cluster maintains synchronous log transmission with the primary cluster.

* Maximum Protection Mode: One and only one standby cluster maintains synchronous log transmission with the primary cluster; other standby clusters use asynchronous log transmission.
