# View the cluster tenant management overview

You can view the resource distribution information, tenant list, and top 5 tenant monitoring metrics of all tenants in the clusters you manage.

## Prerequisites

Ensure that the current OCP user has the following permissions:

* **Cluster Read-only** resource permission.
* Permission to access the **<UI-TERM key="ocp-v2.Detail.Tenant.TenantManagement">Tenant Management</UI-TERM>** menu.

## Procedure

1. Log in to OCP.

2. In the left navigation bar, click **<UI-TERM key="ocp-performance-report.ReportTables.LockStatInfo.LatchStatTable.Cluster">Cluster</UI-TERM>**. The system enters the **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** tab by default.

3. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, select the target cluster and click its name to go to the cluster **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page.

4. In the left navigation bar of the displayed page, click **<UI-TERM key="ocp-v2.Detail.Tenant.TenantManagement">Tenant Management</UI-TERM>** to enter the **<UI-TERM key="ocp-v2.Detail.Tenant.TenantManagement">Tenant Management</UI-TERM>** page.

5. Click **<UI-TERM key="ocp-v2.Cluster.Detail.NewTenant">Create Tenant</UI-TERM>** to create a new tenant for the cluster. For details, see [Create a tenant](../700.tenant-functions/300.create-a-tenant.md).

6. In the **<UI-TERM key="ocp-v2.Detail.Capacity.OverviewOfCapacityUsage">Capacity Usage Overview</UI-TERM>** section, view the resource distribution information.

   The resource distribution information mainly includes the percentage of CPU, memory, log disk, and data disk resources occupied by each tenant in the cluster, as well as the percentage of remaining CPU, memory, log disk, and data disk resources for the system.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <ul>
   <li>When the cluster is an AI cluster (shared storage), <b>Data Disk</b> is displayed as <b>Cache Disk</b>, reflecting the allocation and usage of local cache disk resources.</li>
   <li>Currently, viewing data usage on object storage for AI clusters or Logservice clusters in OCP is not supported. It is recommended to check the specific usage in the cloud vendor's object storage console.</li>
   </ul>
   </main>

   Hover the cursor over a tenant's position in the pie chart to display the specific resource values occupied by that tenant. Click the **<UI-TERM key="ocp-v2.Detail.Capacity.ViewUsageTrends">View Trends</UI-TERM>** button in the upper-right corner of **<UI-TERM key="ocp-v2.Component.OBServerList.Disk">Data Disk</UI-TERM>** to filter data disk usage trends within a specific time period.

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p><ul><li>When CPU overprovisioning is enabled for the cluster to which a tenant belongs, the maximum and minimum allocated CPU cores for each tenant in the cluster are displayed in <b>Capacity Usage Overview</b>.</li><li>Viewing <b>Log Disk</b> data is not supported when OceanBase Database is version earlier than V4.0.</li><li>When the cluster is an AI cluster (shared storage), <b>Data Disk</b> is displayed as <b>Cache Disk</b>.</li></ul></p>
   </main>

7. In the **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.TenantList">Tenants</UI-TERM>** section, view the basic information of all tenants, including the tenant name, tag, OceanBase version number, tenant mode, zone priority, read-only status, lock status, status, and creation time.

   * Hover the cursor over a tenant tag to view all tag information for that tenant. You can click the edit icon to manage tags. For more information, see [Manage tags](../1600.system-management-features/300.manage-tags/100.tags-overview.md).
   * You can lock and clone a tenant. For more information, see [Lock a tenant](../700.tenant-functions/600.manage-a-tenant/300.locked-a-tenant.md) and [Clone a tenant](../700.tenant-functions/600.manage-a-tenant/350.clone-a-tenant.md).

8. In the **Top 5 Tenants by Performance** section, you can view the performance metrics of the top 5 tenants with the highest workload in the current cluster, including QPS, TPS, SQL response time, transaction response time, number of sessions, event wait_count, event wait_time, capacity_tables, and capacity_partitions. You can also view the monitoring information for the last hour, last day, or last week based on your business needs.

   <!-- ![18](https://help-static-aliyun-doc.aliyuncs.com/assets/img/zh-CN/4772988061/p200735.png) -->

   The following table describes the performance monitoring metrics.

   | Metric | Description | Data source |
   |----------|----------------------|---------------------------|
   | QPS | The average number of SQL statements processed per second. | v$sysstat |
   | TPS | The average number of transactions processed per second. | v$sysstat |
   | SQL Response Time | SQL response time (μs). | v$sysstat |
   | Transaction Response Time | The average processing time per server transaction (μs). | v$sysstat |
   | Number of Sessions | The number of active sessions and the total number of sessions. | __all_virtual_processlist |
   | Event Wait Count | The average number of events waited for per second. | v$system_event |
   | Event Wait Time | The average wait time for each event (μs). | v$system_event |
   | Capacity Tables | The number of tables. | gv$table |
   | Capacity Partitions | The number of partitions. | v$partition |
