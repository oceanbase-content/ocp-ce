# Manage TDE transparent encryption

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not support this feature. </p>
</main>

OceanBase Database supports transparent data encryption (TDE) at the data storage layer.

TDE transparent encryption encrypts sensitive data stored on disks. Data is automatically encrypted before it is written to a storage device and automatically decrypted when it is read. This process is transparent to users, and authenticated users can access the data without restrictions. If a storage medium is stolen, TDE ensures that sensitive data on the medium cannot be accessed by unauthenticated users. Even if the storage medium is lost, the data remains protected, maximizing the security of user data.

This topic describes how to enable TDE transparent encryption and how to create a tablespace for a tenant.

## Enable TDE transparent encryption<a id="parameter"></a>

This topic describes how to enable TDE transparent encryption for a cluster.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Once TDE transparent encryption is enabled, it cannot be disabled. Enabling TDE transparent encryption may degrade database performance. To decrypt the data, you must move the tables out of the encrypted tablespace and perform a full compaction. </p>
</main>

### Prerequisites

* The user logging in to OCP has the **ADMIN** or **ORG_ADMIN** role.
* The status of the tenant to be encrypted is **Running**.
* If you use a key provided by OCP, the OceanBase cluster must be of V4.x or later.
* If you use a key provided by a third-party vendor, the OceanBase cluster must meet the following version requirements:
  * [V4.2.5.4, V4.3.0)
  * [V4.3.5.2, +∞)
* If you use a key provided by **Koal**, you must configure the following parameters based on the service type:
  * **Standard**: Set both <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> to false.
  * **Password**: Set both <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> to true.
  For more information about the parameters, see **Parameter description**.

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.constant.alarm.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** list, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page.

4. In the left-side navigation pane of the page that appears, click **<UI-TERM key="ocp-v2.Detail.Security.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. Click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Select the tenant for which you want to enable encryption and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.TurnOnEncryption">Enable Encryption</UI-TERM>** in the Actions column.

7. In the dialog box that appears, select the key type.

   * If you use a key provided by OCP, select the key automatically generated by OCP.
   * If you use a key provided by a third-party vendor, select the key managed by KMS. The following table describes the key information that you need to configure.

      | Parameter | Description |
      |-----------|---------|
      | Cloud Vendor | The cloud vendor. Valid values: **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.AlibabaCloud">Alibaba Cloud</UI-TERM>**, **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**, and **Koal**.  |
      | Service Type | The service type. Valid values: **Standard** and **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Password">Password</UI-TERM>**. <ul><li>**Standard**: The KMS standard service version must be 2.0 or later. </li><li>**<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Password">Password</UI-TERM>**: The KMS password service version must be 3.2.0 or later.   |
      | Access Domain | The endpoint of KMS.  |
      | AK        | The access key ID for signature authentication. |
      | SK        | The access key secret for signature authentication. |
      | SK Version | The version of the SK. This parameter is required only when the cloud vendor is **Koal** and the service type is **<UI-TERM key="ocp-v2.component.common.ObUserSelect.Password">Password</UI-TERM>**.   |
      | Master Key ID | The ID of the user master key.   |
      | Region      | The region of KMS. This parameter is required only when the cloud vendor is **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**.  |

8. Click **<UI-TERM key="ocp-v2.component.OperationConfig.List.Enable">Enable</UI-TERM>**.

### Parameter description

| Parameter  | Description  | Effective after restart  |
|-------|-------|--------------------|
| <code>ocp.kms.tde.koal.useTLS.enabled</code>  | Specifies whether to use the Transport Layer Security (TLS) protocol for Koal KMS encryption. This parameter is stored in the <code>config_properties</code> table of the OCP MetaDB and defaults to <code>false</code>. If the endpoint is <code>https</code>, set the parameter to <code>true</code>.  | No  |
| <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> | Specifies whether to use the kcsp version for Koal KMS encryption. This parameter can be configured in the OCP console under **System Management** > **System Parameters**, and the default value is <code>true</code>.  | No  |

## Create a tablespace

OceanBase Database allows you to enable transparent data encryption (TDE) at the tablespace level to ensure data security.

### Prerequisites

* You have logged in to the OCP console as the **ADMIN** or **ORG_ADMIN** role.
* The OceanBase cluster is of V4.x or later.
* TDE is enabled. For more information, see [Enable TDE](#parameter).

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.page.Overview.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** list, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.src.hook.useMenu.Overview">Overview</UI-TERM>** page.

4. In the left-side navigation pane of the page that appears, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. Click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Find the target tenant and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.CreateTableSpace.CreateATablespace">Create Tablespace</UI-TERM>** in the Actions column.

7. In the dialog box that appears, specify the following information.

   | Parameter | Description |
   |--------|---------|
   | Encrypted Tablespace Name  | You can create multiple encrypted tablespaces in the same tenant. Each tablespace name must be unique. The name must start with a letter and can contain letters, digits, and underscores. The name must be 2 to 30 characters in length.  |
   | Encryption Algorithm      | After you set the encryption algorithm, you cannot modify it or convert it to another type. OceanBase Database of different versions support different encryption algorithms. For more information, see the official documentation of OceanBase Database.  |

8. Specify the encrypted tablespace name and encryption algorithm, and click **<UI-TERM key="ocp-v2.src.constant.iam.Create">Create</UI-TERM>**.

9. After you enable TDE and create an encrypted tablespace, you need to execute DDL operations to create an encrypted table before you can encrypt data. The following example shows how to create an encrypted table:

   ```sql
   CREATE TABLE t1 (id int,id2 int) TABLESPACE sectest_ts1;
   ```

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>After you add a historical table to an encrypted tablespace, you must execute a major compaction to persist the encrypted data. Otherwise, the historical table data cannot be encrypted. </p>
   </main>

10. You can click the name of the encrypted tablespace to view details such as the tenant to which it belongs, the name of the encrypted table, the encryption status, and the encryption progress in the right-side panel. The encryption progress indicates the percentage of data blocks that have been encrypted in the current data table.
