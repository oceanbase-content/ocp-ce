# Manage TDE

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not provide this feature.</p>
</main>

OceanBase Database supports encryption at the data storage layer, namely Transparent Data Encryption (TDE).

TDE encrypts sensitive data stored on disks. Data is automatically encrypted before being written to storage devices and decrypted automatically when read. This process is transparent to users, and authenticated database users can access data without restrictions. If a storage medium is stolen, TDE ensures that sensitive data stored on it cannot be accessed by unauthorized users. Even if a storage medium is lost, data loss can still be prevented, maximizing the protection of user data security.

This topic describes how to enable TDE and create tablespaces for tenants.

## Enable TDE

You can refer to this section to enable TDE for a cluster.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Once TDE is enabled, it cannot be disabled and may degrade database performance. If decryption is required later, move the table out of the encrypted tablespace and perform a full compaction.</p>
</main>

### Prerequisites

* Ensure the current OCP user is in the **ADMIN** or **ORG_ADMIN** role.
* The tenant to be encrypted is in the **RUNNING** state.
* When using an OCP-provided key, ensure the OceanBase cluster is version V4.x or later.
* When using a third-party vendor key, ensure the OceanBase cluster meets one of the following version requirements:
  * [V4.2.5.4, V4.3.0)
  * [V4.3.5.2, +∞)
* When using a key provided by the third-party vendor **Geer**, configure the following parameters in advance based on the service type:
  * **Standard Edition**: Set both the <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> parameter values to false.
  * **Password**: Set both the <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> parameter values to true.
  For more information about the parameters, see the **Parameter description** section in this topic.

### Procedure

1. Log in to OCP.

2. In the left navigation bar, click **<UI-TERM key="ocp-v2.component.ParameterTemplate.Cluster">Cluster</UI-TERM>**. The system goes to the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page by default.

3. On the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** page, find the target cluster and click its name to go to the cluster **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page.

5. Switch to the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Select the tenant for which you want to enable encryption and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TurnOnEncryption">Enable Encryption</UI-TERM>** in the Actions column.

7. Select the key type in the dialog box.

   * Use an OCP-provided key: An automatically generated key by OCP. In this case, the `tde_method` value is internal, indicating the master key is stored in an internal OceanBase table.
   * Use a third-party vendor key: A key managed by KMS. Configure the key information as follows.

      | Service Type | Selected when the vendor is **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.Geer">KOAL</UI-TERM>**, specifying the KMS service type.<ul><li>**<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.StandardEdition">Standard Edition</UI-TERM>**: Ensure the KMS Standard service version is 2.0 or later.</li><li>**<UI-TERM key="ocp-v2.src.component.AddBinlogCredentialModal.Password">Password</UI-TERM>**: Ensure the KMS Password service version is 3.2.0 or later.   |

### Parameters

| Parameter | Description | Whether to Restart for Effectiveness |
| ------- | ------- | -------------------- |
| <code>ocp.kms.tde.koal.useTLS.enabled</code> | Specifies whether to use the Transport Layer Security (TLS) protocol for encryption of data in the Key Management Service (KMS). This parameter is stored in the <code>config_properties</code> table of the OCP MetaDB. The default value is <code>false</code>. When the server address is <code>https</code>, the parameter value must be set to <code>true</code>. | No |
| <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> | Specifies whether to use the KSP version for GEL KMS encryption. This parameter can be configured on the OCP console under <b>System Management</b> > <b>System Parameters</b>. The default value is <code>true</code>. | No |

## Create a tablespace

OceanBase supports enabling transparent data encryption on a per-tablespace basis to ensure secure data storage.

### Prerequisites

* Ensure the current OCP user is in the **ADMIN** or **ORG_ADMIN** role.
* Ensure the OceanBase cluster version is V4.x or later.
* Transparent data encryption (TDE) is enabled.

### Procedure

1. Log in to OCP.

2. In the left navigation pane, click **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ClusterWithExclude.Cluster">Cluster</UI-TERM>**. The system goes to the **<UI-TERM key="ocp-v2.page.Binlog.ClusterList">Clusters</UI-TERM>** page by default.

3. On the **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page, find the target cluster and click its name. The cluster **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page appears.

4. In the left navigation pane of the displayed page, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security</UI-TERM>**.

5. Switch to the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Select the target tenant and click **<UI-TERM key="ocp-v2.src.constant.security.CreateATablespace">Create Tablespace</UI-TERM>** in the Actions column.

7. In the dialog box, specify the following information:

   | Information | Description |
   |--------|---------|
   | Encrypted Tablespace Name | Multiple encrypted tablespaces can be created under a tenant, with each having a unique name. The name must start with a letter, can contain letters, numbers, and underscores, and be 2 to 30 characters long.  |
   | Encryption Algorithm      | The encryption algorithm cannot be modified or converted after selection. Note that supported algorithms may vary by OceanBase version. Choose an appropriate algorithm based on the official documentation.  |

8. Enter the encrypted tablespace name, select the encryption algorithm, and click **<UI-TERM key="ocp-v2.component.PreCheckDrawer.Create">Create</UI-TERM>**.

9. After enabling TDE and creating an encrypted tablespace, you need to perform the DDL operation to create an encrypted table for data encryption. The DDL statement is as follows:

   ```sql
   CREATE TABLE t1 (id int,id2 int) TABLESPACE sectest_ts1;
   ```

   <main id="notice" type='notice'>
   <h4>Note</h4>
   <p>After adding historical tables to the encrypted tablespace, perform a full compaction to persist the encryption. Otherwise, historical table data cannot be encrypted.</p>
   </main>

10. Click the name of the encrypted table to view its details in the right-side panel, including information such as the tenant to which it belongs, the encrypted table name, encryption status, and encryption progress. The encryption progress indicates the percentage of data blocks in the current table that have been encrypted.
