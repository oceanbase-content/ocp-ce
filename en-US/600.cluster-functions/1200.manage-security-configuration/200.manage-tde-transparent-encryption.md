# Manage Transparent Data Encryption

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not support this feature.</p>
</main>

OceanBase Database supports transparent data encryption (TDE) at the data storage layer.

TDE encrypts sensitive data stored on disks. Data is automatically encrypted before it is written to storage devices and automatically decrypted when read. This process is transparent to users, and authenticated users can access data without restrictions. If a storage medium is stolen, TDE ensures that sensitive data stored on the medium cannot be accessed by unauthenticated users. Even if the storage medium is lost, the data remains protected, maximizing the security of user data.

This topic describes how to enable TDE and create tablespaces for tenants.

## Enable TDE<a id="parameter"></a>

This topic describes how to enable TDE for a cluster.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Once TDE is enabled, it cannot be disabled. Enabling TDE may cause a performance degradation. To decrypt data, you must move the tables out of the encrypted tablespace and perform a full compaction. </p>
</main>

### Prerequisites

* You have logged in to the OCP console as the **ADMIN** or **ORG_ADMIN** user.
* The status of the tenant to be encrypted is **Running**.
* If you want to use the key provided by OCP, the OceanBase Database cluster must be of the V4.x or later version.
* If you want to use the key provided by a third-party vendor, the OceanBase Database cluster must be of the following versions:
  * [V4.2.5.4, V4.3.0)
  * [V4.3.5.2, +∞)
* If you want to use the key provided by **Koal**, you must configure the following parameters based on the service type:
  * **Standard**: set the values of the <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> parameters to false.
  * **Password**: set the values of the <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> parameters to true.
  For more information about the parameters, see **Parameters**.

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.constant.alarm.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** list, find the target cluster and click its name. The **<UI-TERM key="ocp-v2.page.Overview.Overview">Overview</UI-TERM>** page appears.

4. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. Click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Select the tenant for which you want to enable TDE and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.TurnOnEncryption">Enable Encryption</UI-TERM>** in the Actions column.

7. In the dialog box that appears, select the key type.

   * Use the key provided by OCP: the key automatically generated by OCP. In this case, the value of the `tde_method` parameter is internal, indicating that the master key is stored in the internal table of OceanBase Database.
   * Use the key provided by a third-party vendor: the key managed by KMS. You must configure the following key information:

      | Parameter | Description |
      |-----------|---------|
      | Cloud Vendor | The cloud vendor. Valid values: **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.AlibabaCloud">Alibaba Cloud</UI-TERM>**, **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**, and **Koal**.  |
      | Service Type | The service type. Valid values: **Standard** and **<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Password">Password</UI-TERM>**. <ul><li>**Standard**: the KMS standard service version must be 2.0 or later. </li><li>**<UI-TERM key="ocp-v2.Credential.Component.ImportModal.Password">Password</UI-TERM>**: the KMS password service version must be 3.2.0 or later.   |
      | Access Domain | The endpoint of KMS.  |
      | AK        | The access_key_id for signature authentication. |
      | SK        | The access_key_secret for signature authentication. |
      | SK Version | The version of the SK. This parameter is required only when the cloud vendor is **Koal** and the service type is **<UI-TERM key="ocp-v2.Oracle.Component.AddOracleUserOrRoleDrawer.Password">Password</UI-TERM>**.   |
      | Master Key ID | The ID of the user master key.   |
      | Region      | The region of KMS. This parameter is required only when the cloud vendor is **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**.  |

8. Click **<UI-TERM key="ocp-v2.TrendAndOutline.SQLLimit.Enable">Enable</UI-TERM>**.

### Parameters

| Parameter  | Description  | Effective after restart  |
|-------|-------|--------------------|
| <code>ocp.kms.tde.koal.useTLS.enabled</code>  | Specifies whether to use the Transport Layer Security (TLS) protocol for Koal KMS encryption. This parameter is stored in the <code>config_properties</code> table of the OCP MetaDB database. The default value is <code>false</code>. If the endpoint is <code>https</code>, set the value to <code>true</code>.  | No  |
| <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> | Specifies whether to use the kcsp version for Koal KMS encryption. You can configure this parameter on the **<UI-TERM key="ocp-v2.page.OBProxy.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="ocp-v2.page.OBProxy.SystemParameters">System Parameters</UI-TERM>** page. The default value is <code>true</code>.  | No  |

## Create a tablespace

OceanBase Database supports enabling transparent data encryption (TDE) at the tablespace level to ensure data security.

### Prerequisites

* You have logged in to the OCP console as the **ADMIN** or **ORG_ADMIN** role.
* The OceanBase cluster is of V4.x or later.
* TDE is enabled. For more information, see [Enable TDE](#parameter).

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-performance-report.ReportTables.SqlInfo.SQLInfoTable.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** list, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page of the cluster.

4. In the left-side navigation pane of the displayed page, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. Click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. In the left-side navigation pane, find the target tenant and click **<UI-TERM key="ocp-v2.src.constant.security.CreateATablespace">Create Tablespace</UI-TERM>** in the Actions column.

7. In the dialog box that appears, specify the following information.

   | Parameter | Description |
   |--------|---------|
   | Encrypted Tablespace Name  | You can create multiple encrypted tablespaces under the same tenant. Each tablespace name must be unique. The name must start with a letter and can contain letters, digits, and underscores. The length must be 2 to 30 characters.  |
   | Encryption Algorithm      | After you set the encryption algorithm, you cannot modify it or convert it to another type. OceanBase Database of different versions support different encryption algorithms. For more information, see the official documentation of OceanBase Database.  |

8. Specify the encrypted tablespace name and encryption algorithm, and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.CreateTableSpace.Create">Create</UI-TERM>**.

9. After TDE is enabled and the encrypted tablespace is created, you need to perform DDL operations to create an encrypted table before you can encrypt data. The DDL statement for creating an encrypted table is as follows:

   ```sql
   CREATE TABLE t1 (id int,id2 int) TABLESPACE sectest_ts1;
   ```

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>After you add a historical table to the encrypted tablespace, you must perform a major compaction to persist encrypted data. Otherwise, data in the historical table cannot be encrypted. </p>
   </main>

10. You can click the name of the encrypted tablespace to view details such as the tenant to which it belongs, the name of the encrypted table, the encryption status, and the encryption progress in the right-side panel. The encryption progress indicates the percentage of data blocks that have been encrypted in the current data table.
