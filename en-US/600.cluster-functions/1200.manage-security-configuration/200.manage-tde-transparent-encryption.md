# Manage Transparent Data Encryption

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This topic applies only to OCP Enterprise Edition. OCP Community Edition does not support this feature.</p>
</main>

OceanBase Database supports Transparent Data Encryption (TDE) at the data storage layer.

TDE encrypts sensitive data stored on disks. Data is automatically encrypted before it is written to storage devices and automatically decrypted when read. This process is transparent to users, and authenticated users can access data without restrictions. If a storage medium is stolen, TDE ensures that sensitive data on the medium cannot be accessed by unauthorized users. Even if a storage medium is lost, TDE ensures that data is not lost, maximizing the protection of user data.

This topic describes how to enable TDE and create tablespaces for tenants.

## Enable TDE<a id="parameter"></a>

This topic describes how to enable TDE for a cluster.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>After TDE is enabled, it cannot be disabled. Enabling TDE also decreases the database performance. To decrypt data, you must move the tables out of the encrypted tablespace and perform a major compaction. </p>
</main>

### Prerequisites

* The user logged in to OCP is of the **ADMIN** or **ORG_ADMIN** role.
* The status of the tenant to be encrypted is **Running**.
* If you want to use the key provided by OCP, the OceanBase Database cluster must be of V4.x or later.
* If you want to use the key provided by a third-party vendor, the OceanBase Database cluster must be of the following versions:
  * [V4.2.5.4, V4.3.0)
  * [V4.3.5.2, +∞)
* If you want to use the key provided by **Koal**, you must configure the following parameters based on the service type:
  * **Standard**: Set the values of the <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> parameters to false.
  * **Password**: Set the values of the <code>ocp.kms.tde.koal.useTLS.enabled</code> and <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> parameters to true.
  For more information about the parameters, see [Parameters](#parameter).

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.Detail.Component.RestartModal.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.Cluster.Component.ClusterList.ClusterList">Clusters</UI-TERM>** list, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.Detail.Overview.Overview">Overview</UI-TERM>** page.

4. In the left-side navigation pane of the page that appears, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. Click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Find the tenant to be encrypted and click **<UI-TERM key="ocp-v2.src.constant.security.TurnOnEncryption">Enable Encryption</UI-TERM>** in the Actions column.

7. In the dialog box that appears, select the key type.

   * Use the key provided by OCP: The key automatically generated by OCP.
   * Use the key provided by a third-party vendor: The key managed by KMS. The following table describes the parameters to be configured.

      | Parameter | Description |
      |-----------|---------|
      | Cloud Vendor | The cloud vendor. Valid values: **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.AlibabaCloud">Alibaba Cloud</UI-TERM>**, **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**, and **Koal**.  |
      | Service Type | The service type. Valid values: **Standard** and **<UI-TERM key="ocp-v2.Auth.User.New.Password">Password</UI-TERM>**. <ul><li>**Standard**: The KMS standard service version must be 2.0 or later. </li><li>**<UI-TERM key="ocp-v2.Auth.User.New.Password">Password</UI-TERM>**: The KMS password service version must be 3.2.0 or later.   |
      | Access Domain | The endpoint of KMS.  |
      | AK        | The access_key_id for signature authentication. |
      | SK        | The access_key_secret for signature authentication. |
      | SK Version | The specific version of SK. This parameter is required only when the cloud vendor is **Koal** and the service type is **<UI-TERM key="ocp-v2.Alarm.Channel.Detail.Password">Password</UI-TERM>**.   |
      | Master Key ID | The ID of the user master key.   |
      | Region      | The region of KMS. This parameter is required only when the cloud vendor is **<UI-TERM key="ocp-v2.SecurityCard.TDE.EnableTde.TencentCloud">Tencent Cloud</UI-TERM>**.  |

8. Click **<UI-TERM key="ocp-v2.Information.Detail.InformationCollectDrawer.Enable">Enable</UI-TERM>**.

### Parameters<a id="parameter"></a>

| Parameter  | Description  | Effective after restart  |
|-------|-------|--------------------|
| <code>ocp.kms.tde.koal.useTLS.enabled</code>  | Specifies whether to use the Transport Layer Security (TLS) protocol for Koal KMS encryption. This parameter is stored in the <code>config_properties</code> table of the OCP MetaDB. The default value is <code>false</code>. If the endpoint is <code>https</code>, the value must be set to <code>true</code>.  | No  |
| <code>ocp.kms.tde.koal.kcsp.mode.enabled</code> | Specifies whether to use the kcsp version for Koal KMS encryption. This parameter can be configured on the OCP console. The default value is <code>true</code>.  | No  |

## Create a tablespace

OceanBase Database supports enabling transparent data encryption (TDE) at the tablespace level to ensure secure data storage.

### Prerequisites

* You have logged in to the OCP console as the **ADMIN** or **ORG_ADMIN** role.
* The OceanBase cluster is of V4.x or later.
* TDE is enabled. For more information, see [Enable TDE](#parameter).

### Procedure

1. Log in to the OCP console.

2. In the left-side navigation pane, click **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ClusterWithExclude.Cluster">Cluster</UI-TERM>**. The **<UI-TERM key="ocp-v2.page.OBProxy.ClusterList">Clusters</UI-TERM>** page automatically appears.

3. In the **<UI-TERM key="ocp-v2.page.Cluster.ClusterList">Clusters</UI-TERM>** list, find the target cluster and click its name to go to the **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page.

4. In the left-side navigation pane of the page that appears, click **<UI-TERM key="ocp-v2.src.hook.useMenu.SecurityConfiguration">Security Configuration</UI-TERM>**.

5. Click the **<UI-TERM key="ocp-v2.component.SecurityCard.TdeTransparentEncryption">Transparent Data Encryption</UI-TERM>** tab.

6. Select the target tenant and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.CreateTableSpace.CreateATablespace">Create Tablespace</UI-TERM>** in the Actions column.

7. In the dialog box that appears, specify the following information.

   | Parameter | Description |
   |--------|---------|
   | Encrypted Tablespace Name  | You can create multiple encrypted tablespaces in the same tenant. Each tablespace name must be unique. The name must start with a letter and can contain letters, digits, and underscores. The name must be 2 to 30 characters in length.  |
   | Encryption Algorithm      | The encryption algorithm cannot be modified or converted. Different versions of OceanBase Database support different encryption algorithms. For more information, see the official documentation of OceanBase Database.  |

8. Specify the encrypted tablespace name and encryption algorithm, and click **<UI-TERM key="ocp-v2.SecurityCard.TDE.CreateTableSpace.Create">Create</UI-TERM>**.

9. After TDE is enabled and the encrypted tablespace is created, you must perform a DDL operation to create an encrypted table before you can encrypt data. The DDL operation to create an encrypted table is as follows:

   ```sql
   CREATE TABLE t1 (id int,id2 int) TABLESPACE sectest_ts1;
   ```

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>After you add a historical table to an encrypted tablespace, you must perform a full compaction to ensure that data is encrypted and persisted. Otherwise, data in the historical table cannot be encrypted. </p>
   </main>

10. You can click the name of the encrypted tablespace to view details of the encrypted table, including the tenant to which the table belongs, the name of the encrypted table, the encryption status, and the encryption progress. The encryption progress indicates the percentage of data blocks that have been encrypted in the current data table.
