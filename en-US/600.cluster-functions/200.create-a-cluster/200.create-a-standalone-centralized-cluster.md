# Create a standalone, centralized database

OceanBase Database offers the standalone, centralized architecture to simplify database deployment and management. Compared with a distributed cluster, a standalone, centralized database is deployed on a single server and is easy to deploy and use. However, it does not support multi-replica deployment or scaling. Therefore, it is suitable for business systems with low data security requirements and for development and testing environments.

This topic will guide you through the process of creating a standalone, centralized database.

## Prerequisites

* The user logging in to OCP has the **Create Cluster** permission.

* Only OceanBase Database V4.1.0 and above are supported.

## Procedure

1. Log in to the OCP console. On the left-side navigation pane, find the entry to create a cluster based on your business scenario.

   1. If you have no manageable clusters, a **<UI-TERM key="ocp-v2.Cluster.Arbitration.Cluster.1">Cluster</UI-TERM>** page appears, prompting you to create a cluster. Click **<UI-TERM key="ocp-v2.page.Cluster.CreateACluster">Create Cluster</UI-TERM>** in the prompt information.

   2. If you already have manageable clusters, click **New Cluster** in the upper-right corner of the **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.Cluster">Cluster</UI-TERM>** page.

2. On the **Create Cluster** page, select **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>**.

3. Set the basic information of the cluster.

    The following table describes the parameters.

     | Parameter  | Description |
     |-----|-------|
     | **<UI-TERM key="ocp-v2.Component.DisconnectDrawer.ClusterName">Cluster Name</UI-TERM>**          | The name of the cluster. The name must start with an English letter and end with an English letter or a number, and can contain only English letters, numbers, and underscores. It must be 2 to 32 characters long. |
     | **<UI-TERM key="ocp-v2.Cluster.New.RootSysPassword">Root@sys Password</UI-TERM>**    | It supports custom or random password generation. The password must meet the following complexity requirements: <ul><li>8 to 32 characters long</li><li>Contains at least two uppercase letters, two lowercase letters, two digits, and two special characters. The special characters are spaces and the following: \~!@#%\^\&\*_-+=\`\|(){}\[\]:;',.?/  </li></ul>   |
     | **<UI-TERM key="ocp-v2.Component.AddBackupStrategy.ObVersion">OceanBase version</UI-TERM>**         | You can select an existing OceanBase cluster version from the list or click **<UI-TERM key="ocp-v2.src.component.PackageSelect.AddVersion">Add Version</UI-TERM>** below the list to upload an OceanBase version.  |
     | **<UI-TERM key="ocp-v2.Component.ShowLimitsModal.ZoneName">Zone Name</UI-TERM>**    | You can keep the default value or customize it. The zone name must start with an English letter and can contain uppercase and lowercase letters, numbers, and underscores. It must be 2 to 32 characters long. An OceanBase cluster with multiple zones must have a zone that has the same region as the primary zone.  |
     | **<UI-TERM key="ocp-v2.Monitor.AddMonitor.CollectTable.Host">Host</UI-TERM>**  | Select a host that is consistent with the architecture of **<UI-TERM key="ocp-v2.Detail.Component.UpgradeModal.ObVersion">OceanBase version</UI-TERM>**. You can select only one host as the OBServer and rootserver. If no hosts are available in the drop-down list, you can click **<UI-TERM key="ocp-v2.page.Host.AddHost">Add Host</UI-TERM>** to add a host.   |

     ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E5%88%9B%E5%BB%BA%E9%9B%86%E7%BE%A4.png)

4. Click **<UI-TERM key="ocp-v2.Component.RuleForm.ParameterConfiguration">Parameter Configurations</UI-TERM>** to open the module and configure the cluster parameters.

    * You can add and configure parameters item by item as shown in figure ①.

    * Alternatively, you can click **<UI-TERM key="ocp-v2.component.ParameterTemplate.ParameterTemplateDropdown.SelectAParameterTemplate">Select Parameter Template</UI-TERM>** as shown in figure ② to browse and select a parameter template. The parameters in the template will be automatically filled into the parameters section.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>If OceanBase Version is V2.2.77, we recommend that you use the built-in <strong>2.2.77 Version Parameter Template</strong>. This template contains common parameter settings for OceanBase Database V2.2.77. You can apply this template for initial cluster setup. </li>
    <li>If no cluster parameter template has been created, you can click <strong>Build a Cluster Template</strong> to create one. For more information, see <a href="../1200.cluster-parameters-template-management.md">Cluster Parameter Template Management</a>. </li>
    </ul>
    </main>

   ![09161737](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/401/%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE1.png)

5. Click **Custom Configuration** to open the section and configure the path and port.

   * Configure the path:
      1. In the **Path Configuration** section, customize **<UI-TERM key="ocp-v2.Detail.Overview.SoftwareInstallationPath">Software Installation Path</UI-TERM>**, **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DataDiskPath">Data Disk Path</UI-TERM>**, and **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.LogDiskPath">Log Disk Path</UI-TERM>** as needed.
      2. After you configure the paths, click **<UI-TERM key="ocp-v2.src.component.ArchiveForm.Test">Test</UI-TERM>** to verify whether the paths are available. If not, you can troubleshoot based on the test results or change the paths to available ones.

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>We recommend that you allocate at least three times the size of the host memory space to the log disk space for OceanBase Database in a production environment. To avoid performance issues, we recommend that you do not mount the data directory and log directory on the same disk. </p>
      </main>

   * Configure the port:
      1. In the **Port Configuration** section, customize **<UI-TERM key="ocp-v2.Detail.Component.OBProxyList.SqlPort">SQL Port Number</UI-TERM>** and **<UI-TERM key="ocp-v2.Detail.TakeOver.RpcPort">RPC Port</UI-TERM>**.
      2. After you configure the ports, click **<UI-TERM key="ocp-v2.Component.StorageConfigCard.Test">Test</UI-TERM>** to verify whether the ports are available. If the ports are occupied, you need to configure other available ports.

    ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/410/%E8%87%AA%E5%AE%9A%E4%B9%89%E8%AE%BE%E7%BD%AE.png)

6. Click **<UI-TERM key="ocp-v2.Alarm.Template.New.Submit">Submit</UI-TERM>**.

7. In the right-side pane, verify the information. Then, click **<UI-TERM key="ocp-v2.Component.AddZoneDrawer.Ok">OK</UI-TERM>**.

8. In the pop-up **<UI-TERM key="ocp-v2.Cluster.Component.NewTenant.CreateATenantReminder">Note</UI-TERM>** dialog box, select whether you want to create a tenant.

    * If you do not want to create a tenant, click **<UI-TERM key="ocp-v2.Component.InstallService.Skip">Skip</UI-TERM>**. In this case, only the cluster is created and no tenant is created. You can create a tenant later by referring to [Create a tenant](../../500.quickstart/600.quickstart-create-a-tenant.md).
    * If you want to create a tenant, specify the tenant mode and the tenant name. After you configure the parameters, click **<UI-TERM key="ocp-v2.Cluster.Component.NewTenant.CreateAndSubmit">Create and Submit</UI-TERM>**. You can view the task progress in the **System Management > Tasks** section.

      The following table describes the parameters:

      | Parameter  | Description |
      |-----|-------|
      | Tenant Mode | The tenant mode allows you to switch between tenant modes. The default value is MySQL. |
      | Tenant Name | The tenant name defaults to the same value as the tenant mode. Custom tenant names are supported.  |
