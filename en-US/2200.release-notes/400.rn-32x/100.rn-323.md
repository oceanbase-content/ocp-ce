# OCP V3.2.3

#RNDate#2021-12-27

The OceanBase Cloud Platform (OCP) V3.2.3 provides a new feature: the visual log query feature and parameter templates. In terms of monitoring and alerts, the version also implements breakthrough updates. The performance monitoring feature allows for drill-down analysis and provides granular performance metrics to help you comprehensively understand and analyze your business. The SQL diagnostics feature supports setting SQL throttling, plan binding, and query binding history. The performance reports include statistics on PRC, memory, and parameter configuration changes. In terms of alerts, the version not only supports multi-threshold alerts but also introduces 10 built-in alerts to enhance OCP's maintenance capabilities for OceanBase clusters.

## Version information

* **Version:** V3.2.3

* **Prerequisites:** V3.1.5

* **Version Released:** 2021-12-27

* **Supported upgrade path: ** For OCP V2.3.x and later, you can directly upgrade to this version. For OCP V2.3.0 and earlier, you must first upgrade to V2.3.x and then to this version.

## Supported OceanBase Database versions

OceanBase Cloud V3.2.3 supports the following versions of OceanBase Database:

* OceanBase V3.2.x

## New features

* **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** supports drilling down into metric data for clusters and tenants.

  By using the drilldown feature, you can directly drill down to the tenant or OBServer node level to view the metric data without the need to navigate through the complex path to the **<UI-TERM key="ocp-v2.page.Monitor.Monitoring">Performance Monitoring</UI-TERM>** page of the tenant or the **<UI-TERM key="ocp-v2.Host.Detail.Surveillance">Monitoring</UI-TERM>** tab of the host.

* Added the log query feature. You can use this feature to set query conditions on the OCP console and view the required logs. This feature supports querying logs for all types of resources, including OBServer nodes, OBProxy, and hosts. This feature allows you to easily perform log retrieval without download logs.

* SQL diagnostics support SQL index binding, plan binding, SQL throttling, and query history for SQL in the details page.

* Add 10 built-in alert items, enabling full monitoring and early warning for metrics such as the number of active sessions, log synchronization delay, and cross-cloud control in OCP. Alerts now support multiple thresholds, providing even stronger assurance for the performance and stability of OceanBase clusters.

* Parameter templates are now supported. If you need to create multiple tenants or clusters with the same settings, you can first create a parameter template and then apply it when you click **<UI-TERM key="ocp-v2.Detail.Tenant.NewTenant">Create Tenant</UI-TERM>** or **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">Create Cluster</UI-TERM>**. This way, you won't have to configure the parameters of the cluster or tenant again when you click **<UI-TERM key="ocp-v2.Tenant.New.CreateACluster">Create Cluster</UI-TERM>** or **<UI-TERM key="ocp-v2.Cluster.Detail.NewTenant">Create Tenant</UI-TERM>**.

  * For information about how to create a template, see [Cluster parameter templates](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000377800).

  * To create a cluster or a tenant, see [Create a cluster](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000378283) and [Create a tenant](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000377507).

## Feature enhancements

* Enhance the Performance Monitoring feature to further segment cluster and tenant-related metrics, providing you with more detailed performance information. These metrics include:

  * Cluster: **QPS** , **Query Response Time** , **TPS** , **Transaction Response Time** .

  * Tenants: **Request Wait Queue** , **TPS** , **Transaction Response Time** .

* Optimized and restarted OBServer nodes to support the offline upgrade and offline restart of OBServer nodes. This optimization allows you to upgrade and restart OBServer nodes without requiring continuous availability.

* Improve the **<UI-TERM key="ocp-v2.Detail.Report.PerformanceReport">Performance Report</UI-TERM>** feature by adding statistics for **<UI-TERM key="ocp-v2.src.component.DeleteUnitSpecModal.Memory">Memory</UI-TERM>**, **RPC**, and **<UI-TERM key="ocp-performance-report.pages.AWR.ParameterConfigurationChanges">Parameter Changes</UI-TERM>**.

## Limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The following table lists the minimum hardware requirements for OCP-Server nodes.

| Hardware |                 Requirement                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very few resources and has no special requirements for the hardware resources of the installation node.

### Operating system requirements

The following table lists the operating system requirements for installing OCP-Server (including OCP-Agent).
