# OCP V3.2.3

<!--#RNDate#2021-12-27-->

OceanBase Cloud Platform (OCP) V3.2.3 introduces new features including log query on the web interface and parameter templates. It also brings significant updates to monitoring and alerting. Performance monitoring now supports drill-down analysis, and some performance metrics have been subdivided to help you understand and analyze your business more comprehensively. SQL diagnostics support setting SQL throttling, plan binding, and binding history queries. Performance reports have added statistics display for PRC, memory, and parameter configuration changes. The alerting feature not only supports multiple thresholds but also includes 10 built-in alerts to enhance OCP's operational capabilities for OceanBase clusters.

## Version information

* **Version:** V3.2.3

* **Previous version:** V3.1.5

* **Release date:** December 27, 2021

* **Supported upgrade path:** You can directly upgrade from OCP V2.3.x and later versions to this version. For versions earlier than OCP V2.3.0, you must first upgrade to V2.3.x and then to this version.

* OceanBase V1.4.x

* OceanBase V3.2.x

## New features

* The **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** section for clusters and tenants now supports drill-down analysis.

  With the drill-down feature, you can directly go down to the tenant or OBServer node dimension to view the data of the metric at that dimension, without having to switch through complex paths to the tenant's **<UI-TERM key="ocp-v2.page.Monitor.Monitoring">Performance Monitoring</UI-TERM>** page or the host's **<UI-TERM key="ocp-v2.Host.Detail.Surveillance">Monitoring</UI-TERM>** tab.
  
* A new log query feature is available. You can use this feature to set query conditions on the OCP interface to view the logs you need. The query scope covers all types of logs, including those on OBServer nodes, OBProxies, and hosts. This allows you to easily search for logs without downloading them.

* The SQL diagnostics feature supports binding indexes, plans, and setting SQL throttling for an SQL statement on its details page, as well as binding its historical queries.

* Ten built-in alert items are added, providing comprehensive monitoring and early warning for active session count, clog synchronization latency, and cross-cloud management of OCP. Additionally, alerts support multiple thresholds, providing a stronger guarantee for the performance and stability of OceanBase clusters.

* A new parameter template feature is introduced. If you need to create multiple tenants or clusters with the same configuration, you can first create a parameter template and then apply it when creating a **<UI-TERM key="ocp-v2.Detail.Tenant.NewTenant">Create Tenant</UI-TERM>** or **<UI-TERM key="ocp-v2.page.Cluster.CreateANewCluster">Create Cluster</UI-TERM>**. This avoids repeating the cluster/tenant parameter configuration when creating a cluster or tenant.

  * To create a template, refer to: [Manage cluster parameter templates](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000377800).

  * To create a cluster or tenant, refer to: [Create a cluster](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000378283) or [Create a tenant](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000377507).

## Feature enhancements

* The performance monitoring feature has been optimized. Relevant metrics for clusters and tenants have been further subdivided to provide you with more detailed performance information. These metrics include:

  * Cluster: **QPS**, **Query response time**, **TPS**, **Transaction response time**.

  * Tenant: **Request waiting queue**, **TPS**, **Transaction response time**.

* The logic for upgrading and restarting OBServer nodes has been optimized to support stopping and then upgrading or restarting OBServer nodes. This optimization meets your requirement for quickly upgrading and restarting OBServer nodes when business continuity is not a concern.

* The cluster **<UI-TERM key="ocp-v2.Detail.Report.PerformanceReport">Performance Report</UI-TERM>** feature has been improved. The performance report now includes statistics for **<UI-TERM key="ocp-v2.src.component.DeleteUnitSpecModal.Memory">Memory</UI-TERM>**, **RPC**, and **<UI-TERM key="ocp-performance-report.pages.AWR.ParameterConfigurationChanges">Parameter Changes</UI-TERM>**.

## Bug fixes

OceanBase Cloud Platform V3.2.3 fixes the following issues:

* Incomplete SQL diagnostics collection and slow frontend loading.

* Data loss in the performance report.

* Abnormal retry and abort behavior after a task fails.

## Version usage limitations

### Hardware requirements

OCP-Server can be installed on physical servers or run in Docker containers. OCP-Server supports high-availability deployment across multiple nodes.

The minimum hardware requirements for an OCP-Server node are listed in the following table.

| Hardware | Requirements |
| ----- | ------------------------------------ |
| CPU | <li>x86_64, 8-core</li><li>ARM AArch64 architecture, 8-core</li> |
| Memory | Available Memory: 16 GB |
| NIC | 10 Gbit/s NIC |

OCP-Agent consumes very few resources and has no specific hardware requirements for the installation node.

### Operating system requirements

The operating system requirements for installing the OCP server (including OCP-Agent) are listed in the following table.

| Server Type | Operating System | Supported Versions |
| ------------- | ------------ | ----------- |
| x86_64 | RHEL | 7.2 and later |
| x86_64 | CentOS | 7.2 and later |
| x86_64 | AliOS | 7.2 and later |
| x86_64 | openSUSE | 12 SP3 and later |
| ARM aarch64 | AliOS | 7.2 and later |
| ARM aarch64 | NeoKylin | 7.6 |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8 |

| Browser | Minimum Version |
| --------- | ------ |
| Chrome | 81 |
| Firefox | 64 |
