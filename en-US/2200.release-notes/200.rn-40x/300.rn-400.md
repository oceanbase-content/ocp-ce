# OCP V4.0.0

#RNDate#2022-10-08

OCP V4.0.0, as a companion product to OceanBase Database V4.0, has been deeply adapted and modified to work with OceanBase Database V4.0. It also introduces end-to-end tracing capabilities in a distributed environment, providing more comprehensive link tracing analysis.

## Version information

* **Version:** V4.0.0

* **Previous version:** V3.3.4

* **Version release date:** October 8, 2022

* **Supported upgrade path:** OCP V2.3.x and later can be directly upgraded to this version. For OCP versions earlier than V2.3.0, you must first upgrade to V2.3.x before upgrading to this version.

## Supported OceanBase Database versions

OCP V4.0.0 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

* OceanBase V4.x

## New features

OCP V4.0.0 introduces the full-link diagnostics feature, which has the following characteristics:

* A new framework is established for full-link tracing in a distributed environment.

* A standard data model for **transaction + SQL tracing** is provided.

* Full-link tracing is supported from the driver to the OBProxy and then to the OBServer node.

## Feature adaptation and changes

* OCP has adapted the views and management commands for the following features to OceanBase V4.0:

  * Cluster management

  * Tenant and unit management

  * Resource management

  * Parameter management

  * Database management

  * Database user management

  * Backup and restore

  * SQL diagnostics

  * SQL collection

  * Monitoring collection

  * Inspection

* OCP has made changes to the following features for OceanBase V4.0:

  * Tenant merge: When OceanBase is V4.0 or later, cluster-level tenant merge is changed to tenant-level tenant merge.

  * Unit management: When OceanBase is V4.0 or later, only tenant-level overall expansion and reduction are supported, and zone-level expansion and reduction are no longer supported.

  * Database management: The Primary Zone parameter is removed for database deletion. When OceanBase is V4.0 or later, setting Primary Zone and Locality at the table, database, and table group levels is no longer supported.

  * Replica view: When OceanBase is V4.0 or later, the concept of partition replicas is removed.

  * Primary and standby databases: When OceanBase is V4.0 or later, the primary and standby database feature is temporarily not supported.

  * Tenant backup and tenant snapshot backup: When OceanBase is V4.0 or later, the tenant backup and tenant snapshot backup feature is temporarily not supported.

  * Secondary backup: When OceanBase is V4.0 or later, the secondary backup feature is temporarily not supported.

  * Cluster upgrade: When OceanBase is V4.0 or later, the cluster version upgrade feature is temporarily not supported.

## Other

* cgroup is enabled by default when a cluster is created.

* The max_iops parameter is confirmed again when a unit is created.

## Fixed issues

OCP V4.0.0 fixes the following issues:

1. Fixed the issue where log backup scheduling timeouts occasionally occurred when the SQL parsing thread pool was exhausted in certain scenarios.

2. Fixed the issue where the database name was not displayed on the SQL details page when entering from a non-SQL list page.

3. Fixed the issue where task accumulation and significant memory increase occurred due to ethtools execution blocking in certain scenarios.

4. Fixed the issue where some tasks failed when reinstalling a large number (100+) of Agent nodes concurrently.

5. Enhanced the security of password display in OSS backup logs.

6. Fixed the issue where an exception was reported when creating a standby cluster without a Server in a zone in multi-cluster mode.

7. Fixed the issue where QPS monitoring before the upgrade could not be queried after upgrading from V3.1.x to V3.2.x.

8. Fixed the issue where alerts were inaccurate due to unreleased MemTables.

9. Fixed the issue where alerts did not take effect when subscribing to OBProxy and other application alerts concurrently.

10. Fixed the issue where inode usage monitoring was inaccurate and false alerts were generated.

11. Fixed the issue where false alerts were generated for disk read-only status.

12. Fixed the issue where TCP retransmission rate monitoring occasionally exceeded 100%.

13. Removed the invalid and server-based filtering feature from the SQL diagnostics page.

## Version limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high-availability deployment.

The minimum hardware requirements for OCP-Server nodes are as follows:

| Hardware  | Requirement                                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8-core</li><li>ARM aarch 64 architecture, 8-core</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very few resources and has no special hardware requirements for the installation node.
