# OCP V4.0.0

#RNDate#2022-10-08

OCP V4.0.0 is a product that is closely integrated with OceanBase Database V4.0. It not only provides deep compatibility and optimization for OceanBase Database V4.0 but also introduces full-link tracing capabilities in distributed environments. This allows for more comprehensive analysis of the entire link tracing process.

## Version information

* **Version:** V4.0.0

* **Previous version:** V3.3.4

* **Version release date:** October 8, 2022

* **Supported upgrade paths:** OCP V2.3.x and later versions can be directly upgraded to V4.0.0. However, for versions earlier than V2.3.0, you must first upgrade to V2.3.x before upgrading to V4.0.0.

## Supported OceanBase Database versions

OCP V4.0.0 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

* OceanBase V4.x

## New features

OCP V4.0.0 introduces the full-link tracing feature, which is characterized as follows:

* A new framework is established for distributed full-link tracing.

* It provides a standard data model for **transactions + SQL tracing**.

* It supports full-link tracing from the driver to OBProxy to OBServer.

## Feature adaptation and changes

* OCP has adapted views and management commands for the following features for OceanBase Database V4.0:

  * Cluster management

  * Tenant and unit management

  * Resource management

  * Parameter management

  * Database management

  * Database user management

  * Backup and restore

  * SQL diagnostics

  * SQL collection

  * Monitoring collection

  * Inspection

* OCP has changed the following features for OceanBase Database V4.0:

  * **New tenant consolidation:** When OceanBase Database is V4.0 or later, tenant-level management is adopted for cluster-level tenant consolidation.

  * **Unit management:** When OceanBase Database is V4.0 or later, the scale-out and scale-in operations for tenants are supported but by zones are no longer supported.

  * **Database management:** The primary zone parameter for databases is deleted. When OceanBase Database is V4.0 or later, primary zone and locality cannot be set for tables, databases, or table groups.

  * **Replica views:** The partition replica concept is deleted when OceanBase Database is V4.0 or later.

  * **Primary and standby databases:** The Primary and standby database feature is not supported for OceanBase Database V4.0 and later.

  * **Tenant backup and tenant snapshot backup:** The tenant backup and tenant snapshot backup feature is not supported for OceanBase Database V4.0 and later.

  * **Secondary backup:** The secondary backup feature is not supported for OceanBase Database V4.0 and later.

  * **Cluster upgrades:** The cluster version upgrade feature is not supported for OceanBase Database V4.0 and later.

## Other information

* cgroup is enabled by default during the cluster creation.

* When you create a unit, the service performs the second confirmation for the max_iops parameter.

## Fixed issues

OCP V4.0.0 fixed the following issues:

1. Fixed the issue where the backup scheduling for logs would timeout intermittently when the SQL parsing threads fully occupied the thread pool.

2. Fixed the issue where the database name is not displayed on the SQL details page when you navigate to the page from a non-SQL list page.

3. Fixed the issue where task backlog and memory exhaustion occurred when the execution of ethtools was blocked in some cases.

4. Fixed the issue where some tasks failed when you reinstalled the agent of a large number (100 or more) of servers in parallel.

5. Enhanced the security of displaying passwords in the backup log of Alibaba Cloud OSS.

6. Fixed the issue where an exception was returned when you created a standby cluster with no zones in the multi-cluster mode.

7. Fixed the issue where the QPS metric before the upgrade was unavailable when you upgraded OceanBase Database from V3.1.x to V3.2.x.

8. Fixed the issue where the alert was inaccurate because the MemTable was not released.

9. Fixed the issue where the alerts were not triggered when you subscribed to OBProxy and other applications alerts at the same time.

10. Fixed the issue where the alerts for the inode utilization were inaccurate and false positive alerts were returned.

11. Fixed the issue where the alert for disk read-only status was false positive.

12. Fixed the issue where the TCP retransmission rate exceeded 100% occasionally.

13. Removed the invalid and server-based filter feature from the SQL diagnostics page.

## Limitations

### Hardware requirements

OCP-Server can be installed on physical servers or virtual machines, and supports high-availability deployment with multiple nodes.

The following table describes the minimum hardware requirements of OCP-Server.

| Hardware  | Requirements                                 |
|-----|------------------------------------|
| CPU | <li>X86_64 with 8 cores</li><li>ARM aarch 64 architecture with 8 cores</li> |
| Memory  | Available memory: 16 GB                         |
| Network card  | 10-Gbps network card                               |

OCP-Agent occupies few resources and does not require any specific hardware resources.
