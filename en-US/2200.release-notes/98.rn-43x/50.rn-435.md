### Key feature overview

#### High availability of arbitration service

OceanBase Database V4.1 provides the arbitration service capability. With its significant advantage of low resource consumption and strong support for multi-clusters, the arbitration service has successfully created a lower-cost high availability solution for OceanBase Database, such as the 2F1A/4F1A architecture. Through this architecture, enterprises can ensure excellent high availability of the database system while effectively controlling resource costs, greatly improving the cost-effectiveness of the system. However, it is undeniable that the arbitration service has the potential for single-point-of-failure during operation. If an arbitration service fails, the high availability of the associated OceanBase cluster will inevitably degrade during the fault duration, which may negatively impact business continuity and stability. To effectively address this challenge, by building an arbitration service group, the system enables rapid switchover to another healthy arbitration service node within seconds when a node in the group fails and the replacement conditions are met, based on the priority settings. This maximizes the stable operation of OceanBase clusters under various complex circumstances and ensures business continuity.

**Usage instructions**:

* The versions of arbitration services within the same arbitration service group must be consistent.
* It is recommended to have at least two arbitration service addresses within a single arbitration service group.
* After an arbitration service switchover is completed, you must reconfigure the association between the cluster and the arbitration service based on your actual business situation to prevent any one arbitration service from becoming overloaded.
* Arbitration service groups and recovery plans: There is no functional conflict between the exit of the OBServer process of an arbitration service and its automatic restart by a recovery plan. That is, when an arbitration service fails, it can be automatically restarted by a recovery plan, but it will also be replaced if it meets the replacement conditions of its arbitration service group.
* Supports four main operations: creating a service group, upgrading a service group, editing a service group, and deleting a service group.

#### Optimization of backup strategies in OceanBase Database V4.x

* The ability to perform batch operations on tenant backup strategies as a cluster-level backup strategy:
  
  * Creating a cluster-level backup strategy only takes effect for tenants that have not set a tenant-level backup strategy.
  * When deleting a cluster-level backup strategy, the system will by default delete both the cluster and tenant backup strategies and disable log backup at the tenant level.

* Support disabling log backup in both cluster and tenant backup strategies. The system enables log backup by default before data backup and disables it after data backup, primarily to address the issue of excessive log backup size in some business scenarios.
* Enabling/disabling log backup in cluster/tenant backup strategies has the highest priority. Even if you manually disable/enable log backup, the system will default to the setting specified in the backup strategy.
* When editing cluster or tenant backup strategies, storage configuration options are grayed out by default, meaning you cannot change the storage path or the corresponding object storage AccessKey and SecretKey, to avoid causing log archiving startup failures or data backup failures.
* When no cluster or tenant backup strategy is available, the system records the log backup status. If log backup is not enabled, the system will enable it before data backup and disable it after data backup when you manually initiate a backup. If log backup is enabled, it will remain enabled after data backup.

The minimum hardware requirements for an OCP-Server node are listed in the following table.

| Hardware | Requirements |
| ------- | ------------------------------------ |
| CPU | <li>x86_64, 8-core</li><li>ARM AArch64 architecture, 8-core</li> |
