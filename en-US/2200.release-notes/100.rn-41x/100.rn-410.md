# OCP V4.1.0

#RNDate#2023-05-26

## V4.1.0 BP2

### Version information

* **Version:** V4.1.0 BP2

* **Previous version:** V4.1.0 BP1

* **Version release date:** September 1, 2023

### Bug fixes

* Fixed the issue where the displayed CPU usage of a tenant is 100 times larger than the actual value.

* Fixed the issue where a non-root user may fail to add a host.

* Fixed the issue where the cleanup of useless alert history fails.

* Fixed the issue where the displayed transaction response time in monitoring is 1,000 times larger than the actual value.

* Fixed the issue where some real-time monitoring data is delayed by two minutes before it can be queried.

* Fixed the issue where you cannot select more than 2 units when you scale out the cluster.

## V4.1.0 BP1

### Version information

* **Version:** V4.1.0 BP1

* **Previous version:** V4.1.0

* **Version release date:** July 20, 2023

### New features

* Added support for two common single sign-on (SSO) authentication and authorization methods: OAuth2 and CAS.

* Optimized English terms and text in the product to support multi-language switching and meet internationalization requirements.

* Optimized the OBAgent startup logic to support automatic cleanup of historical PID files.

* Added support for O&M control of basic scenarios in OceanBase Database V4.2.0.0 to support POCs.

### Bug fixes

* Fixed issues caused by using the `127.1` address in MetaDB across OCP clusters.

* Fixed the issue where the topology map had no monitoring data.

* Fixed the issue where a backup task could not be rescheduled after a secondary backup was canceled.

* Fixed the error reported by the import host interface of the OpenAPI.

* Optimized the issue where host addition failed in specific shell environments.

* Optimized the host addition process to allow successful addition even when ICMP is disabled.

* Optimized fault tolerance in the primary/standby database switching scenario to prohibit some erroneous operations.

* Enhanced compatibility with the openEuler operating system in host management.

## OCP V4.1.0

OceanBase V4.x has undergone significant changes in architecture and product form, along with numerous new features. As the companion O&M management platform for OceanBase, OCP needs to present these new features in a more simple and user-friendly manner to reduce the difficulty for users. Additionally, as a major version of OCP, this release further optimizes the product experience, adjusts the product architecture, and enhances product capabilities.

### Version information

* **Version:** V4.1.0

* **Previous version:** V4.0.3

* **Version release date:** May 26, 2023

* **Supported upgrade path:**

  * You can directly upgrade from OCP V3.2.4 to the current version.

  * For OCP V2.3.x and earlier versions, you must first upgrade to OCP V3.3.4.

  * For OCP versions earlier than V2.3.0, you must first upgrade to OCP V2.3.x, and then to OCP V3.3.4.

### Supported OceanBase Database versions

OCP V4.1.0 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

* OceanBase V4.x

### New features

#### OceanBase V4.x

* **Integrated single-node and distributed deployment**

  You can manage both **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** (available in OceanBase Database V4.1 and later) and **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** in a unified environment, meeting diverse user needs.

  * When you create a cluster, you can choose between **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** and **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** modes. The deployment process for **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** environments is streamlined.

  * When you deploy a **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** cluster, you can automatically create a business tenant using the maximum available resources of the cluster, enabling immediate business use.

  * You can online scale out a **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** cluster to a **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>**, meeting growing business needs and higher security requirements.

* **<UI-TERM key="ocp-v2.page.Cluster.ArbitrationService">Arbitration Service</UI-TERM>**

  If an OceanBase cluster is V4.1 or later, you can configure the arbitration service for 2F or 4F tenants to reduce the arbitration cost for high availability in multi-replica environments.

  * The **<UI-TERM key="ocp-v2.src.constant.auditEvent.ArbitrationServiceManagement">Arbitration Service Management</UI-TERM>** feature is introduced, allowing you to deploy, start, stop, delete, and upgrade the arbitration service.

  * You can deploy multiple arbitration service instances on a single node to meet the high availability requirements of different clusters.

  * You can add, replace, or remove the arbitration service in an OceanBase cluster of V4.1 or later.

  * After you add the arbitration service to a cluster, you can enable or disable the arbitration service for 2F or 4F tenants.

#### Platform features

* **New information architecture**

  * The original first-level entry **<UI-TERM key="ocp-v2.src.constant.information.SoftwarePackage">Software Package</UI-TERM>** is moved to **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** and renamed to **<UI-TERM key="ocp-v2.src.hook.useMenu.SoftwarePackageManagement">Software Package Management</UI-TERM>**.

  * A new first-level entry **Monitoring and Alerts** is introduced. The original **<UI-TERM key="ocp-v2.src.constant.auth.Alert">Alerts</UI-TERM>** and **<UI-TERM key="ocp-v2.page.Inspection.Inspection">Inspection</UI-TERM>** entries under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** are moved to this entry.

  * The original **<UI-TERM key="ocp-v2.src.hook.useMenu.LogService">Log Service</UI-TERM>** entry under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** is promoted to a first-level entry.

  * The original **<UI-TERM key="ocp-v2.Task.Detail.Task">Task</UI-TERM>** entry under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** is moved to the upper right corner of the **Home** page.

  * The original **Diagnosis Center** entry is renamed to **<UI-TERM key="ocp-v2.src.hook.useMenu.AutonomousService">OceanBase Autonomy Service</UI-TERM>**.

  * The original **<UI-TERM key="ocp-v2.src.hook.useMenu.OperationAudit">Operation Audit</UI-TERM>** entry is renamed from **History Events**.

  * The original **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.Security">Security</UI-TERM>** entry under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** is renamed to **<UI-TERM key="ocp-v2.User.Oracle.UserManagement">User Management</UI-TERM>**.

* **Installation templates**

  For hosts added to OCP, you can standardize the database environment settings.

* **Multi-region OSS backup**

  * Local OSS backup is performed for the production cluster, and the local backup is replicated to the remote OSS.

  * The backup scheduling, backup cycle, and retention strategy are different for the local and remote OSS. The local backup is retained for 30 days, and the remote backup is retained for 7 days.

  * You can restore tenants in the remote OceanBase cluster by using the remote OSS.

  * When you replicate log backups, you can synchronize the log backups and log metadata to meet the timeliness requirements of log backups.

### Feature enhancements

* When you set a backup strategy, you can specify a port number in the OSS endpoint.

* When you deploy an OBProxy cluster, the system checks whether the OBProxy log directory has read and write permissions.

* After a server is restarted, the ocp_agent process is automatically started.

* SQL diagnostics support cross-host comparison.

* When you create a cluster, you can enable the zone priority configuration switch. If the switch is disabled, the zone priority of the sys tenant follows the default behavior of OceanBase Database. Specifically, when the cluster version is earlier than V4.x, the first zone has the highest priority. When the cluster version is V4.x or later, the zone priority is random.

* The backup storage trend interface on the overview page of global views is optimized for speed.

* The home page of the diagnostic center is optimized.

* The default value of the log backup delay alert is increased.

* OCP alerts support memory alerts in non-memstore zones.

* You can customize alerts for write lock wait failures and average lock wait time.

* OCP Agent supports digest authentication.

* The inspection item of `max open files` is added to the OBProxy server.

* A parameter is added to control the starting OceanBase Database version for enabling cgroup.

* The monitoring query is optimized. By using asynchronous queries, optimizing the computing chain code, and abstracting the storage layer, the peak pressure of monitoring queries is reduced, thereby improving the overall throughput of monitoring interfaces.

* Capacity Center supports **<UI-TERM key="ocp-v2.Detail.Capacity.CapacityRisk">Capacity Risks</UI-TERM>** and tenant **<UI-TERM key="ocp-v2.Detail.Capacity.OverviewOfCapacityUsage">Capacity Usage Overview</UI-TERM>**.

### Security enhancements

* Sensitive information involved in interactions with web page access interfaces is encrypted during transmission.

* When you deploy OCP for the first time, you can specify a password instead of using the built-in initial password.

* After you upload a software package, a dialog box pops up to prompt you to enter the SHA1 value. You need to confirm the value.

### Version limitations

#### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The minimum hardware requirements for an OCP-Server node are as follows:

| Hardware  | Requirements                                 |
|-------|------------------------------------|
| CPU   | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE NIC                               |

OCP-Agent consumes very few resources and does not have specific hardware requirements.

#### Operating system requirements

The following table lists the operating systems supported for installing OCP Server (including OCP-Agent).

| Server type       | Operating system       | Supported versions      |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
