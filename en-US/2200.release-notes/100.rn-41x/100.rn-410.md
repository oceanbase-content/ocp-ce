# OCP V4.1.0

#RNDate#2023-05-26

## V4.1.0 BP2

### Version information

* **Version:** V4.1.0 BP2

* **Previous version:** V4.1.0 BP1

* **Version release date:** September 1, 2023

### Bug fixes

* Fixed the issue where the displayed CPU usage of a tenant was 100 times higher than the actual value.

* Fixed the issue where a non-root user might fail to add a host.

* Fixed the issue where the cleanup of useless alert history failed.

* Fixed the issue where the displayed transaction response time in monitoring was 1,000 times higher than the actual value.

* Fixed the issue where some real-time monitoring data was delayed by two minutes before it could be queried.

* Fixed the issue where more than two units could not be selected during expansion.

## V4.1.0 BP1

### Version information

* **Version:** V4.1.0 BP1

* **Previous version:** V4.1.0

* **Version release date:** July 20, 2023

### New features

* Added support for OAuth2 and CAS, two common single sign-on (SSO) authentication and authorization methods.

* Optimized English terms and text within the product to support language switching, meeting internationalization requirements.

* Optimized the startup logic of OBAgent to support automatic cleanup of historical PID files.

* Added support for O&M management of basic scenarios in OceanBase V4.2.0.0 to support POCs.

### Bug fixes

* Fixed issues caused by using the `127.1` address in MetaDB across OCP clusters.

* Fixed the issue where the topology diagram had no monitoring data.

* Fixed the issue where backup tasks could not be rescheduled after a secondary backup was canceled.

* Fixed the error when importing hosts via the OpenAPI.

* Optimized the issue where host addition failed in specific shell environments.

* Optimized the host addition process to allow successful addition even when ICMP is disabled.

* Optimized fault tolerance in primary-standby database switching scenarios to prohibit certain erroneous operations.

* Enhanced compatibility with the openEuler operating system in host management.

## OCP V4.1.0

OceanBase V4.x has undergone significant changes in architecture and product form, along with a host of new features. As the companion O&M management platform for OceanBase, OCP needs to present these new features in a more user-friendly manner to reduce the learning curve for users. Additionally, as a major version release, this update further enhances the product experience, adjusts the product architecture, and improves overall capabilities.

### Version information

* **Version:** V4.1.0

* **Prerequisites:** V4.0.3

* **Version Release Date:** May 26, 2023

* **Supported upgrade path:**

  * Direct upgrade from OCP V3.2.4 and later to the current version is supported.

  * For OCP V2.3.x and later versions before V3.2.4, you must upgrade to OCP V3.3.4 first.

  * For OCP versions earlier than V2.3.0, upgrade the OCP version to V2.3.x first, and then upgrade it to OCP V3.3.4.

### New Features

#### OceanBase V4.x

* **Single-unit distributed integration**

  Implement management of **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** (OceanBase V4.1 and later) and **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** in a unified manner to meet the needs of users in various scenarios.

  * You can choose between **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** and **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** in cluster creation. The deployment process of **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** environments is also simplified.

  * If **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** mode is enabled, a business tenant can be synchronously created based on the maximum available resources of the cluster when the cluster is deployed, enabling immediate business use.

  * Scale your **<UI-TERM key="ocp-v2.Cluster.New.SingleCentralized">Standalone Centralized</UI-TERM>** cluster online to a **<UI-TERM key="ocp-v2.Cluster.New.DistributedCluster">Distributed Cluster</UI-TERM>** cluster to meet your business growth and security requirements.

* **<UI-TERM key="ocp-v2.page.Cluster.ArbitrationService">Arbitration Service</UI-TERM>**

  OceanBase Database provides arbitration services for tenants of the 2F or 4F topology when the version of the OceanBase cluster is V4.1 or later. This lowers the arbitration costs of high availability in a multi-replica topology.

  * Added the **<UI-TERM key="ocp-v2.src.constant.auditEvent.ArbitrationServiceManagement">Arbitration Service Management</UI-TERM>** feature, supporting deployment, start/stop, deletion, and upgrades of arbitration services.

  * Allows deploying multiple instances of the arbitration service on one node to meet the HA requirements for arbitration across different clusters.

  * The arbitration service can be added, replaced, or removed in an OceanBase cluster of V4.1 and later.

  * When arbitration service is enabled on a cluster, you can enable or disable the arbitration service for a two-node or four-node tenant.

* **New information architecture**

  * The primary entry point **<UI-TERM key="ocp-v2.src.constant.information.SoftwarePackage">Software Package</UI-TERM>** was moved under **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** and renamed to **<UI-TERM key="ocp-v2.src.hook.useMenu.SoftwarePackageManagement">Software Package Management</UI-TERM>**.

  * Added **<UI-TERM key="ocp-v2.page.Alert">Alerts</UI-TERM>** as a primary entry. Moved **<UI-TERM key="ocp-v2.src.constant.auth.Alert">Alerts</UI-TERM>** and **<UI-TERM key="ocp-v2.page.Inspection.Inspection">Inspection</UI-TERM>** from the **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** section to this location.

  * The **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="ocp-v2.src.hook.useMenu.LogService">Log Service</UI-TERM>** menu entry has been upgraded to a top-level menu item.

  * The **<UI-TERM key="ocp-v2.Task.Detail.Task">Task</UI-TERM>** entry in **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** is moved to the top right corner of the **Dashboard**.

  * The original top-level entry **Diagnosis Center** is renamed to **<UI-TERM key="ocp-v2.src.hook.useMenu.AutonomousService">OceanBase Autonomy Service</UI-TERM>**.

  * The **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** section's **History Events** option has been renamed to **<UI-TERM key="ocp-v2.src.hook.useMenu.OperationAudit">Operation Audit</UI-TERM>**.

  * The **<UI-TERM key="ocp-v2.src.util.menu.SystemManagement">System Management</UI-TERM>** node contains the **<UI-TERM key="ocp-v2.User.Oracle.UserManagement">User Management</UI-TERM>** node.

* **Virtual Machine Template**

  Support is provided for standardized setup of database environments for hosts added to OCP.

* **Multi-Region OSS Backup**

  * OSS backup for production clusters, and replicate the local backup to an OSS instance in a different region.

  * Backup scheduling, backup cycles, and retention strategies differ between two OSS instances. Local backups are retained for 30 days, while backups to the remote OSS instance are retained for 7 days.

  * A tenant of an OceanBase cluster in another region can be restored from an OSS in another region.

  * For log backup copies, synchronize the log backups first and then the log metadata to meet the timeliness requirements of log backups.

### Feature enhancements

* When you set a backup strategy, you can specify the port number in the OSS endpoint.

* When you deploy an OBProxy cluster, the system checks whether the OBProxy log directory has read and write permissions.

* After a server restarts, the ocp_agent process is automatically started.

* SQL diagnostics support comparison of execution results on different hosts.

* When you create a cluster, you can enable the zone priority configuration switch. If the switch is disabled, the zone priority of the sys tenant follows the default behavior of OceanBase Database. Specifically, when the cluster version is earlier than V4.x, the first zone is prioritized; when the cluster version is V4.x or later, the zone priority is random.

* The backup storage trend interface on the overview page of global views is optimized for speed.

* The home page of the diagnostics center is optimized.

* The default value of the log backup delay alert is increased.

* OCP alerts are enhanced to support memory alerts for non-MemStore regions.

* You can customize the write lock wait failure count and average lock wait time alerts.

* The digest authentication method is supported for OCP Agent.

* The `max open files` parameter is added to the inspection items for the obproxy server.

* A parameter is added to control the starting OceanBase Database version for enabling cgroups.

* Monitoring queries are optimized. By using asynchronous queries, optimizing the calculation chain, and abstracting the storage layer, the peak pressure of monitoring queries is reduced, thereby improving the overall throughput of monitoring interfaces.

* The **<UI-TERM key="ocp-v2.Detail.Capacity.CapacityRisk">Capacity Risks</UI-TERM>** and tenant **<UI-TERM key="ocp-v2.Detail.Capacity.OverviewOfCapacityUsage">Capacity Usage Overview</UI-TERM>** are added to the Capacity Center.

### Security improvements

* Sensitive information involved in interactions with web page access interfaces is encrypted during transmission.

* When you deploy OCP for the first time, the system no longer provides an initial password. Instead, you need to specify a password.

* After you upload a software package, a pop-up window displays the SHA-1 value, and you need to confirm it again.

### Limitations

#### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The minimum hardware requirements for an OCP-Server node are as follows.

| Hardware  | Requirement                                 |
|-------|------------------------------------|
| CPU   | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory                         |
| NIC  | 10 GbE                               |

OCP-Agent consumes very few resources and has no special requirements for the hardware resources of the installation node.
