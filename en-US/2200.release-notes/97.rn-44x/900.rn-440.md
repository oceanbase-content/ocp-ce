### Key Features

#### Real-time monitoring

To address the complexity of full-link performance monitoring and fault location in a distributed database environment, OCP innovatively introduced a real-time monitoring solution. It established a five-level monitoring system covering OBProxy, OceanBase cluster, tenants, hosts, and Units. Through its three core capabilities, this solution redefined the O&M experience, enhancing its effectiveness and efficiency.

* **3D topology visualization**: With a dynamic 3D visualization engine, it clearly presents the logical relationships and physical deployment of OBProxy to the cluster, clusters to hosts, and tenants to OBServer. Supports topology drilling down from the overall architecture to individual units, intuitively displaying resource distribution and dependencies, making the transparent operations of a distributed architecture visible.

* **End-to-end performance monitoring with anomaly detection**: Real-time aggregation of core performance metrics such as QPS, TPS, RT, connection count, and CPU/memory utilization, supported by performance trend comparison analysis. Precisely identify performance bottlenecks. View related alarm counts and directly jump to the Alarm Center from the topology diagram, enabling one-click tracing from metric anomalies to root cause. Improve fault localization efficiency.

* **Dual-Mode Data Display**: Provides a structured table data view that combines graphical and digital information, satisfying the needs of both managers and technical personnel. It offers a global overview for managers and supports in-depth analysis for technical staff, effectively reducing the cognitive and management complexity of distributed systems.

You can better manage and optimize system performance with the full-chain real-time monitoring solution for daily O&M, fault troubleshooting, and dashboard display, thereby improving system stability and reliability.

#### KMS TDE encryption

TDE is a powerful data protection feature of OceanBase Database to ensure the security of data stored on the disk. TDE automatically encrypts data while writing it to storage devices and automatically decrypts data when reading it. This process is transparent to users. TDE helps prevent hackers and malicious users from reading sensitive data from data files, database backups, or disks.

OceanBase Database provides the TDE feature to implement encryption and decryption based on two-tiered keys. The encryption unit is a table in a tablespace. However, the tables must be encrypted. A tablespace is a collection of tables and is an ODC concept. A tablespace uses a specific encryption algorithm and data key to encrypt data stored in the tablespace. In addition, a primary key exists for each tenant, and the primary key is used to encrypt the data key of the tablespace. To prevent unauthorized decryption, the primary key is stored in a dedicated Keystore.

KMS supports key generation, storage, backup, recovery, and destruction, among other management functions. Using KMS, users can easily manage access permissions to their digital assets and ensure that only authorized users can access specific data resources. Additionally, KMS helps users avoid the security risks associated with losing or forgetting keys.

OCP serves as a proxy for the KMS service, offering unified key management services and interfaces to shield OceanBase from differences between different cloud KMS services. Users just need to provide access domain names, AKs, SKs, and master key IDs from Alibaba Cloud or Tencent Cloud to easily enable the KMS TDE encryption feature for tenants.

### New feature

#### Basic Operations

1. **Cluster Management**: During a cluster upgrade, if the dynamic partitioning feature is already enabled, you will be automatically prompted to avoid DDL operations during the upgrade. This prevents business impact or interruptions during the upgrade process. This feature is supported in OceanBase Database versions from V4.2.5 BP2 to +∞).
2. **Cluster Management**: During the installation, deployment, or upgrade of OceanBase Database, if the cluster nodes do not support the AVX instruction set, the corresponding operation will be automatically stopped to avoid potential compatibility issues. Supported OceanBase Database versions: [V4.2.5, V4.2.5 BP2) and [4.3.5, 4.3.5 BP4).
3. **Cluster management**: You can view information about master-slave instances, minor compactions, and data backup for tenants, to understand the status of the cluster more efficiently.
4. **Tenant management**: During MySQL tenant creation, you can set the `ob_compatibility_control` variable. Supported OceanBase Database versions are [V4.2.3, V4.3.0) and [V4.3.2, V4.3.5 BP3).
5. **Tenant Management**: You can define custom tenant connection strings for database access under different domains.
6. **Tenant Management**: OceanBase Database allows you to grant the `Create routine` privilege to users in a MySQL tenant. Supported OceanBase Database versions: [V4.2.2, V4.3.0) and [V4.3.1, +∞).

#### Monitoring alerts

1. Supports OceanBase V2.x/V3.x primary-standby cluster synchronization status (SYNCHRONIZATION_STATUS) alerts.
2. Add 8 metrics to the tenant: success rate of read lock acquisition, success rate of write lock acquisition, success rate of RPC request, number of GTS requests, transaction rollback rate, cache hit ratio of fuse rows, cache hit ratio of schema, cache hit ratio of temporary page.
3. Two new cluster-level monitoring indicators are added: RPC network latency in the sampling period and RPC delivery failure in the sampling period.
4. It supports displaying the maximum, average, and current values of the monitored indicators within the specified time range for an OBProxy cluster.

#### Disaster recovery management

1. The primary and standby tenants support multiple standby tenants and cascading for disaster recovery. In a multi standby configuration, a standby tenant can switch the data source for synchronization at any time. This feature is convenient for users to conduct remote switching exercises.
2. When you create a standby tenant in archive mode, you can use the `ocp.standby.tenant.restore.advance.seconds` parameter to set the earliest time that the tenant can be restored, that is, the start time of the restoration process. The default value is current time minus 60 seconds.
3. Tenants' primary and standby relationships are displayed on the Tenants Overview page.

#### Emergency Management

1. In scenarios involving one primary and one standby tenant where both are configured with the same service name, the system supports automatic read traffic switching from the standby tenant to the primary tenant when the standby tenant's service fails.
2. Support for automatically restarting the Binlog process (OBM) after a crash. The restart only occurs once within 30 minutes.

#### Binlog Management

In a binlog instance, you can configure a position to set the Clog parsing starting point, which allows downstream applications to subscribe to the Clog files by need.

#### Backup and restore

1. You can enable or disable the dynamic partition feature based on the actual business scenario during a full restore to prevent data loss in partitions. The OceanBase Database version supported by this feature is [V4.3.5 BP2, +∞).
2. Quick tenant recovery is supported. The recovered tenant is in read-only mode and does not support major compactions or data backup. OceanBase Database version 4.3.3 and later are supported.
3. When a tenant is locked, it is skipped by default during a backup at the cluster level.
4. For the S3 compatibility mode, support the advanced options for object storage:
   * The value of delete_mode is "delete" (default) or "tagging". The supported OceanBase Database versions are V4.2.3.0 to V4.2.5.0 and V4.3.0 or later.
   * checksum_type=md5 (default) / crc32. Supported OceanBase Database versions: V4.2.1.6 to V4.2.2.0 and V4.2.3.0 to +∞.
   * addressing_model=virtual_hosted_style (default)/path_style, supported for OceanBase Database versions in the [V4.2.1.9, V4.2.2.0) interval, [V4.2.5.1, V4.3.0.0) interval, and [V4.3.5.0, +∞) interval.

### Product improvement

#### Cluster Management

1. You can view the utilization of CPU, memory, log disk, and data disks in the Resources tab. This helps you to monitor the resource usage in real time and improve O&M efficiency.
2. If only one OBServer node exists in a zone of the cluster and there are replicas on this node, you cannot reinstall the node.

#### Tenant Management

The system supports searching for tenant specifications by unit specification name, thus improving query efficiency when multiple tenant specification names exist.

#### Host Management

The operation column of the hosts list provides the view button to view the standardization report of a host.

#### Recovery

1. The sys tenant, which is not a system management tenant, has been removed for its backup and restore page to avoid confusion and prevent misoperations. Supported OceanBase versions range from V4.0 to +∞.
2. You can choose to view the progress of tasks in the task center or stay on the task initiation page to continue operations when you restore a tenant.

#### Others

1. The AI assistant provides general conversation capabilities and document search capabilities for scenarios where large models are not configured.
2. Remove the character limit on labels displayed on the detail pages of a cluster, tenant, OBProxy, or host.
3. **Operation Audit** supports displaying the IP addresses of clients that access the database.

### Product Behavior Changes

1. Since the change of behavior of Tencent Cloud COS might result in abnormal database log backup, it is recommended to use the S3 protocol to replace the COS protocol. The supported OceanBase versions are [V4.2.1.9, V4.2.2), [V4.2.5.0, V4.3.0), and [V4.3.3.0, V4.4.0). The OceanBase V4.4.0 and later versions do not support the COS protocol.
2. The service exclusive host limit for the binlog service is removed, allowing multiple products to use the same host (only recommended for test environments), effectively reducing deployment and O&M costs.

The following table lists the minimum hardware requirements for OCP-Server nodes.

| Hardware | Requirement                 |
|-------|------------------------------------|
