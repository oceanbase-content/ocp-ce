# OCP V3.3.4

#RNDate#2022-10-21

OceanBase Cloud Platform (OCP) has been upgraded to support more audit events and other features have been optimized.

## Version information

* **Version:** V3.3.4

* **Previous version:** V3.3.3

* **Version release date:** October 21, 2022

* **Supported upgrade path:** OCP V2.3.x and later versions can be directly upgraded to this version. For OCP versions earlier than V2.3.0, you must first upgrade to V2.3.x and then to this version.

## Supported OceanBase Database versions

OCP V3.3.4 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## Feature enhancements

* Operation audit: added audit events, including stopping a zone, starting a zone, restarting a zone, modifying the deadlock detection switch, deleting a software package, modifying the OceanBase cluster TopSQL switch, triggering an OceanBase cluster major compaction, clearing the OceanBase cluster major compaction failure status, and tenant unit maintenance (scaling in/out).

* In the **<UI-TERM key="ocp-v2.page.Overview.SuspiciousSql">Suspicious SQL</UI-TERM>** section of the diagnostics, a new judgment mode is added. If the value of PARTITION_CNT is greater than AffectRows, it is marked as **<UI-TERM key="ocp-v2.page.Diagnosis.SuspiciousSql">Suspicious SQL</UI-TERM>**.

* Optimized the standby cluster creation process. The success flag of the primary and standby cluster creation is adjusted from the original **add standby command success** to **snapshot access completed**.

* Optimized the test alert feature by adding default values for environment variables to improve the success rate of test alerts.

* Optimized the pre-check logic for the secondary backup path to prohibit the existence of directories with the same cluster name under the backup path.

## Fixed issues

OCP V3.3.4 fixes the following issues:

1. Fixed the issue where the unit of the system variable `connect_timeout` was incorrectly written as **<UI-TERM key="ocp-v2.Backup.Component.RestoreNow.Microseconds">Microseconds</UI-TERM>** instead of **<UI-TERM key="ocp-v2.Alarm.Rule.Detail.Seconds">Seconds</UI-TERM>**.

2. Fixed the issue where OCP could not start when the flow control was disabled.

3. Fixed the issue where the host IP address description in an alert message was incorrect, and the tenant list description was incorrect.

4. Fixed the issue where some parameters that cannot be modified were displayed as modifiable in the frontend.

5. Optimized the performance of AWR report generation to reduce the frequency of report generation timeouts when the number of tenants exceeds 100.

6. Optimized internal table query statements to avoid abnormal cluster status display due to business pressure.

7. Optimized the fault tolerance of host maintenance operations.

8. Optimized the Grafana monitoring push logic to avoid situations where no data is displayed.

9. Optimized the NTP delay collection method for hosts to improve accuracy under high load conditions.

## Version limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports multi-node high availability deployment.

The minimum hardware requirements for OCP-Server nodes are as follows:

| Hardware | Requirements |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 cores</li><li>ARM aarch 64 architecture, 8 cores</li> |
| Memory  | 16 GB of available memory |
| Network card  | 10 GbE |

OCP-Agent consumes very few resources and has no special hardware requirements for the installation node.

### Operating system requirements

The operating system requirements for installing OCP Server (including OCP-Agent) are as follows:

|    Server type    |    Operating system    |   Supported versions    |
|-------------|------------|-----------|
| x86_64      | RHEL       | 7.2 and later |
| x86_64      | CentOS     | 7.2 and later |
| x86_64      | AliOS      | 7.2 and later |
| x86_64      | openSUSE   | 12 SP3 and later |
| ARM aarch64 | AliOS      | 7.2 and later |
| ARM aarch64 | NeoKylin       | 7.6       |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8   |

### Client requirements

| Browser     | Minimum version |
|---------|------|
| Chrome  | 81   |
| Firefox | 64   |
| Safari  | 10   |
| Edge    | 13   |
