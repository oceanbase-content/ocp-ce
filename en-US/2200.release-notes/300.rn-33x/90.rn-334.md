# OCP V3.3.4

<!--#RNDate#2022-10-21-->

The new version of OceanBase Cloud Platform (OCP) introduces several audit events and provides enhancements and optimizations for other features.

## Version information

* **Version:** V3.3.4

* **Previous version:** V3.3.3

* **Release date:** October 21, 2022

* **Supported upgrade path:** You can directly upgrade from OCP V2.3.x and later versions to this version. For versions earlier than OCP V2.3.0, you must first upgrade to V2.3.x and then to this version.

## Supported OceanBase Database versions

OCP V3.3.4 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## Feature enhancements

* Operation auditing: Added audit events for stopping a zone, starting a zone, restarting a zone, modifying the deadlock detection switch, deleting a software package, modifying the OceanBase cluster TopSQL switch, triggering an OceanBase cluster major compaction, clearing an OceanBase cluster major compaction failure status, and tenant unit maintenance (scaling).

* Added a new judgment mode for **suspicious SQL** in diagnostics: a statement is listed as **suspicious SQL** when PARTITION_CNT is greater than AffectRows.

* Optimized the standby cluster creation process. The success flag for creating primary and standby clusters has been changed from **add standy command successful** to **Snapshot Access Completed**.

* Optimized the test alert feature by adding default environment variable values to improve the success rate of test alerts.

* Optimized the pre-check logic for the secondary backup path to prohibit directories with the same cluster name in the backup path.

## Bug fixes

OCP V3.3.4 fixes the following issues:

1. Fixed an issue where the unit of the system variable `connect_timeout` was mistakenly written as **microseconds** instead of **seconds**.

2. Fixed the issue where OCP could not start when flow control was disabled.

3. Fixed incorrect host IP address descriptions for certain alert messages, as well as incorrect tenant list descriptions.

4. Fixed the issue where some unmodifiable parameters were displayed as modifiable in the frontend.

5. Optimized AWR report generation performance to reduce the frequency of report generation timeouts for tenants with a large number of instances (100+).

6. Optimized internal table query statements to avoid abnormal cluster status display due to business load.

7. Improved the fault tolerance of host maintenance operations.

8. Optimized the Grafana monitoring push logic to avoid data absence.

9. Optimized the host NTP latency collection method to improve accuracy under high host load conditions.

## Version requirements

### Hardware requirements

OCP-Server can be installed on physical servers or run in Docker containers. OCP-Server supports multi-node high-availability deployment.

The minimum hardware requirements for an OCP-Server node are listed in the following table.

| Hardware | Requirements |
| ----- | ------------------------------------ |
| CPU | <li>x86_64, 8-core</li><li>ARM AArch64 architecture, 8-core</li> |
| Memory | Available Memory: 16 GB |
| NIC | 10 Gbit/s NIC |

OCP-Agent consumes minimal resources and has no specific hardware requirement for the installation node.

### Operating system requirements

The operating system requirements for installing the OCP server (including OCP-Agent) are listed in the following table.

| Server Type | Operating System | Supported Versions |
| ------------- | ------------ | ----------- |
| x86_64 | RHEL | 7.2 and later |
| x86_64 | CentOS | 7.2 and later |
| x86_64 | AliOS | 7.2 and later |
| x86_64 | openSUSE | 12 SP3 and later |
| ARM aarch64 | AliOS | 7.2 and later |
| ARM aarch64 | NeoKylin | 7.6 |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8 |

### Client requirements

| Browser | Minimum Version |
| --------- | ------ |
| Chrome | 81 |
| Firefox | 64 |
| Safari | 10 |
