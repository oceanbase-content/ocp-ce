# OCP V3.3.3

#RNDate#2022-07-18

The current new version of the OceanBase Cloud Platform (OCP) is mainly upgraded for the encryption box, inspection feature, and compatibility with the OceanBase version, as well as other features are also optimized.

## Version information

* **Version:** V3.3.3

* **Version:** V3.3.1

* **Version release date:** July 18, 2022

* **Supported upgrade path:** You can directly upgrade OCP V2.3.x and later versions to this version. If you have an OCP version earlier than V2.3.0, first upgrade it to OCP V2.3.x and then upgrade it to this version.

## Supported OceanBase Database versions

The following table describes the supported OceanBase Database versions in OCP V3.3.2.

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## What's new?

### Safe

* Support import, export, and sharing of cluster passwords and tenant passwords for assumed clusters.

* Ability to share the connection credentials in the password box with other OCP users.

### Monitoring

The **Memory Usage** indicator is added to the Tenant Performance Monitoring page. The indicator specifies the percentage of memory that is used by the tenants of OceanBase Database.

### Security

* Added the **Set Password to Activate Account** feature. When you first log in to OCP, you need to modify the password of the built-in account.

* In the browser console, remove the prompt about plain passwords to enhance system security.

## Fixed Issues

OCP V3.3.2 fixed the following issues:

* Improve agent performance and stability

* Optimized Server end thread pool logic to improve monitoring query performance.

* Optimize backup and restore data collection process to improve OCP stability for large volume backup.

* Improve the real-time availability of SQL diagnostic data and enhance the speed at which OAS retrieves diagnostic data.

* Optimize the permission validation logic for the admin account to adapt to the private cloud scenario.

* Optimize the pre-check process for the default directory creation when you create a cluster. This allows errors to be exposed early in case of issues, preventing the need to roll back the entire task.

* Fixed the problem where mOnagent files left residual file handles.

* Fixed the issue where a cluster cannot connect in special scenarios.

* Fixed the issue with backup recovery scheduling timeout.

* Fixed an issue where you cannot view the service list after upgrading from a lower version (V2.x) to a higher version (3.x).

* Fixed an issue where the filter by status fails during backup and restore.

* Fix the NPE when there is no data in the merge management page.

* Fixes the issue where OCP V3.3.0 cannot be deployed by using OAT.

* Fixed some internationalization issues for the inspections.

* Fixed the issue where the data disk utilization displayed exceeding 100% in specific scenarios.

* Fixed a problem where CPU sys usage could not trigger an alert in abnormal conditions.

## Limitations

### Hardware requirements

OCP-Server can be installed on a physical server or in a Docker container. OCP-Server supports high-availability deployment across multiple nodes.

The following table lists the minimum hardware requirements for an OCP-Server node.

| Hardware  |                 Requirements                 |
|-----|------------------------------------|
| CPU | <li>X86_64, 8 core</li><li>ARM aarch 64 architecture, 8 core</li> |
| Memory  | 16 GB available memory                         |
| NIC | 10G NIC |

OCP-Agent occupies few resources and has no specific requirements for the hardware resources of the installation nodes.

### OS requirements
