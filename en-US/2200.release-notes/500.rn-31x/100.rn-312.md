# OCP V3.1.2

<!--#RNDate#2021-07-13-->

OceanBase Cloud Platform (OCP) V3.1.2 introduces the Active Session History report, a new feature in the Performance Diagnostics module. It provides historical active session information for the database to assist users in tenant performance diagnostics. This version also supports secondary backup in the Backup and Recovery module. Additionally, it optimizes the visual content for users with different permissions in OCP, ensuring what you see is what you get. A new feature allows for the takeover of OBProxy, ensuring the integrity of the takeover link. Furthermore, other features have been optimized and enhanced. The SQL diagnostics section now includes an export function, making it convenient for you to download and analyze issues.

## Version information

* **Version:** V3.1.2

* **Previous version:** V3.1.1

* **Release date:** September 29, 2021

* **Supported upgrade path:** You can directly upgrade from OCP V2.3.x and later versions to this version. For versions earlier than OCP V2.3.0, you must first upgrade to V2.3.x and then to this version.

## Supported OceanBase Database versions

OceanBase Cloud Platform V3.1.2 supports the following OceanBase Database versions:

* OceanBase V1.4.x

* OceanBase V2.1.x

* OceanBase V2.2.x

* OceanBase V3.1.x

* OceanBase V3.2.x

## New features

* Supports generating and downloading the Active Session History report.

  As part of the tenant performance diagnostics feature, the Active Session History report samples data from related views such as SQL, sessions, wait events, and system statistics to help users view historical active session information for the database. For more information, see [Manage Active Session History Reports](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380271).
  
* Backup and Recovery supports secondary backup.

  Secondary backup provides the capability to archive backup files to other locations, including baseline data and archived logs. Supporting secondary backup reduces storage pressure on backup files. If you need to:
  * Learn about secondary backup, see **Secondary Backup** in [Backup and Recovery Overview](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380164).

  * Use secondary backup, see [Create a Backup Policy](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380317).

* Optimized the visibility for users with different permissions in OCP.

  Blocked the entry for users without the permission, simplified the visible product paths, and reduced unnecessary clicks for users.
  
* Supports the takeover of OBProxy.

  This feature improves the takeover process to some extent. After taking over an OceanBase cluster, you can also take over its corresponding OBProxy cluster in OCP. For information about how to take over OBProxy, see [Take over OBProxy](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380261).
  
* For multi-zone mode, OCP supports GUI-based management.

  Multi-zone mode is designed for OceanBase, OCP, or OBProxy deployments across data centers or cities, allowing priority access to targets within the current zone. It effectively reduces latency and lowers cross-data-center or cross-city bandwidth costs. For more information about multi-zones, see [Multi-zone overview](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380186).

  OCP management of multi-zones supports:
  * Viewing detailed information about each zone, including the IDCs it contains and the OCP instance corresponding to each zone. For more information, see [View multi-zones](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380368).

  * Viewing or modifying multi-zone parameters. For more information, see [Manage multi-zone parameters](https://www.oceanbase.com/docs/enterprise-oceanbase-ocp-cn-10000000000380369).

## Feature enhancements

* Optimized the SQL diagnostics feature by adding the ability to export TopSQL, suspicious SQL, and SlowSQL.

* Optimized the cluster and tenant performance monitoring features by adding prompts when the collection of performance metrics for a cluster or tenant is disabled.

* Optimized memory usage for monitoring collection, ensuring OCP maintains performance as it manages more hosts.

## Bug fixes

OceanBase Cloud Platform V3.1.2 fixes the following issues:

* Inaccurate statistics for remote plans and distributed plans in the SQL diagnostics feature.

* The ob_host_log_disk_percent_over_threshold alert automatically recovered after being reported for a period without resolution, instead of persistently alerting.

* Logs containing the OBProxy type could not be decompressed when downloaded through OCP.

* After OCP upgrade, a tenant's creation time was reset to the OCP upgrade time.

* **TopSQL** contained data without SQL text.

* When modifying OBProxy parameters via OCP, some parameters could not be modified or could not be set to certain value ranges.

* Setting the tenant parameter recyclebin to ON via OCP did not take effect.

* For a partitioned table with two DATETIME fields, if only one field was used for partitioning, the **Inspection** task in **System Management** could not identify this table.

* After a primary/standby disaster recovery switchover in an OceanBase cluster, the primary/standby relationship no longer existed, but it was still displayed as such in the cluster list.

## Known issues

| 1 | An error "Exception in parsing backup file" occurs during backup and restore. | Set the system parameter ocp.backup_restore-time-pre-check.enabled to false. |

| 3 | On the **Inspection Script** tab of the **System Management \> Inspection** page, filtering by inspection object does not take effect. | Currently, the inspection object is only the cluster. No filtering or avoidance of inspection objects is required. |

| 5 | On the OBServer node side, the final directory for the secondary backup storage path of the OSS type is not created. ## Version usage limitations

### Hardware requirements

OCP-Server can be installed on physical servers or run in Docker containers. OCP-Server supports high-availability deployment with multiple nodes.

The minimum hardware requirements for an OCP-Server node are listed in the following table.

| Hardware | Requirements |
| ----- | ------------------------------------ |
| CPU | <li>x86_64, 8-core</li><li>ARM AArch64 architecture, 8-core</li> |
| Memory | Available Memory: 16 GB |
| NIC | 10 Gbit/s NIC |

OCP-Agent consumes very few resources and has no specific hardware requirements for the installation node.

### Operating system requirements

The operating system requirements for installing the OCP server (including OCP-Agent) are listed in the following table.

| Server Type | Operating System | Supported Versions |
| ------------- | ------------ | ----------- |
| x86_64 | RHEL | 7.2 and later |
| x86_64 | CentOS | 7.2 and later |
| x86_64 | AliOS | 7.2 and later |
| x86_64 | openSUSE | 12 SP3 and later |
| ARM aarch64 | AliOS | 7.2 and later |
| ARM aarch64 | NeoKylin | 7.6 |
| ARM aarch64 | Huawei EulerOS | 2.0 SP8 |

| Browser | Minimum Version |
| --------- | ------ |
| Chrome | 81 |
| Firefox | 64 |
| Safari | 10 |
