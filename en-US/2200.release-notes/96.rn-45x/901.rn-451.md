# OCP V4.5.1

OCP V4.5.1 strengthens operational capabilities for complex production environments, addressing issues such as high-risk operations relying on manual experience, backup storage being difficult to plan in tiers, and tenant capacity issues being discovered too late.

## Key features

### Standard Operating Procedure (SOP)
A new Standard Operating Procedure (SOP) feature packages complex and high-risk operations into saveable, executable, and traceable operational tasks, reducing manual confirmation steps and operation omissions.

Built-in procedures in this release:

* Rebuild Standby Tenant
* Enable Arbitration Service When Replica Anomaly Occurs
* Data Reconstruction After OBServer Anomaly

Operators can view the execution progress of each step and retry on failure. Rebuild Standby Tenant supports cross-OCP primary-standby tenant scenarios; the other two procedures only support clusters managed by the current OCP.

### Separate storage for backup data and archived logs
OceanBase 4.x clusters support setting different storage locations for backup data and archived logs, allowing you to choose between file storage and object storage based on reliability, capacity, and cost requirements. This capability covers backup policies, immediate backups, backup scanning, and tenant recovery.

The existing shared storage method remains unchanged. If you need to enable separate storage, it is recommended to complete the entire OCP upgrade first before enabling the new configuration.

### Unit data disk quota
Shared-Nothing cluster unit specifications support setting data disk quotas and displaying usage in tenant and resource views. When usage reaches 80% and 90%, the system issues warning and critical alerts respectively, allowing you to plan capacity expansion or data governance before capacity is exhausted.

This quota is a soft limit; exceeding the quota does not interrupt business writes. It applies to OceanBase 4.0 and later versions.

## Other new features and optimizations

* Standby tenants now support setting log recovery delay, with delay status monitoring and alerting.
* A new Japanese interface is added, covering major product copy for alarms, monitoring, inspection, and parameter configuration.
* KMS adapter scenarios for transparent data encryption are extended, adding solutions for Alibaba Cloud proprietary cloud, CiiSecurity (信安世纪), and Jiangnan KeeYou (江南科友, financial sector), and enhancing HTTPS access for Galaxy KMS.
* Software packages now support SHA256 verification, and upload count and total size limits are added.
* Alarm events now include resource tags, and long-transaction alarms include log stream information for easier localization of specific tenants and log streams.
* The SQL query interface supports specifying a database user, enabling queries to be executed based on existing account permissions.
* New global backup information parsing and offline recovery interfaces are added for easier integration with automated recovery workflows.
* OCP and Agent resource monitoring, real-time monitoring queries, and multilingual search experiences are optimized.

## Behavior changes and scope

### Behavior changes
* Cloning primary tenants is no longer supported; standby tenant cloning capability is unaffected.
* Software package uploads have new count and total size limits; uploads exceeding the limits are blocked by the system.

### Scope
* Separate storage for data and logs applies to OceanBase 4.x clusters; OceanBase 3.x clusters continue to use the same storage location.
* Unit data disk quotas apply to Shared-Nothing clusters and do not apply to Shared-Storage or OceanBase AI clusters.
* Enabling standby tenant log recovery delay requires OceanBase 4.4.2.2 or later; disabling delay requires OceanBase 4.4.1.9 or later.

## Major bug fixes

* Fixed issues in primary-standby tenant switchover, recovery source adjustment, and delay recovery scenarios, improving stability of cross-cluster disaster recovery operations.
* Fixed issues with backup storage identification, log backup checks, and some recovery scenarios.
* Fixed issues with AI clusters and LogService during zone stop, key rotation, and task rollback.
* Fixed slow real-time monitoring queries, missing host monitoring data, and abnormal Agent resource metric display.
* Fixed Oracle tenant query result time type anomalies and empty index information due to database name case sensitivity.
* Fixed SOP permission validation, operation object identification, task retry, and page display issues.
