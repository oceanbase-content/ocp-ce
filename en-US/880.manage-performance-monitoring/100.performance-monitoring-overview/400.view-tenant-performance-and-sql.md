# View performance and SQL

This topic describes how to view tenant performance and SQL monitoring data in OCP. You can access this information through the following two methods:

* **Method 1**: Log in to OCP, go to the Tenant Overview page, and click **<UI-TERM key="ocp-v2.src.util.menu.PerformanceMonitoring">Performance</UI-TERM>** in the left navigation pane.

* **Method 2**: Log in to OCP, click **<UI-TERM key="ocp-v2.src.hook.useMenu.PerformanceMonitoring">Performance</UI-TERM>** in the left navigation pane to go to the **<UI-TERM key="ocp-v2.src.component.ModifyTagResourceDrawer.OceanbaseTenants">OceanBase Tenant</UI-TERM>** tab.

## Prerequisites

* When viewing tenant performance and SQL performance monitoring data through **Entry 1**, ensure the current OCP user has the following permissions:

  * **Cluster Read-Only** or **Tenant Read-Only** resource permission.
  * Tenant **<UI-TERM key="ocp-v2.page.Monitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** menu permission.

* When viewing tenant performance and SQL performance monitoring data through **Entry 2**, ensure the current OCP user has the following permissions:

  * **Cluster Read-Only**, **Tenant Read-Only**, or **Host Read-Only** resource permission.
  * Performance Monitoring **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterAndHostWithExclude.All">All</UI-TERM>** menu permission.

* To view the <b>Response Time</b> monitoring chart, you must configure the following parameters in advance under <b>Tenant</b> > <b>Parameter Management</b>:

  * <code>query_response_time_stats=true</code> (Enable statistics)

  * <code>query_response_time_range_base=2</code> (Set the statistics interval)

  * <code>query_response_time_flush=true</code> (Refresh to apply the modified statistics interval)

## Version limitations

* The <b>SQL Execution Time</b> monitoring metric applies to OceanBase versions [V3.2.4.1, V4.0.0.0), [V4.1.0.0, +∞).

* The <b>SQL Execution Phase</b> monitoring metric applies to OceanBase versions [V4.2.0.0, V4.3.0.0). Specifically:

  * Sub-metrics <code>in_committing</code>, <code>in_storage_read</code>, <code>in_storage_write</code>, and <code>in_remote_das_execution</code> apply to OceanBase versions [V4.2.1.0, V4.3.0.0).
  * Sub-metrics <code>in_plsql_compilation</code> and <code>in_plsql_execution</code> apply to OceanBase versions [V4.2.2.0, V4.3.0.0).

* The <b>Clog Synchronization Latency</b> monitoring metric applies to OceanBase versions [V2.2.76, V4.0.0.0).

* The <b>Frontend Workload</b> and <b>Backend Workload</b> monitoring metrics apply to OceanBase versions [V4.2.0.0, V4.3.0.0).

* The <b>DB Time</b> monitoring metric applies to OceanBase versions [V4.2.2.0, V4.3.0.0).

* The <b>Parallel Execution Worker Thread Utilization</b> monitoring metric applies to OceanBase version [V4.0.0.0, +∞).

* For the <b>Response Time</b> monitoring metric:

  * Sub-metrics <code>99-all</code> and <code>95-all</code> apply to OceanBase versions [V4.2.1.7, V4.2.2.0), [V4.2.5.0, V4.3.0.0), [V4.3.3.0, +∞).
  * Sub-metrics <code>commit</code> and <code>rollback</code> apply to OceanBase versions [V4.2.5.3, V4.3.0.0), [V4.3.5.2, +∞).

* For the **QPS** monitoring metric, sub-metrics <code>commit</code> and <code>rollback</code> apply to OceanBase versions [V4.2.5.3, V4.3.0.0), [V4.3.5.2, +∞).
* The <b>RPC Request Success Rate</b>, <b>GTS Requests</b>, <b>RPC Network Latency</b>, and <b>RPC Delivery Failure</b> monitoring metrics apply to OceanBase versions [V2.2.70, +∞).

## Procedure

The following steps use **Entry 2** as an example.

1. Log in to OCP.

2. In the left navigation bar, select **<UI-TERM key="ocp-v2.Detail.Monitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>**.

3. Select the **<UI-TERM key="ocp-v2.Information.Detail.CreateCollectDrawer.OceanbaseTenants">OceanBase Tenant</UI-TERM>** tab.

4. In the **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">Data Filtering</UI-TERM>** section, configure the monitoring data filtering criteria.

   The filtering criteria are described in the following table:

   |     Criterion  |  Description  |
   |---------------|---------|
   | Refresh  | Refreshes monitoring data. Automatic refresh is supported and is disabled by default. When automatic refresh is enabled, you can configure the refresh frequency.|
   | Selection Time (also known as: Monitoring Window) | Not displayed in automatic refresh mode. Select a time range to retrieve data within that period.  |
   | Tenant | Select a specific tenant to monitor.  |
   | Zone  | By default, all zones are monitored.|
   | OBServer | By default, all OBServer nodes are monitored.|
  
5. The system enters the **Performance and SQL** tab by default, where you can view tenant performance and SQL monitoring data.

   * OCP supports viewing monitoring data from two dimensions: tenant and unit. Data is displayed by default in the tenant dimension. The monitoring metrics supported vary by dimension.
   * The system displays all monitoring items for the current dimension by default. If you do not need to focus on a particular monitoring item, you can uncheck it in the **<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">Selected Chart</UI-TERM>** panel on the right side of the area.
   * All monitoring items support displaying the maximum value (max), average value (avg), and current value (current) for each sub-metric.
   * For the specific meaning and value source of all monitoring items, refer to [Overview of Monitoring Metrics](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md). If the statistical range involves multiple OBServer nodes, aggregated values are displayed.

   The following features help you better view and analyze detailed performance monitoring data in trend charts. You can understand them in combination with the images and the following text.

   <!-- ![Image 114](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1725.png) -->

   * View and hide data for other sub-metrics: Hover the cursor over the metric area and scroll the mouse wheel up or down to view data for all sub-metrics displayed in the trend chart. Click the identifier of another sub-metric to gray it out, and that metric's information will not be displayed in the trend chart.

   * Hover the cursor over a point in time in the trend chart to view detailed data at that moment. Drag the cursor to select an area, and the system will zoom in to display the trend information for that area. You can view the detailed trend of that metric during this time period. Double-click the trend chart to restore it.

   * Zoom in on a trend chart: Click the zoom icon in the upper-right corner of the trend chart. The functions of ① and ② in the preceding figure also apply to the zoomed-in trend chart.

   * Edit a monitoring metric: Click the edit icon in the upper-right corner of the trend chart to choose which sub-metrics to display.

   * Drill down to view monitoring data from different dimensions: On the **<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.Tenant">Tenants</UI-TERM>** tab, if you find abnormal monitoring data for a tenant, such as excessively high tenant response time, you can perform drill-down analysis to locate the server causing the abnormal response time. Click the **<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">Drill-down Analysis</UI-TERM>** icon in the upper-right corner of the trend chart to view the drill-down analysis details. **Performance and SQL** supports drilling down by the following dimensions: **Tenant \> OBServer**.

       The functions of ① and ② in the preceding figure also apply to the trend chart on the drill-down page. Additionally, you can:

       * Reset the filtering criteria on the drill-down page. If you have not set criteria, the settings from the parent level will be automatically inherited.

       * If the metric has sub-metrics, you can select them to view.

       * The trend chart provides an SQL search function. Click the corresponding link to view the TopSQL diagnostic details for the tenant.

       * Provides the **Go to Host Performance Monitoring** feature. Hover the cursor over the **Go to Host Performance Monitoring** link and select the host you want to view to jump to the **<UI-TERM key="ocp-v2.page.Monitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** page of the relevant host for detailed monitoring information.

   * View SQL request analysis: In the **<UI-TERM key="ocp-v2.src.constant.sqlDiagnosis.ResponseTime">Response Time</UI-TERM>** trend chart, click the **<UI-TERM key="ocp-v2.component.MetricChart.Item.SqlRequestAnalysis">SQL Request Analysis</UI-TERM>** icon in the upper-right corner of the chart to view the request analysis details. For more information, see [View request analysis](../../1000.diagnosis-and-tuning-fuctions/100.manage-sql-diagnosis/1300.view-request-analysis.md).

     <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>Only <strong>Response Time</strong> supports viewing SQL request analysis.</p>
     </main>

   * View session analysis: In the **<UI-TERM key="ocp-v2.src.constant.monitor.Sessions">Sessions</UI-TERM>** trend chart, click the **<UI-TERM key="ocp-v2.component.MetricChart.Item.SessionAnalysis">Session Analysis</UI-TERM>** icon in the upper-right corner of the chart to view the session analysis details. For more information, see [Manage tenant sessions](../../1000.diagnosis-and-tuning-fuctions/300.manage-session/100.manage-tenant-sessions.md).

     <main id="notice" type='explain'>
     <h4>Note</h4>
     <p>Only <strong>Sessions</strong> supports viewing session analysis.</p>
     </main>
