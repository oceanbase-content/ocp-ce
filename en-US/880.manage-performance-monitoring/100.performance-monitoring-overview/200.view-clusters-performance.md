# View database performance

OCP supports viewing performance monitoring data in a cluster from different dimensions. You can view the data through the following two methods:

* **Method 1**: Log in to OCP, go to the cluster overview page, and click **<UI-TERM key="ocp-v2.Instance.Monitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** in the left navigation pane.

* **Method 2**: Log in to OCP, click **<UI-TERM key="ocp-v2.src.hook.useMenu.PerformanceMonitoring">Performance</UI-TERM>** in the left navigation pane. The system goes to the **<UI-TERM key="ocp-v2.Task.TaskObjectAndType.OceanbaseCluster">OceanBase Cluster</UI-TERM>** tab by default.

## Prerequisites

* When viewing cluster database performance monitoring data using **Method 1**, ensure the currently logged-in OCP user has the following permissions:

  * **Cluster Read-Only** resource permission.
  * Cluster **<UI-TERM key="ocp-v2.src.util.menu.PerformanceMonitoring">Performance</UI-TERM>** menu permission.

* When viewing cluster database performance monitoring data using **Method 2**, ensure the currently logged-in OCP user has the following permissions:

  * Any one of the **Cluster Read-Only**, **Tenant Read-Only**, or **Host Read-Only** resource permissions.
  * Performance Monitoring **<UI-TERM key="ocp-v2.component.common.BinlogClusterSelect.All">All</UI-TERM>** menu permission.

## Version limitations

* For the <b>SQL Response Time</b> monitoring metric:

  * The sub-metrics <code>99-all</code> and <code>95-all</code> apply to OceanBase versions [V4.2.1.7, V4.2.2.0).
  * The sub-metrics <code>commit</code> and <code>rollback</code> apply to OceanBase versions [V4.2.5.3, V4.3.0.0), [V4.3.5.2, +∞).

* For the **QPS** monitoring metric, the sub-metrics <code>commit</code> and <code>rollback</code> apply to OceanBase versions [V4.2.5.3, V4.3.0.0), [V4.3.5.2, +∞).

* For the <b>Transaction Log Time</b> monitoring metric:

  * The sub-metric <code>write_disk</code> applies to OceanBase versions [-∞, V4.1.0.3).
  * The sub-metric <code>clog_write</code> applies to OceanBase versions [V4.1.0.3, +∞).

* For the <b>Physical IO Count</b>, <b>Physical IO Time</b>, and <b>Physical IO Throughput</b> monitoring metrics, the sub-metrics <code>clog_read</code> and <code>clog_write</code> apply to OceanBase versions [V4.1.0.3, +∞).

<main id="notice" type='explain'>
<h4>Note</h4>
<p>When the cluster is an AI cluster (with shared storage), the data disk-related metrics in database performance monitoring are displayed as cache disk metrics. Additionally, the <b>Object Storage IOPS</b> and <b>Object Storage Bandwidth</b> monitoring metrics are added to monitor the read/write performance of object storage.</p>
</main>

## Procedure

The following procedure uses **Method 2** as an example.

1. Log in to OCP.

2. Select **<UI-TERM key="ocp-v2.page.Monitor.Monitoring">Performance Monitoring</UI-TERM>** from the left navigation pane.

3. The system enters the **<UI-TERM key="ocp-v2.Component.ClusterFilter.OceanbaseCluster">OceanBase Cluster</UI-TERM>** tab by default.

4. In the **<UI-TERM key="ocp-v2.component.MonitorSearch.DataFiltering">Data Filtering</UI-TERM>** section, configure the monitoring data filter conditions.

   The filter conditions are described in the following table:

   | Filter Condition | Description |
   |---------------|---------|
   | Refresh | Refreshes the monitoring data. Automatic refresh is supported and is disabled by default. When automatic refresh is enabled, you can configure the refresh frequency.|
   | Time Range (also known as Monitoring Window) | Not displayed in automatic refresh mode. Select a time range to return data within that period.  |
   | Cluster | Select a cluster to monitor.  |
   | Zone | Monitors all zones by default.|
   | OBServer | Monitors all OBServer nodes by default.|

5. The system enters the **Database Performance** tab by default, where you can view the cluster's database performance monitoring data.

   <!-- ![1126](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/433/202411181453.png) -->

   * OCP supports viewing database performance monitoring data from four dimensions: cluster, tenant, OBServer, and unit. Data is displayed by default at the cluster level. The monitoring metrics supported vary by dimension.
   * The system displays all monitoring items for the current dimension by default. If you do not need to pay attention to a certain monitoring item, you can uncheck it in the **<UI-TERM key="ocp-v2.Detail.Monitor.IndicatorSelection">Selected Chart</UI-TERM>** panel on the right side of the area.
   * All monitoring items support displaying the maximum value (max), average value (avg), and current value (current) of each sub-metric.
   * For the specific meaning and source of values for all monitoring items, refer to [Overview of Monitoring Metrics](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md).

   The following features help you better view and analyze performance monitoring data in trend charts. You can understand them in combination with the images and the following text.

   <!-- ![1](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/ocp/436/1127.png) -->

   1. View and hide data for other sub-metrics: Hover the cursor over the metric area and scroll the mouse wheel up or down to view data for all sub-metrics displayed in the trend chart. Click another sub-metric identifier to gray it out, and that metric's information will not be displayed in the trend chart.

   2. Hover the cursor over a point in time in the trend chart to view detailed data for that moment. Drag the cursor to select an area, and the system will zoom in to show the trend information for that area. You can view the detailed trend of the metric during this period. Double-click the trend chart to restore it.

   3. Zoom in on a trend chart: Click the zoom icon in the upper-right corner of the trend chart. Functions ① and ② shown above also apply to the zoomed-in trend chart.

   4. Edit a monitoring metric: Click the edit icon in the upper-right corner of the trend chart to choose which sub-metrics to display.

   5. Drill down to view monitoring data at different dimensions: On the **<UI-TERM key="ocp-performance-report.pages.AWR.ReportContent.ClusterDimension">Cluster</UI-TERM>** tab, if you find abnormal monitoring data for a cluster, such as excessively high SQL response time, you can drill down to analyze and locate the server causing the abnormal response time. Click the **<UI-TERM key="ocp-v2.component.MetricChart.Item.DrillDownAnalysis">Drill-down Analysis</UI-TERM>** icon in the upper-right corner of the trend chart. The supported drill-down dimensions are: **Cluster \> Tenant \> OBServer**.

      Functions ① and ② shown above also apply to the trend chart on the drill-down page. Additionally, you can:

      1. Reset filter conditions on the drill-down page. If not set, they will automatically inherit the settings from the parent level.

      2. If the metric has sub-metrics, you can select a sub-metric to view; or click ① or ② as shown in the figure to drill down to different dimensions for further analysis.

      3. If the metric involves tenant or host performance, the trend chart provides direct links to the **<UI-TERM key="ocp-v2.Host.Detail.Surveillance">Monitoring</UI-TERM>** page of the relevant tenant or host.

         * To go to the tenant **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** page: Hover the mouse over the **<UI-TERM key="ocp-v2.Detail.Component.DirectToTenantList.GoToTenantPerformanceMonitoring">Go to Tenant Performance Monitoring</UI-TERM>** link in the upper-right corner of the trend chart, select the corresponding tenant, and click.

         * To go to the host **<UI-TERM key="ocp-v2.Monitor.AddMonitor.PerformanceMonitoring">Performance Monitoring</UI-TERM>** page: Hover the mouse over the **Go to Host Performance Monitoring** link in the upper-right corner of the trend chart, select the corresponding host, and click.

6. (Optional) Configure the monitoring collection interval.

   Currently, OCP collects second-level monitoring data by default every 1 second. This collection scale places high demands on both OCP Server performance and MonitorDB storage performance. If your requirements for monitoring data are not stringent, you can modify the value of `ocp.metric.collect.interval.second` in the `config_properties` file to configure a different monitoring collection interval, thereby reducing resource consumption and increasing the overall management scale.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Currently, only the values 1, 5, 10, and 15 are supported for configuration. If you enter a value other than those listed above, the system will automatically adapt it:</p>
    <ul>
    <li>Values less than 1 are uniformly set to 1.</li>
    <li>Values in the [1,5) range are downward-compatible with 1.</li>
    <li>Values in the [5,10) range are downward-compatible with 5.</li>
    <li>Values in the [10,15) range are downward-compatible with 10.</li>
    <li>Other values are uniformly set to 15.</li>
    </ul>
    </main>

   After the configuration is modified, OCP will immediately start collecting data at the new interval. The display interval for monitoring data defaults to three times the collection interval, except when the collection interval is 1 second. For example, if the collection interval is 5 seconds, the display interval for querying second-level monitoring data will be 15 seconds.
