# Create a standard operation and maintenance process

This topic describes how to create a Standard Operation and Maintenance Process (SOP) task in OCP.

## Prerequisites

* The current OCP user has any of the **Cluster Management**, **Tenant Management**, or **Host Management** resource permissions (for operating the target resource).
* The **Update** permission on the cluster/tenant/host (for creating, starting, or executing steps).
* SOP permissions are automatically determined by the system based on the logged-in user's identity. For details, see [Overview of Standard Operation and Maintenance Processes](100.sop-overview.md#权限说明).

<main id="notice" type='notice'>
<h4>Applicability</h4>
<p>This content applies only to OCP Enterprise Edition. OCP Community Edition does not provide this feature.</p>
</main>

## Background information

When you need to perform standardized fault recovery operations on an OceanBase cluster, tenant, or host, you can create a new SOP task to accomplish it. OCP provides preset process templates. You only need to select the task type and configure the target parameters and steps to create a standard operation and maintenance process task.

## Procedure

1. Log in to OCP.

2. In the left navigation bar, click **<UI-TERM key="ocp-v2.src.hook.useMenu.OMManagement">O&M</UI-TERM>** > **<UI-TERM key="ocp-v2.src.hook.useMenu.StandardProcess">Standard workflow</UI-TERM>**.

3. On the **<UI-TERM key="ocp-v2.pages.Sop.StandardProcess">Standard workflow</UI-TERM>** page, click **<UI-TERM key="ocp-v2.Cluster.New.New">Create</UI-TERM>**. The system pops up the **<UI-TERM key="ocp-v2.Sop.CreateTaskDrawer.NewStandardOperationAndMaintenance">Create standard O&M workflow</UI-TERM>** dialog box.

4. Configure the following information in the **<UI-TERM key="ocp-v2.Sop.CreateTaskDrawer.NewStandardOperationAndMaintenance">Create standard O&M workflow</UI-TERM>** dialog box.

   1. Configure basic information.

      | Parameter | Description |
      |------|------|
      | **<UI-TERM key="ocp-v2.page.Result.Success.TaskName">Task Name</UI-TERM>** | Enter the task name. It must meet the following rules:<ul><li>Supports 2 to 32 characters.</li><li>Must start with a Chinese, Japanese character, or English letter.</li><li>Must end with a Chinese, Japanese character, English letter, or number.</li><li>Only underscores are supported as special characters.</li></ul>The task name must be globally unique. |
      | **<UI-TERM key="ocp-v2.pages.Schedule.TaskType">Task Type</UI-TERM>** | Select the SOP task type. Options include **<UI-TERM key="ocp-v2.component.SopImage.RebuildStandbyTenant">Rebuild standby tenant</UI-TERM>**, **<UI-TERM key="ocp-v2.Sop.core.constants.QuorumServiceEnabledWithCopy">Enable arbitration service after a replica failure</UI-TERM>**, or **Data Rebuilding after OBServer Exception**. For detailed descriptions, see [Overview of Standard Operation and Maintenance Processes](100.sop-overview.md#sop-类型说明). |
      | **<UI-TERM key="ocp-v2.src.component.AddArbitrationDrawer.Description">Remarks</UI-TERM>** (Optional) | Enter task remarks to record the purpose or description of the task. |
      | **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ExecuteNow">Execute Now</UI-TERM>** | If selected, the task will start immediately after creation. If not selected, the task status will be **<UI-TERM key="ocp-v2.Plan.Component.PlanExecuteTable_PENDINGExecution">Pending Execution</UI-TERM>** after creation, and you can manually start it later. |

   2. Configure target parameters based on the selected task type.

      * **<UI-TERM key="ocp-v2.Sop.core.constants.RebuildStandbyTenant">Rebuild standby tenant</UI-TERM>**: Select the cluster and standby tenant to rebuild, and choose the primary/standby synchronization method (network-based or archive-based).

      * **<UI-TERM key="ocp-v2.Sop.core.constants.QuorumServiceEnabledWithCopy">Enable arbitration service after a replica failure</UI-TERM>**: Select the target cluster, and choose the arbitration service or arbitration service group (choose one).

      * **Data Rebuilding after OBServer Exception**: Select the target cluster. You can preselect an alternative host. If no alternative host is selected, you can set it before performing the **<UI-TERM key="ocp-v2.Cluster.Detail.AddObserver">Add OBServer</UI-TERM>** step.

   3. Configure the steps.

      The system automatically loads the default step template based on the selected task type. You can view and adjust the configuration for each step:

      | Parameter | Description |
      |------|------|
      | Step Number | The execution order of the step, starting from 1. Steps that can be moved are adjustable within the template. |
      | Step Name | The display name of the current step. |
      | Step Type | **EXECUTABLE**: An executable step that may create an OCP task instance; **CONFIRMATION**: A confirmation step that does not create a task instance. |
      | **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.CreateArbitrationGroup.AutomaticExecution">Automatic Execution</UI-TERM>** | When enabled, this step is automatically triggered after the previous step completes. When disabled, this step requires manual confirmation before proceeding. The automatic execution switch for some steps cannot be modified. |
      | **<UI-TERM key="ocp-v2.Prometheus.Component.Main.Enable">Enable</UI-TERM>** | Whether to enable this step. Some steps are fixed to be enabled and cannot be disabled.|

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><ul><li>The <b>stepKey</b> of a step must belong to the template and be unique.</li><li>Steps that are fixed to be enabled must be retained and cannot be disabled.</li><li>Whether the automatic execution switch for a step can be modified depends on the <b>editable</b> attribute of that step in the template.</li></ul></p>
      </main>

5. Click **<UI-TERM key="ocp-v2.ObjectStorage.Component.Main.NewCreation">Create</UI-TERM>**.

   * If **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ExecuteNow">Execute Now</UI-TERM>** is selected, the task starts automatically after creation, and the page jumps to the execution details page.
   * If **<UI-TERM key="ocp-v2.Alarm.Event.Detail.ExecuteNow">Execute Now</UI-TERM>** is not selected, the status of the task after successful creation is **<UI-TERM key="ocp-v2.src.constant.schedule.ToBeImplemented">Pending</UI-TERM>**. You can view it in the task list and start its execution at any time.

## What to do next

* For tasks in the **Pending Execution** state, you can start their execution, edit task configurations, or delete the tasks.
* For tasks that are in progress, you can view execution details, proceed to the next step, retry failed steps, or update step configurations. For more information, see [View execution details of a standard O&M process](300.view-sop-execution-details.md).
