# Manage performance reports

This topic describes how to use performance reports. Performance reports help you understand the cluster load, performance, SQL, and other information within a specified time period. This facilitates understanding the cluster's operational status and aids in troubleshooting performance-related issues.

You can view and manage performance reports through the following two methods:

* **Method 1**: Log in to OCP, click **Diagnostic Services** in the left navigation bar, select the cluster you want to view, and go to the cluster **<UI-TERM key="ocp-v2.src.hook.useMenu.ReportCenter">Report Center</UI-TERM>** page.

* **Method 2**: Log in to OCP, go to the cluster **<UI-TERM key="ocp-v2.Backup.Overview.Statistics.SummaryInvestingComZa">Overview</UI-TERM>** page, and click **<UI-TERM key="ocp-v2.Report.Detail.PerformanceReport">Performance Report</UI-TERM>** on the left.

<main id="notice" type='notice'>
  <h4>Applicability</h4>
  <p>This content applies only to OCP Enterprise Edition. OCP Community Edition does not provide this feature.</p>
</main>

## Performance report overview

OCP currently supports generating cluster performance reports. On the report list page, you can view the **<UI-TERM key="ocp-v2.Detail.Report.ReportName">Report Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Report.StartSnapshotPoint">Snapshot Start Point</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Report.EndSnapshot">Snapshot End Point</UI-TERM>**, **<UI-TERM key="ocp-v2.Alarm.Channel.Founder">Created By</UI-TERM>**, **<UI-TERM key="ocp-v2.Session.Report.GenerationStatus">Status</UI-TERM>**, and **<UI-TERM key="ocp-v2.Detail.Report.GenerationTime">Generation Time</UI-TERM>** of a performance report, and perform the **<UI-TERM key="ocp-v2.Inspection.Item.ViewReports">View Report</UI-TERM>** and **<UI-TERM key="ocp-v2.src.constant.inspection.DownloadReport">Download Report</UI-TERM>** operations.

* You can sort reports by the time sequence of **<UI-TERM key="ocp-v2.Report.Component.GenerateReportModal.StartSnapshotPoint">Snapshot Start Point</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Report.EndSnapshot">Snapshot End Point</UI-TERM>**, and **<UI-TERM key="ocp-v2.Detail.Report.GenerationTime">Generation Time</UI-TERM>**.

* You can filter the report list by **<UI-TERM key="ocp-v2.Session.Report.GenerationStatus">Status</UI-TERM>**.

## Prerequisites

* When managing performance reports via **Method 1**, ensure the current OCP user has the following permissions:

  * **Cluster Read-Only** resource permission.
  * Diagnostic Service **<UI-TERM key="ocp-v2.src.hook.useMenu.ReportCenter">Report Center</UI-TERM>** menu permission.

* When managing performance reports via **Method 2**, ensure the current OCP user has the following permissions:

  * **Cluster Read-Only** resource permission.
  * Cluster **<UI-TERM key="ocp-v2.Report.Detail.PerformanceReport">Performance Report</UI-TERM>** menu permission.

## Procedure

The following steps use **Method 1** as an example.

1. Log in to OCP.

2. In the left navigation bar, click **Diagnostic Service**.

3. In the **<UI-TERM key="ocp-v2.page.Diagnosis.ClusterDetails">Cluster Details</UI-TERM>** section, click the name of the cluster you want to view. The system defaults to the **<UI-TERM key="ocp-v2.src.hook.useMenu.RealTimeDiagnosis">Real-time Diagnostics</UI-TERM>** page.

4. Click **<UI-TERM key="ocp-v2.Detail.Report.ReportCenter">Report Center</UI-TERM>** in the left navigation bar.

5. Go to the **<UI-TERM key="ocp-v2.Report.Detail.PerformanceReport">Performance Report</UI-TERM>** tab.

6. Click **<UI-TERM key="ocp-v2.Report.Component.GenerateReportModal.GeneratePerformanceReports">View Performance Report</UI-TERM>**.

7. In the dialog box that appears, enter the following information.

   | Parameter | Description |
   |-------|---------------------------------------------|
   | Report Name | The report name cannot be empty.                                    |
   | Start Snapshot Point | Only points within the last 30 days are supported. The available points are fixed and cannot be customized.        |
   | End Snapshot Point | Only points within 24 hours after the start snapshot point are supported. The available points are fixed and cannot be customized. |

8. When tenant-level SQL monitoring data is abnormal in the performance report, you can select and click the corresponding tenant from the **<UI-TERM key="ocp-v2.Detail.Report.GoToTenantActiveSession">View OceanBase Tenant ASH Report</UI-TERM>** drop-down list to navigate to the tenant's **<UI-TERM key="ocp-v2.Session.Report.Detail.ActiveSessionHistoryReport">ASH Report</UI-TERM>** page.

9. Click **<UI-TERM key="ocp-v2.User.Oracle.UserList.Determine">OK</UI-TERM>**. A performance report will be generated for the period between the start and end snapshot points. OCP supports saving performance reports from the last 90 days, which you can view and download from the report list.

   * View the performance report: Click **<UI-TERM key="ocp-v2.Inspection.Item.ViewReports">View Report</UI-TERM>** in the **<UI-TERM key="ocp-v2.Oracle.UserOrRoleDetail.Operation">Actions</UI-TERM>** column to view the performance report.

   * Download a performance report: In the **<UI-TERM key="ocp-v2.Restore.SamplingStrategy.Operation">Actions</UI-TERM>** column, click **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.DownloadReport">Download Report</UI-TERM>** to download the HTML-formatted performance report to your local device.

## Report content overview

You can view the following information in the performance report:

* Basic information

  | Parameter | Description |
  |----------|---------|
  | Cluster basic information | You can view the cluster version, cluster type, number of hosts, number of tenants, start time of the last major compaction, and end time of the last major compaction at the start snapshot point and end snapshot point. <blockquote>**<UI-TERM key="ocp-v2.src.component.AddHostCredentialDrawer.Description">Description</UI-TERM>**</br>When OceanBase Database is V4.0 or later, you cannot view the major compaction-related information.</blockquote>   |
  | Node basic information | You can view the host IP address, zone, whether the start snapshot point and end snapshot point include RS, status, service start time, and last offline time.                                                      |
  | Node resource information | You can view the host IP address, zone, total CPU (core), allocated CPU (core), allocated CPU (%), total memory (MB), allocated memory (MB), allocated memory (%), total disk (GB), used disk (GB), and used disk (%) of the node. |
  | Node data partition information | You can view the host IP address, zone, associated tenant, number of data partitions, and number of leader partitions of the node. The number of data partitions includes the number of leader partitions.  <blockquote>**<UI-TERM key="ocp-v2.Alarm.Template.New.Description">Description</UI-TERM>**</br>When OceanBase Database is V4.0 or later, you cannot view the node data partition information.</blockquote>  |
  | Tenant resource information | You can view the tenant name, tenant ID, tenant type, resource unit configuration, zone priority, locality, and server list.                                                        |
  | Tenant data capacity information | You can view the associated tenant, tenant ID, associated host, and data capacity.                                                                                  |

* Workload statistics: You can view the cluster workload statistics, including **metric, cumulative value, start value, end value, maximum value, time when maximum value occurred, minimum value, time when minimum value occurred**, and **<UI-TERM key="ocp-performance-report.ReportTables.SystemStatInfo.SystemStatTable.Average">Average Value</UI-TERM>**. For more information about metrics, see [Overview of monitoring metrics](../../1900.reference-guide/300.monitoring-indicator-reference/100.overview-of-metrics.md).

* Waiting event statistics: You can view the top 10 waiting events in terms of cumulative wait duration for the cluster and tenants. The statistics include **event name, event category, cumulative wait duration, cumulative wait count, and cumulative timeout count**.

* Routing statistics: You can view the routing statistics for a tenant, including **routing hit rate, number of routing hits**, and **<UI-TERM key="ocp-v2.ReportTable.PartitionStatInfo.PartitionHitStatInfoTable(RouteHits.1">number of routing misses</UI-TERM>**.

* Memory statistics: You can view the memory statistics of tenants in the cluster, including **context identifier, memory usage (bytes), average memory size requested (bytes), maximum memory usage (bytes), time of maximum memory usage, minimum memory usage (bytes)**, and **time of minimum memory usage**.

* Cache statistics

  This module calculates the average KV cache hit rate for tenants. The statistics are sourced from the OceanBase view gv$systat, and the hit rate result is rounded to two decimal places.

  Statistics are collected for seven major types of caches: Block Cache, Block Index Cache, Clog Cache, Clog Index Cache, BloomFilter Cache, Location Cache, and Row Cache.
  The statistics include: cache hit rate, number of cache requests, and cache size.
  
   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>In the statistical report, hover the cursor over the parameter name in the table header to view a detailed explanation of that parameter.</p>
   </main>
  
  | Parameter | Description |
  |-------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
  | Cache Hit Rate | The cache hit rates of different types for each tenant during the snapshot period. For information about these cache types, see [Cache mechanism](https://www.oceanbase.com/docs/oceanbase-database/oceanbase-database/V3.2.1/caching-mechanism). |
  | Cache Requests | Statistics on cache and request information for each tenant during the snapshot period, including the number of requests, cache hits, and misses.                                                                                                                   |
  | Cache Size | Statistics on the sizes of different cache types for each tenant during the snapshot period, including the start and end positions.                                                                                                                             |

* RPC statistics

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>In the statistical report, hover your cursor over a parameter name in the table header to view the source of the statistics for that parameter.</p>
   </main>
  
  | Parameter | Description |
  |--------------------|---------------------------------------------------------------------------|
  | Overall RPC | Displays the statistics of RPCs, including the number of RPCs sent and received, the size of RPCs, the network latency of RPCs, and the number of failed RPCs. The statistics are sorted by the total size of RPCs and shows the top 10 tenants. |
  | Packet Code RPC | Displays the statistics of RPCs aggregated by packet code. |
  | Clog RPC | Displays the statistics of Clogs, including the number of requests, the number of successful requests, and the total time consumed by successful requests. |
  | GTS RPC | Displays the statistics of GTS RPCs. |
  | Location Cache RPC | Displays the statistics of Location Cache RPCs, including the total number of cache refreshes, the number of RPC cache refreshes, and the number of RPC cache refresh failures. |

* Lock statistics

  | Parameter | Description |
  |----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
  | Row lock statistics | Displays the statistics of row locks in a tenant, including the number of row lock acquisitions, the number of row lock waits, the number of row lock timeouts, and the total wait time. |
  | Latch statistics | Displays the statistics of latches in a tenant, including the following items:  <ul><li>Get: the number of successful latch acquisitions by using the willing-to-wait request mode.</li><li>Miss: the number of failed latch acquisitions by using the willing-to-wait request mode.   </li><li>Sleep: the number of times that a thread goes into sleep after failing to acquire a latch by using the willing-to-wait request mode.</li><li>Spin Get: the total number of spin operations in the tenant.   </li><li>Immediate Get: the number of successful latch acquisitions by using the immediate request mode.</li><li>Immediate Miss: the number of failed latch acquisitions by using the immediate request mode.  </li></ul> |

* Parameter configuration changes

  This module displays the parameter configuration changes in different dimensions (clusters, zones, servers, and tenants) during the snapshot period, including the parameter, its current value, and the modification time.
