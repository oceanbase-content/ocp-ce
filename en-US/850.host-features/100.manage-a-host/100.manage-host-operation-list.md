# Manage host operations

Users with the system administrator, host administrator (HOST_MANAGER), or host viewer (HOST_VIEWER) role can click **<UI-TERM key="ocp-v2.Arbitration.ArbitrationGroup.Host">Host</UI-TERM>** in the left-side navigation pane to go to the **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.HostWithExclude.Host">Host</UI-TERM>** page.

## Prerequisites

Make sure that the user logged in to the OCP console has the following permissions:

* The **Cluster Read-Only**, **Tenant Read-Only**, or **Host Read-Only** permission.
* The **<UI-TERM key="ocp-v2.alarm.FormListWithExclude.ObproxyClusterAndHostWithExclude.All">All</UI-TERM>** permission on the host.

## View the host list

The **<UI-TERM key="ocp-v2.page.Host.HostList">Hosts</UI-TERM>** page displays the information of all hosts, including **<UI-TERM key="ocp-v2.Cluster.New.IpAddress">IP Address</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Host.Hostname">Host Name</UI-TERM>**, **<UI-TERM key="ocp-v2.Host.Detail.Basic.Label">Tag</UI-TERM>**, **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.HostType">Host Type</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Resource.Unit.Models">Host Type</UI-TERM>**, **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.ComputerRoom">IDC</UI-TERM>**, **<UI-TERM key="ocp-v2.Component.BackupStrategyDetail.Region">Region</UI-TERM>**, **<UI-TERM key="ocp-v2.Tenant.Detail.BelongsCluster">Cluster</UI-TERM>**, **<UI-TERM key="ocp-v2.Host.Detail.Basic.Service">Service</UI-TERM>**, and **<UI-TERM key="ocp-v2.Host.Detail.Basic.State">Status</UI-TERM>**.

* You can perform a paginated query and search for hosts by IP address, hostname, or cluster. You can also perform a batch query for host IP addresses, with the IP addresses separated by spaces.
* Hover the pointer over a host label to view the label information of the host. You can click the edit icon to manage the labels. For more information, see [Manage labels](../../1600.system-management-features/300.manage-tags/100.tags-overview.md).
* You can filter the hosts by **<UI-TERM key="ocp-v2.component.TagLabel.Label">Tag</UI-TERM>**, **<UI-TERM key="ocp-v2.src.component.AddHostDrawer.HostType">Host Type</UI-TERM>**, **<UI-TERM key="ocp-v2.Cluster.New.Models">Host Type</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Host.DataCenter">IDC</UI-TERM>**, **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.Region">Region</UI-TERM>**, **<UI-TERM key="ocp-v2.Backup.Backup.Log.Cluster">Cluster</UI-TERM>**, **<UI-TERM key="ocp-v2.Host.Detail.Basic.Service">Service</UI-TERM>**, and **<UI-TERM key="ocp-v2.Statistics.components.StatTable.Status">Status</UI-TERM>**.
* When the status of a host is **<UI-TERM key="ocp-v2.src.constant.binlog.OM">In Operation Maintenance</UI-TERM>**, you can click **<UI-TERM key="ocp-v2.page.Welcome.ViewTasks">View Tasks</UI-TERM>** in the **Actions** column to go to the task details page of the cluster O&M task. On the task details page, you can view the logs, roll back, or retry the task. For more information, see [Manage tasks](../../1600.system-management-features/600.manage-tasks.md).
* You can click the IP address of a host to view the basic information, OCP Agent information, and monitoring data of the host. For more information, see [View the details of a host](150.view-a-host-overview.md).
* You can click the name of a cluster to go to the **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page of the cluster to view the details of the cluster.

You can also view the following information in the expanded section: **<UI-TERM key="ocp-v2.page.Host.HostId">Host ID</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Host.MappingPort">Mapping Port</UI-TERM>**, **<UI-TERM key="ocp-v2.Information.Detail.CollectDetails.SshPort">SSH Port</UI-TERM>**, **<UI-TERM key="ocp-v2.Host.Component.ReinstallModal.OcpAgentVersion">OCP Agent Version</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Host.OperatingSystem">Operating System</UI-TERM>**, **<UI-TERM key="ocp-v2.Detail.Component.UpgradeObproxiesModal.CpuArchitecture">CPU Architecture</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Host.CpuModel">CPU Model</UI-TERM>**, **<UI-TERM key="ocp-v2.Host.Detail.Basic.CpuCores">CPU Cores</UI-TERM>**, **<UI-TERM key="ocp-v2.page.Host.TotalMemory">Total Memory</UI-TERM>**, and **<UI-TERM key="ocp-v2.Detail.Component.ModifyParameterDrawer.Description">Description</UI-TERM>**.

| Parameter | Description |
|--------|-----------|
| Cluster | The cluster to which the host belongs. This includes OceanBase clusters and OBProxy clusters. You can click the name of a cluster to go to the **<UI-TERM key="ocp-v2.src.util.menu.SummaryInvestingComZa">Overview</UI-TERM>** page of the cluster.      |
| Host Type   | The current version supports three types of hosts: physical hosts, containers, and Elastic Compute Service (ECS) instances. <li> A single physical host can deploy multiple services, but only one service of the same type can be deployed to avoid conflicts. </li> <li> A single container host can deploy only one type of service. We do not recommend that you deploy an OceanBase cluster to a container host. </li>  |
| Status     | The status of the host. Valid values: New, Idle, Online, Offline, Deleting, Agent Reinstalling, and Agent Restarting.    |
| Mapped Port | The mapping between ocp-agent and the host and between ocp export and the host. The format is: ` <Host Port>:<Port of ocp-agent in Docker>, <Host Port>:<Port of ocp-exporter in Docker 1>`.       |
