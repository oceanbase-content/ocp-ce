# Host standardization checks

During the host standardization process, the system will perform checks on the hosts. This topic describes the checks performed on the hosts during standardization.

<main id="notice" type='explain'>
<h4>Note</h4>
<p><li><b>Host standardization checks</b> apply only to hosts where OBServer is deployed. Use them as needed for other host scenarios. </li><li> In a container environment, due to limitations such as cgroup and namespace, checks or automatic fixes may not be possible. We recommend that you manually perform the required checks as needed. </li></p>
</main>

## Check the file system type

The file system type can be EXT4 or XFS. If the disk capacity exceeds 16 TB, check whether the file system type is XFS. If not, we recommend that you reconfigure the disk.

## Check the kernel parameters

Check whether the kernel parameters meet the requirements:

| Kernel parameter | Default value range | Description |
|--------|----------|-----------|
| net.core.somaxconn | 2048 ≤ value ≤ 16384 | The maximum length of the listening queue for each port. This is a global parameter. |
| net.core.netdev_max_backlog | 500 ≤ value ≤ 10000 | The maximum number of packets that can be sent to the queue when the rate at which the network interface receives packets exceeds the rate at which the kernel processes the packets. |
| net.core.rmem_default | 65536 ≤ value ≤ 16777216 | The default size of the TCP receive window (in bytes). |
| net.core.wmem_default | 65536 ≤ value ≤ 16777216 | The default size of the TCP send window (in bytes). |
| net.core.rmem_max | 8388608 ≤ value ≤ 16777216 | The maximum size of the TCP receive window (in bytes). |
| net.core.wmem_max | 8388608 ≤ value ≤ 16777216 | The maximum size of the TCP send window (in bytes). |
| net.ipv4.conf.default.rp_filter | == 1 | Defines the rules for reverse route verification on the network interface card. <li>0: disables reverse route verification. </li><li>1: enables strict reverse route verification. </li><li>2: enables loose reverse route verification. </li> |
| net.ipv4.conf.default.accept_source_route | ==0 | `accept_source_route` specifies whether to allow the sender of a packet to specify the path for the packet and the path for the response packet. br0 disables this feature. |
| net.ipv4.tcp_syncookies | ==1 | Sends syncookies to the other party when the syn queue overflows. This is to prevent syn flood attacks. |
| net.ipv4.tcp_rmem | The three values, 4096, 87380, and 16777216, correspond to `min`, `default`, and `max`, respectively. The values are divided into three parts: <li>4096 ≤ min ≤ 8192</li><li>65536 ≤ default ≤ 174760</li><li>8388608 ≤ max ≤ 16777216</li> | Defines the memory used by sockets for automatic tuning.<br>The first value specifies the minimum number of bytes allocated for the receive buffer of a socket. <br>The second value specifies the default value (which is overridden by rmem_default). The buffer can grow to this value when the system load is not high. <br>The third value specifies the maximum number of bytes allocated for the receive buffer (which is overridden by rmem_max). |
| net.ipv4.tcp_wmem | The three values, 4096, 65536, and 16777216, correspond to `min`, `default`, and `max`, respectively. | net.ipv4.tcp_fin_timeout | 15 ≤ value ≤ 60 | The time (in seconds) that a socket connection remains in the FIN-WAIT-2 state after the local end disconnects. The other party may disconnect the connection, or the connection may not be terminated, or the process may unexpectedly terminate. |
| net.ipv4.tcp_tw_reuse | ==1 | Specifies whether to allow the use of sockets in the TIME-WAIT state for new TCP connections. |
| net.ipv4.tcp_slow_start_after_idle | ==0 | Specifies whether to enable slow start after TCP is idle. 0 indicates that slow start is disabled. |
| net.ipv4.ip_local_port_range | 3500 ≤ value ≤ 65535 | The range of local port numbers available. We recommend that you set the value to 3500-65535. |
| net.ipv4.ip_local_reserved_ports | 62881 ≤ value ≤ 63881 | The port number range reserved for ocp-agent to provide O&M monitoring services. |
| vm.swappiness | ==0 | The relative weight of the memory to be swapped out. |
| vm.min_free_kbytes | 32768 ≤ value ≤ 2097152 | The size of the reserved free page pool. We recommend that you set the value to 2097152. |
| vm.max_map_count | 327680 ≤ value ≤ 1000000 | The maximum number of memory-mapped areas that a process can use. The default value is 65536.<br>If your application requires more memory-mapped areas, we recommend that you increase this value to 655360. |
| vm.overcommit_memory | ==0 | Specifies whether to accept large memory requests. The default value is 0. |
| vm.nr_hugepages | ==0 | `nr_hugepages` specifies the number of huge pages. A value of 0 indicates that huge pages are not enabled. |
| fs.aio-max-nr | ≥ 1048576 | The maximum number of asynchronous I/O operations that can be performed simultaneously. |
| kernel.numa_balancing | ==0 | Disables automatic NUMA balancing to avoid performance jitter caused by memory node data migration. |
| vm.zone_reclaim_mode | ==0 | Disables the memory zone reclaim mode. This allows memory to be reclaimed from other zones or NUMA nodes, avoiding performance jitter caused by memory reclaim. |
| fs.file-max | ≥ 6573688 | The maximum number of files that can be opened in the system. This is a system-level limit. |
| fs.pipe-user-pages-soft | == 0 | The soft limit on the total size (in pages) of all pipes created or set by non-privileged users (users without the `CAP_SYS_RESOURCE` or `CAP_SYS_ADMIN` capabilities). We recommend that you set this parameter to 0 to disable the soft limit. |

**To manually modify the parameters:** For example, to modify the `net.core.somaxconn` parameter, you can write `net.core.somaxconn = 128` to the custom configuration file `/etc/sysctl.d/oceanbase.conf` using the echo command. To delete a parameter, you can remove the corresponding line from the file.

## Check services

Check whether the `crond`, `sshd`, and `firewalld` services are running. Specifically, check whether the `crond` and `sshd` services are enabled and whether the `firewalld` service is disabled.

| Service | Description |
| --- | --- |
| crond | We recommend that you enable this service. It is mainly used to set up scheduled tasks and provide related O&M capabilities. |
| sshd | We recommend that you enable this service. It is mainly used to encrypt logins and data transmission and provide basic O&M capabilities. |
| firewalld | We recommend that you disable this service or add rules to allow services of the OceanBase cluster to avoid firewall interception. |

**Manual modification method:**

* To enable a service: `systemctl enable {serviceName} && systemctl start {serviceName}`
* To disable a service: `systemctl stop {serviceName} && systemctl disable {serviceName}`

## Check whether transparent huge pages are disabled

Check whether transparent huge pages are disabled to ensure system performance stability.

**Manual modification method:** Run the `echo never > /sys/kernel/mm/transparent_hugepage/enabled` command to set transparent huge pages to never. If the system restarts, we recommend that you add this command to the `rc.local` or `systemd` configuration to achieve persistent configuration.

## Check the Python version

The OceanBase-related scripts depend on Python 2.7.x. Check the Python version to ensure that the scripts can run normally.

**Manual modification method:** Install Python 2.7 through the software package manager and ensure that the `python -V` command returns version 2.7.

## Check whether swap is enabled

Check whether the swap partition is enabled on the deployment server. We recommend that you disable the swap partition to avoid performance jitter.

**Manual modification method:** Run the `swapoff/swapon -a` command and delete the swap-related entries in the `/etc/fstab` file to achieve persistent configuration.

## Check whether the admin user exists

Check whether the admin user is used to run the OCP or OceanBase services.

**Manual repair method:** Run the `useradd` and `groupadd` commands to set the `uid=500` and `gid=500` for the admin user.

## Check whether SELinux is enabled

Check whether SELinux is enabled. SELinux uses mandatory access control (MAC) to manage permissions for specific programs and specific file resources. We recommend that you disable SELinux.

**Manual repair method:** Run the `/usr/sbin/setenforce` command to disable SELinux (set it to 0), and modify the configuration in the `/etc/selinux/config` file to disabled.

## Check ulimit information

ulimit is mainly used to limit the resources consumed by processes started by the shell. The OBServer process involves several limitations, including the maximum thread stack size (stack), the maximum number of file handles (open files), and the core file size (core file size). To avoid system limitations affecting the service, it is recommended to set the ulimit-related items to the following required configurations:

```Json
root soft nofile 655350
root hard nofile 655350
admin soft nofile 655350
admin hard nofile 655350
admin soft stack 10240
admin hard stack 10240
admin soft nproc 655360
admin hard nproc 655360
admin soft core unlimited
admin hard core unlimited
```

**Manual fix:** Create the `/etc/security/limits.d/99-oceanbase_limits.conf` file and write the above configuration content into the file. Ensure that this file has the highest priority.

## Check clocksource information

Check whether the system configuration item clocksource meets the requirements. The recommended value is `tsc`. Other values may trigger performance issues.

**Manual fix:** Execute the `echo tsc > /sys/devices/system/clocksource/clocksource0/current_clocksource` command to set the clocksource value to `tsc`.

## Check the default MTU value of the network card

Check the default MTU value of the network card. The recommended value is 1500. A value that is too large or too small will not affect the system operation, but will affect the network transmission efficiency and performance.

**Manual fix:**

* **Temporary fix**

  * IP command: `sudo ip link set dev eth0 mtu 1500`.
  * ifconfig command: `sudo ifconfig eth0 mtu 1500`.

* **Permanent fix**

  * Debian/Ubuntu: Edit the `/etc/network/interfaces` file and add the following content.

    ```bash
    auto eth0
    iface eth0 inet dhcp
    mtu 1500
    ```

  * CentOS/RHEL: Edit the `/etc/sysconfig/network-scripts/ifcfg-eth0` file and add or modify the following content.

    ```bash
    MTU=1500
    ```

## Check the NTP/Chrony time synchronization service

Check whether the host is synchronized with the clock source. It is recommended to enable the NTP or Chrony service.

**Manual fix:**

1. Install the NTP package. If it is already installed, you can skip this step.

    ```bash
    sudo apt update
    sudo apt install ntp    # For Debian/Ubuntu
    # Or
    sudo yum install ntp    # For CentOS/RHEL
    ```

2. Start the NTP service.

    ```bash
    sudo systemctl start ntp
    ```

3. Set the NTP service to start automatically at boot.

    ```bash
    sudo systemctl enable ntp
    ```

4. Check the status of the NTP service.

    ```bash
    sudo systemctl status ntp
    ```
